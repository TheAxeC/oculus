## Acceptance items, edge by edge

**Edge 1 (O13, the burst case). Met.** The clock is a dependency: `Clock`/`systemClock` at `src/lib/server/watch/git.ts:36-51`, `const clock = options.clock ?? systemClock` at `:115`, used at `:156` and `:204`. Default behaviour is unchanged: `systemClock` delegates to the globals with the same arguments, and the only other change is the timers map widening to `Timer`.

Wall-clock dependence in the burst case is gone for the thing it counts. `touch()` (`git.ts:150-162`) never reads inline; every read happens inside the timer callback, so with the manual clock a read happens at `fire()` and nowhere else, and a late FSEvent can only schedule a timer that is never fired. `reads(first) - before.first` is therefore exactly 4 by construction, not by timing. What remains on the wall clock is event *delivery* (`arming()` writes until `clock.pending() > 0`, `until(..., WAIT=6000)`), which is the right thing to wait for. Reverted, the test fails: `arming()`'s `expect(clock.pending()).toBeGreaterThan(0)` (`tests/server/watch/git.test.ts:179-188`) can never pass, and `npm run check` fails on the unknown option.

One thing to know: the two other cases changed `await sleep(2500)` to `await sleep(500); expect(clock.pending()).toBe(0); clock.fire();` (`git.test.ts:346-351` and `:459-464`). The assertion got stronger in kind (scheduling is synchronous with the event, publishing was not), but the window in which a stray late event would be noticed shrank by two seconds. Not a loosened threshold on what is asserted; worth knowing.

**Edge 2 (Q2). Half met, and the half that is short is the half the brief named.**

The currency check is right: `buildState` (`tests/browser/layer.ts:41-66`) compares the newest mtime under `src/` and under `config/` against the newest under `build/`, refuses when `build/handler.js` is absent, and names the offending source file; `serve.ts:52-56` prints it and exits 1. `tests/browser/layer.test.ts` covers no-build, current, the named file, and the skipped folders, and fails if `layer.ts` is removed.

The cleanup does not run on the exit path Playwright uses, and the tree proves it. After the worker's browser run at 16:32: `tools/oculus/tests/browser/.hub` is still present (76 bytes, 16:32) and `$TMPDIR/oculus-browser-Vq7n63` is still there. So the temporary copy survives a run and is removed only by the *next* run's start sweep, and `.hub` is never removed at all. The brief asked for removal "when the server exits (`process.on('exit')` and the signal it receives from Playwright)".

Fix, inside the brief's allowed paths: add to the `webServer` block of `playwright.config.ts`

```ts

```

Playwright 1.63 is installed and supports it (`node_modules/playwright/types/test.d.ts:11002`); the `removeOnExit` handlers the worker already wrote then run and take both the copy and `.hub`.

A second run started while a first is serving deletes the first run's hub copy out from under it and only then fails on the port, so the report's judgment call 5 ("two runs cannot serve at once, since the port is one") does not hold in the order the code runs. Two worktrees are in flight under the plan, which makes this reachable. Fix: claim the port or a lock file first and sweep only after, or skip a directory whose run is still live.

Also true of the whole file: nothing tests `serve.ts`'s own wiring (the refusal, the sweep call, `removeOnExit`). Deleting the `if (!built.current)` block breaks no test. The worker proved it by running `node tests/browser/serve.ts` once, which is the right evidence for a file that is a process, but the orchestrator should not read the layer.test.ts green as covering it.

## The six judgment calls

1. **Fake `ssh` on PATH.** Sound, and it cannot reach outside the browser run: PATH is set only in the `env` of the server the layer spawns (`serve.ts:124-131`), so it reaches that process and its children (the poller's `ssh`, the pty layer's `tmux`) and nothing else; Playwright and Chrome are started by the test runner, not by the server, and never inherit it. `serve.ts` itself keeps the machine's PATH.
2. **HOME as the run's directory.** Sound and an improvement: `homedir()` follows `HOME` on POSIX, so `transcripts.ts:47`, `registry.ts:30`, `codex.ts:40`, `overrides.ts:25` and `accounts.ts:67,147` all land in the run's own tree, and a browser run stops reading the owner's sessions and writing `~/.oculus/transcript-cache.json`.
3. **`tmux` exits 1.** Sound for keeping a run from spawning Claude CLI sessions on the machine, and it is the direct cause of the terminal stop; state the stop as "needs a config route to a private tmux or a control-mode fake", not as a standing-rule prohibition.
4. **`testMatch: '**/*.spec.ts'`.** Sound and required, given vitest's include pattern.
5. **Start sweep.** The premise is wrong in the order the code runs, and the sweep is destructive to a concurrent run (see edge 2). Fix before landing.
6. **420px viewport for the cross-link case.** Sound; at the default width nothing is measurable.
