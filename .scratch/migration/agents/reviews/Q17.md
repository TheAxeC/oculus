**d. The server-side icon reading.** `src/lib/data/sources/config.ts:445-454` reads 117 files per call with no memory. The report's 8.15 ms and 55,960 bytes are the right magnitude: the 117 trimmed files are 49,235 bytes and JSON-encode to 56,193. Three things the report does not say:
- `src/hooks.server.ts:14-18` calls `iconFindings` in `handle`, which runs on every request, not only a page load. That is 117 `existsSync` calls per request (`config.ts:417-443`), and on a drifted config it is 117 `console.error` lines per request. I did not measure the per-request cost.
- The payload crosses to the browser twice per load: once in the page data (`src/routes/+page.server.ts:32`) and once over the socket, because `src/routes/+page.svelte:140` subscribes to `config` and `src/lib/server/channels.ts:76-86` replays a channel's current message to a new subscriber. Every reconnect replays it again. This is read off the code, not measured over the wire.
- The report's reason for not caching ("a cache would be module-level state") is wrong. `src/lib/server/context.ts:43-48` already carries three per-process memories on the context object (`hpcLogPaths`, `depositPlans`, `wallpaper`), which is exactly the passed-in dependency the no-globals rule asks for. The server context can hold the icon set; nothing forced the recomputation.
- Resolution is by hand-built path (`config.ts:407-409`, `join(engine, 'node_modules', 'lucide-static', 'icons', ...)`). Under any install that hoists or relocates the package the failure mode is 117 findings per request and every icon silently falling back to the character. `createRequire(import.meta.url).resolve('lucide-static/icons/pin.svg')` would not have that mode.

**e. The sanitising path mutates its own exported constant.** `src/lib/ui/html.ts:189` lists `'viewBox'`, the one capitalised entry in either allow-list. DOMPurify's `addToSet` lowercases each entry and writes it back into the caller's array when the array is not frozen (`node_modules/dompurify/dist/purify.cjs.js:147-170`, reached from `:455`). So the first `sanitiseSvg` call in the browser rewrites `SVG_ATTR[n]` to `'viewbox'` in place. ## 5. The nine judgment calls

1. **Which chips stay chips (statusTone or typeTone): kept.** Axel's words in the brief's first paragraph are "the chip capsule stays on the status words alone; every other tag becomes plain muted text with its glyph", and the plan line narrows "status words" to "the `status_legend` chips, the type chip". An HPC job state, an efficiency percentage, a tool turn's ok and a venue quartile are not the status legend, so they are on the tag side of Axel's sentence, and "plain muted text" says the hue goes with the capsule. The worker read it correctly and reported the consequence. The reversal, if Axel wants the hue back on the measured marks, is a `Tag` tone prop, which is judgment call 2.
2. **Tag carries no tone prop: kept.** It is the brief's own decision 2, restated, not a judgment.
3. **Nine colour glyphs to `circle`, two squares to `square`: questionable.** The mapping itself is forced (a one-weight line icon has no colour), but the stated justification covers only the toned chip, and two sites draw those names outside one. See (c). The fix inside the package is a distinct icon per status meaning rather than a shape per colour name (`submitted` to `send`, `blocked` to `ban`, `parked` to `pause`, and so on), which keeps `config/icons.yml` the single place it is decided.
4. **Cross-link class rename: questionable.** Right in `CardLinks.svelte`, not carried to the identical construct in `CardDetails.svelte:87`. See (f).
5. **`iconCatalog` split into `iconCatalog` / `iconFindings` / `iconSet`: kept.** The split is what lets `hooks.server.ts` take the findings without reading 117 files, and the disk check is correctly outside `loadConfig`, which touches no disk.
6. **`config/icons.yml` Prettier-formatted at four spaces: kept.** It obeys the spec's four-space rule. Worth naming at landing that `config/` is now nine two-space files listed in `.prettierignore:19-27` plus one four-space file, so the next config author has two styles to choose between.
7. **The span repeated in both `{#if}` branches: kept.** `src/lib/ui/Glyph.svelte:26-33`; the ascii branch is byte-identical to the old markup, which is what keeps the existing rail and bracket assertions honest.
8. **No Tag demo in the gallery: wrong.** `src/lib/views/Gallery.svelte:14-16` says what the view is for: "Every primitive with sample data, in one pane: the living style sheet. It is opened under each theme to see what a card, a chip, a meter and a table actually look like there". A new primitive that is now 89 of the 98 marks in the app, whose whole definition is a colour (`--muted-txt`) that has to be read under every theme, is exactly what that view exists to show, and its head comment now misdescribes the tree. The stated reason, that new catalog strings would be a shape, does not hold: a section heading in `config/text/views/gallery.yml` is a catalog string like the eleven already there, not a config vocabulary or a manifest key. Two of the findings in section 4, (a) and (h), are the kind a gallery row surfaces on sight.
9. **`bracketedGlyph` moved into `state/text.ts`: kept.** Semantics are identical to the old derived (`src/lib/state/text.ts:117-124` against the removed `Chip.svelte` block), it satisfies the brief's check 9, and the lookup belongs beside `glyph()` rather than in a primitive.
