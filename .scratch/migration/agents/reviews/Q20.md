## 6. Findings

**A. A defect neither the report nor the items name: one bad save of the file from the new source tab locks the source route.** `loadLocal` throws on a malformed value (`config.ts:191` hub, `config.ts:210` port, and so on) where `loadConfig` turns a broken tracked file into a finding, so the machine file is the one file of that folder whose bad content is fatal rather than reported. `handleSource` takes `rootList: Root[] = roots()` (`src/lib/server/source.ts:60`), the production route leaves that default in place (`src/routes/api/source/+server.ts:7`), and a default argument is evaluated before the origin and token checks. I verified it with a probe under $TMPDIR (deleted): with `OCULUS_LOCAL` naming a file holding `port: eight`, `files.roots()` threw `port must be an integer` and `source.handleSource(...)` threw the same before answering anything. So a reader who saves `port: eight` into `config/local.yml` from the Config view's own card gets a 500 on that save and on every later source save, including the one that would put it back; `api/open` (`src/routes/api/open/+server.ts:8`) and the wallpaper route (`server/wallpaper.ts:147`) go the same way, and the next server start throws out of `server/context.ts:113`. Recovery is editing the file outside oculus. The report names a weaker neighbour of this (editing `hub` moves where writes land while the watchers hold the start value) and not this. The file being editable from the page is what the brief asked for, so the fix is a decision: validate the body with `loadLocal`'s rules before writing when the target is that file, or give `roots()` a non-throwing path. I am not picking one.

**B. The file is now inside two repo gates that do not know it is machine-local.** `.prettierignore:19-27` names the nine config YAML files one by one and does not name the machine's own, and `format:check` is `prettier --check .`. I confirmed the resolution with `npx prettier --file-info config/icons.yml` (`"ignored": false`, parser `yaml`) against `config/vocab.yml` (`"ignored": true`); Prettier does not read `.gitignore`. So on any machine that has the file, `npm run format:check` will parse and check it against `tabWidth: 4` and `singleQuote: true`, and a reader who saves it from the new source tab can turn a green check red with a hand-written two-space list. The same move puts it inside the ASCII gate's `find config -type f`. Whether the checkout's own file currently formats clean I cannot say: reading it is outside my brief. One line in `.prettierignore` closes it.
