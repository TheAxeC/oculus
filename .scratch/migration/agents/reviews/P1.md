## 4. Defects in the new code

**D1 (serious). Editing a PRESENT.md never republishes the portfolio.** `src/lib/server/watch/portfolio.ts:55-59`: `relevant()` returns false unless the filename ends in `.yml`, so a `PRESENT.md` write is dropped at the directory watch; `namedByConfig` (`:78-82`) would drop it again, accepting only `project.yml` under a scan tier. Two comments in the new code state the opposite: `src/lib/state/present.svelte.ts:4` and `src/lib/views/Present.svelte:20`. Config edits do push; slide edits need an unrelated `.yml` write or a restart.

**D2. An instance opened on a slide is snapped back to it on every push.** `Present.svelte:66-68` runs `goTo(wanted)` in an `$effect`; `goTo` reads the `slides` derived, which is recomputed on every config or portfolio push. The effect therefore re-runs on each push and reassigns `held`. Reasoned from the code and Svelte 5 dependency tracking; not observed in a browser.

**D3 (serious). Every real `diagram_html` panel renders as unstyled stacked text.** `style` is absent from `ALLOWED_ATTR` (`src/lib/ui/html.ts:74-84`), and `grep -rn "dgrid\|dnode\|darrow\|\.dbar" src/` returns nothing, so the classes the hub's diagrams carry have no rules in oculus. Example: `projects/manuscripts/covert-theory/PRESENT.md:23` writes `<div class="dgrid" style="grid-template-columns:1fr 1fr">` with `.dnode` borders coloured inline. `tools/present/assets/css/deck.css` is where those rules live and nothing ported them.

**D4 (serious). Two archived projects are in the public deck.** `projects/archive/nogo/fed-faithful-ecg/PRESENT.md` and `projects/archive/published/2026/hccnet-fl/PRESENT.md` both reach the snapshot and `deckSlides` places every unnamed project slide. The cockpit deck excludes them by `deck_config.py:31,68`. A no-go project's narrative is now a public deck slide by default.

**D5. Dead payload.** The 14 projects with front matter carry their whole narrative body in the snapshot and never draw it. 33,492 of the 37,279 body bytes are never rendered.

**D6. Asymmetric checking.** `figure:` is checked against `<project>/present/`; `equation:` naming a PNG is checked nowhere. All 13 named PNGs exist today, so it is latent.

**D7. Two readers of `order:`.** `deckFindings` and `order()`. The boundary table (`tests/boundaries.test.ts:51`, the `state` row) blocks a shared reader without a table change. Judged acceptable to land.

**D8. `DeckSlide.title` is documented as the pane title and is not used as one.** `src/lib/data/model-entities.ts:388` says "for the overview grid and the pane's own title"; `Present.svelte:146` is a fixed "Present".

**D9. Focus.** Covered under shape 3 above; the fix is to focus the box when the pane becomes active.

**D10. Swallowed keys.** With the box focused, `o`/`O` and (while the grid is open) `Escape` are `preventDefault`ed. No shell binding on `o` found; every shell Escape handler was not audited, so whether a flyout or palette loses its Escape is not verified.

**D11. KaTeX settings.** `trust: false` and `strict: 'ignore'` are set and the source reaches the page escaped, so the bypass of the sanitiser cannot carry script, a link or a class. `maxSize` and `maxExpand` are not set, so `\rule{9999em}{9999em}` in a PRESENT.md blows the pane's layout. Not named in the report.

**D12. Key collision.** `slideKey` returns the bare project id for a project slide, so a project whose id were `title`, `ideas` or `closing` would collide with a deck key and `seen.has(key)` (`:401`) would silently drop one. No project does today.

**D13. `portfolioConfigFrom` gained a machine-dependent default.** `src/lib/data/index.ts`: `engine: string = engineDir()`. Internal and reversible; the report does not list it.

The report's own sharp edges, judged: keys in force only after focus is a defect inside the brief (D9); a saved list naming a gone slide being silent is a consequence of the brief and matches `deck_config.catalog`; the green-check paragraph is accurate but T1 belongs in it; the two `order:` readers are fine as reported; `present.at` as a bare placeholder is fine; the git commands, see S6.
