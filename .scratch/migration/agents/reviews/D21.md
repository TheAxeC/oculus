## 4. Defects in the change

**(a) A preview tab retargeted from one text file to another keeps the first file's text, and a save writes it to the second file's path.** `retarget` keeps the instance id (`src/lib/state/layout/preview.ts:38`), `openInto` returns that same id (`src/lib/state/layout.svelte.ts:784-797`), and nothing clears the instance's ui state on a retarget: `ui.clearInstanceState` has exactly two call sites, both on close (`src/lib/state/layout.svelte.ts:528`, `:587`). The source draft is keyed by instance id and re-reads at most once per page lifetime (`src/lib/state/source.svelte.ts:136`, `if (sourceDraft(id).readIn === LIFETIME) return;`). Verified by run: after `openView('source', a.py, {preview})` then `openView('source', b.py, {preview})`, `sourceDraft(id).text` is still `'AAA\n'`, expected `'BBB\n'`. This is the main path the package adds (one click after another in the file browser), and Save on that tab overwrites b.py with a.py's bytes.

**(b) A UTF-8 file over 8 KB whose character straddles byte 8192 is classified binary.** `isTextBytes` returns `cut` for a sequence the window cut (`src/lib/data/text-kind.ts:59`) and `cut` is `bytes.length > end` (`:47`), but both callers hand it at most `TEXT_SNIFF` bytes: `readCappedBytes(response, TEXT_SNIFF)` returns `Math.min(taken, limit)` bytes (`src/lib/state/fs.svelte.ts:431`, `:208`), and the route reads at most `TEXT_SNIFF` (`src/lib/server/source.ts:57-58`). So `cut` is always false and the branch is dead. Verified by run: a file of 8191 `a` then `ö` then more text gives `isBinaryFile(file) === true`. Consequence: that file opens as a download in the tree and a save to it is refused with `binary`. The fix is to hand the rule one byte more than the window (or a `cut` flag from the caller).

**(c)** The mirror regression above (point 2), which is a change in what the reader sees, not only a limitation.

**(d)** `src/lib/views/Source.svelte:97` labels the source tab's toolbar with `t('file.toolbar')`, the file view's group, whose word is "File controls" (`config/text/views/file.yml:15`). The `source` group has no toolbar key of its own.

**(e)** Two different things are called `preview` in the same feature: the rendered Markdown half (`src/lib/state/source.svelte.ts:30`) and the preview tab (`src/lib/state/layout/model.ts:18`). One of them should be renamed before more code reads either.

**(f)** Minor cost the report does not name: a double click on a tree row makes three `readFileKind` head fetches (two `onclick` plus the `ondblclick`, `src/lib/views/Files.svelte:183`), and opening a binary from the tree makes two (`Files.svelte:183` then `src/lib/views/File.svelte:99`).

Keeping `Code.svelte` for a locked file is right, but the half that follows from it (leaving the editor's mirror on `state/highlight.ts`) puts oculus in the position that a file is coloured only while it cannot be edited. `DESIGN.md:302` is "files open as an editor opens them"; an editor that drops colouring for every language but YAML and Markdown does not meet that line, and `DESIGN.md:299`'s reason for the eighteen grammars is the research tree's own files, which are exactly the ones now uncoloured. The editor's mirror should paint through `views/source/languages.ts`, or the package should say plainly that D13's CodeMirror is the only fix and book it.
- **Call 11** ("a preview open is looked for after the existing-instance search") is the right order and matches `DESIGN.md:212`'s "two instances of the same view have separate state by construction"; it just needs the case named in point 3.
- Every other call (the star to `views/shared/`, the code window to `views/source/`, the GET without a write token, `openView`'s fourth parameter, the cut draft never sent) follows `DESIGN.md`'s layer table (`:189-193`) and its write chain, and I would keep them.
