- Open item 180 (2026-10-20, Axel: settings kept only in the browser or the app). The problem: oculus keeps some data only in the browser's storage. Chrome at `127.0.0.1`, Chrome at `localhost` and the oculus app each have their own storage, so each holds a separate copy: a theme changed in the app is not changed in Chrome, pages set up in one are missing in the other, and clearing Chrome's site data deletes them. The data is of two kinds. Settings Axel chooses: the theme, the text size, the terminal text size, the code theme, the CRT, wallpaper, icons, Brackets and Monospace toggles, the status bar's hidden items, Do Not Disturb and the status bar's repository, and the suggest panel toggle. State oculus records as he works: the pages with their splits, panes, open tabs and floating panes, each tab's view state (a list's filters, search text, selection, expanded rows), and the debugger's breakpoints and watches. What oculus already has for each kind. For settings, the options catalog and Settings: an option is described in `config/catalogs/options.yml`, shown in Settings, and written by Settings to its config file when changed; the four settings code theme, CRT, terminal text size and suggest panel already are such options, with a browser value on top. For state oculus writes itself, the folder `~/.oculus`, which holds `window.json`, `workspace.json`, the change log and the rest of oculus's own state. Options. (a) Keep the browser storage and correct the help text, which says every window shares one layout. For: no work. Against: the copies keep differing and are lost with site data. The lazy option. (b) Each setting becomes an ordinary option of the options catalog, written by Settings like every other option, and its browser value is removed; the recorded state is written by oculus to `~/.oculus`, and its browser copy is removed. For: Chrome at both addresses and the app show the same settings and the same pages, and nothing is lost with site data. Against: a theme can no longer differ between two windows; the settings land where options already land, oculus's `config/appearance.yml` and `config/behavior.yml`, which move with oculus into its own repository at O39. (c) The recorded state is written by oculus to `~/.oculus`; the settings stay in each browser. For: the same pages everywhere, and a theme can still differ per window. Against: the settings still differ between Chrome and the app and are lost with site data. Under (b) and (c) the two browser keys no code reads any more are deleted. Recommendation: (b), since it is the only option that ends the separate copies for both kinds of data, with the mechanisms oculus already has. Built inside O46 once ruled.
