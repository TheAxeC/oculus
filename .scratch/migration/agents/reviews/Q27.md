## The split, the effect and the strip, judged

**The split.** Props are threaded correctly: `stopIndex`, `ringKeys`, `canShrink`, `canGrow`, `canReset`, `offersWallpaper`, `onsearch`, `onupdate` at `ActivityRail.svelte:427-436` against the `Props` type in `RailAppearance.svelte`, and `themes`/`setTheme`/`setCrt`/`setUnicode`/`setWallpaper`/`stepTextScale`/`setTextScale` moved to the child's own `useState()`. `stopIndex` reads the parent's `current` derived and `ringKeys` reads `stops`, so both stay reactive across the boundary. `focusStop` searches `box.querySelectorAll('[data-stop]')` and `box` is the `.ring` div that wraps both halves, so the child's controls are reachable.

**The CSS.** Equivalent by reading, not measured in a browser. Before: `.rail` was the flex column carrying `justify-content: space-between; gap: 8px`, with `.views` (`overflow-y: auto; min-height: 0`) and `.controls` (`flex-shrink: 0`) as its children. Now `.rail` keeps `display: flex; flex-direction: column; flex: 0 0 auto` and hands `space-between`, `gap: 8px`, `flex: 1 1 auto`, `min-height: 0` and `overflow: visible` to `.ring` (`:457-465`); `.views` is unchanged (`:467-483`); `.controls` carries the identical rules in the child's scoped style, `flex-shrink: 0` included, so on a short window the view list is still the half that scrolls and the foot still cannot pile up. `:global(body.wall) .rail` stays on `.rail`, so the stacking context and the backdrop filter are where they were.

**The effect.** It terminates: it reads `held` and writes it, so it re-runs, but the written value is always a member of `now` (or `''`), and both take the early return at `:231`. The ordering is sound for the reason the code does not state: `held = moved` at `:233` queues Svelte's next flush before `recoverStop` queues its microtask at `:248`, so the disabled attribute is already applied when `activeElement` is read, and `focusStop`'s own second microtask only needs the `data-stop` element to exist, which no arrow press or ring change removes. A ring change while the palette or a field holds the keyboard is safe by two independent routes: the focus moving into the palette input fires `focusout` with a non-null `relatedTarget`, so `holding` goes false, and even with `holding` stale the `loose` test refuses to take the keyboard from a live control.

**The strip.** A tab removed while the stop is on it: `stop` at `:79` falls back to `active`, so the tabindex is right; the focus is not (defect 1). A drag reorder: `stopped` holds an id and `stop` tests membership, so the stop follows the tab by identity. Delete on the last tab of a pane closes the pane. Home and End work and are undocumented (defect 2). `ArrowUp`/`ArrowDown` in a strip and `ArrowLeft`/`ArrowRight` in the rail return null from `nextStop`, are not cancelled, and fall through to the card cursor at `keys.ts:150-161`; the sheet's new arrows row does not mention that, and it also no longer mentions that the four arrows are the card cursor's aliases, which the `j / k` and `i / o` rows do not say either.
