### The defect: a funding scheme's undated follow-up lands under "Tasks"

`Tasks.svelte:37-41` decides the group from the line's `target`:

```ts
function groupOf(line: TickerItem): keyof Groups {
    if (line.target?.subtask !== undefined) return 'subtasks';
    if (line.target?.kind === 'followup') return 'followups';
    return 'tasks';
}
```

A funding scheme's follow-up is built with no target at all (`ticker.ts:327-334`):

```ts
line: item('followup', GLYPHS.followup, `${scheme.title} - ${note.do}`, days)
```

so `groupOf` falls through to `'tasks'` and the note draws under the "Tasks" heading, with no buttons and no click, beside the `tasks.yml` entries. On the Command Center before this package it drew in the Follow-ups group, because that group was the whole `followups` list rather than a per-line test. Fix, one line at `Tasks.svelte:39`:

```ts
if (line.kind === 'followup') return 'followups';
```

`kind` is set from the category at `ticker.ts:136-144` (`item(kind, ...)`), it is `'followup'` on every one of the three follow-up loops, and no other line carries that kind, so the test is exact. Not visible on the real hub today: `funding/funding.yml` declares the `followup` field in its schema but no entry carries one (`grep -n followup funding/funding.yml` returns only the schema line). It is latent, not theoretical.

## 4. The six judgment calls

1. **A snoozed undated task entry goes to the snoozed group.** Sound: every other snoozed line in the ticker goes there, and it is the only control that can wake it; the real hub has no snoozed task entry today, so the browser suite's `focus.command.snoozed(1)` count in `tests/browser/focus-buttons.spec.ts:33` is not disturbed.
2. **No glyph on the three group labels, only on the heading.** Defensible from the brief's key list, but it makes "Follow-ups" and "Subtasks" read differently in the section than the identically named groups above it, which carry `grp_followups_glyph` and `grp_subtask_glyph`; reusing those two existing keys needs no new key and would remove the inconsistency, so this is worth reversing.
3. **A teal left border against the Command Center's red.** Sound, a token either way, and it is the only visual cue that the two blocks are different sections.
4. **Row ids prefixed per partial (`r` and `t`).** Sound and necessary: each partial keeps its own index, and no browser selector names a row id (`grep -rn 'data-\|locator(\|getByRole' tests/browser` shows the focus specs select by role and text).
5. **The write path moved into `rows.ts` with the builders.** Sound: `act` is what makes the two partials' buttons provably the same path, and the alternative was a second copy of `write`.
6. **Giving `charlie` a dated follow-up in the view fixture.** Sound: without a dated note the Command Center case proves nothing, since "Follow-ups" is also the section's own label.
