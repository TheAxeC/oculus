## Judgment calls and decisions

1. **Instance key `label`** (ruling 4): the `latex` view's instance state keeps `label`; `row-menu.ts` writes the same label for one folder from both entry points.
2. **The `building` mark applies to a build only.** A clean only watches its terminal, as before.
3. **The 2 MB rule** (ruling 6): a `.tex` file over `OUTLINE_MAX_BYTES` (2 MB) is not read for the outline; the reader sees `not fully read: {file}` under the sections and none of that file's sections or includes. The catalog line `outline_skipped` changed from "not read: {0}" to "not fully read: {0}" because a file the parser refuses now lists the sections the line scan found, so such a file is read in part.
4. **A press on Build replaces an existing entry** for the same main; a save never does, it sets `again`.
5. **The never-named terminal rule** (ruling 17): an entry whose terminal never appears in the `sessions` list ends at the second push that lacks it, so a start whose terminal the server dropped does not hold the main file for good.
6. **Formatting lives in `kit/load.ts`.** `src/lib/ui/controls/editor/kit` holds 10 items, the folder limit, so `createFormatting`, `Format` and `Formatting` are in the kit's loader.
7. **Test helpers.** `tests/state/sessions/latex/latex-fixture.ts` (router, gated stub, folder answer, `eachClient`) is shared by `folder.test.ts` and `building.test.ts`; `folder.test.ts` was split so each stays under 900 lines.
