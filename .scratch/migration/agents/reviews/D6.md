3. THE PREVIEW IN DETAIL

Every piece of HTML the preview draws goes through `src/lib/ui/html.ts`. `Preview.svelte:30` calls `blockMarkdown`, which is `html.ts:259-261` (`sanitise(marked.parse(...))`), and `Markdown.svelte:30` calls `sanitise(doc.html)` again. There is no `{@html}` in `Preview.svelte` itself and no second `marked` import in the view.

The second pass is idempotent, verified rather than argued. I ran a probe under `$TMPDIR` (deleted) that loaded `node_modules/dompurify/dist/purify.js` and `node_modules/marked/lib/marked.umd.js` into headless Chrome (`channel: 'chrome'`, no server, no port), rebuilt `PROFILE` and both hooks exactly as `html.ts:110-152` declares them, and compared `sanitise(once)` with `once` and `sanitise(twice)` over eleven shapes: heading, outward and relative and anchor links, images, a script tag, a task list, a table, a fenced code block, a hand-written `<details>`, entities and an accented letter, an `onerror`/`javascript:`/`<iframe>` sample, and a non-checkbox `<input>`. All eleven were byte-identical at pass 1, 2 and 3. The mechanism is what `html.ts` implies: `markLinks` (`:131-137`) and `dropOtherInputs` (`:140-143`) are `afterSanitizeAttributes` hooks, so on the second pass DOMPurify first strips `target` and `rel` (neither is in `ALLOWED_ATTR`, `:76-87`) and the hook then re-adds them. Concretely, `[out](https://example.com)` came back as `<a href="https://example.com" target="_blank" rel="noopener noreferrer">` from every pass.

A relative image cannot reach a route. The probe confirms `![fig](figures/a.png)` survives as `<img src="figures/a.png">` (`ALLOWED_URI_REGEXP` at `html.ts:94` permits a scheme-less address), and the app has exactly two route shapes, `/` and `/api/*` (`find src/routes -type f`: `+page.svelte` plus `api/<name>/+server.ts`), with no catch-all. A relative address from the SPA at `/` resolves to `/figures/a.png`, which matches no route and 404s; it cannot become an `/api/file/<root>/<path>` request. The one thing that does reach a route is an image whose address the file itself wrote as absolute (`![x](/api/file/hub/x.png)` survives the filter), and that is identical to how every hub README already behaves in the doc view, unchanged by this package.

The scroll fraction. `Editor.svelte:55-64` computes `fraction = scrollTop / (scrollHeight - clientHeight)` on the textarea's scroll event, guarded against a zero denominator; `Preview.svelte:38-43` applies it in a `$effect` that reads `fraction` first and writes `box.scrollTop = at * room`. The effect depends on `fraction` and `box` only, so typing does not re-position the rendered half and scrolling the rendered half does not move the editor. That is the brief's "nothing more", and the worker states it.

The toggle is per instance and defaults on: `source.svelte.ts:103` reads `held.preview !== false`, so an absent field is on, and `toggleSourcePreview` (`:154-156`) writes through `updateDraft`, which is `ui.setInstanceState` (`:107-109`). `Source.svelte:83,87` passes `draft.preview` and the toggle down.
