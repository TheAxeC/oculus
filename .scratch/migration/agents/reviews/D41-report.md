7. Ruling 4's signal. The recording sink holds only the frames the relay sends to the page. The server's `markdown/fs/readFile` is a request of the server to the relay, answered by the relay (`held.ts` `#entryAnswer`), and is not a frame of the page. The test therefore wraps `spawnChild` in `tapped()`: it reads the server's stdout and the relay's writes to its stdin with vscode-jsonrpc's `StreamMessageReader`, and a row waits for messages in this order: the server's `markdown/fs/readFile` of the file (the read the `introduce` ask causes), the `workspace/didChangeWatchedFiles` naming the file (and, for the folder row, the old file as deleted), the server's next `markdown/fs/readFile` of the file, and the relay's answer to it. The last two are needed because the server re-reads the file when it takes the notice; a references request sent before the server has the bytes is answered from the old table. This holds only for the server version in use (0.5.0, `package.json:112`).
8. `RootWatch.#event` keeps a path as Created when a Changed event for it follows in the same quiet (`watch.ts:128-129`). A file written in two steps (created, then written) raises a rename event and then a change event; with the last event winning the file was told as Changed, a type `introduce` does not act on, so whether a created file was introduced would depend on the order of the platform's events. 9. The hooks are `ServerEntry.filesUnder` (`servers.ts:223`, the Markdown entry's lists the Markdown files under a folder with the exclusions `markdownFiles` uses: folders starting with a dot, `node_modules`, links to folders, withheld files) and `ServerAsk.reading?` (`asks.ts`, optional because the YAML entry reads no file). `held.ts` stays free of Markdown names. 10. A folder created on disk is told as Created files only for files the server has not read, and only when the server has read some file (`notices.ts:157-170`): a server that has read nothing builds its table from the disk at its first workspace request. A folder deleted is told as Deleted for the files the server has read under it. The server's reads are what `Notices` keeps as read (`#seen`); the Files view's `goneFiles` removes the old paths from it (`links.ts:144`, `held.forget`).
11. A file the server was told of and does not read costs the rewrite up to `SETTLE_MAX_MS` (2 s); a file told more than 2 s earlier is not waited for. The wait also ends only while no request of the server to the relay is open, so a `markdown/parse` the server begins after the last read and after that check is not waited for. Both are bounds of the wait, not guarantees.
