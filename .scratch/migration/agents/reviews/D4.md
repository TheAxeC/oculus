## Blocking

**B1. The worktree diff is refused for exactly the worktrees this hub makes.** `worktreeDiff` takes no root from the caller and recovers one with `rootOf`, whose rule is "the deepest root wins" and which counts the path itself as a candidate (`src/lib/server/git-write.ts:464-478`: `if (full !== base && !full.startsWith(base + sep)) continue;`). An agent worktree is its own workspace on the `sessions` channel (`src/lib/server/sessions/group.ts:173-178`, "A worktree's is a file, not a directory"), so it is a key of the `git` payload and therefore an allowed root. For `/hub/.agents/worktrees/d4`, `rootOf` returns the worktree itself, `insideWorktrees(path, path)` is false (`src/lib/data/worktrees.ts:52-56`) and `worktreeDiff` answers `that path is not a worktree oculus made under this repository` (`git-write.ts:301-303`). The value needed to fix it is already in hand and thrown away: `DiffSubject` carries `root` (`src/lib/state/repositories.ts:28`) but `worktreeDiffUrl(path)` drops it (`src/lib/state/repositories.ts:24-26, 45`). No test covers a worktree that is also a watched root, which is why it is green.

**B2. The write surface for all eight actions silently widened to every configured root.** `allowedRoots` is built from the keys of the last `git` payload (`src/routes/api/git/+server.ts:12`, `src/lib/server/sessions/hooks.ts:131-137`). Acceptance item 1 put every file-browser root on that payload, so `commit`, `push`, `discard`, `createBranch`, `switchBranch` and the three new actions are now reachable on `~/workspace/cathedra` and `~/workspace/game-engine` (`config/sources.yml:95-97`) whether or not a session ever opened them. Nothing in the brief, the report or DESIGN.md says so, and both module head comments still describe the old surface: `src/lib/server/git-routes.ts:11-12` ("which is the sessions' workspaces, plus the hub itself") and `src/lib/server/git-write.ts:29-31`. This is a user-visible shape change (a `push` control over a repository nobody opened) that belongs in the report and in the DESIGN line.

## 4. Defects in the change

- B1 and B2 above.
- `merge` onto a detached HEAD is not refused: the guard compares the branch name (`git-write.ts:381-383`), and a detached root answers `HEAD`, which matches no branch, so the merge runs and leaves a commit no branch points at. The view offers the control regardless of `git.detached` (`Worktrees.svelte:60-65` disables only on the worktree's own empty branch).
- `merge` takes any name git's `check-ref-format --branch` accepts (`git-write.ts:449-455`), so a hand-posted tag, `@{-1}` or a sha-shaped ref merges; the branch is never checked against `git.branches` or the worktree list. Token plus confirm is the only gate.
- Payload cost: `log`, `branches` and `worktrees` are written straight onto the state with no cap (`src/lib/server/git.ts:109-111`), while the three change lists are clamped to `MAX_ENTRIES` for the reason stated at `git.ts:39` ("One workspace with 4000 untracked files must not become the payload"). A repository with hundreds of branches now puts every one of them on the channel on every two-second re-read, for every root.
- Two different "dirty" predicates, neither visible to the reader: `removeWorktree` refuses on any porcelain output, untracked files included (`git-write.ts:351`), while `merge` ignores untracked by design (`git-write.ts:386`, `tracked()` at `git-write.ts:482-489`). A worktree with a build folder in it cannot be removed from the page and the message says only "holds uncommitted changes".
- The worktree GET computes a whole `GitState` for the worktree (`git-routes.ts:213-216,222-224`), which is seven synchronous `spawnSync` git commands inside the request, and `Diff.svelte` reads only `body.output` (`src/lib/views/repositories/Diff.svelte:66-80`). The brief asked for the state; nothing on the page reads it.
- `busy` is one string for the whole view (`src/lib/views/Repositories.svelte:72` `if (busy !== '') return false;`), but each section is told `busy={busy === root}`, so while one root is writing the controls of every other section are enabled, do nothing when pressed and say nothing.
- After a successful `createWorktree`, a failed shell start overwrites the root's outcome line with the terminal's error (`Repositories.svelte:84-88,102-109`), so the reader sees a failure over a worktree that was made.
- `follow()` reorders only when a root was added or dropped (`watch/git.ts:268-295`), so a reordering of the same set leaves the section order stale.
- Stale comments: `tests/shell/rail.test.ts:737` still says "Five views" over a six-view Sources group; `git-routes.ts:11-12` and `git-write.ts:29-31` as in B2; `tests/views/type-scale.test.ts:132-137` inserts the three `repositories` rows between `radar/Bucket.svelte` and `radar/RadarCard.svelte`, out of the map's order.
