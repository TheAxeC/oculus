4. Defects shown by concrete input

- Input `setFields("meta: []\n", { meta: [] })` returns the original `meta: []` instead of clearing the key. The empty list is converted to `null` only when the current list contains a map, after which equality suppresses the write. The same defect exists in `setEntryFields`. `src/lib/server/yaml-edit.ts:551`, `src/lib/server/entry-edit.ts:427`
- Input `createEntry(..., "venues", { name: "Example", category: "journal" })` succeeds because only `name` is required by the writer, but the registry assigns an empty key and normalization removes the venue. `src/lib/server/writes/entries.ts:179`, `src/lib/data/sources/registries.ts:105`, `src/lib/data/normalise.ts:620`
- With an existing venue `{ name: "A", id: "same" }`, adding `{ name: "B", id: "same", category: "journal" }` is accepted because duplicate detection compares only `name`; normalization then keeps one entity under `same`, overwriting the other. `src/lib/server/writes/entries.ts:189`, `src/lib/data/normalise.ts:83`
