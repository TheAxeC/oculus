## 1. Brief acceptance items not met

**Item 4, `embed_refused`.** The key is absent from `config/text/ui.yml` (the group gained only `embed_page`, `page_leaf_close`, `page_leaf_close_glyph`). The worker's two reasons verify: `tests/keys.test.ts:161-172` fails on a catalog key no source reads, and no pane has a spoken line (the only `said` state in the tree is `src/lib/shell/UpdateTray.svelte:27,136`; `PaneView.svelte` has none). So the brief's premise, "drawn as the pane's said line as other refusals are", names a mechanism that does not exist. Net end state: a page dragged over a pane that would close a loop produces `hover(null)` (`src/lib/shell/PaneView.svelte:170-173`) and the reader is told nothing at all, anywhere. This is a wrong premise, and the ruling that is owed is whether the refusal gets a word (a said line in `PaneView`) or stays silent.

**Item 1, "a drop on its edge splits beside it", at the shell.** The model does it (`src/lib/state/layout/workbench.ts:46-47` `leafAt`, covered by `tests/state/nested.test.ts:72-77`), but no pointer target reports a drop beside a page leaf: `PageLeaf.svelte` attaches no `onpointermove`, and the leaf's area below its header is covered by the nested page's own panes, which report drops in the nested page. The companion half, "a drop on its centre or strip is refused", is therefore vacuous rather than implemented. Item 3 of the brief does not name a leaf drop target, so this is the brief's silence, not a contradiction of it, but the capability the model carries is unreachable.

**Item 2, "the rail passes the page of the pane that holds the keyboard focus".** Implemented as the last pane pressed or focused, kept until its element leaves the document (`src/lib/shell/workbench-keys.svelte.ts:134-137,334-343`). It is never cleared when focus leaves a pane for something outside the trees, which is deliberate per the comment, but it is not the attribute read the brief specified.

## 4. Defects

1. **The drop insertion mark can be drawn in two panes at once.** `PaneView.svelte:112-116` decides the mark with `here(held.drop.path)`, and `here()` (`:142-147`) compares paths only, never `drop.page`. Two panes on screen now legitimately share a path (a host tree `[pane@0, leaf@1]` beside a nested tree `[pane@0, pane@1]`: both panes are at `[0]`), so hovering the nested pane's strip marks the host pane's strip too. Added by this package; no test.
2. **Escape cannot restore a maximised pane inside a nested page.** `workbench-keys.svelte.ts:122-125` guards on `options.focus()`, which `Workbench.svelte:77,96` binds to `focused()` of the page on screen, then calls `restorePanes(pageOf())`. When the maximised pane belongs to the nested page, the guard sees `null` and Escape returns without doing anything, while the same pane's menu does offer restore (`PaneView.svelte:129-131,201-204`, off `focused(page)`). The call was given a page and the guard was not. No test.
3. **A view opened from inside a nested page by a view's own control lands on the host page.** `openInto` resolves `at(undefined)` to the page on screen (`layout.svelte.ts:158,655-656`), and `views/` cannot pass a page. The rail and the key handler pass one; a project card's editor or document link does not. The report names it and proposes the fix (the store remembering the page last acted in); the brief's stated outcome ("a view opened while reading inside a shown page lands in that page") is not reached for that path.
4. **The same page may be shown twice, and its views mount twice.** `embeddable` (`src/lib/state/layout/nested.ts:20-26`) refuses only self, a missing page and a page that reaches the host, so a host may embed the same page at two leaves, or embed B directly and also embed C which itself shows B. Both leaves render B's tree, so one instance id is mounted twice and `Terminal.svelte:205-232` builds one grid per mounted component (the two-clients-per-session consequence is inferred from that effect, not measured). This contradicts the 2026-09-11 decision left standing in `DESIGN.md`. Nothing refuses it, nothing warns, no test.
5. **A page renamed to nothing draws a blank leaf header and a blank fold strip.** `PageStrip.svelte:244` renames with `draft.trim()` and no empty guard; `PageLeaf.svelte:54` and `FoldedPane.svelte:41` print `page.label` raw, while `pane-view.ts` `embedPageItems` numbers an unlabelled page through `t('ui.page_default', at + 1)`. So the menu can offer "Show Page 2 here" and the header that follows is empty.
6. **A stale page id silently acts on the page on screen.** `at()` (`layout.svelte.ts:158`) falls back to `currentPage()` for an id naming no page, so `unembedPage(path, goneId)` and `closePane(path, goneId)` remove a node from the page the reader is looking at rather than doing nothing. The report names the fallback; it is the destructive operations that make it matter.
7. **`closeInstance(id)` with no page now closes an instance on any page**, where before it only touched the current page's tree (`layout.svelte.ts:497-503`, `holding(id) ?? at(page)`). The only caller passes a page (`PaneView.svelte:238`), so nothing is broken today; the widened contract is not named in the brief.

Report claims checked against the tree and matching: the model shape (`model.ts:28-35`), the store's method list and page arguments (`layout.svelte.ts:80-110`), the file line counts quoted (`wc -l`: `layout.svelte.ts` 760, `layout.test.ts` 970, `workbench.test.ts` 658), 26 cases in `tests/state/nested.test.ts` and 4 in `tests/browser/nested.spec.ts`, `clearPage` leaving an empty pane (`nested.ts:88-90`, `layout.svelte.ts:361`), `DropLayer.svelte` reading `dragging()` only. I found no claim in the report contradicted by the code.

The six "wrong, sharp or uncovered" points, judged: (1) a real defect inside the brief's stated outcome, see defect 3; (2) a consequence of the brief's silence about a leaf drop target, see item 1 above, with the model capability left unreachable; (3) a real defect and a clash with `DESIGN.md`, see defect 4; (4) fine, pre-existing between pages; (5) fine, verified; (6) a defect for the destructive operations, see defect 6.

## 5. The eleven judgment calls

1. `embed_refused` left out: **kept as a stop to rule on**. The premise is verifiably wrong, but what ships is a refusal with no word to the reader at any entry, which is the thing to decide.
2. `unembedPage` removes the node while `closePage` leaves an empty pane: **questionable**. Both are within the brief's words ("as a closed pane does" for one, "an empty pane" for the other), but the reader gets two different answers to "this page is no longer shown here": the space closes up in one case and an empty pane sits there in the other.
3. `page_leaf_close_glyph` instead of `page_leaf_glyph`: **kept**; the glyph exists (`config/glyphs.yml:31`).
4. `fold` snippet keeps three arguments: **kept**; `FoldedPane` reads the page from the store instead.
5. `Drop.page` and the sink's `page` optional: **kept**, with the note that an omitted page silently means the page on screen, which is what makes defect 6 possible.
6. `pageOf(id)` and `focused(page?)` added: **kept**.
7. `activateInstance`/`closeInstance` preferring the page holding the instance: **kept**; see defect 7 for the widened contract.
8. `layout/nested.ts` as its own module: **kept**; `model.ts` importing `tree.ts` would be circular.
9. `startPage` armed at once: **kept**; covered by `tests/state/drag.test.ts:167-171`.
10. The rail's page from `WorkbenchKeys.pageOf()`: **questionable**. It answers with the last pane pressed or focused for as long as that element stays in the document, so a rail button pressed long after the reader left the nested pane still opens in the nested page; that is the intent stated in the comment, and it is not the attribute read the brief named.
11. `parseLayout` settling a leaf it may not show instead of refusing the envelope: **kept**; the unknown-page half is tested, the loop half is not.
