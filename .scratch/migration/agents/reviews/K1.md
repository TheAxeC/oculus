## 3. The tab switch

`perform` passes the pane from `focusedPaneElement()` (`workbench-keys.svelte.ts:105`, `:150`), the same pane the cursor keys use.

- Nothing focused: `focusedPaneElement` (`:180-195`) falls to `lastFocusedPane` if still connected, then to the first `[data-pane]` when a focus exists, then to the pane whose `data-pane-active` is the active main tab. So with a cold page it addresses the main pane holding the active tab, never the panel.
- Panel focused: `element.closest('[data-pane]')` returns the panel's pane, `data-pane-target` reads `panel` (`:170`), and `paneAt(layout('panel'), path)` reads the panel tree. Correct per the ruling.
- A text box inside a pane: `closest` still resolves to that pane, so Ctrl plus a digit switches that pane's tab while typing. A text box outside every pane (the palette, the page rename box) falls to the `lastFocusedPane` chain.

A digit past the pane's last tab: `tabs.at(index - 1)` is `undefined`, `activateTab` returns false (`:173`), `perform` returns false, and `keys()` does not call `preventDefault` (`:123`), so the key is not swallowed. Same for no focused pane (`:167`). `pageShortcut` behaves the same way for a page that does not exist (`layout.svelte.ts:312-317`).

Judgment call 1 (`.at()` rather than `item`): correct and required, as set out in section 1. Judgment call 5 (the card cursor cleared at `:174` before `activateInstance`): `clearCursor` writes null to the focused pane's active instance (`:273-275`), which is the tab being left, so its cursor is dropped rather than restored on return. That matches what the `open` action does (`:135`). It is a real, small behaviour change nobody asked for; it is booked and reversible in one line.
