# 4. Defects in the new code

1. **Archived slides are dropped from the deck by any save, silently** (`data/deck.ts:120`, `state/present.ts:348` vs `present.ts:326`, `state/slides.ts:34`). Proven above. This is the one finding I would not land without a ruling.
2. **`setDeckList` corrupts a flow-style `deck:` map and mixes line endings on a CRLF file** (`deck-edit.ts:92-96`), and `writeDeck` writes the result without parsing it back (`writes/deck.ts:58-60`). A round-trip check (re-parse, confirm the two lists and the rest of the map) would fail closed on both.
3. **No error path on the file read** (`writes/deck.ts:56`): a missing `config/present.yml` is an exception, not a refusal, unlike `writes.ts:160-176`.
4. **`WriteTarget.projects` is optional and defaults to none** (`writes.ts:307`, `writes/deck.ts:44-53`). A caller that builds a target from `target()` alone (which does not set it, `writes.ts:126-134`) gets "every deck write refused as `invalid_order`" with nothing saying why. The capability lives in the route (`src/routes/api/write/+server.ts:14-17`) rather than in `target()`, so a second write route would silently lose it.
5. **`OCULUS_CONFIG` is read on every call with no validation beyond existence** (`config.ts:290-293`). A stray value naming a directory that does not exist gives a finding (`config.ts:309`), which is loud enough; a stray value naming an existing directory that happens to hold `.yml` files silently becomes oculus's whole configuration, and the deck write then writes `present.yml` into it. `grep -rn OCULUS_CONFIG` shows it set only by `tests/browser/serve.ts:147`, so nothing on your machine sets it today.
6. **The unsaved-work drop is silent** (`Slides.svelte:58-75`). The signature is the catalog's keys and their order, so a portfolio push that adds, removes or renames a project slide discards a reader's unticks and reorders with no line in the status region. A save's own push does not lose anything: when the order changed the signature changes and the view redraws from the file, which is exactly what was just written; when only ticks changed the signature is unchanged and the work is kept. I traced this by reading the derivations, not by running the page.
7. **`slide_order` is written for the whole catalog, so a project slide added later sorts to the end**, after `closing` (`data/deck.ts:154-162`, unknown keys get `positions.length`). The cockpit does the same (`deck_config.py:87`), so it is inherited, not introduced; it becomes visible the first time anyone presses Save.
8. Cosmetic: `tests/views/type-scale.test.ts:65` gives Slides `.said=fs-xs` while every other view's status line is `fs-md` (`Projects.svelte`, `Venues.svelte`, `Document.svelte` in the same map).
9. Nothing disables Save while the write is in flight (`Slides.svelte:118-129`), where the cockpit set `save.disabled` and `list.inert` (`10-slides.js:110`). Two fast presses send two writes.

Not defects, checked and cleared: the refactor of `deckSlides` into `data/deck.ts` preserves the old semantics (the per-project slide grouping survives because `Array.prototype.sort` is stable and two slides of one project compare equal); `ondragstart` not calling `dataTransfer.setData` matches `EntryCard.svelte:124-126`; `t('slides.kind', row.kind)` with a `'{0}'` template has precedent at `config/text/views/present.yml:4`; `PRESENT.md` reaching `MARKDOWN_DOCS` affects nothing else, since `renderDoc` (`server/docs.ts:132`) is its only reader.
