## 4. Defects in the new code

- **The press waits on the prewarm** (section 1). This is the defect, not a limitation: `routes.ts:29`/`:37` hold the HTTP response for up to 180 s of accounting query plus directory walk, where before this package the same press was bounded by the poll's 40 s.
- **The working-directory marker is double-quoted, so the remote shell expands it.** `prewarm.ts:42` emits `echo "@@oculus:wd=${dir}@@"` while the rung on the next line single-quotes the same value (`prewarm.ts:47`). `safePath` (`actions.ts:5,25-28`) permits `$` and a backtick: `safePath('/work/$USER/x')` returns the string unchanged, `listingCommand(['/work/$USER/x'])` emits `echo "@@oculus:wd=/work/$USER/x@@"`, and `sh -c` on that line prints `@@oculus:wd=/work/axelfaes/x@@`. Two consequences: the section header then names a directory that `dirOf` does not hold, so `prewarm.ts:154` misses and every job in that directory is silently never prewarmed; and a WorkDir containing a backtick or `$(...)` runs a command substitution on the login node inside the prewarm's ssh call. `actions.ts:50` avoids this by single-quoting the remembered path. `hpc.py:456` has the same line, so this is a ported defect rather than an invention.
- **The number of working directories is unbounded against a fixed outer budget.** `prewarm.ts:142` lists every distinct directory of up to 40 recent rows (`parse.ts:133` caps `recent` at 40), each contributing five rungs of up to 15 s (`prewarm.ts:20,47`), against `LISTING_TIMEOUT_MS` 150 s (`prewarm.ts:33`). Past roughly two slow directories the outer timeout kills the call, `run()` rejects (`ssh.ts:37-44`), the whole listing is discarded, nothing is resolved, and it repeats every cycle. Combined with the first defect, a press landing in that window waits the full 150 s. Not named in the report.
- **`prewarmDue` is not cleared on a failed poll.** `poll.ts:138` sets it only on a good poll and nothing resets it, so a prewarm deferred by a queued refresh can later fire after a failed poll and run against the stale `rows` of the last good one (`poll.ts:173`). Harmless in outcome, but it is not what the comment at `poll.ts:164-165` ("the finished jobs of the last good poll") implies about when it runs.
- **Unreachable branch.** `prewarm.ts:60-62` handles a repeated `@@oculus:wd=` header, which `listingCommand` cannot produce because `prewarm.ts:142` deduplicates through a `Set`. Dead by construction.
- **`parse.ts` head comment.** `parse.ts:1` declares the module "Pure SLURM text parsers"; `dateFrom` (`parse.ts:9-13`) is a query-window formatter, not a parser. The cycle the move avoids is real; the file's stated single reason to change no longer covers its contents.
- The gate rework is otherwise sound: `running` is reassigned before any caller can observe the window (`poll.ts:198-206`, single-threaded, no await between `step()` and the assignment); `prewarmStep` cannot reject, so `void hold(prewarmStep)` raises no unhandled rejection; `close()` is honoured at `poll.ts:200` before launching and at `poll.ts:176` before writing, so no path writes to the map after close.
- The shell script is otherwise correct: a directory containing a space survives both the single-quoted rung argument and `safePath`'s trim (`actions.ts:26`); a rung killed by its own `timeout` leaves the marker sequence intact so rung indices stay aligned; an unmatched glob prints itself and is dropped by `prewarm.ts:69`.

## 5. The judgment calls and the named differences

Judgment calls:

1. **Prewarm takes the gate only when no refresh is queued: wrong.** The mechanism is defensible, the justification is false. "As built, a press never waits on the prewarm" is contradicted by the code's own test: `poll.test.ts:170` presses `refresh()` during the held listing and can only settle it with `await vi.advanceTimersByTimeAsync(5000); await pressed;`. The stated reason for choosing shape two over shape one (that shape one would make a press wait on the walk) applies to what was built.
2. **`dateFrom` moved to `parse.ts`: kept.** The cycle it avoids is real (`prewarm.ts:3` would otherwise pull `poll.ts`, which imports `prewarm.ts` at `poll.ts:16`). Cohesion nit in section 4.
3. **`SACCT_TIMEOUT_MS` and `LISTING_TIMEOUT_MS` as constants: kept.** Neither has a config key, and the brief forbids a new one.
4. **`PREWARM_MAX` exported: kept.**
5. **`queueCalls` narrowed to `squeue`: questionable.** Necessary, but it is an existing helper used by pre-existing cases (`poll.test.ts:37-38`), and after the change those cases no longer notice a non-`squeue`, non-`quota` connection opened beside a poll. Only the new case at `poll.test.ts:170` carries the `most` counter that restores that reach. The assertion values are unchanged, so nothing is loosened in the sense the spec forbids.
6. **`TWO_FINISHED` built from `ANSWER` by `String.replace`: kept.** `ANSWER` is untouched and `expect(good.recent).toHaveLength(1)` still measures one row.

Differences from the cockpit:

1. **No `_t` helper: kept.** Consistent with the bare `timeout 20` at `actions.ts:50`, and the consequence on a cluster without `timeout(1)` is stated.
2. **`validId` accepts a step suffix: kept.** Verified harmless: `parse.ts:102-108` folds dotted rows into their base, so no `.batch` id reaches `rows.recent`.
3. **Oculus markers: kept.** Matches `actions.ts:8-9`.
4. **No thread, no 20 s sleep: wrong as reported.** The two halves are not equivalent. Dropping the sleep is free; dropping the thread is what puts the directory walk on the request path (section 1), and the report presents the difference as costing nothing.
5. **Unique-match pick instead of the brief's "newest entry": kept.** `hpc.py:398-405` is the rule the brief itself names, and `prewarm.test.ts:52-69` covers the refusal.
