## First review (2026-09-14 00:10, codex:gpt-5.6-sol read-only, over diff.patch)

1. Acceptance items not met

- The no-globals amendment is not met. Session-change subscribers remain in module-level mutable state, and usage reaches that state through an import instead of context injection: `src/lib/server/watch/sessions.ts:41-46`, `src/lib/server/usage/watch.ts:8`, `src/lib/server/usage/watch.ts:116`.
- Item 4 does not preserve git suggestions for published workspaces outside the hub. The route validates against context-derived roots, but the suggestion path discards those roots: `src/routes/api/git/+server.ts:11-13`, `src/lib/server/git-routes.ts:167-176`, `src/lib/server/git-message.ts:54-56`.
- The claim that behavior is unchanged is not met for terminal listing. Production GET now returns the terminal manager's cached list, while refresh is asynchronous and not awaited: `src/routes/api/terminal/+server.ts:9-10`, `src/lib/server/pty/channel.ts:284-305`.

2. Spec rules broken

- No globals: the mutable `changeListeners` singleton connects session and usage watchers outside `ServerContext`: `src/lib/server/watch/sessions.ts:41-46`, `src/lib/server/usage/watch.ts:116`.
- Catalog strings through `t()`: `notify.stop` is accessed directly in two new call sites: `src/lib/server/context.ts:93`, `src/routes/api/hook/+server.ts:15`.
- No hardcoded config fallback: empty-object fallbacks are supplied for `slurm` and `usage_tiers`, and the HPC route supplies an empty host fallback: `src/lib/server/context.ts:75`, `src/lib/server/context.ts:82`, `src/routes/api/hpc/post.ts:5-7`.
- Other named categories: none.

3. Tests missing

- Context isolation across two server contexts. The boundary check only detects `globalThis` and `declare global`, so it cannot detect the remaining mutable subscriber singleton. This belongs in `tests/server/context.test.ts`; the current static checker is `tests/boundaries.test.ts:128-138`.
- Actual built-server and Vite request propagation into `hooks.server.ts`. The context test calls the carrier and accessor directly and never exercises either entry point: `tests/server/context.test.ts:99-107`.
- Git suggestion using a published workspace outside the hub. The existing route test always injects a suggestion function, hiding the production path. Add it to `tests/routes/git.test.ts`: `tests/routes/git.test.ts:28-38`, `tests/routes/git.test.ts:143-149`.
- GET `/api/terminal` from the context-owned terminal list, including an immediate GET after a POST. The route test imports only `handleTerminal`, not `handleTerminalList`: `tests/routes/terminal.test.ts:23`.
- Socket forwarding of the context token to terminal authorization. The socket fixture supplies no terminal sink: `tests/server/socket.test.ts:27-30`.
- Vite preview request propagation. The adapter emulator is active during preview, but no preview middleware populates its request store. This needs a preview integration test: `vite.config.ts:18-50`, `node_modules/@sveltejs/kit/src/exports/vite/preview/index.js:68`, `node_modules/@sveltejs/kit/src/exports/vite/preview/index.js:207-230`.
