## The `prefer-const` boundary

Right, and it leaves nothing unreported.

Core `prefer-const` reaches the `.ts` globs through `ts.configs.strictTypeChecked`, which carries `@typescript-eslint`'s `eslint-recommended-raw.js:41` (`'prefer-const': 'error'`), not through `@eslint/js` recommended. So the `'prefer-const': 'off'` line in the `src/**/*.svelte` block is the whole of the exemption, and it is correct that it stayed.

`svelte/prefer-const` is the core rule wrapped: `defineWrapperListener` proxies `VariableDeclaration` and skips only a declarator whose init is a call whose callee is one of `$state`, `$props`, `$derived`, or a member of one, then hands every other declaration to the core listener (`eslint-plugin-svelte/lib/rules/prefer-const.js:7-35,68-78`). A plain `let x = 5` in a `.svelte` script is still reported. One false negative exists and is the rule's shape, not this package's: `let x = $state.snapshot(y)` is skipped because the callee's object is `$state`, and such a declaration could be `const`.
