## What to build

1. **(S1) A replace reads the written files' hits again.** The server's `replace` answer carries, beside `paths`, the hits of every written file as they are after the write: the file's matches read with `matchesIn` (one ripgrep over the one file, as the write itself ran), turned into the same hit shape a search answer carries (line, place, length, the line's text cut by `trimAround`, the regular-expression groups) so the page draws them as it draws a search's. `replaceHits` puts each written file's hits in place of the ones it held, in place (the file keeps its position in the list); a file left with no hit leaves the list. A hit the reader dismissed in a written file stays out when the hits read again hold a hit on the same line text at the same place; one whose line the write changed comes back. The focus moves as `rowAfter` moves it today, onto the next row that is left. A Replace Preview open on that file goes on to the hit the focus moved to with the new places.
2. **(S2) Only the cap cuts the answer; a root that ran out of time says so.** `runSearch` no longer sets `truncated` for a timeout; `truncated` means the cap was reached. The failed-roots line says each root with its reason: a root that ran out of time as "{root} ran out of time." and any other as "No answer from {root}: {reason}." (new catalog lines in `search.yml`; the two may be joined into one line for several roots, each root with its own reason). The cap note and the Replace All question's capped sentence follow `truncated` only.
3. **(S3) The Replace Preview opens beside the Search view.** A view opened for something from a tool view lands outside that tool view's pane: `openDiff`, when the Search view asks for the Replace Preview, passes the asking instance, and `openOpened` with an asking instance runs `landingFor` with that instance's pane taken out of every step (treated as locked), so the preview goes to the pane holding the newest opened tab elsewhere, an empty pane, a documents pane, or a new pane to the right of the Search tab's pane, which later previews land in. A preview already open in the Search tab's pane is moved nowhere; the next one opened lands outside it. Opened from anywhere else, `openDiff` lands as today.
4. **(L1) A LaTeX build runs as a task terminal and every refusal of the terminal route is a word.** `startLatex` starts latexmk as a task terminal (a `TerminalJob` of the folder and the build's name, as a project command's is), so `remain-on-exit` holds the pane after latexmk ends, its output stays readable and its exit status is in `exit`. `startTerminal` sets the name option (and the resume option) in the same tmux invocation as `new-session`, joined by `;` as `taskArgs` are, so no option is set by a later call after the session may have ended. The page treats a build as ended when its terminal has left the list or its `exit` is no longer null (`live` in `latex.svelte.ts:383-387`), so a kept terminal ends the build mark. A refused `resize` is said on the terminal tab's bar through `onsay`, and the server answers a tmux failure of the terminal route in a catalog sentence that names what happened ("The terminal has ended." for a session tmux no longer has), never tmux's raw text.
5. **(L2) The folder is read once the build has ended.** `finish` asks again with `queries.refetch(..., 'again')` (or an equal call that sends a request whatever is held), so the read after a build always reaches the server.
6. **(L3) The folder is read again on opening and on a change.** A LaTeX view or project panel being opened (mounted) marks its folder's state, so it is read again. A `files` message marks every held LaTeX folder state whose folder lies under the named root (the root's `dir` from `fs.roots()` joined with the state's `dir`), and a version gap marks every one, as `docs.svelte.ts:208-217` does; a marked state is read again when shown.
7. **(L5) One problem in the singular.** The problems button says "1 problem" and "{n} problems" otherwise (a new catalog line `problem: problem`, chosen by the count).
8. **(L6) Open LaTeX on a folder never expanded.** When the row menu is opened on a folder or root whose listing is not held, `menuOf` reads it with `client.fs.readListing` and rebuilds its items when it lands, as it does for the project commands; Open LaTeX joins the menu when the listing holds a `.tex` file directly in the folder. A read that fails leaves the menu as it was.
9. **(L7) The picture hover draws the picture.** The preview waits for the image to load (`picture.decode()`, a failed decode giving no preview) before the widget is added, and the image's width is held by a length, not a percentage of the box (`max-width:458px`, the box's 480 px less its padding and border; `max-height:300px` stays), so the box is sized around the drawn image.
10. **Docs.** `HELP.md:181` (Dismiss) and `HELP.md:183` say what a Replace does to the hits left in the file, where the Replace Preview opens, and the failed-roots line; `HELP.md:163` says the build's terminal stays after latexmk ends with its output, and the folder is read when the view is opened and when a file in it changes. Every other paragraph and head comment the change makes false is rewritten (the grep spec.md asks for), the head comments of `search.svelte.ts`, `hits.ts`, `latex.svelte.ts:14-40` and `landing.ts:28-38` among them.

## Decisions taken in this brief (each reversible, none silent)

1. The written files' hits come back in the `replace` answer, read by the server right after its write, rather than by a second request from the page: the server already runs the one-file match for the write, and the page gets the hits of the text it wrote, not of a later one.
