## What to build

1. **The display-message answer.** `cursorArgs` asks `#{cursor_x} #{cursor_y} #{pane_height} #{alternate_on} #{alternate_saved_x} #{alternate_saved_y} #{history_size}` and then each flag of `PANE_MODES` (Decision 4). `modesAt` and `screenAt` change to read their parts of the longer answer, each field taken by its position. An `alternate_on` other than `1` (a `0`, an empty field, a word) reads as not in the alternate screen, and the cursor, the height and the flags still read, so the message is the one sent today. The doc comments of `cursorArgs`, `modesAt` and `screenAt` are made true.
2. **The tmux calls and their order.** In the default state (`alternate_on` not `1`) the calls keep the order `list-sessions`, `capture-pane`, `display-message` (`channel.test.ts:137-141`), and the message is the one sent today, byte for byte. When `alternate_on` is `1`, the attach then makes, in this order:
   - the history alone, `capture-pane -p -e -S -<lines> -E -1 -t <session>`, `<lines>` being `this.#lines`; skipped when `#{history_size}` is 0, since with no history tmux answers that range with the alternate screen's top row;
   - the saved normal screen, `capture-pane -p -e -q -a -t <session>`; an empty answer means the editor left between the reads, and the attach sends today's message;
   - the alternate screen, `capture-pane -p -e -t <session>`.

   The first capture (`captureArgs`) is made in both states and is the message in every fallback. The membership check (`channel.ts:606`) comes after the last capture. These capture arguments were measured on tmux 3.7c (`tmux -V`) on a private tmux server, with `-e` for the colours as `captureArgs` has it; the builder confirms them on its own private tmux server and quotes the run (case 10). The new argument builders sit beside `captureArgs`.
3. **The message for a pane in its alternate screen.** The history and the saved normal screen joined, with CR LF line breaks and the final newline dropped, then the cursor placed at `alternate_saved_y+1;alternate_saved_x+1` (a field of 4294967295, which tmux gives when the editor entered with 47 or 1047, means no saved cursor: no placement), then `\u001b[?1049h`, then the alternate capture placed by `screenAt` with CR LF line breaks, then `modesAt`. As the code that builds the expected bytes (the builder's own code may differ):

   ```ts
   const normal = history + saved; // history is '' when history_size is 0
   let shell = (normal.endsWith('\n') ? normal.slice(0, -1) : normal).replace(/\r?\n/g, '\r\n');
   if (savedX !== 4294967295 && savedY !== 4294967295) shell += `\u001b[${savedY + 1};${savedX + 1}H`;
   const message =
       shell + '\u001b[?1049h' + screenAt(alternate, answer).replace(/\r?\n/g, '\r\n') + modesAt(answer);
   ```

   The reset grid takes the shell's text into its normal buffer with the cursor where the shell left it; `\u001b[?1049h` saves that cursor and switches to the cleared alternate buffer, where the editor's screen is drawn full screen; when the editor exits with `\u001b[?1049l`, the grid shows the normal buffer again and restores the cursor to the shell's.

That file is an eleventh item in `src/lib/server/machine/pty/`, which `spec.md:46` refuses, so the folder would have to be split into folders named for what they hold, a move of files and importers this write list does not name. The builder therefore measures first: when `sessions.ts` stays at or under 880, no file is added; when it passes 880, the builder stops before moving any file and hands back the line count with the folder split it proposes, and the orchestrator rules the write list.
5. **G51's test, in `tests/server/machine/pty/channel.test.ts`.** One `it.each` under a new `describe('a page that attaches', ...)`, titled 'gives an attaching page the modes the pane's program set, after the screen', with two rows:

   - no mode set: every flag at its reset value; the message ends with the placed screen and no sequence.
6. **G52's test, in the same file and `describe`.** One `it.each` titled 'gives an attaching page a pane's shell text, then the alternate buffer with the editor's screen', with these rows, each asserting the message's bytes:

Stated with their expected result, with no case:

- A reconnect while the editor is in its alternate screen: the page resets its grid on the message of version 0, and the attach rebuilds both buffers as on a first attach.
- A resize between the reads: `screenAt` places the editor's cursor by the height `display-message` read; the editor redraws on the resize's SIGWINCH, which reaches the page as chunks after the message.
