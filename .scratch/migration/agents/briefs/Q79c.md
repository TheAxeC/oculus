## What to build

1. The rule. 2. The 12 raw controls become primitives, each keeping what it does, its title, its label and its look as closely as the primitive allows:
   - the two two-line session rows (`TerminalRows.svelte:44`, `Project.svelte:145`) and the card's session row (`CardSessions.svelte:76`) are `RowButton`;
   - the stop control (`TerminalRows.svelte:74`), the status words (`CareerPanel.svelte:168`), the priority glyphs and the project name (`LaneCard.svelte:81, 102`), the crosslinks (`CardDetails.svelte:88`, `CardLinks.svelte:117`) and the lightbox backdrop (`Memories.svelte:262`) are `ToolButton` or `Chip`, whichever already draws that look; a look no primitive has is a variant (a prop) of the nearest one, as the gutter's cells are ToolButton's `cell`. A control that wraps markup (a `Tag`, glyphs) is given a `children` snippet on the primitive where it has none.
   - the picture tile (`Memories.svelte:227`) is the primitive it fits, a variant if needed;
   - the picture chooser (`Memories.svelte:196`) is a new `ui/forms/FileChooser.svelte`: a hidden file input with `accept` and `multiple` props, an `onchoose(files)` callback and an `open()` the view calls, with the head comment every primitive carries.

The hand `<img>` string and its escaping go.
4. marked's tokens for the Help view's cut. The manual's answer carries its runs as the server cut them from marked's tokens: a paragraph whose only content is one image whose `href` names `docs/diagrams/<name>.svg` is a diagram part `{ kind: 'diagram', name, alt }`, taken from the paragraph token and its image token; every other stretch is an `html` part.
