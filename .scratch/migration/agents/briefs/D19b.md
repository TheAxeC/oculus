## How it lives in oculus (the three layers, the data live)

**Data.** Claude Code keeps the bars `/usage` shows, per account, in the account file (`~/.claude.json` for `~/.claude`, `<dir>/.claude.json` for every other config folder, the file D19's `claudeAccountFile` already names) under the key `cachedUsageUtilization`, rewritten whenever Claude Code fetches the usage endpoint (the docs: `/usage` shows "the last usage bars it loaded on this machine"; observed on this machine fetched at 12:24 and 17:20 today without `/usage` being run, so the CLI refreshes it on its own). Its shape, read on 2026-09-13 at 17:55 (read only these keys, nothing else in that file):

```json
{ "fetchedAtMs": 1789312845152,
  "utilization": {
    "five_hour": { "utilization": 26, "resets_at": "2026-09-13T17:00:00.183018+00:00" },
    "seven_day": { "utilization": 3, "resets_at": "2026-09-14T20:00:00.183039+00:00" },
    "limits": [
      { "kind": "session", "group": "session", "percent": 26, "severity": "normal", "resets_at": "2026-09-13T17:00:00.183018+00:00", "scope": null, "is_active": true },
      { "kind": "weekly_all", "group": "weekly", "percent": 3, "severity": "normal", "resets_at": "2026-09-14T20:00:00.183039+00:00", "scope": null, "is_active": false },
      { "kind": "weekly_scoped", "group": "weekly", "percent": 6, "severity": "normal", "resets_at": "2026-09-14T20:00:00.183244+00:00", "scope": { "model": { "id": null, "display_name": "Fable" }, "surface": null }, "is_active": false } ] } }
```

`severity` is `normal`, `warning` or `critical`; `resets_at` is ISO-8601; `limits` may hold other kinds (ignore them) and the whole key may be absent (an account that never fetched). The Gmail account's copy today reads session 19, weekly_all 87 (warning), weekly_scoped Fable 93 (critical, active), fetched 12:24.

**Code.** `server/usage/accounts.ts`: `claudeAccount` (or a reader beside it) returns the bars from `limits`: `session` is the `five_hour` window, `weekly_all` the `seven_day` window, `weekly_scoped` a `weekly_model` window carrying `scope.model.display_name` as `model`; each with `usedPercent`, `resetsAt` (Unix seconds from the ISO string), `severity`, `active`, and the account carries `fetchedAt` (ISO from `fetchedAtMs`). `UsageWindow` in `data/model.ts` gains `name: ... | 'weekly_model'`, `model?: string`, `severity?: 'normal' | 'warning' | 'critical'`, `observedAt: string` (the cache's `fetchedAt`, or the status file's mtime). Per account the windows are merged: for `five_hour` and `seven_day`, the observation with the later `observedAt` wins between the cache and D19's `latestWindows` over the status files (a status file older than the cache loses); `weekly_model` comes from the cache only. The `five_hour` window is always present on a Claude card: when neither source has one, `usedPercent` 0, `resetsAt` 0, `observedAt` empty, and the view says `usage.no_window`. `server/usage/watch.ts` also watches each Claude account's account file (`fs.watch` on the file's folder filtered to its name, since the CLI rewrites the file whole), so a fetch by the CLI reaches the view without waiting for the clock.

**View.** `views/Usage.svelte`: the windows in the order 5 hour, 7 day, then each model week (`usage.weekly_model`: "{0} this week"); the meter's tone from `severity` when present (`normal` green, `warning` amber, `critical` red) and from the 75 and 90 thresholds otherwise; the text `{percent}% | resets in {duration}`, or `usage.no_window` ("no window open") for the empty 5-hour; under the windows one muted line `usage.observed` ("as of {0}", the clock time of the newest observation). Codex cards unchanged.

## Decisions taken in this brief (each reversible, none silent)

1. The cache in the account file is the primary source for the bars; the status-line files stay for the live sessions and as the fallback for the two windows.
2. The 5-hour window is drawn even when no window is open.
3. Severity from the cache colours the meter; the thresholds stay for observations without one.
