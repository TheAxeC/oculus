## What to build

1. **The manifest editor.** `Editor.svelte`'s edits live in the instance state (a state module in `src/lib/state/`, the way `state/source.svelte.ts` keeps the source draft), so a tab switch and a reload keep them; Revert and a successful save clear them; the module's `dirty(id)` is registered with `registerUnsaved` in `state/context.ts`.
2. **The entry form.** Its typed values survive a tab switch and a reload, and the tab that holds a form with a typed value asks before it closes. The form knows which instance holds it without its thirteen callers changing: `shell/PaneView.svelte` puts the id of the instance it mounts into a component context (a small module beside `state/use.ts`, for example `state/instance-context.ts` with `provideInstance` and `useInstance`), and `EntryForm.svelte` reads it. A form's draft is keyed by the instance, the collection and the entry's id (or `new` for an add form), kept through the instance state of that instance under one key the host view does not use (read how host views write their own instance state first, and choose a way no host's write overwrites; say which), cleared on save, on cancel and on close; a registered report says whether an instance holds any form draft with a typed value that differs from the entry.
3. **The confirmation.** Closing a tab with either kind of draft asks through the existing guard; nothing else of the guard changes.
4. **A form outside a pane** (no instance in context) behaves as today and registers nothing.
