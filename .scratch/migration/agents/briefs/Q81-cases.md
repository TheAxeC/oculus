Every rule of the brief and the spec still holds.

1. **Case 5.** Ruled (a). The selected row's announcement is the Command's: `aria-activedescendant` on the input, set in the page. It is a look case: at the landing, the input's `aria-activedescendant` names the selected row and follows ArrowUp, ArrowDown, Home and End. Writing the selected id by hand, on the input or the list, is not done: it is the hand selection item 8 removes.
2. **Item 6, Escape on the key sheet, the palette and the update tray.** The builder's proposal is ruled in, with one addition. The three overlays close through bits-ui's own Escape layer, calling the `onclose` the shell passes them; a Confirm inside the tray takes the first Escape as the topmost layer, and the next Escape closes the tray. The addition: the shell's Escape branches for those three overlays in `shell/keys/workbench-keys.svelte.ts` (the sheet's Escape, the palette's Escape and the tray's Escape, `:70-108`) no longer close anything once bits-ui prevents the key, so they go, with the tests that assert them, and every other key there stays: `?` for the sheet, Cmd-K, `:`, and the sheet's early return that keeps other keys from the workbench while it shows. The report states the before and after of Escape on each overlay.
3. **Case 10, `aria-describedby`.** Ruled as the builder reads item 4: the always-on description of the wrapped control stays through `tip-ids.ts` and `tooltip-target.ts`, proven by `describedBy` and `describedControl` as today, since bits-ui gives it only while open and only on its trigger. The server test for "the wrapper is the trigger" stays as written.
