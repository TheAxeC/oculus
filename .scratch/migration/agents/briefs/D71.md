## What to build

Nine parts, each ruled (plan.md, Rulings: open items 66, 67, 68, 69 and 70, "D71 a step of its own", "Open item 67's design", "Manifest placements unified", "Deposit for every project", Z849 to Z853). Behaviour that exists today stays, except where a part below changes it.

1. **One saved layout per workspace (open item 66 (a)).** The layout, its unread copy and its writes record are kept per workspace: the key carries the workspace's identity, the open workspace file's real path, or `unsaved` for the unsaved workspace. No key is read until the workspace answer has come; a failed answer reads the `unsaved` key. Opening a workspace (Switch, Save As, New, Close, or a move another page or window made, which every page learns from the workspace answer) saves the current pages under the workspace being left and shows the pages saved for the one opened, or the default arrangement for one never opened; Save As carries the pages it leaves to the file it makes. The storage event follows the open workspace's key, and the desktop host's turn on a save covers the per-workspace key the same way. No code reads `oculus.layout.v1` under its old meaning (no migration code): the value saved today is renamed once at landing by the orchestrator, outside the code (open item 70 (a)), so the report names the exact key the research-hub workspace's layout is read from.
2. **`:workspace-close` and `:workspace-new <name>`.** Close Workspace leaves the open workspace file and returns to the unsaved workspace with no folder, as VS Code's Close Workspace does; the workspace file is not changed. New Workspace writes an empty workspace file `folders: []` as `.oculus/workspaces/<name>.yml` of the primary hub (else the first hub), under the name rules and refusals of Save As (no name, a bad name, a name held, no hub, unwritable), and opens it. Both are named actions of `POST /api/fs`, handled before `act`'s last line, palette commands with labels in `app.yml`, and items of the Files view's `...` menu beside Switch and Save. HELP.md's workspace bullet says so.
3. **The usage sessions out of every list.** The transcript reader reads the `agent-name` record and leaves out of every list of sessions and transcripts (the Sessions view, its counts, the Agents and Timeline readers, search) each transcript whose agent name starts with `USAGE_PREFIX`. The usage spend keeps counting their tokens, since the refresher's runs are real spend. The 40 transcripts on disk are not touched.
4. **The deposit (open item 68 (a), "Deposit for every project").** The Deposit view gains, for its mirror: a diff per changed file of the sync plan, opened in oculus's diff editor (the mirror's `HEAD` text against the synced text, both served by the deposit route); Fetch (`git fetch origin` in the mirror); how far the current branch is ahead of and behind `origin/main`, shown in the view; and the list of files that differ from `origin/main`, each opening its diff. Every project is eligible: `depositFor` and `projectIds` find projects through the reader the portfolio uses (`readHubManifests`, scan projects and workspace-folder projects alike), and `code` is `code/` of the project's folder (`manifestDir`), never of `.oculus`. The project view passes the deposit for every project, and the card's comment says so. A project's workbench holds the Deposit view, opened for that project, as a tab of its tool pane after `repositories`, when the project has a deposit: its folder holds `code/`, or its `code_availability` names a `repo` or a `url`; a workbench of a project without one, or of a folder alone, has no such tab, and Reset of a project's workbench gives the tab back. The mirror stays in `~/.oculus/deposits`. `deposit.ts` stays under 880 lines: the new git reads go to a module of their own.
5. **Projects in either placement ("Manifest placements unified", Z849).** A project is a folder holding `project.yml` at its top or `.oculus/project.yml`, for a folder a hub's scan reaches and for a folder of the workspace alike. The scan walk tests both (it still enters no dot folder); a folder that is a hub (holds `.oculus/config/`) is never a project, in the walk (a hub scanning `dir: .`) as on the workspace; a workspace folder that is no hub is a project when either file is there, and `project_in_hub` holds for either file, its text saying so. A folder holding both is read from its top `project.yml`, and its `.oculus/project.yml` is a finding naming both files (new text in `findings.yml`). Every project placed today keeps its id, folder and behaviour.
6. **Scan depth per workspace folder (open item 67 part 1).** A folder entry of a workspace file may carry `repository_scan_depth`, a whole number from 0 up or -1 for no limit; the Repositories view looks for repositories under that folder down to it, a folder without one uses the global `repository_scan_depth`, and a repository cloned or initialised under a -1 folder while the server runs is found. A value that is no whole number, or below -1, is a finding on the workspace file naming the entry, and the global value holds for that folder. The walk with no limit still skips links, `.git` and the ignored folders. The folder writer (`writes/config/lists/folders.ts`) and Save As keep the key on every entry they carry; the unsaved workspace takes no depth. HELP.md says a folder of projects is read as a hub whose `.oculus/config/sources.yml` scans `dir: .`.
7. **The `repository:` block and Clone (open item 67 parts 2 to 4, Z851, Z852).** A manifest may carry `repository:` with `url`, `visibility`, `description`, `homepage`, `topics`, `date` and `clone_dir` (a path relative to the project's folder; default `.`, the folder of the project.yml; `..` segments are allowed while it stays inside the hub's folder for a hub project or inside the workspace folder for a folder project, and one that leaves it is a finding and gets no Clone). It is in `config/schemas/manifest-schema.yml` with labels and help, apart from `code_availability`, which stays the deposit. A project whose `clone_dir` holds no `.git` is not cloned: its card's menu and its project view offer Clone, which clones into `clone_dir` with no question. A missing folder is made; into a folder that holds files Clone runs `git init`, `git remote add origin <url>`, `git fetch origin`, then `git checkout -t origin/<default branch>` (the default branch read from `git ls-remote --symref origin HEAD`; a remote with none is refused in a sentence); a repository that tracks a file the folder already holds is refused before the checkout, naming each such file, and leaves the folder as it was (the `.git` it made removed); a url that does not answer is refused with git's sentence. When `clone_dir` lies inside a hub's folder and the hub is a git repository, oculus writes into the file `git rev-parse --git-path info/exclude` names (making its folder when missing) the line `/<clone_dir from the hub>/*` and, when the project.yml lies inside the clone, the line `!/<path of the project.yml from the hub>`, each escaped by gitignore's rules and written only when the file does not hold it already, so the hub's git shows neither the clone nor its files and keeps tracking the project.yml; `.gitignore` is never written, and a hub that is no git repository gets no exclude and the clone goes on. A cloned project's repository is on the git channel whatever the depth of its root, so the Repositories view lists it; a project not cloned is not listed there.
8. **Clone from GitHub (open item 67 part 5, Z852).** `:clone` is a palette mode whose rows are the account's GitHub repositories (`gh repo list --limit 1000 --json name,url,visibility,description,homepageUrl,repositoryTopics,createdAt`), with a row that takes a typed URL; it is also Clone Repository... in the Repositories view's `...` menu. A chosen repository asks the project's parent folder through the system's folder panel (as Add Folder does), starting at the primary hub's `new_project_dir.personal`; the project folder's name is the repository name lowercased, each character outside `a-z`, `0-9`, `.` and `-` made `-`; its `project.yml` is written there (decision 8 gives the fields) and the repository then cloned into it as part 7 says. A chosen folder under no scan folder of a hub is added to the workspace as a folder (`{ name, path }`, the folder's name) with its `project.yml` at its top. A project folder that exists, a name an existing project or workspace folder holds, and a cancelled panel write nothing, the first two said naming the folder or the name. A `gh` that is missing, or not logged in, is said in a sentence naming `gh auth login`, and nothing is written.

## Added during the build: a moved project folder keeps its clone hidden

Axel asked whether the hidden clone stays hidden when a project folder is moved. Under item 7 as written it does not: the exclude lines are written once at Clone with the path of that moment, so after a move the hub's git shows the clone at its new place and keeps a line for a path that is gone. This addition replaces that part of item 7, and the paths this step writes widen to `src/lib/server/files/fs/ops.ts` and its tests.

10. **The exclude lines follow the manifests.** oculus owns one block of the hub's exclude file (the file `git rev-parse --git-path info/exclude` names), between the line `# oculus: cloned projects, rewritten from the manifests` and the line `# oculus: end`. Whenever the hub's projects are read and the lines the block should hold differ from the lines it holds, the block is rewritten from every project of the hub whose `clone_dir` holds a `.git`: the `/<clone_dir from the hub>/*` line and, when the project.yml lies inside the clone, its `!/<path of the project.yml from the hub>` line, escaped as item 7 says. Clone writes no line of its own; it triggers the same rewrite. Lines outside the block are never changed, and a block that is missing is added at the end of the file. A project folder moved or renamed through the Explorer, Finder or a shell then gets its lines at its new path and loses the old ones at the next read, and a project removed loses its lines. A move or rename through the Explorer (`server/files/fs/ops.ts`) of a folder holding a project.yml whose `clone_dir` leaves that folder rewrites `clone_dir` so that it names the same folder from the new place, in the same History entry as the move, so Undo restores both; a move outside oculus leaves `clone_dir` as written, and the project then reads as not cloned, with Clone offered.
