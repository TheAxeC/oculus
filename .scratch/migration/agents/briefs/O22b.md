# Brief: O22b, the career panel

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md` lines 121 to 141 (Layer 1: one source module per kind of file, each unit-tested against synthetic fixtures; validate and normalise; the snapshot) and lines 168 to 187 (Layer 3 and the boundary table). The cockpit's Focus tab ended in a "Career strategy" panel over the hub's `CAREER.yml` (`render/focus.py` lines 18 to 143, the cautionary reference for which facts it showed); O22 built the Focus board without it because no source module reads that file. This package adds the source, the model, and a view of its own.

## What to build

Under `tools/oculus/src/lib/data/`:

- `sources/career.ts`, new: `readCareer(hub, file)` returning `{ career: Record<string, unknown> | null; findings: Finding[] }`, the pattern of `sources/registries.ts` lines 44 to 70 (`readFile`: unreadable, unparsable, not a map). A file that does not exist answers `null` with no finding, since the panel is optional and a hub without one has nothing to say; a file that exists and is broken is a finding. `file` is hub-relative, `CAREER.yml` by default.
- `model.ts`: `PortfolioConfig` (lines 440 to 446) gains `career: string` (the path), filled by `portfolioConfigFrom` (`index.ts` lines 76 to 104) from `career_file` of `sources.yml` line 82 with the default `CAREER.yml`; `RawPortfolio` (lines 406 to 417) gains `career: Record<string, unknown> | null`; `Entities` (lines 448 to 460) gains `career: Career | null`; and the model gains `Career = { title: string; milestone?: string; situation: { label: string; value: string }[]; order: { task: string; when?: string; note?: string }[]; orderNote?: string; hosts: Host[]; hostCriteria: string[]; notHosts: { who: string; why?: string }[]; eligibility: { rule: string[]; shots: string[]; caveat?: string } | null; dropped: { what: string; why?: string }[] }` and `Host = { name: string; inst?: string; tag?: string; status: string; scores: Record<string, string>; note?: string }`, `scores` keyed by the `field` of `career_score_dims` (`vocab.yml` lines 216 to 222), read off the host row's keys of those names. `buildPortfolio` (`index.ts` lines 121 to 136) reads the file and passes it through; `validate` (`validate.ts` lines 340 to 360) reports a host whose `status` is not a key of `career_host_status` (`vocab.yml` lines 206 to 212; the vocabulary reaches the rules through `Vocabulary`, which gains `hostStatuses: string[]` the way `chips` is filled) and a `situation` that is not a map; `normalise` (`normalise.ts` line 429 and the entities at 477) fills `entities.career`, every field from the key of the same meaning and a malformed value dropped as `str()` drops one, a host's `note` stripped of a leading `[...]` score prefix as the cockpit strips it (`focus.py` lines 62 to 66).

Under `tools/oculus/src/lib/state/`:

- `career.ts`, pure: `hostStatuses(config)` (each `career_host_status` row as `{ key, label, glyph?, tone }`, the icon dropped since it is a character rather than a `glyphs.yml` name and the colour a tone through `state/tones.ts`); `scoreDims(config)`; `scoreTier(value)` (`strong` for strong or high, `good` for good, med-high or high clout, `weak` for a value starting with weak, else `mid`, which is `focus.py` lines 18 to 27); `inFlight(hosts)` (the count with status `awaiting` or `warm`); `awaitingHosts(career)` (the hosts with status `awaiting`, for the Focus strip's "Host outreach" segment, `focus.wait_hosts`).

Under `tools/oculus/src/lib/views/`:

- `Career.svelte`, new, registered as `career` in `routes/views.ts` after `focus` (lines 50 to 56), listed, added to `layout.yml`'s boards group after `focus` (line 19): a view of its own rather than a section of `Focus.svelte`, which is at 762 lines and may not import another view. It draws, from `entities.career` through a selector `career()` added to `state/selectors.svelte.ts` beside `configMap()` (line 49): the title and the milestone line (`focus.next`, the deadline glyph); the situation as a label and value strip; the order of work as numbered rows with the `when` as a chip and the note beside the task; the host pipeline (`focus.host_pipeline`, with `focus.in_flight` on the count) as one row per host: rank, name, institution, tag, one `Chip` per score dimension carrying the badge and the value with the tier as its tone, the status as a `Chip` in the status's tone, and the note under the row inside a `details`; the criteria list; the not-hosts as chips with their reason (`focus.not_hosts`); the eligibility section (`focus.eligibility`): the shots as chips, the rules as a list, the caveat as a line; the dropped section (`focus.dropped`) as chips with their reason. ## Facts checked on the tree, 2026-09-11

- `CAREER.yml` is 70 lines at the hub root: `title`, `milestone`, `situation` (a map of four), `order` (five rows with `task`, `when`, optional `note`), `hosts` (fifteen rows with `name`, `inst`, `tag`, `status`, `proposal`, `ai_fl_clinic`, `backing`, `after`, `note`), `host_criteria` (five strings), `not_hosts` (five `{ who, why }`), `eligibility` (`rule`, `shots`, `caveat`), `dropped` (eight `{ what, why? }`). `sources.yml` names it as `career_file: CAREER.yml` and `tests/config.test.ts` lists that key; no module reads it.
- `vocab.yml` holds `career_host_status` (five statuses with icon, label, colour) and `career_score_dims` (four dimensions with `field`, `badge`, `label`).
- `Focus.svelte` is at 762 lines and `state/focus.ts` at 776; the awaiting strip already draws `wait_people`, `wait_review` and `wait_blocked` segments and none for hosts.
- The `focus` group of `text.yml` holds the panel's words from the cockpit; `t()` interpolates `{0}` and renders text, so `in_flight` (`" - {0} in flight"`) is used as it is.
