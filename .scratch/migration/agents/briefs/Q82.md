## What to build

1. **Dependencies.** `@zag-js/tree-view` 1.44.0, `@zag-js/svelte` 1.44.0 and `@tanstack/virtual-core` 3.17.11 as `dependencies`, `package-lock.json` updated by `npm install`.
2. **TreeView on zag's tree-view machine.** `ui/tree/TreeView.svelte` keeps its props (`label`, `rows`, `current`, `onfocusrow`, `ontoggle`, `children(nav)`) and every caller's composition, and runs `@zag-js/tree-view`'s machine through `@zag-js/svelte` (`useMachine`, `normalizeProps`, `connect`). Its collection is built from `rows` (each row's `parent` placing it), so a caller's rows remain the one statement of what is drawn. Expansion is the caller's: the machine's expanded value is read from each row's `open`, and a change the machine asks for calls `ontoggle(id)` for the row it changes, never for a `fixed` row. The focused row is `current` when given, else the machine's own; a focus move calls `onfocusrow(id)`. The keyboard is the machine's: Up, Down, Home, End, Right (opens a closed row, steps into an open one), Left (closes an open row, steps out to its parent), and type-ahead (a letter moves to the next row whose label starts with it), a `fixed` row stepped through and never opened or closed, Enter pressing the row's button as today, the tree one stop of the focus order. Selection stays the caller's, as each view draws `selected` today; this step adds no multi-select or rename (X3a's).
3. **TreeNav and TreeItem.** `TreeNav` becomes what a row spreads from the machine: the item or branch-control attributes and handlers for a row id (its role, level, tabindex, expanded and selected state, the handlers), and the label the type-ahead reads. `TreeItem.svelte` spreads them when given a `level`, and keeps every other behaviour DESIGN.md:309 states: the fixed-height line, indent guides, arrow, glyph, name, detail, controls at tabindex 0 only while the focus is in the row, the count or mark, selected and current, the tooltip on pointer hover only. Callers keep passing `nav` through unchanged. `tree-keys.ts` keeps `KeyRow` and whatever the machine does not do; `rowMove` and `stopOf` go with their tests if the machine answers all their keys. `TreeSection.svelte` and `Disclosure.svelte` follow the new `TreeNav` where they read it.
4. **Virtualized lists.** The three unbounded lists draw only the rows in view, through `@tanstack/virtual-core` driven from `$state`: the Files tree's rows, the Repositories view's changed files, and the commit graph's loaded commits. Each list keeps its place in its view (the view's own scroll box scrolls, with the rows above and below the list in it), so the virtualizer reads the pane body that scrolls, with the list's offset in it as its scroll margin, and the list's full height is kept by spacers so the scrollbar and the rows after the list are where they are today. The row height is the `--tree-row` height as drawn at the current text scale, read from the page, not a constant. A few rows are drawn past each edge (overscan). A key that moves the focus to a row not drawn scrolls it into view first, through the machine's `scrollToIndexFn` handing the move to the list that owns the row, then focuses it; the "more" row of the graph and every row's drag keep working on the rows drawn.
5. **Drag.** Row drag stays on `drag.svelte.ts` and the views' handlers, unchanged; the machine's pointer handling does not start or cancel a drag.
6. **Documents.** DESIGN.md:309 says the tree runs zag's tree-view machine through `ui/tree/TreeView.svelte`, names the keys with type-ahead, and says which three lists draw only the rows in view; HELP.md's key table gains a row for a tree: arrows, Home and End, and a letter to go to the next row starting with it. `npm run diagrams` rerun.
7. **Tests.** The tests listed above are brought to the new code; every case below that a server render or a pure function can show is a test naming the revert that turns it red; a case only a browser shows (a key, a focus move, a scroll) is stated in the report as left to the landing's look, since this project's tests render on the server and this step adds no DOM test environment.

## Cases

1. A `TreeView` over rows `a` (open), `a/b` under `a`, `c` renders `role="tree"` with its label, and each row drawn in it renders `role="treeitem"` with `aria-level` 1, 2, 1 and `aria-expanded="true"` on `a` (server render).
2. Exactly one row renders `tabindex="0"`: `current` when given and drawn, else the first row; every other row `-1`.
3. A row whose `open` is false renders `aria-expanded="false"`; a row with no `open` renders no `aria-expanded`.
4. The collection built from rows `a`, `a/b` (parent `a`), `a/b/c` (parent `a/b`), `d` holds `a` with child `a/b` with child `a/b/c`, and `d` at the top, in that order (a pure function, tested without a DOM).
5. A `fixed` row asked to toggle by the machine calls no `ontoggle` (the function that turns the machine's expanded change into `ontoggle` calls, tested without a DOM).
6. An expanded change from `[a]` to `[a, c]` calls `ontoggle('c')` once; from `[a, c]` to `[c]` calls `ontoggle('a')` once.
7. The virtual window over 1,000 rows of 22 px in a 440 px box scrolled to 2,200 px with an overscan of 5 draws rows 95 to 125 and keeps the list's height at 22,000 px (the range function or the virtualizer's own range, with the spacer heights, tested without a DOM).
8. The Files tree, the changed files and the commit graph each render through the virtualized list (server render shows the spacer structure, or an audit of the markup, named as an audit).
9. `grep -rn "rowMove\|stopOf" src` prints nothing if item 3 removed them; `grep -n "zag\|virtual-core" package.json` prints the three under `dependencies`.

## Decisions taken in this brief (each reversible, none silent)

1. `TreeView` keeps its props and its `children(nav)` composition, so the Repositories view's section components keep drawing their own rows; virtualization is done in the three lists that grow without a cap, not in `TreeView`, since a composed tree has no single list of rows to window.
2. The three lists virtualized are the ones with no cap on their rows (Files tree, changed files, commit graph); every other tree list (bookmarks, notes, workspaces, pages, branches, tags, stashes, worktrees, repositories) is drawn whole.
3. Selection stays with each view; the machine's selection is not used for drawing in this step.
4. The row height is read from the drawn row, so a text scale change keeps the window right.
