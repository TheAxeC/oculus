## Ruling A: the mode reaches SvelteKit's post-build worker (A1)

SvelteKit's analyse worker loads the config with no mode (`@sveltejs/kit/src/core/postbuild/analyse.js:42`), which resolves `process.env.MODE ?? 'production'` (`core/config/index.js:192`), and the worker is forked with a copy of the parent's environment (`utils/fork.js:38`); so `vite build --mode app` alone fails with `ERR_MODULE_NOT_FOUND .../.svelte-kit/output/server/internal.js`.

- `vite.config.ts` sets `process.env.MODE = mode` when the mode is `app`, with a comment that says SvelteKit's analyse worker reads the mode from there, naming `analyse.js:42` and `config/index.js:192` by file. The command stays `vite build --mode app` everywhere, typed by hand or run by `buildServer`.
- This replaces the sentence of decision 2 and item 1 that no environment variable is needed: the folder names are still read from the mode alone, and the one variable set is SvelteKit's own, set by the config for its worker. No code of oculus reads an environment variable for a folder name.
- A2 (`MODE=app` beside `--mode app` at each caller) is refused: a hand-typed `vite build --mode app` would still fail. A3 (`--mode app` alone) is the lazy option: it does not build.

## Ruling B: the tsconfig under the mode `app` (B1)

- Under the mode `app`, `vite.config.ts` points Vite at `.svelte-kit-app/tsconfig.json` through Vite 8.3.0's `tsconfig` option, so the app's build reads no file under `.svelte-kit/`. `tsconfig.json` is not changed, and `npm run check` keeps working on a fresh checkout.
- SvelteKit's notice "Your tsconfig.json should extend the configuration generated by SvelteKit:" (`write_tsconfig.js:187`) stays in the app build's output; no SvelteKit, Vite or `buildServer` option turns it off, and no code filters it. Case 1's requirement is reworded: the build exits 0 on a tree with no `.svelte-kit/`, reads no file under it, prints no line about a missing tsconfig, and leaves `ls -d .svelte-kit` failing after it. The report states the notice as a host-visible fact of the app's build, with the number of times it prints.
- B2 (the `extends` array) is refused: `npm run check` fails on a fresh tree (TS5083). B3 (B2 plus `MODE=app svelte-kit sync` in the checks) is refused: every check would write the app's folders and the type check would read a second generated tree that goes stale.
