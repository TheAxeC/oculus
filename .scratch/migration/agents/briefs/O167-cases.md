6. Item 15, panes halving. The width a pane has on screen comes from the shell: the pane component measures its own width with a `ResizeObserver` and writes it into a runtime map of the layout store, keyed by pane id, never saved with the layout and dropped when the pane closes. `landingFor` and `openOpened` read that map and the text size. The builder names in its report the files this touches (the pane component, the layout store's construction, `src/lib/state/workbench/layout/access.ts` or the module that holds the landing rules), and each is added to the path list. A pane with no measure yet counts as wide enough, so a page that has not drawn yet opens as today.

8. Item 11, unsaved counts. The typed record of a Settings field carries `refused: true` while the row's writer refuses its text, set by the control that receives the refusal and dropped on the next keystroke; `settingsTyped` does not count a record that carries it or whose text is empty. The record is oculus's own saved layout state, which no person edits, so the key is an internal shape.
