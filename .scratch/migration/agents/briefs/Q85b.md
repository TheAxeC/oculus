## What to build

1. **The rule is Q85a1's, as Q85a2 and Q85a4 apply it.** A schema goes where a map or a list that came from outside the page's own code (a socket frame, a server's answer, browser storage, a tab's saved instance state, the merged configuration, an entry's fields) is read for its named fields or its items. The schema is a `const` beside the function that reads, in that function's file, named in lower camel case ending in `Shape`, built once at module level; a schema whose answer has a declared type is held to it with `satisfies z.ZodType<...>`. The function answers, for every input, what it answers on main, except the changed answers item 15 names: the same value, the same null, the same fallback, the same keys, absent keys absent, the same thrown or answered sentence. zod's own error text is never shown or logged, and no `.issues`, `.error` of a parse, `prettifyError` or `treeifyError` is read. A reader that hands on an object or a list it was given answers the input value itself (`unchanged`), so its identity, key order and keys the schema does not name all stay. A hand check moved into `z.custom(...)` or `.refine(...)` where a shared helper (`anyNumberShape`, `mapShape`, `filledTextShape`, `wholeShape`, `stringItemsShape`) or a zod type expresses the test is a hand check still, and fails the step; each converted reader's answer is built from `safeParse(...).data` or `readAs(...)`, and the reviewer reads the diff for it. The five answer-keeping rules of Q85a4's brief hold here unchanged: a whole number is tested as the hand code tests it (`Number.isInteger`, `Number.isSafeInteger`, never `z.int()`); a `typeof === 'number'` test keeps `NaN` and the infinities accepted (`anyNumberShape`); an optional field is `.optional()` where the hand code refuses `null`, and a field read with a fallback for any other value is `.catch(<fallback>)`; a raw `a ?? b` and a helper fallback keep their own forms; keys read from a map come from the input's own keys in their order, never from `z.record`'s `data`.
