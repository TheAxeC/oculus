## The acceptance list

1. **The form variant.** `shared/EntryForm.svelte` takes `surface?: boolean` (default `true`); with `surface={false}` the form paints no background and no wall rule applies to it (the two rules under a class the prop sets), its border and padding kept so the fields still read as one block. Every other renderer is unchanged and renders as before (`tests/ui` and `tests/views` green with no expectation changed).
2. **The Files pane tinted.** `views/Files.svelte` asks `Pane` for `tinted` and renders `EntryForm` with `surface={false}`. `tests/views/tinted.test.ts` learns the variant without a list of exceptions: a partial rendered with `surface={false}` in the view's own source counts as painting nothing for that view, read off the opening tag (`<EntryForm` ... `surface={false}`) the way `asks` reads the `Pane` tag; a view rendering the form with its surface still counts as before. The audit stays red for a bare view that does not ask and for a surfaced view that asks; a case proves each side over a synthetic pair of sources if the audit is a function of the source text, or over the real tree by naming Files on the asked side.
3. **The note is written at the first keystroke.** `addNote` writes no file: it opens the tab with `{ id, fresh: true }` and nothing else. The first keystroke of a fresh note (`typed` when the draft is untouched) writes the file at once through `save()`, and the keystrokes after it go through the autosave wait as today; once the file is written the instance's `fresh` flag is cleared (`setInstanceState`), so a reload reads the file rather than seeding an empty draft. Nothing is deleted on leaving: `leave` never calls `deleteNote` and never closes a tab; `abandoned` goes from `state/notes.ts` with its test. A fresh tab left with nothing typed stays open and empty, and draws empty again after a reload since `fresh` is still set; the Files list does not list it, since there is no file. An existing note whose file is empty is left on the disk and its tab open; the list's confirm is the one way a note is deleted.
4. **The `saved` line.** The toolbar's saved-at line of a fresh note says nothing until the first write (today it says "saved" for the empty file the control made); `note.unsaved` or the existing key that covers it, in `config/text/views/note.yml`.
5. **Words and docs**: any new key in `config/text/views/note.yml` or `files.yml`; `HELP.md`'s Files paragraph gains one sentence saying a note's file is made at the first keystroke and only the list's delete removes one; DESIGN.md's decision line.
6. **Tests**: `tests/views/tinted.test.ts` (item 2); `tests/ui/primitives.test.ts` or the entry-form test that exists (`grep -ln EntryForm tests`) for the variant (the surface class present by default and absent with `surface={false}`); `tests/views/note.test.ts` (a fresh tab draws empty with no round trip; the saved line silent before the first write); `tests/state/notes.test.ts` (`abandoned` gone; the debounce untouched); a store or view test that the first keystroke of a fresh note calls the save at once and the second does not until the wait; `tests/browser/files.spec.ts`: the case at line 223 rewritten to what holds now (open a note, type nothing, switch to Files: no file, the tab still there; then type one character: the file is listed within the wait), the case at 165 kept, and a case over the tint: with the wallpaper on, the Files pane's box has a background alpha above 0 and the bookmark form's box has none (the way `tests/browser/appearance.spec.ts` measures alpha).

## Decisions taken in this brief (each reversible, none silent)

1. The variant is a prop on the one form component rather than a second component, since the fields and the actions are the same and only the box differs.
2. A fresh note tab with nothing typed stays open rather than closing itself: closing it loses nothing, but a tab that vanishes on a switch is what Axel took for a deletion behind his back.
3. The first keystroke writes at once rather than after the wait, so the file exists the moment the note holds anything, and a reload or a crash inside the wait cannot lose a note's first words.
