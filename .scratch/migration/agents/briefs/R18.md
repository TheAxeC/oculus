## What to build

1. `bin/migrations/` holds `migrate-joint-work.mjs` and `rename-program-to-pillar.ts`, every reference above repointed (the `DESIGN.md` lines through Doc text), so `bin/` has room.
2. `bin/diagrams.mjs`: reads the source and writes `docs/diagrams/`, three diagrams, each as a Graphviz `.dot` file and the `.svg` rendered from it:
   - `layers`: the layers and folders of `src/lib` and `src/routes`, with an edge for each pair that some import joins, read from the import specifiers of every module (the same reading `boundaries.test.ts` does), grouped by the layer rows of that test.
   - `channels`: each watcher or poller, the channel names it publishes, and the client stores and views that read each channel.
   - `writes`: the write chain from the route through the refusals, the edit modules and the change log to the file on disk, read from the imports and calls of those modules.
   Reading is from the source alone (imports, `publish(` and subscribe calls), never a hand-written list; a module the reader cannot place is named in the diagram, not dropped.
3. The render is `@viz-js/viz` as a dev dependency, so no system Graphviz is needed and the same input renders the same bytes on any machine.
4. A test under `tests/checks/` that runs the generator in memory and fails, naming the file, when a committed `.dot` or `.svg` differs from what the source gives now; and cases that the reader finds a new import, a new channel and a new write module, each red under its revert.
5. The Help view shows the three diagrams: `HELP.md` references them (Doc text) and a read-only route serves only the `.svg` files of `docs/diagrams/` by name, refusing any other name. Each diagram is readable under every theme: its lines and text take the page's text colour and it has no opaque background.
