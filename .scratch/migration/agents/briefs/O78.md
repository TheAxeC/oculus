## What is on the tree (read on main at a374362d)

The rule the step ends. Oculus decides which hub file a feature reads by comparing the file's key in `collections:` with a word written in code. ## What to build

When the step is done, no file of `src/` compares a hub collection's key with a word, and every feature reads the collection its flag or registry names, in each hub by that hub's own list.

1. **The entry's new fields.** A `collections:` entry takes, beside `key` and `file`:
   - `registry:` one of `datasets`, `venues`, `pillars`, `domains`, `funding`, `people`, `organisations`, `resources`, `literature`, `leads`, `radar` (Z1010);
   - the flags `band_positions`, `band_teaching`, `awaiting`, `open_badge`, `lead_applications`, `dissemination`, `tasks`, `joint_work`, each `true` or absent (Z1009);
   - `dissemination_skip:` a condition of the `When` shape (`data/model/model-collections.ts:120-124`) (Z1013);
   - `ticker:` `{ category, undated }` (Z1014);
   - `group:` and `order:`, and `label:`, `glyph:` and `about:`, each of these three the dotted key of a word of the text catalog (Z1011).
   The shape (`collectionFileShape` and the `CollectionFile` type) carries them, and `data/sources/collections.ts` makes the findings beside `key_read_twice`, worded in `config/text/findings.yml`'s `findings.collections` group; `config/options/sources.yml`'s `collections` option describes each field with its help and control, and its help sentence no longer names keys as registries.
