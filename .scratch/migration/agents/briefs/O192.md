## What to build

1. **The rule.** For each facet, with `include` its included values and `exclude` its excluded values, a project is kept only when none of its values for the facet is in `exclude` and, while `include` is not empty, one of its values is in `include`. Across facets the rule is AND, as today. A project with no value for a facet (the slice facet with no stage, Role, Hub, Tier) is never hidden by that facet's exclude. Excluding a value for none (`NONE`) hides the projects with nothing there, so excluding No venue keeps only the projects with a venue. The rule is one function, used by `applyFilters`, by the collection's `meets` and by `stageKeeps` (with its terminal rule kept: with no stage included, a terminal stage stays hidden), so they cannot differ.
2. **The call forms.** `applyFilters(items, filters, search, quick?)` and `facets(..., inForce?)` keep their present call forms: the excluded values come in as an optional argument of `applyFilters` and an optional `excluded` field of `InForce`, so `hub-facets.test.ts` compiles and passes unchanged.
3. **The saved state.** Each of the four saved states holds `excluded: Record<string, string[]>` beside `filters`, the same shape, read field by field as `filters` is (a wrong value costs that field alone and reads as `{}`). `parseBoardState` reads it under the rules it reads `filters` by (a compute value no facet offers and a slice no board holds are dropped; a key not in `FACETS` is dropped). `parseCollectionState` (`collection/index.ts`) and `parseMapState` (`graph.ts:413`) read it as they read `filters`. A value saved in both lists of a facet is read as excluded. `PresentBar` and `barFields` carry `excluded`. No code reads an older form: a state without `excluded` has none.
4. **The writes.** Helpers in `state.ts` beside `withPick` and `withPicks`, each taking and returning both maps (`withPick` and `withPicks` become these, so no writer is left on the include-only form):
   - the row press: an off value becomes included, an included value off, an excluded value included;
   - the "not" press: an off value becomes excluded, an excluded value off, an included value excluded;
   - a category head (today's `withPicks` in `pickCategory`): a plain click sets the facet's include list as today and takes those values, and only those, out of the exclude list; an Alt-click excludes every slice of the category and takes them out of the include list (ruling 784 (5) (a));
   - Clear all: both maps empty.
   No bar has a Clear for one group, and none is added. Every writer listed under "What is on the tree" writes both maps through these.
5. **The counts.** A facet's counts leave out its own include and exclude lists (`facets`'s `left`); an excluded value's row shows how many projects carry it under the other filters. `appliedFilters` drops a Role or Hub exclude under the same conditions as their include (a saved one is kept and applies once its group is drawn). The collection's counts (`leftBy`) and the Map's Stage counts follow the same rule.
6. **The choices.** `FilterChoice` gains `excluded: boolean`. `filterGroups`, `groupOf` with `withGone`, `categoryGroup`, `projectGroups`, `stageGroup`, `sliceChoices` and `showGroup` (always `false`) set it, and an excluded value no project holds is listed at 0 after the held values, as a picked one is listed today. A facet whose only value is the value for none draws its group while that value is included or excluded.
7. **The words** (ruling 783 (2) (a)). ## Decisions taken in this brief (each reversible, none silent)

1. The excluded values are saved as a second map, `excluded`, beside `filters`, in every saved state. A prefix on a value inside `filters` could collide with a Waiting on value written as free text, and every reader of `filters` would have to know the prefix. Four real states: a board pane `{ filters: { status: ['blocked'] }, excluded: { status: ['paused'] } }`; a Present pane the same; a Map `{ filters: { stage: ['published'] }, excluded: { pillar: ['p1'] } }`; a collection `{ filters: { status: ['open'] }, excluded: { status: ['no-funding'] } }`.
2. The button words beyond the ruled examples: after the first included and the first excluded value, every other pick of either list is counted in one `+<n>`.
3. The glyph is a new name `exclude`, drawn as lucide `minus`, ASCII `-` (the check mark's ASCII is `+`).
4. The red of an excluded row and chip is the palette's red tokens (`--c-red`, `--on-c-red`, `--c-red-txt`).
5. Shift+Enter and the "not" button on an excluded row clear it, and an Alt-click on an included chip excludes it, since each is the "not" press of item 4.
6. A screen reader hears an excluded row as its words then `excluded` (`board.excluded_state`), and an excluded chip as not pressed with the tip `Stop excluding <value>`.
