## How it lives in oculus (the three layers, the data live)

1. **State.** `MapState` gains `tuned?: { key: string; params: Physics }`: the parameters last tuned for the node set `key` names. `parseMapState` validates it with `isPhysics` (moved or re-exported from `state/graph.ts` so the check has one home) and drops a malformed value. A pure `tunedFor(state, nodes): Physics | null` answers the params when `state.tuned.key === layoutKey(nodes)` and null otherwise, so a changed node set re-tunes.
2. **View.** `Graph.svelte` takes `tuned: Physics | null` and an `ontuned(params)` callback instead of reading storage: with params it runs `bestLayout`, without it runs `optimize` and reports the result through the callback; `Map.svelte` passes `tunedFor(held, graph.nodes)` and writes `{ tuned: { key: layoutKey(graph.nodes), params } }` into the instance state on the callback. The re-tune control writes `{ tuned: undefined }` (the key dropped) and bumps `generation` as today. No `localStorage` in `views/map/` or `state/graph.ts` afterwards.
3. **Migration.** A pane whose saved state carries no `tuned` tunes once on its next mount, as a fresh pane does; nothing reads the old localStorage item and nothing removes it (a stale key in a browser costs nothing and is not oculus's to sweep).

## Decisions taken in this brief (each reversible, none silent)

1. The params live under the node-set key rather than replacing the layout on every node change, so adding one project re-tunes once and a saved page keeps its picture until then.
2. The old localStorage item is not removed.
