# Brief: O10e, pages

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md` lines 188 to 199 ("Layout as data": the tree, the instance, the saved arrangement is the serialised tree), lines 172 to 174 (the shell renders the layout tree and mounts whatever a pane names), line 259 (the decision of 2026-09-10 on docking) and the decision of 2026-09-11 on pages (the last of the dated decisions), which this package implements: the workbench becomes one of several pages, each a whole workbench with its own two trees, dock and panel share, switched by a strip of page names across the top of the main area and the panel; the rail stays what it is. Asked for by Axel on 2026-09-11 and decided with him the same day: the strip at the top; a page made by a control at the end of the strip and named from its menu; the hidden page unmounted, its views rebuilt from the stores when it returns; Ctrl+1 to Ctrl+9 switching pages.

## Facts checked on the tree, 2026-09-11

- The store holds one `Workbench` (`layout.svelte.ts` line 58) saved under `oculus.layout.v1` in a version 2 envelope (`layout.ts` line 74, `serialiseLayout` line 767); the arrangement control keeps the replaced workbench under `oculus.layout.previous` (line 53).
- Instance state lives in `state/ui.svelte.ts` per instance id (line 81) under its own key, so a view keeps its state across a page switch without this package touching it; sessions, terminals and git state live in shared stores.
- `newInstance` mints ids with `crypto.randomUUID()`, so instance ids are unique across pages by construction, and `checkPages` only asserts it.
- No keyboard shortcut with a modifier exists in the shell today (`grep -rn 'ctrlKey\|metaKey' src/lib/shell src/lib/ui` prints nothing); `keys` in `Workbench.svelte` handles Escape alone.
- `ui/Tabs.svelte` takes `onclose` for every tab; a page strip with one page still draws its close, which closes and replaces it with a fresh default page.
