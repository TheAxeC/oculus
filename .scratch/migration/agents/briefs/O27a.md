## The acceptance list, from the roadmap as read on 2026-09-11

1. The roots: the configured `roots:` of `sources.yml` plus the ones the reader adds in-page; a workspace is a named list of roots, saved on this machine, and one is current; the view's toolbar offers the workspace picker, "+ root" (a folder path typed into a form; an absolute path that exists and is a directory, else refused with the reason), a root's removal from the current workspace, and "save as" a new workspace by name. The default workspace is `~/workspace` as one root when the reader has saved none and `sources.yml` names none.
2. The tree: one pane listing the current workspace's roots, each a collapsible folder tree read lazily one level at a time from the server (a `GET /api/fs?root=<key>&path=<dir>` answering the entries of one directory: name, kind file or dir, size, modified; dotfiles and `node_modules`, `__pycache__`, `.git` folders left out; 404 outside the root); a click on a file opens it (item 3); a folder click expands it; the tree remembers what is expanded in the instance state.
3. The file view: a tab per file (`file` view, one instance per root and path, as `document` is), by type: an HTML file in the `document` view as it is today (its relative assets reach `api/file` unchanged); a text or code file (by extension: the list of decision 3) fetched through `api/file` and drawn read-only with syntax highlighting and line numbers; an image (`png`, `jpg`, `gif`, `svg`, `webp`) as an `img` over `api/file`; a PDF in an iframe over `api/file`; any other type as its name, size and a download link; a file over 2 MB of text drawn as its first 2 MB with a note.
4. The rail entry `files` in the Sources group of `config/layout.yml` (line 24, beside `venues, data, code, statements`), opening the tree.

## Decisions taken in this brief (each reversible, none silent)

1. **Workspaces live in `~/.oculus/workspaces.json`**, resolved at the call as `sessions/overrides.ts` line 25 does: `{ current: <name>, workspaces: [{ name, roots: [{ key, dir }] }] }`; `sources.yml`'s roots are always present in every workspace under their own keys and cannot be removed; a reader-added root gets a key from its folder name (deduplicated with a number). `POST /api/fs` with the token and the same-origin check, body `{ action: 'add-root' | 'remove-root' | 'save-workspace' | 'select-workspace', ... }`. `local.yml` gains `workspaces` in `LOCAL_KEYS` (`data/sources/config.ts` line 37) as the file's override, absent by default. These are user-visible shapes and are named here.
2. **The roots the file route serves are the current workspace's.** `roots()` of `server/files.ts` becomes the union of the config roots and the current workspace's, read at the call, so `api/file` serves a reader-added root as it serves a configured one; the inside-root check is unchanged.
3. **Highlighting is highlight.js, the one new dependency of this package**, vendored through npm (`highlight.js`, the current 11.x; the core build with the languages registered by name: `typescript`, `javascript`, `python`, `yaml`, `json`, `bash`, `markdown`, `latex`, `css`, `xml`, `svelte` through `xml`, `plaintext`), applied in the browser to a fetched file; the theme is oculus's own: the token classes are coloured from `themes/tokens.css` with new `--code-*` tokens rather than a highlight.js stylesheet, so the code window follows the app's theme. CodeMirror is not taken: the window is read-only, and an editor's weight buys nothing here. The report records the dependency's size in `node_modules` and the build's size change.
4. **The pure parts.** `state/files.ts`: `typeOfFile(name)` (html, text, image, pdf, other, with the language for text), `treeState` parsing (expanded paths per root), `workspaceRoots(config, saved)`; `server/fs.ts`: `listDir(roots, key, path)`, the workspaces file read and write (through the atomic write of `sessions/json.ts`), the root-key rule.
