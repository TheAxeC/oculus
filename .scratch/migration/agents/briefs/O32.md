## What to build

1. `start` takes an optional `--pid <n>`. The writer records the pid and that process's start time, read the way `registry.ts` reads one, so a pid later reused by another process is never taken for the builder. A `--pid` that names no running process is refused with a message, and nothing is written.
2. The sessions layer reads the two fields. A launch with no end stamp reads done when its recorded process is gone, or when the pid now names a process with another start time. The rules already in `dispatches.ts:91` stand for a record without a pid, so every existing record reads as before.
3. The process check goes through the existing checker interface of `registry.ts` (signal 0 and the start times), never a new way of asking.
4. Tests for each: a record with a live pid reads running while its launcher is gone; a dead pid reads done; a reused pid (same number, other start time) reads done; a record without a pid reads exactly as before; `start --pid` with a dead pid is refused and writes nothing. Each new case carries a revert directive.

## Decisions taken in this brief (each reversible, none silent)

1. The record's two new fields are internal to the note file, which only oculus writes and reads; their names are the builder's choice and are stated in the report.
2. The start time is recorded beside the pid, since a pid alone would call a reused pid the builder, which `registry.ts` already guards against for the same reason.
