## What to build

Rulings 609 and 610: when an entry exists and its file has no `schema:` list that reads, in a collection or a feed, its page draws the fields the card draws, as read-only text, with a line saying so. A key that names no entry keeps the unknown-entry message.

- `src/lib/state/forms/page-entry.ts`: `PageEntry.schema` becomes `SchemaField[] | undefined`. `pageOf` answers a page for such an entry, its values through `settled.overlay`; the pending branch takes a file with no schema; `feedPage` answers a page for a feed with no schema. `pageNamed` for the career file is unchanged. `pageFields` keeps working with no schema.
- `src/lib/views/boards/entry/Entry.svelte`: such a page, read from what the page carries and never from the view's `schema`, draws the card with the line above it. It offers no Status, no Delete, no Edit and no other control that writes. The controls that only read stay (Copy BibTeX, the folder blocks, referrers). A feed page does the same with its own card. The fallback at line 127 compares by the file, so an undefined schema never picks another hub's file.
- `src/lib/views/shared/forms/entry/entry-actions.ts`: `editorRows` answers no row for such a page, its comment made true, so a registry card and a person keep no Edit.
- `src/lib/views/boards/person/Person.svelte`: no Delete for such a page, comments made true.
- `src/lib/views/boards/editor/editor-target.ts`: no form target for such a page, so the editor draws what it draws for a record with no page.
- `src/lib/views/boards/collection` card opening (`Collection.svelte:246-250`, the path the builder finds): a card of an entry with no key is handed no `onpage`, so its title is words and no tab opens.
- `src/lib/views/shared/card/feed/LeadCard.svelte` and `RadarCard.svelte`: only as far as a page with no schema needs, each change named in the report.
- `config/text/views/boards/entry.yml`: the word `no_schema`, single-quoted: `'This file has no schema: list that reads, so this entry has no editor. Add one to the file to edit it.'`

## Cases

- An entry of a collection file with no `schema:`, whose collections entry names a `primary_key`: a page with its title and values, `schema` undefined.
- The same file, a key that names no entry: null, the unknown-entry message.
- A file with a schema: the page with the file's schema.
- A file with no schema and no `primary_key`: the card's title is words and no tab opens.
- A file whose `schema:` does not read: the same page as with none.
- A feed with no schema (the demo hub's `leads.yml`, `radar.yml`), an entry it holds: a page; an entry it does not hold: null.
- An Add to a file with no schema and a named key: the page from the first frame.
- A pending write on such an entry: the page shows the overlaid values.
- The entry is removed while its tab is open: the unknown-entry message.
- A registry file (Venues) and a people file with no schema: no Edit, and no Delete on the Person page.
- An editor tab restored over such an entry: no form.
