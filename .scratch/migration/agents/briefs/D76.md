## What to build

Part 1, a note is an ordinary Markdown file named by its title.
- A note is `<name>.md` inside a hub's `.oculus/notes/`, at the top or in any subfolder; its name is its title, and the file holds the note's text and nothing else. It opens in the Markdown source tab (`openSourceFile`) with its rendered half and the Outline, as any Markdown file of a workspace folder does.
- A note's name follows decision 3 after its leading and trailing spaces are trimmed; a name that differs from a note of the same folder only by letter case, or only by Unicode normalisation, is refused as taken; names are compared and written in NFC. A case-only rename of one note is allowed (`ops.ts:328`). A refusal writes nothing and says why with a catalog sentence naming the character or the reason. `noteFile`'s id rule is replaced by this rule and a path inside the folder; its checks that the resolved path stays in the folder and that a file is no link out of it stay.
- A hub's notes folder that is itself a link to a folder outside the hub is refused for that hub with a sentence in its row, as `noteFile` refuses a note file that links out.

The `note` GET, `note-save` and `note-delete` of `/api/fs` and their code are removed; `order-notes` stays, per hub.
- The order (decision 5): `order.json` at the top of each hub's notes folder names each note by its path inside the folder without `.md`; a note it does not name is listed first, newest first; folders are listed first, by name; a drag between notes of one folder or Alt+Up and Alt+Down reorders, and a drag onto a folder moves the note into it through `/api/ops` (refused as taken when the folder holds a note of that name). Part 2, `[[links]]`.
- `[[name]]`, `[[name#heading]]`, `[[name|shown text]]` and `[[name#heading|shown text]]` link to a note of the same hub by decision 7. A link never reaches another hub's note or a file outside the hub's notes folder. Inside a GFM table, `\|` is the link's `|` and the table keeps its cells.
- In a note's source tab: completion after `[[` lists the hub's notes by name, and after `#` inside the brackets the target's headings; Go to Definition opens the note (at the heading); Find All References on a link, or on the note itself, lists every `[[...]]` to it in the hub's notes; Rename on a link renames the note and rewrites every link to it. oculus's Markdown entry answers these (decision 1), and its answer is merged with the server's answer to the same request, so a note keeps every answer the server gives today (path completion, ordinary links). The entry's hooks (`adapters/entry.ts`, `servers.ts`, the held request code) are extended so an entry can add its own result to the server's for a request; the merge is written once.
- A rename or move of a note (the Notes tree, a source tab's Rename, a drag into a folder) first plans the rewrite of every `[[...]]` that named it in that hub's notes, keeping each link's `#heading` and `|shown text`, through the page's edit plan (`state/system/machine/lsp/edits.ts`) and its write (`server/files/fs/lsp-edit.ts`): a note open in a tab gets the edit in its text, a closed note is written on disk, each write is logged and undone (G8, G9, G67). When the plan is refused (a linking note open in a tab of another page, a tab whose text no longer matches), nothing is renamed and the refusal names the file. Only then is the file renamed or moved through `/api/ops`, and the edits applied. A move into a subfolder leaves bare `[[name]]` links as they are while the name stays unique in the hub, and rewrites them to `[[folder/name]]` when the move makes it shared. Same-named notes of other hubs are never touched. A new name that breaks decision 3, or is taken, rewrites nothing.
- `edits.ts` and `lsp-edit.ts` accept a file inside a hub's `.oculus/notes/` and still refuse every other dot folder, `node_modules`, a hub's `secrets` and `~/.oculus`; the plan keeps refusing an entry that creates, renames or deletes a file (the rename is the `/api/ops` act).

- The rendered half and the Markdown Preview draw each `[[...]]` as a link with its shown text; a press opens the note in a source tab (at its heading). Every name reaching a URL (a page address, a `file:` URI, an `href`, the file route) is encoded once. The link's HTML passes the sanitiser (G5); `[[...]]` in code and code spans is text.
