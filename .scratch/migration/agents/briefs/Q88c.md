## What to build

1. **Discard Changes on an untracked file.** The changed-file menu, the folder row menu and the Untracked group head (Discard All Untracked Changes) offer Discard Changes in the Untracked group, and an untracked row gets VS Code's inline discard control beside its stage control. A new action `trashUntracked` moves the untracked paths to the macOS Trash. `ops.ts` exports `protectedFiles` and `holdsProtected` in place (the word `export` added, nothing moved); the git route's `GitOptions` gains `trash` (the same `{ glob: false }` call, injectable in tests) and `guard` (a function answering the `Guard` the ops route builds, from `browserRoots` and `localFile(engine)`), and the action runs inside `locals.server.opsWrites` through `chained`, so a Files operation and a discard over one file are ordered. A path held by the guard, a tracked path, a path outside the repository and a path whose real path leaves it are refused before the Trash is called. A collapsed untracked folder (`dir/` from `--untracked-files=normal`) goes to the Trash as one folder. The question is VS Code's: "Are you sure you want to DELETE the following untracked file: '{0}'?" (singular) and its plural form for several files, detail "You can restore this file from the Trash.", button "Move to Trash". `discard` stays as it is for tracked paths.
2. **Add to .gitignore.** On a row of the Changes and Untracked groups (VS Code offers it on working-tree and untracked resources only): each path relative to the repository root, `\` turned to `/`, `[` escaped as `\[`, appended one per line to the root's `.gitignore`, made when missing, with a newline first when the file does not end in one, the file's own line ending kept; the write is atomic (`writeBytesAtomic`), re-reads the file and refuses when the appended lines are not its last lines; the `.gitignore` then opens in a source tab. A `.gitignore` that is a symbolic link, or whose real path leaves the root, is refused. Action `ignore`.
3. **Open File (HEAD).** As VS Code's `openHEADFile` opens the change's left side: on a Staged row the file at HEAD (`show --no-textconv HEAD:<path>`), on a Changes row the file in the index (`show --no-textconv :<path>`), and on an Untracked row the item is not offered. A new read `GET /api/git?head=<root>&path=<path>&stage=index|head` answers `{ ok, text }`, or `binary` (through `isBinaryFile`'s rule over the bytes) or `missing`; the path goes through `version`'s `pathInside` check and is read as a literal path; a directory is refused. It opens a read-only source tab named `<file> (HEAD)` or `<file> (Index)`.
4. **Compare with Workspace.** On a changed file of a repository that is a linked worktree: the main worktree is `GitState.worktrees[0]`, checked with `permitted`, `pathInside` and its real path; the diff tab shows the main worktree's file (left) against this worktree's (right), both read from disk; a file the main worktree lacks diffs against empty. Not offered on a repository that is not a linked worktree.
5. **Close Repository, Close Other Repositories, Reopen Closed Repositories.** A repository row's menu gains Close Repository, and Close Other Repositories while more than one repository is listed. The Repositories view's `...` menu and title bar gain Reopen Closed Repositories while any is closed, which opens VS Code's quick pick: title "Reopen Closed Repositories", placeholder "Pick a repository to reopen", each closed repository, and with more than one closed, a separator and "All Repositories". Closed repositories are held in the Repositories tab's state as `closed: string[]` (the roots), so another Repositories tab and a session's Changes panel are not affected.
6. **Open Worktree, and Open Worktree in New Window.** A worktree row's menu gains both. Open Worktree adds the worktree's folder as a root of the current workspace through the existing add-root write, so it appears in Files and in the Repositories list. Open Worktree in New Window does the same and then opens a new browser window of oculus (`window.open` of the page's own address) with the Files view revealed at the worktree's folder.
7. **Checkout (Detached).** On a graph commit and on a remote branch name's own menu (the obligation `Q88.md:57,148` carried here; `refKind` gains `'remote'`): `git switch --detach <hash or ref>`, refused on a dirty tree as `switchBranch` refuses.
8. **Create Branch... and Create Tag... from a commit.** On a graph commit: the name asked as the Branches and Tags sections ask it; `createBranch` and `createTag` gain an optional start point (`switch -c <name> <hash>`, `tag [-a -F <file>] <name> <hash>`). The start point is a full or abbreviated hash matching `^[0-9a-f]{4,64}$`, checked before git runs.
9. **Cherry Pick.** On every commit of the graph, as VS Code offers it on every history item: `git cherry-pick <hash>`. A stop on conflicts is left in progress: `GitSequence` gains `'cherry-picking'`, `sequenceOf` reads `CHERRY_PICK_HEAD` (through the `rev-parse --verify --quiet` form beside `MERGE_HEAD`), the banner says "Cherry-picking", the commit box prefills git's prepared message as it does for a merge, the commit action commits it, and Abort runs `cherry-pick --abort` from `abortMerge`'s place in `git-index.ts`. A pick git calls empty ("The previous cherry-pick is now empty") is aborted and answered with VS Code's message for it. `cherry-pick` joins `ALLOWED` with exactly one call site in `git-write.ts`.
10. **Compare with Remote, Compare with Merge Base, Compare with...** On a graph commit, as VS Code's `git.graph.compareWithRemote`, `compareWithMergeBase` and `compareRef`: the current branch's upstream against the commit; the current branch's base against the commit, the base read as `getBranchBase` reads it (`branch.<name>.vscode-merge-base` naming a remote branch, else the branch's reflog creation entry, a local branch taken at its upstream, else the remote's default branch `refs/remotes/<remote>/HEAD`), without writing the setting back; or a ref picked in a quick pick of local branches, remote branches and tags ("Select a reference to compare with") against the commit. Each opens the diff view over the files of `git diff <from> <to>`, through a new read `GET /api/git?compare=<root>&from=<ref>&to=<hash>[&path=<path>]` answering the file list, and with `path` that file's two sides through `sidesOf`. A ref is refused when it starts with `-`, and is resolved with `rev-parse --verify --quiet <ref>^{commit}` before the diff, which runs with `--end-of-options` and the path after `--` with `--literal-pathspecs`. No upstream: Compare with Remote is not offered; no base: Compare with Merge Base is not offered.
11. **Delete Branch.** On a local branch name in the graph and in the Branches section: `git branch -d <name>` after VS Code's question; not offered for the branch checked out; a branch checked out in another worktree, and a branch git calls not fully merged, are refused with git's own reason. No `-D` and no "Delete anyway?" question are built (open item Z241).

13. **New Text File.** The strip menu offers New Text File, which opens a scratch Note in that pane through the existing `openView('note', { id: noteId(new Date()), fresh: true })`, the file made by its first keystroke as today.
14. **Tab Bar and Editor Actions Position (Z70 (a)).** `config/appearance.yml` gains `show_tabs: multiple` and `editor_actions: strip`; `options.yml` gains their two entries in the `appearance.yml:` block (control `choice`, the values as ruled, the Settings Appearance section); both join `VOCAB_KEYS`; `appearance.ts` reads them, a value outside the vocabulary read as the default. `single`: the strip shows the active tab only; `none`: no tab strip, the pane's title row still drawn with the editor actions; `hidden`: the editor actions are not drawn, the pane menu still reachable by the strip's right click. ## Cases

1. `changeMenu('untracked', ...)` lists Discard Changes; the Untracked head lists Discard All Untracked Changes; `trashUntracked` on a scratch repository's untracked `u.txt` calls the injected Trash with its real path; on a tracked path: refused, no Trash call; on a path the guard holds (a planted `local.yml` beside an engine root of the scratch tree): refused; on a collapsed `dir/`: one Trash call for the folder; two files: the plural question.
2. `ignore` on `a/b.txt`: `.gitignore` ends with `a/b.txt`; on `x[1].txt`: `x\[1].txt`; on folder `a`: `a`; twice: two lines (VS Code does not deduplicate); no `.gitignore`: made; a CRLF `.gitignore` gets CRLF; one not ending in a newline gets one first; a `.gitignore` that is a symbolic link: refused, nothing written.
3. `GET /api/git?head=<root>&path=x.txt&stage=head` answers the HEAD text and `stage=index` the staged text; a file added only in the worktree: `missing`; a binary: `binary`; `path=*.txt` with no such file: `missing`, no glob read; a directory: refused; a root outside the roots: 400.
4. Compare with Workspace on a linked worktree's changed file: left the main worktree's file, right the worktree's; a file only in the worktree: left empty; not offered on the main worktree.
5. Close Repository on one of three rows: two drawn; Close Other Repositories: one; with one listed: Close Other not offered; the quick pick with two closed lists them, a separator and All Repositories, with one closed lists it alone; All Repositories: three; another Repositories tab still shows three.
6. Open Worktree: the current workspace's roots gain the worktree's folder; in New Window: the same, and `window.open` called with the page's address.
7. Checkout (Detached) on a clean tree: HEAD detached at the hash; on a remote branch name: detached at its tip; on a dirty tree: refused, nothing run.
8. Create Branch `x` from a commit: `x` points at the commit and is checked out; a taken name: git's refusal; a start point `-x` or `HEAD~1`: refused before git runs. Create Tag `v1` from a commit: the tag points there.
9. Cherry Pick a commit of another branch: a new commit on the current branch; a conflicting one: `git.sequence` is `'cherry-picking'`, the banner shows it, the commit box holds git's message, Abort clears it; an ancestor of HEAD: empty, aborted, VS Code's message, no sequence left.
10. Compare with Remote with an upstream: the files of `git diff <upstream> <hash>`; no upstream: not offered. Merge Base with `branch.<b>.vscode-merge-base=origin/main`: `git diff origin/main <hash>`; with the setting unset and the branch created from `main` tracking `origin/main`: `origin/main`; `git config --get` of the setting unchanged after the read. Compare with... picking a tag: `git diff <tag> <hash>`. `from=--output=/tmp/x`: refused, no file written.
11. Delete Branch on a merged branch: gone after the question; on the current branch: not offered; on an unmerged branch: git's refusal shown, the branch kept; on a branch checked out in a worktree: git's refusal.
12. Lock Group on an empty pane: `landingFor` skips it, a document opened lands elsewhere; dragged onto it: it goes in; activate, open, move, split and close over the page keep the lock; saved and read back: still locked; a version-5 layout without the field: unlocked; the last tab closed: the pane stays, locked; every pane locked: a new split; Unlock: it lands there again; a locked pane closed with Close pane: gone.
13. New Text File: a new Note tab in that pane, no file written until a keystroke.
