## What to build

1. **The dependency.** `zod` 4.6.5 added to `dependencies` in `package.json` with the lock file, by `npm install zod@4.6.5` run from `tools/oculus` in the worktree. `README.md:13` names it with its licence and what it does here, in the sentence's own form.
2. **Where a schema goes.** At every place a value of type `unknown` enters the server from outside the process, in the 80 files listed: a request's body or query, a socket message, a file oculus parses (JSON, a JSONL line, YAML), and the JSON a subprocess or a remote API answers. The schema is a `const` beside the function that reads the input, named after the type it answers with the suffix `Schema` (`SubscriptionSchema`, `EntryWriteSchema`), and the function parses with `safeParse` and answers what it answered before for every input.
3. **The types stay the facade.** A type that is declared today stays declared as it is, in the file it is in (the `data/model` types and the server's own, `EntryWrite` and the like), and its schema ends `satisfies z.ZodType<TheType>`. No declared type is replaced by `z.infer`. A reader with no declared type today may use `z.infer` for its local shape.
4. **What is deleted.** Every hand check on a value the schema has already checked: the `typeof`, `Array.isArray` and `isMap` lines between the entry and the first use, and the local helpers that exist only for them (`text`, `number`, `severity` in `machine/usage/accounts.ts:43-53` and their like). `text`, `whole` and `list` of `core/json.ts` are deleted when no caller is left, and the re-export of `isMap` there when no server module imports it from there.
5. **What stays.** A check that narrows a type the compiler already knows (`typeof value === 'string'` on a `string | number`), a check on a value that does not come from outside (an argument one server function hands another), and `isMap` on a value the YAML parser produced where the code keeps the parser's own objects (a `z.record` refuses a `Date`, a `Map` and a class instance, which `isMap` accepts; decision 3 shows it). The report lists every file of the 80 where checks stay, with the reason per file.
6. **Behaviour is unchanged.** For every input, each reader answers what it answers on main: the same value, the same null, the same thrown sentence, the same keys kept or dropped. No refusal sentence, status code or wire shape changes. A lenient reader stays lenient: a field that falls back today falls back through `.catch(<the same fallback>)`, and a reader that keeps the keys it does not read uses `z.looseObject`. A strict reader that builds its answer from named fields keeps answering exactly those fields.
7. **No test is rewritten to fit.** Every test under `tests/` passes unedited. A test that fails after a conversion shows a changed behaviour, which is fixed in the conversion. A test file is edited only where it imports a helper item 4 deletes.
8. **Docs.** DESIGN.md gains, in the paragraph that names `views/shared/changes/CommitBox.svelte` and the git writes (line 339) or the paragraph on the write endpoint if one is nearer (grep `server/edit/writes` in DESIGN.md), one sentence saying the server checks untyped input with zod schemas beside each reader and that the declared types stay the facade. Every head comment of a changed file that describes hand checks is corrected.

## Cases

Each is a test of pure functions. Cases 1 to 12 are covered by tests that exist; the builder names the test for each in the first run, and adds a test under `tests/routes/` only for a case no existing test holds.

1. `parseSubscription('{"type":"subscribe","channels":["a"]}')` answers `{ type: 'subscribe', channels: ['a'], token: undefined }`.
2. `parseSubscription` answers null for `'x'`, `'null'`, `'[]'`, `{"type":"other","channels":[]}` and `{"type":"subscribe","channels":["a",1]}`.
3. `parseSubscription('{"type":"subscribe","channels":[],"token":5,"extra":1}')` answers `{ type: 'subscribe', channels: [], token: undefined }`: a token that is no string is dropped, an extra key is dropped.
4. `entryWrite({ kind: 'entry', collection: 'c', id: 'i', fields: { a: 1 } })` answers the same four fields.
5. `entryWrite` answers null for an empty `collection`, an empty `id`, `fields` that is a list, `fields` that is null, and a body that is null.
6. `entryWrite` with an extra key `more: 1` answers the four fields without `more`.
7. `subtaskWrite` with an `action` outside the allowed list answers null; with `value: 3` answers null; with no `value` answers a write with no `value` key.
8. `sessionWrite` naming none of `hidden`, `top`, `area` and `title` answers null.
9. `overrides()` over a file holding `{ "sessions": { "a": { "hidden": true }, "b": 3, "c": [] } }` answers `{ a: { hidden: true } }`; over a file that is not JSON, `{}`; over `{ "sessions": [] }`, `{}`; a key beside `sessions` changes nothing.
10. `claudeUsage` over `{ type: 'assistant', message: { model: 3, usage: { input_tokens: 4, output_tokens: 'x' } } }` answers model `''`, input 4, output 0; over `{ type: 'assistant', message: 5 }` answers zeros and no `context`; over `{ type: 'assistant', message: { usage: [] } }` answers zeros and no `context`.
11. A JSONL line that is not JSON, or is JSON and not a map, is skipped by every line reader (`machine/usage/accounts.ts:350-356` and its like), and the next line is read.
12. Every refusal `tests/routes/edit/write.test.ts` asserts still holds, with the file unedited.
13. Implied, a deep input: a body nested 10,000 levels deep answers null or the refusal it gets today and does not throw out of the route.
14. Implied, a prototype key: a body `JSON.parse('{"__proto__":{"kind":"entry"}}')` answers null from every write reader.
15. Implied, a large list: `reorderWrite` with an `order` of 50,000 strings answers the write, as today.
16. Implied, numbers: `NaN` and `Infinity` cannot come from `JSON.parse`; a reader of a YAML value that holds `.nan` or `.inf` falls back as it does today.

The builder's first task, before any change, is the first run of every case above on the unchanged tree, each as a test, with each case's result noted. When the first run finds a case the brief's own rules get wrong, the builder stops there, before changing any code, and hands back the first run and that case, with the rule and the result it gives.

## Decisions taken in this brief (each reversible, none silent)

1. A schema sits beside its reader in the reader's file; there is no schemas folder.
2. The schema's name is the type's name with `Schema`.
3. The conversion rule, run on five real sites with zod 4.6.5 (a probe in a scratch folder compared the hand version and the schema version on the inputs of cases 1 to 6, 9 and 10; every answer was equal):
   - `root/socket.ts:59-67` becomes `z.object({ type: z.literal('subscribe'), channels: z.array(z.string()), token: z.string().optional().catch(undefined) })`, the function answering `{ type, channels, token }` from `safeParse` or null.
   - `edit/writes/bodies.ts:160-166` (`entryWrite`) becomes `z.object({ kind: z.literal('entry'), collection: z.string().min(1), id: z.string().min(1), fields: z.record(z.string(), z.unknown()) })`, the function answering `safeParse(body).data ?? null`; `z.object` drops the extra key as the hand version does.
   - `transcripts/usage.ts:33-45` (`claudeUsage`, a lenient reader) becomes `z.looseObject({ model: z.string().catch(''), usage: z.looseObject({ input_tokens: z.number().catch(0), output_tokens: z.number().catch(0) }).nullable().catch(null).optional() }).catch({ model: '' })`, with `count()` kept on the numbers since it also truncates and refuses negatives.
   - `sessions/overrides.ts:34-42` becomes `z.looseObject({ sessions: z.record(z.string(), z.unknown()) })`, an entry kept when it parses as a record.
   - `machine/usage/accounts.ts:34-41` (`json`) becomes `z.record(z.string(), z.unknown()).safeParse(JSON.parse(...)).data ?? null`.
   - The probe also showed `z.record(z.string(), z.unknown())` refusing a `Date`, a `Map` and a class instance, all of which `isMap` accepts, and accepting an object with no prototype. `JSON.parse` produces none of the three, so the rule is safe on JSON; on a YAML value item 5 keeps `isMap`.
4. zod's error text is never shown: a reader answers null or its own sentence, as today.
