## What to build

The right-click menus of the inventory's six surfaces. Each menu carries every item of the inventory marked **has** or **clipboard** for that surface, and the "has" half of a row marked **part**. Items go in the inventory's order, with a rule between VS Code's groups. An item shows only under the condition its inventory row names. Items marked **new**, and the new half of a **part** row, are Q88b's and are absent here. Items marked **out** are absent.

Each surface's items are built by a pure function beside the view (the shape of `railMenu` in `shell/rail/rail.ts`), which takes the row or the surface's state and `t`, and returns `MenuItem[]`. Its pick is answered by the function the view's own control for that action already calls, so a menu's Discard asks the same question the row's Discard control asks. Each row that has a menu is wrapped in its own `ContextMenu`, as `RailPages.svelte:179` wraps a page button. The keyboard reaches every menu by Shift+F10 or the context menu key on the focused row or control, which `ContextMenu` already gives.

1. **A rule between groups.** `MenuItem` gains `rule?: boolean`: a separator is drawn above the item, as VS Code draws between its menu groups. `MenuList.svelte` draws it with bits-ui's Separator, in the border colour, 1 px, with the menu's own vertical padding, and never as the list's first or last line. It is not a choice, so type-ahead and the arrow keys skip it.
2. **The Files view** (`views/sources/files/tree/`), on each row of `Tree.svelte`:
   - a file: Open to the Side (the file opened as `openRow` would open it, through `openBeside`); Open in Integrated Terminal (a shell in the file's folder); Download... (the file's bytes saved, as the file view's link does); Copy Path (absolute), Copy Relative Path (under its root); Open Preview, on a Markdown file only (the file opened in the source tab, which shows its rendered half);
   - a folder: Reveal in Finder (`openFile(root, path)`); Open in Integrated Terminal; Copy Path, Copy Relative Path;
   - a root: Reveal in Finder; Open in Integrated Terminal; Find in Workspace... (the Search view opened with that root chosen); Copy Path, Copy Relative Path (the relative path of a root is `.`, as VS Code copies it); Add Folder to Workspace... (the view's add-root form); Remove Folder from Workspace, on a root the reader added only, through the view's question.
3. **The Repositories view:**
   - a changed file (`Changes.svelte`), by group:
     - Changes: Open Changes, Open File, Stage Changes, Discard Changes, Reveal in Explorer View.
     - Staged: Open Changes, Open File, Unstage Changes, Reveal in Explorer View.
     - Untracked: Open File, Stage Changes, Discard Changes, Reveal in Explorer View.
     - The merge group keeps its own controls and gets no menu; the inventory has no row for it.
   - a group's head: Changes gets Stage All Changes and Discard All Changes; Staged gets Unstage All Changes; Untracked gets Stage All Untracked. Each item calls what the head's control calls.
   - a repository row (`RepoList.svelte`): Open in Integrated Terminal and Reveal in Finder.
   - a worktree row (`Worktrees.svelte`): Open in Integrated Terminal and Delete Worktree. Delete Worktree goes through `onremove`, with its question.
   - a commit of the graph (`graph/Graph.svelte`): Open Changes (the commit's files, as a press opens them), Copy Commit ID and Copy Commit Message. Then, for each local branch named on the commit, a submenu Checkout holding each branch name. For each tag on it, a submenu Delete Tag holding each tag name. Each goes through the Branches section's switch and the Tags section's removal, with their questions. The row's "more" menu gets the same list.
   - a branch or tag name on the graph: a right-click on the name opens that name's own menu, Checkout for a local branch and Delete Tag for a tag. A remote branch name gets no Checkout; that is Q88b's Checkout (Detached).
4. **The pane** (`shell/panes/PaneView.svelte`, with its item builder in `shell/panes/pane-view.ts`). A right-click on the strip's empty area and in an empty pane's body opens: Open File... (the palette, as Cmd+P opens it); Split Up, Split Down, Split Left and Split Right (the active tab into a new pane on that edge, only while the pane holds a tab); Close (the pane, through the pane menu's own close and its question, only while the page holds more than one pane); New Terminal (`composeIn` on the pane's page). The palette's opener reaches the pane from `Workbench.svelte` by the shell's existing way of handing a function to the panes.
5. **The terminal** (`views/sessions/terminal/`):
   - the grid: Copy, while the grid holds a selection (xterm's `getSelection()` to the clipboard); Paste (the clipboard's text through the grid's paste path, so a paste of several lines is asked about, as a browser paste is); Select All (xterm's `selectAll()`); then Split Terminal and Kill Terminal on the grid's terminal, as the list's controls do.
   - a row of the list: Split Terminal and Kill Terminal (the row's own actions); Unsplit Terminal, on a row that is one half of the split this tab shows (that terminal shown alone); Join Terminals, a submenu of the terminals other Terminal tabs own, each by its name. Picking one moves it into this tab with `moveTerminal` and shows it split with this row.
   - the list's empty area: New Terminal (`composeInTab` on this tab), and New Terminal With Profile, a submenu of the kinds the composer offers (shell, Claude, Codex), which opens the composer on that kind.
6. **The text surfaces:**
   - every text box, in `ui/forms/TextInput.svelte` and `ui/forms/TextArea.svelte`: Undo, Redo, Cut, Copy, Paste and Select All, acting on that box. Cut and Copy show only while the box holds a selection. A Paste is one edit, which Undo takes back. The box keeps its focus and its caret.
   - rendered Markdown (`views/shared/prose/Markdown.svelte`): Copy, with a selection inside it. Over an image: Copy Image (its bytes as `image/png` to the clipboard), and Open Image for an image the hub serves (in the file view, by the root and path its URL names). With no selection and not over an image, nothing opens, as VS Code opens nothing on plain text.
   - the Document view's frame (`views/sources/document/Document.svelte`): the same menu as rendered Markdown, over the frame's own selection and images. The frame is same-origin, so its right-click is heard on its document and the menu is opened at that point in the page.
7. **Words.** Each label is VS Code's word for the item, as the inventory writes it. Where oculus already has the item under its own word (Copy Commit ID, Copy Commit Message, Stage All Untracked), oculus's word stays. Every label is a catalog key in the view's own text file under `config/text/views/...`, or in `config/text/ui.yml` for the pane, the text boxes and the prose. No label is written in code.
8. **Documents.**
   - `DESIGN.md:306` gets one sentence: which surfaces carry a right-click menu, that each item runs an action the surface already has, that `rule` separates VS Code's groups, and that Shift+F10 opens each menu.
   - `HELP.md`: the Files, Repositories, Terminal and pane rows of "The views" (lines 108, 109 and 124) and "Pages and the pane tree" (lines 27-47) say what each right-click menu offers. The keys table gains one row for Shift+F10, after line 78; lines 85 and 87 are D13a's and stay as they are.

## Decisions taken in this brief (each reversible, none silent)

1. A rule between groups is `MenuItem.rule`, drawn above its item, since VS Code separates its groups with a line and the menus have none.
2. An item oculus cannot run yet is absent, not drawn greyed out. Q88b adds each one to these menus.
3. One `ContextMenu` per row, as the rail and the catalogue use it, so each row's items are built from that row.
4. Where no surface of this step draws a menu, the browser's own menu stays. In rendered Markdown and the Document frame with no selection and no image, nothing opens, as VS Code opens nothing there.
5. Rendered text offers Copy and not Cut or Paste, since no cut or paste can change it.
6. Paste from a menu reads the clipboard through `navigator.clipboard.readText()`, which Chrome asks the reader to allow once for the page's origin. A refusal leaves the box or the grid as it was.
7. Join Terminals is a submenu of the terminals other Terminal tabs own. An oculus tab owns a list of terminals, so the join moves a terminal into this tab, where VS Code joins two of its tabs.
8. Open File... opens the palette as Cmd+P does, since oculus has no file dialog.
9. A remote branch on the graph gets no Checkout in this step, since `switchBranch` takes a local branch; its detached checkout is Q88b's.

Everything in "What to build". Every behaviour a surface has today stays: its controls, its keys, its tooltips, its drag and its focus order. No item is shown whose pick would do nothing in the state the surface is in.
