## Decisions taken in this brief (each reversible, none silent)

1. The snippet is decoded on the server, where each provider's thread is built, so every reader of the payload gets readable text.
2. The sender is split by one pure function in `state/feeds/inbox.ts`; a From with no display name is titled by its address.
3. An account's hue is its place in the payload's account list, cycling through the six `HUES`, so two accounts of one reader keep their colours while the list does not change.
4. An event with no link opens nothing on a click; the published link's events carry the ICS `URL` property when present.
5. The link must start `https://` or `webcal://`; `webcal://` is fetched as `https://`. A plain `http://` link is refused.
6. The add request carries the link as `url`, on the calendar endpoint only; the page never receives it back.
7. The calendar name of an ics account is the file's `X-WR-CALNAME`, else the label.
