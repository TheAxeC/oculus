## What to build

1. **The headings.** The Settings view's groups are, in this order: This browser, Appearance, Editor, Terminal, Sessions and usage, Cluster, Boards and audit, Rail and pages, Presentation, Project sources, Calendar and mail, This machine; then the Catalogs and Texts groups as today. Each catalog entry outside `local.yml` names its heading with a new key `heading:` (the heading's id: `appearance`, `editor`, `terminal`, `sessions`, `cluster`, `boards`, `rail`, `presentation`, `sources`, `calendar`); every `local.yml` key is under This machine. The heading's words come from `config/text/` (a new line per heading). Inside a heading, rows gather under their `section` as today, the section now saying the file beside its words when two files meet under one heading is not needed: each row already shows its file and line. A row's place in its heading follows the file order of `FILES`, then the catalog's order. The table of contents lists the twelve and their sections. The mapping of every option is the table below.
2. **The controls.** The catalog's `control` vocabulary grows, and a family field may carry a control:
   - Leaf options: `toggle`, `number`, `text`, `choice` and `list` as today; new: `long` (a TextArea, free words over a line), `multi` (a MultiSelect of `values` or of `values_from`), `glyph` (GlyphSelect over `catalogs/glyphs.yml`), `hue` (a new ui primitive, `ui/forms/choice/HueSelect.svelte`, drawing a swatch per palette hue and writing the hue's name), `colour` (the same primitive in its colour form, drawing each palette colour and writing its hex), `folder` and `file` (a text box whose suggestions are the entries of the folder typed so far, read through the file browser's listing of the hub root; a path that is not there is refused before the write with its own sentence), `parked` (a list of items each with Remove and no Add).
   - A `choice` or `multi` takes either `values` (a fixed list) or `values_from` (one of a closed set of sources, each read from what the page already holds: `domains` the keys of `registries/domains.yml`, `clusters` the cluster keys of `registries/resources.yml`, `models` the Claude models of `catalogs/agents.yml`, `languages` the editor's language names, `arrangements` the `arrangements` keys, `nav_groups` the `nav_groups` keys, `rail_pages` the rail's page keys, `views` the registered view ids, `collections` the collection keys of `sources.yml`, `projects` the project ids, `project_types` the project types, `wallpapers` the images of `wallpaper.dir`, `code_themes` the Code theme menu's list (`views/system/workbench/code-theme-menu.ts`)). A `choice` may carry `empty: true` when an empty value is allowed, drawn as the first item with words saying what empty does.
   - A `number` may carry `min` and `max`, held by the NumberInput.
   - A family's `fields:` entry is either a string (its description; the field is `text`) or a map `{ description, control, values, values_from, empty, min, max, fields }`, where `fields` (with `control: records`) describes the records of a nested list, drawn as a sub-editor of cards inside the card (move up, move down, remove, add), never as one line of YAML.
   - `options.ts` reads the new keys and refuses an unknown control word, an unknown `values_from`, a `choice` with neither `values` nor `values_from`, and a field map without `description`, each as a finding that names the file and key, the entry's control then read as `text` (G13).
   The draft (`state/system/config/editors/draft.ts`) holds each field as its typed value (a boolean, a number, a string, a list, nested cards) rather than flow text, so Save writes the value the control holds; a field the catalog does not name is kept as today.
