# Brief: O18, the terminal view

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "PTY" under Layer 2, "Layer 3, view", "Theming", step 6 of the migration order, and the decisions on tmux and on the three kinds of terminal. O17 gave the `pty:<id>` channel, the input and resize messages, and `/api/terminal`; this package draws it: the terminal view over xterm.js, the control to start one of the three kinds, the composer, and a message routed into another session.

## What to build

Two dependencies, the only ones this package may add: `@xterm/xterm` and `@xterm/addon-fit` (the fit addon sizes the grid to the pane), installed with `npm install`, versions pinned and reported. The CSS the package ships (`@xterm/xterm/css/xterm.css`) is imported by the view; its colours are overridden by the theme (below).

Under `tools/oculus/src/lib/state/`:

- `terminals.svelte.ts`: `terminals()` from the `sessions` payload's `terminals` list; `startTerminal(kind, cwd)`, `stopTerminal(id)`, `resizeTerminal(id, cols, rows)` posting to `/api/terminal` through `state/writes.svelte.ts`'s token; `sendInput(id, bytes)` and `sendResize(id, cols, rows)` writing the two inbound messages on the socket (`state/socket.svelte.ts` gains `send(message)` and includes the token in its subscribe message, as O17's server expects); `subscribePty(id, onBytes)` subscribing to `pty:<id>` and handing every payload's bytes, decoded from base64, to the listener, with the first message (the scrollback) first; `unsubscribePty(id)`.
- `selection.svelte.ts`, extended: the selected session may name a terminal (`oculus-<id>`), and a terminal's record in the `sessions` payload (O17 puts terminals there) selects like any session.

Under `tools/oculus/src/lib/views/sessions/`:

- `Terminal.svelte` (`terminal`), replacing O14's placeholder: mounts an xterm.js `Terminal` in the view's body with the fit addon, subscribes to the selected or pinned terminal's `pty:` channel, writes every chunk to the terminal, sends every `onData` as input, and sends a resize on mount and whenever the pane's size changes (a `ResizeObserver` on the body, debounced 100 ms; the fit addon computes cols and rows). The terminal's theme comes from the tokens: `background` from `--panel`, `foreground` from `--ink`, `cursor` from `--accent`, the sixteen ANSI colours from the palette hues (`--c-red`, `--c-green`, `--c-gold` as yellow, `--c-blue`, `--c-magenta`, `--c-cyan`, `--muted` and `--ink` for the two greys and the bright variants from the same hues), read from `getComputedStyle(document.documentElement)` each time the theme changes (an `$effect` on `ui.theme()`), so a theme switch repaints the terminal too. When no terminal is selected the view shows the start control: a `Segment` for the kind (`claude`, `codex`, `shell`; glyph names `terminal_claude`, `terminal_codex`, `terminal_shell` added to `glyphs.yml` with existing characters, the report names them), a `Select` of cwd from the workspaces the `sessions` payload knows plus the hub, and a start button; starting selects the new terminal.
- `Composer.svelte` is a primitive under `ui/` (a multi-line `TextArea` with a send button, Enter sends and Shift-Enter breaks a line) and sits under the terminal in the view: what is typed goes to the terminal as input followed by Enter, which is how a prompt is given to an agent without typing into the raw grid; the composer keeps the last ten sent texts and the up arrow recalls them.
- Routing into another session: the composer's send control has a menu (`Menu`) listing the other live terminals (`sessions.route_to`), and picking one sends the text to that terminal's channel instead, which is DESIGN.md's "human routing into another session". A terminal that is not live is not offered.
- `SessionList.svelte`, extended: terminals appear in the list under a "Terminals" workspace heading with their kind mark, cwd basename and created time, selectable like a session; a stop control on each behind a confirm (`ui.confirm_stop`).

Under `tools/oculus/config/`: `text.yml` gains the strings under `text.sessions` (`start_terminal`, `kind_claude`, `kind_codex`, `kind_shell`, `cwd`, `route_to`, `send`, `terminals`, `stop_terminal`, `confirm_stop`, `no_terminal`); `glyphs.yml` gains the three glyph names.

Under `tools/oculus/tests/`:

- `state/terminals.test.ts`: the posts and the socket messages with the socket and `fetch` stubbed; the base64 decoding; subscribe and unsubscribe bookkeeping.
- `views/sessions.test.ts`, extended: the terminal view with no selection renders the start control; with a terminal selected it renders the mount point and the composer (xterm.js itself needs a DOM and is not instantiated under `svelte/server`; the report says so); the list shows a terminal under its heading.
- `ui/primitives.test.ts`, extended: the composer.
- `tests/ui/colours.test.ts`: the xterm theme is set through the xterm API from computed tokens, not through CSS, so the gate sees no colour; the report says so and names the one file that reads `getComputedStyle`.

## Facts checked on the tree, 2026-09-10

- xterm.js is the terminal DESIGN.md names; it renders a byte stream into a grid, emits `onData` for keystrokes, and its `Terminal` takes a `theme` object of colour strings; the fit addon reports `cols` and `rows` for a container. Neither is in `node_modules` today; the brief names both as the package's two dependencies (the plan's "vendored" means this).
- The tokens are hex strings on `:root` and the theme blocks (`themes/tokens.css`), and `applyTheme` sets the derived ones on `documentElement.style`; `getComputedStyle(document.documentElement).getPropertyValue('--panel')` gives the value in force.
- The page's token reaches the client in `state/writes.svelte.ts` (O11); the socket's subscribe message must carry it for input to be accepted (O17).
