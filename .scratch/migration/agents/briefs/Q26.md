## What is on the tree (written 2026-09-16 at 05:20 against 316a9453)

- The four update tasks (`litwatch`, `scout`, `linkedin`, `inbox`, `TASKS` at `src/lib/server/pty/routes.ts` line 52) start through `POST /api/terminal` action `task`: `startTask` (line 180) runs `taskCommand(local.claudeBin, kind)` (line 164) as a `claude` terminal in the hub, and that command is `<claude> -p --output-format stream-json --verbose --include-partial-messages --dangerously-skip-permissions '/research-cockpit <kind>'`, every word through `shellWord`. `-p` is the CLI's print mode: it runs the skill unattended and a permission prompt inside it has nobody to answer it, which is what the skip flag was for. `tests/routes/terminal.test.ts` line 417 asserts that command word for word.

## How it lives in oculus (the three layers, the data live)

1. **Data.** `chat.skip_permissions` in `config/behavior.yml`, a boolean, default `false`, read beside `chat.model` off `config.chat` (`chat.ts` line 55 is the shape): true means `=== true` and anything else is off, since the `chat:` keys have no validator today and a wrong value must not run a task unattended; it reaches the page in the merged config the config channel carries, read by the tray through `configMap()`.
2. **Server.** `taskCommand(binary, kind, skip)` builds `<claude> '/research-cockpit <kind>'` as an interactive session, no `-p`, no `--output-format`, no `--verbose`, no `--include-partial-messages`, so the skill runs in the pty the terminal pane shows and every permission prompt the CLI raises is answered there by the reader; `--dangerously-skip-permissions` is added only when `chat.skip_permissions` is true. The terminal's `kind` stays `claude`, its name `task <kind>`.
3. **View.** The tray's task control, when `chat.skip_permissions` is true, opens `ui/Confirm.svelte` first with the sentence that the task will run without permission prompts (`app.tasks.skip_confirm` in the catalog, and its two control words), and starts the task on yes; when false it starts the task as now. HELP.md says the tasks run as ordinary Claude sessions whose prompts are answered in the terminal, and how to turn the unattended run on; DESIGN.md's decision line records the change and why (the port rule: the reader's answer is what a permission prompt is for).

## Decisions taken in this brief (each reversible, none silent)

1. The task runs as an interactive session rather than print mode, since a prompt answered in the terminal needs a terminal the CLI is talking to; the skill invocation `/research-cockpit <kind>` is the session's first message, passed as the CLI's positional argument as the chat terminal passes its seed.
2. The setting lives under `chat:` beside `model`, as the plan line names it, since both are how oculus starts a Claude CLI.
3. The confirmation is asked in the tray, once per press, and is not remembered.
