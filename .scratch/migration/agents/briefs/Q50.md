# Brief: Q50, a web address written without a scheme is not a hub path

## What is on the tree (read on main at c3cc1304)

- `src/lib/state/collection.ts` line 241: `const ADDRESSED = /^([a-z][a-z0-9+.-]*:|\/)/i;` and line 260: `isHubPath(value)` is `value !== '' && !ADDRESSED.test(value)`. A value with no scheme and no leading slash is a hub path by that rule.
- Line 283: `const PATH_FIELDS = ['link', 'url', 'folder'];`, read by `hubPathsOf` (line 291), which is what a card's Show in Files control is drawn from (D22).
- `hrefOf` (line 250) uses the same `ADDRESSED` rule to decide whether a value is opened as written or served through the hub root, so a change to the rule changes where a card's own link goes as well.
- `registries/repos.yml` writes every `url:` with `https://` (its own comment says to put the GitHub URL there). The reviewer of D22 counted no scheme-less `url` in funding (3), applications (23) or repos (20).

## What to build

1. **A host-looking value is an address, not a path.** `isHubPath` answers false for a value whose first segment looks like a host: a `www.` prefix, or a first segment carrying a dot and ending in a letters-only suffix of two or more (`github.com/x`, `example.co.uk/y`), with an optional port. A path whose first segment merely holds a dot (`README.md`, `notes.v2/plan.md`) stays a hub path.
2. **`hrefOf` follows the same rule**, so a scheme-less address in a `link` or `url` field opens as an address (`https://` put in front), not through the hub root, and a hub path keeps going through the hub root as it does today.
3. **Say what the rule is** in the comment above `ADDRESSED`, in one sentence, with no history.
