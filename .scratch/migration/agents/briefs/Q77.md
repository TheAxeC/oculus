## Why

A step spends most of its time waiting on checks. On Q78, 136 minutes of builder time (the first run and the repair round) held 80.5 minutes of revert-check runs, 13.0 minutes of whole unit-suite runs, 4.5 of scoped unit runs and 4.5 of browser runs, leaving 25.5 minutes of reading and writing. revert-check proves every directive of every file it is given, one case at a time, each in a fresh copy of the tree, a browser case after a production build of its own, and a directive points at its target by line number, so an edit above a target moves the pointer and forces a sweep of re-pointing. This step makes a directive point at its target by content, proves only what a change added or changed, runs cases side by side, and ends the timeouts of the tree-walking checks under load.

## What to build

Each item is an acceptance item.

1. **A directive points at its target by content.** The new form is
   `// revert: <path> "<anchor>" => <replacement>` and, for a range, `// revert: <path> "<first anchor>" .. "<last anchor>" => <replacement>`. An anchor is a JSON string literal (a `"` or `\` inside it escaped), and names the one line of the target file whose text, with its indentation trimmed, contains it. An anchor that matches no line or more than one line makes the directive unproven with the count in the line it prints, never red and never a guess. Where no substring of the target line is unique in its file, the anchor may carry an offset, `"<anchor>" +<n>`, meaning the n-th line below the line the anchor names. The replacement keeps its current meaning (`delete`, or the new line's content with the target's indentation kept). The old `<path>:<line>` form stops being read: after this step no directive in the tree uses it, and revert-check reports any it finds as unproven with the reason "a line-number directive".
2. **Every existing directive is converted, and none changes what it proves.** A script under `bin/` converts every directive of the tree to the new form, choosing for each the shortest anchor that is unique in its target file (the whole trimmed line when no shorter one is unique, an offset from the nearest unique line above when the line itself is not unique). The script proves its own work before it writes: for every directive, the line the new form resolves to is the line the old form named, on the tree as it is; a directive where they differ is not written and is printed. It is run once in this step and its result committed with the step; it stays in `bin/` with its test, since a branch cut before this step lands still carries the old form.
3. **Only what changed is proven.** `node bin/revert-check.mjs --base <dir> <files>` skips a directive when `<dir>` holds the same test file with the same directive text inside a case of the same name whose body is the same, and the target file's resolved lines, with the ten lines above and below them, read the same in `<dir>` and in the tree. A skipped directive is counted and listed as `same` in the output and in the summary line, never as proven. Without `--base` every directive is proven, as today. The builder of a step runs it with `--base` pointing at an export of the step's base tree that the orchestrator puts beside the worktree at `.agents/worktrees/<step>-base/tools/oculus`; the landing runs it with `--base` pointing at the builder's worktree. The exact path is an argument, so nothing in the script knows the plan's folders.
4. **Cases run side by side.** `--jobs <n>` runs up to n cases at once, each in its own copy of the tree and, for a browser case, on its own free port, as one case runs today; the default is the number of cores less two, at least one. The printed lines keep the order of the directives in the files, whatever order the cases finish in, and a stop by signal removes every copy in hand.
5. **A browser revert without a production build per directive, where that proves the same.** Measure two ways against the current per-directive build over a sample of at least twelve browser directives from at least four spec files: (a) the copy served by the dev server (`vite dev`) instead of `build/`, (b) any other way you find that serves the edited copy without a full build. Keep a way only when its red and green verdict matches the full build on every sampled directive, including at least three that are green (a revert that leaves its case green, made for the measurement in a scratch copy, never committed); otherwise keep the build. The report gives each way's verdicts and wall time per directive.
6. **The timeouts end.** Each test of item 3 of the tree runs within vitest's default under the load of a whole-suite run, by making its walk cheaper (read the tree once per file, not once per case; skip what cannot hold a match), or, where the walk cannot be made cheaper without losing coverage, by a timeout on that case with a comment saying why its walk takes the time it does. No global timeout change. The browser case of item 5 of the tree: find why its row is redrawn while the press waits, under load, and end that cause; a longer timeout is not a fix for it.
7. **Docs.** The head comment of `bin/revert-check.mjs` states the new form, `--base`, `--jobs` and the browser way kept. `grep -n "revert" HELP.md DESIGN.md` prints nothing on the base; any comment or document under `src`, `tests`, `bin` and `docs` naming the `<path>:<line>` form, found by grep, is made true.
8. **Measured.** The report gives the wall time of `node bin/revert-check.mjs` over the same set of test files (the eleven test files Q78 changed: `tests/browser/views/contents.spec.ts`, `tests/browser/shell/tinted.spec.ts`, `tests/browser/workbench/sanitise.spec.ts`, `tests/browser/workbench/system.spec.ts`, `tests/browser/shell/views.spec.ts`, `tests/data/prose/markdown.test.ts`, `tests/routes/docs/docs.test.ts`, `tests/views/system/help.test.ts`, `tests/views/sources/doc.test.ts`, `tests/views/sources/source.test.ts`, `tests/views/whole/sanitise.test.ts`) three ways: before this step's changes (run it first, before any edit), after them with `--jobs 1` and no `--base`, and after them with the default `--jobs` and no `--base`; and the count of directives skipped as `same` when run with `--base` pointing at the base export.
9. **Tests.** `tests/checks/bin/revert-check.test.ts` covers: an anchor resolving to its line; an anchor matching none and one matching two, each unproven with its count; an offset; a range; a line-number directive reported as unproven; `--base` skipping an unchanged directive and proving one whose target lines, context lines, case body or directive text changed (one case per kind); `--jobs 3` printing the same lines in the same order as `--jobs 1` over the same files; the conversion script's proof refusing a directive whose new form resolves elsewhere. Each case carries a revert directive in the new form.

## Decisions taken in this brief (each reversible, none silent)

1. The anchor is a substring of the target line, in a JSON string literal, so a line holding quotes, `=>` or backticks can be named without a new escaping rule.
2. "Changed" for `--base` is the test's directive, its case body, and the target's resolved lines with ten lines of context; a change further away in the target file is not a reason to prove again, since the directive was proven against the same code around its line.
3. The conversion script stays in `bin/` with its test.

## How to verify while working, and before you report

While working run only the test files you change, never the whole unit suite and never the whole browser suite. Each of the following runs once, at the end, from `.agents/worktrees/Q77/tools/oculus`, and must hold:

1. `npx vitest run --reporter=dot` prints every file and every case passed.
2. `npm run check` prints `0 ERRORS 0 WARNINGS`.
3. `npm run build` exits 0.
4. `npm run format:check` prints `All matched files use Prettier code style!`
5. `npm run lint` exits 0.
6. The ASCII gate of the rules file prints nothing.
7. `sh bin/size-check.sh` and `sh bin/folder-check.sh` exit 0.
8. `npm run diagrams`, then again: the second run changes nothing in `docs/diagrams/`.
9. `npm run build`, then `OCULUS_BROWSER_PORT=<a free port> npx playwright test` over the spec files you change: all pass.
10. The conversion script's own proof over the whole tree prints no directive it refused.
11. `node bin/revert-check.mjs tests/checks/bin/revert-check.test.ts <each test file of item 3 of the tree>` prints 0 unproven. The converted directives of the rest of the tree are proven by the script's proof, not by a full revert-check run.
12. `ls -d $TMPDIR/oculus-* | wc -l` is the same before and after.

Running the whole unit suite or revert-check more than once is a finding in the review.
