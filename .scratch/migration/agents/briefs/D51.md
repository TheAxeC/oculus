## What to build

1. **The converter.** `utils/migrations/convert-vscode-themes.ts`, run from the hub's root as `node tools/oculus/utils/migrations/convert-vscode-themes.ts [--from <extensions folder>] [--check]`, its head comment saying so as the other converters' do. It reads each of VS Code's colour themes from `--from` (default the installed app's `extensions` folder on macOS; a missing folder or theme file stops it at the start with the path and the flag that sets it), parses JSON with comments and trailing commas, follows `include` to its end and reads `tokenColors` given as a list or a file, and writes `src/lib/themes/vscode.css`: one `body.vscode-<slug>` block per theme, generated, its head comment naming the source, VS Code's MIT licence and the command that writes it. `--check` writes nothing and exits non-zero, naming each block, when the file is not what a run would write. A second run changes nothing. The mapping is pure (a function from a resolved theme to its block), so the cases run it without the file system.

2. **The mapping.** Each token is the first key of its list that the resolved theme holds (decision 2): `--bg` sideBar.background, activityBar.background, editorGroupHeader.tabsBackground, editor.background; `--panel` editor.background, else the scopeless tokenColors rule's background; `--card` editorWidget.background, input.background, dropdown.background, sideBarSectionHeader.background; `--chip` the value of `--card`; `--ink` foreground, editor.foreground, sideBar.foreground, else the scopeless rule's foreground; `--muted` tab.inactiveForeground, descriptionForeground, editorLineNumber.foreground; `--line` sideBar.border, panel.border, editorGroup.border, contrastBorder, tab.border; `--accent` focusBorder, button.background, activityBarBadge.background; `--tab-active-txt` tab.activeForeground, `--tab-inactive-txt` tab.inactiveForeground, `--tab-active-border` tab.activeBorder, each only when the theme holds the key; the Source Control tokens from `gitDecoration.addedResourceForeground`, `modifiedResourceForeground`, `deletedResourceForeground`, `conflictingResourceForeground`, `editorGutter.modifiedBackground`, and the `-bg` tints from `diffEditor.insertedLineBackground` and `diffEditor.removedLineBackground` and `merge.incomingContentBackground`. The six code tokens from the last `tokenColors` rule whose scope list holds the scope exactly: comment `comment`; keyword `keyword`, `storage`, `keyword.control`; string `string`; number `constant.numeric`; name `entity.name.function`, `entity.name`, `support.function`; meta `meta.tag`, `entity.name.tag`, `meta.preprocessor`, `punctuation.definition.tag`. A colour with an alpha is composited over the theme's `--panel` to six digits, an alpha of `ff` dropped. A dark or high-contrast-dark theme also sets `color-scheme: dark`, `--shadow: none` and the red and amber tints of `body.dark`, as the Modern dark block does.

3. **The fallbacks.** A token none of whose keys the theme holds takes the value of the same token in oculus's own base of its type (decision 3): `body.dark` for `vs-dark` and `hc-black`, `:root` for `vs` and `hc-light`; a high-contrast theme's `--line` and `--accent` take `contrastBorder` and `contrastActiveBorder` first. A tab token with no key is left out, so the strip keeps the surfaces' colours. The block's comment names each token that fell back.

4. **The contrast.** Every generated theme passes `tests/checks/look/contrast.test.ts` at 4.5:1, its threshold unchanged. An authored text token the test measures directly (`--tab-active-txt`, `--tab-inactive-txt`) that falls short is nudged by the converter in lightness with `derive.ts`'s own rule and functions until it clears 4.5:1 on its surfaces, and the block's comment names VS Code's value beside it, as the light Modern block does today; no other value is changed to pass. A theme that still fails is a finding the report names with the pair and its ratio, never a theme added with a loosened check.

5. **The themes.** All 19 colour themes go through the converter: the 17 oculus does not have and the two Modern themes, whose hand-written blocks leave `themes.css` (decision 1). `config/appearance.yml`'s `themes:` gains a row per theme, `name` and `class` `vscode-<slug>` (`vscode-2026-dark`, `vscode-2026-light`, `vscode-dark-plus`, `vscode-light-plus`, `vscode-visual-studio-dark`, `vscode-visual-studio-light`, `vscode-high-contrast`, `vscode-high-contrast-light`, `vscode-abyss`, `vscode-kimbie-dark`, `vscode-monokai`, `vscode-monokai-dimmed`, `vscode-quiet-light`, `vscode-red`, `vscode-solarized-dark`, `vscode-solarized-light`, `vscode-tomorrow-night-blue`; the Modern rows keep their names), glyph `theme_base`, label "vscode " and VS Code's label in lower case; the VS Code rows follow `vscode-light-modern`, in VS Code's picker order (light, dark, high contrast, each by label). `vscode.css` is loaded beside `themes.css` (`+layout.svelte`, `ui/theme.ts`) and read by `tests/checks/look/themes.ts`, so the contrast test measures every block. A saved choice of `vscode-dark-modern` or `vscode-light-modern` still applies.

6. **The text.** The head comment of `themes.css` drops the sentence on two hand-written VS Code blocks and says the VS Code themes are generated into `vscode.css` by the converter; `DESIGN.md:72`, `:244` and `:565`, `tokens.css:5`, `derive.ts:1` and `window-options.ts:35` are made true or marked still true; `docs/window.md` or the guide that lists the themes, and `HELP.md` where it names them, list the VS Code themes and the command that regenerates them.

7. **Sizes.** `vscode.css` at or under 880 lines; `themes.css` shrinks by the two Modern blocks. No folder passes 10 items (`src/lib/themes` takes one file, `utils/migrations` one).

## Decisions taken in this brief (each reversible, none silent)

1. The two Modern themes go through the converter too (Z747), so every VS Code theme in oculus comes one way and the hand-written sentence goes with them; the visible change is `--card` and `--chip` of the dark block (`#262626` to `#202020`) and what case 9 lists. Keeping the two hand-written blocks beside generated ones is the lazy option: two ways to the same kind of theme.
2. The mapping of item 2, each token's key list in that order (Z747): it reproduces the hand-written dark Modern block's `--bg`, `--panel`, `--ink`, `--muted`, `--line` and `--accent` and gives a value for every theme the run above read; `--chip` follows `--card` because oculus's chip is a neutral surface and VS Code's `badge.background` is a filled accent.
3. A missing key falls back to oculus's own base of the theme's type (Z747): the result reads like the rest of oculus, where VS Code's registered defaults sit in its compiled workbench and are no file the converter can read.
4. The converter lives in `utils/migrations/` beside the other converters, since `utils/` is full and the folder holds the tree's one-shot writers; it is run by hand when VS Code's themes change, and `vscode.css` is committed.
5. The names, classes and labels of item 5 (Z747): `vscode-` and VS Code's label as a slug, as the Modern rows are named, glyph `theme_base` as theirs.
