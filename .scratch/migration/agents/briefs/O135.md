## What to build

1. One reading of a note's header, in `front-matter.ts`: an exported function that takes a note's text and gives its header the way the note scan reads it (`withoutMark`, CR and CRLF read as LF, `FRONT_MATTER`), and `scanNote` calls it, so the tags and the command read the same lines. `front-matter.ts` may import `withoutMark` from `text-edits.ts`. Its head comment (:1-24) names the function, and the comment of `tests/checks/tree/layer-rows.ts:228-236` says what the module holds after the change, as true as it is now.
2. The text the command inserts, `---\ntags: []\n---\n`, is one exported constant in `front-matter.ts`, written with LF, with a doc comment naming the templates page's note head it matches. Monaco writes it in the model's line ending, so no code of the step picks the ending.
3. `isNoteFile` is exported from `note-hooks.ts` (it may be renamed to say what it answers; its callers at :42 and :84 change with it), and the head comment (:1-8) says the source tab asks it too.
4. The source tab offers the action in `tabActions` while all hold, tested in this order: the text may be written (`editing`), the file is a note (item 3, with `client.fs.roots()` and the tab's file as `root/path`), and the note has no header (item 1). The fact is one `$derived` boolean, declared in `Source.svelte` or a partial, which a getter of `facts` returns, so `own` is derived again only when that boolean changes and a tab that is no note never reads its text for it. The action's id is exported from `editor-status.svelte.ts` beside `SAVE_ACTION` and `REVERT_ACTION`, its doc comment saying the tab offers it and the tab menu runs it. Its palette label is `Markdown: Add Front Matter`. The head comments of `ask-perform.ts` and `tab-asks.svelte.ts` and the palette list of `Source.svelte`'s head comment (:40-43) name it. `SaveKeyHost.svelte` gains whatever field `SourceFacts` or `SourceDoes` gains.
5. Running it is one edit at the start of the text through the editor: `EditorCommand` gains a command that inserts a text at line 1 column 1, performed in `commands.ts` as one `executeEdits` with `forceMoveMarkers: true` between two `pushUndoStop` calls, after which the editor takes the keyboard (`made.focus()`, as `insert` does). One Undo takes the header out and gives the text back as it was; the caret and the selections stay on the text they were on. The doc comment of `EditorCommand` and `commands.ts`'s head comment name the command. The edit is an editor edit like typing and saves through the tab's save, so spec.md's rule on a write that edits a file's text re-parsing its result does not apply; C8 is the read after it.
6. The tab menu offers `Add Front Matter` on a tab whose published actions (`editorStatus.statusOf(tab)?.actions`) hold the action's id, in a group of its own after the compare items, and a pick of it asks the tab `{ kind: 'action', id }`. A tab with no published status is offered none. The head comments of `tab-menu.ts` and `tab-menu-state.svelte.ts` and `tabMenu`'s doc comment name the item.
7. `docs/HELP.md`, in the notes section, after the front-matter bullet (line 406): one sentence. A note without front matter offers Markdown: Add Front Matter, in the command list and the tab's menu, which writes `---`, `tags: []` and `---` at its top as one edit that one Undo takes back; a note with front matter, and a file that is no note, are not offered it. The builder words it to the rules file's prose rules.
8. `Source.svelte` stays at 520 lines or fewer: what the step adds there is offset by moving code of the tab into a partial under `status/` (which has room for two files), named in the report.

## Decisions taken in this brief (each reversible, none silent)

1. Whether a note has a header is the note scan's reading (item 1), so the command is offered exactly when the tags read no header. The preview's reading differs only for a byte-order mark and for lone CR line ends (`docs/HELP.md:406`), and a tab's text never holds the mark. Run on seven texts under "What is on the tree".
2. The reading and the inserted text live in `front-matter.ts`, the one module of the note scan's family the views row admits (`layer-rows.ts:290`), so the source tab imports them with no new line in an allow list; the action id lives beside `SAVE_ACTION` in `editor-status.svelte.ts`, which both the tab and the shell may import.
3. The tab menu offers the item on a tab that has published its actions: a note tab shown since the page loaded, on screen or hidden behind another tab of its pane. A tab not shown since the page loaded has no text in the page, so whether its note has a header is not known there, and it is offered none.
4. The labels: `Markdown: Add Front Matter` in the palette, after `Markdown: Open Preview to the Side` and `Markdown: Toggle Rendered Half`; `Add Front Matter` in the tab menu, whose items carry no category, in a group of its own after the compare items.
5. The insert goes through a new editor command at the start of the text, not through `replace` of the whole text, so text typed meanwhile is never overwritten and the caret stays where it was; the editor takes the keyboard after it, as the `insert` command does.
6. No guarded entry and no test: a wrong offer, on a note that has a header, puts a second, empty header above the first, so the note's tags read as none until one Undo takes it back; no text is lost and the file stays a valid note. The rules file's test rule calls for none; the cases are case-run output and the look.
