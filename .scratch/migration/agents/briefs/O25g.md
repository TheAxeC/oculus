# Brief: O25g, the Focus ticker's feed lines open their views

Read `../spec.md` first; it governs this package unchanged. The Focus board's command center (`views/focus/CommandCenter.svelte`) already draws, from the snapshot, the position-lead deadlines (`state/focus.ts` line 565 on, each line with a target `{ kind: 'lead', id: <title> }`), the attention lines (`state/feeds.ts` `attention()`: `{ kind: 'inbox' | 'linkedin' | 'venue', count, label? }`) and the refresh nudges (`refresh()`: `{ feed, days }` for the feeds that have not run lately). The cockpit's ticker lines were links into the tabs they named; here `pick()` (`CommandCenter.svelte` line 308 on) opens a project's tab or a collection file's tab and nothing for a lead, an attention line or a nudge, since the Leads, Inbox and LinkedIn views and the Update tray did not exist when P2 built the board. O25c to O25f landed them; this package is the link-up.

## The acceptance list

1. A lead line opens the Leads view (`leads`) with that lead revealed: the line's target `{ kind: 'lead', id }` goes through the reveal mechanism O25f built (open the view with `openView('leads', 'main')`, then `setInstanceState(<the returned instance id>, { ...held, reveal: id, expiredOpen: true })`, the same call the palette makes; read `shell/palette-open.ts` and do it the same way from the view). A lead line carries no other control: the leads feed writes `status` only and a lead's actions live in the Leads view (the sentence "keeps its snooze control" that stood here until 2026-09-12 was wrong; the worker said so).
2. An attention line of kind `inbox` opens the Inbox view, one of kind `linkedin` the LinkedIn view, one of kind `venue` the Venues view with that venue revealed (`reveal: <venue id>`; the line's `label` is the venue's label and the venue's id is what the item carries, add it to `AttentionItem` as `id?` if it is not there). The count and the words stay as they are.
3. A refresh nudge (`feed` one of `litwatch`, `scout`, `linkedin`, `inbox`, whatever `refresh()` names) opens the Update tray. The tray is the shell's (`shell/UpdateTray.svelte`, opened by `openUpdate()` in `shell/Workbench.svelte`) and a view never imports the shell, so the view asks through the ui store: `state/ui.svelte.ts` gains `requestUpdateTray()` and `updateTrayRequested()` (a counter or a flag the workbench's effect observes and resets after opening the tray). A user-visible shape only in that the nudge becomes clickable; the store call is internal.
4. Each of the three line kinds is a control (a `ToolButton` or the line's existing link primitive, whichever the board's other lines use; read how a project line opens its tab), with the words unchanged.

## Decisions taken in this brief (each reversible, none silent)

1. **The reveal goes through the ui store, never the layout state**, as O25f's repair settled: the layout instance's state is its identity, so a reveal there would open a second tab.
2. **The tray request is a ui-store signal.** `requestUpdateTray()` increments a counter; `Workbench.svelte` opens the tray in an effect when it changes. Nothing else changes in the shell.
3. **No new text key.** The lines' words are the board's.
