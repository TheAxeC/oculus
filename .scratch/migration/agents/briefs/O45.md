## What to build

What must hold: a source that names `folder` unpacks only the entries under that folder of each of its archives, the folder's own contents landing in the archive's folder (where the unpack puts every archive today); `strip` then drops leading folders below it as it does today; a source without `folder` unpacks exactly as today.

- `model-entities.ts`: `SourcePlace` gains `folder?: string`, its doc comment saying what it does and that `strip` counts below it; `RecoverFile.unpack` becomes `{ strip: number; folder?: string }`, its comment saying so.
- `retrieval.ts`: `placeShape` reads `folder` as text (a number written in the YAML reads as its digits, as `into` does through `wordShape`) and as a relative path inside an archive: one or more segments joined by `/`, none empty, `.` or `..`, no leading `/`, no backslash, a trailing `/` allowed and dropped. A `folder` that breaks this, or a `folder` on a source without `unpack: true`, does not fit, so the source is left out and its set is not one Recover runs.
- A source left out is a finding: `retrieval.ts` (or `normalise.ts` beside `resourceFaults`) gives the faults of each dataset's sources by position, and `validate-kinds.ts` reports each as a finding, as it reports `resourceFaults`, naming the dataset, the source's position and kind, and that Recover does not run the set, through one new line of `config/text/findings.yml`. This covers every field of a source, `strip` and `folder` alike, and the head comment of `retrieval.ts:6-8` is rewritten to what holds.
- `routes.ts:159`: the plan row of an unpacking source carries `folder` when the source names one.
- `files.ts:53` and `recover.svelte.ts:42`: the kept listing's row and the page's row accept `folder`, the kept listing's through the same rule as `retrieval.ts` (one shared function), so a kept listing whose folder breaks the rule reads as no listing and the sources are listed again from the registry; the page's as a string.
- `unpack.ts`: `UNPACK_PROGRAM` takes the folder as a sixth argument (empty when the source names none). With a folder, the program finds it one segment at a time by exact name in `readdirSync` of the folder above (so this Mac's case-insensitive disk and the cluster's give one answer), each segment checked with `lstatSync` to be a folder and not a link, and then checks `fs.realpathSync` of the found folder is inside `fs.realpathSync(<work>/out)`. When a segment is missing, a file or a link, the program says `unpack failed: the archive holds no folder <folder>`; when the folder is empty, `unpack failed: the folder <folder> in the archive is empty`; in both it moves nothing, and the archive stays. A folder argument that is absolute or holds a `..` segment is refused the same way, before 7-Zip runs. `place()` then starts at the found folder, and the walk below it uses `lstatSync`, so a link inside the archive is moved as a link and never followed (this also holds for the walk with no folder). The rest of the archive is removed with the work folder, as today. The head comment (`:1-12`, which says every path is moved with `strip` folders dropped) and the argument comment are rewritten to the folder, the strip below it and the six arguments. `UnpackInput` gains `folder: string` and `unpackVector` passes it as one argument.
- `local.ts`: passes `row.unpack?.folder ?? ''`.
- `cluster.ts`: the job's `unpack()` function passes `"$3"` to the program as its sixth argument, and each call line is `unpack <name> <strip> <folder>`, the name and the folder through `shellWord` (the empty folder as `''`), the strip a number as today.
