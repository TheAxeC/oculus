## The acceptance list

1. **The location.** `localFile` reads `<configDir(engine)>/local.yml` by default (`OCULUS_LOCAL` as now, `required` as now), with `base` still the engine directory, so a relative `hub` in the file means what it meant. `configNames` leaves `local.yml` out, so `loadConfig` never merges it and never reports its keys as a clash; a `local.yml` in the folder with a key the merged map also holds is not a finding. `tools/oculus/.gitignore` says `config/local.yml`. The checkout's own file is moved by the orchestrator at landing, never by you (you never touch the real `tools/oculus/local.yml` or `config/local.yml`).
2. **Served and carded.** The `engine` root serves the file like any other of the folder (the file route reads it, the source route saves it; `server/files.ts`'s comment says so). The Config view draws it as one card when the file is there, after the tracked files, marked as this machine's own (a `Tag` with the catalog's words, `config.local_tag`), with `config.desc_local` as its line; the intro line no longer says the file is not served and says instead where it is and that it is this machine's own; `Config.svelte`'s head comment follows. A folder without the file draws no such card and no empty line for it.
3. **What a save does.** A save of `local.yml` from the source tab is an ordinary write under the root; the watcher's config push follows and `loadConfig` skips the file, so nothing else moves. Which keys are read once at start (`server/context.ts`: at least `hub` and `port`) and which at each use is a fact `HELP.md`'s paragraph states in one sentence, and your report lists every key with its reader's `file:line` and whether it is read at start or per call; the sentence is written from that list.
