## What to build

1. **The command sources** (new `src/lib/server/machine/commands/`). For a repository (an absolute folder that is a served root or a git repository under one, its real path inside that root), the commands are, in this order, each `{ name, run, cwd, depends_on, default?, source }`, every file read through a zod schema beside its reader, a field of the wrong type a finding with the file and the field:
   - `<repo>/.oculus/commands.yml`: `commands:` a list of `{ name, run, cwd?, depends_on?, default? }`; `cwd` relative to the repository, default the repository, its real path inside the repository's real path (an absolute `cwd`, `../x` or a link leading out is a finding); `default` is `build` or `test`; `source: 'file'`.
   - `~/.oculus/commands.json` (Z194 (1)): `{ "<absolute repository path>": [ { name, run, cwd?, depends_on?, default? } ] }`; `source: 'saved'`.
   - found (Z85 (2)): CMake presets from `CMakePresets.json` and `CMakeUserPresets.json` (configure as `cmake --preset <n>`, build as `cmake --build --preset <n>`, test as `ctest --preset <n>`, `hidden: true` left out); `package.json` `scripts` as `<pm> run <name>`, `<pm>` `pnpm` with `pnpm-lock.yaml`, `yarn` with `yarn.lock`, else `npm`; the top `Makefile` (or `makefile`, `GNUmakefile`) targets: a line `^([A-Za-z0-9_][A-Za-z0-9_./-]*(?:\s+[A-Za-z0-9_][A-Za-z0-9_./-]*)*)\s*:(?![:=])` gives each name before the colon, except a line whose `:` begins `:=`, `::=` or `:::=`, a pattern rule (`%`) and a name starting with `.`; every name from a found source is one quoted shell word in its line (`npm run 'a b'`); `source: 'found'`, named `cmake: <n>`, `npm: <n>`, `make: <t>`.
   - An empty or whitespace `name` or `run`, a name over the terminal name limit (`NAME_MAX`) or holding a tab or newline, a repeated name within one source (the first kept), a second `default: build` or `default: test` in a repository (the first kept): each a finding, the entry left out or the default ignored. A name in two sources lists both; a `depends_on` name resolves to the first in the order file, saved, found.
2. **One shell quoting.** `shellWord` moves to one exported module (`server/machine/pty/shell-word.ts`) and its three copies import it; it always quotes (`'7'`).
3. **Placeholders** (Z85 (3)). `${file}`, `${fileDirname}`, `${fileBasename}`, `${fileBasenameNoExtension}`, `${lineNumber}`, `${selectedText}`, `${workspaceFolder}` are replaced by the server before the shell sees the line, each value one `shellWord`, from the context the page sends: the active source tab's absolute file and line (from `editor-status.svelte.ts`), its selected text (the editor's selection, which `Source.svelte` adds to what it publishes there), and the repository. A placeholder the page has no value for refuses the run, naming the placeholder. Any other `${...}` is left as written.
4. **Approvals** (Z194 (3), `DESIGN.md:326`; new `src/lib/server/machine/approvals/`, shared with the apps and D20). The file is the one `DESIGN.md:326` describes, its path the `approvals` key of `local.yml` read through `loadLocal` (a new key in `data/sources/config/local.ts`, default `~/.oculus/approvals.json`); the builder never opens the real `local.yml`, and tests set `HOME` and hand the path in. A command entry is `command:<sha256 hex>` with `label` (the text) and `at`. The hashed text is exactly what runs before placeholders are replaced: each command of the chain as `<cwd relative to the repository>\t<run>`, one per line, so a changed `cwd`, line or chain asks again. Written mode 0600 in a 0700 folder, by rename, read back; a file that is not JSON or not the shape is read as empty for checking and a write over it is refused with the reason, the file untouched. A command saved through the form is text the reader wrote into oculus and needs no approval; a found command or a file command does. A chain needing approval asks once, listing every unapproved text.
5. **The routes.** `GET /api/commands?repo=<abs path>` lists the commands and the findings; `POST /api/commands` carries `{ action: 'approve', repo, texts }`, `{ action: 'save', repo, command }` and `{ action: 'remove', repo, name }`, each through the origin rule and the write token (`DESIGN.md:147`), the saves and removes through the write chain and the change log, the bodies read through zod shapes; a `repo` that is relative, missing or under no served root is 400 with nothing read. A listing, an approval check or a page render starts no process.
6. **The run** (`pty/routes.ts`, a `command` action). `{ action: 'command', repo, name, context, cols, rows }` resolves the command and its `depends_on` chain (each once, in the order listed; a cycle, a self-dependency or an unknown name refused with the names), checks the approval, answers `{ approve: [<texts>] }` when one is missing and starts nothing, and otherwise starts one shell terminal named after the command whose line runs each command in order, `cd <cwd> && printf '%s\n' <name> && <line>` joined by `&&`, every `cwd` and name one `shellWord`, so a failure stops the chain. The terminal is shown and selected. The action list's refusal text names `command`.
7. **The task terminal and its result** (Z194 (5); `sessions.ts`, `model-sessions.ts`, `terminal-payloads.ts`). A terminal started by a command is a task terminal: `remain-on-exit on` is set in the same tmux invocation as `new-session`, and a tmux user option `@oculus_task` marks it, so it survives a server restart. `Terminal` gains `task: boolean` and `exit: number | null` (`#{pane_dead}`, `#{pane_dead_status}`), added to `LIST_FORMAT` before `#{pid}` so `#{pid}` stays last, `terminal-edit.test.ts` updated, `terminalShape` and every fixture that builds a full `Terminal` given the two fields. While a task terminal runs, the pty channel polls at `POLL_MS` whether or not a page is attached, so its result reaches the page within 5 s of its end. The tab and the list row show a check for exit 0 and a cross otherwise, as VS Code's do. Its menu and bar gain Rerun (after it ended: `respawn-pane -k` of the same line in the same terminal; refused while it runs) and Restart (while it runs: a confirmation naming the process, then the line stopped and run again; after it ended, it behaves as Rerun). An ended task terminal does not count as running for the rule that a Terminal tab never closes while its terminals run, or for Close pane's confirmation. Closing a task terminal kills its session. The LaTeX build terminals are not task terminals.
8. **Errors made clickable** (Z281). In a task terminal's output a line matching `^(?<file>[^\s:][^:]*):(?<line>\d+)(?::(?<column>\d+))?:\s*(?<severity>error|warning)\b:?\s*(?<message>.*)$` (case-insensitive severity) has its `file:line[:column]` drawn as a link (an xterm link provider) that opens the file, resolved from the command's `cwd`, at the line in a source tab; a file that does not exist under the repository is not a link. The commands store keeps each task terminal's matches as diagnostics in D14's shape, `{ root, file, line, column?, severity, message, source: 'command:<name>' }`, through `commandDiagnostics()`, a rerun replacing them.
9. **Default build and test** (Z281). Cmd+Shift+B runs the default build and Cmd+Alt+T the default test (Ctrl in place of Cmd off macOS) of the repository holding the active source tab's file; with no such tab, no repository, or no default, the status bar says which, and nothing runs. The keys go through `shell/keys/keys.ts` and are listed in HELP.md's key table.
10. **Where they are drawn** (new `src/lib/views/shared/commands/`). One commands component: buttons with each command's name, a press runs it, a tooltip with its text and source, an overflow menu beyond five; on the project card (`CardActions.svelte`, the commands of the project's folder when it is a repository), in each repository header (`Repo.svelte`), and as a "Run Command" submenu in the Files row menu of a root or a repository's folder. A press on an unapproved command shows the confirmation: the command's name and each exact text, Approve and Run, Cancel. "Add Command..." opens the form: name, the line, an optional folder, an optional list of commands it depends on, an optional default (build, test, none), saved for that repository; a saved command's menu has Edit and Delete; a file or found command's has Open File at its entry (`.oculus/commands.yml`, `package.json`, the presets file or the Makefile).
11. **The client store** (`state/sessions/terminal/commands.svelte.ts`, the folder's tenth item). `commands(repo)` per repository through the query helper, read again on a `files` channel mark under that repository's command files and after a write of the form; `run(repo, name)`, `approve(repo, texts)`, `save(repo, command)`, `remove(repo, name)`, and the Rerun and Restart calls; a read answered after its view closed changes nothing, a later read supersedes an earlier one. `terminals.svelte.ts` stays under 900 lines.
12. **Docs.** `DESIGN.md`'s Processes passage names `commands.json` and the command approvals; its sentence that a terminal that ends leaves the list (in the bullet "The pty bridge is tmux control mode") and the comments of `channel.ts:12-16` and `:62-67` say a task terminal stays after its end and is polled while it runs; `HELP.md` says where commands come from, the form, the approval, the placeholders, `depends_on`, `default`, the two keys, the error links, and Rerun and Restart.
