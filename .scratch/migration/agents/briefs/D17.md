# Brief: D17, project commands

Read `tools/oculus/.scratch/migration/agents/spec.md` first; its rules govern this step unchanged. The plan names no further standards. No ADR touches the step: the repository has no `docs/adr` folder (`ls tools/oculus/docs/adr docs/adr` prints "No such file or directory" for both, and the configuration block has no `adr:` key). The `DESIGN.md` rule the step is measured against is **Processes** (`DESIGN.md:150`): "A process oculus starts from text the reader did not write into oculus's own configuration (a command in a repository's `.oculus/commands.yml`, a debug launch, an agent seeded with a task) runs only after the reader has approved that exact text on this machine, the approval kept under `~/.oculus/` and keyed by the text, so a changed text asks again; it runs in a pane the reader can see, never in the background; and oculus stops only processes it started itself, behind a confirmation naming the process."

A design ruling decides what is built. It never exempts the code: every line is written to the standards pages, so that people can read, use and maintain it.

## What to build

1. **The command sources** (new folder `src/lib/server/machine/commands/`). For a repository root (an absolute folder that is a served root or a git repository under one), the commands are, in this order, each `{ name, run, cwd, depends_on, source }`:
   - from `<repo>/.oculus/commands.yml`: `commands:` a list of `{ name, run, cwd?, depends_on? }` (`cwd` relative to the repository, default the repository; `depends_on` a list of names of this list, Z194 (2)); `source: 'file'`. A malformed file or entry is a finding the view shows with the file's path and the reason, and its good entries still list.
   - from the form, `~/.oculus/commands.json` (Z194 (1)): `{ "<absolute repository path>": [ { name, run, cwd?, depends_on? } ] }`; `source: 'saved'`.
   - found (Z85 (2)): CMake presets from `CMakePresets.json` and `CMakeUserPresets.json` (`configurePresets` as `cmake --preset <n>`, `buildPresets` as `cmake --build --preset <n>`, `testPresets` as `ctest --preset <n>`, a preset marked `hidden: true` left out); `package.json` `scripts` as `<pm> run <name>`, `<pm>` `pnpm` with a `pnpm-lock.yaml`, `yarn` with a `yarn.lock`, else `npm`; the top `Makefile`'s (or `makefile`, `GNUmakefile`) rule targets as `make <target>`, a target being a line `^([A-Za-z0-9_][A-Za-z0-9_./-]*)\s*:(?!=)` that is not a pattern rule (`%`) and not `.PHONY`-style (leading `.`); `source: 'found'`, names `cmake: <n>`, `npm: <n>`, `make: <t>`.
   A name repeated within one source keeps its first entry, and the view shows the repeat as a finding.
2. **Placeholders** (Z85 (3)). `${file}`, `${fileDirname}`, `${fileBasename}`, `${fileBasenameNoExtension}`, `${lineNumber}`, `${selectedText}`, `${workspaceFolder}` are replaced by the server before the shell sees the line, each value quoted as one shell word (the existing `shellWord`), from the context the page sends: the active source tab's absolute file, its line, its selection, and the repository. A placeholder whose value the page has none for (no source tab open) refuses the run with the placeholder named. Any other `${...}` is left as written.
3. **Approval** (`DESIGN.md:150`, Z194 (3)). A command from `.oculus/commands.yml` or found by oculus runs only when its text, as written before the placeholders are replaced, is approved on this machine: `~/.oculus/approvals.json` holds `{ "<sha256 of the text>": { "text": "<text>", "approved": "<ISO instant>" } }`. A run of an unapproved text answers `{ approve: <text> }`; the page shows a confirmation naming the command and quoting its exact text, with Approve and Run and Cancel; Approve writes the approval and runs. A changed text asks again. A command saved through the form is text the reader wrote into oculus and needs no approval. A chain needs every unapproved text approved in one confirmation listing each.
4. **The run** (`pty/routes.ts`, a new `command` action). `{ action: 'command', repo, name, context }` resolves the command and its `depends_on` chain (names in the order listed, each once, a cycle or an unknown name refused with the names), checks the approvals, and starts one shell terminal named after the command whose line runs each command of the chain in order, each in its own `cwd`, as `cd <cwd> && <line>` joined by `&&`, so a failure stops the chain; before each command the line prints its name (Z194 (4)). The terminal is shown and selected, as every start is. Nothing runs without a press.
5. **The task terminal and its result** (`sessions.ts`, `model-sessions.ts`, Z194 (5)). A terminal started by a command is a task terminal: tmux's `remain-on-exit` is set on its session, so it stays after its line exits; the terminal record gains `task: boolean` and `exit: number | null` (`#{pane_dead}` and `#{pane_dead_status}` in the list's format, null while it runs). The tab and the list row of a task terminal show a check for exit 0 and a cross otherwise, as VS Code's do. Its menu and its bar gain Rerun (runs the same line again in the same terminal, `respawn-pane -k`, only after it has ended) and Restart (stops the running line and runs it again, behind no confirmation as VS Code's restart has none, since oculus started it). Closing a task terminal kills its session as today. The LaTeX build terminals are not task terminals, so their watch, which waits for the terminal to leave the list, is unchanged.
6. **Where they are drawn.** One commands component, drawn as buttons with each command's name, a run on a press, a tooltip with its text and source, and an overflow beyond five: on the project card (the commands of the project's folder when it is a repository), in the Repositories view (each repository's header), and in the Files row menu of a root or a repository's folder as a "Run Command" submenu. Beside them, "Add Command..." opens the form: name, the line, an optional folder and an optional list of commands it depends on, saved to `~/.oculus/commands.json` for that repository; a saved command has Edit and Delete in its button's menu. A command from the file or found has Open File, which opens `.oculus/commands.yml`, `package.json`, the presets file or the Makefile at the entry.
7. **The client store** (`state/sessions/terminal/commands.svelte.ts`, the folder's tenth item). `commands(repo)` held per repository through the query helper and read again when the repository's `.oculus/commands.yml`, `package.json`, presets or Makefile change (the `git` and `fs` channel marks the store already hears) and after a form write; `run(repo, name)`, `approve(texts)`, `save(repo, command)`, `remove(repo, name)`. `terminals.svelte.ts` is not grown past 900 lines.
8. **Docs.** `DESIGN.md`'s Processes passage names `approvals.json` and `commands.json`; `HELP.md` says where commands come from, the form, the approval, the placeholders, `depends_on`, and Rerun and Restart.

## Cases

Unit cases (server cases over a scratch repository and a scratch home under the test's temp directory; `HOME` set there):

1. `.oculus/commands.yml` with `{ name: build, run: make }` and `{ name: test, run: make test, cwd: sub, depends_on: [build] }`: both listed, `cwd` absolute under the repository, `source: 'file'`; an entry without `run`: a finding, the other entries listed; a file that is not YAML: a finding, no entries from it.
2. `commands.json` with two repositories: each repository lists only its own.
3. Found: a `CMakePresets.json` with one configure preset, one hidden one and one build preset; a `package.json` with `dev` and `test` and a `pnpm-lock.yaml`; a Makefile with `all:`, `clean:`, `%.o: %.c`, `.PHONY: all` and `X := 1`: `cmake: <configure>` as `cmake --preset <n>`, `cmake: <build>` as `cmake --build --preset <n>`, `npm: dev` as `pnpm run dev`, `make: all`, `make: clean`, and nothing else.
4. Placeholders: `echo ${fileBasenameNoExtension} ${lineNumber}` with the file `/r/a b.tex` and line 7: `echo 'a b' 7`; `${selectedText}` holding `'; rm -rf /'`: one quoted word; `${file}` with no source tab: refused naming `${file}`; `${env:HOME}`: left as written.
5. Approval: a file command never approved answers `{ approve: <text> }` and starts nothing; after `approve`, it runs; the file's text changed: asks again; a saved command: runs with no approval.
6. A chain: `test` depending on `build`: one terminal whose line is `cd <repo> && <echo build> && make && cd <repo>/sub && <echo test> && make test`; a cycle `a -> b -> a`: refused naming both; an unknown dependency: refused naming it.
7. The task terminal: started with `remain-on-exit`; a line that exits 3 lists `exit: 3`, `task: true` (driven over the tmux layer's fake as the existing session tests are); a running one `exit: null`; Rerun of a running one refused; Rerun of an ended one respawns.
8. The store: `commands(repo)` asks once; a form `save` then reads again.
9. The view: buttons for three commands, an overflow at six, Add Command opening the form; a press on an unapproved command shows the confirmation with its exact text.

Look items on landing (TEST, the orchestrator): a repository with `.oculus/commands.yml` (written in a scratch repository under a root, never in the hub's own folders), a `package.json` and a Makefile; the buttons on the card, in Repositories and in the Files menu; a first run asking approval with the text; a chain; a failing command showing a cross on its tab and a passing one a check; Rerun and Restart; the form's add, edit and delete.

Implied inputs, each with its result:

10. A repository with no command source: no buttons, Add Command only.
11. A `cwd` that leaves the repository (`../x`): refused at listing as a finding.
12. A name in both the file and the form: both listed, the file's first, each with its source.
13. A command started while another task terminal of the same command runs: a second terminal, as VS Code allows (stated).
14. `approvals.json` or `commands.json` that is not JSON: read as empty, and a write over it refused with the reason rather than replacing it.
15. A task terminal ended while no page is open: its result is in the list when a page opens (the session stays).

## Decisions taken in this brief (each reversible, none silent)

1. Z194 (1) (the orchestrator, automode): the form saves to `~/.oculus/commands.json`, keyed by the repository's absolute path, beside `changes.jsonl`.
2. Z194 (2): a command's dependencies are `depends_on`, a list of names run in the order listed, VS Code's `dependsOn` with `dependsOrder: sequence` in the hub's snake case.
3. Z194 (3): approvals are `~/.oculus/approvals.json`, keyed by the SHA-256 of the text and holding the text and when it was approved.
4. Z194 (4): a chain runs in one task terminal, each command in its own folder, joined by `&&`, so the chain's result is one check or cross; VS Code shows each dependency in its own terminal.
5. Z194 (5): a task terminal stays after its line ends (tmux `remain-on-exit`) and the terminal record carries `task` and `exit`; this is what lets its tab show the result and Rerun run it again.
6. A command saved through the form needs no approval, under `DESIGN.md:150`'s "text the reader did not write into oculus's own configuration".
7. The package manager of a `package.json` script follows the lockfile, as VS Code's npm tasks follow its package manager setting.
