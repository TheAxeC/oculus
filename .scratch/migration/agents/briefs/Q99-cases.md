# Q99, the cases ruled (round 0)

The builder's first run found two rules of the brief that give a wrong result, and one risk item 2 creates. Each ruling below replaces the brief's text it names.

1. Item 3, the screen an attaching page is given. The brief's rule (keep the capture's lines up to row `lines - pane_height + cursor_y`, then `ESC[<cursor_x + 1>G`) lands on tmux's row only when the pane has no history or the cursor is on its last row; with history and a cursor above the last row (the builder's probe: `8 20 24 20`, 44 lines) it leaves the page's cursor on the bottom row and drops the rows under the cursor. Ruled: the whole capture is sent without its final newline, the CR LF rewrite kept, followed by `ESC[<cursor_y + 1>;<cursor_x + 1>H`. `screenAt` takes that shape. The cases become: a 24-line capture with cursor `2 2 24` gives all 24 lines and `ESC[3;3H`; a 30-line capture with cursor `0 23 24` gives all 30 lines and `ESC[24;1H`; the history case with cursor `8 20 24` gives all 44 lines and `ESC[21;9H`; a cursor that does not parse gives the capture as now, said on the console. The report states that both the page's grid and tmux's pane must be the same height for the cursor to land right, which holds once the page's resize has reached tmux.
2. Item 2, the tabs that follow the selection. `followsSelection` is also true for a composer New put in a tab (`{ id, follow: true }`), which shows the composer and not the selected terminal. Ruled: when the selected terminal has ended, the selection is cleared and only the Terminal tabs that follow the selection and carry no identity of their own (`stateId(state) === null`) close; a composer tab stays, with what the reader typed. The builder's added case "keeps a composer the reader is filling in" is kept.
3. A failed `list-sessions`. `refresh` in `server/machine/pty/channel.ts` publishes an empty list when the command fails for any reason, so with item 2 one timeout would close every Terminal tab on every page while the terminals run on. Ruled, inside item 2: a failed list keeps the last list published, except when tmux's error says no server runs (`no server running on` or `error connecting to ... (No such file or directory)`), which is a real empty list, the state after the last session exits. Tested with the recording driver refusing `list-sessions` both ways.
4. The brief's byte-for-byte case is green on the unchanged tree, so it proves nothing about the fix; it stays as a check that the bytes arrive in order, and the builder's one-read case ("hands a mouse report to the pane in one read") is the proof of item 1. That case needs `python3` in the scratch pane; where `python3` is absent it is skipped with a printed reason, which the report names.
5. The Pages row's press calling `switchPage` cannot be run without a DOM; the test checks the row renders its press, and the press is seen at the landing look.
