# L2, nested pages

Read `../spec.md` first, its section "The principles every package is judged on" above all. Axel ruled on 2026-09-14 at 20:29 (plan.md Rulings): a page leaf shows another page at that spot in a page's tree; it is the same page and never a copy, so a tab opened in it is open everywhere the page shows; a page never contains itself, directly or through another page, and such a drop is refused; two page leaves side by side show two pages next to each other; a nested page is reached by focus, not by a digit (a bare digit is the strip's page, K1). L1 made a page one tree whose split children fold; this package adds the third kind of node to that tree.

## What to build

1. **The model.** A third node: `PageLeaf = { kind: 'page'; page: string }`, the id of another page; `Layout = Split | Pane | PageLeaf`. A page leaf is a leaf like a pane: it can be a split's child, it folds like any child, a drop on its edge splits beside it, a drop on its centre or strip is refused (a page leaf has no tabs of its own). `checkLayout(layout, pages)` refuses a page id the list does not hold and refuses a cycle: `containsPage(pages, hostId, nestedId)` walks every leaf of the nested page's tree, and through the pages those leaves name, and answers whether `hostId` is reached; `embedPage(pages, hostId, path, edge, nestedId)` splits the pane at `path` in the host's tree and puts a page leaf on `edge`, refusing (returning the pages unchanged) when the nested page is the host or contains it. `closePage(id)` also turns every leaf naming `id` in every other page into an empty pane, so no tree names a page that is gone. `serialiseLayout` writes the leaf as it is; `parseLayout` reads it, and a leaf naming a page the envelope does not hold reads as an empty pane. `LAYOUT_VERSION` stays 4: a version-4 envelope without page leaves is unchanged.
2. **The store.** Every tree operation that takes a path takes the page it addresses: `change(edit, page?)`, `activateInstance(id, page?)`, `closeInstance(id, page?)`, `closePane(path, page?)`, `transferInstance(id, path, index, page?)`, `splitInstance(id, path, edge, page?)`, `foldPane(path, page?)`, `expandChild(path, index, page?)`, `maximisePane(path, page?)`, `restorePanes(page?)`, where `page` is a page id and the default is the strip's current page; `activeInstance(page?)` and `layout(page?)` the same; `instanceLayoutState(id)` and `restateInstance` find the instance in whichever page holds it, as they did across the two trees before L1. New: `embedPage(nestedId, path, edge, page?)` and `unembedPage(path, page?)` (the leaf becomes an empty pane, which `settleFocus`'s rules then collapse as a closed pane does). `openView(view, state?, page?)` and `openBeside(view, state?, page?)` take the page the same way; the rail passes the page of the pane that holds the keyboard focus (read off `data-pane-page`, the strip's page when none has it), so a view opened while reading inside a nested page lands in that page; `lastActive` and `lastBeside` are per page already. A tab dragged from one page's pane into a pane of a page shown nested moves between pages: `transferInstance` and `splitInstance` take the instance out of whichever page holds it (as `moveInstanceToPage` does) and put it in the named page.
3. **The shell.** `SplitView.svelte` gains a `page: string` prop (the id of the page whose tree it draws) handed to its snippets (`pane: Snippet<[Layout, number[], string]>`, `fold` likewise) and a `leaf: Snippet<[string, number[], string]>` (the nested page id, the leaf's path, the host page) it renders for a page leaf; `Workbench.svelte` supplies `leafOf` as `PageLeaf.svelte`, a box with a one-line header (the page's label and one control, `ui.page_leaf_close`, that unembeds it) over a `SplitView` of that page's root with `page` set to the nested id, so SplitView still imports no registry and no store; every `PaneView` takes `page` and carries `data-pane-page={page}` beside `data-pane-path`, the strip's own page included, so the key handler reads one attribute pair; `Drop` and `DragSink` carry `page`. `PaneView.svelte`, `DropLayer.svelte` and `workbench-keys.svelte.ts` hand the page they read to every store call. The pane menu gains `ui.embed_page` items, one per page other than the one the pane is in and other than any page that would make a cycle, each splitting the pane to the right with that page's leaf (`embedPage` with `right`); the page strip's tab becomes draggable onto a pane's edge as well as within the strip: `drag.svelte.ts` gains a drag of kind `page` (the page id and its label) whose only drop is `edge`, performed through `embedPage`, and the strip starts one when a tab press crosses the threshold and leaves the strip. A nested page's maximised pane (`focus`) is drawn maximised inside its leaf, since the leaf draws the page's own workbench. Nothing about a nested page appears in the strip: the strip lists the pages, as it does.
4. **The words.** `config/text/ui.yml`: `embed_page` (the menu item, with the page's name), `page_leaf_close`, `page_leaf_glyph` if a glyph is drawn, `embed_refused` (the one line the pane says when a drop would make a cycle, drawn as the pane's said line as other refusals are); the key sheet unchanged.
5. **DESIGN.md.** "Layout as data" names the third node and the two rules (same page, no cycle); the pages decision line of 2026-09-11 stays; a dated decision line (2026-09-14, Axel: pages nest, the same page never a copy, never containing itself) beside L1's.
6. **Tests.** Model: a page leaf parses and serialises; a leaf naming a missing page reads as an empty pane; `containsPage` through one and two levels; `embedPage` refusing self and a cycle and splitting otherwise; `closePage` clearing leaves in other pages; folding a page leaf. Store: `embedPage`/`unembedPage`; an operation addressed to a nested page changes that page's tree and the strip shows the change after switching to it; `moveInstanceToPage` into a page shown nested; `instanceLayoutState` of a tab inside a nested page. Shell: a rendered nested page's panes carry `data-pane-page` of the nested page and `data-pane-path` within it; the leaf header names the page. Browser (`tests/browser/pages.spec.ts` or a new `nested.spec.ts`): embed page 2 into page 1 from the pane menu, see its header and its tab, open a view in the nested pane and find it open on page 2 after pressing `2`, try to embed page 1 into itself and see the refusal, unembed and see the leaf gone; the folded-leaf case reuses L1's strip.

## Decisions taken in this brief (each reversible, none silent)

1. A page leaf is a node of the tree, not a fourth tree: it folds, splits and drops as a child does.
2. Every store operation names its page with the strip's page as the default, so the existing call sites change nothing and a nested pane's calls add one argument read off its element.
3. The pane menu is the keyboard path to embedding; the page-tab drag is the pointer path; both split to the right and refuse a cycle.
4. `LAYOUT_VERSION` stays at L1's 4, since a leaf is an addition every older envelope lacks.
