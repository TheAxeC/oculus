# Brief: O14, the session views

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "Layer 3, view" (views know no layout; "Sessions is therefore six views, arranged by a saved default layout, not one view with three panes inside"), "Client state", "Sessions" under Layer 2, and the decisions "sessions are six views, not one" and "order: shell, then Projects, then Sessions". O13 put `sessions` and `git` on the socket; this package draws them: the six views, the selection that ties them together, and the saved arrangement that puts them on screen at once. The cockpit's Sessions tab (its client module `11-sessions.js`) is the fact source for what each view shows; nothing of its structure is ported.

## What to build

Under `tools/oculus/src/lib/state/`:

- `selection.svelte.ts`: the workbench's current session, one id or null, `$state`; `select(id)`, `selected()`. Not persisted. The list view sets it; every other session view follows it unless its own instance state pins an id (`{ session: <id> }` through `instanceState`), which is how two detail views can show two sessions side by side. A view whose followed or pinned session is no longer in the payload shows its empty state.
- `selectors.svelte.ts`, extended: `sessionById(id)`, `sessionsByWorkspace()` (the `workspaces` of the payload, with a per-row `hidden` filter applied unless the list asks for the dismissed ones), `gitFor(workspace)`, `touchers(path)` (the other live sessions whose `files` hold the same path), and `sessionsForProject(folder)` (records whose `cwd` or `area` lies in a project's absolute folder; O15 puts them on cards).
- `state/format.ts` (no runes, tested): `compactCount(n)` (`1.9M`, `84k`, `512`), `stamp(iso, now)` (`HH:MM` today, `day HH:MM` before), `clock(iso)`, `seconds(start, end, now)`, `modelShort(name)` (`claude-opus-5` to `opus-5`), `basename(path)`, `relativeTo(path, workspace)`, `elide(path, max)` (loses its head, never its basename).

Under `tools/oculus/src/lib/views/sessions/` (the folder the design's layout names; `tests/boundaries.test.ts`'s `views` row allows `views/registry` only, so each file imports `ui/**`, `state/**` and the registry, never a sibling; the six register in `src/routes/views.ts`):

- `SessionList.svelte` (`session-list`): the rail of the cockpit as a view: workspaces, each with its areas, each with its session rows, newest activity first at every level (the payload's order). A row: the state dot (`working`, `idle`, `ended`, `unknown`, and `observed` muted), a tool mark (`claude` or `codex`, from the record's `tool`, as a small `Chip` so the two agents read apart at a glance), the title, a live label (`busy`, `idle` from the registry) when live, the short model, the started stamp, the last activity (the last timeline event's basename or the last prompt, a turn as "finished in N s"), the secondary areas as chips; an ended row carries a dismiss control and a dismissed row a restore control, both through `api/write` with `kind: 'session'` (O11's route gains that kind here: `{ kind: 'session', id, hidden: boolean }` writing through O12's `setHidden`, refused without the token as every write is). Ended sessions are collapsed under "Ended (N)" until asked; dismissed ones hidden until "Show dismissed (N)". A click selects; the selected row is marked. The area heading shows its short name with the full one as the tooltip and an "unknown" mark when the area is not a known project folder.
- `SessionDetail.svelte` (`session-detail`): the key-value block of the selected session (title, cwd, branch, model, effort, permission mode, kind, status or "ended", pid when live, version, started), then the context meter: the last turn's occupancy against the context window as a `Meter` (tone by fill: low under 50 %, mid to 75 %, high above), the lifetime tokens (in, out, thinking), and the cache line (TTL, the cache-read share of the last turn, busts). The context window size is `context_window` in `config/behavior.yml`, a key this package adds with the value the cockpit's `11-sessions.js` holds in `CONTEXT_WINDOW` (the agent reads it there and quotes it).
- `Timeline.svelte` (`timeline`): the events newest last, each a clock, a kind chip (prompt, tool, edit, turn, bust; an unknown kind prints itself) and the text: a path as its basename with the whole path as the tooltip, a turn as "finished in N s", a bust as "prompt cache rewritten, N tokens", a prompt as its words. Scrolled to the newest event when the session or the view is fresh, and left where the reader put it otherwise.
- `Changes.svelte` (`changes`): two sections. "Touched by this session": every file of the record with its path relative to the workspace and elided from the head, the tool, the count, and an "also open" mark naming the other live sessions touching the same path. "The repository": from the `git` payload for the session's workspace: the branch line (detached, N ahead, N behind, or "in step with the upstream"), then Staged, Changed and Untracked groups with git's own letter coloured by meaning, the path, and `+a`/`-d` or "binary"; a workspace that is not a repository says so with the error as the tooltip.
- `Agents.svelte` (`agents`): one row per dispatched agent, newest first: a status dot (running, done, error), the subagent type (or "agent"), the short model, the description with the whole as the tooltip, and the status, the duration (`N s`, `Mm SSs`; a running one counted from its start to now) and the result size.
- `Terminal.svelte` (`terminal`): a placeholder `Empty` saying the terminal arrives with a later step (`sessions.centre_pending` exists in the catalog).
- Every string through `t()`: `text.js.sessions.*` already holds most of them (`ended_section`, `show_dismissed`, `tl_empty`, `ev_k_*`, `ev_turn`, `ev_bust`, `ag_*`, `ch_*`, `f_*`, `cache_*`, `tok_*`, `context*`, `live_busy`, `live_idle`, `state_ended`, `kind_observed`, `meta_sep`, `activity_turn`, `area_unknown`, `close_tip`, `restore_tip`); keys that do not exist are added under `text.sessions` and named in the report. The catalog's `{G.x}` tokens inside a string are not used; the glyph goes through `Glyph`.

The arrangement:

- `config/layout.yml` gains `arrangements:` with one entry, `sessions`: the main tree a row split of `session-list` (0.28) and a column split of `terminal` (0.6) over `timeline` (0.4); the panel a pane with `session-detail`, `changes` and `agents` as three tabs; dock right. The shape is the O7 tree written in YAML (`kind`, `dir`, `sizes`, `children`, `view`), and `parseArrangement(unknown): Workbench | null` in `state/layout.ts` turns it into a workbench with fresh instance ids, refusing anything that fails `checkWorkbench`.
- The rail gains, under a `nav_groups` heading "Sessions" that O10c's `layout.yml` now lets oculus define (a group naming the six view ids), the six views, and one control in the dock menu, `ui.arrange_sessions`, that applies the arrangement: the current workbench is kept under `oculus.layout.previous` in `localStorage` and the same control, when the arrangement is in force, restores it (`ui.arrange_restore`). A saved arrangement of the user's is therefore never lost by opening the sessions layout.

Under `tools/oculus/tests/`:

- `state/format.test.ts`: every helper above.
- `state/selection.test.ts` and `state/selectors.test.ts`: the selection, `sessionsByWorkspace` with the hidden filter, `touchers`, `sessionsForProject`.
- `views/sessions.test.ts`: `render` from `svelte/server` of each of the six views over a synthetic `sessions` and `git` payload in `entities`: the list's workspaces, areas and rows with their marks; the detail's fields and the meter's value; the timeline's kinds and the turn and bust texts; the changes' two sections, the shared mark, the git letters; the agents' rows; the terminal placeholder; the empty state of each when nothing is selected.
- `state/layout.test.ts`, extended: `parseArrangement` over the YAML shape, refusing a bad tree.
- `routes/write.test.ts`, extended: `kind: 'session'` writing the overrides file in a temporary directory.
