## What is on the tree (read 2026-09-14 at 14:05 on main at b44335db; R12a touches `src/lib/server/watch/git.ts` for its stderr and hub-root edges and lands before this package is dispatched, so the window's lines are re-read then)

1. **O13, the git watcher's burst case fails in a full run under load and passes alone.** `tests/server/watch/git.test.ts` lines 270 to 290: three writes inside the watcher's two-second window are expected to collapse into one read (four git commands), and under load the window closes between the writes, giving eight. `src/lib/server/watch/git.ts` lines 87 and 116 to 124: a `setTimeout` per root, every event inside the next two seconds collapsing into one read at the end of the window. Fix: the watcher takes its clock as a dependency (the `setTimeout` and `clearTimeout` pair, defaulting to the globals), and the test drives it with fake timers, so the window is the test's and no wall-clock load reaches it; the assertion stays `4`. The other cases of the file that wait on real time follow the same clock where they can.
2. **Q2, nothing checks `build/` is current before the browser layer serves it; `tests/browser/.hub` and the temporary hub copy are never removed.** `playwright.config.ts` says "It does not build"; `tests/browser/serve.ts` copies `demo/` under `mkdtemp` (line 34) and never removes it, and writes `tests/browser/.hub`. Fix: `serve.ts` refuses to start when `build/` is older than the newest file under `src/` or `config/` (a mtime comparison, the reason printed), and removes the temporary copy and `.hub` when the server exits (`process.on('exit')` and the signal it receives from Playwright). A unit test over the two helpers (`isBuildCurrent`, the cleanup) with `mkdtemp`.
3. **O26, no Playwright spec over a stubbed `hpc` channel.** The `hpc` channel carries the cluster's queue and quota to the Live HPC view; the demo hub has no cluster. Fix: `serve.ts` (or a demo-only setting the server already reads) feeds a fixed `hpc` payload from a fixture under `demo/` so the Live HPC view draws it, and `tests/browser/hpc.spec.ts` (new) opens the view from the System group and asserts the fixture's queue rows and quota are drawn. How the stub reaches the channel without a code path that exists only for tests is the decision to make and say (a fixture file the server's hpc poller reads when configured is the shape; a test-only flag is not).
4. **R14, the transcript's assistant turn is sanitised but no browser case exercises it.** `demo/` holds no sessions. Fix: a sessions fixture under `demo/` (one Claude transcript in the store layout `config/behavior.yml` names, with an assistant turn carrying `<div onclick="alert(1)">x</div>` and a fenced block) that the served hub's session store points at, and a case in `tests/browser/sanitise.spec.ts` opening that session's transcript and asserting the handler is gone and the block kept. Read how `serve.ts` points the server at the copy (`OCULUS_LOCAL`) and where the session stores are configured, so the fixture is reached without a test-only path.
5. **O18, `@xterm/xterm/css/xterm.css` is in every route's stylesheet.** `src/lib/views/sessions/Terminal.svelte` line 25 imports it, and the build folds it into the one route's CSS, so every page loads it. Fix: measured first (`grep -c xterm build/client/_app/immutable/assets/*.css` after a build): if the stylesheet is in the shared chunk, the import moves to a dynamic import in the Terminal view's mount so it loads with the view; if it is already in a chunk only the Terminal view loads, the edge is closed by that measurement and the report says so.

6. **The workbench suite's import case under load.** `tests/shell/workbench.test.ts` line 426 on: one case does `await import('../../src/routes/views.ts')`, every view, inside vitest's 5 s timeout; at a load average above about 12 the suite's import phase doubles and the case times out, and the file's later mounts fail with it, while the file alone is green. Fix: the import is hoisted into a `beforeAll` of the describe block (its own timeout is the import's, the cases' 5 s cover the assertions only), and no threshold changes. A run of the file with the load reported.

7. **R12b, four behaviours asserted from the source because the unit suite has no DOM.** `tests/ui/primitives.test.ts` reads `Tooltip.svelte`'s `focusin` listener and `Chip.svelte`'s ellipsis rule off the source; `tests/views/crosslinks.test.ts` the cross-link ellipsis; `tests/views/sessions.test.ts` the terminal tab label following a rename; `tests/views/intro.test.ts` the trusted and sanitised paths. Fix: one browser case each, in the spec that already covers the surface (`tests/browser/appearance.spec.ts` or a new `tests/browser/views.spec.ts`): a tooltip open on a hovered control closes when `Cmd-K` opens the palette; a chip with a long value ends in an ellipsis inside its card (`alphaOf`-style measurement of the chip's box against the card's); a cross-link button with a long title likewise; a pinned terminal tab's label changes after the terminal is renamed through the toolbar; an intro line with a `<script>` in a hub value is drawn without it while a catalog line keeps its `<b>`; the page rename box has focus the moment it appears; `K` with a card cursor held on a collection reorders the entry and the file. The source-reading unit tests stay.
