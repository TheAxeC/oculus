## The acceptance list

1. **The languages.** `languages.ts` registers `lisp`, `ocaml`, `r`, `matlab`, `julia`, `ini` (for `.toml` and `.ini`) and `makefile` from `highlight.js/lib/languages/`, and `typeOfFile` maps `.lisp`, `.el`, `.scm`, `.ml`, `.mli`, `.R`, `.r`, `.m`, `.jl`, `.toml`, `.ini`, `Makefile`, `.slurm` (bash), `.bib` (latex), `.ipynb` (json), `.svelte` (xml, since highlight.js ships no Svelte grammar; the script and style blocks are what xml's sublanguage rules pick up, and the report says how far that reaches). `registered()` and the map stay in step: `tests/views/file.test.ts`'s existing case over every mapped language being registered keeps passing, and gains the new names. The bundle grows by the seven grammars only; the report gives `npm run build`'s client chunk size before and after.
2. **The preview.** A source tab over a `.md` file draws a preview beside the editor: the pane splits into the editor on the left and the rendered Markdown on the right (`views/source/Preview.svelte`), rendered live from the editor's working text through `marked` on the client and filtered through the client's sanitiser before it is drawn, with the document styles `Markdown.svelte` already has (reuse it rather than a second stylesheet), a relative image left unresolved (the preview is text, the file route is not asked for figures). The split is `ui/Sash.svelte` between the two halves; a toggle in the source toolbar hides the preview, kept per instance in its ui state. For a file that is not Markdown the tab is as today. The preview follows the editor's scroll proportionally (the editor's scroll fraction applied to the preview), nothing more.
3. **Words** in `config/text/views/source.yml`; `HELP.md`'s sentence naming the `source` view (the paragraph after the view table, line 99) names the preview; DESIGN.md's decision line.
4. **Tests**: `tests/views/file.test.ts` (every new extension mapped to a registered language; a Lisp, an OCaml, an R and a MATLAB snippet highlighted to a `hljs-` class), `tests/views/source.test.ts` (the preview drawn for a `.md` tab with the rendered heading, absent for a `.yml` tab, hidden by the toggle state, a script tag in the text absent from the preview), `tests/state/source.test.ts` (the toggle in the instance state), and a browser case: open a Markdown file from the file browser in the source tab, type a heading, see it in the preview.

## Decisions taken in this brief (each reversible, none silent)

1. `.svelte` is highlighted as xml, since highlight.js ships no Svelte grammar and no dependency is added; the report names what that does and does not colour.
2. The preview renders on the client from the working text, so it never asks the server and never waits for a save.
3. The preview is on by default for a Markdown file and its toggle is per instance.
