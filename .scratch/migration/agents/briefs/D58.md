## What to build

When the step is done, the Help page's Apps guide tab draws the guide on any hub, whatever that hub's `docs:` list holds and wherever the engine folder sits (inside the hub, as here, or outside it); the manual's links to the guide and the guide's link back to the manual open the other document on any hub; this hub has one tab for the guide, never two.

1. **The route.** `src/lib/server/content/docs.ts` serves a fourth thing, `engine=<path>`: a `.md` file named by a path relative to the engine folder, read and rendered as `renderHubDoc` renders a document of the engine now (prose, with each diagram of `docs/diagrams/` as a part when the document holds one). It refuses, with a 404 whose message names the reason, in literal English as the route's other refusals are, and without opening the file: an empty path, a path not ending in `.md` (`.MD` included), an absolute path, a path that climbs out of the engine folder, a path with a segment `node_modules` or a segment starting with a dot (`.scratch/`, `.git/`), a path whose real path lies outside the engine's real folder (a link leading out), and a path naming no file or naming a folder. `handleDocs` reads `manual` first, then `engine`, then `hub`, then a project, so a request carrying two of them is the first. The head comment lists the four things, and the doc comments of `MANUAL` and `renderManual` no longer say the manual is the one engine file or the one path outside the hub the route opens.
2. **The answer.** Every answer carries `engine: boolean`, true for the manual and for an engine document. For an answer with `engine: true`, `path` is the document's path relative to the engine folder and `manual` is `HELP.md`; for any other answer they stay relative to the hub as now. Every answer also carries `engineAt`: the engine folder's path relative to the hub, taken on the paths as configured when the engine path lies under the hub path, else on the real paths when the engine's real path lies under the hub's real path (an engine reached through a link in the hub), and the empty string when neither does. `docs.svelte.ts` reads both fields (a missing field reads as `false` and `''`), holds an engine document under its own key, and gains `engineDocument(path)` beside `hubDocument` and `manual`. `DocState` carries both fields, and the literal `DocState` of `src/lib/views/shared/prose/RenderedMarkdown.svelte:68-77` gives `engine: false` and `engineAt: ''`.
