## What to build

1. **One module.** `src/lib/data/sources/documents/decks.ts` becomes the one module both reads call (no new file in `sources/deck/`, which is full). Given a hub (its key and folder), its settings, the hub's projects in the merged shape (`Project`, internal ids, every reference resolved as the merge resolves it), the words the facts name records by, and for the route the drafts and the kept keys, it builds each `DeckProject` (one `deckProject`: the domain as the resolved internal id, the tier, the chips, the stage, the form, the workspace folder, the facts by `projectFacts`) and the reader's domains, tag tones, frame and catalog, and calls `createReader`. No other file in `src/` builds a `DeckProject` or a reader's input; `tests/checks/config/integrity.test.ts` reads its decks through the module too. The tests of `createReader` in `present.test.ts` keep building their own inputs, since they test the reader.
2. **The snapshot build reads through it.** `decked` in `data/index.ts` reads the hub's project decks and its portfolio deck through the module, with the hub's projects made as the merge makes them: `deck-facts.ts` gives the resolved `Project`s (the work `hubFacts` does now, returning the projects, not only their facts) and the words over the hubs' records, and its head comment says so. The `unnamed` rule of the portfolio deck (`decks.ts:90-93`) and the `decks` record (`path` and `tags` per project) are kept.
3. **The route reads through it.** `src/lib/server/content/deck/read.ts` keeps what is the route's own: the refusal of a root or a path outside the roots, the hub a root is read under, the drafts matched by real path, the kept keys, and the `unnamed` answer for the portfolio deck; it builds no `DeckProject` and reads no domains file of its own (no `hubDomainsOf` call). `DeckSource` and `readDeck` keep their shape, so `+server.ts`, `endpoint.ts`, `deck.ts` and `deck-files.ts` keep working; a change to that shape carries every one of them.
4. **Same deck, one domain check.** For every deck both reads read (the project decks and the primary's portfolio deck), the two give the same deck: the same slides, groups, members, project of each slide, domain of each slide, legend domains, grid card domains, summary row domains and facts. A project's domain follows the merge's resolution: the record the manifest's `domain:` key resolves to (its own hub's, else the one other hub's that holds it), so a key held only by another hub raises no finding and draws that hub's domain on both reads. The domain is checked once, in the module, on the build's read, which holds each manifest's key as written: a key no hub holds raises `findings.deck.domain_unknown` once, on the project's manifest, and the slide draws the neutral tone; an empty key is no key; an ambiguous key raises the merge's ambiguity finding alone. The route's projects carry the resolved domain or none, so its answer raises no domain finding; its findings are drawn nowhere, and the Findings view lists the build's. No field is added to `Project`. The finding's words in `config/text/findings.yml:123` say a key no hub's domains registry holds.
5. **The tests move.** The rows of the two readers' projects, facts and domains (the case of `deck-facts.test.ts`, the facts-and-domain case of `deck.test.ts`) become one table in `tests/data/hubs/decks.test.ts` (the file `deck-facts.test.ts` renamed with `mv`; no new folder in `tests/data/sources/`, which is full), one row per input that gives a different outcome, among them the equality rows of item 4. Each equality row compares the build's findings from `buildHubs` (as `factsWorkspace` gives them) and the module's deck for the build's own input with `readDeck`'s answer. The file is slow (`@module-tag slow`), run alone with `npx vitest run tests/data/hubs/decks.test.ts`, and the report quotes that run. The rows of `present.test.ts` that test `createReader` itself (its splitting, groups, image links, narrowing, counts, and the filling of `{{project.<field>}}` from a project's facts) stay there. The route's refusal, draft and unnamed tests stay in `deck.test.ts`. `guarded.md` G32's Test line names the new file and titles and drops the titles that are gone.
6. **The comments.** Every comment that says there are two readers, names `readDecks` or `hubFacts` as it was, or describes the build's read of the decks (the list under "What is on the tree") says what is true after the step. `docs/` and `README.md` are grepped for the same.

## Decisions taken in this brief (each reversible, none silent)

1. The one module takes projects in the merged `Project` shape, since the route already holds them and the build already makes them that way for the facts (`hubFacts`); the build's raw-manifest `DeckProject` path is the one removed.
2. The domain rule is the merge's resolution, as the step line says; a key resolved in another hub is no finding, which changes what the Findings view lists (C2). The report's before and after names it.
3. The route's own tests (refusals, drafts, unnamed) stay with the route, and the tests of `createReader` stay in `present.test.ts`; only the rows of the two readers' projects, facts and domains move.
4. The domain check runs on the build's read, the one read that holds the key as written; the route's answer carries no domain finding, since a `Project` field to carry the key would change the apps' payload, a public shape, and the route's findings are drawn nowhere.
5. The module stays at the path of `documents/decks.ts` and its test at `tests/data/hubs/`, since both deck folders are at their ten-item limit.
