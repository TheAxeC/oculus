## What to build

1. **The icon map.** `config/icons.yml`: `icons:` a map of every `glyphs.yml` name to a Lucide icon name (117 rows, one per glyph name, chosen for the meaning the name carries: `refresh` to `refresh-cw`, `expand` to `plus-circle`, `collapse` to `minus-circle`, `darkmode` to `contrast`, and so on; the report lists every pair). `src/lib/data/sources/config.ts` reads it as `iconCatalog(config)`, refuses a name that is not a glyph name or an icon the package does not ship (the server checks `node_modules/lucide-static/icons/<name>.svg` exists at config load and reports a finding otherwise), and a glyph name with no icon row is a finding too, so the map and the vocabulary cannot drift. The server reads the SVG text of every mapped icon once per config load and pushes it to the page beside the glyph map (`icons: Record<glyphName, svg>`), installed by `setIcons` in `text.ts`; the browser never fetches an SVG file.
2. **The primitive.** `Glyph.svelte` draws the icon's SVG inline (`{@html sanitise(svg)}`, the `svg` profile of the sanitiser, `width`/`height` 1em, `aria-hidden`) while the mode is `unicode`, and the ASCII stand-in as text, exactly as now, while the mode is `ascii`; a name with no icon (only possible while the config is broken) draws the character as now. `Chip.svelte` draws its glyph through `Glyph` rather than `glyphOf`, its `bracketed` rule unchanged (it reads the stand-in in ASCII mode only). Every `glyph(name)` call that puts the character into text rather than the DOM (a document title, a tooltip, a terminal row, the key sheet) keeps the character: the report lists those sites.
3. **Chips only for status.** A `<Chip` whose tone is a status (`statusTone`) or the project type (`typeTone`) stays a chip. Every other `<Chip` (datasets, people, collaborators, pillars, programs, funding, compute, code state, venue names, counts) becomes a `Tag` primitive (`src/lib/ui/Tag.svelte`): the glyph through `Glyph`, then the words in the muted text colour, no capsule, no hue, the same inline size; a tag that was clickable (the card's cross-links, the venue links) keeps its button and its click. The report lists the 98 sites with each one's decision (chip kept or tag) and the reason.
4. **Dependency.** `lucide-static` is added to `package.json` (a dependency, since the server reads it at runtime) with the lockfile; the licence note goes into README.md's dependencies list where the others are.
5. **Tests.** `tests/data/config.test.ts` (or beside the glyph catalog's tests): the icon map covers every glyph name and only glyph names, every icon exists in the package, a finding for a missing or unknown row; `tests/ui/glyph.test.ts`: the primitive renders an `<svg>` in unicode mode and the stand-in in ascii mode, and the sanitiser strips a script from a crafted svg; `tests/ui/tag.test.ts`; a chip-or-tag audit test (`tests/views/chips.test.ts`) that renders the project card and asserts the status chip is a chip and the dataset tag is a tag; `tests/contrast.test.ts` stays green (the muted text over every surface is already a checked pair); the browser suite green with the rail's icons (the rail spec locates buttons by role and name, not by glyph).
6. **DESIGN.md.** The theming section names the icon set and the chip rule, one sentence each; a dated decision line (2026-09-13, Axel: chips for status only; 2026-09-15, Axel: Lucide through `lucide-static`, mapped in `config/icons.yml`).

## Decisions taken in this brief (each reversible)

1. The SVG text travels with the config over the socket rather than as files the page fetches: one path for every config file, and a change to `icons.yml` repaints like any config edit (R11).
2. `Tag` is a new primitive rather than a `Chip` prop: a tag has no hue and no capsule, and a primitive with two looks would carry the rule at every call site.
3. Text contexts keep the character: an icon cannot be a window title.
