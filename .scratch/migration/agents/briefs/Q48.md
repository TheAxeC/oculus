# Brief: Q48, an add answer closes only the opening it was sent from

Read `tools/oculus/.scratch/migration/agents/spec.md` first; its rules govern this step unchanged, its principles above all.

## What is on the tree (read on main at c9335540)

- `src/lib/views/shared/EntryForm.svelte` `save()` (line 196 on): an edit goes through `into.settle(which, sent)`, which answers false when the opening has moved on, so an edit keeps what was typed while the request was out. An add takes the other branch: `into.clear(which); onclose();` (lines 227 to 229), unconditionally. So an add form closed and reopened, or typed into again, while its save is out loses the new text, and `onclose()` runs over the new opening.
- `src/lib/state/fs.ts` has the rule for the Files forms: `formSettled(now, asked)` (line 468) answers the forms an answer may close, null when the opening moved on; `bookmarkLeft` (line 455); `editedGone(now, marks)` (line 432) is read by `src/lib/views/Files.svelte` line 393 in an effect that closes the form over a bookmark the file no longer holds.
- `views/files/BookmarkForm.svelte` takes the instance and the forms when it mounts and is the host of the bookmark form; the collection views host the add forms through `state/open-forms.ts`.
- `Files.svelte`'s gone-bookmark effect runs on the mounted instance: an unshown tab's Files view is not mounted, so the effect does not run for it, and a value typed during a rename save is not considered by `editedGone`.

## What to build

1. **One settle rule for both branches.** An add's answer closes the form and forgets its draft only while the host says the opening the save was sent from is still open and holds what it held; otherwise the answer leaves the form as the reader left it and forgets nothing. The edit branch's `settle` is the shape to follow; if the draft target's interface cannot answer that for an add, give it the one call that can, and say in the report what changed.
2. **The Files bookmark form and the collection add forms both under it.** A bookmark add and a collection add behave the same: closed and reopened during a save, the new text stays; typed on during a save, the typing stays; unchanged and still open, the form closes as it does today.
3. **The gone-bookmark close.** It keeps a value typed while a rename save is out (it closes a form over a bookmark that is gone, not one whose text is newer than its last answer), and it runs for a Files instance whose tab is not shown, so a bookmark taken away on disk does not leave a hidden tab asking about text it no longer shows. Say in the report where that rule now lives if it moves out of the mounted view.
