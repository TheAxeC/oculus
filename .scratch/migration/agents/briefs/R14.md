## What to build

1. **The revert check** (`bin/revert-check.mjs`). A test case may carry a machine-readable revert beside its prose one, in the shape `// revert: <path>:<line> => <replacement text>` or `// revert: <path>:<line> => delete`. The script reads every such line in the files a diff names, applies each one to a copy of the tree, runs that one case, and fails when the case stays green. It reports each revert as red or green with the case name. Cases with no machine-readable revert are listed as unchecked, never as passed.
2. **The head-comment print**: a script or a one-line command that prints the first fourteen lines of every source file a diff names, so a report can confirm each still holds. Name it in the report as a verification line.
3. **The duplication test** (`tests/duplication.test.ts`): fails when a window of eight or more non-trivial lines (comments and blank lines dropped, whitespace normalised) is identical in two files under `src/lib`, or in two files under `tests`. An allow list names what is deliberate, each entry with its reason.
4. **The citation check** (`bin/cited-lines.mjs`): reads a report file, finds every `path:line` citation, and prints the line the tree holds there, so a wrong citation is seen before the report is sent.
5. **The scratch-directory count**: a command that counts `oculus-*` directories in the system temporary directory before and after a suite run and fails when the count grew. The tree's tests must leave it equal; fix any that do not, in the test files themselves.
6. **The size check**: a command that fails when a file under `src`, `tests` or `bin` is over 900 lines, or is a component over 540. The seven files over that line today are named in an allow list inside the command or a file beside it, each entry to be removed when its split lands; a file not on the list that crosses the line fails the check.
7. **The negatives test** (`tests/negatives.test.ts`): fails when a case under `tests/views` or `tests/browser` uses `.not.toContain(`, `.not.toHaveAttribute(`, `.not.toBeVisible(` or `toHaveCount(0)` without a comment on the line above saying what makes the absence right. Existing cases that lack one get the comment where the absence is right, and are reported as a finding where it is not.
8. **The primitive-styling case**: a case in `tests/boundaries.test.ts` that fails when a `:global(...)` selector in a component under `src/lib/views/` or `src/lib/shell/` names a class declared in the `<style>` block of a `src/lib/ui/*.svelte` file. An allow list names what is deliberate today, each entry with its reason.
9. **The audits test** (`tests/audits.test.ts`): fails when a case body under `tests/views/` calls neither `render(` nor the file's own render helper, unless the case name begins with "audits".
10. **The config-diff print**: a command that prints every added or changed line under `config/` in a diff, so a report names each new user-visible key in its decisions.
11. **The look rule**: one line added to `agents/spec.md`, exactly: "A browser case over a look runs under a rice theme and at the largest text scale as well as the default, or its comment names the fact that makes the default decide it."
