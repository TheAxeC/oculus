## What to build (the three layers: this is code only, no data, wire or view change)

1. **One usage reader per tool, in one module.** `src/lib/server/transcripts/usage.ts` (new; the folder is new and holds what both the sessions layer and the usage layer read): `claudeUsage(record): UsageEvent | null` for an `assistant` record (`model`, `stamp`, `input`, `output`, `cacheRead`, `cacheCreation`, `thinking`, `ttl` of the cache creation as `'1h' | '5m' | null`) and `codexUsage(record, previous): UsageEvent | null` for a `token_count` event (the totals turned into deltas against `previous`, `thinking` from `reasoning_output_tokens`, `context` from `last_token_usage`); every key name of a transcript's usage exists in this module and nowhere else under `src/`.
2. **One file finder per tool, in one module.** `src/lib/server/transcripts/stores.ts` (new): `claudeTranscripts(store, windowDays, maxSessions)` and `codexRollouts(store, windowDays, maxSessions)` are the existing finders of `sessions/transcripts.ts` line 209 and `codex.ts` line 352 moved there unchanged in behaviour, and `usage/transcripts.ts` lists its files through them (its own `Found` listing goes).
3. **Both folds consume the reader.** `sessions/fold.ts` `foldUsage` and `codex.ts`'s token block call the reader and add its event to `Acc` (the cache-bust and TTL bookkeeping stays in the sessions fold, fed by the event's fields); `usage/transcripts.ts` builds its day rows from the same events. The session record's numbers and the Usage view's rows are unchanged for every fixture in the tests, proven by the existing tests passing unchanged except for imports.
4. **Boundaries.** `tests/boundaries.test.ts`'s ALLOWED map gains the new folder as a server module that `sessions/` and `usage/` may import and that imports only `data/`; nothing under `transcripts/` imports `sessions/` or `usage/`.

## Decisions taken in this brief (each reversible, none silent)

1. The shared module lives at `src/lib/server/transcripts/` (two files), not inside `sessions/`, so the usage layer does not depend on the sessions layer.
2. A `UsageEvent` is one plain record type for both tools; a tool-specific field (`ttl`, `context`) is optional on it.
