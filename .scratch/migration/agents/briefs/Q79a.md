## What to build

1. `json()`. Every hand JSON answer in `src/lib/server` becomes `json(body, { status })` from `@sveltejs/kit` (with `headers` when the answer carried more than the content type). Each file's local `answer` or `json` helper that only did this goes. The status codes and bodies stay exactly as they are.
2. One origin guard for `/api/`. `handle` in `src/hooks.server.ts` refuses, before `resolve`, every request whose path starts with `/api/` and fails the one rule below, answering `json({ error: 'forbidden' }, { status: 403 })`; the two OAuth callback paths (`/api/calendar/callback`, `/api/mail/callback`) are the only paths it passes unchecked, named in one list beside the guard with the reason (a provider's redirect, guarded by its `state`). The rule is one function in `server/core/auth.ts`, `sameOrigin(headers, host)`:
   - `Sec-Fetch-Site` `same-origin` or `none`: admitted.
   - An `Origin` header: admitted when `allowedOrigin` accepts it or it names the request's own host; refused otherwise.
   - No `Origin` and a `Sec-Fetch-Site` of any other value (`same-site`, `cross-site`): refused, since a browser sent it from another page.
   - Neither header: admitted, since no browser sends a request without one; every write still needs the process token (`gatedBody`, `hasToken`), which such a client does not hold.
   Every `sameOrigin(` call in the route modules and `images.ts`'s own `sameOrigin` go, and `gatedBody` keeps only its token and body checks. `root/hooks.ts` keeps its rate and size limits and drops its own origin check, which the rule now covers. `DESIGN.md`'s "Auth" section and the head comment of `core/auth.ts` state the one rule, the guard in `handle`, and the two callback paths.
3. The configuration read one way. Inside a request the configuration comes from `locals.config()`: every route that reads it (`locals.server.config`, or `loadConfig(locals.server.engine)`) reads `locals.config().config` instead, and a server module a route calls takes the configuration (or the part it needs) as an argument from the route in place of calling `loadConfig` itself (`content/images.ts` `configOf`, `files/project-files.ts:199`, `files/files.ts:306`, `git/git-routes.ts:171`, `machine/pty/routes.ts:180,294,329`, `machine/pty/chat.ts:84`). What stays, each with a comment saying why: `server/root/context.ts`'s start read (it builds the watchers, outside any request), `root/watch/portfolio.ts:287` (the watcher's reread on a config change), and `edit/writes.ts:212` and `edit/writes/subtasks.ts:161` when they must see the file after the write they make (if they read it before the write, they take `locals.config()` too). `ServerContext.config` stays only if a reader outside a request remains; with none, the field goes.
4. `isDeepStrictEqual` from `node:util` in place of `yaml-edit.ts`'s `deepEqual` and `deck-edit.ts`'s `same`. `sameValue` keeps its rule that absent and null are one thing. The callers keep their names or import the built-in directly; no wrapper that only renames it.
5. `TextDecoder` for the text sniff. `isTextBytes` keeps its rule (no NUL in the window; the window decodes as UTF-8; a sequence cut at the window's end is accepted when the file goes on and refused when it ends there) and does it with `new TextDecoder('utf-8', { fatal: true }).decode(window, { stream: cut })` in a `try`, so `AFTER`, `sequenceLength` and `follows` go. The existing cases in `tests/data/helpers/text-kind.test.ts` (or wherever `isTextBytes` is tested: `grep -rln isTextBytes tests`) pass unchanged.
6. `util.parseArgs` from `node:util` in `root/args.ts`, `bin/cited-lines.mjs`, `bin/migrations/migrate-joint-work.mjs` and `bin/migrations/rename-program-to-pillar.ts` (if it reads flags; a script that only takes positionals keeps them through `parseArgs`' `allowPositionals`). `parseEngineArgs` keeps every sentence and rule it has today (the last `--engine` wins, `--engine=<dir>`, a value starting with `--` is the missing-directory error, anything else is `unknown argument: <arg>`, a folder without `config/` is refused), using `parseArgs` with `tokens: true` and `strict: false` so it can name the argument it refuses. Its existing tests pass unchanged.
7. `refresh.ts`: `util.stripVTControlCharacters` in place of the regex at `:99`, and `setTimeout` from `node:timers/promises` in place of the promise at `:138`.
8. `migrate-joint-work.mjs` writes its YAML with `yaml`'s `stringify` (a document built as objects, then stringified), so a value with a line break, a colon or a quote round-trips. `quoted` and the hand `key: value` lines go. The output for today's inputs keeps its keys, order and values; its formatting may follow `stringify`.

## Decisions taken in this brief (each reversible, none silent)

1. The one origin rule admits a request with neither `Origin` nor `Sec-Fetch-Site` (the command line), as `images.ts` does today, rather than refusing it, as `auth.ts` does today. A browser always sends one of the two, so a page in the browser is judged the same either way; a client that sends neither can also send any `Origin` it likes, so refusing it protects nothing, and the hook's `curl` needs it admitted. Writes keep the token. The five real call sites this changes, read on the tree: `core/changes.ts:235` (the Changes list, a GET: a `curl` without headers was refused, now answered), `files/fs.ts` (the file listing GET: the same), `git/git-reads.ts` (git reads: the same), `content/memories.ts:143` (already admitted: unchanged), `root/hooks.ts:215` (already admitted: unchanged).
2. The guard lives in `handle`, the one place every request passes, rather than in a helper each route calls, so a new route under `/api/` is guarded without remembering to be.
3. `ServerContext.config` is removed when no reader outside a request is left; the start read in `context.ts` becomes a local.
