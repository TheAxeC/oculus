## What to build

1. **The rule, as arithmetic in `card-layout.ts`.** One exported function takes the drawn boxes of the text as `{ top, bottom }` pairs measured from the top of the text, and the clamp's height (the line height times `CLAMP_LINES`), and answers the height the cut ends at. It is the bottom of the last box that fits: the largest box bottom that is no more than 1 px past the clamp's height and lies more than 1 px inside no box (above that box's bottom and below its top, each by more than the pixel). A pixel of rounding is allowed in both tests, as `overflowsClamp` allows it, because lines stack at fractions of a pixel. An answer within 1 px of the clamp's height is the clamp's height, so a plain text is cut exactly as now. With no such bottom, because no box fits whole or there are no boxes, the answer is the clamp's height, the cut the text has today.
2. **The measurement, in `Clamp.svelte`.** Inside `measure`, in the same window with `--field-gap` at 0, it collects the boxes: each line of text, and each element drawn whole or not at all, which are `.katex-display`, each `.katex-base` of a formula outside a `.katex-display` (a long inline formula wraps between them, and a `.katex` box is shorter than its tall parts), a `pre`, a table's `tr` and an `img`. Text inside those elements gives no line box of its own, and nor does the `.katex-mathml` copy. A line's box is one line height tall, centred on the drawn rectangle of the line's text, since a text rectangle is the font's height and shorter than the line, and a plain text's fourth line must end at the clamp's height. Tops and bottoms are relative to the text's own top with the box's `scrollTop` added, so a box that focus has scrolled answers the same. The answer is kept in `$state` beside `long` and written through the `style=` expression on the box as a custom property in px, as `spec.md` keeps a reader-visible behaviour in state.
3. **The cut uses it.** `.text.cut`'s `max-height` is that property, and `calc(var(--clamp-lines) * 1.45em)` and `--clamp-lines` go: `.cut` is only applied by the `measure` that sets the value (see What is on the tree).
4. **It stays current.** The text's contents get a plain wrapping `div` inside `.text`, and the `ResizeObserver` watches that `div` in place of the box: its height is the whole text's whatever the cut, so a width change, a text size change, a font swap and an image that loads all run `measure`, and the cut follows. The `MutationObserver` stays for edits and KaTeX. The custom property is an attribute, which the `MutationObserver` does not watch, and the wrapping `div` does not change size when the cut does, so writing the value does not run `measure` again.
5. **What does not change:** whether Show more or Show less is drawn (`overflowsClamp` and `clampControl`), which the text's whole height decides; the open state; the callers.
6. **Comments.** The `.text.cut` comment and the head comment of `Clamp.svelte`, and the head comment of `card-layout.ts` where it lists the rules, say what the code now does. The head comment of `Clamp.svelte` says the observer watches the contents.

## Decisions taken in this brief (each reversible, none silent)

1. The custom property is internal to `Clamp.svelte`, no user-visible name. Its name is the builder's.
2. A `tr` is a box, so a table is cut between rows. A `pre` is one box, so a code block is shown whole or not at all, since its lines scroll as one.
3. No guard against a page scrollbar that appears and goes as the cut changes the page's height. The feedback path exists today through `long` drawing the control, which nothing guards, it needs a classic scrollbar and a formula on the wrap boundary, and the cost is a flicker.
