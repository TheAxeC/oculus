# Brief: D69, two clipping defects

Size: a full step

Read `tools/oculus/.scratch/migration/agents/spec.md` first; its rules govern this step unchanged. It is also the one standards page the configuration lists. No ADR folder exists (`ls docs/adr tools/oculus/docs/adr` answers no such file for both), so no ADR touches this step.

You work in the worktree `.agents/worktrees/D69` (from the repository root) and nowhere else; the base copy is `.agents/worktrees/D69-base/tools/oculus/`.

A design ruling decides what is built. It never exempts the code: every line is written to the standards pages, so that people can read, use and maintain it.

Two defects were seen on a scratch oculus at D63's landing look. The source editor's right-click menu is cut off at the right and bottom edges of its pane, so its lower entries cannot be reached, apps' `editor/context` entries among them. The status bar's left group, when its items do not fit, cuts an item in the middle of a word ("Indexi", a 609 px group over 766 px of items in a 1512 px window with a Python tab) and hides the items after it, apps' items and the window progress among them.

## What to build

1. **The editors' pop-up widgets drawn whole, over the page and over every float.** The right-click menu, the hover, the suggest list, the parameter hints, the rename box and every other widget Monaco draws outside the text, in the source editor, the diff editor (inline and side by side), the merge editor and the peek, in every theme, wallpaper on or off, are drawn on one node on the document body, as oculus's own menus are drawn through `Portal` (DESIGN.md:246), never cut by a pane, the editor's box, a split, the diff list or a float, and drawn above every float (ruling Z825). The mechanism: `fixedOverflowWidgets: true` and an `overflowWidgetsDomNode` on that node for every editor, and a layout-service override handed with every create so that the context view (the right-click menu) is drawn there too. The node carries the class `monaco-editor`, so Monaco's colour variables, its widget CSS and `kit/theme/rename.css` apply, and the right-click guard keeps the browser's menu away from it. The widgets keep their place next to the cursor or the pointer, close as today, and take the theme as today. Keys typed in a widget (the rename box, the suggest list, the find box's own keys stay inside the editor) behave as today: the editor's capture handlers and `tab-out.ts` still see them. A widget open when an ancestor of the editor scrolls (the source view's column, the diff list) is closed or moved with the text, never left floating where the text was. The shared options and the override go into `options.ts`, so each component stays at or under 520 lines. DESIGN.md:246's sentence is extended to name Monaco's widgets beside the tooltips and menus.
2. **The status bar never cuts an item.** An item is shown whole or not at all. The right group wraps whole items out of the bar's one row from its left end first (`flex-wrap: wrap; flex-direction: row-reverse`, its markup reversed in SourceItems, LanguageItems, AppItems and wherever else the right group's items are written, so the visible order is today's). The right group's narrowest width is its widest item. When the window is narrower than the left group plus that width, the left group's last items leave the row whole in the same way (ruling Z819 goes past VS Code here). No status item is wider than 40 % of the window: `max-width: 40vw` on the `ToolButton status` and the `Menu status` items alike, through every element between the group and the label, and a longer label ends in an ellipsis inside the item. The bar and its groups clip without being scroll containers (`overflow: clip`), so focus never scrolls a second row into view. An item that has left the row is no tab stop and is hidden from screen readers until it comes back (ruling Z826), and it can still be hidden and shown from the bar's right-click menu as today. The comment above `.group` says what is now true.

Z825 (automode): Monaco's widgets are drawn on one node on the body above every float, through `fixedOverflowWidgets`, `overflowWidgetsDomNode` and a layout-service override, as oculus's own menus are drawn through `Portal`.
