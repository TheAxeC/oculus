## What to build

1. **The workspace header (Z76 a, Z214).** An unrooted Files tab's tree starts with one header row for the workspace in force (its name, or "Configured roots" for the default), drawn as VS Code's 22 px pane header, its actions on hover: New File..., New Folder..., Refresh Explorer, Collapse Folders in Explorer (VS Code's four title actions, acting on the selected row's folder or the first root), and its menu (`...`): Add Folder to Workspace..., Switch Workspace..., Save Workspace As..., Open Folder..., and the checked items Show Hidden Files, Show Ignored Files and File Nesting, kept per tab. Under it every root is a top-level folder row (no small-capitals head), its right-click adding Remove Folder from Workspace where item 4 allows it. The Workspaces section, the header's workspace menu in `Controls.svelte` and the bar's two toggles go; the follow toggle and the pin stay on the view's toolbar; a root whose folder is gone still says so on its row.
2. **The folder picker (Z187 f, Z202).** `POST /api/folders/pick` (with the token) runs `osascript -l JavaScript` with a script the server holds as text, which opens NSOpenPanel with `canChooseDirectories` true, `canChooseFiles` false, `allowsMultipleSelection` true, the prompt "Add", the home folder as its start, and the panel brought to the front (`NSApplication.sharedApplication.activateIgnoringOtherApps(true)`), and prints the chosen paths one a line; the route answers `{ ok: true, paths: [...] }`, `paths: []` when the panel is cancelled, `{ error: 'unsupported' }` off macOS and `{ error: 'failed' }` when the helper exits non-zero, each with the `NO_STORE` headers; the subprocess is run through one injectable runner so tests never open a panel, and a second request while a panel is open answers `{ error: 'busy' }`. Add Folder to Workspace adds every returned path through item 4's write; a path already a root is skipped with a line; Open Folder takes the first. The route lists and serves nothing; the paths it returns become roots only through the add, so nothing outside a root is served.
3. **Switching and saving workspaces (Z209).** Palette commands: `:workspace` lists the saved workspaces and the default one as results, the one in force marked, and a pick switches in place with no reload, as today; `:workspace-save <name>` saves the folders in force under the name, refusing an empty name, a taken name (`name-held`) and a reserved one with the Workspaces section's existing words; `:folder` is Open Folder (item 15). The header menu's items open the palette with the command typed. `PaletteCommand.name` gains the three names; the shell reaches the fs store and the layout store as the other commands do, and imports no view.
4. **The default workspace's folders (Z199).** In the default workspace Add Folder to Workspace appends `{ key, dir }` to `sources.yml`'s `roots:` and Remove Folder from Workspace removes the entry, through a new write kind `roots` in `server/edit/writes.ts` built on `server/edit/list-edit.ts` (the file's comments and order kept, the key made by `rootKey` against every key in force, the reserved keys refused), recorded in the change log with its undo like the rail write. In a named workspace both write `workspaces.json` as today, and a configured root shown there offers no Remove (`refused_root_fixed` says why). The hub and the engine's `config/` folder have no Remove anywhere. HELP.md and the options catalog's `roots` description say the default workspace's folders are `sources.yml`'s roots.
5. **Multi-select.** Cmd+click toggles a row in the selection, Shift+click and Shift+Up/Down extend it from the anchor, Cmd+A selects every row drawn; the focused row stays one row. The selection is the instance's state (`selection` beside `selected`, rows by root and path), pruned of rows a refresh no longer lists. Delete, Cut, Copy, Copy Path, Copy Relative Path (one path a line) and Compare Selected (exactly two files) act on the selection; Delete asks once for all (VS Code's "Are you sure you want to delete the following {0} files?", "... {0} directories and their contents?" or "... {0} files/directories and their contents?" by what is selected, the names listed). `RowMenuFacts.selection` is the selection's size. The selection fold is a pure function with its own tests.
6. **Drag and drop (Z207).** File and folder rows drag onto a folder row or a root row to move there, Option held to copy (VS Code's macOS modifier), the drop target drawn as VS Code draws it (the folder's row and its open subtree tinted); a move asks first (VS Code's default `explorer.confirmDragAndDrop`, no "Do not ask me again", fixed by the Settings ruling). A drop onto the row's own folder or into itself does nothing; a drag of a selected row moves the whole selection; a drag of a row that is not selected moves that row alone. A folder row drags under a drag type of its own that only the Files tree takes; a file row keeps `FILE_DRAG`. Files dragged in from Finder onto a folder upload into it through the Upload write; a Finder folder is refused with a line. Moves and copies go through `POST /api/ops` as Cut, Copy and Paste do; a move between two roots is a copy and a trash of the source, as Paste across roots does. The drop decision (target, refusal, move or copy) is a pure function with its own tests.
7. **The keys (Z181 a).** On a focused row of the Files view: Enter and F2 rename, Cmd+Down opens (a file in the pane's preview tab, a folder toggles), Cmd+Backspace deletes to the Trash, Cmd+C, Cmd+X, Cmd+V copy, cut and paste, Escape cancels a cut, Option+Cmd+C copies the path, Option+Shift+Cmd+C the relative path, Space opens a file kept in the background (VS Code's `filesExplorer.openFilePreserveFocus`) unless a type-ahead is pending, Cmd+Z and Shift+Cmd+Z undo and redo (item 21). Enter on a root row, on the workspace header or with two or more rows selected does nothing (VS Code renames neither a root nor a selection); Enter on a row of the Bookmarks, Notes, Open Editors, Outline or Timeline section opens it. Every other tree keeps Enter opens: `TreeItem` takes the keymap from its tree, and `keyRoute` routes each bound chord of the Files keymap to the tree (a case per chord). Each row-menu item that has a key shows it at the item's right, in the menu's hint place.
8. **Git decorations (Z204, Z205).** A row inside a repository the `git` channel carries shows its status: the name in the decoration colour and VS Code's letter at the right (`M` modified, `U` untracked, `A` added, `D` deleted, `R` renamed, `!` conflict), staged or not, in `--c-scm-*-txt` (untracked in the added hue, renamed in the modified hue); a folder holding a changed file takes the colour of the strongest change below it (conflict, deleted, modified, added) with no letter; an entry listed with `ignored: true` is drawn in the muted text colour. `server/files/fs.ts` `listShown` marks an ignored entry `ignored: true` when the toggle shows it, from the same `ignoredIn` read and cache; the client's listing shape reads the optional field. The status fold (the channel's lists to a row's decoration) is a pure function with its own tests.
9. **File nesting (Z203).** `config/catalogs/file-nesting.yml` holds `patterns:`, VS Code 1.137.0's default `explorer.fileNesting.patterns` as a map from a parent pattern to the list of its children's patterns, `${capture}` and `${basename}` kept, with a head comment, read by a loader in `data/sources/config/` (split the folder first) and carried to the page with the configuration. File Nesting (item 1's checked item; off by default, as VS Code's `explorer.fileNesting.enabled`) nests the matching files under their parent row, which takes a twistie; a nested child is a row like any other for the menu, the keys and the drop. `DESIGN.md:44` names the file among the catalogs and `tests/checks/config/config-folder.test.ts` pins its key. A pattern map whose key is empty or whose list is not texts is refused at load with a finding, the rest kept.
10. **Compact folders.** A chain of folders each holding exactly one folder and nothing else is one row `a / b / c`, as VS Code's default `explorer.compactFolders` draws it; a press on a segment selects that folder (the menu, a drop and New File act on it); opening the row opens the last folder; Left on a compacted row closes it whole; type-ahead reads the row's last segment; Show in Files and a reveal open a chain on the way through. Read only from what is listed: a folder not yet read is not compacted.
11. **The filter's fuzzy toggle.** The filter bar gains VS Code's find widget toggle "Fuzzy Match": on, the filter matches names through `fuzzysort` (through `state/shared/words/fuzzy.ts`, the one matcher) and highlights the matched characters; off, the substring match of today. The toggle is the instance's state.
12. **Open Editors section (Z214).** A section above the workspace header, collapsed at first, listing the tabs open on the page the view is on, grouped by pane ("Group 1", "Group 2" when there are several), each row the tab's icon and label with a close control on hover and the unsaved dot for a dirty source tab; a press activates the tab. Its header actions: Save All (the dirty source tabs), Close All (with the existing unsaved question).
13. **Outline section (Z182, Z214).** A section, collapsed at first, showing the structure of the active source or document tab of the page: Markdown headings (`#` to `######`, outside fenced code) and LaTeX sectioning commands (`\part` to `\subparagraph`, starred or not, outside comments), nested by level; a press moves the tab's editor to the line. For any other language it says "No symbols for this file yet." (the line D23 replaces with symbols).
14. **Timeline section and local history (Z200, Z201, Z202).** A section, collapsed at first, for the selected file (or the active tab's file): its local saves and its git commits, newest first, each row the time ago and the subject ("File Saved" for a save, "File Deleted" for a delete's copy). A save through `POST /api/source` first copies the file as it was into the history folder (`local.yml`'s new `history` key, default `~/.oculus/history`, in `LOCAL_KEYS`, the options catalog's `local.yml` block and HELP.md's list of the keys, read at every request): one folder per file named by the first 16 hex digits of the SHA-256 of its real path, holding `entries.json` (`{ path, saves: [{ id, at, size, kind }] }`) and one copy per save named by its id (`YYYYMMDDTHHMMSSmmm`, `-n` for a second save in the same millisecond); 50 copies of kind `save` kept per file and none over 256 KB; the copy is written after the save's own refusals pass and before the file is written; a copy that fails (a full disk) is said and the save goes on; `config/local.yml` is never copied (by device and inode, as `ops.ts` protects it). `GET /api/history?root=<key>&path=<rel>` lists the saves; with `&id=<id>` it answers that copy's text, the id taken only from the file's `entries.json`, so `id=../x` is refused. The commits come from `GET /api/git?log=<repository>&path=<rel>` in `git-reads.ts` beside `blame` (50 at most, `git log --follow` with the path after `--` as a literal pathspec, `GIT_LITERAL_PATHSPECS=1`), a new form of `server/core/git.ts`, which is split into a folder by what its forms do before the form is added, the form list in its head and `tests/server/core/git.test.ts` and `DESIGN.md:128` updated; a file outside any repository answers an empty list. A press on a save opens a diff of that copy against the file now; a press on a commit opens the diff of the file at that commit against its parent, through the diff view the Repositories view opens. Restore on a save's right-click writes the copy back through the source save (itself copied first). A newer read for another file supersedes an older one, whose answer is dropped.
15. **Show in Files and Open Folder (Z1, Z210).** Show in Files of a folder (the project card, the person's supervision folder) opens a Files tab rooted at that folder, or activates one already rooted there, the rooted top kept in the instance state's `top`; its one top row is the folder, with a parent row `..` above it that moves the top one folder up, drawn while the top is below the root that serves it; no workspace header is drawn on a rooted tab. Show in Files of a file (the entry card, the venue card, the Repositories view's reveal) reveals it in the page's Files tab as today. A file opened from a rooted tab lands in the Explorer page's right pane by the landing rule. Open Folder...
