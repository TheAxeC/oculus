## How the view lives in oculus (the three layers, the data live)

**Data.** Three sources, all on this machine, verified 2026-09-13 (read them, take nothing on trust):

1. Claude's rate windows come only from the JSON Claude Code hands its status-line command on stdin after every API response: `rate_limits.five_hour.used_percentage`, `rate_limits.five_hour.resets_at`, `rate_limits.seven_day.*` (Unix seconds; the object is present for a Pro or Max login after the first response and a window may be absent), `session_id`, `model.id`, `model.display_name`, `context_window.used_percentage`, `context_window.context_window_size`, `cost.total_cost_usd`, `transcript_path`, `cwd`. Nothing on disk carries the windows otherwise. So oculus ships the command `tools/oculus/bin/claude-usage.sh` (POSIX sh, `jq` not required: read stdin whole, write it unchanged) that writes the JSON atomically (write to a temp file in the folder, rename) to `~/.oculus/usage/claude/<account>/<session_id>.json`, where `<account>` is the basename of `${CLAUDE_CONFIG_DIR:-$HOME/.claude}` (a child process inherits the variable, so the two config folders `~/.claude` and `~/.claude-work` give `.claude` and `.claude-work`), and prints one short status line to stdout from the same JSON: `<model.display_name> | <context_window.used_percentage>% context | 5h <five_hour.used_percentage>% | 7d <seven_day.used_percentage>%`, each part left out when its field is absent (a small awk or sed over the JSON is fine; the script has a test that pipes a fixture through it under mkdtemp with `HOME` and `CLAUDE_CONFIG_DIR` set). The orchestrator installs it in `~/.claude/settings.json` as `"statusLine": { "type": "command", "command": "<hub>/tools/oculus/bin/claude-usage.sh" }` at landing (both accounts share that file by symlink); you never write there.
2. The account behind a Claude config folder: `<dir>/.claude.json` (for `~/.claude` the file is `~/.claude.json`, beside the folder) holds `oauthAccount` with `emailAddress`, `organizationName`, `organizationRateLimitTier` (today `default_claude_max_20x` for `~/.claude`, `default_claude_max_5x` for `~/.claude-work`), `billingType`, `subscriptionCreatedAt`. Read those five keys and nothing else from that file; it also holds session state that is not yours.
3. Codex: every rollout under `<CODEX_HOME>/sessions/YYYY/MM/DD/rollout-*.jsonl` (`~/.codex` by default, which `server/sessions/codex.ts` line 41 already resolves) carries on its token-count events a `rate_limits` object: `limit_id`, `primary.used_percent`, `primary.window_minutes` (10080 is the week), `primary.resets_at` (Unix seconds), `secondary` (same shape or null), `plan_type` (today `prolite`), `credits`. The newest event in the newest rollout is the current state. `~/.codex/auth.json` is never read.
4. Tokens per day and per model, both tools, the last seven days: Claude transcripts under each account's `projects/` (the two folders share one by symlink: dedupe by real path) carry `usage` on every assistant record with `message.model` and `timestamp` (`server/sessions/fold.ts` lines 111 and 127 to 137 read them today per session); Codex rollouts carry `total_token_usage` and `last_token_usage` (`codex.ts` lines 170 to 179). A new reader `server/usage/transcripts.ts` folds only files modified within the window, streaming line by line, into rows `{ tool, account, day, model, input, output, cacheRead, cacheCreation }`, with an in-memory cache keyed by path, size and mtime so an unchanged file is never re-read (the pattern of `server/sessions/cache.ts`; say whether you reuse it or copy it). This session's transcript is 53 MB, so the first fold is measured and stated in the report (time, files, bytes).

**Config.** `local.yml` gains `accounts:`, a list of `{ tool: claude | codex, dir: <config folder, ~ allowed>, label: <words> }`, read by `data/sources/config.ts` beside `claude_bin` (LOCAL_KEYS line 39); absent, the default is `[{ tool: claude, dir: ~/.claude, label: claude }, { tool: codex, dir: ~/.codex, label: codex }]`. The tier labels come from `config/behavior.yml`, a new map `usage_tiers:` (`default_claude_max_20x: "Max 20x"`, `default_claude_max_5x: "Max 5x"`, `default_claude_pro: "Pro"`, `prolite: "Plus"`, an unknown tier shown as its raw string). These two are the user-visible shapes; Axel's yes came with the package.

**Code.** `server/usage/watch.ts` on the sessions watcher's pattern (`server/watch/sessions.ts`: `fs.watch` handles, a debounce, one rebuild, one publish): it watches each Claude account's `~/.oculus/usage/claude/<account>/` folder (created when absent), the Codex `sessions/` tree's current and previous day folders, and reuses whatever change signal the sessions watcher already raises for the transcripts (export a subscription from it if none exists; a second `fs.watch` over `projects/` is the fallback, named in the report), and publishes one `usage` channel message: `{ accounts: [{ tool, label, dir, email, organisation, tier, tierLabel, billing, windows: [{ name: 'five_hour' | 'seven_day' | 'primary' | 'secondary', usedPercent, resetsAt, windowMinutes }], live: [{ sessionId, model, contextPercent, costUsd, updatedAt, cwd }] }], days: [{ tool, account, day, model, input, output, cacheRead, cacheCreation }], builtAt }`; `live` holds the status-line files written within the last hour. Wire it in `src/server.ts` as `watchHpc` is (lines 70 to 81) and add the channel where the socket's channel list and `state/entities.svelte.ts` (`hpc()` at line 64) declare the others; a `usage()` reader.

**View.** `views/Usage.svelte`, registered as `usage` under the System group in `config/layout.yml` line 24 (after `hpc`), with `views.usage` and `views.usage_glyph` in `config/text-oculus.yml`'s `views` group and every other string under a new `usage:` group there: one card per account (the label, the email and organisation, the tier label, the billing kind), each window a `Meter` with its percentage and `usage.resets_in` ("resets in {0}", a duration from `resets_at` to now, refreshed by the socket's messages, never by a timer in the view), the live sessions under the card as rows (model, context percentage, cost with two decimals, the session id's first eight characters, the working directory's last folder); then a table (`ui/Table.svelte`) of the last seven days, one row per day and model with the four token counts in `--font-num`, and a total row; the empty states through `Empty` (no account, no status-line file yet: `usage.no_line`, naming the install in one sentence). Sizes from the type scale as the HPC view's after Q12.

## Decisions taken in this brief (each reversible, none silent)

1. The status-line JSON files live under `~/.oculus/usage/claude/<account>/`, one per session, overwritten on each response, never deleted by oculus.
2. The Codex state is read from the rollouts, not from `auth.json` or any endpoint.
3. `accounts:` and `usage_tiers:` are the two config shapes; the tier map is config so a new tier name is one line.
4. The daily table folds transcripts with a size-and-mtime cache; the window is seven days.
