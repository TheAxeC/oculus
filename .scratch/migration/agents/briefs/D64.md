# Brief: D64, apps in the tools

Size: a full step

Read `tools/oculus/.scratch/migration/agents/spec.md` first; its rules govern this step unchanged. It is also the one standards page the configuration lists. No ADR folder exists (`ls docs/adr tools/oculus/docs/adr` answers no such file for both), so no ADR touches this step.

You work in the worktree `.agents/worktrees/D64` (from the repository root) and nowhere else; the base copy is `.agents/worktrees/D64-base/tools/oculus/`.

A design ruling decides what is built. It never exempts the code: every line is written to the standards pages, so that people can read, use and maintain it.

This step is the third of three (D62, D63, D64) that give an oculus app everything a VS Code extension can do (ruling "Apps as capable as VS Code extensions"). D62 built the host process, its JSON-RPC protocol and the frame's methods; D63 added the contributions to the shell. This step adds the contributions to the tools: languages, language servers and language features in the source editor, the workspace API a ported extension calls, debug adapters in the Debug view, tasks and terminals, source control providers in the Repositories view, and file decorations in the Files view. At its landing every row of the ruling's inventory is met. The protocol table of DESIGN.md is kept: this step builds its four `oculus/stream/*` rows and adds new rows; it changes no row already built, so every new kind of call is a row of its own. Every API an app calls follows VS Code's API by name and shape (the host's namespaces `oculus.languages`, `oculus.workspace`, `oculus.debug`, `oculus.tasks`, `oculus.scm`, `oculus.window`, and the classes `Uri`, `Range`, `Position` and the rest), as D62 and D63 did, and every manifest point is VS Code's contribution point by its own name and shape, written in YAML. Where VS Code has the same name only in its proposed API, oculus does not build it. Rulings Z833 to Z848 (plan.md, Rulings) shape each part and are restated below as requirements.

## What to build

Every item holds for a machine app and a root app alike; a root app's language server, providers, decorations, source control, tasks and debug configurations act only within its own root (G49), and a machine app's within the workspace folders. A contribution of this step acts only while its app is approved, enabled and unchanged, and goes the moment that ends, its streams closed and its servers, adapters, terminals and tasks ended; a stop of its host alone ends what the host's streams fed and leaves its tmux terminals running. The Disable, Remove and Revoke questions name the debug session, the tasks and the terminals of the app they will end. Every id an app adds follows D63's rules: it starts with the app's name and a dot, except a language id, a debugger type, a task type and a source control id an app shares with VS Code's world (a debugger type, a task type) or extends (a language), which follow item 2 and item 5.

0. **The relay split** (plan.md D64 Step 0, Z840). `relay.ts` and `relay-options.ts` move into a new subfolder `lsp/relay/`, keeping `lsp/` at 10 items or fewer, and the relay is split there by responsibility into modules: the page sessions, the routing of the page's messages, the making of a held server, the server's messages to the page, the life of a held server; `#prepare` and `#heldOf` come back as named helpers. No behaviour changes in the split; each module is under 880 lines and the relay's head comment moves to the module it describes. The tests that import the relay change only their import paths; the report lists the Code-line paths of G1, G36 and G63 for the orchestrator to rewrite at landing.

1. **Streams** (the protocol's four `oculus/stream/*` rows, Z841).
   - A stream rides the host's one JSON-RPC connection; nothing travels outside it, and nothing is written raw to file descriptor 1. `oculus/stream/open` (from the host, a request: `{ id, kind }` with kind `languageServer`, `debugAdapter` or `terminal`, and what it is for) answers ok or a refusal (`refused:id` for an id the host already holds open). `oculus/stream/data` (both ways, a notification): `{ id, bytes }` (base64) for a terminal, `{ id, message }` (one JSON-RPC or DAP message object) for a server or an adapter, `{ id, stderr }` (text lines) for a server's or an adapter's own output. `oculus/stream/control` (both ways): `{ id, credit }` (bytes or messages the receiver will take), `{ id, rows, columns }` for a terminal, `{ id, end, code }`. `oculus/stream/close` (both ways): `{ id }`.
   - Flow control by credit: each side grants the other 1 MiB of bytes, or 256 messages, at open and grants more as it consumes; a sender with no credit holds its data (the runner pauses the child's readable stream, oculus pauses the page's input), so memory held per stream is bounded by the window. A stream is not a message `apps.messages_per_min` counts.
   - Ids are the host's own: a `data`, `control` or `close` naming an id this host did not open, or one closed, is dropped and logged to the host's output; a `languageServer` or `debugAdapter` data that is not one message object closes that stream with a line in its server's output; neither ends the host.
   - The host's stop closes every stream it opened. The DESIGN.md row is marked built and its text says this.

2. **New protocol rows** (open item 65, built as its option (a) until Axel rules). Each new call is a row of its own, named `oculus/<namespace>/<call>`, with the direction, kind and what it carries written into DESIGN.md's table: `oculus/languages/*` (register and unregister a server, a provider or a diagnostic collection; `provide` to the host for a provider's answer; `documents` events to the host), `oculus/workspace/*` (folders, `fs` calls, `findFiles`, `applyEdit`, a watcher's events, a content provider's `provide`), `oculus/debug/*` (register a factory or a configuration provider, `startDebugging`, `customRequest`, session and breakpoint events), `oculus/tasks/*` (register a provider, `provide`, `execute`, `terminate`, task events), `oculus/terminals/*` (create, `sendText`, `show`, `hide`, `dispose`, events), `oculus/scm/*` (create, change, the input box's value both ways, `dispose`), `oculus/decorations/*` (register, `provide`, changes). The rows D62 and D63 built keep their meaning.

3. **Languages** (Z833, Z842).
   - `contributes.languages`: VS Code's `{ id, aliases?, extensions?, filenames?, filenamePatterns?, firstLine?, configuration?, icon? }`. A new id is registered while the app acts and withdrawn when it stops; an app may name an existing id (a shipped one or another app's) to add extensions, file names and patterns to it, as VS Code merges them. A language's file rules join `languageMap`'s on the server and the page: the user's `languages:` of `config/sources.yml` first, then the shipped rules, then the apps' in the Views list's order; an extension or file name two apps give to different ids goes to the first, with a finding on the later (`findings.apps.language_taken`, naming the id it lost to). `filenamePatterns` are picomatch globs over the path from the root; `firstLine` is a regular expression over the first line, read on the page when a tab opens a file no name rule decides. `registered` and every `languageOf` caller read the joined map, so an app's language is the language of its files on the server (the host's `onLanguage:`) and on the page.
   - `configuration` names a language configuration file of the app (comments, brackets, auto-closing and surrounding pairs, folding markers, word pattern, indentation rules, `onEnterRules`), applied with Monaco's `setLanguageConfiguration`; for a shipped language it is dropped with a finding.
   - `contributes.grammars`: `{ language?, scopeName, path, embeddedLanguages?, injectTo?, tokenTypes? }`, the TextMate grammar loaded through the shiki highlighter oculus already uses (`kit/load.ts`); a grammar whose `scopeName` a shipped grammar has is dropped with a finding and the shipped one kept; a grammar file that does not read refuses the app with a finding naming the file. The page stays responsive under a slow grammar: tokenizing runs under Monaco's time budget per line.
   - `contributes.snippets`: `{ language, path }`, a VS Code snippet file (prefix, body with tab stops, placeholders, choices and variables, description, scope), offered by the editor's completion for that language while the app acts.
   - `contributes.semanticTokenTypes`, `semanticTokenModifiers` and `semanticTokenScopes`: the types and modifiers a server or provider of the app may answer, and the TextMate scopes that colour them under the theme.
   - `contributes.jsonValidation`: `{ fileMatch, url }`, a JSON schema file of the app (a `url` that is not a recorded file of the app is a finding) applied to matching JSON files by Monaco's JSON support and to matching YAML files by the YAML server.
   - `contributes.configurationDefaults`: `[<languageId>]` blocks of the editor options oculus offers per language under the same VS Code names, and defaults of the app's own settings; a key oculus has no option for is dropped with a finding. A value the user set wins.
   - Faults are worded under `findings.apps` as D63's are.

4. **Language servers** (Z834, Z843). `oculus.languages.registerLanguageServer(id, options)` in the host, `options` in the shape of `vscode-languageclient`'s two arguments: `documentSelector` (a list of `{ language, pattern? }`), `serverOptions` (an executable `{ command, args?, options?: { cwd?, env? } }` the runner starts as a child of the host, or a function answering `{ reader, writer }` streams or `{ listen, send }` for a server inside the host), `initializationOptions`, `synchronize.configurationSection`, `outputChannelName`. It answers a client with `start()`, `stop()`, `sendRequest`, `sendNotification`, `onRequest`, `onNotification` and `state`.
   - The relay serves it as an entry of `servers.ts`: one server per served root in the app's scope that holds an open document of a selected language, started on the first `didOpen` under that root, through a `oculus/languages` request the runner answers by starting the server and opening a `languageServer` stream; the same addresses, id remapping, library files, watchers, `workspace/configuration`, progress, `applyEdit`, refreshes, diagnostics to the Problems view, the 30 s `initialize` bound, the 60 s grace after the last page closes, Restart Language Server and Show Language Server Output (the stream's `stderr` lines, kept as an oculus server's output is). A server that exits on its own is started again at most four times in three minutes, then left stopped with Restart offered.
   - The page learns an app server's capabilities from its `initialize` answer, which the relay sends to the page after the handshake; the page registers the editor's features from that answer, as it does from a shipped entry's `capabilities`. The served languages are the shipped list joined with the acting apps' registrations, held in state and handed to the `ui/` kit as a parameter (`ui/` imports no state); `keys.test.ts` follows.
   - Several servers for one language (oculus's and an app's, or two apps'): each document goes to every server whose selector matches. The relay joins their answers as VS Code's client does: diagnostics kept per server and drawn together, each with its server's name as its source; completion, code actions, code lenses, links, inlay hints, folding ranges, symbols and references concatenated (oculus's server first, then apps in the Views list's order); hovers joined; a one-answer request (definition and the other locations, signature help, rename, formatting, highlight, semantic tokens, selection range) answered by the first server in that order that declared the capability. A joined request waits at most 2 s for the slower servers, answers with what came and cancels the rest with `$/cancelRequest`; oculus's own server's answer is never held back by an app's. The language's status item lists each server with its state; Restart Language Server and Show Language Server Output ask which server when the language has more than one. An `executeCommand` goes to the server that offered the command.
   - A server is given only documents under the workspace folders in its app's scope, through `uris.ts` (G2); a private file is never put on it.

5. **Language features** (Z835). `oculus.languages` holds VS Code's provider registrations, each with a document selector: `registerCompletionItemProvider` (trigger characters), `registerHoverProvider`, `registerDefinitionProvider`, `registerDeclarationProvider`, `registerTypeDefinitionProvider`, `registerImplementationProvider`, `registerReferenceProvider`, `registerDocumentSymbolProvider`, `registerWorkspaceSymbolProvider`, `registerDocumentHighlightProvider`, `registerCodeActionsProvider`, `registerCodeLensProvider`, `registerDocumentLinkProvider`, `registerDocumentFormattingEditProvider`, `registerDocumentRangeFormattingEditProvider`, `registerOnTypeFormattingEditProvider`, `registerRenameProvider`, `registerSignatureHelpProvider`, `registerFoldingRangeProvider`, `registerSelectionRangeProvider`, `registerInlayHintsProvider`, `registerDocumentSemanticTokensProvider`, `registerCallHierarchyProvider` and `registerTypeHierarchyProvider`, and `createDiagnosticCollection(name)` with `set`, `delete`, `clear` and `dispose`, its entries drawn in the Problems view under the collection's name. The runner serves an app's providers as one language server inside the host over a `languageServer` stream (item 4's path), each provider answering its LSP request, with the value classes these providers take and answer in VS Code's shapes, and `workspace.textDocuments`, `openTextDocument`, `onDidOpenTextDocument`, `onDidChangeTextDocument`, `onDidCloseTextDocument` and `onDidSaveTextDocument` over the documents that server was given. A provider that throws answers the error to that request alone.

6. **The workspace API** (Z844). The host gains VS Code's `Uri` (`file`, `parse`, `joinPath`, `with`, `scheme`, `path`, `fsPath`, `toString`), `EventEmitter`, `CancellationTokenSource`, `Disposable`, `Range`, `Position`, `Selection`, `Location` and the value classes items 4 to 9 use, and `workspace.workspaceFolders` (`{ uri, name, index }` of the workspace folders in the app's scope), `onDidChangeWorkspaceFolders`, `getWorkspaceFolder(uri)`, `asRelativePath`, `workspace.fs` (`readFile`, `writeFile`, `stat`, `readDirectory`, `createDirectory`, `delete`, `rename`, `copy`) over files in the app's scope, `createFileSystemWatcher(glob)` (`onDidCreate`, `onDidChange`, `onDidDelete`), `findFiles(include, exclude, maxResults)`, `applyEdit(workspaceEdit)` (through the language server edit's write, so an open tab follows and History records it), `saveAll`, and `registerTextDocumentContentProvider(scheme, provider)`. A path in the app's API is a `Uri` of the `file:` scheme with a real absolute path; oculus turns it into `{ root, path }` where it crosses to a page, and a `Uri` outside every workspace folder is refused `outside` where a workspace folder is needed. A private folder is never read or written through this API.
