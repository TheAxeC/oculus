Its tier id is `side-projects`; `tier: personal` is the client's board key, which matches no research board. `Tier` gains `'side-projects'`.

5. **The roots (Z228).** `buildPortfolio(hub, config, version = 0, roots: Root[] = [])` takes the roots as an optional fourth argument, so the six tests keep compiling. `WatchPaths` gains `roots: () => Root[]` and `workspacesFile: string`; `context.ts:256-261` passes `roots: () => browserRoots({ config: make.loadConfig(engine).config, engine, local })` and `workspacesFile` as the git watcher's are made (lines 299-305), reading `local.yml` in no new way. `readPersonal` drops `HUB_ROOT` and `ENGINE_ROOT`, expands `~`, and reads each remaining root once by real path, skipping one whose real path is the hub, the engine's config folder or an earlier root's (the first key kept). 6. **The watcher (Z228).** `namedByConfig` and `roleDirectories` take the roots: an event on `<root>/.oculus/project.yml` is a rebuild. A root whose `.oculus/` does not exist is watched through `openParent` (the root folder, filtered on `.oculus`), so a folder made later is heard; each root's `.oculus/` is watched flat. The workspaces file is polled with `pollFile` as the git watcher polls it, and a change rebuilds with the new roots; a config push that changes `roots:` rebuilds as now. A root removed and restored is reopened at the next rebuild. The new parameters of `namedByConfig` and `watchedDirectories` are optional, defaulting to no roots.
7. **The manifest's shape (Z222, Z231).** One parser in `normalise-personal.ts` serves both sources. A `SideProject` is `{ id, title, status, eli5, next, links, source, file }`: id `side:<slug>` for the hub, `root:<key>` for a repository, so the two never collide and no id is a reserved object key; `source` is `{ kind: 'hub', folder }` or `{ kind: 'root', key, dir }`; `file` the manifest's absolute path. Read through zod. Only a regular file is read (`lstat`, then `isFile`): a directory, a FIFO, a device or a symlink is a finding and no card. A file over 64 KiB is a finding and no card (`PERSONAL_MAX_BYTES`, a named constant with its reason in a comment). A file that does not parse, an empty file and a file that is not a map are a finding and no card. `title`: text, trimmed, non-empty; else the folder name (the root's key for a repository) and a finding. `status`: one of the vocabulary's keys, compared exactly; anything else, or none, a finding naming the value and the status `unknown`. `eli5`, `next`: text or absent; any other type a finding and empty. `links`: a list of text; a non-list or a non-text entry a finding, the entry dropped. Any key outside the five is a finding naming it (`id` and `type` included); `record()`'s research findings do not run on this tier. The finding keys, each a sentence in `config/text/findings.yml` with a literal reader (`tests/checks/source/keys.test.ts`): `findings.manifests.personal_no_manifest` (a hub folder with no `project.yml`), `personal_not_file`, `personal_too_large`, `personal_no_title`, `personal_status`, `personal_field_type`, `personal_links`, `personal_key`; the parse and not-a-map cases reuse `findings.file.does_not_parse` and `findings.file.not_a_map`.
