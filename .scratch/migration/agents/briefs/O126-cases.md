# O126, the cases ruling (round 0)

The builder's first run (handed back before any change) found that the brief's premise for item 1 is wrong. Each section head is a `TreeSection`, whose `.section` carries `border-top: 1px solid var(--line)` (`src/lib/ui/tree/TreeSection.svelte:96-101`). So a 1 px line already stands between the list's fold and the first section head. It stops 12 px short of each pane edge, inside the pane body's `padding: 10px 12px` (`src/lib/ui/frame/Pane.svelte:233-239`; the Sessions pane is not `flush`, `SessionList.svelte:378`). The same inset line stands between every two sections, so nothing marks off the list from the sections. Each ruling below stays inside the step's part.

1. **Item 1 and C1, the divider.** The divider is a 1 px `--line` line across the whole width of the pane, edge to edge through the body's side padding, between the list's fold and the first section head after it (Details, or Customizations when no session is followed). In the Sessions tab, that first head drops its own top border, so one line stands there. The other section heads keep their inset lines, so the divider is the one full-width line in the tab. The clause "with the spacing the tree's sections keep between them" is dropped, since sections keep no spacing between them. The rule lives in `SessionList.svelte`. C1 reads: with a session followed, one full-width 1 px `--line` line between the list and the Details head, and no second line touching it; with none followed, the same line before Customizations; a Session tab has neither. Option (b), widening the existing head line alone, was the lazy option.
2. **C13, the two rename fields.** Coordination is within one tab. The Sessions tab keeps one value naming the field that is open (the list's or Details', and for which session), passed down to `DetailsBody`. Opening one field closes the other. A Session tab's Details field stands alone. Escape closes only the field that holds the focus: the Escape handling of both fields is one shared helper, and its document listener in capture phase acts only while its own input has the focus. So an Escape in a Session tab's field never closes a Sessions tab's list field. C13's last sentence reads: "Within one tab, opening one of the two fields on a session closes the other, and an Escape closes only the field that holds the focus."
3. **The Details row names.** `sessions.f_cwd` becomes "folder", since `DetailsBody.svelte:199` is its one reader and the brief names the row folder. The other names keep the catalog's words, and only their capital styling goes.
4. **The points you handle in the paths** stand as you proposed:
   - Cmd+Enter on a session's tracked row calls `openChange` with the session's id, and an untracked row keeps `openChangeBeside`.
   - A fact row's whole value is a `title` on its wrapper, and `TreeItem.svelte` stays unchanged.
   - The shared selection removes duplicate ids.
   - The Pin menu uses `groups`, its first group with heading `''`.
