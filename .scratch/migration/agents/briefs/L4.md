# Brief: L4, floating panes and kept empty panes

Read `tools/oculus/.scratch/migration/agents/spec.md` first; its rules govern this step unchanged. The plan names no further standards. No ADR touches the step: the repository has no `docs/adr` folder (`ls tools/oculus/docs/adr` and `ls docs/adr` print "No such file or directory"; the configuration block has no `adr:` key).

## The plan line and its rulings

"L4 floating panes: a pane floated over the page with an orange border, on top on every page, docked still on every page (Axel 2026-09-22); and a pane kept when its last document or Terminal tab goes, one empty pane per kind per page (Z143)", with its sub-lines: a terminal's line height, letter spacing, weight and ligatures stay fixed, said in HELP.md (the Settings ruling); Z95 ruled (1) (a), (2) (a), (3) (a).

- Answer 10 (`agents/reviews/axel-2026-09-21.md:63`): any pane can float over the page with an orange border, always on top and still there when the rail switches pages; docked, it keeps the border and still shows on every page. The orange is a theme token every theme sets.
- LA18 (library audit, Axel 2026-09-26): the float's move and resize run on `interactjs`.
- Z1 and Z3 (Axel 2026-09-26): Live HPC and Usage are the first floats; a float's state stands alone, so it can later move to a window of its own.
- Z95 (1) (a): docked is a strip along the window's left, right or bottom edge, outside every page's tree, drawn beside whichever page is on screen, resized by a sash, with the orange border.
- Z95 (2) (a): a Float item in the pane strip's right-click menu and in the pane menu, and a tab dragged with Alt held floats on drop; the float's own strip menu holds Dock Left, Dock Right, Dock Bottom and Return to Page, which puts it back in the page on screen as a split of its largest pane.
- Z95 (3) (a): the saved layout gains `floats:`, a list beside the pages, each a float placed by fractions of the window `{ x, y, w, h }` or docked `{ dock: left | right | bottom, size }`; `config/layout.yml` gains a top-level `floats:` list in the same shape with `view:` in place of the pane, which a first load and Reset all pages read; its first entry is `{ view: [hpc, usage], dock: right, size: 0.3 }`, and the Focus arrangement loses its Live HPC and Usage pane. Decided with it: the border is a new token `--float-border`, `--c-orange` by default and so set by every theme (declared on `body`, item 5); a float is kept inside the window when the window shrinks; Escape and the keyboard reach a float as they reach a pane.
- Z184 (the orchestrator, automode, booked with this brief from the brief check): (1) a browser holding a saved version 4 or 3 layout gets the shipped floats too, and each tab of a view a shipped float holds moves out of its page into that float, its instance id and state kept, the pane it leaves going as a pane does when its last tab goes; (2) a view opened while its instance is in a float activates that tab in the float, as a view opened while its instance is on a page activates it there; (3) a pane's `keeps` is a property of the pane, so a kept pane stays empty whatever removes its last tab (a close, a drag out, a cross-page move, an edge drop, a record deleted, a view leaving the registry); (4) the attention's `touched()` never returns a float, so a view opened with no page named lands on a page; (5) a float's menus offer no maximise, and floats stay drawn while a page's pane is maximised; (6) a build older than this one reads a saved version 5 as no saved layout; each port is its own browser storage and runs one build, so nothing is carried back.
- Z143 (5), widened to terminals: a pane stays when its last tab, closed or dragged out, was a view opened for something or a Terminal tab; at most one empty pane of each kind per page; documents land in the document one first; Close pane removes a kept one.

## What to build

1. **The model.** `model.ts` gains `Float = { id: string; pane: Pane; place: FloatPlace }` with `FloatPlace = { kind: 'free'; x; y; w; h }` (fractions of the window, each in 0..1, `x + w <= 1`, `y + h <= 1`, `w` and `h` at least `MIN_SIZE`) or `{ kind: 'dock'; edge: 'left' | 'right' | 'bottom'; size }` (a fraction of the window's width, or height for `bottom`, `MIN_SIZE` to 0.6). `Pages` gains `floats: Float[]`. An empty `Pane` may carry `keeps?: 'terminals'`; an empty pane without it is a documents pane. `LAYOUT_VERSION` becomes 5.
2. **The save.** `serialiseLayout` writes `floats`. `parseLayout`'s gate accepts 5, 4 and 3 (5 and 4 read with `readWorkbench`, 3 with `readDockedWorkbench`), and a version 5 envelope's shape gains `floats`. It reads version 5 with its `floats` (each float read by a zod shape; a float whose pane is not one pane of at least one tab, or whose place does not add up, is dropped and the rest kept; two floats docked on one edge keep the first), and reads versions 4 and 3 as today with `floats: []`. `readPane` reads `keeps`. `checkPages` checks the floats' ids are unique and differ from every page id.
3. **The arrangement's floats.** `config/layout.yml` gains a top-level `floats:` list, each `{ view, dock, size }` or `{ view, x, y, w, h }`, `view` as an arrangement pane's `view` (one view id or a list of tabs), first entry `{ view: [hpc, usage], dock: right, size: 0.3 }`; the Focus arrangement becomes `root: { kind: pane, view: focus }`. A reader beside `parseArrangement` in `navigation/arrangement.ts` reads the list (an entry that does not read is dropped, the rest kept). A browser with no saved layout starts with these floats; Reset all pages (`resetPages`) puts them back in place of the floats it holds. `options.yml` gains the `floats` entry in section "Rail and pages" with its fields. The server's `layout.yml` check (`portfolio.ts:326`) accepts the key.
4. **Floats in the store.** `LayoutAccess.at`, `pageOf`, `holding`, `workbench`, `apply` and `change` resolve a float's id as they resolve a page's: a float is a workbench whose root is its one pane, so opening a tab in it, closing, moving, activating and New Terminal in it go through the existing operations. A float is never a page: the rail, the Pages view, the page lists of the pane menu and `currentPage` never list it. A change that leaves a float's root other than one pane is refused (no split inside a float), and a float whose pane loses its last tab is removed. The access functions `at`, `pageOf` and `holding` return a `Host = { id: string; workbench: Workbench }`, the common part of a page and a float (a float's workbench is `{ root: pane }`, no `focus`); `Page` is a `Host` with its `label` and `rail`, and a caller that reads a label or the rail flag narrows with an `isPage` guard. Every loop of `instances.ts` over the pages (`closeInstancesOfView`, `closeRecord`, `closeInstanceAnywhere`, `carryToPage`, `moveInstanceToPage`) walks the floats too, so a view leaving the registry or a record deleted closes its tab in a float, and a tab carried from a float to a page leaves the float. `touched()` never returns a float (Z184 (4)): a press in a float leaves the attention on the page it was on. `openInto` looks for an existing instance in the floats too, and activates it there (Z184 (2)). `takeSaved` and every `{ pages, current }` literal of the store carry `floats`; closing the last page keeps the floats. `startOnRailPage` and `resetPages` take the shipped floats as a second argument, read from `config.floats` by the reader of item 3 on the props path beside `railPages` (`Workbench.svelte:66`); `PagesReset.svelte` passes them. A saved version 4 or 3 is taken with the shipped floats, each tab of a view a shipped float holds moved into it (Z184 (1)), by `adoptFloats(pages, floats)` in `floats.ts`. The pure operations live in a new `src/lib/state/workbench/layout/open/floats.ts`: `floatPane(pages, page, path)` (the pane leaves the page's tree as `closePane` removes it, and becomes a free float centred on the window, `w` 0.3, `h` 0.4), `floatTab(pages, id, at: {x, y})` (the tab leaves its pane as `moveInstance` leaves it and becomes a free float at the point), `dockFloat(pages, id, edge)` (an edge already holding a docked float takes this float's tabs into its pane, the moved active tab active, and this float goes), `freeFloat(pages, id)` (a docked float floats again, centred), `returnFloat(pages, id, page)` (its tabs go back into the page as a new pane split off the right of the page's largest pane, by area, and the float goes), `placeFloat(pages, id, place)` (move, resize), `fitFloats(floats)` (every free float moved and shrunk back inside the window's fractions), and `adoptFloats`. A float's `w`, `h` and a dock's `size` are bounded by a constant of their own, `FLOAT_MIN = 0.1`, in `floats.ts`, not by the split's `MIN_SIZE`.
5. **Floats on screen.** A new `src/lib/shell/panes/FloatLayer.svelte`, mounted once in `Workbench.svelte` outside `{#key page.id}`, so a page switch never remounts a float's views. Docked floats are drawn as strips at the window's left (between the rail and the area), right and bottom (above the status bar) edges of `.body`, each with a sash (the same sash look and keyboard as `SplitView`'s) setting its `size`. Free floats are drawn over the area in a layer above the panes and below the palette, the update tray and the drag layer, positioned from their fractions of the area. Each float is a `PaneView` of its pane, with its host the float's id, and a border of `1px solid var(--float-border)`; `tokens.css` gains `--float-border: var(--c-orange)` in a `body { }` block beside `--chip-on-wall` (`:208-211`), so each theme's orange is taken. The float layer stays drawn while a page's pane is maximised (Z184 (5)). A free float moves by a drag of its tab strip's empty part and resizes by its edges and corners, both through `interactjs`, the result written by `placeFloat` at the end of the gesture. A free float dragged with its pointer within 24 px of the area's left, right or bottom edge docks there on release. A `resize` listener on the window, added and removed by the float layer, runs `fitFloats` through `placeFloat`. The keyboard reaches a float's strip and body as a pane's: a float's pane carries its float id as `data-pane-page`, and `workbench-keys.svelte.ts` resolves it through the access as it resolves a page (`:147`, `:200`, `:227`); Escape in a float does what it does in a pane.
6. **The menus.** The pane menu (`PaneView.svelte` `items`) and the strip menu (`pane-view.ts` `stripMenu`) gain Float, offered on a pane of a page's tree. On a float's pane both menus offer, in place of Float, the splits, the fold, maximise or restore (Z184 (5)) and the page lists: Dock Left, Dock Right, Dock Bottom (each left out for the edge the float is docked on), Float (on a docked float only) and Return to Page. Close on a float's pane closes the float and its tabs with the pane close's own question.
7. **The drag.** `drag.svelte.ts` reads the Alt key from the pointer event: a tab dropped while Alt is held becomes a free float at the pointer through `floatTab`, wherever it was released, and the drop layer draws the float's outline there. A float's pane takes strip and centre drops like any pane, and refuses edge drops (no split inside a float). The last tab dragged out of a float removes the float.
8. **Kept empty panes.** `removeTab` takes a rule from the store: when the tab removed was a pane's last and is a view opened for something (the registry's `opened`) or a Terminal tab (`TERMINAL_VIEW`), and the page holds no other empty pane of that kind (`keeps: 'terminals'` for a Terminal tab, none for the documents pane), the pane stays, empty, carrying the kind; every other pane goes as today. The rule reads the pane's kind and holds whatever removes the last tab (Z184 (3)): a close, a drag out (`moveInstance`), a cross-page move (`carryToPage`), an edge drop (`splitWith`, `workbench.ts:58`, which then leaves the kept pane empty beside the new one), a record deleted, a view leaving the registry, and the views' own closes (`File.svelte:148`, `Doc.svelte:76`). Close pane (`closePane`) removes a kept pane. An empty terminals pane draws the line `ui.pane_empty_terminals` ("Terminals you start from this pane's menu appear here."); the documents pane keeps `ui.pane_empty`. `landingFor` takes an empty documents pane before an empty terminals pane (its "an empty pane" step split in two, documents first). A float is never kept empty (item 4).
9. **Words and docs.** New keys in `config/text/ui.yml`: Float, Dock Left, Dock Right, Dock Bottom, Return to Page, `pane_empty_terminals`, and the drop layer's float words. `DESIGN.md:210` and `:358-365` gain the floats (a list beside the pages, a float a workbench of one pane, docked strips outside every page's tree, the saved shape, the `floats:` key) and the kept empty panes. `HELP.md:27-45` gains a **Float** bullet (the menus, Alt-drag, docking by drag and by menu, Return to Page, the orange border, on every page) and the kept-pane rule in the Close bullet's place; `HELP.md:127`, the `terminal` row, gains the sentence that a terminal's line height, letter spacing, weight and ligatures are fixed.

## Cases

The builder's first task, before any change: the first run of every case below on the unchanged tree, each as a test of the pure functions or the store, with each result noted (a case of new behaviour fails there; say so). A case the brief's rules get wrong is handed back before any code changes.

1. `serialiseLayout` then `parseLayout` of pages with one free float `{x: 0.6, y: 0.5, w: 0.3, h: 0.4}` and one docked right `size 0.3` gives the same pages back, `version: 5`. A version 4 envelope reads with `floats: []`.
2. A version 5 envelope holding a float whose pane has no tab, one with `x: 0.9, w: 0.3`, one with a duplicate id, and one valid float: only the valid float is read, the pages unchanged.
3. Two floats docked on the right in a saved envelope: the first is kept.
4. A browser with no saved layout, on the shipped `layout.yml`: one float docked right, `size 0.3`, holding `hpc` and `usage`; the Focus page's tree is one pane holding `focus`.
5. `resetPages` after the reader moved the hpc float free and floated another pane: the floats are the shipped list again.
6. `floatPane` on the right pane of a two-pane page: the page's tree is the left pane alone, one free float centred with `w 0.3, h 0.4` holds the right pane's tabs, active tab kept.
7. `floatPane` on a page's only pane: the page's tree is an empty documents pane, the float holds the tabs.
8. `openIn(floatId, [], instance)` adds a tab to the float; `closeInstance` of the float's last tab removes the float.
9. `dockFloat(f, 'right')` with no right dock: `f` docked right at size 0.3. With a right dock `g` already: `g`'s pane holds its tabs then `f`'s, `f`'s active tab active; `f` is gone.
10. `returnFloat(f, page)` on a page of a row split `[0.7, 0.3]`: the tree is a row of the 0.7 pane split in two and the 0.3 pane, the new pane holding `f`'s tabs; `f` is gone.
11. `fitFloats` with a float at `x 0.8, w 0.3`: `x 0.7`; with `w 1.2`: `x 0, w 1`.
12. A change that would split a float's pane (a split item, an edge drop) leaves the pages unchanged.
13. A drop with Alt held over a pane's centre: the tab is in a new free float at the pointer, the pane it left cleaned as `moveInstance` cleans it.
14. The menus: `stripMenu` for a page pane lists Float; for a free float lists Dock Left, Dock Right, Dock Bottom and Return to Page and no split; for a float docked right lists Dock Left, Dock Bottom, Float and Return to Page.
15. Kept panes: on the Explorer arrangement, closing the right pane's only tab (a `source` tab) leaves the right pane, empty, a documents pane; closing a `files` tab that was the left pane's last of a page with two panes removes the pane as today.
16. A Terminal tab that is its pane's last, closed: the pane stays with `keeps: 'terminals'`. A second Terminal pane emptied on the same page closes.
17. A page already holding an empty documents pane: a second pane emptied of a document closes.
18. The same rule for a drag: the last document tab dragged out of a pane to another pane leaves the pane empty and kept.
19. `closePane` on a kept empty pane removes it.
20. `landingFor` on a tree holding an empty terminals pane and an empty documents pane lands a document in the documents pane; with only the terminals pane empty, it lands there.
21. The page renders (server render of `Workbench.svelte` with a docked and a free float): the float strip, the float pane and the border token in the markup; a page switch keeps the float (the float layer is outside the keyed block, by reading the component).
22. A saved version 4 layout whose Focus page holds `[hpc, usage]` in a pane: read with the shipped floats, the Focus page's tree is the `focus` pane alone, the right float holds `hpc` and `usage` with their instance ids. A version 4 layout with no hpc tab: the float is made with new `hpc` and `usage` instances.
23. `takeSaved` of an envelope from another browser tab with two floats: the store holds both floats; the next save writes them.
24. Closing the last page with a float held: the default page opens and the float is still held.
25. `touched()` after a press in a float's pane: the page the attention was on; `openView('notes')` with no page named lands on the page.
26. `openView('hpc')` with `hpc` open in a float: the float's tab is active, no second `hpc` instance anywhere.
27. `closeInstancesOfView('hpc')` and `closeRecord` of a record shown in a float: the float's tab closes (and the float, if it was the last).
28. `moveInstanceToPage` of a float's tab to a page: the tab is in the page, gone from the float.
29. Kept rule on other routes: an edge drop of the last tab of a kept documents pane leaves that pane empty beside the new pane; `carryToPage` of a kept pane's last tab leaves it empty; the same tab closed by `File.svelte`'s own close leaves it empty.
30. Alt-drag of the only tab of a page's only pane: the page's tree is an empty documents pane, a free float holds the tab.
31. A float's tab dragged to a page pane: the float is gone; dragged back with Alt: a new free float.
32. `fitFloats` is called by the window's resize (the float layer's listener, by reading the component).
33. `workbench-keys` resolves a pane whose `data-pane-page` is a float's id to the float's pane (a test of its resolver).
34. The float menu has no maximise; the float layer markup is drawn with a page pane maximised (server render).
35. `pageOf`, `at`, `holding` of a float id return a `Host` without `label`; the rail and the Pages view list no float.

## Decisions taken in this brief (each reversible, none silent)

1. A float is held beside the pages as a workbench of one pane, addressed by its id where a page id is taken, so every tab operation reaches a float without a second set of operations; it is never a page, so no page list shows it.
2. One docked float per edge; docking onto a taken edge merges the tabs, since Z95 (1) rules a docked float a strip along an edge, and two strips on one edge would split that strip.
3. A free float starts centred at 0.3 by 0.4 of the window; a tab floated by Alt-drag starts at the pointer at the same size.
4. A float is removed when its last tab goes; it is never kept empty.
5. Docking by drag snaps within 24 px of the area's edge.
6. The kept empty pane's kind is saved on the pane (`keeps: 'terminals'`, absent for documents), since a reload must keep the at-most-one rule and the landing order.
7. The float's border is 1 px, the width Answer 10's orange border needs to be seen without taking room from the float's tabs.
8. `FLOAT_MIN` is 0.1 of the window, the smallest float that still shows a tab strip on a laptop window.
9. The access returns a `Host` (item 4), so no second set of access functions exists for floats.
