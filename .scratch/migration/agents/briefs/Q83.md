## What to build

1. **Colour math on culori, as LA5 names it.** `derive.ts`'s `luminance` and `ratio` become culori's `wcagLuminance` and `wcagContrast`; `channels`, `hex`, `mix`, `rgbToHls`, `channel` and `hlsToRgb` stay by hand, since culori's conversions would change 1,656 derived colours (probe) and LA5 named only the WCAG and CIEDE2000 functions. The head comment says the one import is culori. `lane-distance.test.ts` measures with culori's `differenceCiede2000()` over hex strings in place of `lab`, `hueAngle` and `ciede2000`; its threshold of 10 is unchanged. `isDark` in `ui/controls/editor/theme.ts` uses `wcagLuminance`, its `0.18` cut unchanged.
2. **Code colour in Markdown.** The highlighter moves to `src/lib/data/prose/languages.ts` (the server's document and turn renders need it, and the server may import data); `src/lib/state/shared/words/languages.ts` stays as the page layers' way in, re-exporting what the state and view importers use, its head comment saying so, so no state or view importer changes; the `state` row of `tests/checks/tree/boundaries.test.ts` gains `data/prose/languages`, and the `DESIGN.md` sentence listing what `state/` may import from `data` names it. `data/prose/` also exports `codeColour`, the marked-highlight extension: `markedHighlight({ langPrefix: 'hljs language-', highlight: (code, lang) => codeHtml(code, languageNamed(lang) ?? 'plaintext') })`. `renderDocument` uses it, and `turns.ts:155` renders an assistant turn with `new Marked(codeColour).parse(body, { async: false })`, so documents, the source preview and transcript turns all colour code. `span` joins `ALLOWED_TAGS`, with the comment saying why; `DIAGRAM_PROFILE` takes it too, since a diagram already allows `style` on `div`. The `.hljs-*` rules leave `Code.svelte` for `src/lib/themes/code.css` (the same selectors without the `.text` scope, the same tokens), imported by `src/routes/+layout.svelte` beside `tokens.css` and `themes.css`; `tests/ui/theme/colours.test.ts:548-557` reads `code.css` in place of `Code.svelte`.
3. **The terminal's find.** `gridOptions` sets `allowProposedApi: true`. `@xterm/addon-search` is loaded on the grid beside fit with decorations on. Cmd+F (Ctrl+F off macOS) while the grid holds the focus opens a find bar over the grid's top right, as VS Code's terminal find widget: a text box, Match Case, Match Whole Word and Use Regular Expression toggles, the count ("3 of 12", or "No results"), Previous and Next, Close. As VS Code's: Enter, Shift+F3 and Cmd+Shift+G find the previous match (upward); Shift+Enter, F3 and Cmd+G the next; Escape closes the bar, clears the marks and gives the grid the focus back. The key is taken from the grid before xterm sends it (`attachCustomKeyEventHandler`), so the shell never sees it and the browser's find does not open. Matches are drawn in the theme's `--accent-bg` and the active match in `--accent`, the two overview-ruler colours the same, each read from the computed tokens as a 6-digit hex as the grid reads its other colours, and read again when the theme changes. The bar is a component of its own in the terminal folder (the folder then holds ten items), every label a catalog key in the terminal view's catalog.
4. **The terminal's links.** `@xterm/addon-web-links` with its default URL rule makes a URL a link: underlined on hover, opened in a new browser tab (`noopener`) on Cmd+click (Ctrl+click off macOS); a plain click stays a click to the program. Only `http:` and `https:` open. The handler is a pure function beside the grid, handed to the addon's constructor. File paths are not linked.
5. **Wide characters.** `@xterm/addon-unicode11` is loaded and `term.unicode.activeVersion = '11'` set.
6. **The Gmail message.** `rawMessage` builds the message with nodemailer's `MailComposer` (`import MailComposer from 'nodemailer/lib/mail-composer'`) from `to`, `subject`, `inReplyTo`, `references` and `text`; it becomes async, its caller awaits it, and it returns the base64url string as today. MailComposer's `Message-ID` and `Date` are kept (Gmail's send takes a message that carries them).
7. **Atomic writes on write-file-atomic.** `writeAtomic` in `core/json.ts` becomes: make the folder (`mkdirSync(..., { recursive: true })`), then `writeFileAtomic.sync(path, content, options)` with `mode: newMode` passed only when the file does not exist, so an existing file keeps its mode, a new one takes `newMode`, and every write is fsynced. The exported writers keep their names and signatures. The nine plain `writeFileSync` calls go through `writeTextAtomic` (`triage.ts:83` with its `MODE`). The three that are not the reader's files stay plain. `tests/routes/files/source.test.ts:232` checks that the folder holds no file but the ones it held before the write, so it still fails when a temporary file is left.
8. **Image sizes on image-size.** `sizeOf` reads at most `READ_CAP = 512 * 1024` bytes of the file (`openSync`/`readSync`) and takes width, height and JPEG orientation from image-size's `imageSize`; `pngOrientation`, `isTurned` and `turned` stay by hand; `readSize`, `SEGMENTS`, the `ReadAt` type and the rest of the parser go, with their cases (`images.test.ts:447-522` and the `readSize` fixtures), and the head comment says image-size reads the head. The three fixtures whose answer changes are kept as `sizeOf` cases with image-size's answer, each named in the report's before and after. `images.ts`'s picture set stays exactly `.jpg`, `.jpeg`, `.png` and `.webp` (`PICTURES`), which filters `images()` and `stream`; the type `stream` serves comes from `mime`.
9. **MIME types on mime.** `files.ts` answers `mime.getType(extname(path))` (so a bare `.png` is still no extension), a `text/*` type or `application/json` with `; charset=utf-8` added, `image/svg+xml` as it is, and `application/octet-stream` for anything `mime` does not know and for `.ts`, `.mts` and `.cts`, which mime reads as video but a code tree holds as TypeScript. 10. **TOML on smol-toml.** `tomlServers` and `tomlTools` parse with smol-toml's `parse`: servers are the keys of `mcp_servers` when it is a table (header tables, dotted keys and inline tables alike), tools the keys of `tools` whose value is `true` when it is a table; a value of either that is not a table gives no names; a parse error gives `malformed: true` and no servers, and no tools. `customizations.test.ts:194` loses the repeated key.
11. **Debounce on perfect-debounce.** Each of the five watchers debounces with `debounce(() => { void rebuild(); }, wait)` from perfect-debounce (imported under the name `debounced` where the file's own wait is called `debounce`), with the wait it has today, so an async rebuild never shortens the wait; each watcher's close calls the debounced function's `cancel()`. No `setTimeout` or `clearTimeout` stays in the five files but the intervals `sessions.ts` and `usage/watch.ts` already run. `git.ts`'s throttle stays.
12. **Documents.** `README.md:13` lists the new runtime dependencies with their licences. `HELP.md`: a key row after line 84 for Cmd+F in a terminal and its keys, in the shape of the rows around it; line 126 names the find bar and Cmd+click on a URL. `DESIGN.md:70` lists `code.css` among the `themes/` files; `:116` names perfect-debounce as the watchers' debounce; `:284` names the highlighter's place in `data/prose/`.
