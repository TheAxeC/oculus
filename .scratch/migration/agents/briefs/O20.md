## The rule this package keeps

`server/git.ts` stays the read-only module its two gates guard (`tests/server/git.test.ts` lines 296 to 316: the source scan of `git.ts` alone, and the recorder over the suite). Every write lives in `server/git-write.ts`, whose own gate is the opposite: a test asserts that every command it can run is one of an enumerated list, that each has exactly one call site, and that none is reachable except through `POST /api/git` with the token, the origin check and a `confirm: true` field the page sets only from a confirm dialog. No write runs on a timer, on a watcher event, or on the socket. `git-write.ts` does not import `git.ts`'s `run` (that would put a writing subcommand through the read-only module's recorder); it may import the `GIT` constant.

## What to build

Under `tools/oculus/src/lib/server/`:

- `git-write.ts`: one `run(root, args, timeout)` through `execFile` with list arguments (`-C <root>` first, the way `git.ts` line 216 builds its vector), a ten-second timeout for every command but `push`, which gets sixty seconds (a push crosses the network), and these operations and no others: `stage(root, paths)` (`git add -- <paths>`), `unstage(root, paths)` (`git restore --staged -- <paths>`), `discard(root, paths)` (`git restore -- <paths>` for tracked files; an untracked path is refused, never `clean`), `commit(root, message)` (the message from the page is written to a file under `mkdtemp` and passed with `-F <file>` so no quoting can break it, the file removed afterwards; an empty or whitespace-only message is refused), `push(root)` (`git push` to the current branch's upstream; a branch without one is refused with the reason before any command runs, read with `git rev-parse --abbrev-ref @{upstream}`; `--force` is never sent), `branches(root)` (read: `git branch --format=%(refname:short)%09%(upstream:short)%09%(HEAD)`), `createBranch(root, name)` (`git switch -c <name>`, the name checked first with `git check-ref-format --branch <name>`), `switchBranch(root, name)` (`git switch <name>`, refused when `git status --porcelain` is non-empty, with a reason saying the tree is dirty, since a switch over dirty files is what loses work), and `stagedDiff(root)` (`git diff --cached`, which `suggestMessage` reads; `--cached` is not one of `git.ts`'s four commands, so it lives here). Every root must be one the last published `git` payload names (a session workspace) or the hub's own root (`target().hub` of `server/writes.ts` line 246) or a path under it; anything else is refused before any command runs. Every result is `{ ok, output, error }`, never a throw. The module keeps a recorder like `git.ts` line 53 to 57 so the test's gate can see every argv.
- `git-message.ts`: `suggestMessage(root)` runs `claude -p` once with the staged diff on stdin and the fixed instruction `git.message_prompt` from the catalog (the hub's message shape: a capitalised imperative subject, a blank line, `- Verb ...` bullets, no attribution of any kind), a 60-second timeout, `--model <model>` only when `behavior.yml`'s `git.message_model` is non-empty (empty means the CLI's default), and returns the text or an error; nothing is committed by it. An empty staged diff is refused before `claude` runs. The config key is read the way `server/hooks.ts` lines 105 to 118 read `notify:` (defensively, a default on a malformed key).
- `git-routes.ts` and `routes/api/git/+server.ts`: `POST /api/git` with `{ action, root, ...fields, confirm }`, token-guarded and same-origin the way `handleWrite` is (`server/writes.ts` lines 260 to 308; `routes/api/write/+server.ts` is the whole route module pattern, nine lines); `confirm` must be `true` for `commit`, `push`, `discard`, `createBranch` and `switchBranch`, answered 400 when it is not; `GET /api/git?root=` lists branches; `{ action: 'suggest', root }` answers the suggested message. `handleGit(request, token, options)` takes an options bag the way `handleTerminal` does (`server/pty/routes.ts` lines 40 to 50, `TerminalOptions`): `run`, `rootsFor` (the allowed roots) and `suggest`, each defaulted to the real one by the route, so the route test stubs them. The allowed roots come from the last published `git` payload through the hook bridge: add `bridgedGitRoots(): string[]` beside `bridgedRecord` in `server/sessions/hooks.ts` (lines 116 to 124; it reads `hub.latest('git')` and returns the payload's keys). After any write the endpoint re-reads that root at once rather than waiting for `fs.watch`: `watchGit`'s returned `Watcher` gains `refresh(root)` calling its `reread` (`watch/git.ts` lines 95 to 107), `watch/git.ts` gains `bindGitWatcher(watcher | null)` and `refreshGit(root)` over a `globalThis.__oculusGitBridge`, the exact pattern of `bindTerminals` and `refreshTerminals` in `server/pty/channel.ts` lines 457 to 481, and `src/server.ts` binds it after line 58 (`const git = watchGit(hub);`) and unbinds it on close.
