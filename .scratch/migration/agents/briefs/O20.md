# Brief: O20, the git panel

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "Git" under Layer 2 (the four read-only commands, "Git writes are Axel's alone; the commit action runs `git commit` only from an explicit click carrying the write token, and nothing else in the application can reach that endpoint"), "Auth", step 6 of the migration order, and the decision of 2026-09-10 on git writes (commit, push and branches on any git root, every write behind the token and a confirm). O13's `git.ts` reads; this package writes, in a second module that the read-only gates never see, and draws the panel.

## The rule this package keeps

`server/git.ts` stays the read-only module its two gates guard: its source names no writing subcommand and its recorder proves only the four commands ran. Every write lives in `server/git-write.ts`, whose own gate is the opposite: a test asserts that every command it can run is one of an enumerated list, that each has exactly one call site, and that none is reachable except through `POST /api/git` with the token, the origin check and a `confirm: true` field the page sets only from a confirm dialog. No write runs on a timer, on a watcher event, or on the socket.

## What to build

Under `tools/oculus/src/lib/server/`:

- `git-write.ts`: one `run(root, args)` through `execFile` with list arguments and a ten-second timeout, and these operations and no others: `stage(root, paths)` (`git add -- <paths>`), `unstage(root, paths)` (`git restore --staged -- <paths>`), `discard(root, paths)` (`git restore -- <paths>` for tracked files; an untracked path is refused, never `clean`), `commit(root, message)` (`git commit -m <message>`; a message from the page is written to a temp file and passed with `-F` so no quoting can break it, and an empty message is refused), `push(root)` (`git push` to the current branch's upstream; a branch without one is refused with the reason, and `--force` is never sent), `branches(root)` (read: `git branch --format=%(refname:short)%09%(upstream:short)%09%(HEAD)`), `createBranch(root, name)` (`git switch -c <name>`, the name checked with `git check-ref-format --branch`), `switchBranch(root, name)` (`git switch <name>`, refused when the worktree has changes that the switch would touch: `git status --porcelain` non-empty means a refusal saying so, since a switch over dirty files is what loses work). Every root is one the `git` channel currently names (a session workspace) or a path under the hub's own root; anything else is refused before any command runs. Every result is `{ ok, output, error }`, never a throw.
- `git-message.ts`: `suggestMessage(root)` runs `claude -p` once with the staged diff (`git diff --cached`, read through `git.ts`'s recorder-visible path? no: through `git-write.ts`'s `run`, since `--cached` is not one of the four read commands) on stdin and a fixed instruction from `config/text.yml` (`git.message_prompt`: the hub's message shape, a capitalised imperative subject, a blank line, `- Verb` bullets, no attribution), a 60-second timeout, the model from `behavior.yml` `git.message_model` (empty means the CLI's default), and returns the text or an error; nothing is committed by it.
- `routes/api/git/+server.ts` and `server/git-routes.ts`: `POST /api/git` with `{ action, root, ...fields, confirm }`, token-guarded and same-origin; `confirm` must be `true` for `commit`, `push`, `discard`, `createBranch` and `switchBranch`; `GET /api/git?root=` lists branches. After any write the git watcher of O13 republishes that root (the endpoint calls the watcher's re-read directly rather than waiting for `fs.watch`).

Under `tools/oculus/src/lib/views/sessions/`:

- `Changes.svelte`, extended into the panel: each row of Staged, Changed and Untracked gets a control (unstage, stage, discard behind a confirm; an untracked row gets stage only), the repository section gets the branch line as a `Menu` (switch, with the refusal shown when the tree is dirty; "new branch" with a `TextInput`), a push button with the ahead count and the upstream name (disabled with the reason when there is none), and a commit box: a `TextArea` for the message, a "suggest" button that fills it from `suggestMessage` (editable afterwards), and the commit button behind a confirm naming the branch and the staged count. A file that another live session's record lists among its `files` carries the "also open" mark the touched section already draws, so a stage or discard on a file a running session is editing is seen before it is clicked.
- Every control posts through `state/writes.svelte.ts` and shows the outcome line; `ui/Confirm.svelte` is the one confirm dialog (a primitive: a message, a confirm and a cancel, Escape cancels, focus trapped), used by O10b's pane close as well from now on.

Under `tools/oculus/config/`: `behavior.yml` gains `git: { message_model: "" }`; `text.yml` gains `text.git.*` (the prompt and the panel's strings).

Under `tools/oculus/tests/`:

- `server/git-write.test.ts`: every operation on repositories under `mkdtemp` with the real `git`: stage, unstage, discard a tracked change, an untracked path refused for discard, commit with a multi-line message holding quotes, an empty message refused, push to a bare clone and a branch without upstream refused, branches listed, a branch created and switched, a switch refused on a dirty tree, a root outside the allowed set refused before any command; the enumeration gate (a recorder as in `git.ts`: every argv over the suite starts with one of the listed subcommands and `--force` never appears); `suggestMessage` with `execFile` stubbed.
- `routes/git.test.ts`: the handler: 403 without the token, 400 without `confirm` on a commit, 200 on a stage.
- `views/sessions.test.ts`, extended: the controls rendered per row, the push button disabled with its reason, the commit box.
- `tests/server/git.test.ts` unchanged and green: the read-only module's gates still hold.
