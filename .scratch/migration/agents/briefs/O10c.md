# Brief: O10c, the configuration regrouped

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "Configuration", "Hot reload", and the decisions on the configuration. The six files O5 copied from the cockpit grew there by accretion: thresholds beside subsystem settings, vocabularies beside board rules, scan roots beside a top bar. Axel asked on 2026-09-10 for one concern per file. `loadConfig` merges every file's top-level keys into one map, so a key moves between files without any reader noticing; only two keys change name, and the readers of those two are named below.

## The files after this package

Every key of the six files today lands in exactly one of these, and the report lists the mapping key by key:

- `sources.yml`: what the portfolio reads. `scan`, `venues_file`, `datasets_file`, `programs_file`, `domains_file`, `collections`, `docs`, `indexes`, `leads_file`, `radar_file`, `publications_file`, `linkedin_dir`, `career_file`.
- `vocab.yml`: words and their colours, nothing else. `palette`, `domains` (today `themes`: the research domains' colour and label, keyed by the `domain:` a manifest carries; renamed because the UI themes are also themes), `type_color`, `type_order`, `status_legend`, `status_palette`, `focus_lanes`, `holding_color`, `priority_levels`, `fund_stages`, `career_host_status`, `career_score_dims`, `archive_categories`, `archive_dead`, `leads_fit`, `lifecycle`, `arch_color`, `data_access`, `venue_tiers`, `radar_buckets`.
- `layout.yml`: how things are arranged. `nav_groups`, `board`, `tab_rollup`, `nav_live`, `focus_label_mode`, `project_label_mode`, `archive_label_mode`, `map_label_mode`.
- `behavior.yml`: thresholds and horizons. `read_limits`, `stale_days`, `data_domains`, `stale_lag_days`, `refresh_stale_days`, `deadline_horizon_days`, `leads_horizon_days`, `conf_horizon_months`, `leads_badge_days`, `venue_conc_warn`, `linkedin_cadence_days`, `file_index`, `slurm`, `chat`.
- `appearance.yml`, new: `themes`, a list of `{ name, class, label }` in picker order, one entry per UI theme, taken from `text.js.theme.order`, `class_<name>` and `label_<name>` (fifteen today; the labels keep their glyph character, since the file is config); `wallpaper` (today in `behavior.yml`); `crt: { default: false }`.
- `meta.yml`, `glyphs.yml`, `text.yml`, `manifest-schema.yml`: unchanged, except that `text.js.theme.order`, every `class_<name>` and every `label_<name>` leave `text.yml` (their data now lives in `appearance.yml`), and the remaining strings of that group (`title`, `crt_on`, `crt_title`, `unicode`, `unicode_title`, `wallpaper`, `wallpaper_title`, `accent_title`, `accent_reset`) move under `text.ui` with the same key names.

Dropped, each with no consumer in any package of the plan: `nav`, `tabs` (the cockpit's top bar; the rail and the registry replace them), `coll_files` (a duplicate of `collections`), `venue_categories` (the set of `category` values in the venues registry), `git_sync` (empty and cockpit-only). Nothing else is dropped: `radar_buckets`, `leads_fit`, `fund_stages`, the `career_*` keys, `slurm`, `chat`, `file_index`, `wallpaper`, `linkedin_*`, `publications_file` all have a view in the plan (O20 to O28).

The files keep the cockpit's two-space style and their comments (each key travels with the comment block above it), and the six copies stop being byte-identical to the cockpit's; `.prettierignore` lists the new file and its comment is reworded to say the config is oculus's own. `tests/config.test.ts`'s check that the real `config/` loads with zero findings and holds the expected top-level keys is updated to the new key set, and it gains a check that no key appears in two files (which `loadConfig` already reports as a finding; the test asserts the finding list is empty).
