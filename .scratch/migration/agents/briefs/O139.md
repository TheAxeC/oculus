## What to build

1. **The chip.** Each row of the Files list draws, after its file name, the chip of the root that holds its file: the root is `fileUnder(finding.file, roots(), primary())?.root`. A row whose file is the primary's draws no chip, as `RootChip` already gives; a row whose file no root holds, or whose file is empty, draws none.
2. **The chip's words.** `RootChip` takes its tooltip words from its caller: a new optional prop, a function from the root's name to the words, its default the words it draws today (`t('hubs.root_tip', root)`), so its nine callers are unchanged. The Files row passes the words of a new line of `config/text/views/system/findings.yml`, `findings_file_root_tip: 'This file is under the folder served as {0}'`, placed after `findings_files`. RootChip's head comment says what the chip names and that a caller may give it its own words; it no longer says every chip names a hub.
3. **The control.** Each row whose file a root holds draws its name (the text `named` gives, unchanged) as a control: a `ToolButton` drawn `plain` and `cut`, inside a wrapper of `display: inline-flex; min-width: 0` that does not clip the button's focus ring, with the label `named(...)` gives and the title `t('audit.open_place_tip', finding.file)`.
   - A file that names a file: the press calls `openSourceFile(client, { root, path, line })` with the root and path `fileUnder` gives, and `line` only when the finding has one.
   - A file that ends in `/` names a folder: the press calls `client.layout.showFolderInFiles(path, root)` with the path without its closing `/`, so the folder is shown as a Files tab, in place of a source tab.
   - A row whose file no root holds, or is empty, keeps its name as plain words, with its whole path as the tooltip, as today.
4. **The name's form.** The name stays one line in the mono face, cut with an ellipsis at its end where the row is narrower; the chip keeps its words while the name is cut. A long name and its chip stay on one line of the row, the name giving way first, the key and the message wrapping after them as today.
5. **The keyboard.** Each control is one tab stop; Enter and Space press it; its focus ring is drawn whole; the shell's arrow keys behave as today.
6. **`named` and the search are unchanged:** the search reads the same name, the key and the message, never the chip. A folder's name keeps its closing `/`.
7. **`fileUnder` matches `dir` as well as `real`.** `src/lib/data/helpers/files/paths.ts`: for an absolute path, a root holds it when the path lies under the root's `real` folder or under its `dir` folder (each without a closing `/`, an empty one skipped); of the roots that hold it, the one whose matched folder is longest wins, as now; the path under the root is the part after the folder it matched. Its doc comment says both folders are read and why (a finding is written by a root's folder as given, a file read from disk by its resolved folder). Every caller takes the change unchanged.
8. **The folder finding.** `options-folder.ts:134` names its folder as `join(dir, OPTIONS_DIR)` with a closing `/`, so the finding says it is a folder; the words of the finding (`defined_twice`) are unchanged. The comment at :128 says so.
9. **Comments.** The head comment of `Findings.svelte` (lines 20-40) says that a row draws the chip of the root that holds its file when that is not the primary, in the words "This file is under the folder served as", and that its file name is a control that opens the file at its line, or shows a folder in Files, a file no root holds staying plain words. No comment carries history.
10. **HELP.** `docs/HELP.md:345`, the Findings bullet, gains one sentence: a Files row whose file lies under a root other than the primary carries that root's chip, and a press on a row's file name opens the file at the finding's line, or shows a folder in Files; a file no root serves stays plain words.
11. No change to `configPayload`, the server or the wire beyond item 8.
