# D56, the cases ruling (round 0)

The builder's first run (`agents/reviews/D56-report.md` is not written yet; the hand-back is quoted in the orchestrator's records) found two places where the brief's rules give a wrong result. Each is ruled here (Z759, the orchestrator, automode). Build the step under the brief with these two rulings; everything else in the brief stands.

A. A closed workbench keeps its tabs' view state (case 11, items 3 and 7). The view state of the six left-pane tabs (Files `top` and expanded folders, Search `under` and query, Problems `scope` and `under`, the Repositories and sessions filters) lives in the ui record `oculus.ui.v1`, and `closePage` clears it through `instances.forgetTabs`. Ruling: each kept workbench entry also carries a snapshot of the ui record of each of its tabs, taken at close before `forgetTabs`, as `states: { <instanceId>: <state> }` on the kept entry, and written back into the ui store under the same instance ids when the workbench is opened from that entry. A source tab that held unsaved text at close is left out of the snapshot, so text the reader discarded is not brought back. The cap of 20 kept layouts and the dropping of a malformed kept entry (brief item 7) cover `states` too: a malformed `states` value drops the whole entry. Case 11 reads: closed and reopened, the workbench comes back with its tabs, their layout states and their view states, the folder limit of each tab included. Add a case: a workbench closed with a source tab holding unsaved text, reopened: the source tab is there, its unsaved text is not.

B. The Workbenches menu's close control (item 6, case 10). `MenuItem` (`src/lib/ui/menu/menu-items.ts`) has no second control on a row. Ruling: `MenuItem` gains an optional trailing action (its glyph, its label for the tooltip and the screen reader, and its own callback), drawn by `MenuList.svelte` as a separate button at the row's end that does not pick the row, and passed through `Menu.svelte`. The Workbenches menu uses it for Close on each row; picking the row shows the workbench. The path list widens to `src/lib/ui/menu/menu-items.ts`, `src/lib/ui/menu/MenuList.svelte` and `src/lib/ui/menu/Menu.svelte`, and to the existing tests of those files where a row is added. No other menu changes.

The HOME of every further run is under `$TMPDIR`, as the brief says.
