## What to build

When the step is done, a Workbenches view manages every workbench, open and closed; the rail's menu opens and closes workbenches and reaches the view; and the status bar's branch and sync items follow the repository the reader is working in, with the repository's name drawn and pressable to choose another.

1. **The Workbenches view.** A new unique view `workbenches`, registered in the `views` group at order 10, after Processes, listed in the Views catalogue, so it has no chord and every existing chord stays (Z781). Its glyph is the existing `folder` glyph. Its one component goes in `src/lib/views/system/workbench/` (which then holds ten items); any other file it needs goes where its concern lives in `src/lib/state/` in a folder with room. It draws two sections, each a list of explorer rows (`ui/tree/TreeItem.svelte` in a `TreeView`, as the Pages view's rows are):
   - **Open**: one row per open workbench, in page order: its name (`pageName`), its folder (the root's key and the path, as `root/path`, or the key alone for a root's top), and the branch of the repository holding its folder (the rule of item 3), or nothing when the folder is in no repository. The workbench on screen is the row in force. A press shows it. The row's controls (under the pointer and with the focus inside the row, as the Pages view's) are Reset layout, through the page flows' question and `folders.reset(id)` as the Pages view resets a workbench, and Close, through `createPageFlows`, which asks about unsaved text and running terminals.
   - **Closed**: one row per kept layout, newest closed first: the folder's name (`folderName`) and its folder. A press, or its Reopen control, opens the workbench from its kept layout (`open(folder)`), which removes the row. When `pageFromKept` answers null (a tab id the kept layout holds is held elsewhere), the kept tabs are given fresh ids and the workbench opens with them, so Reopen never drops a kept layout. Its Forget control drops the kept layout after a question naming the folder; nothing else changes, and a later open of that folder makes a fresh workbench, which is what Reset does for an open one. The layout store gains a reader of the kept layouts and a Forget that saves `withoutKept`; `layout.svelte.ts` is at 877 lines, so the change comes with a split of that file by concern, into files named for what they hold. A kept layout whose root the current workspace does not serve draws its row disabled with a tooltip saying the root is not served in this workspace, and Forget stays available; while the workspaces are still being read (no roots yet), no row is drawn disabled.
   - **New workbench** (Z786): an icon in the pane header opens a menu of the served roots of the Files view (their keys), and Open Folder..., which shows the folder panel Add Folder to Workspace shows. A root's key opens the workbench of that root's top (`open({ root, path: '' })`). A folder the panel answers that lies in a served root opens its workbench at that root and path; one outside every served root is added to the workspace by the same act as Add Folder to Workspace (its refusals and lines as that act has them), and its workbench then opens at the new root's top. A cancelled panel does nothing.
   - The view opens as a unique view does: it shows the tab a page or float holds. When none holds it and the page on screen is a workbench, it opens on the rail page the Views catalogue's `views` group is keyed to in `config/layout.yml`, never inside a workbench, so a Close or a Reset from a row never takes the view with it.
   - An empty section draws one line saying it is empty. Every word is in `config/text/views/system/workbench.yml` or `ui.yml`, never literal.
2. **The rail menu.** `WorkbenchMenu.svelte` keeps its list of open workbenches with the close button, loses the Reset layout group, and gains one item under the list, "Manage Workbenches", that opens the Workbenches view as item 1 says; with no workbench open the menu holds the empty line and that item. Its head comment says so. `workbench-reset.ts` and its provide call in `+page.svelte` are deleted, since nothing reads them after the group goes (`spec.md:85`), and `ui.workbenches_reset_heading` goes when nothing else reads it.
3. **The status bar's repository.** The repository the branch and sync items read is, in order: the repository holding the active tab's file, or the folder a Files or LaTeX tab shows (the tab `activeInstance()` gives, as now, a float's included); else, on a page that is a workbench (the page on screen), the repository holding the workbench's folder; else the repository last chosen in the picker below; else the hub, as now. A file or a workbench folder in no repository decides and draws nothing, as a file in no repository does today. The choice is kept in the ui store with the appearance, an optional field read with a fallback of none so an envelope saved before the change reads as none with no change of `UI_VERSION`; it is one value for the browser tab or window, as the appearance is. A chosen repository the `git` channel does not report yet (after a reload) or reports with an error is kept and the hub is shown until it is reported; a chosen repository no longer among the picker's repositories is dropped and the hub is shown.
   - A new status bar item `repository`, drawn before `branch` in `LEFT_ITEMS`, shows the repository's name (`RepoStatus.name`) and hides with the others from the bar's right-click menu. Its tooltip names the repository's folder and why it is the one shown (the active tab, the workbench, the last chosen, or the hub). A press opens a picker listing the repositories of the Files view: every repository the `git` channel reports at a served root or below one with no error, by the label `repositoryLabels` gives, the one shown marked; a session's workspace outside the served roots and a row that is no readable repository are not listed. A pick makes it the last chosen (Z782).
   - A pick while a file or a workbench decides is kept and is drawn as soon as neither decides; the picker says so in its heading line when that is the case (Z782).
   - `repoStatus` keeps one rule for "the repository holding a path", used for the file, the folder, the Open rows' branch and the check that a chosen repository is still reported.
4. **The text.** `HELP.md:35` counts eleven views held once and names Workbenches. `HELP.md` "### Workbenches" says what the Workbenches view holds and does, New workbench and Open Folder included, and that the rail menu opens and closes workbenches and reaches the view; "### The status bar and notifications" says which repository the branch and sync items follow, in the ruled order, and what a press on the repository's name does. `DESIGN.md`'s workbench and status bar paragraphs follow each mechanism they describe. The head comments of `WorkbenchMenu.svelte`, `RepoItems.svelte`, `status.ts`, `status-items.ts` and the layout store's files follow.

## Cases

1. Two workbenches open (on `hub/projects/ideas/<a folder>` and on a root's top) and one closed: the view's Open section has two rows with folder and branch, the Closed section one row. Unchanged tree: no such view.
2. Reset layout on an open row: the page flows' question, then the workbench is made again from `workbench:` and no kept layout of its folder remains. Close on a row: `createPageFlows`'s close is called with that page's id (the question and its No are that function's, unchanged).
3. Reopen on the closed row: the workbench comes back with its kept tabs and the row moves to Open; the same when a kept tab's id is held elsewhere, with fresh ids. Forget on a closed row, confirmed: the kept layout is gone from `Pages.kept` (the saved layout read back), and opening that folder later makes a fresh workbench.
4. A kept layout whose root key the current workspace does not serve: its row is disabled with the tooltip, and Forget removes it. Before the workspaces are read: no row disabled.
5. New workbench, pick the root `engine` or another served root: a workbench of that root's top opens. Open Folder..., a folder inside a served root: its workbench at that root and path. A folder outside every root: added to the workspace, then its workbench opens. Cancel: nothing.
6. The rail menu: the open workbenches with their close buttons and "Manage Workbenches", no Reset layout group; with none open, the empty line and "Manage Workbenches". Manage Workbenches pressed on a workbench page with no page holding the view: the view opens on the views group's rail page.
7. Status bar, a source tab of a file in repository A active: the repository item reads A. A Settings tab active on a workbench of a folder in repository B: B. The same tab on a page that is no workbench, after picking C in the picker: C. With nothing picked: the hub's repository, as now. After a reload, before the channel reports C: the hub; once it does: C.
8. The picked repository C removed from the served roots (no longer among the picker's repositories): the bar shows the hub, the choice is dropped, and the picker no longer lists C. A session's workspace outside the roots is never listed.
9. A file in no repository on a workbench of a folder in B: the file decides first and finds no repository, so the items draw nothing, as now for a file in no repository. A workbench folder in no repository with a Settings tab active: nothing drawn.
10. The `repository` item hidden from the bar's menu: not drawn, branch and sync unchanged; still hidden after a reload, as the hidden set is kept.
11. A ui envelope saved before the change: reads with no last chosen repository, the hub shown, nothing else of the envelope changed.
12. The views group's chords: Settings to Processes keep `y1` to `y9` as before, and Workbenches has none.
