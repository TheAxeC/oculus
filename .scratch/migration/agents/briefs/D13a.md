## What to build

### Dependencies

Add, pinned exactly: `monaco-editor` 0.57.0, `shiki` 4.4.3, `@shikijs/monaco` 4.4.3 (the rulings LA9 1 (a) and 2 (a)). The lock records them and nothing else changes in it but their own dependencies.

### `src/lib/ui/controls/editor/`, the editor primitive (new folder, ten items at most)

One Svelte component, `Editor.svelte`, and the modules it needs, each under its own concern. The primitive imports nothing from `state/`, `views/` or `shell/`: it takes values and callbacks, as the spike's `MonacoEditor.svelte` did.

1. **Loading.** Monaco, Shiki and `@shikijs/monaco` are imported by a dynamic import inside an `$effect`, once per page (a module-level promise), so the server bundle holds none of them. The workers load through `?worker` imports (`monaco-editor/editor/editor.worker?worker` and the `json`, `typescript`, `css` and `html` language workers) and `self.MonacoEnvironment.getWorker`, as the spike's `monaco-setup.ts` does; Monaco's own language services for those languages stay on.
2. **Languages.** Every name of the highlighter's 19 is an editor language. Plaintext is Monaco's own. The other 18 are coloured through Shiki: one highlighter per page, loaded with the Shiki grammars for them, each registered as a Monaco language where Monaco has none, then `shikiToMonaco`. A map from oculus's names to Shiki's ids is one table in the folder: `bash` to `shellscript`, `lisp` to `common-lisp`, `makefile` to `make`, and the rest by their own name; the builder confirms each id against `shiki`'s `bundledLanguages` and reports any that differ. The Monaco language id of a model is the Shiki id, so `shikiToMonaco` finds it registered.
3. **Theme from the tokens.** One function reads the body's computed style and builds two things: Monaco's colour map (`editor.background` from `--panel` and every other colour key Monaco 0.57 registers, each set from an oculus token, with a token plus an alpha suffix where VS Code's default is a translucent colour), and a TextMate theme for Shiki whose `tokenColors` map scopes to the six code hues (keyword and storage to `--c-code-keyword`, string to `--c-code-string`, numeric and language constants to `--c-code-number`, entity, function and type names to `--c-code-name`, meta, tag, punctuation and variables to `--c-code-meta`, comment to `--c-code-comment`, with bold and italic as the code window's `strong` and `emphasis` rules draw them, and `markup.inserted` and `markup.deleted` to `--c-green` and `--c-red`). Every hex value is expanded before Monaco sees it: 3 digits to 6, 4 digits to 8, 6 and 8 unchanged. The theme is defined through the highlighter (loaded as a Shiki theme, so `shikiToMonaco` maps its scopes) and set as the page's one Monaco theme, and it is built again and set again when the app theme changes, which the page announces the way the terminal already follows it (`views/sessions/terminal/grid-look.ts` reads the computed tokens; follow its trigger). A colour key Monaco registers that the map leaves out paints with VS Code's own default, which breaks the rule that every colour is a token, so the map names every key: the list of keys is read from the installed `monaco-editor` at test time (see Cases 3).
4. **Keys.** At first load, `monaco.editor.addKeybindingRules` removes every Cmd+K chord listed above and Ctrl+K on macOS (`command: null` on the first chord's key), so Cmd+K and Ctrl+K reach the shell and open the palette from inside the editor (LA21 (a)). Nothing else of Monaco's 379 bindings is removed. The list of removed chords with each one's action id and Monaco's own label (`editor.getAction(id)?.label`) is exported, for the palette.
5. **The component.** Props: the text, the language (oculus's name), whether it may be written, the indentation (size and tabs or spaces), the line ending, the breakpoints (line numbers), the quick diff marks and the blame lines (as the gutter takes them today: `LineMark[]` and the blame of `state/sources/repositories/file-git.ts`), and a model name unique per tab instance. Callbacks: every change of the text, every caret move (line, column, selection length), every scroll as a fraction of the scrollable height, a press on a quick diff mark (with its mark), a press on a blamed line (with its commit), and a press in the glyph margin (with its line). A method the parent calls through `bind:this` runs one action by id and performs the asks below. One model per instance, on a URI of its own (`inmemory://oculus/<instance>/<path>`), disposed with the component. Options: `automaticLayout: true`, `glyphMargin: true`, `readOnly` from the prop, `contextmenu: true` (Monaco's own menu, VS Code's editor menu, coloured from the tokens by item 3), the font and size from the code tokens the code window uses, minimap and sticky scroll as Monaco's defaults.
6. **The gutter.** The quick diff marks are line decorations in Monaco's line-decorations lane (where VS Code draws them): a bar for an added or a modified run, a wedge at the deletion's place, in the colours `Gutter.svelte` uses today; a press on one calls the mark callback. The blame, while on, is drawn in the line-number column through Monaco's `lineNumbers` function (the run's first line says author and how long ago with the line number, the others the line number alone), the column widened to hold it, with the commit and its subject on a hover; a press on a blamed line number calls the blame callback. The breakpoints are glyph-margin decorations (the gutter D11 needs); the primitive draws what it is handed and reports the press, and D11 decides what a breakpoint is.
7. **Tab and Escape.** Tab inserts one step of the indentation, as today. Escape with nothing of Monaco's open (the find widget, a suggestion, a hover) arms the next Tab (or Shift+Tab) to move the focus out of the editor as Tab does anywhere else, so the keyboard is never held there (`DESIGN.md:294`). A press of any other key disarms it.

### The source tab

- `views/sources/source/Editor.svelte` becomes the tab's use of the primitive: the draft, the language (the one chosen from the status bar, or the file name's), the caret report, the Markdown split with `Preview.svelte` and the sash, and the asks. Its textarea, mirror and hand-written caret and indent code go.
- The status bar's asks are performed on the model: `goto` moves the caret and reveals the line, `indent` sets the model's options, `convert` turns the indentation into tabs or spaces through Monaco's own indentation actions, `ending` sets the model's end-of-line, `language` sets the model's language. A new ask `{ kind: 'action'; id: string }` runs one Monaco action by id on the tab it names.
- The paint limit keeps its meaning: a file over `editor.paint_limit_kb` is opened with the plaintext language, so it is not coloured; the key and its readers are unchanged.
- The preview follows the editor's scroll fraction as it follows the textarea's today.
- A keystroke still keeps a preview tab, and a save, a revert and the unsaved guard (`sourceDirty`) work on the draft as today.
- `Gutter.svelte` stays for the read-only code window, which keeps drawing it. What both gutters read (the marks, the blame runs and words) stays in `state/sources/repositories/file-git.ts`, one copy.

### The palette

While a source tab is on screen, the palette lists the removed Cmd+K chords' actions, each under Monaco's own label with its old chord as the hint (for example "Add Line Comment", `Cmd+K Cmd+C`), matched fuzzily like every other item; choosing one sends the `action` ask to that tab. A new `PaletteItem` kind `editor` carries them, and its kind word is "Editor", catalogued as `app.palette.kind_editor` beside the other kind words (`config/text/app.yml:22-23`) and answered by `kindWord`.

### `typingIn`

An element inside `.monaco-editor` counts as typing, so a digit, `:`, `?` or `/` typed in the editor reaches the editor and not the shell.

## Decisions taken in this brief (each reversible, none silent)

1. The primitive is `ui/controls/editor/`, since the ui root holds ten items; the editor is a control that takes typing.
2. Every language but plaintext is coloured by Shiki, Monaco's own grammars included where it has one, so one TextMate theme built from the tokens colours every file; Monaco's language services (the TypeScript, JSON, CSS and HTML workers) stay on.
3. The editor keeps Monaco's own right-click menu, which is VS Code's editor menu; this is "the editor's own through Monaco" that Q88's line names.
4. The blame is drawn in the line-number column, where the gutter draws it today, through Monaco's `lineNumbers` function.
5. The paint limit key keeps its meaning by opening a larger file as plaintext.
6. The palette's editor actions are a new item kind `editor` with the kind word "Editor", listed only while a source tab is on screen.
7. One model per tab instance on an `inmemory://oculus/<instance>/<path>` URI; D23 decides the `file://` URI a language server needs.
