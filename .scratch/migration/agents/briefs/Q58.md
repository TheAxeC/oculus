## What to build

1. **The eleven files split by concern**, not by line count: a test file into files named for what they hold, the describes as the seam, a case moving whole with its name; a source file into modules each with one reason to change and its own head comment, every export keeping its name and shape. Each ends under the line, and `bin/size-allow.txt` ends with no entry.
2. **At most ten tracked items in every folder under `src`, `tests`, `bin` and `config`.** Files are grouped into subfolders by concern, each folder's name saying what it holds; `tests/` mirrors `src/lib` where a test has a source counterpart. The layer of a file stays the first folder under `src/lib`, so the layers of DESIGN.md are unchanged.
   - `src/routes/api`: route groups, `src/routes/api/(<group>)/<route>/`, which SvelteKit leaves out of the URL, so every URL stays as it is. No URL changes.
   - `src/lib/views`: a view and its partials become `views/<group>/<name>/`, the group being the view's rail group from the list above, and a view opened for something rather than listed sitting in the group it is opened from (decision 2). `ownPartials` in `tests/boundaries.test.ts` is rewritten to the same rule at the new depth (a view reaches its own folder and nothing of another view, a sibling in the same group included), and a synthetic case proves a view cannot import a sibling view of its group.
   - Every path the boundary rows name is rewritten to where its module now is; no row gains a pattern it did not have in effect before.
   - `config/`: `glyphs.yml`, `icons.yml`, `vocab.yml`, `meta.yml` and `manifest-schema.yml` move into `config/catalogs/`; `configNames` reads `config/catalogs/` as it reads `config/text/`, and every reader of those files by name follows.
   - `config/text/views`: one subfolder per rail group as listed above, each file keeping its name.
3. **The rule and its check.** `agents/spec.md` is the orchestrator's; the builder writes the check. `bin/folder-check.sh` fails when a folder under `src`, `tests`, `bin` or `config` holds more than ten tracked items, naming each; `tests/size.test.ts` (or a sibling test) runs it the way it runs `bin/size-check.sh`. Seen failing first on the tree before the moves.
4. **History wording out** of every file of `src`, `tests`, `bin`, `config`, `HELP.md`, `DESIGN.md` and `README.md`: a step or package id, a date that records when something was decided or changed, what the code or a rule did before, what was removed or renamed, a reason that is the other tool's practice. Each candidate line is read; a date that is test data, and a sentence naming the cockpit as a fact about what oculus reads or replaces, stay. A comment keeps what the code does and why. `DESIGN.md`'s decisions keep their content and lose their dates and incidents.
5. **Documents follow the tree**: every path in `HELP.md`, `DESIGN.md`, `README.md`, the head comments and the config comments that a move changed is rewritten. Q58 runs alone, so these documents are this step's.
