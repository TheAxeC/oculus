## What to build

1. **The key.** `terminal.transcript_font_px`, a number in CSS pixels, clamped to 6 to 40 as `font_px` is, read by `terminalShape` with the same bounding and shared with `font_px` rather than copied, with a getter beside `terminalFontPx`. It has an option row beside `terminal.font_px` (heading terminal, section Display and keys, control number, min 6, max 40) whose help says it is the text size of a terminal tab's transcript, that leaving it out follows the theme's `--fs-sm` token, and that the tab's text size buttons write it while the Transcript shows. It has no key in `config/defaults/appearance.yml`, only one commented line under `terminal:` of the form `# transcript_font_px: 14`, with a short comment that leaving it out follows `--fs-sm`, as `terminal.opacity` has at line 86. The row's help does not say a value is clamped: a value in a file is held to the row's `min` and `max` by the workspace layer.
2. **The ui store.** A reader and a setter for the key beside `terminalFont` and `setTerminalFont`, the same shape: the write held until its push, 6 to 40, null resetting the key, through the same `writeOption` and `resetOption`. Rewrite `setTerminalFont` and the new setter so the clamp and reset are written once.
3. **The size in force.** The transcript's size is the key when set, used as given as `font_px` is, and otherwise `--fs-sm` times the text scale. `transcriptZoom` no longer reads the grid's size and has no floor. A function gives that size so the buttons and the zoom use one rule. Where no size comes of it, the zoom stays 1 as today. `TranscriptBody` reads the new key through the ui store, and its zoom follows a change as today.
4. **The buttons.** `TerminalFontTools` takes a required boolean prop saying the transcript shows, passed through `TerminalBar` from `Terminal.svelte` as `session.reading`, which `tab-session.svelte.ts:41-42` defines as the condition; `Terminal.svelte:375` is left as it stands, since it narrows `session.target`. While it is true, smaller and larger move the transcript's key by one CSS pixel from the transcript's size in force, and reset clears that key alone. While it is false they do what they do today, to `terminal.font_px` alone. The labels follow: three new words `transcript_larger` (Larger transcript text), `transcript_reset` (Reset transcript text size) and `transcript_smaller` (Smaller transcript text) in the same catalog file, each read by a literal `t('...')` per branch, since `t(cond ? 'a' : 'b')` is a dynamic reader under `tests/checks/source/keys.test.ts`. The guard of `current !== undefined` stays, so a size that cannot be read writes nothing.
5. **Comments and pages.** Every paragraph listed under "What is on the tree" says what is true after the change. `terminal.font_px`'s help and the defaults comment stop naming the transcript; the help says the buttons write the key while a grid shows, and drops "a value is clamped to 6 to 40", which is not true of a file; and `docs/HELP.md:459` says the buttons size what the tab shows, each view keeping its own size, with reset returning only that one.

## Cases

Nothing here is kept as a test: the size of a text costs no lost work, no broken installation and no wrong configuration accepted that the option row does not already refuse (a value in a file is held to the row's `min` and `max`, the setter's clamp bounds the buttons), and `agents/spec.md` allows a test only as the test of a guarded entry. The builder writes no test. Each case is checked by a read of the code with `file:line` in the report, and the orchestrator looks at the running result at landing.

- `terminal.font_px` 16 and no transcript key, Transcript showing: the transcript draws at `--fs-sm` times the text scale, whatever `font_px` says.
- `terminal.font_px` 10.5, `terminal.transcript_font_px` 11, Transcript showing: 11 px, below `--fs-sm`, with no floor.
- Smaller, pressed twice from no key at an `--fs-sm` of 12 at scale 1: the key reads 11, then 10, and `terminal.font_px` is unchanged.
- Smaller at a key of 6: the key stays 6. Larger at 40: stays 40.
- Reset with the transcript showing: the transcript key goes, `terminal.font_px` stays. With Live showing: `terminal.font_px` goes, the transcript key stays.
- Reset with the transcript showing and no key in any file: nothing changes and nothing is refused.
- `terminal.font_px` 14 with Live showing, smaller: the grid moves to 13, the transcript key is not written. The same tab on Transcript then shows the same size as before.
- Two Terminal tabs, one on Live and one on Transcript: a press in one changes only the size of what that tab shows; two transcripts share the key, as two grids share theirs.
- A tab on Transcript with no terminal: smaller writes the transcript key and `terminal.font_px` is unchanged.
- A key of 3, 100 or a word in the workspace file's `settings:`: a finding names `settings.terminal.transcript_font_px`, and the key reads as left out, so the transcript draws at `--fs-sm`.
- A key of 13 at a text size of 1.2: the transcript draws at 13 px, the zoom being 13 divided by `--fs-md` times 1.2.
- Smaller from no key at a text size of 1.2 and an `--fs-sm` of 12: the key reads 13.4 and stays there if the text size changes, as a press on a grid pins `font_px`.
- The key set and reset in the Settings view: the same as the buttons, with a value out of range refused by the row.
- A write refused or a workspace not saved: the same path as `font_px`, the store says so and nothing is held.
- The theme changes while no key is set: the transcript takes the new `--fs-sm` through the observer `TranscriptBody` has.

The builder's first task, before any change, is a first read of every case above on the unchanged tree, with each case's result noted. When that read finds a case the brief's own rules get wrong, the builder stops there, before changing any code, and hands back the case with the rule and the result it gives.

## Decisions taken in this brief (each reversible, none silent)

1. The left-out size follows `--fs-sm` times the text scale, as ruled, so it is 12 px at scale 1 and 11 px under the terminal themes that set that token lower.
2. A set key is used as given and is not multiplied by the text scale, the rule `font_px` follows.
3. The buttons' labels name the transcript while it shows, since "terminal text" would be false there.
4. No test and no new guarded entry: see "Cases".
5. The key lives under `terminal:` with `font_px`, the place the ruling names.
