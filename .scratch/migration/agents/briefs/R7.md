# Brief: R7, the catalog and the registry oculus's own

Read `../spec.md` first and its amendment of 2026-09-13 22:30. Axel ordered on 2026-09-10 (O10c) that every config file be oculus's own, laid out for oculus, and on 2026-09-13 at 22:30 and 22:45 that the text catalog follow, that no cockpit-only key remain, that every key have a reader, and that no package edit the shared files (`views.ts`, `layout.yml`'s key lists, one catalog file) again.

## What is on the tree (read 2026-09-13 at 22:15)

- `config/text.yml` (988 lines, 13 groups, the cockpit's catalog copied at O5 with a `js:` group of 14 cockpit JavaScript subgroups) and `config/text-oculus.yml` (15 groups, oculus's own since O10c), merged by `data/sources/config.ts` `textCatalog` (line 335) into one flat dotted map; 908 keys in `text.yml`, of which 228 are named by nothing under `src/` (counted 2026-09-13 with a literal search; some may be reached through a computed prefix, which the orphan test below settles).

## What to build (the three layers: this is config and code, no data or wire change)

1. **One catalog laid out for oculus.** `config/text/` holds one file per owner: `app.yml` (the shell: rail, tabs, palette, tray, pages, keys sheet), `ui.yml` (the primitives), one file per view (`views/focus.yml`, `views/projects.yml`, ..., `views/usage.yml`), `server.yml` (strings the server or the status line write), each with a head comment saying what it is for oculus. `loadConfig` reads every `config/text/**/*.yml` in name order into the one flat map (a key defined twice is a finding, as today); `config/text.yml` and `config/text-oculus.yml` are deleted. Every key keeps its dotted name where oculus reads it, renamed only where the name is the cockpit's (`js.slurm.*` becomes `hpc.*`, `js.sessions.*` becomes `sessions.*`, `sf.*` becomes the view it serves, and so on: the renames are listed in the report), with every reader following. Every cockpit-only key goes: the `js.boot` log lines, `js.slides` (P1 gets its own file when it is built), `js.entryform`, and any key the orphan test names; a key with no reader is deleted, never kept "for later" (YAGNI).
2. **The orphan test.** `tests/keys.test.ts` gains the reverse check: every catalog key is named by a `t()`/`lookup()` literal, by a config value that names a key (a registration's `label`, a glyph name, a `views.<id>` for a registered id), or by one documented computed prefix listed in the test with the file that computes it; anything else fails the suite. Run it first, and let it drive the deletions.
3. **Views register themselves.** Each view's `.svelte` module script exports its `registration` (id, label key, glyph key, `group`, `order`, the badge hooks it has today); `src/routes/views.ts` becomes a loader over `import.meta.glob('$lib/views/*.svelte', { eager: true })` that registers every exported registration and names no view (the boundary table is untouched: the loader stays outside `src/lib`); `config/layout.yml`'s `nav_groups` lists the groups (label, glyph, chord) and no longer their `keys:`; the rail orders a group's views by `order` then id; `tests/shell/rail.test.ts`, `tests/views/registry.test.ts` and `tests/config.test.ts` follow; the browser suite's `data-view` and `data-group` selectors stay.
4. **The cockpit's copy stays where it lives**, `tools/cockpit/data/config/`, untouched.
5. **Every config file in oculus's own words and ASCII, and no cockpit path as a default.** `src/lib/server/wallpaper.ts` line 20 falls back to `tools/cockpit/assets/wallpaper` when `wallpaper.dir` is absent and `config/appearance.yml` lines 41 to 45 document that cockpit path: the wallpapers get an oculus folder named in `appearance.yml`, and the code reads the key with no default beside it. `config/behavior.yml` lines 50 to 67 still carry the cockpit's emoji comments copied at O5 (found by the D19 and D19c reviews); each comment says what its key does for oculus, in ASCII, and the ASCII scan of the spec's verify list runs over `config` as well as `src`, `tests` and `bin`.

## Decisions taken in this brief (each reversible, none silent)

1. One file per owner under `config/text/`, dotted keys unchanged for oculus's own groups, the cockpit's `js.*` and `sf.*` names replaced by the owner's.
2. A view's group and order are the view's own registration data; `layout.yml` keeps the groups' labels, glyphs and chords.
3. The orphan test's computed prefixes are an explicit list in the test.
