## What to build

1. **The fold.** `FoldKey` gains `'career'`; `Focus.svelte` passes `open={foldOpen(folds, 'career')}` and `ontoggle={() => fold('career')}` to `CareerPanel`, as it does for the command center and the tasks, so the banner starts open in a tab with no saved state, and its fold survives a reload and a move of the tab. The banner's local `unfolded` state goes. Folded, the body stays `hidden="until-found"` and mounted, and a find-in-page match inside it unfolds it through `ontoggle`. `Focus.svelte`'s head comment says the three sections fold the same way and start open.
2. **The box and the flow.** The banner's box is the command center's box, drawn from `TickerGroup.svelte` (item 9) with a purple left edge where the command center's is red: the padding, the borders, the radius, the background, the two-column flow (`columns: 2 22em; column-gap: 16px`) and the two wallpaper rules, each group a block that does not break across the columns, the heading row spanning both columns (FoldHead does). The editor, while open, spans both columns. The `.sections` grid, the `.facts` definition grid, the `<ol class="order">` list, the `.when` date boxes, the `Table`, `.career`'s box rules and their styles are removed from `CareerPanel.svelte`.
3. **The groups and their rows.** Each group is drawn by `TickerGroup.svelte` (item 9): a heading in the command center's look (a glyph and the label) over a `Ticker` with `reveal`, in this order, each drawn only when it has a row:
   - NEXT (`focus.next`, glyph `career_next_glyph`): one row, the milestone; its tail the milestone's day and its days left, `2026-11-17, in 23 days` (a new key `career_next_tail: '{0}, {1}'` with `daysLeft`'s words), toned by `daysTone` of the days left; with no day, no tail and no tone.
   - GOAL (`career_goal`, glyph `career_goal_glyph`): one row, the goal.
   - SITUATION (`career_situation`, glyph `career_situation_glyph`): one row per fact, the fact's label as its words and its value as its tail.
   - ORDER OF WORK (`order_of_work`, glyph `career_order_glyph`): one row per task, its words the task, followed by its note when it has one (a new key `career_task_note: '{0}, {1}'`), its tail its `when`; the order's own note (`orderNote`) under the rows as a note line in the command center's look (`TickerGroup.svelte`'s note line).
   - TRACK RECORD (`career_record`, glyph `career_record_glyph`): one row per role of `trackRecord`, its words the role's label, its tail the counts of the record rows it has projects in, each `<count> <row label>` (a new key `career_record_count: '{0} {1}'`), joined by ", " (`3 in review, 2 in flight`); then, when funding is obtained, a row `career_funding_row` with the count as its tail.
   Each row's glyph is its group's glyph. A row's whole words are its hover title when the row cuts them (the ticker does this). `recordTable`, its types, `nextLine` and `career_next_line` go, since nothing reads them after the change; `trackRecord` stays, and `daysLeft` (module-private at `career.ts:31`) is exported so the NEXT row's tail is built beside the other rows.
4. **A press on a row of the file.** A press on the NEXT, GOAL, SITUATION or ORDER OF WORK row opens the career file in its source tab, kept, with the caret at that entry's line in the tab's text: `milestone:` for NEXT, `goal:` for GOAL, the fact's key under `situation:`, and the task's row under `order:` (the n-th row whose task, written as a map's `task:` or as a plain string, equals the row's task, so two rows with one task each open at their own line). The place is found in the draft's text the way Edit in File finds an entry. The text rule (which line a top-level key, a key under `situation:` written as a block or a flow map, plain or quoted, or the n-th row of `order:` with a given task stands on) lives in a new file `src/lib/data/helpers/files/yaml/career-text.ts`, beside `collection-text.ts` and over the YAML parser and the helpers that file uses; `src/lib/state/sessions/source/draft-entry.ts` gains the function that reads the draft and calls it, as it calls `collection-text.ts` for `findEntry`, and its head comment names both text-rule files. `tests/checks/tree/boundaries.test.ts` gains `'data/helpers/files/yaml/career-text'` in its `state:` list beside `'data/helpers/files/yaml/collection-text'`, the one change to that file, so `state/` may import it as it imports `collection-text`. `entry-file.ts` exports what opens a file at a found place (from `openedDraft` and `arrived`), so Edit in File and the banner share it. When the text does not hold the entry, the tab opens as the shared opener opens it, with no line (a tab newly opened shows the file's top, one already open stays where it was), and the board's outcome line says so, naming the file (the banner takes `onsaid` from `Focus.svelte`).
5. **The buttons under the pointer.** Each row of the file carries the button Edit (`entry_form.edit`), drawn under the pointer or the keyboard and never kept. It opens the banner's editor on that row's section: the editor opens (unfolding the banner when folded) and the field of the section (`milestone`, `goal`, `situation` or `order`) is scrolled into view and its first control takes the focus. `EntryEditor.svelte` gains an optional prop naming the field to open on, passed to `EntryForm.svelte`, which marks each field with its name; with the prop absent, as on the person and entry pages, nothing scrolls and nothing takes the focus. A section the file's `schema:` has no field for opens the editor with no field focused.
   A row of the file whose words or tail hold a web address (as `linkRuns` of `src/lib/ui/html.ts` finds one) also carries, after Edit, one button Open link per distinct address in the order they are written: its label the address's host as the URL parser gives it (`example.org`), its title the words of a new key `career_open_link: 'Open {0}'` with the whole address. A press opens the address in a new browser tab the way the apps' frame opens one (`window.open(address, '_blank', 'noopener,noreferrer')`), and the row's own press is not taken. A row with no address carries Edit alone. The row's words keep the address as text.
6. **The Track record rows.** A press on a role's row opens that role's board: the first key of the merged `boards:` value, in its order, whose `role` (a word or a list) holds the role's key and that is a registered board view, so Lead opens Projects, Supervisor opens Supervision and Collaborator opens Coauthor on oculus's own values. A role no board takes is drawn plain, with no press. The Funding obtained row opens the Funding view (`openView('funding')`). These rows carry no button.
7. **Edit in the heading row.** The Edit control moves into `FoldHead`'s `end`: Edit, or Done while the editor is open, as today (`toggle`, the question before closing over unsaved edits kept). Pressed while the banner is folded, it unfolds the banner and opens the editor.
8. **The words.** `docs/HELP.md` line 287's sentences on the Career banner are rewritten to the banner as built: open by default and folded like the command center, the groups in order as rows, the Next row's tail and tone, a press opening the career file at the entry, Edit under the pointer and in the heading row, Open link under the pointer on a row that holds a web address, the Track record rows opening their board and the Funding view. The head comments of `CareerPanel.svelte`, `Focus.svelte` and every file the step changes say what the code does; every sentence in the step's paths that the change makes false is made true. The rows' words come from `config/text/views/boards/focus.yml`, the four new keys among them (`career_next_tail`, `career_task_note`, `career_record_count`, `career_open_link`); a key no code reads any more is removed. The head comment of `CommandCenterView.svelte` says its groups and box are drawn by `TickerGroup.svelte`.

9. **One source for the command center's look.** A new component `src/lib/ui/display/ticker/TickerGroup.svelte` holds the command center's group look and its box, and both `CommandCenterView.svelte` and `CareerPanel.svelte` draw with it:
   - A group: a block that does not break across the columns, 4px under the one before it, headed by the glyph and the label in extra-small bold capitals in the accent colour, over its runs, each run an optional note line (the muted small line) over a `Ticker`, the ticker's props (`onpick`, `onaction`, `reveal`, `kept`, `marked`) passed through as the caller gives them, then an optional note line under the runs and an optional snippet of the caller's own content after them (the attention group's `.behind` lines). It also draws the two other forms the command center has: the split form (each run its own unbreakable block, the heading inside the first, so the deadlines group runs on into the second column a category at a time) and the folded form (a `<details>` closed by default, its heading the `<summary>`, for the snoozed rows). The prop names are the builder's.
   - The box: a snippet exported from the component's `<script module>`, taking the left edge's colour and the box's content, drawing a `<section data-surface>` with the box's padding, borders, radius, background, two-column flow and two wallpaper rules, the styles written in `TickerGroup.svelte`. If the installed Svelte refuses that export (the type check or the build fails on it), the builder stops and hands it back with the output, before writing the box another way.
   - Every group of the command center is drawn through it: `group`, `kindGroups`, the attention group, the deadlines group, the refresh group and the snoozed group. After the change neither `CommandCenterView.svelte` nor `CareerPanel.svelte` holds a style of the box, a group, a group heading or a note line (`.week`, `.grp`, `.grp.split`, `.category`, `.lbl`, `summary.lbl`, `.sub`, `.career`); `CommandCenterView.svelte` keeps the styles of its own content (`.behind`, `.lead`, `.link`, `.more`). The command center looks and behaves as it does today: the same rows, headings, notes, gaps, columns, the red edge, the HPC pill, the snoozed group closed by default, every press and button.

## Decisions taken in this brief (each reversible, none silent)

1. The place of an entry is found in the source tab's text when the row is pressed, as Edit in File finds a collection entry, rather than carried as line numbers in the career model: the model, which apps read as `career`, keeps its shape, and a draft with unsaved text is opened at the place it holds.
2. An order row is found by its task and its rank among the rows with that task, since the model leaves out a row with no task and so holds no index into the file.
3. A role's board is the first board of `boards:` whose `role` holds it, read from the configuration rather than written into the code, so a hub's own boards are followed.
4. The order's note stays, as a `.sub` line under the ORDER OF WORK rows, since the file holds it and the line names no place for it.
5. A row's glyph is its group's glyph.
6. The words of an order row with a note are "<task>, <note>"; a Track record row's tail is its counts joined by ", ".
7. The editor's field to open on is a prop of `EntryEditor` and `EntryForm`, absent everywhere but the banner.
8. The box is a snippet exported from `TickerGroup.svelte`'s module script, with the edge colour as its parameter, so the one new file the ruling names holds both the group and the box and the styles of each are written once.
9. An Open link button is labelled by the address's host and titled with the whole address, so two addresses on one host differ by their title; an address written twice in a row gives one button.
