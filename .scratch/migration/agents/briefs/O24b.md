Read `../spec.md` first; it governs this package unchanged. O24 was split on 2026-09-11: O24a landed the metalist editor, the entry form as the shared partial `views/shared/EntryForm.svelte`, the three registry files carried as `collections.venues`, `collections.programs` and `collections.domains` beside their entities, and the Venues view; this package builds the three remaining views on that. ## The acceptance list, from the cockpit tabs as extracted on 2026-09-11

**Programs** (the cockpit calls the tab Pillars), top to bottom:

1. The intro (`col.programs_intro`, rendered as inline Markdown) with "+ add" at its right (the shared form over `registries/programs.yml`'s schema, saving through `newEntry`).
2. The pillar cards: one per entry whose `kind` is neither `provisional` nor `offpillar`, in file order, then the orphans card (item 4). A card: the title as inline Markdown, "N project(s)" (`col.project` with the plural the cockpit adds an s for; add `col.projects` for the plural rather than appending a letter), the edit control (the shared form pre-filled, saving through `writeEntry` by the entry's `key`); the metrics row: the in-flight count in bold with `col.in_flight`, the member total with `col.total` muted, and the tier strip, one chip per venue tier in `venue_tiers` order with the count of in-flight members whose venue carries that tier (`unrated` for a member with no venue or no tier), in the tier's colour; the goal, the funding line with the `funding` glyph, the blurb, each as inline Markdown when present; the cross-link groups of the members (grouped by type with counts, each member opening its project tab, the grouping O24a exported from `state/collection.ts`). A card whose members hold no active, manuscript or idea project is drawn dormant (muted).
3. Membership: a project is a member of a line when its `programIds` names the line's key, and it counts only when it is real (every project-tier project, and an archive or coauthor project whose type is not in `vocab.yml`'s `archive_dead`); in flight means real and of type active or manuscript. The venue tier of a member is its venue entity's `tier`.
4. The orphans card: the real projects whose `programIds` name no key of the file (`col.orphans`, `col.untagged` with the count, `col.orphans_blurb`, the `warn` glyph, the cross-link groups); or, with none, the clean card (`col.no_orphans`, `col.no_orphans_blurb`, the `check` glyph).
5. The provisional band, when the file has a `kind: provisional` entry: `col.provisional_h`, `col.provisional_note`, then those cards with full metrics.
6. The off-pillar band, when the file has a `kind: offpillar` entry or a project is archival: `col.offpillar_h`, `col.offpillar_note`, the off-pillar cards (muted, no metrics), then the archival card (`col.archival`, `col.not_active` with the count, `col.archival_blurb`, the `archived` glyph): the projects that are not real, grouped by their type in `archive_dead` order, each group a collapsible with its count, each member opening its project tab.

**Domains**, top to bottom:

7. The intro (`col.domains_intro`) with "+ add" (the form over `registries/domains.yml`'s schema).
8. One card per domain entry that has at least one member, in file order: the title, "N project(s)", the edit control, the blurb, the cross-link groups; the card's accent is the domain's colour from `vocab.yml`'s `domains` map through `domainTone`; dormant when no member is active, manuscript or idea. A member is a real project whose `domainIds` names the key. `col.domains_empty` when no card remains.

**Map**, the relationship graph:

9. The head: the sentence the cockpit's `maphead` carries, as catalog words (a `map` group in `config/text-oculus.yml`: the research lines with the `square_filled` glyph and the projects with the `circle_filled` glyph, linked by line membership and directed `related:` edges, drag a node, click a project to open it), the legend (active, manuscript, idea in their type colours; research line), the link-mode toggle (`link` glyph, `map.link`, `map.link_tip`) and the re-tune control (`refresh` glyph, `map.retune`, `map.retune_tip`).
10. The toggles row: "+ collaborators" (off by default; on, the collaborator nodes appear) followed by "+ archived:" and one checkbox per archived status present among the archived projects, each with its `arch_color` dot (off by default; on, the archived projects of that status and their edges appear). The two are `Checkbox` primitives.
11. The graph, an SVG: a node per project (a circle in the project's type colour, its label `short` or the title by `layout.yml`'s `map_label_mode`), a node per research line reached by a visible project (a square, `map.line_color` token, labelled with the line's title), a node per collaborator reached by a visible project when the toggle is on (a square in the collaborator tone, labelled with the collaboration entry's title or the key when the file has none); an edge per project-to-line membership, per project-to-collaborator, and one per unordered `related` pair, directed one way (an arrowhead at the target) or both (a distinct colour and two arrowheads) when each manifest lists the other; an archived project carries its status and an edge is archived when either end is; a line or collaborator node shows only when at least one visible project links to it. Node radius grows with degree as the cockpit's does (`04-map.js` line 55).
12. The layout: the cockpit's self-tuning spring layout ported as pure functions (`04-map.js` lines 102 to 265: `physics`, `crossings`, `score`, `placeInit`, `settle`, `bestLayout`, `optimize`), seeded so a test is deterministic; the tuned parameters cached per visible node set in `localStorage` under a key derived from the node ids, re-used on the next open, cleared and recomputed by re-tune. After the initial settle the layout keeps cooling with `requestAnimationFrame` while a drag reheats it.
13. Interaction: drag a node (a project node dropped without moving opens its project tab; a line node opens the Programs view and a collaborator node opens the Collaborations collection view, both through `openView`); drag empty space to pan; wheel to zoom; double-click to reset the view. Link mode: dragging one project node onto another toggles the target in the source's `related:` list, written through `writeManifest(source, { related })` (the existing manifest write; `related` is a `chips` field of `config/manifest-schema.yml` line 53), and the graph redraws from the next snapshot push; the rubber-band line while dragging and the highlight of the target node as the cockpit draws them.
14. `map.empty` when no project carries a `program:` or a `related:`.

## Decisions taken in this brief (each reversible, none silent)

1. **Three views, three registrations.** `views/Programs.svelte` (partials `views/programs/`: `LineCard.svelte`, `OrphansCard.svelte`, `ArchivalCard.svelte`), `views/Domains.svelte` (`views/domains/DomainCard.svelte`), `views/Map.svelte` (`views/map/Graph.svelte`, `Controls.svelte`), registered as `programs`, `domains`, `map` in `src/routes/views.ts`, with `views.programs` ("Pillars", glyph `program`), `views.domains` ("Domains", glyph `circle_filled`) and `views.map` ("Map", glyph `link`) in `config/text-oculus.yml`'s `views` group.
2. **The pure parts.** `state/lines.ts`: `realProjects` is O24a's (`state/venues.ts`; move it to `state/collection.ts` or a small `state/real.ts` if two modules need it, and say which), `lineMembers(line, projects)`, `inFlight(projects)`, `tierStrip(members, venues, tiers)`, `orphans(lines, projects)`, `archival(projects, dead)` grouped in `archive_dead` order, `isDormant(members)`, `domainMembers(domain, projects)`; `state/graph.ts`: `buildGraph(snapshot, options)` (nodes and edges as item 11 describes, with the visible-set rule), the layout functions of item 12 over a `Rng` the caller seeds, `layoutKey(nodes)`. Every function under test.
3. **The map's colours are tokens and tones.** A project node's fill is `typeTone(type)` and an archived one's is `toneOf(arch_color[status])`; the line node, the collaborator node, the membership edge, the one-way and the mutual related edge each have a token in `themes/tokens.css` (`--map-line`, `--map-collab`, `--map-edge`, `--map-related`, `--map-mutual`), never a hex in the component.
4. **The map words are a new group.** `map:` in `config/text-oculus.yml` (the tab's own words lived in `page.py` as literals, so no group holds them): `head`, `legend_line`, `link`, `link_tip`, `retune`, `retune_tip`, `collaborators`, `archived`, `empty`, and the glyph names the head uses. The Programs and Domains words are `col.*` in `config/text.yml` (lines 816 to 833) and are used as they stand; `col.projects` (the plural) joins that group there.
5. **The tuned parameters live in `localStorage`.** As the cockpit kept them: a per-machine convenience, keyed by the visible node set, cleared by re-tune; not part of the saved layout tree.
