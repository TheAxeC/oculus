## The acceptance list

1. **The images.** Copy the sixteen files of `tools/cockpit/assets/memories/` to `tools/oculus/assets/memories/` byte for byte (`cmp` each pair in the report), and add `memories: { dir: tools/oculus/assets/memories }` to `config/appearance.yml` beside `wallpaper:`, the same shape. The folder is served by a new `api/memories` route: `GET /api/memories` answers the sorted list of image names (`.jpg`, `.jpeg`, `.png`, `.webp`), `GET /api/memories?file=<name>` streams one, with `server/wallpaper.ts`'s rules reused rather than copied (the folder under the hub, the file's basename only, resolved and refused outside the folder, the same-origin check, the cache header); factor what both routes share into one module rather than a second copy.
2. **The Memories view** (`views/Memories.svelte`, id `memories`, in the Personal group after the two documents, `listed`): a wall of the images as tiles in a CSS masonry or column layout (no library), each tile a control opening the image in a lightbox drawn by this view (`ui/` gains nothing: the lightbox is the view's own overlay, closed by Escape, a click outside, or its close control, focus returned to the tile), an "+ add photo" control taking one or more files through a hidden file input and posting each as `POST /api/memories` `{ name, data }` (the name's basename, the three extensions only, base64 body, written into the folder with `writeTextAtomic`'s sibling for bytes, behind the write token and the same-origin check), the wall re-asked after a write. An empty folder says so in the catalog's words. The images are referenced by URL, never inlined.
3. **The audit scan** (`src/lib/server/audit.ts`, layer 2): a pure function over the snapshot's projects and collections plus the hub on disk, answering `AuditFinding[]` of `{ scope, where, kind, message, signature }` with `kind` one of `todo`, `data`, `conform`, `readability`, `publink`, and `signature` the cockpit's twelve-hex sha1 of scope, where, kind and message so a muted finding stays muted across the two tools. The rules are the cockpit's, each ported as a fact: the markers (`%TODO`, `%VERIFY`, `%FIXME`, `TODO`, `FIXME`, `TBD`, `XXX` as whole words) in each project's `README.md`, `code/README.md` and `PRESENT.md` and in each collection entry's text; the `data` gaps listed above, with `read_limits` and `stale_days.audit` read from the config and the data domains and waiting statuses from the vocabulary rather than hardcoded; the `conform` rules above; the readability limits as `readability`; the website sync as `publink` when the file `publications_file` names exists under the hub and skipped silently when it does not (the cockpit's matching: exact normalised title, then a word-overlap of at least 0.72, many hub records to one site entry; the five flags: missing from the site, a negative result leaked, a dead end that is public, a differing title or section, the untracked count). The manifest hard errors and the references are the `Findings` view's already and are not scanned twice; the Audit view links to Findings for them.
4. **The scan on the wire.** The scan runs in the portfolio watcher after each rebuild (`src/lib/server/watch/portfolio.ts`), published on a new channel `audit` as `{ findings, muted }` where `muted` is the signature list of `config/behavior.yml` `audit_ignore:` (a new key, a list of signatures, absent by default); the client store `state/audit.svelte.ts` holds the last payload. The scan reads the disk (markers, folders), so it runs once per rebuild and never per request.
5. **The Audit view** (`views/Audit.svelte`, id `audit`, System group after config, order 7): the six sections in the cockpit's order with a count each, one card per finding (`ui/Card.svelte`) with the scope, the place and the message, a search box (`ui/Search.svelte`) filtering the cards, a mute control per card and an un-mute on each muted card in a collapsed section at the end; the rail's System flyout shows the open count as a badge through `state/rail-badges.ts` as the Sessions and HPC badges are. ## Decisions taken in this brief (each reversible, none silent; the shapes go to Axel through the orchestrator)

1. The images live under `tools/oculus/assets/memories/` (beside `wallpaper/`), tracked in git as the cockpit's are, and are served by their own route rather than as a root of the file browser: a wall is not a folder listing.
2. `POST /api/memories` is the upload, with the cockpit's `{ name, data }` body; the folder is the only place a write lands.
3. The audit is its own channel and its own view; `Findings` keeps the data layer's own errors, and the Audit view is the cockpit's six sections. The `manifest` and `reference` kinds are not duplicated.
4. The mute list is `config/behavior.yml` `audit_ignore:`, the cockpit's place under its new name, written by the `audit-mute` kind.
6. `waiting_status` in `config/behavior.yml` carries the list the cockpit built into code; `data_domains` is there already.
5. `readability` is the kind name for the cockpit's `lint` flag on manifest findings.
