## What to build

The ruling (Z40 (d)): a Terminal tab is a terminal panel of its own. It owns one or more terminals, its list shows only those, New in a tab adds a row to that tab and shows it, Split divides that tab's body between two terminals, a terminal belongs to exactly one tab, and dragging a row onto another tab's list moves it there. The Sessions view lists every terminal; pressing one shows the tab that owns it, and a terminal no tab owns (started by a task, a hook or LaTeX, or left when its tab closed) is taken into the Terminal tab of the page on screen, or a new one. A terminal's row goes when it ends, and the tab closes when its last terminal ends. Closing a tab leaves its terminals running, listed in the Sessions view.

1. **A tab's own state.** A pure module `src/lib/state/sessions/terminal-tabs.ts` holds the rules over a Terminal tab's layout state, the one shape every reader goes through: `{ terminals: string[], shown: string | null, beside: string | null, share: number, composing: boolean, label: string }`. `terminals` is the tab's own order; `shown` is the terminal on the left or alone; `beside` is the second terminal of a split, or null; `share` is the left half's share of a split, 0.5 by default; `composing` is whether the composer shows (alone, or beside `shown` in a split). Functions, each pure and tested: reading a saved state (an old `{ session, label }` reads as that one terminal shown; an old `{}`, `{ id }` or `{ id, follow }` reads as a tab with no terminal, composing; ids that are not terminal ids are dropped, duplicates kept once); the terminal ids a tab owns; the tab owning an id among a list of tabs; a state with a terminal added at an index (and shown); a state with a terminal removed (its `shown` moving to the next row in order, else the previous, `beside` cleared when it was either half); a state with the order changed; a state split (`beside` set, `composing` false) and one showing a single row (`beside` null). The label is the shown terminal's name, set by the view as today's pinned label is (`Terminal.svelte:157-169`).
2. **The store keeps ownership.** `createTerminals` is handed, as today, the Terminal tabs of every page, plus `restate(id, page, state)`, `activate(id, page)`, `switchPage(page)`, `currentPage()`, the active Terminal tab of a page's focused pane (or null), and `open(page, state)` returning the new tab's id. It gains:
   - `showTerminal(id)`: the tab that owns `id` is activated (its page switched to when it is another page) and shows it (alone, unless it is one half of the tab's split, which stays); when no tab owns it, the Terminal tab of the page on screen takes it (decision 2), or a new Terminal tab on that page, and shows it.
   - `moveTerminal(id, toTab, toPage, index)`: `id` leaves the tab that owns it and joins `toTab` at `index`, shown there. A tab whose last terminal left it this way closes.
   - On each `sessions` message, an ended id (by `endedTerminals`, unchanged) leaves every tab that owns it; a tab whose last terminal ended closes, on any page; a selection that was the ended terminal is cleared. The following-tab closing and the `followed` bookkeeping go, with the selection's part in closing.
   The following tab, `followsSelection`, `composerState`, `composerTarget` and `pinnedTerminal` go, with their tests. A terminal is never taken into a tab without `showTerminal`, a start from a tab, a drop or `Open in its own pane`, so a tab's close leaves its terminals unowned and listed in the Sessions view.
3. **The Terminal view.** `Terminal.svelte` draws the tab's own state:
   - The grid of one terminal moves into a partial `views/sessions/terminal/TerminalGrid.svelte` (the xterm mount, the pty subscription, the resize, the bell, the paste question, the file drop and the theme and size updates of today's `Terminal.svelte:259-366` and the markup around the grid), so a split tab draws two and `Terminal.svelte` stays under 600 lines.
   - The body: the composer when `composing` and nothing is shown; one grid for `shown`; in a split, `shown` on the left and `beside` (or the composer, while `composing`) on the right, with a `Sash` between them that moves `share` and resets it on a double click. The steer box shows under a grid whose terminal runs Claude or Codex.
   - The bar: `new terminal` sets `composing` in this tab; the terminal the composer starts joins this tab after the shown one and is shown (in a split's right half, it becomes `beside`). The pin control goes. The rest of the bar stays.
   - The list (`TerminalList.svelte`) shows only this tab's terminals, in the tab's own order; a press shows that row (alone when it is outside the split; a press on a half of the split focuses its grid); Split on a row splits this tab: the row's terminal left, the composer right in the row's folder and kind (`splitState`, Z39's folder rule), and what it starts becomes `beside`; Kill stays. A row dragged within the list reorders the tab; a row dropped on another Terminal tab's list, or on its body when that tab draws no list, moves there by `moveTerminal`. Both halves of a split are marked current in the list. The list is drawn from two terminals on, and with one while the composer shows (`listDrawn`, unchanged).
   - The page-wide order (`storedOrder`, `withOrder`, `orderedRows` over `pageViewState`) and the steer-box-disabled branch for a selected session running elsewhere go.
4. **Every start shows its terminal through `showTerminal`.** Each place in "What is on the tree" that selects a started terminal and opens a Terminal tab when the page has none keeps its `select` and calls `showTerminal(answer.id)` instead of `openView('terminal')`; `repositories.svelte.ts:219` calls `showTerminal` instead of opening a pinned tab. New in the Sessions list and the `n` key set `composing` in the Terminal tab of the page (decision 2), or open a new Terminal tab composing. A terminal row press in the Sessions view selects it and calls `showTerminal`; `Open in its own pane` opens a new Terminal tab on the page on screen and moves the terminal into it by `moveTerminal`.
5. **Docs.** `HELP.md:123` and `DESIGN.md:266` and `:273`, and every other sentence of `DESIGN.md` and `HELP.md` the change makes false (grep for `follows the selection`, `pinned to it`, `Terminal tab`, `for the page`, `pin`), say what a tab owns, what New, Split, a drag and a press in the Sessions view do, and that a tab closes when its last terminal ends and closing one leaves its terminals running. Head comments of every changed file say what the file does now. `npm run diagrams` rerun.

## Decisions taken in this brief (each reversible, none silent)

1. The tab's layout state is the shape in item 1, and an old saved state is read into it, so a reload after the change keeps every Terminal tab: a pinned tab keeps its terminal, a following or fresh tab opens on the composer.
2. The Terminal tab of the page on screen, for a terminal no tab owns, is the active tab of that page's focused pane when it is a Terminal tab, else the first Terminal tab of the page in tab order, else a new Terminal tab on that page; it is activated.
3. A session row pressed in the Sessions view selects the session as today and shows no terminal; only a terminal row, a start, a drop or `Open in its own pane` puts a terminal in a tab.
4. A tab closes when its last terminal ends or is moved away; a tab that never held one (New, or a reload of a following tab) shows the composer and stays.
5. When the shown terminal leaves a tab, the next row in the tab's order is shown, else the previous; a split whose half leaves shows the other half alone.
6. A press on a row outside the split shows it alone; there is no separate unsplit control.
7. A row dropped on another tab's body joins at the end of its order; on its list, at the drop mark.
8. `Open in its own pane` keeps its words and now moves the terminal into a new Terminal tab.
