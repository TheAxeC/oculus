## What to build

The sweep reads every file under `tools/oculus/tests/views/`, `tests/shell/`, `tests/ui/` and `tests/themes/`, slow-tagged files included, test by test, and applies the rules below.

1. **Delete** each test that breaks `agents/spec.md:57` or `:61`:
   - a test of behaviour whose failure costs nothing, the costs being the rule's list: lost or corrupted work, a write to the wrong file, a broken start or install, a wrong configuration or input accepted, or a view, key or command the user relies on that stops working;
   - a test of a constant, a label or catalog string, stylesheet text, a type, a pass-through or re-export, or markup the look covers (a rule between menu groups, a class, a colour, a size);
   - an assertion over one component's source text (`spec.md:61`): which calls, names or style rules it holds, or that a deleted file stays deleted;
   - a test that cannot fail on its own fixture, or that still passes with its behaviour taken out, judged by reading what the code does on that path;
   - a test whose outcome another case already gives through the same branch of the code (Z363): the case at the lowest level that reaches the branch stays (a pure function before a rendered view), and among cases at one level the one that reaches the most of the branch;
   - a rendered-view test of a behaviour a function below the view decides and a test of `tests/state/` or `tests/data/` already holds, unless it is the one case of the wiring between the two;
   - a case of a `*.client.test.ts` file that tests a press, a focus or a key rather than an effect's timing (`spec.md:65`), and a press through `press-on-render.ts` whose outcome the handler's own function decides, unless it is the one case of that press's wire;
   - a measurement that asserts nothing a user relies on.
   A kept test that carries one assertion of a kind this item deletes (over source text, a label, or markup the look covers) loses that assertion and keeps the rest; the report lists it (`repositories-menu.test.ts:130`'s `rule` assertion among them).
2. **Fold** cases of one outcome that differ only in their input into rows of one table, one test per outcome. Each row has a short name as its first column, and the table's title prints that name, so the verbose output names every row in full.
3. **Tag** each test that cannot run well under a second as slow, by its cause and by its time (Decision 1): the whole file with `// @module-tag slow: <reason>` as the last line of the head comment when every test left in it is slow; otherwise a slow describe with `describe(name, { tags: ['slow'] }, fn)`, and a slow single test with `{ tags: ['slow'] }` as its second argument, a numeric timeout moving into that object as `timeout`. A slow table takes its tag on its describe. A cause reached through imported code counts as the test's own. A hook counts with the tests it serves: a `beforeAll` or `beforeEach` with a cause, or whose body takes 100 ms or more (timed in a scratch copy), makes them slow, so a cold-start cost (an import of every view, the editor kit) sits in the `beforeAll` of a slow describe, or the file takes the file tag; it never leaves the cost in `npm test`. A file's module import time outside its hooks is the suite's shared cost and is T1a's to measure. Work at collection (a describe body, a module constant built by a call that reads files) counts with the tests it serves, as a hook does (Z382). A file or describe tag stands only where every test under it meets Decision 1; otherwise the tag goes on the tests that do (Z384). The file tag keeps a file's tests out of `npm test` but not its imports, so a module whose load starts a process is imported with `await import` inside the slow `beforeAll` (Z383). A file already tagged whose tests are all quick after the sweep loses the tag, and a file tagged for "time out or fail on a loaded machine" is re-measured under Decision 1 and keeps the tag only where it holds.
4. **Keep** every other test. No assertion of a kept test is loosened or widened. An assertion of a kind item 1 deletes (a shipped constant, a label or catalog string, source text, markup the look covers) is cut from a kept test, or an assertion whose outcome another case gives through the same branch, each cut listed in the report with its kind and its holder (Z381); an assertion is otherwise rewritten only to fold it into a table under item 2. A kept test's title is corrected when it is false, and the word "audits" leaves the title of a kept test. A kept test's setup may lose what the test does not use, its assertions unchanged. A wall-clock margin or a fixed sleep in a kept test breaks `spec.md:64`: the wait moves to a signal or a fake clock and the assertion holds on the answer, before item 3 judges the tag (`paint.test.ts:525`). An awaited `vi.waitFor` polls on a real 50 ms interval: where the code gives a signal the test awaits it; where none, it stays and the test is judged by time. A file the sweep changes that is left at 880 lines or more is split by concern (`spec.md:45`). A file the sweep changes keeps main's formatting and comment wrapping on every line no item changes.
5. **Comments and helpers.** Every comment in these folders that names a deleted or renamed test is corrected, in the files the sweep changes and in those it does not, and each file it changes has its head comment say once what the file tests after the sweep, opening with its layer label (`spec.md:49`). A `// Revert:` comment that names a change the test does not catch is corrected or deleted with its test. A file left with no test is deleted, and a describe or a `beforeAll` left with no test is deleted. A helper module imported from outside these folders keeps every export some file imports (Decision 2); a helper nothing imports any more is deleted (a `.svelte` probe or harness included), except `ui/frame/client-runtime.ts`, which `vite.config.ts:63` loads; a helper the sweep rewrites keeps how it fails. A helper of another sweep's folder that the sweep leaves unused is named in the report for that sweep, never deleted. The label: `// Layer 3, view tests.` for a test file and `// Layer 3, view test helper.` for a helper, Layer 3 being DESIGN.md's view layer (`DESIGN.md:159`), which `shell/`, `ui/` and `themes/` draw.
6. **The duplication allow list.** Each entry of `tests/checks/tree/allow-duplication.txt` at the lines listed above that the sweep makes stale (its clone no longer shared) is removed; a fold that makes a new clone among `tests/` is changed until `duplication.test.ts` passes, never listed.
7. **The report** (path below) lists every file of the four folders, one row each: the tests deleted, folded, retitled or tagged in it, or "read, kept whole" with its test count. Each removal names the behaviour it guarded and the kept test that still holds it by `file:line`, or why it guarded none; a kept test in another sweep's folder is marked as such, so the orchestrator checks it is still there when both have landed. A row dropped in a fold is a removal. Each fold lists the old case titles against the table's rows. Each test tagged by time, and each test left quick whose minimum is 80 ms or more, gives every time taken (Decision 1). The report gives the line count and test-file count of each subfolder before and after, the time of `npx vitest run tests/views tests/shell tests/ui tests/themes --tagsFilter '!slow'` before any change and after the last, with the load average beside each (a slower quick run after the sweep is explained file by file), and a section "Doc text" (below).
8. **Doc text.** Every `src/` export the sweep leaves with no caller once its only test goes (`state/system/deposit.svelte.ts:134`, `state/sessions/changes.svelte.ts:62`, `transcript.svelte.ts:225` are such test-only methods today), for removal at landing (`spec.md:83`). Every sentence outside the step's paths that the sweep makes false, with the line as `grep -n` prints it and its replacement, which the orchestrator applies at landing: the comments outside these folders that name a deleted test file, the seven source comments of `src/lib` listed above that name a test, and any sentence on the slow tier's form that T1c's proposal leaves false.
9. **The audits check (Z376 (b), Z389 (a)).** `tests/checks/tree/audits.test.ts` computes one fact and fails on it: each case in a test file under `tests/views/` that imports a `.svelte` component (an `import` statement whose source ends in `.svelte`) whose body reaches no `render(`, no `mount(` and no name the file binds to one of them. A file that imports no component tests a view-layer module of `src/lib/views/` (a menu builder, a press handler, a layout function); the check does not read it, and it stays where it is, under items 1 and 2 like every other file. There is no title escape and no allow list: `findAudits` loses the `startsWith('audits')` test and its allow argument, `readAudits`, `AUDITS`, `AUDIT_ENTRIES`, the `Audit` type and the three cases over the allow list (`:321-340` of the file at the base, 'holds the allow list to cases the tree still has', 'holds the allow list to the cases the scan still finds', 'holds every entry of the list to a reason') go, `allow-audits.txt` is deleted, and the case that passes "one that says it audits" (`:250`) becomes a case where a case titled as an audit that renders nothing is reported. `reaches` counts `mount(` beside `render(`. Its head comment says what it now checks, opening `// Layer 4, tree check.`. A kept case the check flags moves to the folder of the code it calls: a case over `src/lib/state/` to `tests/state/`, over `src/lib/server/` to `tests/server/`, over `src/lib/ui/` to `tests/ui/`, over `src/lib/data/` to a new file under `tests/data/` (T1e is changing that folder's existing files, so a moved case there goes only into a new file, in a folder of fewer than 10 items), each into the file that already tests that module when there is one, else a new file named for the module, its label the destination's; a tree check moves to `tests/checks/views/` (Decision 5), and `DESIGN.md:223` and `:227` are rewritten to name the moved paths. A file that holds both kinds, as `views/whole/chips.test.ts` and `views/whole/sanitise.test.ts` do, is split: its scans move to `tests/checks/views/` and its rendered cases stay in `tests/views/whole/`. A moved case keeps its assertions and its holder role; the report lists each move with its old and new place. `npm run test:checks` passes with the rewritten check.

## Decisions taken in this brief (each reversible, none silent)

1. **Slow, by cause and by time.** A test is slow when it starts a real process, awaits a real timer of 1 ms or more, or opens a socket, in its body, in a hook it runs under, or at the load of its module; a zero-delay yield (`setTimeout(0)`, `setImmediate`, a resolved promise) is no timer. Any other test is slow when the minimum of its times over the verbose runs of its own file (`npx vitest run <file> --reporter=verbose`), at least five and every one taken counted, is 100 ms or more; the report gives every time and the load average of each run. A cause reached through imported code, or in a hook, counts. The minimum is used because load only ever adds time.
2. **Shared helpers.** A helper module here that a file outside these folders imports keeps every export some file imports, so the other sweeps' files still compile; an export no file imports is removed (`rail-fixture.ts`'s `COLLECTIONS`, `shipped-rail.ts`'s `SHIPPED_RAIL_LABELS` among them), and a helper nothing anywhere imports is deleted.
3. **Per-test and describe tags.** The test and describe forms are used where a file mixes quick and slow tests, so its quick tests stay in `npm test`; a head comment states the file's tagging rule once.
4. **Rendered views.** A test that renders a view stays only for what no function below the view decides (what the view draws from its state, a refusal sentence it chooses, the wiring of a press to its call, one case per wire); a rendered test of an outcome a state or data function decides goes when that function's own test holds it.
5. **Tree-wide checks, each on its own rule.** A check here that reads the source of many views against one rule (`views/whole/tinted`, `type-scale`, `chips` and `sanitise`, `ui/theme/colours` and `wall`, `views/system/help`) is a tree check, set apart from the unit tests by `spec.md:56`, and is judged file by file: it stays where it holds a written rule of `agents/spec.md` or `DESIGN.md`, which the report names for it (`type-scale` `DESIGN.md:223`; `chips` `DESIGN.md:227`; `sanitise` the untrusted value of `spec.md:67`; colours from `themes/tokens.css`, `spec.md:48`, for `colours`), its rule is never loosened, and its own parse cases are judged under items 1 and 2. A check that holds no written rule is named in the report for Axel, never deleted, since the step that added it was his approval. Under item 9, a kept tree check moves to `tests/checks/views/` and loses any slow tag, since `npm run test:checks` runs with no time limit and a tree check is never tagged slow (`spec.md:56`).
6. **`vi.waitFor`.** It polls on a real interval, so it gives way to the code's own signal where there is one, and where there is none it stays and its test is timed.
7. **Client tests.** A `*.client.test.ts` case holds an effect's timing (`spec.md:65`); one of a press, a focus or a key is deleted, the look holding it.
