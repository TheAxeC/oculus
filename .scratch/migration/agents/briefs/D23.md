## What to build

When D23 is done, a Python, C or C++ file opened in a source tab is served by a language server of its root, started by oculus in the background: hover, go to definition, declaration, type definition and implementation, references, peek, document highlights, completion, signature help, diagnostics, document symbols, folding (clangd), selection ranges (clangd), inlay hints (clangd), `#include` links (clangd), formatting of the document, a selection and while typing (clangd), the quick fixes whose edit touches only the open file, clangd's inactive regions and its switch between header and source, and, under OI-6 (a), clangd's semantic colouring. The Files Outline lists the file's symbols; the breadcrumb over the tab ends in the symbol path at the caret; the status bar names the server's state, the interpreter and the compile database. A repository's `.oculus/cpp.yml` names compile databases and fallback flags. A key `format_on_save` per language formats on save where a server formats.

### 1. The server side: `src/lib/server/machine/lsp/` (new folder, at most ten items, each file at most 880 lines)

- **The servers' registry** (`servers.ts`): a table keyed by Monaco language id, one entry per server: its command and arguments, how its program is found, what it is asked at `initialize`, how `workspace/configuration` is answered, and which capabilities are kept. Two entries: `python` (pyright) and `c` plus `cpp` (one clangd serves both, as one server per root). M8 (yaml-language-server), D43 (texlab) and D34 (typescript-language-server, svelte-language-server) each add an entry and nothing else, so the table is the one place a server is described.
  - pyright: `node <oculus>/node_modules/pyright/langserver.index.js --stdio`, the `pyright` package at 1.1.414 a dependency of oculus (LA16, Z72 (1) (a)); never a global install or PATH.
  - clangd: `clangd` from the oculus process's PATH, unchanged, with `--header-insertion=never` (Z74 (4) (a)), `--compile-commands-dir=<the link folder>` when a database is chosen, `--background-index`, and no `--query-driver` (Z72 (1) (a)); `initializationOptions.fallbackFlags` from the configuration of `.oculus/cpp.yml` in force (Z92 (2) (a)).
  - Each server reads its repository's own settings (`.clang-tidy`, `.clangd`, `pyrightconfig.json`, `pyproject.toml`), every other setting at the server's default (the Settings widening, `plan.md:523`).
- **Processes** (`process.ts`): each server is a child process spawned with an argument array (G7), the root's real path as its working directory, stdin and stdout carrying LSP and stderr kept as the server's output (the last 2000 lines, shown by Show Output). One server per page, root and language (Z72 (3) (c)): a page's server stays 60 s after the page's socket closes, and a page that opens the same root and language within those 60 s takes it over (the new page's client sends `didClose` for every document of the old page first, then its own `didOpen`s). A server whose root stops being served is ended at once. The oculus server's close ends every server. Ending is `shutdown`, `exit`, then SIGTERM after 2 s and SIGKILL after 5 s. A server that exits on its own is restarted once on the next request of its page; a second exit within 3 minutes leaves it failed until Restart.
- **The relay** (`relay.ts`): the page talks LSP over its one socket (DESIGN.md:114) on the channel `lsp:<language>`, one per language per page, sent and received as `{ channel, payload }` text frames, accepted only from a socket whose subscription carried the write token, as pty input is (G1). The relay sends each message to that socket alone, in order; nothing is merged or dropped (the Hub's latest-only merge is never used for it). Per page and language it holds one client session and, below it, one server per root that has an open document.
  - It answers the page's `initialize` itself: the capability set of the registry's entry, each kept provider as an options object carrying `documentSelector: [{ language }]` (so `toMonacoLanguageSelector` registers it for that language alone), `textDocumentSync` incremental, and none of what is left to D23b (rename, workspace symbols, call and type hierarchy). It removes `textDocument.diagnostic` from what it tells each server, so pyright pushes (premise 3).
  - It starts a root's server on the first `didOpen` of a document under that root, sending the server its own `initialize` (`processId` the oculus server's, `rootUri` and one `workspaceFolders` entry the root's real path, the client capabilities with `diagnostic` removed and `workspace.didChangeWatchedFiles.dynamicRegistration: true`), queuing the page's messages for that root until `initialized` is sent.
  - It routes each request and notification by the root of its `textDocument.uri`; a request naming no document (workspace symbols, an unknown method) is answered with a method-not-found error.
  - It answers each server's requests itself: `workspace/configuration` from the registry (pyright's `python` section `{ pythonPath }` from the interpreter in force, Z80 (a); every other section null); `client/registerCapability` and `client/unregisterCapability` recorded and answered, the `workspace/didChangeWatchedFiles` ones turned into watchers (below), the rest not forwarded since the page's providers are fixed at its `initialize`; `window/workDoneProgress/create` answered and the progress read for the status item; `workspace/applyEdit` passed to the page, which applies it only when every edit names the document the page asked about (section 3); `workspace/diagnostic/refresh`, `workspace/semanticTokens/refresh` and `workspace/inlayHint/refresh` forwarded to the page.
  - It remaps request ids, so the page's ids and each server's ids never collide, and a server's late answer for a request the page cancelled or whose server ended is dropped.
- **URIs** (`uris.ts`): the page names a document as `oculus-file:///<root key>/<path>`, its path parts percent-encoded; the relay turns it into the `file://` URI of the root's real path and the file's path, and every `file://` URI of a server's message back into the page's form, in the URI-bearing fields only (`textDocument.uri`, `uri` and `targetUri` of locations and location links, `relatedInformation[].location.uri`, `documentChanges[].textDocument.uri` and the keys of `changes`, `rootUri`, `workspaceFolders[].uri`). Paths are compared decoded, NFC-normalised and by real path (premise above: clangd answers both forms). A page URI whose root key is not served, or whose path is absolute, holds `..` after decoding, or leaves the root by a symlink, is refused and nothing reaches a server (G2). A server location outside every served root is dropped from its answer. The page never sends `workspace/didChangeWorkspaceFolders` or a second `initialize`; the relay drops both.
- **Watching** (`watch.ts`): for each server that registered `workspace/didChangeWatchedFiles`, one recursive `fs.watch` of the root's real path (the watchers' pattern, DESIGN.md:116; the library audit kept `fs.watch` over chokidar, `library-audit.md:305`), its events matched against the registered globs with `node:path`'s `matchesGlob` (Node 24, no warning, checked), debounced 200 ms, sent as one `didChangeWatchedFiles` with created, changed and deleted. A document open in a tab is the tab's text, so its own path's events are not sent.
- **Compile databases** (`databases.ts`): the choices for a repository, in the picker's order: the configurations of its `.oculus/cpp.yml` in file order, then the databases oculus finds (`compile_commands.json` at the root, then in each `build/*/`, the folder named `debug` first, then the others newest first by the database's modification time) (Z72 (2) (a), Z92 (2) (a)). The one in force is the reader's remembered choice when it is still a choice, else the first. Oculus links it as `<lsp folder>/<root key>/<database folder>/compile_commands.json` and passes that folder to clangd, so the index is written under the link folder and never into a repository (probe above). A choice changed from the picker restarts that root's clangd.
- **The interpreter** (`interpreter.ts`): pyright's Python for a root: `<root>/.venv/bin/python`, then `<root>/venv/bin/python`, else `python3` from the oculus process's PATH, resolved to its real path; the reader's remembered choice wins while it still exists (Z80 (a)). The picker lists the three found ones and any interpreter the reader typed a path to. A changed choice is sent as `workspace/didChangeConfiguration`.
- **The choices file** (`choices.ts`): the interpreter and compile database per repository under OI-1, written atomically, refused without overwriting when it does not read (G31), every write recorded in the change log as other machine-local writes are.

### 2. `.oculus/cpp.yml` (Z92 (2) (a))

`configurations:` is a list of `{ name, compile_commands, fallback_flags }`, every key optional except `name`, the file optional. `compile_commands` is a folder inside the repository holding a `compile_commands.json`; `fallback_flags` is a list of strings passed to clangd as `fallbackFlags` for a file the database has no entry for. A configuration with no `compile_commands` runs clangd without a database, on its fallback flags. The reader lives in `src/lib/data/sources/config/cpp.ts` (the folder at 9 items); a wrong value is refused with a finding that names the file and key and the entry is skipped (G13), and the findings show in the Findings view as `.oculus/settings.yml`'s do. Nothing else is read from the file: no compiler path, no flags added to a database entry (the ruled text below).

### 3. The page side

- **The Monaco side**: `src/lib/ui/controls/editor/kit/lsp/` (new). `kit/` is at ten items, so `colours.ts` and `theme.ts` move into `kit/theme/` (their only importers are each other and `kit/load.ts`, `grep -rln "kit/colours\|kit/theme\|from './colours'\|from './theme'" src tests`), which leaves `kit/latex/` (D37 writes it) and `kit/rite/` (D11 adds a file to it) in place.
  - One `MonacoLspClient` per language per page, made the first time a model of that language registers and disposed when the page's last model of it goes, on a transport of D23's own (the transport type above) carried over a port the state layer gives (`send(text)`, `listen(fn)`, `state`). The client is never subclassed with field initialisers (its features are made inside the base constructor); `_initPromise` gets a rejection handler through the transport's closed state.
  - The transport owns which models the server sees. A source tab registers its model with `(root, path, language)`; the transport sends its own `didOpen` with the full text and version 1 at registration, numbers every later `didChange` of that document, sends `didClose` at unregistration, and drops every `didOpen`, `didChange` and `didClose` the client's synchroniser sends for any model (the synchroniser opens every model on the page, premise 1). Feature requests from a model that is not registered (a diff side, a merge pane, a peek model, a model of another language) are answered locally with an empty result and never reach the socket. Two tabs of one file are one document to the server: it follows the first registered model, and a request from either is sent for the file; a location in that file is answered in the asking model's URI.
  - A language change of a registered model (from the status bar) unregisters it from the old language and registers it under the new one.
  - Locations in a file no tab holds get a peek model: read through the page's file route, made read-only under its language and the page's URI form, never sent to the server, disposed when the peek or references widget closes. A read that fails or is truncated gives no model, and the location is dropped from the answer. `editor.registerEditorOpener` opens a location's file in a source tab at the line (the same tab when the file is open), so go to definition, a references entry and a link press land in oculus's tabs.
  - Diagnostics: the transport hands each `publishDiagnostics` to the page's diagnostics store (below) and sets markers under one owner per language client (`lsp-python`, `lsp-cpp`), so one client never clears another's (premise 5); a diagnostic for a file no model holds is kept in the store and sets no marker.
  - Code actions and commands: a code action is offered only when its `edit` names only the asking document, or when it carries a command; a `workspace/applyEdit` that names only that document is applied to its model as one undo stop, and any other is refused with `applied: false` and a notice saying the edit reaches other files (D23b applies those through the write chain). A completion's `additionalTextEdits` apply to the open file as Monaco does.

Where clangd's folding provider and `kit/folding.ts`'s brace provider both answer, clangd's ranges are the ones used while clangd serves the model, and the brace ranges while it does not.
- **The state side**: `src/lib/state/system/machine/lsp/` (new): the port over `state/client/socket.svelte.ts` per language (subscribe with the token, send, listen; the client reconnects with the main socket and registers its models again); the server states per root and language for the status items (starting, indexing with its count from `$/progress`, ready, not found, failed with its output); the diagnostics store keyed by root and path, which the Outline reads now and D33's Problems view and the Explorer's decorations read later; the document symbols per open tab (below); the picker lists and the choice asks.

- **The Outline's code symbols** (Z182 (a)): for a served language, `outline.ts` answers the symbols the transport read with its own `textDocument/documentSymbol` request after each change (debounced 300 ms), as a tree with VS Code's symbol kinds and icons (the `symbolIcon.*` colours are in `kit/colours.ts:53-75, 450-485`), each row going to its line, the row under the caret marked when Follow Cursor is on, and a symbol with an error or warning in its range coloured as VS Code's `outline.problems.colors` does. - **Format on save** (Z79 (4) (a)): a field `format_on_save` in a language's record of `editor.languages` (and of a repository's `.oculus/settings.yml`), `false` by default, read by `resolveEditor`. Python has no formatter in pyright, so the key does nothing there and its Settings line says so.

## Cases

Each case is the input, then its expected result. "First run" is the run on the unchanged tree.

### The ruled examples

1. A Python tab in the hub: hover on `catalog` at `tools/present/build.py:24:25` shows its signature; F12 opens `tools/present/deck_config.py` at line 42 in a tab.
2. Shift+F12 on that name lists every use across the root's files in the references widget, each entry opening its file.
3. A type error in an open Python file is marked within 2 s of typing it, and the marker goes when the error is fixed.
4. `lib.py` changed in another tab and saved, and in a terminal outside oculus: `main.py`'s diagnostics follow both (premise 4).
5. A C++ tab of `cathedra/src/monastery/src/mirrors.cpp` with `build/debug` in force: F12 on a function declared in `mirrors.h` and defined in another `.cpp` goes to the definition after the index ends; references across the repository's files.
6. The status bar of that tab: `compile_database` reads `build/debug`; the picker lists cathedra's 13 found databases, `debug` first; choosing `build/release` restarts clangd and the item follows.
7. A repository with `.oculus/cpp.yml` naming two configurations: the picker lists both first, by name, then the found databases; with no remembered choice the first configuration is in force.
8. `.oculus/cpp.yml` with a configuration without `compile_commands` and `fallback_flags: [-std=c99, -Isrc]` on scotoma's `src/dlg.c`: the include of `scotoma.h` resolves; without the file, clangd reports it.
9. `format_on_save: true` for `cpp`: saving a badly indented `.cpp` saves it formatted; `false` saves it as typed; `true` for `python` saves as typed.
10. The Outline on a Python file lists its classes, functions and module variables with their kinds; on a C++ file its namespaces, classes, methods and functions; a press goes to the line; a Markdown file keeps its headings; a YAML file says "No symbols for this file yet.".
11. The breadcrumb of a Python tab with the caret inside a method: root, folders, file, class, method.
12. The interpreter item on a Python tab of a root with no `.venv` or `venv` reads the PATH `python3`'s version; with `<root>/.venv` made it reads `.venv` after a restart; Select Interpreter lists both and the choice survives a reload of the page and of the server.
13. Two pages over the hub, one closed: its pyright is still running 50 s later and ended at 65 s; a page opened at 30 s takes it over (one pyright process, `ps`).

### The implied inputs

14. pyright missing from `node_modules` (renamed away in a scratch copy) or clangd not on PATH: the status item says not found with the program it looked for; no spawn loop; the editor works without the features.
15. A server that crashes at start, and one that crashes after an hour: restarted once on the next request; a second crash in 3 minutes leaves it failed, its output under Show Output; Restart starts it again.
16. A server that never answers `initialize` (a stub that reads and says nothing): after 30 s the state is failed, the process is ended, the page's queued requests are answered with an error and the editor stays responsive.
17. A server slow on one request (a stub delaying 10 s): other requests to it and to other servers are answered meanwhile; a request the page cancels gets no late answer applied.
18. A file outside every served root (a file opened from a path that is no root, if the tab allows it) and a file whose root is removed from the workspace while open: no server is started for it, and the root's server is ended.
19. A root with no compile database and no `.oculus/cpp.yml` (scotoma): clangd runs on its defaults, `compile_database` reads `No compile database`, single-file features work, cross-file references are limited to open files.
20. Two roots, each with Python and C++ files open (the hub and cathedra, ordo and game-engine): four servers, each answering for its own root only; a definition in one root never resolves into another.
21. A huge file: `game-engine/src/engine/tests/src/main.cpp` (158810 bytes) and a Python file of 439320 bytes inside the linfoot venv: served, typing stays responsive (no request is sent per keystroke beyond the debounced ones); a Python file over 2 MiB opens truncated and locked, and no server sees it.
22. A file renamed while open, inside oculus (Files view rename): `didClose` of the old path and `didOpen` of the new; markers and symbols follow. Renamed outside oculus: the server gets the watched-file events, the tab is marked deleted as now, and its document is closed on the server.
23. A model whose path or instance id holds upper-case letters, a file `fig(1).py`, a root folder with a space or parentheses, and a file name that is NFD on disk: hover and locations map back to the tab's own model.
24. A model's language changed from the status bar (python to plaintext, plaintext to python, c to cpp): unregistered and registered again; plaintext gets no server.
25. An empty file and an untitled tab: the empty file is served; the untitled tab, having no root and path, gets no server.
26. A diff side, a merge pane and a peek model of a Python file while pyright runs: nothing reaches the socket for them and no console error.
27. Two tabs of one Python file: one document on the server; hover from either; a definition in the same file opens in the asking tab.
28. The oculus server restarts with tabs open: the page's clients reconnect with the main socket, register their models again, and the servers start again; no two pyrights for one page and root remain after 65 s.
29. A page reload: the old page's servers are taken over by the reloaded page within 60 s; no `didOpen` of an already open document is sent twice.
30. The socket and the relay refuse: a `lsp:` message from a socket without the token; a page URI with root `''`, an unknown root key, an absolute path, `..`, `%2F..%2F`, or a symlink out of the root; a `workspace/didChangeWorkspaceFolders` and a second `initialize` from the page. Each is refused or dropped and nothing reaches a server.
31. In flight, after close, superseded: the socket closes while a spawn is in flight (the process is ended once it exists); a peek read resolves after its widget closed (no model made); an answer arrives for a disposed model (dropped); a model registers while its client's socket is closing (a new client takes it).
32. The close reason of a failed server sent to the page stays under 123 bytes (`ws` 8.21.3 throws above, `node_modules/ws/lib/sender.js:197-198`): the relay sends a short code (`not_found`, `exited`, `refused`, `no_answer`); the words come from `statusbar.yml`.
33. `.oculus/cpp.yml` keys: an empty `name`, two configurations with one name, a `name` equal to a found database's folder (`build/debug`), a `compile_commands` outside the repository or holding no `compile_commands.json`, `fallback_flags` not a list of strings, an unknown key, a file that is not YAML: each is a finding naming the key, and the entry is skipped (G13); the rest of the file is read.
34. The choices file unreadable (not JSON): read as no choices, a choice made is refused with the reason, the file is left as it was (G31).
35. A code action whose edit names another file, and a clangd tweak whose command answers a `workspace/applyEdit` naming a header: refused with the notice; the open file is unchanged.
36. pyright's `workspace/configuration` before any interpreter is chosen, and after the chosen interpreter is deleted from disk: the found interpreter is answered; the remembered choice is dropped from the list.
37. A database link folder whose target was deleted (a `build/debug` removed): the choice falls back to the next found one and the status item says which.
38. clangd's index writes: after the cathedra and game-engine looks, `git status --porcelain` of both repositories is unchanged and nothing new is under `<root>/.cache` (`find <root>/.cache -newer <a stamp file>` prints nothing).

The builder's first task, before any change, is the first run of every case above on the unchanged tree, with each case's result noted.

- A case of a code step becomes a test of the step only when the rules file's test rule calls for a test of it: under G1 (case 30's token), G2 (case 30's paths), G7 (the spawn arguments), G13 (case 33), G31 (case 34), and G36 under OI-4 (cases 13, 15, 16, 28, 29, 31).
- A case kept as a test is run on the unchanged tree first.
- No prototype script stands in for such a test.
- Every other case of a code step is checked by a run the report quotes, and no test is kept for it.
- For each case kept as a test, the report names one small change to the code under test that the case must catch.
- The report quotes the test's failing line with that change made.

When the first run finds a case the brief's own rules get wrong, the builder stops there, before changing any code, and hands back the first run and that case, with the rule and the result it gives. The orchestrator rules on the case and resumes the builder with the ruling, and the final report carries it.

The first proof, before the rest is built: pyright and clangd each serve a hover, a definition and a pushed diagnostic to a Monaco page through `monaco.lsp.MonacoLspClient` over the relay. If that proof fails for a reason the client cannot be made to meet, the builder stops and hands back the evidence; it does not switch to monaco-languageclient (premise 2).

## Decisions taken in this brief (each reversible, none silent)

1. **The wire is the page's one socket**, channels `lsp:<language>`, token-gated like pty input. DESIGN.md:114 names one WebSocket per page; a second socket path would break it. DESIGN.md:114 and :149 are rewritten to name the channel and what it accepts. The lazy option, a second `/lsp` socket with its own hello, was not taken.
2. **One client per language per page, the relay routing by root.** The client registers its providers by language, so one client per root would run every root's provider on every model of the language; one client per language with the relay choosing the root by the document keeps one provider per feature.
3. **The relay answers `initialize` and the servers' registrations itself**, with the registry's fixed capability set per language, so the page's providers never depend on which root's server started first.
4. **The feature split follows Z72 (4) (b1) by what an edit reaches**: a code action, command or completion edit that names only the open document is D23's; one naming any other file is refused here and applied by D23b through the write chain. Rename stays wholly in D23b, as the plan line names it there.
5. **Pull diagnostics are turned off at the relay** (premise 3), so both servers push and one store holds every diagnostic.
6. **Peek models are never opened on the server**: a server's analysis of a file no tab holds comes from disk, and a truncated read or a read before a save would otherwise override it.
7. **Paths are compared by real path, decoded and NFC-normalised**, never by encoded URI strings.
8. **The interpreter reaches pyright through `workspace/configuration`** (probe above), never through an environment variable or a `pyrightconfig.json` written into a repository.
9. **The compile database in force without a remembered choice** is the first of the picker's list, so a `.oculus/cpp.yml` configuration wins over a found database, as its listing first implies.
10. **The Outline's code symbols come from the transport's own `documentSymbol` request**, so the Outline, Go to Symbol, sticky scroll and the breadcrumb read the same answer.
11. **The breadcrumb's symbol segments are built here**: Z47 4 (a) put them "after D23" and no step carries them; they read the same symbols as the Outline.
12. **Folders**: `server/machine/lsp/`, `state/system/machine/lsp/` and `ui/controls/editor/kit/lsp/` are new; `kit/colours.ts` and `kit/theme.ts` move into `kit/theme/`, and `views/sources/source/latex-editor.ts` and `symbols.ts` into `views/sources/source/language/`, because both parents are at ten items. Neither move touches a path a step in flight writes (`kit/latex/` is D37's, `kit/rite/` D11's).
13. **The servers' registry is code**, not a config file: adding a server is a step's work (M8, D43, D34), and no reader edits it.
14. **A server's stderr is kept as its output** (the last 2000 lines), shown by Show Language Server Output (OI-2 (a)'s menu and the palette) in a read-only tab, as VS Code's Output channel of that server shows it.
