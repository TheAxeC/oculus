## What to build

When D23 is done, a Python, C or C++ file opened in a source tab is served by a language server of its root, started by oculus in the background: hover, go to definition, declaration, type definition and implementation, references (the widget and the References view), peek, document highlights, completion, signature help, diagnostics, document symbols, folding (clangd), selection ranges (clangd), inlay hints (clangd), `#include` links (clangd), formatting of the document, a selection and while typing (clangd), the quick fixes whose edit touches only the open file, clangd's inactive regions, its switch between header and source, its AST view and its memory-usage view, and clangd's semantic colouring. The Files Outline lists the file's symbols; the breadcrumb over the tab ends in the symbol path at the caret; the status bar names the server's state, the interpreter and the compile database. A repository's `.oculus/cpp.yml` names compile databases and fallback flags. A key `format_on_save` per language formats on save where a server formats.

### 1. The server side: `src/lib/server/machine/lsp/` (new folder, at most ten items, each file at most 880 lines)

The folder holds `servers.ts`, `process.ts`, `relay.ts`, `wire.ts`, `uris.ts`, `watch.ts`, `choices.ts`, `clangd/` (`databases.ts`, `cpp-file.ts`) and `pyright/` (`interpreter.ts`): nine items.

- **The servers' registry** (`servers.ts`): a table keyed by server, one entry per program: the Monaco language ids it serves, its command and arguments, how its program is found, what it is asked at `initialize`, how `workspace/configuration` is answered, and which capabilities are kept. Two entries: `pyright` serving `python`, and `clangd` serving `c` and `cpp`. M8 (yaml-language-server), D43 (texlab) and D34 (typescript-language-server, svelte-language-server) each add an entry and nothing else, so the table is the one place a server is described.
  - pyright: `process.execPath` with the arguments `[<oculus>/node_modules/pyright/langserver.index.js, --stdio]`, the `pyright` package at 1.1.414 a dependency of oculus (LA16, Z72 (1) (a)); never a global install, a `node` looked up on PATH, or a PATH `pyright`.
  - clangd: `clangd` from the oculus process's PATH, unchanged, with `--header-insertion=never` (Z74 (4) (a)), `--compile-commands-dir=<the link folder>` when a database is chosen, `--background-index`, and no `--query-driver` (Z72 (1) (a)); `initializationOptions.fallbackFlags` from the configuration of `.oculus/cpp.yml` in force (Z92 (2) (a)), each relative path of an include flag resolved against the repository root (section 2).
  - Each server reads its repository's own settings (`.clang-tidy`, `.clangd`, `pyrightconfig.json`, `pyproject.toml`), every other setting at the server's default (the Settings widening, `plan.md:531` (corrected after X3f: `grep -n "Widened 2026-10-01 by the Settings ruling" plan.md` lists 533 among its lines, the one under D23's line at 532)).
- **Processes** (`process.ts`): each server is a child process made by a `spawn` function the context passes in (no module-level state; the G36 test passes a stub), with an argument array (G7), the root's real path as its working directory, stdin and stdout carrying LSP and stderr kept as the server's output (the last 2000 lines, shown by Show Language Server Output). One server per page, root and registry entry (Z72 (3) (c)): one clangd per page and root serves both the `c` and the `cpp` tabs of that root. A server ends (Z482, G36):
  - 60 s after the last tab of its root and languages closes on its page, unless a tab of them opens on that page inside the 60 s, which keeps it;
  - 60 s after its page's socket closes, unless a page opens the same root and language inside the 60 s and takes it over (the new page's client sends `didClose` for every document of the old page first, then its own `didOpen`s);
  - at once when its root stops being served;
  - with the oculus server's close.
  - Ending is `shutdown`, `exit`, then SIGTERM 2 s after `exit` and SIGKILL 5 s after it. A server that exits on its own is restarted once on the next request of its page; a second exit within 3 minutes leaves it failed until Restart. A server that answers no `initialize` within 30 s is ended and failed with the code `no_answer`.
- **The relay** (`relay.ts`) and **the wire** (`wire.ts`): the page talks LSP over its one socket (DESIGN.md:114) on the channel `lsp:<language>`, one per language per page, each frame `{ channel, payload }` text, accepted only from a socket whose subscription carried the write token (G1, the gate below). `payload` is a JSON-RPC message, or one of the oculus messages `wire.ts` types (UV-2): page to server `{ oculus: 'restart', root }`, `{ oculus: 'output', root }`, `{ oculus: 'output_off', root }`, `{ oculus: 'choices', root }`, `{ oculus: 'choose', root, interpreter? , database? }`; server to page `{ oculus: 'state', root, state, done?, total?, code?, program? }` with `state` one of `starting`, `indexing`, `ready`, `not_found`, `failed` and `code` one of `not_found`, `exited`, `refused`, `no_answer`, `lsp_folder`, `{ oculus: 'output', root, lines, append }`, `{ oculus: 'choices', root, interpreters, interpreter, databases, database, findings }` and `{ oculus: 'refused', root, code }` with `code` one of `choices_unread`, `choices_write`. The relay sends each message to that socket alone, in order; nothing is merged or dropped (the Hub's latest-only merge is never used for it). A failed server is an `oculus: 'state'` message on its channel; the page's socket stays open. Per page it holds one client session per language and, below them, one server per root and registry entry, shared by the sessions of the languages that entry serves; a server message about a document goes to the channel of the language the document was opened under.

## Decisions taken in this brief (each reversible, none silent)

1. **The wire is the page's one socket**, channels `lsp:<language>`, token-gated like pty input. DESIGN.md:114 names one WebSocket per page; a second socket path would break it. DESIGN.md:114 and :149 are rewritten to name the channel and what it accepts. The lazy option, a second `/lsp` socket with its own hello, is not taken.
2. **One client per language per page, the relay routing by root.** The client registers its providers by language, so one client per root would run every root's provider on every model of the language; one client per language with the relay choosing the root by the document keeps one provider per feature.
3. **The relay answers `initialize` and the servers' registrations itself**, with the registry's fixed capability set per language, so the page's providers never depend on which root's server started first.
4. **The feature split follows Z72 (4) (b1) by what an edit reaches**: a code action, command or completion edit that names only the open document is D23's; one naming any other file is refused here and applied by D23b through the write chain. Rename stays wholly in D23b, as the plan line names it there. The References view and clangd's AST and memory-usage views edit nothing and are D23's (Z483).

6. **Peek models are never opened on the server**: a server's analysis of a file no tab holds comes from disk, and a truncated read or a read before a save would otherwise override it.
7. **Paths are compared by real path, decoded and NFC-normalised**, never by encoded URI strings; a document belongs to its innermost served root.
8. **The interpreter reaches pyright through `workspace/configuration`** (probe above), never through an environment variable or a `pyrightconfig.json` written into a repository.
