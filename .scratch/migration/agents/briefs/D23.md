## What to build

## Decisions taken in this brief (each reversible, none silent)

1. **The wire is the page's one socket**, channels `lsp:<language>`, token-gated like pty input. DESIGN.md:114 names one WebSocket per page; a second socket path would break it. DESIGN.md:114 and :149 are rewritten to name the channel and what it accepts. The lazy option, a second `/lsp` socket with its own hello, is not taken. (corrected after D44, O30, A3 and E4: the two lines are DESIGN.md:116 and :154, `grep -n "^\*\*The socket\.\*\*\|^\*\*Auth\.\*\*" DESIGN.md` printing 116 and 154)
2. **One client per language per page, the relay routing by root.** The client registers its providers by language, so one client per root would run every root's provider on every model of the language; one client per language with the relay choosing the root by the document keeps one provider per feature.
3. **The relay answers `initialize` and the servers' registrations itself**, with the registry's fixed capability set per language, so the page's providers never depend on which root's server started first.
4. **The feature split follows Z72 (4) (b1) by what an edit reaches**: a code action, command or completion edit that names only the open document is D23's; one naming any other file is refused here and applied by D23b through the write chain. Rename stays wholly in D23b, as the plan line names it there. The References view and clangd's AST and memory-usage views edit nothing and are D23's (Z483).
5. **Pull diagnostics are turned off at the relay** (premise 3), so both servers push and one store holds every diagnostic; the transport keeps `publishDiagnostics` from the client and sets the markers itself (premise 4).
6. **Peek models are never opened on the server**: a server's analysis of a file no tab holds comes from disk, and a truncated read or a read before a save would otherwise override it.
7. **Paths are compared by real path, decoded and NFC-normalised**, never by encoded URI strings; a document belongs to its innermost served root.
