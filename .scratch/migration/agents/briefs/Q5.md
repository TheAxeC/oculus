Read `../spec.md` first; it governs this package unchanged. Axel decided on 2026-09-12 (option A of the state file's note): a control that opens a session view or the Terminal view pinned to one session or terminal, so pinned panes sit side by side while the unpinned ones keep following the workbench's selection, and tab labels that name the session a pinned tab shows. ## What to build

1. **One home for a pin: the layout instance's state.** A pinned view is opened with `openView(view, where, { session: <id>, label: <words> })`: the `session` makes the instance its own tab (a second pin to another session is another tab, one pin per session per view since `stateId` matches the existing one), the `label` names the tab. `sessionFor(instanceId)` and the Terminal view read the pin from the layout instance's state (a small layout selector giving an instance's state by id, or the view passing `instance.state`), the ui-store read kept only if the worker finds something writing a pin there (say so). The unpinned instance of a view keeps following the selection as now.
2. **The control.** A session row's menu in the sessions list gains "Open in its own pane" (a new `sessions.open_pinned` key with a tooltip key, named here), opening the Session detail pinned to that session in the main area with the session's title as the tab label; a terminal row gains the same for the Terminal view, the tab labelled with the terminal's name. A pinned Session detail's toolbar offers the other four views for the same session (Transcript, Timeline, Changes, Agents), each opening pinned and labelled, the way its toolbar offers the resume today (read `SessionDetail.svelte` for the toolbar's shape).
3. **Pin and unpin in place.** Every session view and the Terminal view carry a pin toggle in their pane toolbar (`sessions.pin_pane` and `sessions.unpin_pane`, new keys with tooltips): pinning writes the session (or terminal) the view shows now, and the label, into the instance's layout state through a layout store call that restates one instance (`state/layout.svelte.ts` has `restate` for an existing instance; expose what is needed, no more); unpinning clears both, and the tab goes back to the view's name and the selection.
4. **The labelled tab.** A pinned tab reads "Detail: <title>" only if the catalog has such a form; otherwise the label is the session's title or the terminal's name alone, and the view's name stays in the tooltip. No new mechanism: the `label` rule of `PaneView.svelte` is the one used.

## Decisions taken in this brief (each reversible, none silent)

1. The pin is layout state, as above; a reveal stays ui state (O25f), the two being different things: a pin is a tab's identity, a reveal is a one-shot.
2. Four new text keys in `config/text.yml`'s `sessions` group (`open_pinned`, `open_pinned_tip`, `pin_pane`, `unpin_pane`); the file is at 977 lines.
3. The session group arrangement (all five views pinned to one session at once) is not built here; it is a saved arrangement applied with a session, a later package if Axel wants it.
