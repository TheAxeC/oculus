# Brief: Q4b, the views: one type scale, the terminal's size control, the folded groups' look, the cards' surface, the intro block

Read `../spec.md` first; it governs this package unchanged. Five items Axel raised on 2026-09-12 after using the O25 landings, all in the views and the primitives; each is a user-visible shape and is checked in Chrome on the TEST page at landing.

## What to build

1. **One type scale across the views.** The views set `font-size` 150 times, 67 of them `--fs-xs` (10.5 px) and 62 `--fs-sm` (11.5 px), 11 `--fs-md` (12.5 px), a few `--fs-xxs` and `--fs-3xs`, so a card's note reads at 10.5 px in one view and 12.5 px in the next (Axel: "some font sizes seem weird, overall, Live HPC, Position Leads, others"). The cockpit set its body at `--fs-md` and its tabs at `--fs-sm` (`tools/cockpit/assets/css/08-themes.css` lines 217 and 231). The rule, applied to every file under `views/` and the partials: a view's prose (an intro, a card's body, a note, a description, a list line) is `--fs-md`; a card's sub line, a meta row, a table cell and a chip's words are `--fs-sm`; a chip inside a meta row, a badge, a counter and a timestamp are `--fs-xs`; `--fs-xxs` and `--fs-3xs` are for the rail's group labels and nothing in a view; headings keep their levels. The pass changes the rules in place, one file at a time, and the report lists every file with the count of rules changed. No token value changes. A view test that asserts a size follows.

2. **The terminal's size control.** `views/sessions/Terminal.svelte` reads the grid's size from `terminalFontPx()` (config, `terminal.font_px`, 12.5 today) and Axel finds it still too large. The pane's toolbar gains three compact controls, smaller, larger and reset (glyphs from the catalog, the words in tooltips, three new `sessions.*` keys in `config/text.yml`, which is at 977 lines), stepping by 1 px between 6 and 40; the chosen size is saved in the ui store's appearance (`state/ui.svelte.ts`, beside `theme`, `crt`, `wallpaper`, `unicode`: a `terminalFont: number | null`, null meaning the config's default), applied live to every mounted grid (`grid.options.fontSize`, then the fit and the resize the theme switch already does at lines 245 to 255) and on the next mount. Tests: `tests/state/ui.test.ts` (the field saved and bounded), `tests/views/sessions.test.ts` (the three controls in the toolbar).

3. **The folded cross-link groups look like groups.** `views/shared/CrossLinks.svelte` draws each group as a `ToolButton` reading "1 manuscript" (lines 28 to 36), which is the look of an action button, so five groups on a card read as five buttons (Axel). The control becomes a disclosure chip: the count strong, the type after it, a small disclosure glyph (the catalog's `disclosure` or the `chevron` glyph, whichever `glyphs.yml` has; add none) turning when open, on the `Chip` surface (`ui/Chip.svelte`: the pill, `--chip` background, `--fs-xs`) rather than the `ToolButton` box; a new primitive `ui/Disclosure.svelte` if `Chip` cannot be a button without losing its tests, with `aria-expanded`. The five view tests that assert the group control follow.

4. **A card stands off its pane.** `ui/Card.svelte` paints `--panel` (line 85) and `ui/Pane.svelte`'s body paints `--panel` too (line 43), so a Pillars card (`views/programs/LineCard.svelte`) and a Domains card (`views/domains/DomainCard.svelte`) sit flat on the same white (Axel: "not distinctive enough, same background colour"); the boards' cards read as cards because they carry a tone bar. Add a `--card` token to `themes/tokens.css` (and every theme block of `themes/themes.css` that sets `--panel`, one shade off it, checked by the contrast test) and paint the card's background from it; the Pillars card takes its pillar's `arch_color` as its tone bar and the Domains card its domain's colour (both in `config/vocab.yml`; read how `ProjectCard` passes a tone), so those two views read as the boards do. Tests: `tests/ui/colours.test.ts` (the token in every theme), `tests/views/programs.test.ts` and `domains.test.ts` (the tone on the card).

5. **The intro block.** Six views draw `<p class="intro">` (Radar, Collection, Programs, Leads, Domains, Data) and the feed views of O25d and O25e draw their meta lines, each with its own rule, so the line "Academic openings - auto-scouted (BE/NL/LU). 1 live | 32 expired (hidden) | ..." floats under the title (Axel: "just floating, not like the cockpit"). The cockpit's intro is a bordered muted block under the tab title (its `.intro` rule in `tools/cockpit/assets/css/`, find it with `grep -rn '\.intro' tools/cockpit/assets/css`). A shared partial `views/shared/Intro.svelte` draws that block (the muted surface `--chip`, a left rule in the accent, `--fs-md`, the catalog's HTML through `{@html}` since the intros carry `<b>` and `<code>`), and every view that has an intro or a meta line uses it. Tests: `tests/views/intro.test.ts` (the partial), the view tests asserting the block's class.
