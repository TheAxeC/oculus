## Decisions taken in this brief (each reversible, none silent)

1. The text form is one word, not words joined by spaces (item 1), since that is how the value rule reads a `multi` that is not `joined`; the step line says so.
2. The text form is held by `enum` of the words, not by a pattern of the escaped words: for one text the two admit the same values, and `enum` gives the editor's word-list message and completion.
3. The text branch comes first in `anyOf` (form B): with the list first the editor's message for a wrong one-text word says the value must be a list, which the rule does not say.
4. A `joined` multi gets no rule over its text: its one field draws from a source the schema never holds, so it would be code for an input that does not happen.
5. The list of lists in a `holds: lists` family stays as it is, named in the head comment: it is the family wrapper's concern, not the text form of a `multi`.
