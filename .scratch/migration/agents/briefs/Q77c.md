## What to build

1. **The new form.** A directive names its target by the text of the target line:

   ```
   // revert: <path> "<the line's whole text, indentation trimmed>" [+<n>] [.. "<last line's text>" [+<n>]] => <replacement>
   ```

   The quoted text is a JSON string literal, so a line holding quotes, `=>` or backticks is written with JSON escapes. It names the one line of the target file whose trimmed text EQUALS it. `+<n>` counts down from that line to the target, and is used only when the target line's own text is not unique in its file: then the anchor is the nearest line above whose trimmed text is unique. A range names its first and last line, each by the same rule. `DIRECTIVE` and `directives()` read this form and resolve it to the same `first` and `last` line numbers the rest of `revert-check.mjs` uses today, so nothing below `directives()` changes. The old `<path>:<line>` form is no longer read: a line holding it is printed as `unproven ... names a line number; convert it` and the run fails.
2. **Resolution failures are unproven, never a guess.** An anchor that matches no line, or more than one, makes that directive `unproven` with the count it found. An offset that runs past the end of the file is `unproven`.
3. **The converter.** `bin/migrations/revert-anchors.mjs` rewrites every old-form directive under `tests/` to the new form, computing each anchor by the rule of item 1 from the line the old number names on the tree as it stands. Before writing a file it proves, for every directive it rewrote, that the new anchor resolves (by the resolver of item 1, imported from `bin/revert-check.mjs`, not a copy) to exactly the line or range the old number named; a directive that fails the proof is left in the old form and printed as `refused`. It prints `<n> directives converted in <m> files written, <r> refused`. With `--check` it writes nothing and prints the same count for what it would do. Run it once over the whole tree.
4. **Head comment.** The head comment of `bin/revert-check.mjs` states the new form, the uniqueness rule, the offset, the range, and that the old form is refused.
5. **Tests.** `tests/checks/bin/revert-check.test.ts` covers: an anchor resolving to its line; an anchor matching none and one matching two, each unproven with its count; an offset; a range; an old-form directive refused; a target line deleted, so the anchor matches nothing and the directive is unproven, never another line. `tests/checks/bin/revert-anchors.test.ts` covers the converter on a scratch tree: a unique line, a repeated line (offset), a range, a line with quotes, and a directive whose proof fails being left as it was and counted as refused. Each new case carries a revert directive in the new form.

## Decisions taken in this brief (each reversible, none silent)

1. The anchor is the whole trimmed line and matching is equality, so a changed target line makes the directive unproven instead of silently matching a similar line.
2. The old form is refused after the conversion rather than read alongside, so one form exists in the tree.
3. The converter stays in `bin/migrations/` with its test, as the other migrations there do.
