## What to build

1. **The message box only under an agent.** `SteerBox` is drawn under the grid only when the terminal's `kind` is `claude` or `codex`. Under a shell the grid takes the whole height. The "selected elsewhere" case (an agent session running outside oculus) keeps its sentence and its disabled box.
2. **The list of terminals** replaces `TerminalPicker` (the file is deleted, with the `sessions.pick_terminal` and `pick_terminal_tip` words). A new `src/lib/views/sessions/terminal/TerminalList.svelte`, drawn on the right of the view's body when two or more terminals exist (VS Code's `tabs.hideCondition` singleTerminal and `tabs.location` right), whatever the tab shows (a grid or the composer). Its width is fixed at a sensible narrow column and the grid takes the rest.
   - One row per terminal of `terminalChoices` (foreign ones left out, as today), in the order the terminals were started, or in the reader's order once dragged (item 6).
   - A row: the kind glyph; the title; the description, muted, after the title, cut with an ellipsis; the row of the terminal this tab shows marked as the current one. The title is named after what runs: an agent terminal is "Claude" or "Codex", and a shell is its `command` ("zsh", "vim", "npm"), or "shell" when tmux reports none. The description is the session's title for an agent terminal (the label `terminalChoices` gives today) and the last segment of `cwd` for a shell. The row's tooltip holds the terminal's name, command, folder and start time.
   - A press on a row shows that terminal in this tab, by the picker's rule (item 2 of the tree): `select` in a following tab, `pinInstance` in a pinned one.
   - The list is one keyboard stop; the arrow keys move between rows and Enter shows the row, as the tree's roving rule does (`ui/tree/roving.ts`).
   - On hover or focus a row shows two controls: Split, and Kill. Split opens a Terminal tab beside (`openBeside('terminal', ...)`) holding the composer with the row's folder and kind chosen. Kill arms on the first press and stops the terminal on the second (`stopTerminal`), as the Sessions list's stop does.
   - A bell (xterm's `onBell`) in a terminal this tab shows marks its row with the `bell` glyph for one second (VS Code's `bellDuration` default); a terminal no tab shows has no grid in the page and so no bell.
3. **One terminal:** with fewer than two terminals no list is drawn, and the toolbar shows the shown terminal's title and description in place of the picker (VS Code's `tabs.showActiveTerminal` singleTerminal).
4. **Multi-line paste:** a paste into the grid of text holding a line break is held, and `Confirm` asks whether to paste its N lines into the terminal; yes pastes it (`term.paste`), no drops it. A one-line paste goes through as today.
5. **A file dropped on the grid** from the Files view (`FILE_DRAG`) types its absolute path into the terminal, quoted for the shell (wrapped in single quotes, each single quote written as `'\''`), followed by a space and no Enter.
6. **Reorder:** a row dragged within the list moves there; the order is kept in the reader's layout state for the page, so it survives a reload, and a terminal missing from the stored order goes last in start order.
7. The words: every new label, tooltip and question in `config/text/views/sessions/terminal.yml`, the removed ones taken out of `session-list.yml`; `HELP.md:123` and any sentence of `HELP.md` or `DESIGN.md` the change makes false are corrected (grep `pick_terminal`, `TerminalPicker`, `steer box`, `Pick a terminal`).

## Decisions taken in this brief (each reversible, none silent)

1. An agent terminal is titled by its agent ("Claude", "Codex") and a shell by its running command, since `${process}` for an agent may read `node` (not verified) and would say nothing; the session title is the agent row's description. On the rows of the cases: Claude / "Fix the parser"; vim / "oculus"; shell with no command / "shell".
2. The bell shows only for a terminal a tab on the page is drawing, since only a drawn terminal has its bytes in the page.
3. Split opens the composer beside with the row's folder and kind chosen, rather than starting a terminal at once, since an agent terminal needs its account and pickers.
4. The reader's row order lives in the page's layout state, like the tabs' order, and not in any config file.
