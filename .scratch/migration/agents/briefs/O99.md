## What to build

The step is one part with eight items. Each is judged by what a reader can do in the running oculus.

1. **Scopes (rulings 519, 521, O99 scopes).** Settings gets a scope picker in its header with the scopes Workspace, Primary hub, Hub, This machine and Repository. Beside it, Hub and This machine pick one of the workspace's hubs (the primary included) and Repository one of its repositories; every row on screen then reads and writes the file of the scope picked: the open workspace file's `settings:`, the primary hub's `.oculus/config.yml`, the picked hub's `.oculus/config.yml`, the picked hub's `.oculus/local.yml`, and the picked repository's `.oculus/settings.yml`. Each scope shows its own keys in today's groups; a key that scope cannot take is not drawn there. The per-row hub pick goes. The scopes follow the workspace live: a change in the Workspace scope that changes the primary, a folder added or removed and a hub made redraw the scopes and their pickers, and the Primary hub scope then shows the new primary's values. A scope whose file does not exist makes it at the first change; in the unsaved workspace the first change in the Workspace scope asks for a name and saves the workspace as Save Workspace As does, then writes the setting there.
2. **Saves (rulings 520, 522).** Each scope keeps its own unsaved changes with its own Save; Cmd+S (Ctrl+S off macOS) saves the scope on screen. A Save All button in the header and the File menu's Save All write every changed setting in every scope. Each file a save touches gets one write in History, which undoes it. A value written as it is changed today (a toggle, a pick) becomes a change of its scope, saved by Save. Save All is the existing File menu row and word (`desktop.menu.save_all`), its answer reaching Settings' scopes as it reaches the source tabs. With the unsaved workspace among the changed scopes, Save All asks the workspace's name first. Two scopes that write one file (Primary hub, and Hub with the primary picked) hold one set of changes for that file, so a save writes it once. A save whose file changed on disk since it was read is refused with the file named, and the scope keeps its changes. A change made for one file stays with that file when the primary changes or the hub leaves the workspace; a hub that leaves the workspace with changes held is said, and nothing is written to it.
3. **A control for every setting (ruling 519).** No row of Settings opens a user's file to edit it as text: `EditLink.svelte` is removed with its words, and so are the per-row file-and-line link (`settings/Item.svelte:355-366`), the link of `editors/Origins.svelte:30` that opens `.oculus/settings.yml` for `editor.languages`, and the lines under a group heading that open the user's file. Show Defaults and the Catalogs, Schemas and Texts rows stay: they show oculus's own files read-only and edit nothing (decision 5). Every option of `config/options/*.yml`, `config/options/catalogs/*.yml` and `config/options/schemas/*.yml`, every key of `LOCAL_KEYS`, `workbench`, every `latex_editing` section and a list, multi or family with no value in force has a control in its scope; a list with no value draws its editor empty, with Add. A value whose shape the editor does not draw is a finding of the file naming the key and the shape, never a link to the file. A raw text box holding a list, a record or a family as YAML is not a control. A `secret` field is a password box: it shows "set" or "not set", never the value; a new value replaces it, a box left empty keeps the stored secret, and clearing it is its own action. No route answer, channel push, History record or log holds a secret's value: History records that the field was set, and its undo is not offered for that field. A scope file that does not parse says so in its scope with the finding's line, and the scope writes nothing to it. `port` is drawn only in the This machine scope of the primary hub.
4. **The reader rows' nested values (ruling 526 (a)).** A field record in the options catalog may refer to a description by name, so the record of a reader row is described once in `config/options/behavior.yml` and its five places name it, and a field's `else` and `each` and a step's `then` are drawn as nested cards at any depth. The eleven values of O97's report get controls, and so does every value of every row oculus ships under item 7; none is kept as text.
5. **Forms for the files that are no setting (ruling 519).** In the Debug view, each configuration of `.oculus/launch.yml` is edited and deleted, its fields those its debugger's schema gives. On the compile database item, `.oculus/cpp.yml` is edited in a form opened from the item's choices, its fields from `config/schemas/cpp-schema.yml`. In the Slides view, every key `config/schemas/deck-schema.yml` describes for a deck has a control. A data file at the finding `key_none`, `key_two`, `key_beside` or `key_missing` offers there the choice of the field that is its primary key, written as `primary_key: true` on that field alone and the other marks taken away; a list or map field is not offered. The workspace file's `primary` and each folder's `name` are set in the Workspace scope of Settings; a renamed folder that is the primary carries `primary` with it, and an empty, invalid or taken name is refused, naming it. No file of these is edited only as text.
6. **The line counts table (ruling 519).** The top two rows of the Status view's line counts no longer overlap, at every pane width the view is drawn at.
7. **The generic service rows ship in oculus (rulings 537, 541).** `config/defaults/behavior.yml` ships the rows the hub holds today for `literature.sources`, `recover.sources`, `links`, `sign_in` and `connections.failures`, and `recover.node_download` (`https://nodejs.org/dist/`), `clusters.key_type` (`ed25519`) and `clusters.key_file` (`~/.ssh/id_{type}_{resource}`). Each of the five lists is laid over oculus's by the field that tells its rows apart (`key` for the reader lists, `links` and `sign_in`, `kind` for `connections.failures`), with the vocabulary merge's rules: a hub adds a row, changes one, or removes one with `{ <field>: x, removed: true }`, and two rows naming one value apply neither, a finding, oculus's row standing. A hub that sets nothing gets oculus's rows. A changed row keeps its place; a hub's new `connections.failures` row goes before oculus's, so a hub's own error text is matched first (decision 8), and a new row of any other list goes after oculus's. The shipped `literature.sources` are tried in oculus's order where `literature.prefer` names none. The sentences saying oculus ships none, or stating it in other words, are corrected everywhere they stand: `config/defaults/behavior.yml` lines 79, 84, 88, 91, 251 and 268, `src/lib/data/sources/config/settings/rows/read.ts:5`, `config/options/behavior.yml` lines 204, 211, 216, 238, 306, 772, 1194 and 1681 ("Empty makes no key", "Empty tells no failure apart", "Empty downloads nothing", "With none, the search says no source is configured", and each "This is a setting of the hub"), the `HUB_LIST` comment of `src/lib/data/helpers/hub-names.ts:680-697`, `src/lib/views/personal/account-setup/ClusterSteps.svelte:3`, `config/text/views/personal/account-setup.yml:128-129` and `config/text/views/sources/data.yml:72`. The sentences that stay true (`catalogs.ts:94`, `catalog-files/vocab.ts:6`, `in-place.ts:77`, `config/options/catalogs/vocab.yml:357`) are left alone. The tests that expect empty defaults expect the shipped rows: G136's 'case 15: a primary hub with no literature.sources' (`tests/server/core/reader/reader.test.ts:168`) and the `neither` row of `tests/data/hubs/connection-keys.test.ts:45` among them. The hub keeps only what is its own (`venues.browser`, its clusters' own rows); the deletion of its copies is the "Hub text" of the report, applied at landing.
8. **New views on saved pages (ruling 538).** `venues-browser` is a pinned tab after `venues` in the `registries` arrangement. A rail page records the views it was given, as it records documents, so a view newly added to its shipped arrangement is given to a saved page once, pinned with the pane's pinned tabs, and a tab of it the reader closes is not given again. A page saved with no record is given the views of its arrangement it lacks, once, as a page with no document record is given every document of its group (decision 7). A view given to a rearranged page goes into the pane that holds the arrangement's tab before it, or the page's first pane when none does. An empty or repeated entry of the record is ignored.

The constraints on every file: a folder at its ten-item limit takes a new subfolder for what is added; the size limits of the rules file (880 lines for a source file, 520 for a component; Settings.svelte stands at 517, so its parts move into `settings/`), at most ten items in a folder, words through `t()` from `config/text/`, no history in comments, and the layer rules of `spec.md`.

## Decisions taken in this brief (each reversible, none silent)

1. The nested values are drawn by a catalog reference (option (A) of O97's report): one key by which a field record names a described record, read by the catalog reader, `config-fit.ts` and the card renderer, with a guard against a record naming itself in a loop. Option (B), the nesting written out to a fixed depth, keeps values kept again one level down; (C) is the lazy option.
2. A value written as it is changed today becomes an unsaved change of its scope, so that rulings 520 and 522's saves hold for every row; nothing in Settings writes without a save.
3. A removal of a shipped row by a hub uses the vocabulary merge's shape `{ <field>: x, removed: true }` (`merge/in-place.ts:9,36`); no second shape is added.
4. Repository scope lists every folder of the workspace that is a git repository holding or able to hold `.oculus/settings.yml`, the hubs included, and draws the `editor:` block.
5. "The folder-file lines" of ruling 519 are read as the lines that open a user's file to edit it. Show Defaults and the Catalogs, Schemas and Texts rows only show oculus's own files read-only, so they stay.
6. The saved record of the views a rail page was given is the key `views` of a page in the saved layout, beside `docs`, a list of view ids; a key in a saved record under `~/.oculus` is a user-visible shape (`spec.md:18`), named here for Axel to reverse.
7. A page saved with no view record is given every view of its arrangement it lacks, once, which gives back a shipped tab the reader had closed before this change. This is the rule a page with no document record already follows, which ruling 538 names ("as a hub document already is").
8. `kind` is the field that tells `connections.failures` rows apart, since the hub's six rows carry six kinds and `match` repeats; a hub's new failure row goes before oculus's, so a hub's own error text is matched first.
