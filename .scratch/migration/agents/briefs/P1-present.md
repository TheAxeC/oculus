## What is on the tree (written 2026-09-15 at 14:35 against 57e15794; re-read at dispatch, 14:42: unchanged)

## The shapes, ruled by Axel on 2026-09-15 at 14:42 (yes to each)

1. **Several slides per project.** The `present:` front matter stays one slide, its id the project's id. More slides are a `slides:` list in the same front matter, each entry the same fields as `present:` plus `id: <slug>`, the slide's id being `<project>/<slug>`; `present:` and `slides:` may both be present, and the order within the project is the list's. 
2. **The deck in `config/present.yml`**, an oculus config file with the shape of `tools/present/content/present.yml` (`meta`, `themes`, `order`, `framing`, `summaries`, `ideas`, `selection`, `slide_order`), read by the config loader and pushed like every config file; `tools/present/content/present.yml` stays the cockpit tool's own until the tool is retired. The `order` entries name project slides by their id (`ref: hccnet-revision` or `ref: hccnet-revision/data`).
3. **The view.** `present` is a listed view in the Academic life group of the rail, drawing the deck as one pane: the current slide full-size, left/right keys and the on-screen controls to move, `O` for the overview grid, the six kinds as components under `views/present/` (`Title`, `Framing`, `Project`, `Summary`, `Ideas`, `Closing`), the theme colour by the project's domain through `themes`; the slide reached from a project card (P2) is the instance state's `slide`.
4. **LaTeX in the page: KaTeX** (`katex`, MIT, the one new dependency), rendering an `equation:` written as LaTeX text (`equation: "\\min_{...}"`) in the slide; an `equation:` naming a PNG keeps working through the file route until the seventeen files are rewritten (a later inline change, not this package). KaTeX's CSS and fonts are served from the package by the build.
5. **Figures through the file route**: `figure: foo.png` resolves to `api/file/hub/<project>/present/foo.png`; `diagram_html` panels are drawn through the sanitiser (`ui/html.ts`), which is what every html field already passes.

## What to build

1. **Data.** `src/lib/data/sources/present.ts` reads each project's `PRESENT.md` front matter into `Project.present: PresentSlide[]` (id, the fields above, the body markdown) with findings for a slide whose `id` repeats or whose `figure` names no file under `present/`; the snapshot carries them; `config/present.yml` is read by `loadConfig` as `deck` with its own checks (an `order` entry naming an unknown slide is a finding).
2. **State.** `state/present.svelte.ts` (`createPresent(entities)`): the deck's slide list in order (the deck-level slides from the config, the project slides from the snapshot, selection applied), `current`, `next`/`previous`, `overview` on and off, `goTo(id)`.
3. **The view** as shape 3, with the keys through the pane's own key handling (the shell's digit and chord keys stay the shell's), the overview grid, and the theme colours as CSS custom properties from `themes`.
4. **Words** in `config/text/views/present.yml`; DESIGN.md's views list and a dated decision line; tests: the reader (front matter, several slides, findings), the deck order and selection, the view rendered with `svelte/server` for each of the six kinds, a browser case opening the view and moving one slide; the registry test.
