## What to build

1. **Every terminal oculus starts has a UTF-8 locale.** Each start (`startTerminal`) carries its locale as `-e` pairs beside `GRID_ENV`.
   - The locale of an environment is the first of `LC_ALL`, `LC_CTYPE` and `LANG` that is set and not empty, as the C library reads it. It is UTF-8 when its value names UTF-8, in either case, with or without the hyphen (`en_US.UTF-8`, `C.utf8`, macOS's `LC_CTYPE=UTF-8`).
   - When oculus's own process has a UTF-8 locale, the start carries each of the three variables that is set and not empty in the process, with its value. When it has none, the start carries `LANG=en_US.UTF-8` on macOS and `LANG=C.UTF-8` on every other platform, and an empty `LC_ALL` or `LC_CTYPE` for each of those two that is set and not empty in the process, so the pane's locale is the `LANG` given.
   - The choice is one pure function of an environment and a platform, so a test holds each branch on any machine; `startTerminal` reads `process.env` and the running platform through it. It is a new file of `src/lib/data/places/` (`sessions.ts` has 43 lines left to the 880).
   - The variables a request, a task or an app sets for itself are unaffected: none of them is one of the three today, and a later pair of the same name wins in tmux.
   - The session a usage refresh reads takes no pair.
   - The head comment and `startTerminal`'s comment say it. `docs/HELP.md` is not written; the report names line 258.
2. **The terminal has sixteen colours of its own.** Sixteen tokens, `--ansi-black`, `--ansi-red`, `--ansi-green`, `--ansi-yellow`, `--ansi-blue`, `--ansi-magenta`, `--ansi-cyan`, `--ansi-white` and the same eight as `--ansi-bright-<name>`, are the theme's terminal colours, and `gridLook` fills xterm's sixteen slots from them alone. Nothing else reads them.
   - Oculus Light (`:root`) holds the light column of the table, Oculus Dark (`body.dark`) the dark column.
   - A VS Code block and an app's converted theme hold the theme's own `terminal.ansi*` key where it is a visible colour, else the registered default of the theme's type, written exactly (composited over the panel only when it has an alpha, as every mapped colour is), never nudged.    - Each rice block holds the sixteen of its published palette: mocha, macchiato, frappe, latte, gruvbox (dark hard), gruvboxlight (light hard), nord, rosepine, rosepinemoon, rosepinedawn, everforest, everforestlight, dracula, kanagawa (wave), kanagawadragon, kanagawalotus and solarized (solarized-dark) from the theme file of that name in `@shikijs/themes`, and those of "Palettes given here" below.    - The colour a terminal is marked with, its menu, and an app's file decorations stay on the interface hues: `COLOR_TOKENS` and `colorToken` keep their meaning, and the grid no longer reads them. `colorToken` is then used by its own module alone and is no longer exported.

## Decisions taken in this brief (each reversible, none silent)

1. The locale goes with every start, oculus's own when it is UTF-8, since a tmux session takes none from the process that starts it. A process under a locale that is not UTF-8, an explicit `LC_ALL=C` included, gives its terminals the default.
2. The tokens are named `--ansi-*` and not `--c-*`, so no derived token, lane or contrast pair is minted for them.
3. A non-hex or transparent key of a theme file takes the registered default, the rule `pick` already has for the other tokens.
4. A family's palette is that of its VS Code theme file where `@shikijs/themes` holds it, else the project's own file; Flexoki's is its kitty file, which gives sixteen distinct slots where its Alacritty file repeats black and white.
5. The terminal colours of 1.145.2 join blocks converted from 1.137.0, so the other tokens keep their values (ruling 771, nothing outside the terminal changes colour).
6. Inverse text in the default colours keeps its strength by a style rule, since xterm's DOM renderer measures it against the wrong colour.
7. An app's page is handed every custom property of `tokens.css` (`docs/apps.md:491`), so it gets the sixteen too.
