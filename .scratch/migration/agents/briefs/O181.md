## Decisions taken in this brief (each reversible, none silent)

1. **What stays in code**, from the step's words "a value of a kind config can hold": (1) an absence value (`''`, `null`, `0`, `false`, `[]` meaning nothing is there); (2) a fact of another program or format (an exit code, an HTTP status, `SYMBOL_KIND_NAMES` of the language server protocol, the number of months in a year); (3) a word the code branches on over a closed set of oculus's own (the type `TabBar`, a view id, a message key, `FeedKind`). A named limit, size, cadence, timeout, path, file name or program name is under none of the three and gets a key.
2. **An invalid value.** A value of a key that fails its option's `options` or its reader's shape is a config finding naming the key and the value, and the merged config keeps the shipped default, so a reader never needs a fallback. The workspace layer does this today; the check is built in `hub-layer.ts` for the keys a hub sets, and `wordOf` no longer throws for a word a finding already refused.
3. **Key names**, `<section>.<what the value is>` in snake case, the unit as the suffix (`_ms`, `_s`), under the existing section where the value belongs, in the file that holds that section. Five real cases: `poll.ts:330` to `slurm.poll_timeout_ms: 40000`; `latex/endpoint.ts:502` to `latex.format_file_name: main.tex`; `opening.svelte.ts:187` to `terminal.default_agent: claude` in `appearance.yml`; `UPDATE_TASKS` to the rows of `update_tasks` in the hub; `FEED_REGISTRIES` to `feed_registries: [leads, radar]` in the hub.
4. **Where a key lives.** A value of oculus goes in `config/defaults/`; a word that names one hub's content goes in that hub's `.oculus/config.yml`, with the default `[]` or `''` in `config/defaults/`.
