# Brief: Q27, Tab moves focus and Ctrl+Tab cycles a pane's tabs

Read `../spec.md` first, its section "The principles every package is judged on" and its amendment of 2026-09-16 (the port rule) above all. The plan's Q27 line (Axel, 2026-09-16 00:35): Tab and Shift+Tab return to the browser's focus navigation; Ctrl+Tab and Ctrl+Shift+Tab cycle the focused pane's tabs; the key sheet and HELP.md follow. The reason: a Tab that never moves focus takes the keyboard away from every control, and the editor convention is Tab for focus and Ctrl+Tab for tabs.

## How it lives in oculus (the three layers, the data live)

1. **Tab is the browser's.** The `'Tab'` branch of `keys.ts` goes; a bare Tab or Shift+Tab reaches no handler and the browser moves focus between controls. The `order.all` cycling and its `currentView` context input go with it if nothing else reads them (check `order.all`'s other readers before removing it).
2. **Ctrl+Tab cycles the pane.** `keys.ts` answers `{ kind: 'cycle-tab', by: 1 | -1 }` for Ctrl+Tab and Ctrl+Shift+Tab (Cmd+Tab is the operating system's and is not bound); `workbench-keys.svelte.ts` handles it through `activateTab(pane, current + by)` modulo the pane's tab count, over the focused pane as `pageShortcut` finds it, and prevents the default so the browser's own tab switch does not fire where it would.
3. **Words.** The key sheet's row becomes "Ctrl+Tab / Ctrl+Shift+Tab | next / previous tab in the focused pane"; HELP.md line 42 says the same and a sentence says Tab moves focus between controls as it does everywhere.

## Acceptance list

1. A bare Tab and Shift+Tab produce no action and no `preventDefault` (a keys case each; a workbench-keys case that the event is left alone).
2. Ctrl+Tab and Ctrl+Shift+Tab cycle the focused pane's tabs with wrap-around, and do nothing while a text field, textarea or the palette holds the keyboard (cases in both test files).
3. The key sheet row and HELP.md updated; `keys.test.ts` (the catalog gate) green.
4. A browser case in `tests/browser/keyboard.spec.ts`: two tabs in one pane, Ctrl+Tab activates the second, Ctrl+Shift+Tab the first, and a bare Tab moves focus to the next control (assert `document.activeElement` changed).
5. DESIGN.md's decision line.
6. The checks of `spec.md`, the narrowed ASCII gate included.

## Decisions taken in this brief (each reversible, none silent)

1. Cmd+Tab is left to the operating system; the binding is Ctrl on every platform.
2. The rail's whole-order cycling is not re-bound elsewhere: the chords and the palette reach every view.
