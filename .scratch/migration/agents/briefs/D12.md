## The shapes this brief sets (booked in the state file's open items; built as written)

1. **The query.** `GET /api/search?root=<key>&q=<text>&word=<0|1>&case=<0|1>&regex=<0|1>&max=<n>`, behind the token and origin gates as `/api/git` is; `root` one of the served roots' keys or `all` for every root; `q` the pattern (literal unless `regex=1`; `word=1` adds word boundaries; `case=1` matches case); the answer `{ files: [{ root, path, hits: [{ line, column, text }] }], total, truncated, ms }`, hits capped at `max` (default 500, the cap the answer says it hit), each `text` the matching line trimmed to 240 characters around the match. The server runs `rg --json` from `@vscode/ripgrep`'s `rgPath` through `execFile` with list arguments only, a ten-second timeout, `--max-count` and `--max-filesize 2M`, the root's directory as the working directory, honouring `.gitignore` as ripgrep does by default and adding `--glob '!node_modules' --glob '!.git' --glob '!.svelte-kit'`; the pattern is one list argument, never a shell string; a regex that ripgrep refuses answers 400 with ripgrep's one-line reason. One call site, as git has one.
2. **The view.** `search`, listed in the Sources group at order 6 (after Repositories), glyph `search` added to `config/glyphs.yml` and `config/icons.yml`, catalog `config/text/views/search.yml`: a query field (Enter runs it, the `/` key of the view focuses it), a root picker (every served root and "all"), three toggles (word, case, regex), the result count with the time and the cap word, and the results grouped by file (the file path as a heading with its root when `all`, one row per hit with the line number and the line's text, the match emboldened). A hit opens the file in a source tab at that line; the file heading opens it at its first hit. The query, the root, the toggles and the last answer are the instance state, so a saved page keeps its search. No search runs on typing; only Enter and the Search control run one.
3. **Opening at a line.** `sourceTabState` gains an optional `line`; `openSourceFile` passes it; the source view scrolls the textarea and its mirror so that line is in view and places the cursor on it when the draft has loaded; a `line` past the end lands on the last line. The instance state carries `line` once, and the tab's later scrolls are the reader's.
4. **"Find all references" for C++.** The search view's word toggle on the identifier over a code root is the answer; no language server. The catalog's help word says so in one sentence, and HELP.md's section says which roots are searched and that the query never leaves the machine.

## Decisions taken in this brief (each reversible, none silent)

1. Ripgrep from the npm dependency, never from the machine's PATH, so the search works on a machine with no `rg` and the binary's version is the lockfile's.
2. `GET` rather than a channel: a search is a request with an answer, not a state the server keeps.
3. The cap is 500 hits and the timeout ten seconds, both in `config/behavior.yml` under `search: { max_hits: 500, timeout_s: 10 }`, read by a `searchSettings` beside `slurmSettings`.
4. The instance state keeps the last answer, so a page reload draws the last results without a new run.
