1. **A failed read is asked again.** A read that ended in an error does not hold the round: the next time the view asks for that thing in a later round it reads again, and a read that failed is retried on a plain interval while the section is drawn, or when the reader returns to the view, whichever you judge to fit the store's shape. Say which you built and why in the report.
2. **The reader can ask.** The failed line carries a control that asks again, in the section's own row style, with its own catalog key under `files.*`.
3. **The same for the three reads that share the shape**: bookmarks, notes and workspaces. The workspaces section has no failure sentence today, so it gets one, with its own `files.workspaces_failed` key, drawn the way the other two are, and the control beside it like theirs.
4. **The line goes when a later read succeeds**, so no failure sentence outlives its cause.
