## What to build

1. **The dependency.** `zod` 4.6.5 added to `dependencies` in `package.json` with the lock file, by `npm install zod@4.6.5` run from `tools/oculus` in the worktree. `README.md:13` names it with its licence and what it does here, in the sentence's own form.
2. **The rule, for this step and the four after it.** A schema goes where a value of type `unknown` that came from outside the process is narrowed: a request's body or query, a socket message, a file oculus parses, the answer of a subprocess or a remote API. The schema is a `const` beside the function that narrows, in that function's file. The function answers, for every input, exactly what it answers on main: the same value, the same null, the same keys. zod's own error text is never shown or logged.
3. **Two forms of reader.**
   - A reader that builds its answer from named fields reads them from `safeParse(...).data`.
   - A reader that hands on the object it was given (written back to a file, or sent to the page whole) uses the schema only to accept or refuse and answers the input object itself, so the order of its keys, an own `__proto__` key and keys the schema does not name all stay as they are.
4. **`parseSubscription`** (`root/socket.ts`). `const subscriptionShape = z.object({ type: z.literal('subscribe'), channels: z.array(z.string()), token: z.string().optional().catch(undefined) }) satisfies z.ZodType<Subscription>`. The function keeps its `JSON.parse` in the `try`, then answers `{ type: 'subscribe', channels, token }` from the parsed data, or null. Lines 59 to 62 and the `typeof` of line 66 go.
5. **`handleHook` and the log's name** (`root/hooks.ts`). One schema of the hook body: `z.object({ hook_event_name: z.string().catch(''), session_id: field, notification_type: field, message: field, title: field, cwd: field })` with `const filledTextShape = z.string().min(1).optional().catch(undefined)` standing for `field`. `handleHook` parses the body with it, answers null when the parse fails, and builds the event from the parsed fields as today (`byKey(EVENT_NAMES, name)` stays). The helper `str` and its comment go. `handleHookRequest` lines 231-234 read the name from the same schema: a body that parses and whose `hook_event_name` is not empty is logged, with the body itself, as it was sent and with every key it holds, handed to `logFirstPayload` as today; the parsed data is never what is logged. The body has no declared type, so the reader uses the schema's inferred type.
6. **`notifyConfig`** (`root/hooks.ts`). `z.object({ enabled: z.boolean().catch(DEFAULT_NOTIFY.enabled), events: z.array(z.unknown()).transform((all) => all.filter((one): one is string => typeof one === 'string')).catch(DEFAULT_NOTIFY.events), quiet_seconds: z.union([z.number().min(0), z.literal(Infinity)]).catch(DEFAULT_NOTIFY.quietSeconds) })`. The schema ends `.transform((held) => ({ enabled: held.enabled, events: held.events, quietSeconds: held.quiet_seconds })) satisfies z.ZodType<NotifyConfig>`, so the declared `NotifyConfig` is held. A `notify:` value that does not parse answers `DEFAULT_NOTIFY`, the same object as today. The union keeps `.inf` answering `Infinity`, which `z.number()` alone refuses. The filter's `typeof` stays: it drops the entries of a list that are no string, which a `z.array(z.string())` would refuse whole.
7. **`parseLine`** (`core/changes.ts`). `z.looseObject({ at: z.string(), kind: z.string(), file: z.string(), field: z.string() })`, the second form of item 3: the function answers the parsed line itself when the schema accepts it, or null. The schema checks the four fields the hand code checks and no others, so a line without `key` or `undo` is read as today; it is typed `z.ZodType<Pick<Change, 'at' | 'kind' | 'file' | 'field'>>` through `satisfies`.
8. **The schema's name.** A schema is named for what it reads, in lower camel case, ending in `Shape`: `subscriptionShape`, `hookBodyShape`, `filledTextShape`, `notifyShape`, `changeLineShape`. A zod schema is a lower camel case `const` assigned from `z.`; the type `RefusalShape` of `core/auth.ts:78` and `repoShape` of `state/sources/repositories/repositories.ts:566` are neither and keep their names. The suffix `Schema` is taken: `collectionSchema`, `scaffoldSchema` and `checkCollectionSchema` name the collection schemas of `config/collections.yml`.
9. **What stays, each with its reason in the report.** Every line listed under "The other check lines" above stays as it is, and `core/auth.ts`, `core/git.ts`, `core/file-poll.ts`, `root/watch/portfolio.ts`, `root/watch/sessions.ts` and `root/watch/git.ts` are not changed. `gatedBody` keeps `isMap`: the guard narrows `unknown` to `Record<string, unknown>` for the compiler, where `z.record(z.string(), z.unknown()).safeParse(body).success` would need a cast to answer the same object, and the two accept and refuse the same inputs (run on eleven, `{}`, a map with an own `__proto__` key, `[]`, `null`, a string, a number, `true` and `1e999` among them). The lines of `core/git.ts`, `core/git-parse.ts`, `root/watch/git.ts:402`, `core/changes.ts:234`, `root/hooks.ts:212-213`, `root/socket.ts:32,103-104`, `core/auth.ts:99` and `core/json.ts:28-30` named under "What is on the tree" stay, each with the reason given there. `text`, `whole`, `list` and the `isMap` re-export of `core/json.ts` stay until their callers are converted.
10. **The duplication allowlist.** Line 31 of `tests/checks/tree/allow-duplication.txt` is removed, since `parseSubscription` no longer holds the clone. No other line of the file changes.
