## Decisions taken in this brief (each reversible, none silent)

1. **The feeds views are a rail group.** `config/layout.yml`'s `nav_groups` gains `feeds: [{ label: "Feeds", glyph: scout, keys: [radar, leads, inbox, linkedin] }]` between `collections` and `more`; each later feed package registers its key. The label and the glyph are user-visible and are named here.
2. **A feed is served on request, not carried in the snapshot.** `server/feeds.ts`: `readFeedFile(hub, config, kind)` for `radar`, `leads` and `inbox` (the paths from `config/sources.yml`'s `radar_file`, `leads_file` and the `docs:` entry keyed `inbox`, `sources.yml` lines 50 and 68 to 74), parsing the YAML into `{ meta, entries }` with every entry a map, and a `GET /api/feeds?kind=<kind>` route (`src/routes/api/feeds/+server.ts`, the handler in `server/feeds.ts` `handleFeeds` shaped like `server/project-files.ts`'s) answering `{ ok: true, kind, file, meta, entries }`, 400 for an unknown kind, `{ ok: true, missing: true }` when the file is not there. Every feed view fetches on mount and again on every portfolio push (`state/entities.svelte.ts`'s `portfolio()` changes when the watcher rebuilds, which it does for a change under `feeds/`: check `server/watch/portfolio.ts` and say in the report whether `feeds/` is under its watch; if it is not, add the folder to what it watches, since the cockpit's own watcher rebuilt on it).
3. **The feed writes are two kinds of the write route.** `kind: 'feed-field'` `{ feed, id, field, value }` sets or clears one scalar field on the entry the identity names (radar and inbox entries are identified by `title` and `id` respectively, leads by `title`; the identity field per feed is a table in `server/feeds.ts`), through `setEntryFields` of `server/entry-edit.ts` over the file, refused for a field outside the feed's own field list (radar: `dismissed`; inbox: `triaged`; leads: `status`); `kind: 'feed-delete'` `{ feed, id }` removes the entry (leads only, refused for the others). The spin-to-idea save is the existing `new-idea` write followed by a `feed-field` dismiss from the view. `state/writes.svelte.ts` gains `writeFeedField` and `deleteFeedEntry`. The feed files are hub data: tests use fixture copies under `mkdtemp` and never the real files.
4. **The pure parts.** `state/radar.ts`: `bucketsOf(entries, buckets)`, `sortBucket(entries)`, `isNew(entry, lastRun)`, `relevanceTone`, `radarSearch`, `ideaSeed(entry)` (the id and eli5 of item 5), `crossLinksOf(entry, projects)`; a `RadarState` from the instance state (search words, the dismissed section open or not).
