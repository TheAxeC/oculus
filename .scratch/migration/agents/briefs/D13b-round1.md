1. Z59 (a), Axel's ruling, with Behaviour 4's measurement (git applies a patch whose only non-UTF-8 byte sits on a written line, and stages or writes U+FFFD bytes). The server checks each version's bytes with `isUtf8` (node:buffer) before decoding and marks the file `encoded: false` on `DiffSides` when either side is not UTF-8. `diffActions` answers `'none'` for such a file, so no hunk or line action is offered, and the `diff_whole` note is drawn. A `working-tree-encoding` attribute and an `ident` attribute count as a conversion in the same rule as `filter`, so they also withhold the partial actions. Cases: a Latin-1 file on each side gives `encoded: false` and `'none'`; a UTF-8 file gives `encoded: true`; the two attributes each give `'none'`.
2. Behaviour 1. A type change (git lists the same path twice, deleted then added) no longer gives a duplicate key. The `{#each}` in `Diff.svelte` and the view-state and model keys use the path plus its occurrence among the entries (`x`, `x#2`), so the first entry of a path keeps its plain key. Cases: the key helper over `[x deleted, x added]` gives two distinct keys; a view case draws a type-change diff of two entries without throwing.
3. Behaviour 2. After the pane closes nothing writes its instance state: `Diff.svelte` sets a closed flag in its `onDestroy` before anything else, clears the keep timer, and `viewed()` and `keep()` return at once when the flag is set. A case: close the pane (or run the destroy path) with a pending view state and assert no `setInstanceState` for its id afterwards.
4. Behaviour 3. A file git lists as changed for which Monaco finds no line change (line endings only) draws a note at the section's head, a new catalog key `diff_eol_only` with the text "Only the line endings differ", and turns `hideUnchangedRegions` off for that file so its lines show. A case over the pure rule (git changed, zero hunks) and a view case with CRLF against LF.
5. Behaviour 5. A file that mounts no `DiffEditor` (binary, or equal texts) counts 0 changes, so it is not a stop for Previous and Next. A case over `stepFiles` with a binary entry and a rename-only entry.
6. Behaviour 6. `Merge.svelte` `typed()` recognises an undo by the content-change event's `isUndoing` flag (and a redo by `isRedoing`), never by comparing whole texts. A case: the reviewer's sequence (a choice, typing another conflict back to the choice's text, then editing the chosen conflict back) keeps the other conflict marked `edited`.
