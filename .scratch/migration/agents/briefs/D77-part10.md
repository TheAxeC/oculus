## What to build

1. **Every section's content indented one step under its head**: in Changes, Merge Changes, Staged, Changed and Untracked drawn at depth 1, their file and folder rows at depth 2 and below (each one step deeper than now), the cut warning and an empty group's muted row at the file rows' depth, in list mode and tree mode alike; in Graph, its head rows, commit rows, failure and pending rows one step in, and a commit's files one step deeper than now; in Branches, Tags, Stashes, Worktrees and an app's source sections, every row one step in from its section head. One rule for all of them, so no section is drawn flush with its head. The keyboard's `level` values stay consistent with the drawn depth.
2. **The right-click menu acts on the selection**: a pick from a row's menu whose row is among the selected rows of its group acts on every selected row of that group, as the row's hover controls do: Stage Changes, Unstage Changes, Discard Changes (one question naming the count: the restore question for Changed, the Trash question for Untracked, as `askDiscardPaths` and `askTrash` word them) and Add to .gitignore. A pick on a row outside the selection acts on that row alone and the selection is left. Open Changes, Open File, Open File (HEAD), Reveal in Explorer View and Compare with Workspace open the pressed row only. `changePicked` takes the acted paths, as the hover controls compute them, so the menu and the controls cannot disagree.
3. **Every untracked file listed on its own row, as VS Code does**: the status read of the Repositories view's state passes `-uall` (`--untracked-files=all`) in place of `--untracked-files=normal`, and every other reader of `status --porcelain=v1 -z` the view's writes rely on (the readers `src/lib/server/core/git/parse.ts:7` names) lists untracked files the same way, so a Stage, Discard or Trash of a selection names files the list showed. The cap of 200 entries (`MAX_ENTRIES`, `state.ts:52`) and its warning row stay. A path git still lists as `dir/` (a nested repository) keeps the folder row and its reveal. The comments that describe the `normal` form (`change-tree.ts:8`, `run.ts:17`, `state.ts`) say what the code then does.
4. **The change count before `...` on a repository row**: the badge of changed paths drawn after Sync or Publish and before the row's `...` menu, the `...` last at the row's right; through `TreeItem`'s existing slots (its `end` or `trailing` form) or one optional prop of `TreeItem` that every other row leaves as it is; RepoList's head comment says the new order.
5. The comment heads of `Changes.svelte`, `ChangeRow.svelte` and `menus/change-menu.ts` say what the code then does; `HELP.md`'s Source Control text names the menu acting on the selection.
