# Brief: Q18, the Tasks section of the Focus board

Read `../spec.md` first, its section "The principles every package is judged on" above all. Axel ruled on 2026-09-14 at 17:39: the Command Center keeps every line that carries a date, and the undated follow-ups, the undated subtasks and the undated `tasks.yml` entries move to a Tasks section of their own on the Focus board, under the Command Center and above the lanes, in the same two-column ticker markup with the same tick, snooze and delete controls. ## What is on the tree (read 2026-09-14 at 17:43 on main at 38443bff)

- `src/lib/state/ticker.ts` (531 lines): `ticker()` answers `{ overdue, deadlines, followups, subtasks, venueLoad, snoozed, behind }` (the type at line 119). `deadlines` holds every dated line by category (papers, funding, events, teaching, tasks, positions, collaborations, conference calls, subtask deadlines); `followups` holds every due `followup:` note of projects, schemes and entries, dated (`days` a number, due today or past) and undated (`days === null`, from `dueFollowups` at line 156) together, undated sorted last; `subtasks` holds the open subtasks with no date (a dated subtask is a deadline line). A `tasks.yml` entry reaches the ticker only with a date inside the horizon (the entry loop at line 242: `days === null` skips it), so an undated task is on no board.
- `src/lib/views/focus/CommandCenter.svelte` (419 lines) builds the rows and their buttons from the ticker; `src/lib/views/focus/CommandCenterView.svelte` (271 lines) draws them: the deadline groups, then "Open subtasks" and "Follow-ups" as groups of the same two-column layout (lines 169 to 176), the words in `config/text/views/focus.yml` under `command:` (`grp_open_subtasks_label`, `grp_followups_label`, `grp_followups_glyph`).
- `src/lib/views/Focus.svelte` (207 lines) mounts `<CommandCenter>` at line 106, then `<QuickAdd>`, the waiting strip, `<Lanes>`, `<Band>`.
- The tests: `tests/views/focus.test.ts` "the command center" (line 397 on) renders the board and asserts its lines and buttons; the ticker's own cases are found with `grep -rln "ticker(" tests`.

## What to build

1. **The split in the state.** `ticker()` answers two more lists and narrows two: `followups` keeps the dated notes only; a new `tasks` list holds, in this order, the undated follow-ups (as they are built today), the undated open subtasks (today's `subtasks` list, which goes), and the open `tasks.yml` entries with no date (status not terminal, not deadline-met, not snoozed; each a line of kind `task` with the entry target the dated task lines carry, so the same status and snooze buttons apply). The type says what each list holds. Tests over each list: a dated and an undated note land on different lists; a dated subtask is a deadline and an undated one a task; an undated task entry is a task line and a dated one a deadline line; a terminal or snoozed entry is neither.
2. **The section.** A new partial `src/lib/views/focus/Tasks.svelte`, mounted by `Focus.svelte` under the Command Center and above `QuickAdd`, drawing the `tasks` list in the ticker's two-column markup with one heading (a new `focus.tasks.*` block in `focus.yml`: the heading, its glyph, and the group labels "Follow-ups", "Subtasks", "Tasks" as three groups of the one section), the rows built by the same row builder the Command Center uses (lift `CommandCenter.svelte`'s row and button functions into a module both partials import, `src/lib/views/focus/rows.ts`, rather than copying them), so a task row carries tick, snooze and delete exactly as before, and a task entry row carries its status buttons. The Command Center loses its "Open subtasks" group and draws the follow-ups group with dated notes only. An empty section draws nothing, not an empty heading.
3. **The tests.** `tests/views/focus.test.ts`: the Tasks section draws an undated follow-up, an undated subtask and an undated task entry with their buttons, and the Command Center no longer draws them; the existing command center cases follow the split. `tests/views/type-scale.test.ts` gets a row for the new partial.

## Decisions taken in this brief (each reversible, none silent)

1. The section's three groups are follow-ups, subtasks, tasks, in that order, undated only.
2. The row builders move to `views/focus/rows.ts` and are shared, not copied.
3. A task entry row on the Tasks section carries the status buttons the dated task line carries in the Command Center, and no tick (a task is done by its status).
