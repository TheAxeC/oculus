## What to build

1. **Placement by neato.** A new module `src/lib/state/boards/structure/layout.ts` (under 300 lines) lays a `Graph` out with `@viz-js/viz`'s `instance()` and Graphviz's `neato` engine, in the page:
   - it writes the graph as Graphviz input with each node's id, its size taken from its `radius`, and every edge as an undirected edge (a membership edge, a collaborator edge, a related edge);
   - it asks for JSON output (`renderJSON` or `render` with format `json`), reads each node's position, and maps it into `DEFAULT_BOUNDS` (1000 by 680, padding 48), flipping Graphviz's y axis, so the result is the `PointNode[]` the Map draws today;
   - it takes a start seed, passed to neato as `start=<seed>`, so the same node set and seed give the same picture every time;
   - the engine's name is one exported constant, `'neato'`, so `fdp` can be tried by changing one word;
   - the Graphviz instance is loaded once per page and shared by every Map pane.
2. **The search goes.** `placeInit`, `crossings`, `score`, `settle`, `bestLayout`, `optimize`, `isPhysics`, `savedTuning` and the `Physics` fields a saved tuning carried are removed from `graph.ts`. `physics` stays with `DEFAULT_PHYSICS`, as the tick that runs while a node is dragged, so dragging keeps pulling its neighbours as today.
3. **The seed is the pane's state.** `MapState.tuned` is replaced by `start?: { key: string; seed: number }`: the seed a pane chose for the node set named by `layoutKey`. `parseMapState` reads it, drops a malformed one, and ignores a saved `tuned` (an old pane then lays out once from its default seed, `layoutSeed(nodes)`). `startFor(state, nodes)` replaces `tunedFor` and answers the saved seed for this node set or the default.
4. **The Map draws what neato placed.** `Graph.svelte` takes `seed` in place of `tuned` and `ontuned`, awaits the placement (the SVG draws its nodes once it resolves; until then it draws nothing and the pane keeps its size), and keeps the drag tick. When the placement fails (the engine refuses the input or does not load), the pane shows one line from the catalog, `map.layout_failed`, with the error's message, and logs the error.
5. **Re-tune lays out again.** The control keeps its label and glyph; pressing it saves `start: { key, seed: <the current seed + 1> }`, which lays the map out again from another start and keeps that picture. Its tip becomes "Lay the map out again from another start" (`map.retune_tip`).
6. **The package.** `@viz-js/viz` moves from `devDependencies` to `dependencies` at the same version, 3.30.0, and `package-lock.json` follows (`npm install`).
7. **Docs.** `DESIGN.md:290` is rewritten to say what is true after the step: the Map is placed by Graphviz's neato through `@viz-js/viz` in the page, the pane keeps the start seed per node set as `start: { key, seed }`, re-tune moves to the next seed, and the drag tick is `physics` of `graph.ts`. The head comments of `graph.ts`, `layout.ts`, `Graph.svelte` and `Map.svelte` say the same. `npm run diagrams` is run and its output kept.

## Cases

- Two calls of the layout for the same graph and seed give the same positions, node for node.
- Two different seeds give a different position for at least one node of a graph with three or more nodes.
- Every placed node lies inside `DEFAULT_BOUNDS` less its padding.
- A graph of one node, and an empty graph, place without an error (the empty one returns an empty list).
- A node id holding a quote, a space or a backslash (as a project key might) is written so Graphviz reads it and its position comes back under the same id.
- `parseMapState` of `{ start: { key: 'k', seed: 3 } }` keeps it; of `{ start: { key: 'k', seed: 'x' } }` drops it; of `{ tuned: { key: 'k', params: {...} } }` returns a state with neither `tuned` nor `start`.
- `startFor` answers the saved seed when the key is this node set's, and `layoutSeed(nodes)` for another set or none.
- Pressing re-tune writes `start` with the seed one above the one in force.
- A drag still moves a linked neighbour: one `physics` tick with a node fixed away from its linked partner moves the partner toward it (the existing case at `graph.test.ts:301` keeps holding).
- In the page's build, the layout module loads `@viz-js/viz` without a server import: `npm run build` passes and the server bundle holds no `@viz-js/viz` (grep of `build/server`).
