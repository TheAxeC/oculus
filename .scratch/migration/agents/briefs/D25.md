## What to build

1. **The editor's keys** (Z329), in `config/behavior.yml`'s `editor:` block, each with its catalog entry in `config/catalogs/options.yml` (section Editor, a description saying what it does and VS Code's name for it) so the Settings view draws its control:
   - `editor.tab_size: 4` (number), `editor.insert_spaces: true` (toggle), `editor.word_wrap: off` (choice: `off`, `on`, `wordWrapColumn`, `bounded`, Monaco's wrap column 80), `editor.minimap: true` (toggle), `editor.render_whitespace: selection` (choice: `none`, `boundary`, `selection`, `trailing`, `all`), `editor.sticky_scroll: true` (toggle).
   - `editor.languages`, a family keyed by oculus's language name (the names of `sources.yml` `languages:` and `plaintext`), each record holding any of `tab_size` (a whole number 1 to 8), `insert_spaces` (true or false), `word_wrap` (one of the four words) and `rulers` (a list of column numbers). The tracked file holds `editor.languages` with VS Code's own language defaults that differ from the global keys: `makefile: { insert_spaces: false }`, `markdown: { word_wrap: on }` (VS Code's `[markdown]` default), `yaml: { tab_size: 2 }` (VS Code's `[yaml]` default `editor.tabSize: 2`).
   - Readers in `data/helpers/editor.ts` beside `paintLimit`: one function answering the global options and the language records from the merged configuration. A missing key is read as its default with no finding, so a configuration without the new keys (`config.test.ts:600`'s `SOUND`) draws none. A value of the wrong type or outside its words or range is read as the global default, and is a finding (`findings.config.editor_option`, naming the key) in `behaviorFindings` of `data/sources/config/catalogs.ts`, as `paint_limit_kb` is: `word_wrap: true` is outside the words; the global `editor.tab_size` is a whole number 1 to 8 as a record's is (0, 9, 2.5 and -1 refused); `insert_spaces` only `true` or `false`. In a record, each field is read on its own: a bad field is not read and is a finding, the record's other fields are; `rulers` is read only as a list whose every entry is a whole number of 1 or more (VS Code bounds it no further), a scalar or a list with any other entry not read at all. `editor.languages` that is `null` or `{}` sets nothing and draws no finding; one that is not a map is a finding. A language name the editor does not know is a finding, matched as written (`Python` is unknown; the names are lower case), and a reserved name (`__proto__`, `constructor`, `prototype`) is a finding and never merged; every merge of records is into an object made with `Object.create(null)`. The server does not require the keys at start. A client selector beside `editorPaintLimit` (`state/client/selectors.svelte.ts`, its type at `:98`, its entry in the returned object at `:501`; the file stays under 900 lines) hands them to the views.
2. **A repository's `.oculus/settings.yml`** (Z89, Z329): a file `<root>/.oculus/settings.yml` in a Files root holds `languages:`, a map of the same records as `editor.languages`, and overrides them for the files of that root; any other key of the file is not read. The source tab reads it through `fileText(root, '.oculus/settings.yml')`. It is read again when it is marked (Z330): a source-tab save of any file marks that file's text query, through a function of the fs store that marks one `['fs', 'text', root, <the file's key>]` and is called from the save hook in `state/client/context.ts:326` beside `latex.onSaved`, so a `.oculus/settings.yml` saved in a source tab is read again at once, and every other reader of a saved file's text sees the saved text; an edit made outside oculus is read at the Files view's refresh or a reload, as every file text is. The cases of the file:
   - A root without the file (the read answers 404): no override and no line in the Settings view.
   - An empty file, a comments-only file, a file without `languages:`, or `languages: null` or `{}`: read, nothing set, nothing said.
   - A file that does not parse, or whose `languages:` is not a map: not read, and the Settings view says so with the parser's first line (item 4).
   - A file the read cuts at `TEXT_LIMIT` (`fileText`'s `truncated`): not read, never parsed in part, said as "Not read" with that reason.
   - A file the read refuses (403, 500, a network error): not read, said as "Not read" with the read's error.
   - An unknown language, a reserved name, or an unknown or bad field in the file: that entry or field skipped, the rest read, and each skipped entry said under the row as item 4 says.
   - Any key of the file other than `languages:`: not read, said nowhere.
   - A tab with no root (a new untitled text file): no lookup.
   - The tab's read in flight when the tab is closed or pointed at a file of another root: its answer is dropped, and the tab takes the new root's file.
   The parse and the merge are pure functions in `data/helpers/editor.ts`.
