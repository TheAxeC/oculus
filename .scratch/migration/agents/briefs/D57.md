## What to build

1. **A pane records that the page's arrangement did not define it.** A pane made while the page is used carries a mark of its own on `Pane` (decision 1): the pane `splitPane` makes, and so every caller that splits through it (the opening paths, the menu and key splits, an edge drop from the page, another page or a float, the Views catalogue's `openNextTo` and `openAway`), the pane Return to Page puts back (`returnFloat`), and the empty pane a saved layout's refused page leaf becomes (`withoutLeaves`; an arrangement never holds a page leaf, `arrangement.ts:63-66`). A pane made from an arrangement, the root pane of a page made by New page and the one empty pane `removeNode` leaves at the root carry no mark. `repane` carries the mark through every rebuild, so a tab opened, moved, pinned, renamed or closed in the pane keeps it; a split that collapses into the pane keeps it. The saved layout writes the mark and `saved.ts` reads it back; a pane saved without it reads as one the arrangement defined. A float's pane carries no mark: `floatPane` drops it when a page's pane is floated (`pages.ts:233`), and `floatTab` and `copyTab` make none.

2. **The rule.** When the last tab of a page's pane goes, by any operation the rule reaches today (a close, a drag out, a move to another page, an edge drop, a record deleted, a view leaving the registry):
   - a marked pane is removed, the split it leaves collapsing as today;
   - an unmarked pane stays, emptied: an empty terminals pane when its last tab was a Terminal tab, an empty documents pane for any other view, a tool view included;
   - a locked pane stays, emptied and locked, as today, marked or not;
   - when the pane removed is the page's only pane, the page keeps one empty pane (`removeNode` of the root, as today).
   The cap of one empty pane per page goes: two unmarked panes emptied on one page both stay. A float is not a page: its pane's last tab still removes the float. Close pane still removes any pane. `adoptFloats`, which passes no rule today, goes through the same rule: an unmarked page pane it empties stays, a documents pane, as the ruling keeps the arrangement's panes.

3. **Where it reaches.** The rule stays one function in `layout/tree.ts` that every operation taking a last tab out goes through; the store's `keepRule` and the type `KeepRule` change to what the new rule needs, and every caller listed under "What is on the tree" (`floatTab`, `windowTab`, `moveInstance` and `adoptFloats` included) reaches it. No caller decides a pane's fate on its own.

4. **The text.** `docs/window.md:41` states the new rule in place of the old sentences: a pane split off at run time (by opening a view with no pane to land in, Open to the Side, Split Right, Down, Up or Left and Split & Move, a drop on an edge from this page, another page or a float, a view opened beside itself from the Views catalogue, Return to Page) closes with its last tab; a pane of the page's arrangement stays, empty, a terminals pane after a Terminal tab and a documents pane after any other; a locked pane stays; a page keeps one pane; Close pane removes any pane. The sentence "A page keeps never more than one empty pane ..." and "A pane whose last tab was a tool view closes ..." are replaced, not kept beside the new rule. `docs/window.md:15` names the Explorer's five views as `config/layout.yml:82` gives them. `DESIGN.md:238` and each head comment listed under "What is on the tree" are made true, or left and marked still true in the report.

## Decisions taken in this brief (each reversible, none silent; 1 and 2 ruled by Axel)

1. Ruled by Axel (D57-1 (a), plan.md Rulings "D57 pane marks"). The mark sits on the panes made at run time, not on the panes an arrangement made, and its name is `added` (`added?: true`, "a pane added while the page was used, which the page's arrangement did not define"); it is internal state of the saved layout, which no reader edits. Marking the arrangement's panes instead would read every pane of a layout saved before this step as unmarked, so the Explorer's documents pane would close with its next file until the page was reset; marking the run-time panes leaves those layouts as they are. The cost: a pane split off before this step lands reads as the arrangement's and stays when emptied, until Close pane removes it once.
2. Ruled by Axel (D57-2 (a), plan.md Rulings "D57 pane marks"). The panes the arrangement defines stay, whatever view their last tab was, as the ruling says ("the panes the arrangement defines stay"). Today a pane whose last tab was a tool view closes; after this step an arrangement pane emptied of its tool views stays as an empty documents pane (case 3).
3. A locked pane stays when emptied, marked or not, as the lock's own rule says (`docs/window.md:54`, "keeps its place when its last tab closes, so only Close pane removes it").
