## What is on the tree (read on main at 3d6a3ae2c)

- Each name of Focus's Awaiting box is drawn as `<ToolButton plain label={name.text} onclick={name.press} />`, inline inside `<span class="wait-names" class:blocked={row.key === 'blocked'}>`, the names joined by `focus.wait_join`, a name with no press drawn as its words alone: `src/lib/views/boards/focus/Focus.svelte:369-377` (`sed -n 365,380p`).
- A plain `ToolButton` draws no box, no border and no background, and takes its box's colour and `text-decoration` by `inherit`: `src/lib/ui/controls/ToolButton.svelte:335-357` (`.tool.plain`). Its only hover rule is `.tool:hover:not(:disabled) { border-color: var(--accent); }` at `:207-209`, which a plain button's `border: 0` does not show. So hovering a name of the box changes nothing on screen: seen on localhost:8790 by hovering "Maryam Amir Haeri" under Waiting on, the name drawn the same as at rest.
- The box's styles: `.wait-names` (`Focus.svelte:458-463`, font size, line height, `overflow-wrap: anywhere`) and `.wait-names.blocked { color: var(--c-red-txt); }` (`:465-467`); no hover or focus rule (`grep -n "hover\|focus-within" src/lib/views/boards/focus/Focus.svelte` prints nothing).
- The band's rule this step follows (ruling 524, "the band's rule"): `src/lib/views/boards/focus/Band.svelte:113-115` wraps the title's plain `ToolButton` in `<span class="entry-name">`, and `:290-294` reads `.entry-name:hover, .entry-name:focus-within { color: var(--accent-txt, var(--accent)); text-decoration: underline; }`, the plain button inheriting both. Its comment at `:280-281`: "The entry's name is a plain button: the words of the row, with the focus ring the button draws and an underline under the pointer."
- The command center and Tasks lines underline under the pointer (`src/lib/ui/display/ticker/Ticker.svelte:182-185`, `button.name:hover, button.name:focus-visible { text-decoration: underline; }`); seen on 8790 on "FWO Senior Postdoctoral Fellowship 2026" and "MSc supervision - Statistics & Data Science (2026-2027)".

## What to build

Ruling 524, word for word: "In `Focus.svelte`, the box's name buttons get the band's rule: an underline under the pointer and with keyboard focus. Blocked's red stays red. The names keep the box's colour until hovered, as the command center lines do."

1. In `src/lib/views/boards/focus/Focus.svelte`, each name of the Awaiting box that is a button is drawn inside a span of its own class (the box's name class), as the band draws its title inside `.entry-name`. A name with no press stays its words alone, with no span and no hover.
2. That class gets the band's rule: under the pointer and with the focus inside it, the name is underlined and drawn in `var(--accent-txt, var(--accent))`; at rest it keeps the box's colour.
3. In the Blocked row, the name keeps `var(--c-red-txt)` under the pointer and with the focus; it is underlined.
4. The span is inline, so the names still wrap as one run of words with their joins between them, each name whole on its line as now.
5. A comment above the new rule says what it is, in the shape of the band's comment: a name of the box is a plain button, underlined under the pointer and with the focus. No history in the comment.

## Cases

1. Hover a name of Waiting on (for example "Maryam Amir Haeri"): underlined, in the accent colour; at rest, the box's colour and no underline.
2. Hover a name of Under review, Applications or Grants: the same as case 1.
3. Hover Blocked's count when the box draws a Blocked row: underlined, still red.
4. Tab to a name with the keyboard: underlined and in the accent colour while it holds the focus, with the focus ring the button draws.
5. A grant whose hub names no funding collection (a name with no press): its words alone, no underline under the pointer.
6. A narrow Focus pane: the names wrap between names, each name whole, the joins unchanged.

## Decisions taken in this brief (each reversible, none silent)

1. The focus rule is `:focus-within` on the span, as the band's, so the underline follows the button's focus as the band's title does.
2. The span wraps the `ToolButton` only, not the join after it, so the comma is never underlined.
