## What to build

The step is large: about 40 behaviours across the server, the store, the editor, the viewer, a view and the shell. Every one is inside D45 by the plan line and the two inventories; none is split out.

### A. Root and build

1. **Root detection** (`server/content/latex/root.ts`, the shared reader). For a source file (`.tex`, and the literate kinds of item 9): (1) a `% !TEX root = <path>` in the leading comment block, resolved from the file's folder inside the same served root and followed while the named file is not a main, a cycle answering none; (2) the file itself when it declares a class; (3) walking up from the file's folder to the served root, at each folder the mains of that folder (`mainsIn` order) whose include closure holds the file, the first such folder and the first such main winning; the closure follows `\input`, `\include`, `\subfile`, `\import`, `\subimport`, `\includefrom` and `\inputfrom` through the shared reader, each file read once, and, when the main has a `<main>.fls` beside it or in the output folder, its `INPUT` lines under the root; (4) the only main of the file's own folder (today's rule); (5) none. A `% !TEX root` naming a file outside the root, missing, or not a `.tex` file falls through to (2). `GET ?root=&file=` answers `{ root, path, main, how }`, `how` one of `magic`, `self`, `included`, `folder`, and `{ main: null }` otherwise. The walk is measured over the cases of "Cases" and stops at the served root.
2. **Recipes and tools** (`server/content/latex/recipes.ts`, new; `pty/routes.ts`). LaTeX Workshop's defaults, in `config/behavior.yml` under `latex:` as `recipes` (name and tool names) and `tools` (name, command, arguments with the placeholders `%DOC%`, `%DOCFILE%`, `%DOC_EXT%`, `%DOCFILE_EXT%`, `%DIR%`, `%OUTDIR%`), read through zod. Every tool runs with `-synctex=1` where LTW's has it. A build runs one recipe as one task terminal whose line is the tools joined by `&&`, every value quoted by `shellWord`. The recipe is the one asked for (the TeX view's Build node lists every recipe), else a `% !LW recipe = <name>` comment, else `latex.recipe_default` (`first` or `last_used`), and with `first` a `% !TEX program = xelatex | lualatex` picks LTW's `latexmk (xelatex)` or `latexmk (lualatex)` recipe, so today's program comment keeps working. Before the terminal starts, every program of the recipe is looked up on PATH; a missing one refuses the build with a catalog sentence naming the program and how TeX Live or Homebrew installs it, and no terminal starts.
3. **Output folder.** `latex.out_dir`, default `%DIR%` (beside the main, as today and as LTW). Any other value is resolved from the main's folder inside the served root; a value leaving the root is refused with its sentence. The PDF, `.log`, `.synctex.gz` and `.fls` are looked for there.
4. **A build that can be stopped.** A `latex` step `stop` sends Ctrl+C to the foreground of the main's kept build terminal and to no other terminal (G35); it answers 404 when the main has no build running. The next build after a stop, and any build of a main whose `.synctex.gz` is missing, passes `-g` to latexmk, since latexmk otherwise answers "Nothing to do" after an interrupted or failed run and never writes the SyncTeX file to a folder built before (cases 9 and 14). Clean while a build of that main runs is refused with a notice naming Stop.
5. **Clean and retry, auto clean.** With `latex.clean_and_retry` true (LTW's default), a build that ends non-zero, was not stopped and is not itself a retry is cleaned (`latexmk -c` with the output folder) and run once more. `latex.auto_clean` `never` (default), `on_failed`, `on_succeeded`, `on_built` runs Clean after the build, as LTW's `latex.autoClean.run`.
6. **Auto build.** `latex.auto_build`: `never`, `on_save` and `on_file_change` (the default is choice 1). `on_file_change` builds a root when a file of its dependency set changes on disk, from any writer (the editor's save, an agent, git), for roots the page watches: the root of every open LaTeX source tab and of every PDF tab of a build. The dependency set is the root's include closure and its `.fls` `INPUT` files under the root, minus what the build writes. Changes are taken from the `files` messages the fs store already receives; builds of one root start at most once per `latex.auto_build_interval_ms` (1000, LTW's `autoBuild.interval`) and coalesce into the one-more-build rule. A change while the root is building gives one build after it.
7. **Saving before a build.** A build the reader asks for saves first, as choice 4 rules. An auto build never saves.
8. **Build state for the page.** The store keeps per root: idle, building (with the recipe and the step), succeeded, failed or stopped, and the time; the TeX view, the status item, the title bar and the viewer read it. A build started anywhere (title bar, key, TeX view, project panel, save, file change) is the same state.
9. **Literate sources.** `.rnw`, `.Rnw`, `.jnw` and `.pnw` join the `latex` list of `config/sources.yml:106`, are roots by the self rule when they declare a class, and default to the Rnw, Jnw or Pnw recipe; a missing `Rscript`, `julia` or `pweave` is refused as in item 2.

## For the orchestrator: user-visible choices

Each option is something the reader sees or sets. The recommendation follows VS Code's LaTeX Workshop where it has one.

1. **Auto build default.** (a) `on_file_change`, LTW's real default (`latex.autoBuild.run` "onFileChange"): every write to a watched root's files builds it, an agent's edit included, so the PDF beside the source follows whoever edits. (b) `on_save`, today's default and the plan line's wording: only the editor's saves build; an agent's edit shows on the next save or Build. (c) `never`.
