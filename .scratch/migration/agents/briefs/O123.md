## What to build

1. **The Sessions tab.** `session-list` is the Explorer's third tab, built as Repositories is: a fold headed Sessions holding the list, and under it the sections of the session the tab follows (`followedSession`), Details, Changes, Timeline and Agents, then Customizations as a section of the same look. One pane scrolls them all. The list's fold holds at most ten rows' height and scrolls inside itself, so the sections stay in reach of a long list. With no session followed, the four session sections are not drawn; Customizations stays. The tab calls `keepShown`, so a reload shows what it showed. The sections follow a session terminal through `sessionOfTerminal` when the selection is a terminal, so a terminal row, a resume or a fork keeps them; a by-hand terminal with no session leaves them as they were. The list is one `TreeView`, as `RepoList` is: the list is one Tab stop, arrows scroll a row into the fold, Alt+Up acts only on section heads, a letter typed in the rename field stays in the field, and `onpressagain` carries the double press.
2. **One set of sections.** The sections move out of `SessionDetail.svelte` into one `SessionSections.svelte` in a new folder `src/lib/views/shared/sessions/sections/`, which also takes `SessionSection`, `session-sections.ts`, `AgentRows`, `ChangesRepo`, `ChangesRepository`, `ChangesTouched`, `DetailsBody`, `SharedMark` and `TimelineTurns`, since one view may not import another's folder. Both the tab and `SessionDetail.svelte` draw it, with the closed and order state in the owner's tab state. The `session-detail` view stays as the tab a pinned session opens (decision 1), and leaves every arrangement.
3. **The rows.** A session row is one line of the tree's row height, in the Files look: the state dot, the title, and the age at its right; the agent, model, files changed and prompts move to the row's hover words. The pin mark stands before the title; a session needing input keeps the amber left edge and its dot, and its input words move to the hover words. Menus, rename, pin to top, archive, resume and fork work as now. Terminal rows take the same height: kind glyph, title and stamp, with Stop and its armed words on the row and the folder in the hover words. The workspace `GroupHead`s stay, inside the fold.
4. **A press.** A press on a row picks the session, so the sections below follow it, and shows its terminal or transcript in the page's Terminal tab, and a press no longer opens `session-detail` on any page. A terminal owned by another page's tab goes to that page, as now.
5. **The Sessions page goes.** The rail entry, `arrangements.sessions` and the chord `m` are deleted. `session-list`, `terminal` and `session-detail` register under `explorer`. The Explorer's group order is Files, Repositories, Sessions, Search, LaTeX, Terminal, Problems, References, the debug view, the Debug Console, Notes Graph, then Session. So s1 Files to s9 Debug, and Debug Console, Notes Graph and Session have no key (ruling 636).
6. **The right side.** `arrangements.explorer` and `workbench:` draw the right side as a column, `sizes: [0.6, 0.4]`: the empty editor pane above, and below it a pane with `terminal`, `problems`, `references` and `debug-console`, pinned. The left pane holds `files`, `repositories`, `session-list`, `search`, `latex`, with `deposit` after `repositories` on a workbench. The empty top pane is the documents pane, and a document never lands in the bottom pane. A row menu's Pinned and a notice's press (`SessionList.svelte:343`, `context.ts:703`) open `session-detail` in the documents pane rather than over the list. The Files tab keeps its Follow control and no default tab follows a session.
7. **Terminals on a workbench.** A press and New in a list limited to a folder use the page's Terminal tab where it has one, and a Terminal tab on a workbench starts in that folder (`startOf`). New, `n` and the tab's menu all start there: `folderOf` gives the page's folder for a tab with no terminal, so `showComposer` keeps it. The `documents` path stays only for a page with no Terminal tab.

   **A pinned Terminal tab stands (ruling 636).** On every page, a pinned Terminal tab left owning no terminal stays and shows its composer: `TerminalTab` carries `pinned`, and `closeEnded` and `moveInto` read it. An unpinned tab closes as now.
8. **The rail.** A tab says how much is in the view; the rail says only what needs the reader now. `repositories` and `problems` take `rail: false` and keep `tab: true`. `session-list` stays `rail: true` and gives `tone: 'amber'`, so the Explorer's button draws the needs-input count in amber and nothing while none waits. The status bar's Sessions and Problems items act on the page in front, as now (ruling 636).
9. **Comments and pages.** Every head comment and registration comment that names the Sessions page, a group or an order says what is true, and the comment of `counts` in `layout.yml` states the rule of item 8. `docs/HELP.md` describes the Sessions tab, the bottom pane, the rail's rule and the views table. No sentence anywhere names the Sessions page: `README.md:16,25`, `docs/HELP.md:85,143,455`, `layout.yml:34`, `Repositories.svelte:66` (the view's count, not a rail badge), `opening.ts:62`, `RowButton.svelte:5` if false.

The saved layout is changed once by the orchestrator at landing, as a data edit of `~/.oculus/layouts.json`: the Explorer page and each saved workbench take the new shape, the terminals the Sessions page's tabs own move to the Explorer's Terminal tab, then that page goes, with `Page.views` following. No running agent is ended, and no code reads, carries or converts the old form.

## Cases

Page cases are proved by the look at landing.

- Explorer, new page: left tabs Files, Repositories, Sessions, Search, LaTeX; top right empty; bottom right Terminal, Problems, References, Debug Console. The rail has no Sessions button, and `m` opens no group.
- A list of 200 sessions: the fold scrolls at ten rows, and the sections stand under it.
- Row height: one tree row. Tab reaches the list once, and arrows move in it.

- A row menu's Pinned and a notice's press: the Session tab opens in the top pane.
- A workbench: same shape, Deposit after Repositories; New, `n` and the tab's menu all start in the folder; Reset layout gives the shape back; a limited list shows the "In root/folder" line.
- The pinned Terminal tab's last terminal ends, and when its terminal is moved out: the tab stands and shows its composer, and the next press lands in it. An unpinned Terminal tab closes.
- Two sessions need input and 37 files changed: the Explorer's badge reads 2 in amber, its tooltip names sessions; the Repositories tab still reads 37. None waiting: no badge however many changes or problems.
- The status bar's Sessions and Problems items while on the Explorer: show their tabs.
- A debug start: Debug Console shows in the bottom pane.
- Find All References: results show in the bottom pane.
- A narrow Sessions tab: titles cut with an ellipsis and the age stays.
- A rename in a row: the field fits the one line.
- A wallpaper theme: the list and sections draw as Files does.
- No session and no terminal: the empty words, and Customizations.
- A saved page, not a new one: after the landing's data edit, the same shape, and running terminals still shown.
