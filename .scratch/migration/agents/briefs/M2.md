## What to build

1. **The vocabulary.** In `tools/oculus/config/vocab.yml`, after `venue_tiers:`, two lists in the `venue_tiers` row shape without a colour: `venue_themes:` with the 13 venue words and `data_themes:` with the 11 dataset words, each row `{ key, label }`, one row per line, a one-line comment above each saying what it lists and that a word used in the registry and missing here is a finding. The dataset labels are `theme_labels`' labels byte for byte. The venue labels are: `core-ml` Core ML, `clinical` Clinical, `high-end` High-end, `signal` Signal, `theory` Theory, `informatics` Informatics, `federated` Federated, `neuro` Neuro, `imaging` Imaging, `bio` Bio, `cs` CS, `systems` Systems, `method` Method. Rows in the order of the counts above. `HELP.md` line 157 and `DESIGN.md` line 47 name the theme words among what `vocab.yml` holds.
2. **The finding.** `Vocabulary` gains `venueThemes?: string[]` and `dataThemes?: string[]`, filled in `portfolioConfigFrom` from the two lists' keys when the config holds them, absent otherwise (then nothing is checked, as `chips`). A new check in `validate.ts`, run once per portfolio, pushes one finding per word not on its list: file the entry's `file`, key `entries[<i>].themes[<j>]` for a venue and `datasets[<i>].themes[<j>]` for a dataset (the list names the registry files use), message `theme "<word>" is not one of the venue themes` or `... the dataset themes`. A `themes` value that is not a list of strings is left to the existing shape handling; say in the report what that is. `DESIGN.md`'s "Validate" paragraph gains the clause, and a dated decision line joins the decisions list after the last one: the theme words are a listed vocabulary in `vocab.yml`, labels there, a word off the list a finding.
3. **The labels read from the config.** `Collection.themeLabels` and its read in `normalise.ts` go. `state/datasets.ts` `themeFacets` and `state/venues.ts` `themeFacets` take the label list from the config (a pure helper that turns `venue_themes` or `data_themes` rows into a word-to-label map, one helper for both, in the state layer beside them, and the word itself as the label when a row is missing). The Data view's facets, the Venues view's facets and the venue card's theme tags draw the label; the facet toggles and the held `off` list keep the word. The views read the config the way `views/Pillars.svelte` line 77 reads `venue_tiers` (`configMap()`).
4. **The hub files, in the worktree's copy, these edits only.** `registries/data.yml`: the `theme_labels:` block and its three comment lines above it are removed, and the `themes` schema row's help says the words are listed in `config/vocab.yml` `data_themes`. `registries/venues.yml`: the `themes` schema row gains the help `Theme words, listed in config/vocab.yml venue_themes`.
