## What to build

1. The dependency. `cloc` at exactly `2.6.0-cloc` in `package.json`'s `dependencies`, installed with `npm install --save-exact cloc@2.6.0-cloc` so `package-lock.json` records it.
2. The git read. One more exact form in `server/core/git.ts`: `ls-files -z` run in a given folder, through the module's one subprocess call site, answering the tracked paths relative to that folder. The module's pinned list of forms and its test take the new form; `DESIGN.md:128` says thirteen subcommands and names `ls-files -z`, "for the Status view's line counts".
3. The counter, a new server module `src/lib/server/machine/lines.ts`:
   - The files counted: `git ls-files -z` of the engine folder, minus every path under `.scratch/` (the plan's ledger), under `docs/diagrams/` (written by `npm run diagrams`) and `package-lock.json` (a lock file).
   - cloc run as `perl <cloc script> --list-file=- --by-file --json --quiet` with the engine folder as its working folder, the paths written to its standard input one per line. The script's path is resolved from the installed package (`createRequire(import.meta.url).resolve('cloc/lib/cloc')`), never a hardcoded path. List arguments only, no shell, a timeout of 60 s. The call is asynchronous, so the server keeps answering while cloc runs.
   - The folder of a path, the row it is counted under: a path with no slash is the top level; a path under `src/lib/<x>/` with at least one more segment is `src/lib/<x>`; a path under `src/routes/` is `src/routes`; any other path under `src/` is `src`; any other path is its first segment. The rule is one exported function.
   - Per file, the TODO count: the number of its lines matching the TODO rule of Decisions 3, read from the file itself.
   - The answer: `{ rows, total, counted }`. `rows` holds one row per folder in path order, each `{ folder, files, blank, comment, code, todo, languages }`, and `languages` one row per language inside it, each `{ language, files, blank, comment, code, todo }`, in descending code lines. `total` sums every folder. `counted` is the ISO time the count finished. cloc's `header` and `SUM` keys are not files and are never counted.
   - A failure (git or perl missing, cloc exiting non-zero or timing out, its output not JSON) answers `{ error }` with one sentence naming what failed, never a stack.
   - No module-level state: the module holds no cache and no timer. Each request counts.
4. The route `src/routes/api/(machine)/lines/+server.ts`: GET, the same-origin check the other machine GETs make, one call into the counter over `locals.server.engine`, the answer as JSON (200 with the count, 500 with `{ error }`).
5. The store, `src/lib/state/system/lines.svelte.ts`, registered in the client context beside the others: it fetches GET `/api/lines` the first time the view reads it, on a microtask and only in the browser, as the memories store does; `recount()` fetches again. It holds `{ count, error, loading }`. An answer whose shape is wrong is held as an error naming what was wrong, not as a shorter table.
6. The view. A new `src/lib/views/system/status/LineCounts.svelte`, drawn in `Status.svelte` after the git line and before the hooks block:
   - A heading, "Lines of code", and a line naming what is counted: oculus's tracked files counted by cloc, the plan's ledger, the lock file and the generated diagrams left out.
   - A table with the columns Folder, Files, Blank, Comment, Code, TODO and Lines (blank plus comment plus code). One row per folder, its language rows under it indented and in the muted colour, the total row last, in bold. Numbers right-aligned in tabular figures and grouped by thousands through the page's number formatting (look for an existing formatter in `state/` or `ui/` before writing one).
   - While counting: "Counting lines..."; once counted: "Counted at <time>" in the page's time format, and a Count again control (a ui/ primitive, `ToolButton`) that calls `recount()`. A failure: "The line count failed: <sentence>", with Count again.
   - Every word in `config/text/views/system/status.yml` under `status:`; colours as tokens; the table wide enough to scroll inside the view's own overflow rather than past the pane.
7. The docs. `HELP.md:128`, the Status row, adds "and the line counts of oculus's own files by folder and language, with a TODO count". `README.md:13` adds `cloc` (GPL-2.0), run as a separate Perl program to count the Status view's lines, and `README.md:5` names Perl as a prerequisite of that count (macOS and most Linux systems carry it). `DESIGN.md:128` as item 2 says.
