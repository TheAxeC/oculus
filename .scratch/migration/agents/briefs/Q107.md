## What was seen (the state file's closed log, Z99)

At about 16:15 on 2026-09-30 the Terminal tab of the page TEST, holding four shells and one Claude terminal, was gone from its pane while `tmux list-sessions` still listed all five sessions, each with 0 clients attached. No view on TEST offered them again. In the two minutes before, `src/lib/server/machine/pty/channel.ts` had been saved on main, and the running dev server loads that checkout; whether the tab closed because the server loaded that module again is not established, and nothing else was seen to cause it.

## What is on the tree (read on main at the base)

- The page closes a Terminal tab when the `sessions` payload stops listing its terminals: `endedTerminals` (`src/lib/state/sessions/terminals.svelte.ts:127-138`) takes the terminals an earlier message listed and this one does not (on the page's first message also those a tab holds), and the `afterReceive` handler (`:326-348`) passes them to `closeEnded` (`:313-324`), which takes them out of every tab and closes a tab left owning none unless the reader is composing in it (`:320`). A message with no list says nothing (`:331`). `seen` and `heard` live for the page's life.
- The server withholds the list until it has read one: `list()` answers null before any list was read, "so a page that connects in the moment after the server starts is not told that every terminal has gone" (`src/lib/server/machine/pty/channel.ts:318-325`); `refresh()` re-reads it (`:333-345`), and a failure other than "no server" is handled at `:340` onward.
- tmux runs through `src/lib/server/machine/pty/tmux.ts`. `socketArgs` adds `-S <socket>` only when a caller passes one (`tmux.ts:31-47`); no server module passes one (`grep -rln "socketArgs\|socket?:" src/lib/server` finds only `tmux.ts`), so the running server uses the tmux server of the user who runs it. With no `-S`, tmux takes the socket from `$TMUX` when that variable is set, and only otherwise from `TMUX_TMPDIR` or `/tmp/tmux-<uid>/`; `run()` (`tmux.ts:53-75`) and `control()` (`:222-231`) pass no `env`, so the server and every shell it starts inherit it. `printenv TMUX` exits 1 in the orchestrator's session, so a builder started from it has no `TMUX`. A macOS unix socket path is limited to 104 bytes, so the scratch folder's path is kept short.
- The server's own state folder is `join(homedir(), '.oculus')` (for example `src/lib/server/core/changes.ts:85-88`); Node's `homedir()` reads `HOME`.
- `npm run dev` is `vite dev` (`package.json:7`); the socket server is attached by the Vite plugin (`src/lib/server/root/vite-plugin.ts`, imported at `vite.config.ts:9`). A restart of the dev server (a save of a config dependency such as `channel.ts`) makes Vite's client reload every open page (`node_modules/vite/dist/client/client.mjs:1031-1036`, "server connection lost. Polling for restart..." then `location.reload()`).
- The socket refuses a handshake whose `Origin` does not name 127.0.0.1 or localhost, a missing one included (`src/lib/server/root/socket.ts:11-13,88`, `auth.ts:29-38`); a Node `ws` client (`ws` is in `package.json`) must be given one.
- The `sessions` payload is published by `src/lib/server/root/watch/sessions.ts:162-168` (`terminals: options.terminals === undefined ? null : options.terminals.list()`, then `hub.publish('sessions', payload)`), built in `src/lib/server/sessions/index.ts:59-60`; `src/lib/server/root/hooks.ts:277-284` republishes `hub.latest('sessions')`. `refresh()` (`channel.ts:334-345`) has no sequence guard: one start fires several change events (`CHANGE_EVENTS`, `:55-65`, each calling `refresh()` at `:290`), and `#took` keeps whichever reply resolves last (`:417-429`). A read failing with a message `noServer` takes for "no server" makes `[]` the list (`:343`).
- The page's whole workbench, every page, is saved under one localStorage key, `oculus.layout.v1` (`src/lib/state/workbench/layout/saved/storage.ts:14`), written by `savePages` on every layout change (`layout.svelte.ts`, for example `:384` `savePages({ pages: [...store.current.pages, page], current: page.id })`), and nothing listens for another browser tab's writes (`grep -rn "addEventListener('storage'" src` prints nothing). So with two browser tabs of one server open, a layout change in one saves a workbench without a Terminal tab the other added, and the reload after a restart restores that.
- The usage refresh starts `claude` in an `oculus-usage-*` tmux session at server start and every `usage_refresh_min` (`src/lib/server/usage/refresh.ts:302-305`), then kills it; the list filters it (`sessions.ts:244`).
- The Live HPC poller starts with the server and runs read-only `ssh` queries (squeue, sacct, sinfo, quota) to the host `config/behavior.yml:79` names; OpenSSH reads its config and keys from the passwd home, so a scratch `HOME` does not stop it. These are the queries the user's own server already runs, and the hub's HPC rules allow them on a login node.
- A terminal no tab owns: `showTerminal` (`terminals.svelte.ts:378-406`) already joins one to the end of the Terminal tab of the page on screen when something asks to show it; `moveTerminal` (`:415`) moves one between tabs. The row menu's Join Terminals lists the terminals other Terminal tabs own (`src/lib/views/sessions/terminal/terminal-list.ts:349-370`, label `sessions.menu_join`, `config/text/views/sessions/terminal.yml:28`). ## What to build

1. **Reproduce the closing on a server of your own.** Start the dev server from your worktree's `tools/oculus` on a port that is neither 8787 nor 8790 (for example `npx vite dev --port 8797 --strictPort`, after `lsof -iTCP:8797 -sTCP:LISTEN` shows the port free), with `HOME` and `TMUX_TMPDIR` set on that one process to folders under a scratch folder of your own in `$TMPDIR`, so its `~/.oculus` and its tmux server are its own and the user's terminals, tmux server and `~/.oculus` are never reached. Every tmux command you run names that server (`tmux -S <your TMUX_TMPDIR>/tmux-<uid>/default ...`); never run a tmux command without `-S`, and never `kill-server` or `kill-session` on any other socket. Before starting it, `printenv TMUX` must exit 1; if it prints a value, stop and hand back. Drive it the way the page does: read the write token your server hands its own page, start terminals through its start route, subscribe a WebSocket client (`ws`, with an `Origin: http://127.0.0.1:<port>` header) to `sessions`, and record every payload. Then make happen, one at a time, each event that could leave a running terminal out of a `sessions` list: the dev server loading `channel.ts` again after a save (rewrite the file with its own bytes), a restart of your server, the socket reconnecting, a start that fires several `refresh()` calls whose replies resolve out of order, a list read failing as `noServer` while sessions run, the usage session's start and kill, and anything the code shows can do it. Feed the recorded payloads to `endedTerminals` in the two shapes the page gives them: after a restart the page is reloaded, so its next list is a first list (`first = true`, `seen` empty, `held` every terminal its restored tabs hold, `terminals.svelte.ts:336-342`); after a reconnect without a reload, `first = false` with `seen` carried. The list path is reproduced when `endedTerminals` answers a terminal that tmux still lists. Then the layout path, in the unit suite: two layout stores sharing one `Storable` (`storage.ts` takes a plain object for a test), a Terminal tab added in the first, a layout change saved by the second, then a third store restoring from the storage as the reloaded page does: the layout path is reproduced when the restored workbench lacks the Terminal tab. Keep the probe script at `.scratch/migration/agents/reviews/Q107-probe.mjs` in your worktree (the only ledger file you write besides the report); the report quotes it whole with the command that runs it, and the reviewer reruns it under the same isolation. Write the red command of each path that turns red (the event, the payloads or the stores, the ids answered) into the report, run three times. When neither path turns red on the base, the report says so with every event tried and its payloads, and the step is handed back after item 3 is built.
2. **Fix the cause** of each path that turned red, at the place it occurs. The list path: in the server or the page, so that no `sessions` message leaves out a terminal tmux still runs, or so that the page never treats such a message as the terminal's end, whichever the cause is; a fix in `refresh()` is tested in flight, after `close()`, and superseded by a later read. The layout path: as open item Z115 rules (the orchestrator sends the ruling; until it arrives, build the rest and leave this fix out, saying so in the report's first line). A guard at `closeEnded` that hides a wrong list is not a fix while the list is what is wrong. A test at that place fails on the unchanged tree in the form it has after the change and passes after; the red command of item 1 is green after the fix, three runs. A terminal that really ends (its tmux session gone) still leaves its tab, and a tab left owning none still closes as today.
3. **Offer the running terminals no tab owns.** A running terminal no tab owns is one the latest `sessions` list names and no Terminal tab on any page lists in its `terminals`. Add one pure function beside `endedTerminals` that answers them, in list order, from the list and every page's Terminal tabs (hidden pages included), leaving out foreign terminals (`foreign: true`) as Join does. The bar's kinds dropdown (`kindsMenu`) and the list's empty area's menu (`emptyListMenu`) gain the item "Attach to Session" (catalog key `sessions.menu_attach`, VS Code's name for its "Terminal: Attach to Session"), a submenu with one entry per such terminal, labelled as the Sessions view's row labels it (its title, or its name when the title is empty), two terminals of one label being two entries told apart by id, drawn only while there is at least one. Its pick ids carry a prefix of their own, never read as a `JOIN` or `PROFILE` pick nor the reverse. Choosing one puts it at the end of this Terminal tab's order and shows it alone (`withTerminal`, the rule `showTerminal` uses for a terminal no tab owns, applied to this tab rather than the page's; a tab composing drops its composer, as `withTerminal` sets `composing: false`), and activates the tab. A terminal that ended, or that another tab took, between the menu opening and the pick changes nothing.
4. **Stop and clean up.** At the end, stop your server, run `tmux -S <your socket> kill-server` on your own socket only, and remove your scratch folder (the probe script is kept in the ledger copy, item 1). The report quotes `lsof -iTCP:<your port> -sTCP:LISTEN` printing nothing and `ls <your scratch folder>` failing.
5. **Docs.** `DESIGN.md:361`'s paragraph and `HELP.md:127` each say, in their own voice, that a Terminal tab offers the running terminals no tab owns under Attach to Session, and correct any sentence the fix of item 2 makes false (grep `endedTerminals`, `closeEnded`, `list()` and every name you change across `src`, `DESIGN.md`, `HELP.md` and `README.md`).

## Decisions taken in this brief (each reversible, none silent)

5. `TMUX` is not unset on the server process: it is absent from the orchestrator's session, and the builder stops if it is present, so nothing beyond Z114 (a)'s two variables touches the environment.
