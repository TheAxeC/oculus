## What to build

When the part is done, every project card whose manifest holds a non-empty `repository.url` draws that address as the first line of its address list, before the `links:` entries, on a board and on the project page alike, whatever the project's tier. A card whose manifest holds no non-empty `repository.url` draws its non-empty `code_availability.url` in that place instead, by the same rules (ruling 761 (1)); the line is called the code line below, whichever of the two it draws. A card that holds neither draws its address list exactly as now. Non-empty means non-empty after trimming, for both keys.

`src/lib/views/shared/card/project/CardAddresses.svelte` draws the code line, and stays at or under 520 lines:

- The code line is drawn as the `links:` lines are: an address `posting` answers is a link to `posting`'s answer that opens in a new tab (`target="_blank" rel="noreferrer"`), its words the address as the manifest writes it; an address `posting` gives nothing for is drawn as its words, with no link.
- The code line carries the glyph `repositories` in place of `link`, on the link and on the words alike, so it is told from a `links:` entry at a glance.
- A `links:` entry that is the code line's address is not drawn a second time: the two are the same address when their `posting()` answers are equal, or, where `posting` gives nothing for either, when their trimmed texts are equal.
- The code line has a key of the keyed `{#each}` (or its own element outside it) that no `links:` line can take.
- The list draws when either the code line or a `links:` entry is there, and not at all when neither is.
- The head comment says the component draws the repository's address first, or the code deposit's address where the manifest has no repository address, and then the manifest's `links:`, with the glyph each carries; no other comment of the card names the address lines (`grep -n "links" src/lib/views/shared/card/project/ProjectCard.svelte`), and the builder re-reads the head comment of `ProjectCard.svelte` and says in the report whether it is still true.

`src/lib/views/shared/card/project/ProjectCard.svelte` changes only `toClone` (lines 157-160) and stays at or under 520 lines: the menu's Clone row is drawn only when `repository.url` is non-empty after trimming and `repository.clones` is empty, and its tip names the trimmed address (ruling 761 (3)). The Cloned in row is not changed. The docstring above `toClone` stays true.

The report states what assistive technology reads for the code line and for a `links:` line before and after, since `Glyph` is `aria-hidden`.

"On a board" means every board that draws `ProjectCard`: the Projects boards, the listings (`Listing.svelte`, through `ProjectCards.svelte`) and the project page. The Focus board's lane card (`LaneCard.svelte`) is its own markup and draws no address lines; it is not changed (ruling 761 (2)).

No other file changes, and no word of `config/text` is added, since the line shows the address itself.

## Decisions taken in this brief (each reversible, none silent)

1. The glyph is `repositories` (`folder-git-2`), the glyph of repositories, since no glyph is named `git`.
2. The line's words are the address as the manifest writes it, as the `links:` lines show theirs; no label word is added, so no text key is needed.
3. A `links:` entry that is the code line's address, by equal `posting()` answers or, where `posting` gives none, equal trimmed texts, is drawn once, as the code line. A twin that differs by a trailing slash, by case or by its scheme is drawn twice; no manifest holds one.
4. The code line follows `posting` as the `links:` lines do: an address `posting` answers is a link, any other is words with no link. The ruling's "a link" holds for every address a manifest holds today (16 of 16 are `https`); an `ssh` or `git@host:path` address has no web page to link to. The same holds for `code_availability.url`: 15 of 16 are `https`, and the site path of algebraic-effects-compilation is words.
5. The words of the Clone row's tip are the trimmed address, so a manifest's stray spaces never reach the tip.
