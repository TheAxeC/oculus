Axel wants the folder `~/.oculus` bookmarked. A bookmark today names a file or a folder below a root, never a root's own top, so a root over `~/.oculus` could not be bookmarked as a whole. This step lets a bookmark name a root's top. ## What to build

1. **A bookmark of a root's top** (Z806, Z816). An entry with a `root` and no `path` line (or `path: ""` written by hand) names that root's top. The server's reader `bookmark()` gives such an entry the field `path: ''`, so every reader on the page (`bookmarkAt`, `markedKeys`, `bookmarkRef`, `bookmarkRows`) sees one shape and `bookmarkAt(entries, root, '')` finds it; `fs-transport.ts` is unchanged. `bookmarkRows` keeps an entry whose root is a filled text and whose path is empty, so it is a row of the rail's Bookmarks menu; `markedKeys` gives it the root row's key (`treeKey(root, '')`); `bookmarkKind` answers `folder` for it when the root is served and its folder is there, and `missing` otherwise. An entry with no `root`, or a `root` that is not a text, still names nothing. The writer is unchanged: a root's top is stored with no `path` line, as every empty field is, and a rename or a reorder of it in the Bookmarks section writes no `path` line either.
2. **The star on a root's row.** A root's own row in the Files view (`row.path === ''`, not the up row) draws the star, and the root branch of `rowMenu` (`row-menu.ts:420-436`) gains the bookmark group, Add Bookmark or Remove Bookmark, as a folder row has it. A press of either adds the bookmark or, when `bookmarkAt` finds one, removes it. The bookmark's label is the root's row name, the root key. When another bookmark already carries the root key as its label, `markLabel` answers the root key (never the empty path), the server refuses the taken label as it refuses any taken label, and the refusal is said on the refusal line, as for a file whose name and path are both taken.
3. **Drawn and opened as the root's folder.** The Files view's Bookmarks section says the root alone (no trailing `/`) for such an entry and draws it with the folder glyph; the rail's Bookmarks menu draws it as a folder with the hover the root alone (`rail.ts:33`); a press in either shows the root's row in the Files view, as a folder bookmark does, also when the root is collapsed or the Files view shows a sub-folder.
4. **The words.** HELP.md line 292 says a star is on a file, a folder or a root's row; the `SCAFFOLD` comment says an entry is a file, a folder or a root's top; `Files.svelte:40-44`, `ui.yml:9` and `views/sources/files.yml:22` say the star on a file, a folder or a root adds one; every other sentence the change makes false, found by grepping each name the diff changes across the documents and comments.

3. The server's reader gives a missing `path` as `''`, so the page has one shape for an entry; the alternative, `bookmarkAt` and each page reader treating a missing path as `''`, spreads the same rule over four places.
