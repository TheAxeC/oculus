# Brief: O25f, the Update action and the Cmd-K search

Read `../spec.md` first; it governs this package unchanged. The cockpit keeps two controls in its header beside the feed tabs (`page.py` lines 949 to 952): "Cmd-K Search", a palette over every project card, collection entry and tab by full text with a colon-command mode (`05-leads.js` lines 34 to 160), and "Update", a tray that runs one of the four update tasks (`06-tasks.js` lines 1 to 50; the server route `serve_http.py` lines 385 to 398 runs `claude -p --output-format stream-json --verbose --include-partial-messages --dangerously-skip-permissions "/research-cockpit <kind>"` in the hub root for `scout`, `litwatch`, `linkedin` and `inbox`, and streams its output). This package builds both on oculus's design: the palette as a shell overlay over the state the views already hold, and a task as a terminal.

## The acceptance list, as extracted on 2026-09-11

1. Cmd-K (and Ctrl-K) opens the palette anywhere in the workbench; Escape closes it; a `:` typed with the palette closed opens it in command mode. The rail carries a search button (`js.leads.cmdk_placeholder` is the box's placeholder; a new `app.search` and `app.search_tip` for the button).
2. The list: every view of the registry (matched on its label plus the word "tab"), every project of the snapshot (matched on title, short, eli5, results, ideas, next, latest, the venue and the tags), every entry of every collection of the snapshot (matched on every string field), the leads and the radar entries when their feeds have been fetched; a query's words each must occur, a word in the title ranks higher; the first thirty matches drawn, arrow keys and Enter pick one; picking a view opens it, a project opens its tab, an entry opens its collection view and scrolls to the entry (the instance state carries the entry id to reveal), a lead or a radar entry opens its view the same way.
3. Command mode, the query starting with `:`: `theme <name>` (the names of `config/appearance.yml`'s `themes`), `crt`, `accent <name | #hex | reset>` (the accent names the tree's `state/appearance.ts` knows), `tab <view id>`, `goto <project id>`, `help` (the help view when O28 has landed; until then the command lists as unavailable), `update` (the tray of item 4); a prefix matches, and the list shows each command with its argument hint.
4. The Update tray, opened from the palette's `update` and from a rail button (`js.tasks.update_tasks`): the four tasks as buttons (`js.tasks.lit_label`, `scout_label`, `linkedin_label`, `inbox_label` with their notes as tooltips), each starting a terminal of kind `claude` in the hub root running `claude -p --output-format stream-json --verbose --include-partial-messages --dangerously-skip-permissions "/research-cockpit <kind>"` through a `task` action of the terminal endpoint (decision 2), the terminal selected and the Terminal view opened as O25a's recover does; `js.tasks.inbox` note (`js.tasks.note_prefix` with the Gmail caveat) shown for inbox; the last run date of each task beside its button, from the feeds summary of the snapshot (`feeds.radar.lastRun`, `feeds.scout.lastRun`, `feeds.linkedin.lastPost`, `feeds.inbox.run`).

## Decisions taken in this brief (each reversible, none silent)

1. **The palette is a shell overlay.** `shell/Palette.svelte` mounted by the workbench, reading the registry and the state stores (`state/entities.svelte.ts`, `state/selectors.svelte.ts`, `state/feeds.svelte.ts`) and never a view; the index is built on open from those stores by `state/palette.ts` (`buildIndex(snapshot, feeds, views)`, `match(index, query)`, `parseCommand(query)`, `commands(config)`), pure and under test; the keyboard handling is in the shell (`shell/` is where the workbench keys live; check `shell/Workbench.svelte` or wherever the key handler is, and say where).
2. **A task is a terminal.** `server/pty/routes.ts` gains `action: 'task'` `{ kind, cols, rows }` for the four kinds, starting a `claude` terminal in the hub root with the command above (the argv built server-side, the `claude` binary from `local.yml`'s `claude_bin` when set, else `claude` on PATH), named `task <kind>`; 400 for another kind. `state/terminals.svelte.ts` gains `startTask(kind, cols, rows)`.
3. **The reveal of an entry.** A collection view, the leads view and the radar view take `reveal: <id>` in their instance state and scroll the card into view and flash it once on mount, the way the cockpit's `revealCard` does; the state is cleared after.
