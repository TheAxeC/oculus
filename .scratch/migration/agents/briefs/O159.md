## What to build

1. **The store.** A store of folder-glob matches, a type and a factory in a new file under `src/lib/data/sources/documents/` (beside `deckReader`; `deck/` already holds ten items), shaped as `IgnoredCache` is. It holds, by the key `` `${root.dir}\n${pattern}` ``, the raw matches of the walk (the strings), never `Doc` objects, which belong to one reader. Its factory takes the walk as a parameter (`globSync` by default), so a test counts the walks of the walk it passes, and a listener called when the store takes a new key (item 4). It offers: the matches of a key, read from the store or walked and kept on a miss; the keys it holds with each pattern's fixed part (the segments before the first glob character); and a drop of a key. No module-level state: the store is a value its owner makes and passes.
2. **The reader reads through it.** `DeckContext` gets the store as a required field. `under` takes its matches from the store and keeps doing per reader everything after the walk: `resolveIn`, the `path_outside` finding for a match that leaves the root (raised by every reader, a stored key included), the `present.yml` folder rule and the `existsSync(join(dir, DECK_FILE))` test, so a `present.yml` added to or removed from a matched folder is seen at the next read with no drop. The reader's own `globbed` map goes.
3. **The server owns one store, and every caller names its store.** `ServerContext` holds one store, built in `createServerContext` beside `ignoredCache()`, and `tests/server/root/context-fixture.ts` builds one for its context. It reaches every reader the server makes:
   - the watcher, given the store by `startPortfolio`, passes it to `buildHubs`, which passes it to `withDecks`, which passes it to `readDecks` (a new argument of each, the builder's choice of position or input object, named in the report);
   - the deck route's `sourceOf` (`src/routes/api/(docs)/deck/+server.ts`) puts `locals.server`'s store on the `DeckSource`, which `readDeck` hands to `deckReader`;
   - the writes: `target()` (`writes.ts`) takes the store from its `server` argument, the `WriteTarget` carries it, and `deckSourceOf` reads it from there. A target built with no server carries a fresh store from the factory, which reads as a fresh walk per target, today's behaviour; the report says which of the 8 test files that build a `WriteTarget` needed a change and why.
   The field is required at `DeckContext`, `DeckSource` and `deckReader`'s input, so no reader is made without naming its store; a test or a check that has no server (`integrity.test.ts`, `deck-hub.ts`, `hub-build.ts`, `reference-hub.ts`, `present.test.ts`, `deck.test.ts`) makes its own with the factory.
4. **The watcher hears every held glob.** When the store takes a new key (the listener of item 1), the watcher opens a recursive `fs.watch` handle on the key's root joined with the pattern's fixed part, unless a recursive handle of its own already covers that folder, at that moment, under any root (a workspace folder that is no hub included), and closes it with the others. For the research hub's portfolio deck that is a handle on `projects/`; for a pattern whose fixed part is empty (such as `**/present`) it is the root itself. A key a deck route read takes between two rebuilds is heard from that read on. The handle's callback runs the drop rule of item 5 alone; it queues a rebuild only as item 6 says.
5. **The drop rule.** A function of its own in a new file under `src/lib/server/root/watch/portfolio/`, taking the event type, the event's path under its root, whether that path is a folder now, and the held keys, and giving the keys to drop. A key is dropped when the event is a `rename` whose path lies under the key's root joined with its pattern's fixed part, has no segment in `NEVER` (`code`, `attic`), and one of these holds:
   - the path is a folder now;
   - the path is gone and is one of the key's held matches or an ancestor of one (a prefix test on the held strings);
   - the path's last name is the pattern's last segment (`present.yml` for a file pattern).
   A save through `write-file-atomic` then drops nothing: its temporary name is gone and is no match, and its final name is a file whose name is not the pattern's last segment. A `change` event never drops. The builder reads Node's documentation of `fs.globSync` for whether it enters a dot folder the pattern does not name, and, where it does not, a rename under a dot folder drops nothing; the report quotes the passage. Every recursive handle of the watcher runs the rule in `open`'s callback (`portfolio.ts:274`) before `accepts`, and so does each handle of item 4, so the drop happens at the event, before the debounce.
6. **A folder moved queues a rebuild.** A `rename` whose path is a folder now, or was one of a held key's matches or their ancestors, under a watched scan folder and with no segment in `NEVER`, queues a rebuild, so the snapshot names a moved or added project folder at its new path and a group's `tiers:` or other filter keeps its deck. This is part of the step: without it a moved deck stays out of the portfolio deck until another event.
7. **The deck acts drop at the write.** Each deck act drops the keys covering every path it makes or removes, in the same call, before it answers: `createDeck`'s `present.yml`, `outlineDeck`'s folder, and the undo's `mkdirSync` and `rmdirSync`, since the page reads the deck right after the act's answer, before the watcher's event can arrive. The other writes that make, move or remove folders (the Files view and its undo, the new-project write, the app workspace writes) rely on the watcher through items 4 and 5: none of them reads a deck in its own request, and the page reads a deck only on a later press or after the publish that follows the watcher's event.
8. **The words.** The head comments of `read.ts`, of the store's file, of the drop rule's file and of `portfolio.ts` say what the store holds, who owns it, what drops it and what the watcher hears; `docs/decks.md` is not changed (`agents/spec.md:72`; O165 rewrites it): a sentence there that the change makes false, such as one on `find.folders`, is named in the report with its line, for the orchestrator to bring to Axel.
9. **The measurement.** One program the brief approves, `.agents/O159-time.ts` in the worktree (under the ignored worktree root, never committed), run with `node .agents/O159-time.ts <hub folder>`. It times the server's answer to a filter change: `readDeck` of the hub's portfolio deck with `keep` set to a subset of its research projects, over a `DeckSource` built with no server along the path `integrity.test.ts` uses (`loadConfig`, `portfolioConfigFrom`, `buildOneHub`, `mergeHubs`). "Before" is ten reads each with a fresh store, which is the same one walk per read as the unchanged tree's one reader per read; "after" is one untimed read, then ten timed reads through the same store, as the server's store is warm from the snapshot build at start. It prints the mean and the standard deviation of each. It writes nothing. The builder runs it only over a synthetic fixture hub in a temporary folder, to show it runs, and quotes that run; the orchestrator runs it over `~/workspace/research-hub` at landing. The page's request and its drawing are outside what the step changes. No other program is written for this step.
10. **The sizes.** `context.ts` is split by concern so it ends at or under 880: one concern of `createServerContext` moved, whole, into a file named for it under `src/lib/server/root/process/context/`, the report naming the concern and why it was the one. Every other file the step changes stays at or under 880, split the same way where it would pass.
11. **The guarded entry.** G32's guarantee, "What the hub shows is what its files say", is what this step keeps for a deck folder added, moved or removed. The orchestrator widens G32's Code line in `guarded.md` to the store's file, the drop rule's file, `src/lib/server/root/watch/portfolio/portfolio.ts` and `src/lib/server/edit/writes/config/lists/deck/deck-new.ts` and `deck-undo.ts`, and adds the tests' titles from the report at landing. ## Decisions taken in this brief (each reversible, none silent)

1. The store holds the raw glob matches, not the reader's `Doc` objects, so each reader still raises its own findings and tests `present.yml` itself (item 2).
2. A drop is by the rule of item 5 alone, so an oculus save, which is always a rename of a temporary file, drops nothing, and the store stays warm through an edit of a slide followed by a look at the deck.
3. A `rename` inside `code/` or `attic/` drops nothing, as no rebuild is made for those folders today; no deck lies there in the hub.
4. The deck acts drop at the write (item 7), since the page reads the deck at once after the act's answer; every other folder write relies on the watcher.
5. The store's field is required (item 3): no reader is made without naming the store it reads through.
6. A folder renamed under a scan folder queues a rebuild (item 6), which today it does not, so the moved deck is shown.
7. G32 is widened (item 11): the guarantee of the hub showing what its files say covers a deck folder that changes on disk; no new entry is made.
8. The timing over the real hub is the orchestrator's, at landing (item 9), since the rules file lets no builder program read the real hub.
