## What to build

1. **The stage is a facet of the Filter menu.** `FACETS` gains `stage`, first in the list, so the menu opens with it. `facetValues(item, 'stage')` is the project's stage, or no value (`[]`) for a project whose stage is empty, so such a project is listed under no Stage value and has no `NONE` row. Its values are listed in the order of `preset.stageOrder`, a stage the order does not name after every stage it does (the order `stageCounts` gives today), each labelled with the `label` of its row in `stages`, so a stage reads by its label (`in preparation`, not `in-prep`), a hub's word that is also a chip or a form still reads by its stage row, and a word no hub defines reads as itself. That label is given by a new `stageLabel(stage, hub?)` beside `stageTone` in `src/lib/state/shared/words/tones.ts`, read with no hub as `chipLabel` is (the union words, the primary hub first); `chipLabel` is not used for it, since a later list's word takes the place of a stage's there (`tones.ts:118-120`). Its heading is a new text key `board.facet_stage` ("Stage") through `facetHeading`. A pick keeps the projects at the picked stages, as every facet does: with no stage picked the board shows every stage.
2. **The stage chips go.** The per-stage chips, `toggleStage`, `hiddenStages` (in `BoardState`, `QuickFilters`, `applyFilters`, `emptyBoardState`, `boardStateShape`, `parseBoardState`), `stageCounts` with its export and type `StageCount` where nothing else reads it, and `board.stage_toggle_tip` are removed. A saved board state that still holds `hiddenStages` is read without it (the shape drops an unknown field), so such a board shows every stage; no code reads or converts the old field (`spec.md`'s rule on stored data).
3. **Each facet's counts are taken over the projects the other filters leave (Z994: by hand).** For each facet F, the count of a value is the number of the board's projects that the search, stale, deadline, Mine only and every facet other than F leave, and that carry the value. The values a facet lists stay those the board's whole set of projects holds, in the order they have today, so the menu does not reflow while picking and a picked value stays in the menu; a value the other filters leave no project for is listed with the count 0. The set the board draws stays `applyFilters` over every filter; the counting reuses `applyFilters` and `facetValues` rather than a second filter rule. `parseBoardState` keeps reading the whole-board facets for its compute check, as today. The free facets (domain, pillar, funding, dataset) keep their order by the whole board's counts, so the menu does not reflow. The counting is done by `facets` itself, given the filters in force (search, quick filters and facet values) as an optional last argument, so the counts the menu draws and G92's rows run the same function; with the argument left out it counts over every project, as today. The fixture of `hub-facets.test.ts:38` gains `stageOrder: []` so `facets` can read the stage order there.
4. **The values in force are removable chips under the bar, with Clear all.** While one or more facet values are in force, a line under the bar's controls draws one chip per value in force, facet by facet in the menu's order and value by value in the order they were picked, each reading `<facet heading>: <value label>` (`Stage: in preparation`, `Funding: none`) through a new text key `board.filter_chip` ("{0}: {1}"), with the value label `valueLabel` gives, or the stored value itself for a value the board no longer offers. A stored value of a facet the menu does not offer, such as a `role` filter on a workspace that names no `self` (which `applyFilters` still applies, `state.ts:49-53`), gets its chip too, so a filter that empties the board can always be removed. The list of chips, their order and their words is a function of `filter-menu.ts` (beside `filterGroups`), read by the view, so it is state and not a DOM side effect (`spec.md:90`). Each chip has a remove control drawn after its label with the `dismiss` glyph and a label `Remove <facet heading>: <value label>` (a new text key `board.filter_remove`, "Remove {0}") as its accessible name and tooltip; pressing it takes that one value out, as unpicking it in the menu does. After the chips, a text button Clear all (a new text key `board.filter_clear`, "Clear all", with the glyph `clear_all`) takes every facet value out at once. Search, stale, deadline and Mine only are not cleared by it and draw no chip, since each is its own control in the bar. With no value in force the line is not drawn. The remove control is added to `src/lib/ui/controls/Chip.svelte` as an optional prop (`onremove`, with the words for its label), a button inside the chip after the label, reachable by Tab, and a chip given none draws as today. A chip with `onremove` is never a toggle: the remove control is drawn only on a chip given no `onclick`, so no button is drawn inside a button.
5. **Mine only is drawn only where it can change what is shown.** The Mine only chip is drawn while the workspace names a `self` and at least one of the board's projects is one Mine only does not keep (`items.some((item) => !item.mine)`, over the board's projects before any filter). On a board where every project is kept by it, the chip is not drawn and Mine only is not applied, whatever the saved state holds. The rule is a function of `src/lib/state/boards/board/state.ts`, beside `applyFilters`, read by the view; with Mine only not drawn, it is not applied to the counts either.
6. **Cards/List and title length move to the pane's toolbar.** In the `tools` snippet, after Expand all and Collapse, the header draws, as `bare` icon ToolButtons (`Pane.svelte:10-13`): Cards (`board.view_cards`, the glyph name `cards` written as the prop) and List (`board.view_list`, the glyph name `list`), the one in force pressed, a press setting the mode and a press on the one in force changing nothing; the same two buttons on a `cards: grid` board, Cards drawing the grid and List the table; and Full titles, one toggle pressed while the board draws full titles, a press switching between full titles and short handles (a new text key `board.full_titles`, "Full titles", and a new glyph name `full_titles`: `icons.yml` `full_titles: whole-word`, `glyphs.yml` `full_titles: "Aa"`, each row right after the `list` row). The bar no longer holds `ModeSwitch` or the Short/Full `Segment`. `ModeSwitch.svelte` is deleted, since nothing else draws it, and the keys only it or the Segment read (`board.view`, `board.view_cards_glyph`, `board.view_list_glyph`, `board.labels`, `project.helper.short`, `project.helper.full`) are removed with it once `grep` finds no reader.
7. **The view stays under its limit.** `Projects.svelte` is at 497 of 520 lines; the bar (the Toolbar of item 4's controls and the chips line) moves into a new partial `src/lib/views/boards/projects/FilterBar.svelte`, as `Stats.svelte` and `NewIdea.svelte` are partials of the board, taking the held state and the board's callbacks as props. Each file stays under 520 lines.
8. **The words that state the bar are made true.** The head comment of `Projects.svelte` (the bar's controls, Mine only, the facets), the doc comments of `BoardState` and of the functions changed, `filter-menu.ts`'s head comment where it names what the control's words carry, `docs/HELP.md:290` (Mine only drawn on a board where it can change what is shown, the stage as a facet, the counts over the other filters, the chips and Clear all, Cards/List and Full titles in the pane's header) and `docs/HELP.md:518` ("a board's stage buttons" becomes the stage facet), the head comment of `stages` in `config/catalogs/vocab.yml:52` ("the order every board splits its stage buttons by" becomes the order the stage facet lists its values in), the sentence "the board's Aa toggle overrides it for the viewer" in `config/defaults/layout.yml:226` and in the Settings help `config/options/layout.yml:236` (the Full titles button in the board's header), and the head comments `stats.ts:1`, `presets.ts:236` (`QuickFilters`) and `Chip.svelte:13-14` (the remove control). `docs/HELP.md:290` may become several short bullets placed right after it. Each changed sentence states what holds now, with no history.

## Decisions taken in this brief (each reversible, none silent)

1. The stage is the first facet of the menu, since it replaces the bar's most used control.
2. A facet lists every value the board's projects hold and shows 0 for one the other filters leave no project for, so the menu does not reflow and a picked value stays in it.
3. The chips line shows the facet values only; search, stale, deadline and Mine only are their own controls and Clear all leaves them as they are.
4. Mine only is drawn where one of the board's projects is one it does not keep, read from the board's projects rather than from the board's rule, so a board's rule and its data cannot disagree.
5. Cards and List are two icon buttons with the one in force pressed, and the title length is one toggle Full titles, since the header holds icon actions only (`Pane.svelte:10-13`); the glyph `full_titles` is drawn by Lucide's `whole-word` and by `Aa` under a terminal theme.
6. A saved `hiddenStages` is dropped by the reader, so a board saved with hidden stages shows every stage once; no conversion of the old field.
7. The bar moves into `FilterBar.svelte` so `Projects.svelte` stays under its limit.
8. The remove control is drawn only on a chip that is no toggle, so a button is never nested in a button.
9. A stored facet value gets its chip whether or not the menu offers its facet, so every filter that narrows the board can be removed from the bar.
10. A stage reads by its `stages` row's label through a new `stageLabel`, so a hub word that is also a chip keeps its stage label in the Stage group.
