# Brief: O5, themes and the configuration copied in

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "Configuration", "Theming", "Hot reload", "Boundaries" and the repository layout. O4 built the snapshot from a hand-typed `HUB_CONFIG_TODAY`; this package copies the cockpit's configuration into `config/`, so the snapshot is built from the files, and ports the palette and the fifteen themes with the contrast gate that guards them.

## What to build

Under `tools/oculus/config/`:

- The six files `tools/cockpit/data/config/{behavior,glyphs,layout,manifest-schema,text,vocab}.yml` copied in byte for byte (`cmp` proves it in the report), with one exception: `text.yml` also gains, under its `text:` root, the `app:` group today's `config/text.yml` holds (`app: { title: oculus }`), so every key today's code reads stays readable. `config/meta.yml` holds `meta:` with the `title` and `subtitle` of `tools/cockpit/data/cockpit.yml`; `output` (a static build target) and `doc_title` (the tab title, which is `text.app.title` here) are not carried. The copies keep their glyphs and every other non-ASCII character: `glyphs.yml` is the icon vocabulary and the others quote it. After the copy the files are oculus's; nothing reads the cockpit's.
- The catalog is one of the seven files, read like the others: `loadTextCatalog(engine)` becomes `textCatalog(config: Record<string, unknown>)`, flattening the merged config's `text` key with `flattenText`, and `hooks.server.ts` calls `loadConfig` then `textCatalog`. A `loadConfig` finding is written to stderr once per request until O6 carries findings on the socket. `text.js.*` keeps its `js.` prefix: in oculus every string reaches the browser, and renaming keys is step 8's business, not O5's.
- O4's `HUB_CONFIG_TODAY` is deleted; `tests/integrity.test.ts` and `tests/data/real-hub.probe.ts` build their config with `portfolioConfigFrom(loadConfig(engineDir()).config)` and assert the same counts as before.

Under `tools/oculus/src/lib/themes/`:

- `tokens.css`: the `:root` block of `tools/cockpit/assets/css/01-base.css` (lines 11 to 41: chrome, palette, shape, type scale, `--scan`), values unchanged.
- `themes.css`: fourteen blocks of token overrides and nothing else, values unchanged: `body.dark` from `01-base.css` (lines 42 to 46) and the thirteen named blocks of `08-themes.css` (`mocha` at line 10 through `tokyoneon` at line 188), then `body.rice` (lines 209 to 218, the shape shared by the thirteen terminal palettes: type scale, radii, shadow, `--font-ui`, and the two `font-*` declarations on body) and the `body.crt` overlay (lines 702 to 705 and 709). Rules in `08-themes.css` that name a cockpit class (`.tabbtn`, `.card`, `.thisweek`, the `body.rice .*` rules from line 219 on, lines 203 to 205 and 707 to 708) are not ported: their components do not exist, and O9 takes the terminal shape from the tokens. The report lists the rules left behind by selector so O9 can read the list.
- `derive.ts`: the derived tokens the cockpit computes at build time in `tools/cockpit/src/cockpit/contrast.py` (a fact source: port the numbers, not the shape), as pure functions with no imports: `ratio(a, b)` (WCAG relative luminance), `contrastOn(hex)` (black or white, whichever scores higher), `readable(fg, bg, minimum = 4.5)` (lightness nudged in 0.02 steps, up to 50 steps, away from the background first, hue and saturation kept, the best reached when nothing clears), and `deriveTokens(theme: Record<string, string>): Record<string, string>` producing `--on-c-<hue>` for every `--c-<hue>`, `--muted-txt`, `--accent-txt`, `--ink-txt`, and `--c-<hue>-txt` for every hue (each made readable on the hue's own `--c-<hue>-bg` when it has one, then on `--chip`, `--panel` and `--bg`, in that order; skip hues ending in `-bg`, `-txt`, `-on` and the hue `on`). `parse.ts`: `parseBlocks(css)` returning the token map of `:root` and of every `body.<name>` block, comments stripped first, and `resolveTheme(name)` merging a block over `:root`. Nothing here applies a token to the document; O8 does that when it sets the theme class, using these functions.
- `src/routes/+layout.svelte` imports `tokens.css` and `themes.css`, so the built page carries them and today's title renders in `--ink` on `--bg`.

Under `tools/oculus/tests/`:

- `contrast.test.ts`: for every one of the fifteen themes (`light` is `:root` alone; the others are `text.theme.class_<name>` applied over `:root`, `rice` included where the class string names it), derive the tokens and assert at least 4.5:1 for `--ink-txt`, `--muted-txt`, `--accent-txt` and every `--c-<hue>-txt` on each of `--bg`, `--panel` and `--chip`, for every `--c-<hue>-txt` on its `--c-<hue>-bg` when defined, and for every `--on-c-<hue>` on `--c-<hue>`. A pair that fails is reported verbatim with its ratio and never fixed by loosening the threshold or editing a colour. Also: every `var(--x)` referenced in the two sheets is defined in `:root`.
- `keys.test.ts`: every `t('...')` and `t("...")` call in `src/**/*.svelte` and `src/**/*.ts` names a key of the flattened catalog, and every `t(` call whose first argument is not a string literal fails (the test must be able to see every key). `hooks.server.ts` reads its key through a literal the test sees. Keys in the catalog that no component uses are not a failure.
- `config.test.ts`, extended: `loadConfig(engineDir())` on the real `config/` gives zero findings and the merged map holds the top-level keys `meta`, `text`, `glyphs`, `ascii`, `palette`, `status_palette`, `type_color`, `scan`, `collections`, `manifest_schema`, `read_limits`, `stale_days`.
- `static/` is deleted (it holds a scaffold `robots.txt` that a 127.0.0.1 tool does not serve to anyone); SvelteKit does not need the folder.
