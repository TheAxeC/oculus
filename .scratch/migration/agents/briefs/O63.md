## What to build

1. One hub key `audit:` holds the audit's hub conventions, each off unless the hub sets it (rulings 300 (1), 318 (1), 318 (3), Z980).
   - The hub writes it as one map in its `.oculus/config.yml`: `audit: { required_files, required_sections, website, stage_folders }`. On the hub list it is the dotted rows `audit.required_files`, `audit.required_sections`, `audit.stage_folders`, `audit.website.file`, `audit.website.list`, `audit.website.title` and `audit.website.kinds`, bound to `behavior.yml`, as `lint.writing_skip` is; `config/defaults/behavior.yml` ships `audit:` with each list empty and each website key empty, with a comment saying what it holds; `config/options/behavior.yml` describes each row in the section "Audit checks", so the Settings view shows and edits each and the editor's schema of the hub's `.oculus/config.yml` validates it as it does `lint.writing_skip`. A workspace file's `settings:` setting one gets `settings_hub_key`.
   - A new control `words` joins `CONTROLS`: a word block `{ words?, not_words?, flags?, not_flags? }`, each a list of words, the words drawn from the list the field's `from:` names (the stages for `stages`) and the flags from that list's flags. Every file that switches over a control handles it: its JSON schema (an object of those four keys, each an array of strings), its value rule and words, its fit for a write, its draft and its field in the Settings view's editor, drawn with the controls the view already has for a list of words. The options shape (`src/lib/data/shapes/catalog-files/options.ts`) and the options catalog's head comment describe it.
   - `audit.required_files`: rows `{ file, stages?, folder?, folders? }`. `file` is a path relative to the project's folder; `stages` a word block of the stage, held by `blockHolds`; `folder` a folder relative to the project's folder; `folders` a list of folders relative to the hub. The file is required of a project when every key the row names holds: its stage meets `stages`, the folder `folder` exists in the project, and the project lies under one of `folders`. A row naming none of the three requires the file of every project. A required file missing is a finding of the kind `conform` that names the file.
   - `audit.required_sections`: rows `{ file, heading, key, folders? }`. When the project's manifest holds a value at the dotted key `key`, as written in its `project.yml` (a list with an item, a text that is not empty, a number, or `true`; `false`, a map and an empty value hold none), and the project lies under one of `folders` when the row names them, the file `file` must hold the heading. A heading is held by a line, trimmed, that is the heading or that starts with the heading and a space, at the same level: `## Data + reproduction` holds `## Data`; `## Database` and `### Data notes` do not. A missing file or a missing heading is a finding of the kind `data` naming the key, the file and the heading. A manifest that does not parse gives no section finding; the manifest check reports it.
   - `audit.website`: `{ file, list, title, kinds }`. `file` is a path relative to the hub; its top-level keys are the feed's sections; `list` is the key of each section that holds its entries; `title` the key of an entry's title; `kinds` rows in the shape of today's `publication_kinds` rows (`{ kind, stages?, forms? }`, first matching row wins). The website check reads these in place of `publications_file`, `papers`, `title` and `publication_kinds`, and runs for every hub whose `audit.website.file` is set, the primary or another, each hub against its own feed. Its matching, its soft thresholds and its sections of findings are as today.
   - `audit.stage_folders`: rows `{ stages, folders }`. A project of the hub, read from the hub's own folders, whose stage meets `stages` and whose folder lies under none of `folders` (each relative to the hub, a trailing slash ignored; "under" is a whole path segment, so `projects/archive/published-old/x` is not under `projects/archive/published`) is a finding of the kind `manifest` naming the stage and the folders. A project read from a workspace repository is held to no row.
   - A row with `folders:` applies only to projects of the hub lying under one of them; a project read from a workspace repository is held to `required_files` and `required_sections` rows that name no `folders`.
   - A project of a tier `research_audit.skip_tiers` names is held to none of these checks, as the research rules are today.
   - The reader of `audit:` is a new file in `src/lib/server/content/audit/`. Every part of `audit:` that is not of its shape (a key the setting does not take, a row that is not a map, a row lacking `file`, `heading`, `key`, `stages` or `folders` where this item requires it, a `stages` that is not a word block, a `website` with `file` set and `list`, `title` or `kinds` missing, `kinds: []`, a `kinds` row without `kind`) is an audit finding of the hub, one per part, naming the hub's `.oculus/config.yml` and the dotted key down to the field (`audit.required_files.0.file`), with its words in `config/text/views/system/audit.yml`; that part is off and the rest of `audit:` runs. It runs per hub with that hub's settings, so a hub other than the primary, and a workspace with no primary, are covered.
