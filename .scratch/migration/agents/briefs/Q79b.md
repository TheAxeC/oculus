## What to build

### 1. The sweep as one fixture

- In `tests/fixtures/scratch.ts`, add the test API a file that makes scratch directories takes its cases from. It is vitest's `test.extend` with one fixture, `sweep`, declared `{ scope: 'file', auto: true }`. Its body hands nothing to the cases and calls `sweepScratch()` once they are done. Export it as `test` and as `it`, so a file writes `it(...)` and `test.beforeAll(...)` as today.
- In each of the 103 files:
  - delete `afterAll(sweepScratch);`;
  - take `it` (and `test`, where the file uses it) from `tests/fixtures/scratch.ts` in place of `vitest`;
  - drop from the `vitest` import each name the file no longer uses (`afterAll`, `it`, `test`) and `sweepScratch` from the helper import.
  - A file that calls `sweepScratch()` early from its own hook, which `scratch.ts:45` allows, keeps that call.
  - A file whose cases include `it.each`, `it.skip` or `describe.each` uses the fixture's `it`, which carries them.
- The helper's head comment says the sweep is the fixture's, and that a file takes its `it` from here. `tests/data/real-hub.probe.ts` keeps `process.on('exit', sweepScratch)`.

### 2. The scratch check

`tests/checks/tree/scratch.test.ts` holds the new rule in place of the registration rule:
- A test file that reaches the helper, directly or through a test helper that imports it, takes every case it declares from the fixture's `it` or `test`: its `vitest` import names neither `it` nor `test`.
- No test file registers `afterAll(sweepScratch)` any more. A file that does is refused, so the sweep has one registration.
- The `mkdtempSync` rule stays.
- The check reads the files through the one code reader (section 4). `withoutComments` and `codeOnly` go.
- Its cases over planted files are rewritten for the new rule. They include the refusals in "Cases".

### 3. The redundant tmpdir assertions

- Delete each `expect(resolve(<path>).startsWith(resolve(tmpdir()) + sep)).toBe(true);` whose `<path>` is the unchanged value `scratchDir` or `plantScratch` returned: the variable it was assigned to, with no `join` or other change between. The helper has already thrown on that condition.
- Keep every other one, such as a path built by `join`, handed to a spawned command, or read back from a server. Keep the helper's own check.
- An import (`tmpdir`, `sep`, `resolve`) left unused is removed.
- The report gives the count deleted and lists each kept line with its reason.

### 4. One code reader

`tests/checks/source/code.ts` is rewritten on TypeScript's parse and svelte/compiler, keeping `fileCode`, `code` and `commentLines` with their current signatures and meaning. It adds `withoutComments(name, text)`: every comment turned to spaces and every string kept, line breaks kept.
- **A module** (`.ts`, `.js`, `.mjs`) is parsed with `ts.createSourceFile`:
  - Comments are the leading and trailing comment ranges of every token, as `bin/diagrams/code.mjs` finds them.
  - Strings are the insides of string literals, no-substitution templates, template heads, middles and tails, and regular expression literals.
- **A component** (`.svelte`) is parsed with svelte/compiler's modern `parse`:
  - Its scripts are read as a module is, at their content offsets.
  - The comments of its markup expressions come from `ast.comments`.
  - Its HTML comments are its `Comment` nodes, nested ones included.
  - Its style block's comments are `ast.css.comments`.
  - Its markup text stays code, as today.
- **A stylesheet** (`.css`): its comments are those `parseCss` reports.
- **A shell script** (`.sh`) keeps the `#` rule in the same module. No parser for shell is installed, and no dependency is added for it.
- **A file that does not parse** is not guessed at: the functions throw with the file's name. Every file of the tree parses today, and a check that meets one that does not fails loudly.

These checks read through it, and their own pattern goes:
- `scratch.test.ts`;
- `keys.test.ts` (`stripComments` becomes `withoutComments`);
- `negatives.test.ts` (`commentAbove` reads the comment lines from `commentLines` of the file; `explains` keeps reading the words of a comment it is handed);
- `history.test.ts` (`isComment` for a code file becomes membership in `commentLines`; its `.yml` and `.txt` rules stay, `.yml` and `.txt` being no code);
- `boundaries.test.ts` (`selectorAt` reads the style text through `withoutComments('style.css', ...)`);
- `html-sites.test.ts`: the `{@html}` sites are svelte/compiler's `HtmlTag` nodes, each expression's source text from the node's range, so a site inside an HTML comment or a script comment is none.

`audits.test.ts`, `add-forms.test.ts` and `comment-width.test.ts` keep their calls; the API is unchanged. `comment-width.test.ts`'s `wrappable` reads the marker of a line already known to be a comment, and stays.

### 5. The folder walks on `fs.globSync`

In each of the 31 files, a function that walks a folder tree becomes one `globSync` call (from `node:fs`) with the pattern of the files it collects. A walk here is recursion over `isDirectory()`, or `readdirSync` with `recursive: true`.
- Paths come back relative to the root as the walk returned them.
- The walk's exclusions become the call's `exclude`.
- The result is sorted where the walk's callers relied on its order.
- A `readdirSync` that reads one folder's entries, not a tree, stays.
- Before converting a walker, record the list it returns on the tree. After converting it, compare the list `globSync` returns. The report states, walker by walker, that the two lists are equal, with the command that compared them.

## Decisions taken in this brief (each reversible, none silent)

1. **The sweep is one automatic file-scoped fixture.** A file takes its `it` from the helper, and no case receives a scratch value from the fixture. The helper already remembers every directory it makes, at module load, in a hook or in a case, so one sweep per file removes them all. The files keep calling `scratchDir` and `plantScratch` where they do today, seven of them at module level, which a per-case fixture value cannot serve.
   - The five real cases above: `order.test.ts` (a helper `plant` calling `plantScratch` inside cases), `size.test.ts` (scratch made inside cases), `rename-pillar.test.ts`, `pty/context.test.ts` (`const ROOT = scratchDir(...)` at module level) and `git/deposit.test.ts` (scratch made in `beforeAll`).
   - Input: `afterAll(sweepScratch);` removed, `it` imported from the helper. Output: 62 cases passed and the temporary directory count unchanged.
   - In the orchestrator's first run of the five together, two cases failed (`order.test.ts` "holds the data folders", `size.test.ts` "is on the list with a count it has not passed"). Neither failed in two later runs, together or alone, and the cause was not found. If the builder sees either fail on the converted tree, it hands back the output before going on.
2. **A redundant assertion** is one on the unchanged return of `scratchDir` or `plantScratch`; every other one stays (section 3).
3. **The code reader** is TypeScript's parse, not its bare scanner, since the scanner cannot tell a regular expression from a division. Components and stylesheets are read by svelte/compiler's `parse` and `parseCss`. The shell keeps its `#` rule in the same module (section 4).
4. **A file that does not parse throws** rather than being read by a fallback.
5. **`bin/diagrams/code.mjs` stays the diagrams' own reader.** It is a tool under `bin/`, and this step is the checks' reader. The two share the way comments are found.
6. **`agents/spec.md:34`** says tests "assert the resolved path is inside it before any write". With the assertions deleted, that assertion is the helper's. The orchestrator rewords the line at landing from the report's "Doc text" section; the builder writes nothing under `.scratch/`.
