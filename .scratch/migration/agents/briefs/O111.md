## What to build

Settings stays responsive at every keystroke, and a fold control always does what its press says.

1. **A long nested list starts folded.** A list or map drawn by `Cards.svelte` as a nested field goes under the same `Fold` a row's editor uses, with the field's name as its title and its entry count, in a new file `editors/NestedCards.svelte` that holds the nested branch, so `Cards.svelte` stays under its limit. Past `FOLD_AFTER` entries it starts folded and draws nothing, at every depth. A `single` record has no fold of its own, and its maps fold. The fold is kept per row and nested path in the Settings tab's instance state, beside the existing folds, by place: a Move or Remove of a parent leaves a held fold on the place it was at, a stated limit. `Fold`'s body id holds the path. An edit under no query keeps every list on its `path` unfolded, as `Editor.svelte` does for the row, so an Add from 5 to 6 does not fold the list under the reader.
2. **A search draws matches only.** While a query with plain words stands, a pure function in a new file `src/lib/state/system/config/view/matches.ts` walks the row's draft in order and picks the entries the query is found in, at most `SEARCH_DRAWN` (25) per row, however deep. The list holding a picked entry draws its picked entries and the lists above it open; a line under the row's list says how many more match. Show more is not drawn under a filter. An entry drawn this way keeps its real index in every use: `idOf`, `path`, `data-card`, the `{#each}` key, a slot's name, the labels, and `sparse`'s Add field. An edit, a Move or a Remove lands on the entry the reader acted on.
3. **Rules of a search.**
   - An entry matches when some plain word occurs in its values or map keys at any depth, its `kept` and `unread` included, never in `Card`'s own keys `fields`, `kept` and `order`. A part reads the same rule, on the draft. A list the query is not found in has its kept fold, and a press unfolding it draws the whole list with PAGE and Show more.
   - `plainWords` and `readQuery` become one reader of a query, so `@8` is found in an entry. A query of filters alone (`@modified`, `@id:x`) has no plain word, filters nothing and leaves the kept folds.
   - An entry the reader edits stays drawn while the query stands, uncounted, even when it stops matching, so the input is not destroyed under the caret. An Add under a filter draws the new entry last and gives it the focus, found by its card id and no longer by DOM position. A Move goes past the next drawn entry, using `by`. A Remove drops the edited set of that list. This set is the `Editor`'s own state and goes with the query.
   - An edit under a query does not write the kept fold.
   - The rail list and the Fields list are not filtered; a press folds them as item 4 says.
4. **A fold press always works.** Under a query, a press on any fold line folds or unfolds that part at once: a row's entries, its Fields list, a nested list and the rail row. The press stands for the query it was made under, under a `searchFolds` key of the tab's instance state holding the query's words and the presses, and it does not change the fold kept for an empty search. `withSettingsQuery` drops it when the query's words change, so query A, B, A does not bring it back, and `a` and `A ` keep it. Clearing the query brings the kept folds back.
5. **A row a query leaves out stays mounted.** `List.svelte` draws every row of the scope's groups and hides, with the `hidden` attribute, a row, section or group the query leaves out, so a keystroke changes attributes and mounts nothing. The table of contents, the count and the Header keep reading `found`. Whatever walks the pane's cards or headings (the card cursor in `workbench-keys.svelte.ts`, `Settings.svelte:366`, a reveal) skips a hidden row. A held cursor on a card a filter drops is cleared, as `reconcilePane` does today.
6. Words: under `settings` beside `fold_entries`, `fold_more_one` is "1 more entry matches this search" and `fold_more` is "{0} more entries match this search", in the file's form for a count.
7. Every comment that states the old behaviour says the new one: `fold.ts`, `editors/Fold.svelte`, `settings/Item.svelte` (`:26-28`, `:115`), `editors/Editor.svelte`, `RailEditor.svelte` (`:13-15`, `:75`), `Cards.svelte` (`:18-20`, `:31-33`), `search.ts`. `docs/HELP.md`'s Settings entry gains the fold rules: long lists start folded, a search draws matching entries, and a press under a search stands for that search.

Stated limits: a `FieldControl` holds local state (an Add person write-out), lost when its list folds. A problem naming an entry a filter hides is reached by clearing the query. Rows with few long lists (`agents`, `workbench`) draw as they do now. The row test in `search.ts` still reads the file's value, so a word only in a draft does not bring its row back.

## Decisions taken in this brief (each reversible, none silent)

1. Long lists fold and a search draws a capped match list, rather than a windowed list: `Cards` entries have varying heights and hold focusable controls, and the fold is what the reader already knows from a row's editor.
2. `SEARCH_DRAWN` is 25 per row, not per list, since a cap per list multiplies through nesting (about 12,500 elements for `e` on `latex_editing`, a judgment from the brief check's count). It is a constant, not a setting. Z1092.
3. A part the query is not found in keeps its kept fold, so a filters-only query and a kept row behave as they do with no query. Z1092.
4. Rows a query leaves out stay mounted and hidden, so clearing a search mounts nothing. Z1092.
5. A press under a search is held under `searchFolds` with the query's words, dropped in `withSettingsQuery`. Z1092.
