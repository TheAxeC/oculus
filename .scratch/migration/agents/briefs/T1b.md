## What to build

The sweep reads every file under `tools/oculus/tests/state/`, slow-tagged files included, test by test, and applies the rules below.

1. **Delete** each test that breaks `agents/spec.md:57`:
   - a test of behaviour whose failure costs nothing, the costs being the rule's list: lost or corrupted work, a write to the wrong file, a broken start or install, a wrong configuration or input accepted, or a view, key or command the user relies on that stops working;
   - a test of a constant, a label or catalog string, a type, a pass-through or re-export;
   - an assertion over source text (`spec.md:61`), the generation readers of `shared/words/generation.test.ts` among them;
   - a test that cannot fail on its own fixture, or that still passes with its behaviour taken out, judged by reading what the code does on that path;
   - a test whose outcome another case already gives through the same branch of the code (Z363): of such cases the one at the lowest level that reaches the branch stays (a function's own test before a test through its caller), and among cases at one level the one that reaches the most of the branch;
   - a state test of a behaviour that a test under `tests/data/` already holds at the data layer, which sits below the state layer (`tests/checks/tree/boundaries.test.ts:20`), unless it is the one case of the wiring between the two;
   - a state test that drives server code (the three listed above) for a behaviour a test under `tests/server/` already holds at the server module's own level, unless it is the one case of the wiring between the client state and the server; the report names the `tests/server/` test that holds it;
   - a test of two copies of one value held equal across a boundary no import may cross is kept when it can fail and its failure lets a wrong input through (`system/config-files.test.ts:17`, `LOCAL_NAME`); one where a side re-exports the other's value cannot fail and is a pass-through (`life/memories-message.test.ts:76`, since `server/content/memories.ts:25` and `:50` re-export `MAX_UPLOAD_BYTES`);
   - a measurement that asserts nothing a user relies on (a benchmark that prints a time and counts what it fed).
2. **Fold** cases of one outcome that differ only in their input into rows of one table, one test per outcome. Each row has a short name as its first column, and the table's title prints that name, so the verbose output names every row in full.
3. **Tag** each test that cannot run well under a second as slow, by its cause and by its time (Decision 1): the whole file with `// @module-tag slow: <reason>` as the last line of the head comment when every test left in it is slow; otherwise a slow describe with `describe(name, { tags: ['slow'] }, fn)`, and a slow single test with `{ tags: ['slow'] }` as its second argument, a numeric timeout moving into that object as `timeout`. A slow table takes its tag on its describe. A cause reached through imported code (a helper or a `src/` module that starts a process at load or in the call) counts as a cause of the test. A probe run at module load (a `tmux -V`, a `which`) is a cause for every test of the file: it moves into a `beforeAll` of the slow describe that needs it, so the quick tests load with no process; where every test needs it, the file takes the file tag. A cold-start cost that one test pays for the rest of the file moves into a `beforeAll`. A file already tagged whose tests are all quick after the sweep loses the tag.
4. **Keep** every other test. No assertion of a kept test is loosened, widened or rewritten except to fold it into a table under item 2. A kept test's title is corrected when it is false, and the word "audits" leaves the title of a kept test. A kept test's setup may lose what the test does not use, its assertions unchanged. A wall-clock margin or a fixed sleep in a kept test breaks `spec.md:64`: the wait moves to a signal or a fake clock and the assertion holds on the answer, and this is done before item 3 judges the test's tag, so a test whose only cause was the sleep stays quick. The three fixed waits listed above are such waits. An awaited `vi.waitFor` is a poll on a real 50 ms interval: where the code under test gives a signal (a promise it returns, an event, a fake clock it reads) the test awaits that signal instead; where it gives none, the `vi.waitFor` stays and the test is judged by its time under Decision 1. A file the sweep changes that is left at 880 lines or more (the size check refuses 900, `tests/checks/tree/size.test.ts:28`, and `spec.md:45` splits a file within 20 lines of it) is split by concern into files named for what they hold. A file the sweep changes keeps main's formatting and comment wrapping on every line no item changes.
5. **Comments and helpers.** Every comment under `tests/state/` that names a deleted or renamed test is corrected, in the files the sweep changes and in those it does not, and each file it changes has its head comment say once what the file tests after the sweep, opening with its layer label (`spec.md:49`): `// Layer 2, client-state tests.` for a test file and `// Layer 2, client-state test helper.` for a helper module, Layer 2 being DESIGN.md's code layer (`DESIGN.md:110`), as T1c labels `tests/server/` "Layer 2, server tests." A comment that says a revert turns a test red when none does is corrected. A file left with no test is deleted, and a describe or a `beforeAll` left with no test is deleted. A helper module under `tests/state/` imported from outside `tests/state/` keeps every export (Decision 2); a helper nothing imports any more is deleted. A helper outside `tests/state/` (the eight listed above) that the sweep leaves with no importer is named in the report for the sweep that owns its folder, never deleted. A `src/` export the sweep leaves with no importer outside its own file goes into "Doc text" for removal at landing (`spec.md:83`).
6. **The duplication allow list.** Each entry of `tests/checks/tree/allow-duplication.txt` at lines 30 and 65-110 that the sweep makes stale (its clone no longer shared) is removed, the edit being removals only; an entry that also names a T1d or T1e file is removed by the sweep whose change makes it stale, and when both do the orchestrator merges the removals at landing; a fold that makes a new clone among `tests/` is changed until `duplication.test.ts` passes, never listed.

## Decisions taken in this brief (each reversible, none silent)

1. **Slow, by cause and by time.** A test is slow when it starts a real process (git, a shell, tmux, cloc), awaits a real timer of 1 ms or more, or opens a socket (a loopback server included), in its body, in a hook it runs under, or at the load of its module; a zero-delay yield (`setTimeout(0)`, `setImmediate`, a resolved promise) is no timer. Any other test is slow when the minimum of its times over the verbose runs of its own file (`npx vitest run <file> --reporter=verbose`), at least five and every one taken counted, is 100 ms or more; the report gives every time and the load average of each run. The minimum is used because load only ever adds time; the cause rule follows the causes `spec.md:57` names and does not move with the load.
2. **Shared helpers.** A helper module under `tests/state/` that a file outside `tests/state/` imports keeps every export, so the other sweeps' files still compile; only a helper nothing anywhere imports is deleted.
3. **Per-test and describe tags.** The test and describe forms are used where a file mixes quick and slow tests, so its quick tests stay in `npm test`; a head comment states the file's tagging rule once.
4. **Measurements go.** A test that prints a time and asserts only what it fed (`client/socket-timing.test.ts`) guards no behaviour; an A/B the plan needs names its benchmark under the configuration block's `bench:`, which holds none.
5. **`vi.waitFor`.** It polls on a real interval, so it gives way to the code's own signal where there is one, and where there is none it stays and its test is timed; ruling it a cause in every case would tag tests whose first check passes at once.
6. **The head-comment label.** `Layer 2, client-state tests.`, the code layer DESIGN.md names, matching `tests/server/`'s label.
