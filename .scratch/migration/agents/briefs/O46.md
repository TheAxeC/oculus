## What to build

When the step is done: no settings or state oculus keeps live in browser storage beyond the four `sessionStorage` values listed above; every option Settings writes lands in the workspace file's `settings:` map or, for a key of the hub list, in the primary hub's `config.yml`, and never in oculus's own files; oculus's shipped values live in `config/defaults/`, their descriptions in `config/options/`; and every key of every schema the editor completes carries a description.

1. **Oculus's own config files (Open item 180, point 5).**
   - `config/appearance.yml`, `behavior.yml`, `layout.yml`, `present.yml` and `sources.yml` move to `config/defaults/` under the same names (`git mv` is not yours to run: write the new files, delete the old ones; the landing stages the moves). Their logical names stay `appearance.yml` and the others wherever a name is an identifier: the catalog's section keys, `HUB_LIST`'s `file`, `loadConfig`'s `from`, the findings, `placeOf`. Only the path on disk changes. `configNames` reads `defaults/*.yml` in place of the root `*.yml`.
   - `config/catalogs/options.yml` is split into `config/options/<file>.yml`, one per section of `options:` (`appearance.yml`, `behavior.yml`, `layout.yml`, `present.yml`, `sources.yml`, `local.yml`), each in the shape of decision 2, and the old file is deleted. `loadConfig` reads the folder `options/` itself and builds the merged map's `options` (file name to entries, as `readCatalog` reads it today) and the group help lines from the files, so no top-level key is reported twice; every reader of `config.options` is unchanged in what it gets.

   - The support for a `local.yml` inside oculus's `config/` is removed: the `configNames` exception and its comment ("local.yml is left out by name"), the sentence of `configDir`'s comment, and `isMachinePlace`'s engine case (`config-checks.ts:141-150`, `machine-file.ts`), with every test that sets one up.
