## What to build

1. **Boards registered from `boards:` (ruling 388 (a), Z1022, Z1024).** The project board views are registered from the merged config's `boards:`, one view per key in its order, the order numbers 1, 2, ... in that order; `Projects.svelte` names no board. One pure function under `src/lib/state/boards/board/` (a new module, for example `board-views.ts`) turns the merged config into the registrations; the page registers them as `registerCollections` registers the collection views (`src/routes/views.ts`, from the page data of `+page.server.ts` and `+page.svelte`), so a Settings save or a config push that adds, removes or renames a board changes the registered views as it changes the collection views, and a removed board's open tab acts as a removed collection view's does. A `boards:` entry carries `label:` and `glyph:`, each the dotted key of a text-catalog word, and oculus's six entries name the words used today (`views.projects`, `views.projects_glyph`, and so on for each). The board pane's title (`Projects.svelte:224`) reads the board's `label:`, not a key built from its id. A board naming no `label:` or `glyph:`, or a key the catalog lacks, is a config finding naming the board and the field, and the board is drawn with its key and the glyph `paper`. A board key equal to a view id a module registers or to a collection key is a finding naming the board, and that board is not registered, as `registerCollections` leaves out such a key. A rail entry may carry `project_boards: true`, set on oculus's Projects entry; the boards are registered in that entry's group (its `page:`), and the career panel's `BOARD_GROUP` is read the same way. No rail entry carrying it, or two, is a finding naming the rail (the first flagged entry read when two are, as Z1024 rules), worded beside `unplaced`, `unplaced_none` and `unplaced_twice` in `config/text/findings.yml`; with none the boards are in no group and are reached from the catalogue's ungrouped views. A `project_boards:` that is not true or false is a finding naming the entry, and the entry is read without the flag. Describe `label:`, `glyph:` in `config/options/layout.yml` under `boards:` and `project_boards:` under the rail as `unplaced_collections:` is described, and add the Settings rail editor's tick for it as the Unplaced collections tick is drawn, written back as that flag is (`src/lib/server/edit/writes/config/lists/rail.ts`, `bodies.ts`). The comments of `layout.yml` over `rail:` and `boards:` say in one sentence each what the new keys do. Follow how O78 built `unplaced_collections` (`unplacedGroup` in `src/lib/data/sources/config/rail.ts`, `registration(views, unplaced)` in `src/lib/views/boards/collection/registration.ts`) rather than a second mechanism. The five tests that call `registerAll` (premise 1) get the board views the way they get the collection views.
