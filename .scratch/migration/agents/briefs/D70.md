## Cases

1. A hub's `.oculus/local.yml` with valid keys: open in the source tab, edit a key, save: the file holds the new text, a copy of the old text is in the file history, and History's undo puts it back.
2. The same file, a save whose body sets `port: abc`: refused with the sentence naming `port`, nothing written; a source-tab create of `.oculus/local.yml` in a hub that has none, with `port: abc`: refused the same way.
3. Files view: move a file over a hub's `.oculus/local.yml`, and upload a file over it with replace; rename `.oculus/local.yml` to `local.old.yml` and back; trash it and restore it from the Trash: each done as for any file, each recorded and undoable.
4. The ops `replace` request naming a hub's `.oculus/local.yml` (as the page sends it from a search result) with `claude_bin` and another word: the file is replaced. A workspace search does not list the file, as for every ignored file (unchanged).
5. The YAML language server on a hub's `.oculus/local.yml` with an unknown key: the schema's diagnostic; hover on a known key gives its help. A file under `secrets/` or `~/.oculus` is still refused.
6. The writing rules' folder Fix All over a workspace folder over a hub's `.oculus`: the plan lists `local.yml` when it has an automatic fix, and the write applies it; a start folder under `secrets` is still refused.
7. The git discard of untracked files over a workspace folder over oculus's folder holding an untracked `config/local.yml`: the file is moved to the Trash as any untracked file.
8. Oculus's own `config/local.yml` in a workspace folder over oculus's folder: opened and saved in the source tab with the key check, copied into the file history at the save.
9. A write other than a source-tab save that leaves a hub's `.oculus/local.yml` with `port: abc` (an upload with replace, the ops replace, an undo): written; the machine read's finding names `port` and the default is in force.
10. The Settings view's "This machine" section with a primary setting `claude_bin`, `hpc_host` and two `calendars` rows, a second hub setting one `accounts` row and one `calendars` row whose label repeats a primary row: `claude_bin` and `hpc_host` show their values; `calendars` shows the primary's two lines, each with the primary's name, and not the repeated row; `accounts` shows the second hub's row alone with its name; a key set nowhere shows its default; Open file opens the file that sets the key, and for `calendars` and `accounts` each hub file that sets it.

12. A workspace with no primary whose hub sets one `mail` row: the `mail` row shows that line with the hub's name; every scalar key shows its default.
13. Trash of a hub's `.oculus` folder from the Files view, then its restore: done and undoable as for any folder, and an edit of the restored `.oculus/local.yml` changes `server.machine()`.
14. Trash of oculus's `config/` folder in a workspace folder over oculus's folder, on a scratch engine: done and undoable; the next request's config read gives the findings of the missing files, and after the restore it reads clean.
