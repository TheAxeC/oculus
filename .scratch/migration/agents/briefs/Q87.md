## What to build

1. **The dependency.** `jscpd` 5.3.3 as a `devDependency` (it runs only in the test), `package-lock.json` updated by `npm install`.
2. **The check on jscpd.** `tests/checks/tree/duplication.test.ts` runs jscpd through its programmatic API (the `detectClones` export, or the one the installed package's types name) over `src/lib` and over `tests`, as two groups kept apart as today, with `minLines: 8`, `minTokens: 50`, the formats `typescript`, `javascript` and `svelte`, and import lines ignored (`ignorePattern` `^\s*import\b`), and nothing written to disk (no report files, or a report folder under the test's own scratch directory, removed after). From jscpd's clones it keeps those whose format is not CSS, so a component's repeated style rule is not a copy, as today. Each clone is one line of output `<a>:<line> and <b>:<line> hold the same <n> lines (<mark>)`, the mark the first 12 hex digits of the SHA-256 of the clone's fragment as jscpd reports it with whitespace runs collapsed to one space. The hand scanner (`blockOpens`, `meaningful`, the window map in `copies`) goes, with its tests.
3. **The ratchet kept.** `DELIBERATE` and `HELD` stay, in the same shape and files; `allow-duplication.txt` is regenerated from jscpd's clones on this tree, one entry per clone with its reason naming where the first shared lines sit, as its head comment says; every case over the lists stays (a reason for each entry; an entry whose clone is no longer shared fails).
4. **The cases of the check** are rewritten against jscpd over scratch files, as today's are over the hand scanner: a copy is reported once, at the line it starts on; a clone under 8 lines or under 50 tokens is not reported; an import list and a style block are not copies; comments and whitespace do not hide a copy; the allow list silences one clone of a pair and not a second clone of the same pair.

## Cases

1. Two scratch files under one group sharing a 12-line function of 60 or more tokens: one line naming both files, the line each clone starts on and its mark.
2. The same function copied at 7 lines: nothing reported.
3. Two files sharing only an 8-line import list: nothing reported.
4. Two `.svelte` files sharing only a 10-line `<style>` block: nothing reported.
5. File one holds the function; file two holds it with a comment added on a line and extra spaces: reported, with the same mark as case 1's clone.
6. The pair of case 1 listed in the allow list with its mark: nothing reported; a second, different clone between the same two files: reported.
7. A file under `src/lib` and a file under `tests` sharing the function: nothing reported (the groups are kept apart).
8. On the tree as it stands after the regeneration: `findCopies` over `src/lib` and over `tests` returns nothing, and every `HELD` entry names a clone that is still shared.
9. `grep -n "blockOpens\|meaningful\|WINDOW" tests/checks/tree/duplication.test.ts` prints nothing.

The builder's first task, before any code changes: turn every case above into a test of the step, run the tests against the unchanged tree, and note each case's result. No prototype script stands in for the tests.

## Decisions taken in this brief (each reversible, none silent)

1. The thresholds are 8 lines, as today, and 50 tokens, jscpd's default: on this tree they give 79 non-CSS clones under `src/lib` (the five above are real copies of a fold or a reader), against 177 at 30 tokens (106 TypeScript, 71 markup), where short shapes such as prop lists start to count.
2. Markup clones (22 under `src/lib`) are kept, since today's check compares a component's markup lines too; CSS clones are dropped, as today's check drops the style block.
3. The mark is taken over jscpd's fragment with whitespace collapsed, so an entry of the list stands for one clone as today.
4. jscpd is a `devDependency`, since nothing in `src` runs it.
