## What to build

When this step is done, a project card's Venue tag reads the venue's tier icon, then its name, quartile and JIF, and no cost. The icon is the glyph the tier's row of `venue_tiers` names, drawn in the tier's colour, with the tier's label as its tooltip. The shipped tiers draw a crown (flagship), a star (strong) and a target (specialist); unrated draws no tier icon.

1. **The vocabulary.** Each `venue_tiers` row of `config/catalogs/vocab.yml` gains `glyph:`: `flagship` `crown`, `strong` `star`, `specialist` `target`; `unrated` carries none. `config/catalogs/glyphs.yml` gains `crown` and `target` with their ASCII stand-ins, and `config/catalogs/icons.yml` maps `crown` to the lucide file `crown` and `target` to `target`, both in each file's "tab / section icons" group, where `venue` sits (`glyphs.yml:86`, `icons.yml:85`). The description of `venue_tiers` in `src/lib/data/shapes/catalog-files/vocab.ts:532-536` names the glyph beside the colour, as `radar_buckets`' does. The comment above `venue_tiers` in `vocab.yml` says what a row holds, the glyph included, as the comment above `radar_buckets` does. The shipped config reads with no finding (G12).
2. **The options entry.** `config/options/catalogs/vocab.yml`'s `venue_tiers` entry describes the `glyph` field with `control: glyph`, as `radar_buckets` does, its help saying it is the glyph a venue of the tier is drawn with on a project card and that a tier with none draws the venue glyph; the entry's `help` names the glyph among what each tier carries.
3. **The tier read.** A tier row read by `venueTiers` carries its glyph when the row writes one (`TierRow` gains `glyph?: string`). The board item's venue gains its tier as drawn: the glyph, the tone and the label of the venue's tier row, read from the vocabulary of the project's own hub (G127), or nothing.
   - The vocabulary is that of the venue's own hub, `rootOf(venue)`, since the venue is that hub's record and its `tier` is a word of that hub's list (G127); for a venue of the project's own hub this is the project's hub.
   - The venue's `tier` names the row; a venue with no tier, or a tier the list lacks, takes the fallback row (`assignable: false`). A list with no fallback row, and an empty list, give such a venue no tier icon: a venue that has no tier is not drawn with another tier's icon, unlike `tierStrip`'s count under the last row.
   - A row with no glyph, an empty glyph, or a glyph that is a name the glyph vocabulary lacks (`hasGlyph`) gives no tier icon, so a hub's mistyped glyph never throws in `Glyph`.
   - The tone is the row's colour through `paletteTone` and the venue's hub; a colour the palette does not map, and `unrated`'s `muted`, give no tone, and the glyph is drawn in the tag's muted colour.
4. **The text.** `venueText` returns the name, the quartile and `JIF <n>` and no cost; its doc comment says so. The search keeps finding a project by its venue's cost: the haystack reads the cost beside the venue's text, so a search that found a project before this step still finds it.
5. **The card.** The Venue tag draws the tier glyph in place of the `venue` glyph, in the tier's colour (`--c-<tone>-txt`, the token pair `tests/checks/look/contrast.test.ts` measures), with the label's words kept in the tag's muted colour. A venue with no tier icon draws the `venue` glyph as today, and a project with no venue draws no Venue line, as today.
   - The tier glyph is the tag's own glyph, so `Tag`'s bracket rule holds for it: in the ASCII mode with the terminal's brackets on, each tag reads one bracket pair (`[^] <text>` for flagship, `[*] <text>` for strong, `[(+) <text>]` for specialist), never two.
   - The glyph carries the tier's label as its tip through `ui/menu/Tooltip.svelte`, as the card's facts row does, so the tip shows on hover and on keyboard focus and reaches a screen reader through the Tooltip's description; no browser `title` is used.
   - `Tag` gains what this needs (a tone and a tip for its glyph alone, under names the builder chooses and the report names); every other caller of `Tag` draws as today.
6. **The docs.** `docs/HELP.md:299` says the Venue line reads the tier's icon, with the tier as its tip, then the venue's name, quartile and JIF, and that the cost is on the Venues view. `docs/templates.md:541-546` names the glyph in the comment and gives it in the example rows, as `radar_buckets`' example does; the template still shows every key it stands for (G83).
7. **The test.** One case added to `tests/state/shared/hub-words.test.ts`, describe "the words of each hub's records", with the glyph vocabulary installed by `setGlyphs`: two hubs whose `venue_tiers` give one tier word different glyphs and colours, each hub's venue given its own hub's glyph, tone and label; a third hub whose list carries no glyph, its venues given no tier icon; a row whose glyph is empty or names no glyph giving no tier icon; and a project of one hub naming a venue of another, given the venue's hub's row. Its failing run on the unchanged tree is quoted. The unit the case tests (the file that joins a venue to its tier row) is added to G127's Code line by the orchestrator at landing, since a builder does not edit the plan's files. No other test is added.

## Decisions taken in this brief (each reversible, none silent)

1. The tier glyph replaces the `venue` glyph on the tag, so the tag reads one icon and then the text; a venue with no tier icon keeps the `venue` glyph, so every Venue tag still carries a mark. The tier glyph is `Tag`'s own glyph, so the terminal theme's bracket rule holds for it.
2. The ASCII stand-ins are `crown: "[^]"` and `target: "(+)"`, each three printable characters.
3. A venue with no tier or with an unknown tier takes the fallback row; with the shipped list that row draws no tier icon. With no fallback row it draws no tier icon, since a venue with no tier is not drawn with another tier's icon.
4. A glyph name the vocabulary lacks draws the `venue` glyph and raises no finding, as a Focus lane row naming a glyph the catalog lacks draws the Focus glyph (`docs/HELP.md:297`); a finding for a vocabulary row's glyph name would hold every vocabulary list that names glyphs (`radar_buckets`, `chips`, `stages`), which is another concern than this tag.
5. The search keeps the venue's cost, so this step changes what the card shows and not what finds a project.
6. The tier's row is read from the venue's own hub, the hub whose record the venue is.
7. The tip is `ui/menu/Tooltip.svelte`, the card's own tip, and the tone is `paletteTone`, so an unmapped colour draws muted rather than grey.
