# Brief: D1, the change log of every write

Read `../spec.md` first, its section "The principles every package is judged on" above all. The plan's D1 line (Axel, 2026-09-12 23:45): the change log of every write through `api/write`: what file, what field, from what to what, when, undoable where the write is.

## What is on the tree (written 2026-09-15 at 19:20 against 63533113; re-read at dispatch)

- Every write of the hub goes through `src/lib/server/writes.ts` `handleWrite(request, token, into)` (381 lines): the token and origin checks, then one parser per body kind from `writes/bodies.ts` in this order: `sessionWrite` (line 176, the per-session overrides under `~/.oculus`), `manifestWrite` (201, `writes/manifest.ts` `writeManifest` line 115, fields of one project.yml through `yaml-edit.ts` `setFields`), `entryWrite` (208, `writes/entries.ts` `writeEntry`), `subtaskWrite` (224), `hostWrite` (245), `newEntry` (252, `createEntry`), `reorderWrite` (265, `reorderCollection`), `deleteEntryWrite` (278, `removeEntry`), `feedFieldWrite` (293) and `feedDeleteWrite` (311, the feeds), `leadAddWrite` (322), `linkedinIdeaWrite` (329) and `linkedinPostWrite` (341), `deckWrite` (349, `writes/deck.ts`, the two lists of `config/present.yml`), `newIdea` (365, `createIdea`, a new folder). Each answers `WriteOutcome { found, changed, refused }` (line 89); `changed` is the list of fields whose bytes changed, not their values. The client is `src/lib/state/writes.svelte.ts` (`WriteAnswer` line 11, `send`, one method per kind).
- The writers read the file, edit it as text and write it back; every one has the parsed source in hand before the edit (`writeManifest` reads the manifest through the snapshot's `RawManifest`; the entry writers through `readCollection`; the deck write through `config.deck`), so the value before the edit is known at the one place the edit is made.
- The machine-local files under `~/.oculus` are JSON through `src/lib/server/sessions/json.ts` (`readJson`, `writeJsonAtomic`, `writeTextAtomic`), each with a `local.yml` override (`sessions_cache`, `sessions_overrides`, `workspaces`, `bookmarks`, `notes` in `LOCAL_KEYS`, `src/lib/data/sources/config.ts` lines 57 to 68).
- A view named Changes exists (`src/lib/views/sessions/Changes.svelte`, the git state of a session's workspace), so the log's view needs another name.
- The System group holds status, findings, gallery, hpc, usage, help, config (orders 0 to 6); package O28b, running beside this one, adds `audit` at order 7, a `HELP.md` row, a `config/behavior.yml` key and a write kind of its own, so this package's additions to those files are made where a merge keeps both; `HELP.md`'s view table names every listed view and `tests/views/help.test.ts` fails on one it does not; `tests/views/registry.test.ts` pins group and order; `tests/views/type-scale.test.ts` pins font sizes.

## The acceptance list

1. **The record.** `src/lib/server/changes.ts` (layer 2): one `Change` per write that changed something: `{ at, kind, file, key, field, before, after, undo }` where `at` is an ISO time, `kind` the body kind, `file` the hub-relative path written (or the `~/.oculus` file, or `config/present.yml`), `key` the project id, entry identity, session id or deck, `field` the field or `entries` for a whole entry, `before` and `after` the values as the writer read and wrote them (a field's value; a whole entry for a create or delete; the two lists for the deck; the folder's manifest for a new idea), and `undo` one of `field` (write `before` back through the same kind), `create` (a delete undoes it), `delete` (a create undoes it), `reorder`, or `none` where nothing can be undone (a new idea's folder). A write that changed nothing logs nothing; a refused field logs nothing.
2. **The log file.** Appended as one JSON line per change to `~/.oculus/changes.jsonl` (`local.yml` key `changes` overrides the path, added to `LOCAL_KEYS` and to `HELP.md`'s `local.yml` paragraph, which `tests/views/help.test.ts` holds to the list), through the write chain the fs writes use (`ServerContext.fsWrites`) so two writes never interleave a line; read back newest first, capped at a count `config/behavior.yml` `changes: { keep: 500 }` names (a new key), the file rewritten to the cap when it passes twice the cap. Nothing outside that file is written by the log.
3. **The wire.** `GET /api/changes` answers the newest entries, same-origin only, with `?before=<at>` for the page before; `POST /api/write` gains the kind `undo` `{ at }`: the server finds the change, checks the file still holds `after` at that field (refused with `error: 'moved'` when it does not, so an undo never writes over a later edit), writes `before` through the same writer the change came from, and logs that write as a change of its own with `undo: 'field'` pointing back (`undoes: <at>`), so an undo can be undone. `create` and `delete` undo through `createEntry` and `removeEntry`; `reorder` through `reorderCollection`; the deck through `writeDeck`; a session override through `setOverride`.
4. **The History view** (`views/History.svelte`, id `history`, System group after config and after O28b's Audit view (order 7, in flight beside this package), order 8, listed): one row per change, newest first, with the time, the kind, the file, the key and field, the value before and after (a scalar shown whole, a list or map summarised to its size with a disclosure for the text), and an undo control where `undo` is not `none`, disabled while a write is in flight and after a refusal with the refusal's sentence in the status region; a filter box over file, key and field; "load older" at the foot. The rail's System flyout gets no badge.
5. **Words** in `config/text/views/history.yml`; a `HELP.md` row and its `local.yml` paragraph; DESIGN.md's views list and one dated decision line, plus a sentence in its "Auth" or writes section saying every write is logged and where; the registry and type-scale rows.
6. **Tests**: `tests/server/changes.test.ts` (each writer's change record over a synthetic hub under `mkdtemp`, the cap and the rewrite, the JSON lines), `tests/routes/changes.test.ts` (the read, the paging, the origin refusal), `tests/routes/write.test.ts` (an undo of each kind writing `before` back, `moved` when the field changed since, an undo logged and undone again, nothing under `~/.oculus` touched: the target's `changes` path under `mkdtemp`), `tests/state/changes.test.ts`, `tests/views/history.test.ts`, and a browser case: edit a manifest field from the editor, see the row in History, undo it, see the field back.

## Decisions taken in this brief (each reversible, none silent; the shapes go to Axel through the orchestrator)

1. The log is a machine-local JSON-lines file under `~/.oculus`, not a file in the hub: the hub is the researcher's data and git already holds its history; the log is what oculus did on this machine.
2. The view is called History (`history`), since Changes is the git view.
3. `undo` is a write kind of `api/write` addressed by the change's time, refused when the field has moved since.
4. `changes.keep` in `config/behavior.yml` is the cap.
