## What to build

1. **The map in config (Z176)**: a top-level key `languages:` in `config/sources.yml`, a map of oculus's language name to a list of file-name endings: an entry starting with a dot is an extension (`.py`), any other entry is a whole file name compared lowercased (`makefile`, `cmakelists.txt`). One language per line, the endings in flow style, the comment above it saying what it is and that a file no entry matches is plain text. The tracked file holds exactly these, every ending in force today kept:
   - bash `.sh .bash .zsh .slurm`; css `.css`; diff `.diff .patch`; ini `.ini .toml`; javascript `.js .jsx .mjs .cjs .javascript`; json `.json .jsonc .json5 .ipynb`; julia `.jl .julia`; latex `.tex .latex .bib .sty .cls`; lisp `.lisp .el .scm`; makefile `.mk .mak .make .makefile` and `makefile`; markdown `.md .markdown .mkdown .mkd`; matlab `.m .matlab`; ocaml `.ml .mli .ocaml`; python `.py .pyi .gyp .ipython .python`; r `.r`; typescript `.ts .tsx .mts .cts .typescript`; xml `.xml .html .xhtml .rss .atom .xjb .xsd .xsl .plist .wsf .svg`; yaml `.yml .yaml`; plaintext `.txt .text .plaintext`.
   - c `.c .i`; cpp `.cpp .cc .cxx .c++ .hpp .hh .hxx .h++ .h .ii .ino .inl .ipp .tpp`; cmake `.cmake` and `cmakelists.txt`; lua `.lua`; ruby `.rb .rbi .rake .gemspec .podspec .ru` and `gemfile`, `rakefile`, `podfile`, `vagrantfile`; scss `.scss`; java `.java .jav`; dart `.dart`; fortran `.f90 .f95 .f03 .f08`; fortran-fixed `.f .for .f77`; jinja `.jinja .jinja2 .j2`; svelte `.svelte`; rite `.rite`.
   - Absent on purpose: `.wren`, `.dot` and `.gv` (Wren and Graphviz stay plain text).
2. **Its reader**: `languageMap(config)` in a new `src/lib/data/helpers/files/languages.ts`, narrowing `config.languages` through a zod schema beside it, answering a `Map` from lowercased ending to language (a `Map`, so a file named `constructor` or `__proto__` finds nothing inherited). Rules: a key `__proto__` is skipped; a value that is not a list drops its language; an entry that is not a non-empty string, or that holds a slash, or (for an extension) a second dot, is dropped; a language name that is not one the editor colours (the keys of `SHIKI_IDS` plus plaintext, item 4) drops its language; an absent `languages` key answers an empty map (every file plain, no finding); a value that is not a map answers an empty map. A whole name is matched before an extension, so `CMakeLists.txt` is cmake and `notes.txt` plaintext. A dotfile (`.bashrc`) has no extension (`extensionOf` answers `''`), so it is plaintext. Two languages claiming one ending, compared lowercased, keep the first in file order. The answer is computed once per config: the selector of item 3 is a `$derived`, never a parse per tree row.
3. **The finder**: `languageFindings(config)` in a new `src/lib/data/sources/config/languages.ts` (the folder goes to 10 items), re-exported from `src/lib/data/sources/config.ts`, gives one finding per dropped entry or language and per ending claimed twice, each naming the key (`config/sources.yml [languages.<name>] ...`), worded from new keys in the catalog file that holds the other `findings.config` sentences; a `languages` that is not a map is one finding. It is called from all three lists: `watch/portfolio.ts:331-340`, `context.ts:241-246` and `FINDERS` in `config-key.ts:104-110`.
4. **`file-type.ts`**: `typeOfFile(name, bytes?)` answers the kind only (`language` leaves `FileType`), so its kind-only callers do not change. `languageOf(name, map)` reads the map; `LANGUAGES`, `NAMES` and the highlight.js lookup for a file name go. `languages(map)` lists every language the map names plus plaintext. The selectors gain `languages: () => LanguageMap` read from `configMap()`, empty until the config channel has spoken. `Source.svelte:133`, `source/Editor.svelte:109`, `Merge.svelte:90`, `DiffSection.svelte:332` and `row-menu.ts:93` call `languageOf(name, selectors.languages())`; each is `$derived`, so a file opened before the config arrives is plaintext until it does, then takes its language, and a later change of the map moves it (a language removed from the map makes it plaintext).
5. **The editor's grammars** (`kit/grammars.ts`, `kit/load.ts`): `SHIKI_IDS` gains `c`, `cpp`, `cmake`, `lua`, `ruby`, `scss`, `java`, `dart`, `fortran` (Shiki `fortran-free-form`), `fortran-fixed` (Shiki `fortran-fixed-form`), `jinja`, `svelte`, and `rite` (item 6). Two lists: the eighteen ids of today load with the first editor as now; every id is registered with Monaco at `start()`, so a model can be made under any of them. Every other grammar loads when the first model of its language is made, set or picked: through a function of the kit, `ensureLanguage(name)`, which runs inside `painter`'s queue (so a grammar load and a theme paint never interleave), calls the highlighter's `loadLanguage` once per language (a second model of the same language while the load is in flight waits on the same promise), and then runs `shikiToMonaco` again with the wrap reset as `painter` does, so the new grammar gets its tokens provider. `painter` builds each new highlighter with every grammar loaded so far, so a theme change keeps them. Until its grammar has loaded, a model of `c`, `cpp`, `lua`, `ruby`, `scss`, `java` or `dart` draws Monaco's own Monarch colours, and a model of the other six draws plain; both take Shiki's colours when the load ends. A grammar that fails to load leaves that file as it was before the load (Monarch or plain), logs one console line, and does not stop the next language's load. A page torn down mid-load loads nothing more and throws nothing. A file above `editor.paint_limit_kb`, handed to the editor as plaintext, loads no grammar. The callers that make or change a model's language call `ensureLanguage`: `ui/controls/editor/Editor.svelte:268,321`, `DiffEditor.svelte:188,270` (one load for both models), and `commands.ts:33` (the picker). The head comments of `load.ts` and `grammars.ts` say so. Loading `svelte` or `jinja` brings in their embedded grammars, so Shiki's tokens then replace Monaco's for `html` and `scss` too, which the head comment says.
6. **rite**: the grammar and the language configuration of `~/workspace/cathedra/utils/vscode-rite/` carried as a TypeScript module, `src/lib/ui/controls/editor/kit/rite/rite.ts` (the folder holds the module and its registration), exporting the grammar object (`name: 'rite'`, `scopeName: 'source.rite'`) and the configuration with every value of the two JSON files unchanged; the word pattern becomes a `RegExp`. Monaco gets `setLanguageConfiguration('rite', ...)` at `start()`; the grammar loads on first use as item 5 says, from the module.
