## What to build

1. **The map in config (Z176)**: a top-level key `languages:` in `config/sources.yml`, a map of oculus's language name to a list of file-name endings: an entry starting with a dot is an extension (`.py`), any other entry is a whole file name compared lowercased (`makefile`, `cmakelists.txt`). The tracked file holds every ending in force today (the aliases above as extensions, `LANGUAGES` and `NAMES`) plus the new languages below, grouped one language per line in flow style. `.svelte` moves from xml to svelte. `.txt` stays plaintext. A comment above it says what it is and that a language not listed is plain text.
2. **Its reader**: `languageMap(config)` in a new `src/lib/data/helpers/files/languages.ts`, narrowing `config.languages` through a zod schema beside it (a map of non-empty names to lists of non-empty strings; an entry that is not text is dropped, a value that is not a list drops its language, a key `__proto__` is skipped), answering a map from lowercased ending to language. A whole name is matched before an extension, so `CMakeLists.txt` is cmake and `notes.txt` plaintext. An ending claimed by two languages is a finding on the config channel (`config/sources.yml [languages] ...`, worded from the catalog in `config/text/`), and the first language in file order keeps it. The server's config findings (`watch/portfolio.ts`'s list, `context.ts`'s start list) gain this finder.
3. **`file-type.ts`**: `languageOf(name, map)` and `typeOfFile(name, map, bytes?)` (or a shape the builder judges cleaner, the map always an argument, never a module-level variable) read the map; `LANGUAGES`, `NAMES` and the highlight.js lookup for a file name go. `languages(map)` lists every language the map names plus plaintext. The selectors gain `languages: () => LanguageMap` read from `configMap()`, empty until the config channel has spoken; every caller listed above takes it from there, and a file opened before the config arrives is plaintext until it does, then takes its language (each caller is `$derived`, so the language follows).
4. **The editor's grammars** (`kit/grammars.ts`): `SHIKI_IDS` gains `c`, `cpp`, `cmake`, `lua`, `ruby`, `scss`, `java`, `dart`, `fortran` (Shiki `fortran-free-form`), `fortran-fixed` (Shiki `fortran-fixed-form`), `jinja`, `svelte`, and `rite` (the grammar of item 5). The eighteen grammars of today load with the first editor as now; every other grammar loads when the first model of its language is made, through the highlighter's `loadLanguage`, and stays loaded for the page: `painter` builds each new highlighter with every grammar loaded so far, so a theme change keeps the colours of a language loaded since. A model whose grammar has not loaded yet draws plain and takes its colours when the load ends. A grammar that fails to load leaves the file plain and logs once on the console. The head comments of `load.ts` and `grammars.ts` say so.
5. **rite**: `rite.tmLanguage.json` and `language-configuration.json` copied into `src/lib/ui/controls/editor/kit/rite/`, unchanged; the module that registers rite says they are cathedra's VS Code extension's files, carried in oculus's tree so nothing is read from cathedra at run time. Monaco gets `setLanguageConfiguration('rite', ...)` from the copied file (comments, brackets, auto-closing and surrounding pairs, word pattern as a RegExp). `.rite` maps to rite.
6. **The code window** (`data/prose/languages.ts`): highlight.js registers `c`, `cpp`, `cmake`, `lua`, `ruby`, `scss`, `java`, `dart`, `fortran` (for both Fortran names), and `django` under the name `jinja`, so a file of these languages is coloured in the read-only code window and in a Markdown fence as in the editor; svelte keeps xml's grammar there (no Svelte grammar in highlight.js) and rite is plain there. The fence lookup `languageNamed` keeps highlight.js's names and aliases. The head comment's count and its Svelte sentence follow.
7. **The Settings entry**: `config/catalogs/options.yml` gains `languages` under `sources.yml`, a family entry (`section: Files`, or the section the builder finds the file browser's keys under), its `fields`: key, the language's name as the editor and the status bar show it; value, the extensions (with their dot) and whole file names of that language. The description says a file's language is the first match of its whole name, then its extension, and that a name outside the map opens as plain text.
8. **Docs**: `HELP.md` and `DESIGN.md` sentences that list the coloured languages or say a Svelte file is painted as xml (found with `grep -n -i "svelte\|eighteen\|highlight\|language" HELP.md DESIGN.md`, outside the lines U3, D31, Q85c and D35 write) say what this step makes true: the map in `sources.yml`, the languages coloured, rite in oculus's tree, Wren and Graphviz plain.
9. **Tests**: the cases below, each in the test file of the module it exercises: `tests/state/sources/fs/` for `languageOf` and `typeOfFile`, `tests/ui/controls/editor/kit/grammars.test.ts` and the kit's load test for the grammars and the load on first use, a new test file for `data/helpers/files/languages.ts` beside the tests of its folder's other modules (found with `grep -rln "opens-in-program\|text-kind" tests`), and `tests/views/sources/source.test.ts` where a view's language changes. `npm run diagrams` regenerates `docs/diagrams/`.

## Decisions taken in this brief (each reversible, none silent)

1. Z176 (the orchestrator, automode): the map is `languages:` in `config/sources.yml`, language name to a list of endings, a dot meaning an extension and no dot a whole file name. `sources.yml` already holds what decides how a file is read; one list per language is the shape Z78 (2) names ("the extensions of each language are one map"). Five real cases under the rule: `tools/oculus/package.json` gives json; `projects/*/code/run_all.sh` bash; `tools/oculus/src/lib/views/sources/source/Source.svelte` svelte; `~/workspace/cathedra/CMakeLists.txt` cmake (whole name before `.txt`); `~/workspace/cathedra/examples/*.rite` rite.
2. Whole name before extension, the reverse of today's order, so `CMakeLists.txt` is not plaintext; no file in today's tables changes language by it.
3. Oculus's names for the new languages are Shiki's ids, except the two Fortran forms (`fortran`, `fortran-fixed`), so the status bar shows a short name.
4. The code window registers the highlight.js grammars of the new languages (item 6), so a file shows the same language coloured in the editor and the code window; svelte and rite stay as item 6 says, since highlight.js has no grammar for them.
5. The eighteen grammars of today stay loaded at the first editor; only the new ones load on first use, which is what the plan line asks and keeps today's first paint unchanged.
6. A file opened before the config arrives is plaintext until it does (the precedent of `programApps`, "nothing until the config channel has spoken").
