## What to build

When this step is done, oculus holds no address of any outside service it searches or lists files from, and no code names a literature source, a Recover source or a journal browser. One reader reads a row of configuration, sends the requests the row describes and reads the records and fields the row names. The rows are in the hub's `.oculus/config.yml`; oculus ships none. With no row, the feature that needs it says what is missing and where it is set.

1. **The reader.** A new folder `src/lib/server/core/reader/` holds the one reader. `src/lib/server/core` is at ten items, so the step splits it by concern (decision 1) and names the split in its report. The reader takes a row, a request (the terms filled in), the `downloads` rows, the `links` rows, a fetcher and a clock, and answers records of named fields, or a refusal with a line naming the row's `name`. It holds the formats (`json`, `xml` through `fast-xml-parser`, `html` through `cheerio`, `text`, `none`), the paging kinds, the auth mechanics, the pacing and the 429 wait, and the named operations. It holds no service: no address, no parameter name, no field path, no header name and no service key appears in its code (verify 4).
2. **The row's keys**, as rulings 511 (3) and 517 (1) name them, with the additions of decisions 2 and 6:
   - `key`, `name`, `format`, `address` with `{name}` holes and the text operations `{hole|quote}`, `{hole|plain}` and `{hole|series}` (GEO's series folder, `GSE12345` to `GSE12nnn`, written as a named operation);
   - `query`: each term of the literature form (`words`, `doi`, `years`, `type`, `open_access`, `venue`, `author`, `min_cited`) to `{ param, text }`, with the holes `{words}`, `{doi}`, `{from}`, `{to}`, `{value}`, `{from-1}`, `{to+1}`, `{value-1}`; `query.doi` may name `address` and `match` instead; `join` per parameter; `query.issn`, the browser's ask by ISSN (an `address` and `match`, as `query.doi`); `query.id`, a lookup by a source's own paper id (Copy BibTeX by a Semantic Scholar id); `skip_when`; a term left empty sends nothing; a term the row neither maps nor lists is not sent;
   - `filters` and `sorts`, each a list of `{ label, params }`, a filter's `{value}` the value the reader picks;
   - `types` and `types_only`;
   - `paging` with `kind` (`offset`, `page` with `first`, `cursor` with `from`, `param`, `in: body` and `start`, `next` with `from`, `link`), `param`, `size`, `sizes` (the page sizes offered), `max`, `total`; a page shorter than asked ends the paging;
   - `params`, `method: post` and `body`;
   - `then`, a list of follow-up requests each with its own `address`, `format`, `records` and `fields`, and one of `ids` (the ids of the request before, joined by commas), `for_each` (one request per record) or `recurse` (`when`, `id`, `folder`, `max_depth`);
   - `pace: { gap, gap_with_key }` and `wait: { retry_after, reset, remaining }`;
   - `auth`, a list of `{ header | param | basic: true, row, prefix, required, help }`, each naming the `downloads` row it reads; `contact`, the parameter `literature.mailto` is sent as;
   - `records` and `fields`, a field a dotted path with `[]` for a list and `[name=value]` for the element of a list whose field has that value (Stanford's `digests[type=sha1].digest`, with `else` the md5 element and its `kind`), a CSS selector with `attr` for HTML, or a record `{ path, op, ... }` with the operations `inverted_index`, `strip` (with `prefix`), `first_byte_size`, `checksum_file`, `join` (with `by` or `parts`), `date`, `https`, `first`, `match`, `exists` and `link` (with `link` and `id`); a field record may carry `kind` (the checksum's kind) and `else` (the field read when the first is empty);
   - `none_when`, a path whose presence in an answer means no hits (Scopus's empty result, one `error` entry), and `missing: none`, an answer status read as no hit (a DOI lookup's 404);
   - for a Recover row also `archive` (Kaggle's and PhysioNet's whole-set download), `access` (decision 2), `pick` (the entry field whose values pick the files to list: DANDI's `assets`, TCIA's `series`, Hugging Face's `patterns`, with `glob: true` for a glob, and the source's `files`), `{hole|path}` (a hole of several segments joined by `/`, each segment encoded: Kaggle's `owner/slug`), `clash` (the record field a repeated file name is put under: figshare's article id) and `pace.field` (the entry field that gives the gap between downloads: PhysioNet's `throttle`).
   A key the reader does not know, and a key missing that the row's format needs, is a finding of the hub's `config.yml` the moment the row is read, through the options catalog of item 9, never a failure at a search.
3. **Values that reach a request.** Every hole filled from a term, an entry's field or an answer is percent-encoded for the part it fills: a parameter value as a query component, an address path hole as one path segment, so `../`, `?`, `#`, `&` and a space never change the address's shape. A row whose `address` (or a `then` or `archive` address, or a `links` address) is not `https:` is not read and is a finding naming the row. A row with an empty `key`, two rows of one list sharing a `key`, and a `links` key twice are each a finding naming the row. `literature.sources` and `links` written in a hub other than the primary are a finding of that hub's `config.yml`, as every primary-only key of HUB_LIST is. The `downloads` secret reaches only the header or parameter the row's `auth` names on requests to that row's addresses, never a log line, an error, a refusal's line, the route's answer, a channel or a cache key (G3 and G113 hold as written).
4. **The literature sources.** `literature.sources` is a list of reader rows, read from the primary hub (ruling 518 (1)). The Literature search lists the rows in their order, each by its `key` and `name`; `LITERATURE_SOURCES`, the `literature.source_<id>` words and the adapters are removed. A row whose `auth` entry carries `required: true` and whose `downloads` row is missing is off with the line that says which `downloads` row to add and the entry's `help` (as WoS and Scopus are off today); one with an optional key is asked without it. `pace` and `wait` replace the waits written in code: a 429 stops the source with state `limited` and its `wait_s` read through the row's `wait` keys, with no wait and no retry, as today (G3's row stays). A DOI lookup answered 404 is no hit, not a failure; an answer holding the row's `none_when` path is no hits. The merge (G45), the cache, the form and the BibTeX copy keep their behaviour; the BibTeX lookup reads its DOI, arXiv and Semantic Scholar addresses from the rows' `query.doi`, `query.id` and `links`, and the words `copied_arxiv` and `copied_semantic_scholar` give way to one word naming the row's `name`. The help of `literature.per_source` (`config/options/behavior.yml:651`) names no service: each source's cap is its row's `paging.max`. With no `literature.sources`, the Literature search says no source is configured and that `literature.sources` of the primary hub's `.oculus/config.yml` sets them, in Settings.
5. **The Recover sources.** `recover.sources` is a list of reader rows, each hub's own serving that hub's datasets (ruling 518 (1)). Fetch's credentials (`src/lib/server/machine/runs/recover/local.ts`, `cluster.ts`, `plan.ts`) are built from the row's `auth` (`basic`, or a header with its `prefix`, Synapse's `Bearer `) in place of the service list `['physionet', 'kaggle', 'synapse']`, the curl config at mode 600 and removed at the end as today (G113); `recover.svelte.ts` takes any `service` word. A source of a kind that is stated on the card (`library`, `request`, `derived`) has no row, no Recover control and no missing-row line, as today; the card's Recover control (`FETCHED_KINDS`, `retrieval.ts:175-184`) is drawn for a kind its hub's `recover.sources` names. A source whose kind no row of its hub names says so, naming `recover.sources` of that hub's `.oculus/config.yml`, and sends no request. G111 to G114 hold as written: the file lists, the states, the writes and the access answers are the same for every kind as today.
6. **The links.** `links` is a list of `{ key, address }` with `{id}`, read from the primary hub. A `links` address holds `{id}` and may hold other holes filled from the hit's fields (Europe PMC's `{source}`, so a hit whose source is not `MED` keeps it). The literature rows' `link` operation, the BibTeX lookup, the Lit Watch feed (`src/lib/server/edit/feeds/literature.ts`), the page's literature lookup, merge and Google Scholar link (`src/lib/state/feeds/literature/`) and the lint view's ShellCheck link (`src/lib/server/machine/runs/lint/readers.ts`) build their addresses from it. A link whose row is missing is not drawn; nothing falls back to a written address. The page reads the rows through the configuration it already receives.
7. **The journal browser.** `venues.browser` is one reader row, each hub's own serving that hub's venues (ruling 518 (1)); a hub with none shows no browser. oculus asks it only on a reader's press, one request per press, each with a User-Agent naming oculus and its version; no request runs in the background, at start or on a refresh (ruling 511 (1) (a)).
   - (a) A venue's entry gets `issn` (a list), `fee` and `open_access` (ruling 517 (2) (a)); the venue card draws the fee line and the open-access status from the stored fields, and a "Read from the browser" press on a card whose venue has an ISSN asks the browser by that ISSN through the row's `query.issn` and writes `fee` and `open_access` into the entry through the write chain, with its History record. A venue with two ISSNs is asked by the first, then by the next while no hit answers, and the line names the ISSN that answered. An answer with no hit, or with several, writes nothing and says so. A venue with no ISSN draws the press disabled with the reason.
   - (b) A new view, the journal browser, in the Registries group beside Venues (`src/lib/views/sources/venues/`), searches the configured browser by words with the filters and sort orders the row names and its page sizes; each hit shows its title, ISSN, publisher, fee and open-access status, and an Add press writes the hit into `venues.yml` as a new entry with `name`, `issn`, `fee` and `open_access` filled, through the collection's Add (G134); a hit with no ISSN is added with the fields it has and no `issn`.
   - The UT row's selectors are read off the browser's page once at the build: one request to `https://library.wur.nl/WebQuery/utbrowser` with a words query, and one by an ISSN, each its HTML saved as a recorded answer; no other request to the library is made during the build.
   - A recorded answer is fetched with one `curl -sS '<address>'` whose output is printed to the terminal, never redirected to a file, and written into the answers folder with Write: the UT browser's two pages and one answer per public literature source to the words query of case 1, with no key and no `downloads` row. WoS and Scopus, which no key on this machine reaches, are written by hand from their adapters' zod shapes (`wos.ts`, `scopus.ts`). No other request leaves the machine during the build.
8. **The keys out of `local.yml`.** The six keys `literature.wos_key`, `literature.scopus_key`, `literature.scopus_insttoken`, `literature.openalex_key`, `literature.semantic_scholar_key` and `literature.ncbi_key` are removed from `config/options/local.yml`, `local.ts` and every reader; `literature.mailto` stays. A `downloads` row's `service` is any key a row's `auth` names (`DOWNLOAD_SERVICES` removed); a `downloads` row no row names is read and unused. A `local.yml` still holding one of the six keys reads it as a key the reader does not know, and nothing reads its value (no migration code). `LITERATURE_NAMES` and its use in Settings' defaults (`machine-defaults.ts:19-24`, `:78`), `machine-values.ts:20`, `:60`, the re-exports of `src/lib/data/sources/config.ts:28-32` and `tests/routes/hubs/machine-answer.test.ts:86`, `:126` follow: the six keys leave them, and the `downloads` rows are shown as the rows they are.
