## What to build

1. **Actions on hover.** On the Command centre rows, the Tasks rows, the collection entry cards and the project cards, a row's or card's action controls are drawn only while the pointer is over it or the keyboard focus is inside it (transparent, still in the layout so nothing shifts, still in the accessibility tree and reachable by Tab); the one control a row exists for (a task's done tick, a card's title link) stays visible. A card whose actions still do not fit one line puts the ones past the line into one `ui/Menu` ("More", its label from the catalog) at the line's end, so no action row wraps.
2. **One filter control.** The Projects boards draw one "Filter" `ui/Menu` in the toolbar whose items are grouped under each facet's heading, a ticked item per value in force, and a count of the values in force on the control; the row of eleven menus is gone. Every filter the row offered stays reachable. If `ui/Menu` has no group headings, add them to it (the one `ui/` file this step may edit), with its tests.
3. **Long text.** A card's long description is clamped to four lines with a "Show more" control that opens it whole and "Show less" that closes it; which cards are open is kept in the view instance's state, so a tab switch keeps it. A description that fits shows no control.
4. **No voids.** The card grids of the boards and collections lay cards out in rows that start at the same top, in file order, with no empty cell left beside a short card; no reordering (`grid-auto-flow: dense` is not allowed, since it breaks the order).
5. **Subtasks.** A card with no subtasks draws no subtasks block; adding the first subtask is one of the card's actions (item 1). A card with subtasks draws the block as today.
6. **The Map's labels.** Labels of nodes placed close together do not overlap: a label that would overlap one already drawn is hidden until its node is hovered or selected, the selected and hovered nodes' labels always drawn on top.
7. **Lit Watch's source line** ends in an ellipsis inside its card, the whole text in the tooltip.
8. **Memories** draws a placeholder of the photo's box (a muted surface of the final size, no layout shift when the photo arrives) while a photo loads, and the photo's alt text when it fails.
9. **The project view** draws its documents once: the card's `CardDocs` list is left out of the card drawn at the top of the project view (a prop of `ProjectCard`), and the view's own section stays.
10. **The editor's help.** Every `help:` in `config/manifest-schema.yml` says what the field holds and how to fill it, in the reader's words; how the value is stored or moved (a folder move, set by the folder) is said in the reader's terms ("Set by the folder the project is in; move the folder to change it"). No field loses its help.
