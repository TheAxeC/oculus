## What to build

Under `tools/oculus/src/lib/server/`:

- `deposit-git.ts`: the git and `gh` calls of the deposit, in a module of its own with its own gate, since `git-write.ts`'s gate forbids `--force` anywhere in its source and the snapshot mode of this package needs it once. One `run(cwd, args, timeout)` through `execFile` with list arguments (the shape of `git-write.ts` lines 71 to 95, with a recorder as at lines 59 to 61) and one `gh(args, timeout)` the same way, both only for a `cwd` under the mirrors folder (`~/.oculus/deposits/`, resolved at the call the way `sessions/overrides.ts` lines 23 to 26 resolve `~/.oculus/sessions.json`; an option overrides it for tests). The git subcommands it may run: `clone`, `init`, `remote`, `add`, `rm`, `ls-files`, `status`, `diff`, `commit`, `push`, `branch`, `switch`, `rev-parse`, `log`, `check-ref-format`, `symbolic-ref`. `--force` appears at exactly one call site, in `snapshot`. The `gh` calls: `repo view <name> --json url,defaultBranchRef`, `repo create <name> --public|--private --source <mirror> --remote origin --push`, `repo edit <owner/repo> --description ... --homepage ... --add-topic ...`. Timeouts: ten seconds for a local command, 120 seconds for `clone`, `push` and every `gh` call. Every result `{ ok, output, error }`, never a throw.
- `deposit.ts`: the library over one project. `mirrorOf(id, config)` is `~/.oculus/deposits/<repo>/`, `repo` being `code_availability.repo` or the project id. `adopt(id)` makes the mirror when there is none: `git clone` of the GitHub repository when `gh repo view` says it exists (the history of a project that already is a public repository, the engram case), else `git init` with `main` as the branch and no remote yet. `sync(id)` empties the mirror's checkout of everything but `.git`, copies `code/` in (never `.git`, `__pycache__`, `*.pyc`), writes the mirror's `.gitignore` from the patterns of `code/.gitignore` and `code/.depositignore` (comments dropped, `attic/` added when there is no `.depositignore`), and runs `git add -A`; it answers the plan: the files that would ship (`git ls-files`), what changed against the mirror's last commit (`git status --porcelain`), the scan findings (the names, suffixes and the 25 MB limit above; a missing `README.md` is a finding), and whether the mirror has a remote. `commit(id, message)` commits what `sync` staged (`-F <file>` as `git-write.ts` line 188 does; an empty message refused; refused when the scan has findings). `push(id)` pushes the mirror's current branch to its upstream, or `gh repo create` when the mirror has no remote (the visibility from `code_availability.visibility`, public by default), then sets the About from the manifest's `description`, `homepage` and `topics` when any is set, then writes `code_availability.status` (`deposited`, or `review-anon` for a private repository), `url` and `date` through `writeManifest` of `server/writes.ts` lines 134 to 200 (the one manifest writer, which keeps every other byte of the file). `snapshot(id, message)` is the mode of today kept as a second button: an orphan commit of the synced tree (`git switch --orphan` in the mirror, then the commit) force-pushed to `main`, the mirror's `main` reset to it; history on the remote is gone after it, which is what the confirm says. `branches(id)`, `createBranch(id, name)`, `switchBranch(id, name)`: as `git-write.ts` does on a workspace, in the mirror; a switch is refused when the mirror's tree is dirty, and after a switch the mirror's checkout is copied back into `code/` (everything but `.git` and the generated `.gitignore`; the hub then shows the tracked files of `code/` as modified, which is the record of the switch, and `results/`, `figures/` and `attic/` of `code/` are left as they are since the mirror never held them).
- `deposit-routes.ts` and `routes/api/deposit/+server.ts`: `POST /api/deposit` with `{ action, id, confirm, ...fields }` token-guarded and same-origin the way `handleGit` is (`git-routes.ts` lines 142 to 188, with an options bag of the same kind at lines 61 to 68 so the route test stubs every operation): actions `adopt`, `plan` (`sync`), `commit` (`message`), `push`, `snapshot` (`message`), `branches`, `createBranch` (`name`), `switchBranch` (`name`); `confirm: true` required for `commit`, `push`, `snapshot`, `createBranch` and `switchBranch`. `GET /api/deposit?id=` answers the mirror's state: whether it exists, its branch, its remote URL, ahead count, the last plan when one was made in this process. `id` must be a project the portfolio holds (the `target()` of `server/writes.ts` line 246 and the snapshot in the hub's last `portfolio` payload through the hook bridge, `sessions/hooks.ts` lines 122 to 130 for the pattern); anything else answers 404.

Under `tools/oculus/src/lib/views/`:

- `Deposit.svelte`, registered as `deposit` in `routes/views.ts` beside `editor` (lines 83 to 89: unlisted, instance state `{ id }`), opened from the project tab's card by a "Deposit" control beside "Edit manifest" (`Project.svelte` lines 236 to 240, `openView('deposit', 'panel', { id })`). It draws: the mirror's state line (repo name, branch, remote or "no remote yet", ahead); a "Plan" control (`sync`) and the plan it answers (the file count, the changed paths with their letters, the scan findings in the warning tone, a note when `README.md` is missing); a commit box with a `TextArea` and a "Suggest" that fills it from `POST /api/git { action: 'suggest', root: <mirror> }` (the mirror is under `~/.oculus/deposits/`, so `git-write.ts`'s `allowedRoots` gains the mirrors folder as a third source beside the published workspaces and the hub; `tests/server/git-write.test.ts` gets one case for it); the commit control behind a confirm; the push control behind a confirm naming the remote, or "create the repository" when there is none; the snapshot control behind a confirm that says the remote's history is replaced; the branch `Menu` and the new-branch `TextInput` as `Changes.svelte` lines 305 to 336 draw them, the switch confirm saying `code/` will be overwritten with the branch's files. Every control is disabled with its reason while the plan has findings (commit, push, snapshot) or while a request is in flight. `ui/Confirm.svelte` is the dialog.
