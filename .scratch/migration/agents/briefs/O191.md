## What to build

The seven facets Situation (`status`), Domain (`domain`), Waiting on (`waiting`), Venue (`venue`), Pillar (`pillar`), Datasets (`dataset`) and Form (`form`) give a project with nothing in that field the value `NONE`, as Year, Funding, Compute and Code do now (ruling 781). A group that would hold the value for none alone is not drawn, and the Venue bars compare named venues only (ruling 782).

1. `src/lib/state/boards/board/state.ts` `facetValues`: each of the seven returns `[NONE]` where it returns no value today: an empty list for `status`, `pillar`, `dataset` and `waiting`, a `null` for `domain` and `venue`, an `undefined` for `form`. Hub, Tier, Role, Slice, Reproduced and Sessions are unchanged. The head comment is rewritten so it states, for every facet it names, what a project with nothing there carries, and stays true.
2. `src/lib/state/boards/board/facets.ts` `orderValues`: Situation and Form list their named values in the order they list them now, then `NONE` last when a project carries it. The other five already list it last; their branch is unchanged.
3. `src/lib/state/boards/board/filter-menu.ts` `valueLabel`: `NONE` of each of the seven is drawn with its own words, from new strings under `board:` in `config/text/views/boards/projects.yml`, placed in the file's key order. The words are ruled (ruling 781) and are the requirement:
   - Situation: `No situation`
   - Domain: `No domain`
   - Waiting on: `Not waiting`
   - Venue: `No venue`
   - Pillar: `No pillar`
   - Datasets: `No dataset`
   - Form: `No form`
   The keys follow the file's form `no_<thing>`, as `no_year` and `no_funding`: `no_situation`, `no_domain`, `no_waiting`, `no_venue`, `no_pillar`, `no_dataset`, `no_form`. Each `t('board.no_...')` is a literal key, so `tests/checks/source/keys.test.ts` sees it.
4. `filter-menu.ts` `filterGroups` (ruling 782 (1) (a)): a facet whose values, offered and picked, are the value for none alone draws no group, unless the value for none is picked, in which case the group is drawn with that one row so it can be taken out. This holds for all eleven facets that have a value for none: the seven above and Year, Funding, Compute and Code. A facet with a named value beside the value for none draws its group as today. The head comment is rewritten to state the rule. Since the board, the Present view, the Map's bar and a collection page's Projects section all draw through `filterGroups`, the rule holds on each with no change in their files.
5. `filter-menu.ts` `choicesOf` (ruling 782 (2) (a)): the Venue choice of the value for none carries no `share`, so no bar is drawn for it, and `most` is the largest count over the named venues only, so the named venues' bars are scaled against each other.
6. A pick of a value for none narrows the board to the projects with nothing in that field, alone or beside named values of the same facet (an OR within the facet, as today), and counts like any value under the other facets' picks. This follows from item 1 through `applyFilters` and `countValues` and needs no code of its own.
7. `src/lib/state/boards/board/presets.ts:44`, the head comment of `NONE`, is rewritten to name every facet that gives it.
8. Every sentence the change makes false is carried in the same step: grep each changed name and the phrases "no value" and "draws no group" across `src`, `tests`, `config` (with `--exclude=local.yml`), `docs` and `README.md`. `docs/HELP.md` and `docs/data-map.md` are not written (`spec.md`, a step writes them only with a ruled line); a sentence there the change makes false goes into the report's "Doc text".
