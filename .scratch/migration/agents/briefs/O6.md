# Brief: O6, the socket and the portfolio watcher

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "Server" (the socket, watchers), "Client state", "Hot reload", "Boundaries", and the decision of 2026-09-10 on live data. O4 builds the snapshot and O5 reads the config from `config/`; this package carries both to the browser over one WebSocket and rebuilds them when a file changes, so the bare page shows the snapshot version tick when a manifest is edited.

## What to build

Two dependencies, the only ones this package may add: `ws` (runtime) and `@types/ws` (dev), installed with `npm install ws` and `npm install -D @types/ws`, versions reported. Node 24 has a WebSocket client and no server, which is why.

Under `tools/oculus/src/lib/server/`:

- `channels.ts`: the protocol with no socket in it, so it is tested without one. A `Hub` holds, per channel, the latest payload and a version that starts at 0 and increments on every `publish(channel, payload)`. A client is a `Sink` (`{ send(text): Promise<void>; close(): void }`) with a set of channels; `subscribe(sink, channels)` sends the current message of every named channel that has one, at once; `publish` sends to every subscriber of the channel. Latest only: a sink whose previous send has not completed gets no message queued; it is marked pending and receives the latest message of that channel when the send completes, so a page that fell behind sees the newest state and never a backlog. `remove(sink)` on close. Messages on the wire are `{ channel, version, payload }` as JSON; the one message a client sends is `{ type: 'subscribe', channels: string[] }`.
- `socket.ts`: `attachSocket(server: http.Server, hub: Hub, options: { path: '/ws' })` using `ws`'s `WebSocketServer({ noServer: true })` on the server's `upgrade` event. The upgrade is refused with 403 and the socket destroyed unless the request's `Origin` header parses as a URL whose hostname is `127.0.0.1` or `localhost` (any port, since Vite's dev port differs from the built server's); a missing `Origin` is refused too. This is the read side of the auth DESIGN.md describes; O11 adds the write side.
- `watch/portfolio.ts`: `watchPortfolio(hub: Hub, paths: { hub: string; engine: string }, options: { debounce: 200 })`. On start: `loadConfig`, `portfolioConfigFrom`, `buildPortfolio`, and publish `portfolio` (the snapshot, version passed through from the hub's channel version) and `config` (payload `{ config, text, findings }`: the merged map, the flattened catalog, the config findings). Then `fs.watch` with `recursive: true` on every `scan:` directory, on the directory of every registry and collection file, and on `<engine>/config`. An event is ignored unless its filename ends in `.yml` and no path segment is `code` or `attic`; the rest are debounced (200 ms after the last event) into one rebuild. A change under `<engine>/config` republishes `config` and `portfolio` (the vocabulary may have changed); a change in the hub republishes `portfolio` only. Returns `{ close(): void }`, which closes every handle. A rebuild that throws is caught, written to stderr, and the previous payloads stand.
- `src/server.ts`: create the hub, attach the socket, start the watcher, then listen, as today.
- `vite.config.ts`: a plugin `oculusSocket()` whose `configureServer(server)` does the same three things on `server.httpServer`, so `npm run dev` has the socket and the watcher too and hot reload of everything holds (the table in "Hot reload").

Under `tools/oculus/src/lib/state/`:

- `entities.svelte.ts`: `$state` of the latest message per channel; `receive(message)` stores it unless its version is below the stored one; `portfolio()` returns the `Snapshot` or null; `config()` returns the config payload or null. `state/` imports `data/model` for the types and nothing else from `data/`.
- `socket.svelte.ts`: `connect(channels: string[])` opens `ws://<location.host>/ws`, sends the subscribe message on open, hands every message to `receive`, and reconnects with backoff (250 ms doubling to 5 s, reset on a successful open) on close or error; `status` is `$state` in `connecting`, `open`, `closed`; `disconnect()`. When the `config` channel arrives, `setCatalog(payload.text)` in `state/text.ts` runs, which is the push the O1 decision named.
- `src/routes/+page.svelte`: connects to `portfolio` and `config` on mount and shows, through `t()` keys added under `text.app` in `config/text.yml`: the title, the socket status, the portfolio version, and the count of projects, venues, datasets, programs, domains, funding schemes and collections. `+page.server.ts` and `+page.ts` keep shipping the catalog as page data for the first render.

Under `tools/oculus/tests/`:

- `server/channels.test.ts`: subscribe sends the current message of each channel that has one; publish increments the version per channel and reaches every subscriber and no one else; a sink whose send is still pending gets only the latest message once it completes (a fake sink whose promise the test resolves by hand); a removed sink gets nothing.
- `server/socket.test.ts`: an `http.Server` on `127.0.0.1` port 0 with the socket attached; a `ws` client with `Origin: http://evil.invalid` is refused (the upgrade fails); one with `Origin: http://127.0.0.1:<port>` subscribes to `portfolio` and receives the message the hub holds, then a publish. Every server started is closed in the test. Never port 8787 and never 8790.
- `watch/portfolio.test.ts`: a synthetic hub in a temporary directory (one project under `projects/active`, the five registries, one collection, a `config/` with `layout.yml`, `vocab.yml`, `manifest-schema.yml`, `text.yml` holding what the build needs), a hub with a recording sink; after start the sink holds `portfolio` version 1 and `config` version 1; editing the project's `title` yields a `portfolio` message within 2 s whose payload holds the new title; a file written under `projects/active/<p>/code/` yields nothing within 500 ms; editing `config/text.yml` yields `config` and `portfolio`. The watcher is closed at the end of every test.
- `state/entities.test.ts`: receive stores by channel and drops an older version.

## Facts checked on the tree, 2026-09-10

- `buildPortfolio` on the real hub takes 58 to 109 ms over three runs under `node` (`performance.now()` around the call) and the snapshot is 355692 bytes of JSON. A rebuild per debounced burst is therefore cheap; nothing needs to rebuild only part of it.
- `projects/` holds 50690 files, most under `code/` folders; `fs.watch(dir, { recursive: true })` on this machine (darwin, Node 24.21.0) delivers `rename` and `change` events with the path relative to the watched directory, verified in a temporary directory. The `code` and `attic` filter is what keeps a build or an editor's swap file from triggering rebuilds.
- `src/routes/+layout.ts` sets `ssr = false`, so `+page.svelte` runs in the browser only and may open the socket in its script.
- The boundaries table in `tests/boundaries.test.ts` allows `server/` to import `server/**` and `data/**`, and `state/` to import `state/**` and `data/model`. `vite.config.ts` and `src/server.ts` sit outside `src/lib` and the table does not read them.
