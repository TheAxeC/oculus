## What to build

1. **Mains in any folder** (`server/content/latex.ts`). `mainsIn(dir)` answers the mains directly in one folder by today's rule; `mains(folder)` becomes `mainsIn(join(folder, MANUSCRIPT))`. Each `MainState` gains `program`: `pdflatex`, `xelatex` or `lualatex`, from a magic comment `% !TEX program = <name>` (item 8 reads it); any other value, or none, is `pdflatex`.
2. **A folder's state.** `GET /api/latex?root=<key>&path=<folder>` answers `{ root, path, mains }` for a folder under a served root, resolved through `resolveRootPath` (`server/files/files.ts`); refused: `root` or `path` missing (400), an unknown root key, a path outside the root, missing, or a file (404). Every path in the answer (`pdfPath`, a problem's file) is relative to the root. `?id=` answers as today, with paths relative to the project folder as today. Both `id` and `root`, or neither, is 400. Query parameters and every answer are read through zod shapes.
3. **Root detection.** `rootOf(root, file)` answers the main a `.tex` file builds through: the file itself when it is a main; else the main a `% !TEX root = <path>` names (any case of `TEX`, `!` and spaces free, the value trimmed), resolved from the file's folder and inside the same root; else the folder's only main; else none. A cycle of root comments answers none. `GET /api/latex?root=&file=<path>` answers `{ root, path, main }` or `{ main: null }`.
4. **Build, clean and log for a folder** (`pty/routes.ts`, the terminal route, `terminals.svelte.ts`). The `latex` action takes `id` (as today) or `root` and `path`, read through a zod shape; the main is checked against `mainsIn` of the resolved folder and the terminal runs in that folder. `latexCommand` is exported and takes the program: `-pdf`, `-pdfxe`, `-pdflua`. The store's `latex` takes a target `{ id } | { root, path }`; `terminals.svelte.ts` stays under 900 lines (move the latex call into `latex.svelte.ts` if needed). Log opens `<main>.log` in a source tab when it exists.
5. **The LaTeX view** (new `src/lib/views/academic/latex/`, Z192 (1)). A view `latex`, label "LaTeX", not listed, instance state `{ root, path }` read with `instanceText`, its tab named after the folder (the root's label when `path` is empty). It draws the folder's mains through one shared rows component, which the project panel draws too (`boards/project/Latex.svelte` keeps its heading and project id). Per main: its name, the PDF's time, Build, Clean, Open PDF, Log, Count Words, the outline (a disclosure closed until pressed, each section indented by its level, a press opening its file at its line), and the problem list: errors first, then warnings, each row its place (`file:line`, a file alone, or none) and its message, a press opening the file at its line (no file: the main; no line: the file's top). The project panel shows the same controls, served by the project form of the route, which gains the same `outline` and `count` parameters. The latex store keys a folder `['latex', 'folder', root, path]` and a project `['latex', 'project', id]`, so neither can collide with the other; `watch`, `invalidate` and `redraw` take the target. A view whose folder is removed says the folder cannot be read, with Retry.
6. **Problems as diagnostics** (Z196 (b)). The latex store exposes the latest build's problems of every target it holds as one list in the shape D33 will gather: `{ root, file, line?, severity: 'error' | 'warning', message, source: 'latex' }`, the file relative to the root, through a `latexDiagnostics()` reader; a source tab showing one of those files draws them as Monaco markers (error and warning) through a callback prop from `Source.svelte` to the editor kit. A new build of the main replaces its problems.
7. **Opened from the file browser** (`tree/menu/row-menu.ts`, Z192 (1)). The row menu gains "Open LaTeX" in its own group after the reveal and terminal group: on a `.tex` file (opening the view on the folder of the main `rootOf` answers, else on the file's own folder) and on a folder or root whose held listing has a `.tex` file directly in it. The fact is computed in `rowFacts` from what the fs store holds, never by a new request.
8. **One LaTeX reader on `latex-utensils`** (Z279; a pure module under `src/lib/data/helpers/latex/`, usable by the server and the page). It reads: the magic comments of a file's leading comment block (the lines before the first line that is neither blank nor a comment), parsed with `latexParser.parse(block, { enableComment: true })`, so the parser never meets the body; the sections of a text, `{ level, title, line }`, `level` 0 to 6 for `\part` to `\subparagraph`, starred forms included, the title as written; and the include commands `\input`, `\include`, `\subfile`, `\import` (two groups) with their paths. A text the parser refuses yields no sections and a `refused` flag. `latexOutline` in `state/sources/explorer/sections/outline.ts` becomes a call of this reader (its `OutlineItem` shape and depth rule kept), so the Files Outline and D25's sticky scroll read the same sections; a refused file shows the Files Outline's existing "no headings" answer. Before wiring the Files Outline, measure the parse time over the 231 real `.tex` files (`find funding applications projects -name '*.tex'`): if the median is above 50 ms or any file above 500 ms, stop and hand back the measurement (case 20).
9. **The outline over includes.** `GET ...&outline=<main>` (both forms) answers the main's sections in order, `{ level, title, file, line }`, following the includes from the main's folder (`.tex` added when the name has none), each file read once (a cycle stops), a file outside the root or missing skipped; a file the parser refuses is listed in `skipped: [<file>]`.
10. **Word count.** `GET ...&count=<main>` runs `texcount -inc -total -sum -brief -utf8 <main>` in the folder with no shell and a 20 s timeout. The output is read so: any line starting `!!!`, or an `(errors:N)` with N above 0, is a failure answered 502 with the first `!!!` line's text between the marks; otherwise the first line that is only an integer is `{ words }`. A missing program answers 502 with the catalog sentence that `texcount` is not installed; a timeout answers 504 with its sentence. The view shows the number in the row until the main is built again.
11. **The hover preview** (`ui/controls/editor/kit/`, one new file, the span finder pure). In a `latex` source tab, the pointer resting 300 ms over math (`$...$`, `$$...$$`, `\(...\)`, `\[...\]`, and the `equation`, `align`, `gather`, `multline` environments, starred or not; an escaped `\$` is not a delimiter) shows a Monaco content widget holding KaTeX's rendering (`throwOnError: false`, `trust: false`, display mode for all but `$...$` and `\(...\)`). Over `\includegraphics[...]{<path>}` it shows the picture: the path resolved from the main's folder (from `rootOf`) or the file's own, `.pdf`, `.png`, `.jpg`, `.jpeg` tried in that order when none is given, a PDF shown as its name only; a path that is absolute, holds `..` leaving the root, or names no file shows nothing. The picture is read through the file route, never a raw path in an `<img>`. The widget goes when the pointer leaves the range or the editor. `Editor.svelte` takes the hover and markers through props and stays under 540 lines.
12. **Format Document** (Z278). In a `latex` source tab, Format Document (the editor's action and Shift+Alt+F) sends the tab's text to `POST /api/latex` `{ action: 'format', text }`, which runs `tex-fmt --stdin` with no shell and a 20 s timeout and answers `{ text }`; the page replaces the tab's text as one undoable edit and does not save. A missing program answers 502 with the catalog sentence naming `brew install tex-fmt`; a non-zero exit answers 502 with its first stderr line; the tab is unchanged in both.
13. **Build on save** (Z192 (3), (5)). The logic lives in the latex store (`onSaved(root, path)`), called by `Source.svelte` after a save that succeeded: for a `.tex` file with `latex.auto_build` `on_save` it asks `rootOf` and, when it answers a main, starts a build not shown; the store watches it, so an open view's row says it is building and redraws when it ends. `never` runs nothing; an empty or any other value counts as `on_save`. A second save while the `rootOf` request is out starts one build, for the later save. The key lives under a `latex:` map in `config/behavior.yml` with its entry in `config/catalogs/options.yml` (`control: choice`, `on_save` and `never`, default `on_save`, the description saying what each does and that any other value counts as `on_save`).
14. **Every `<main>` parameter checked.** `outline`, `count` and the `latex` action's main are each checked against `mainsIn` of the target folder before any file is read or process started; any other value (`../x.tex`, an absolute path, a name starting with `-`, a non-main `.tex`) is 404 with no process.
15. **Docs.** `DESIGN.md:406` and `HELP.md:156` (the LaTeX passages) say a LaTeX view opens on any folder from the Files menu, what each control does, build on save and its key, Format Document and `tex-fmt`, and that magic comments name the root and the program. New words go beside their siblings: the view's in a new `config/text/views/academic/latex.yml`, the menu's in `views/sources/files.yml`, the server's in `server.yml`.
16. **Dependency.** `latex-utensils` 7.0.0 added to `package.json` and the lockfile.
