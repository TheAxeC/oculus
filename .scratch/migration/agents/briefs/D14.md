## What to build

1. **Mains in any folder** (`server/content/latex.ts`). `mainsIn(dir)` answers the mains directly in one folder by the rule of today (a `.tex` file, a link followed, whose head declares a class outside a comment; `main.tex` first, then by name); `mains(folder)` becomes `mainsIn(join(folder, MANUSCRIPT))`. Each `MainState` gains `program`: `pdflatex`, `xelatex` or `lualatex`, from a magic comment `% !TEX program = <name>` (also `!TeX`, any case of `TEX`, spaces around `=` free, the value trimmed and lowercased; any other value, or none, is `pdflatex`). A magic comment is read only in the file's leading lines, before its first line that is not blank and not a comment, as LaTeX Workshop reads them.
2. **A folder's state** (`latex.ts` and the route). `GET /api/latex?root=<key>&path=<folder>` answers `{ root, path, mains }` for a folder under a served root, resolved through `resolveRootPath` (`server/files/files.ts:102`), refusing a missing root or path (400), a path outside the root or missing (404), and a path that is a file (404); `pdfPath` is relative to the root. `?id=` answers as today. A request with both, or neither, is a 400.
3. **Root detection** (`latex.ts`). `rootOf(rootList, key, file)` answers the main a `.tex` file builds through: the file itself when it is a main; else the file a `% !TEX root = <relative path>` names, resolved from the file's folder, when that file is a main inside the same root; else the folder's only main when it has exactly one; else none. `GET /api/latex?root=&file=<path>` answers `{ root, path, main }` (the main's folder and name) or `{ main: null }`.
4. **Build, clean and log for a folder** (`pty/routes.ts`, `terminals.svelte.ts`). The `latex` action takes either `id` (as today) or `root` and `path`; the main is checked against `mainsIn` of the resolved folder and the terminal runs in that folder. `latexCommand` takes the program: `-pdf` for `pdflatex`, `-pdfxe` for `xelatex`, `-pdflua` for `lualatex`, the rest as today. The terminals store's `latex` takes a target `{ id } | { root, path }` and keeps `terminals.svelte.ts` under 900 lines. The panel's Log control opens `<main>.log` in a source tab when the log exists.
5. **The LaTeX view** (new `src/lib/views/academic/latex/`, Z192 (1)). A view `latex`, label "LaTeX", not listed, opened with instance state `{ root, path }`, its tab named after the folder. It draws the folder's mains through one shared component, which the project panel draws too (`boards/project/Latex.svelte` keeps its heading and its project id and draws the shared rows): per main its name, the PDF's time, Build, Clean, Open PDF, Log, Count Words and Lint; then a list of the main's problems, errors first, then lint warnings, then build warnings, each row its place (`file:line`, one of them, or none) and its message, a press opening the file at its line in a source tab (a row with no file opens the main; a row with no line opens the file at its top). The latex store keys a folder as `['latex', root, path]` beside `['latex', id]`; `watch` and `invalidate` take the same target; `redraw` bumps the PDF under the target's root. The store module moves out of the full `state/sessions` folder only if the builder needs a new file; otherwise it stays in `latex.svelte.ts`.
6. **Opened from the file browser** (`row-menu.ts`, Z192 (1)). The row menu gains "Open LaTeX" in its own group after the reveal and terminal group: on a `.tex` file (opening the LaTeX view on the folder of the main `rootOf` answers, or on the file's own folder when it answers none) and on a folder or root whose held listing has a `.tex` file directly in it. The fact is computed in `rowFacts` from what the fs store holds, never by a new request.
7. **Build on save** (Z192 (3)). After a source tab saves a `.tex` file and `latex.auto_build` is `on_save`, the page asks `rootOf` for it and, when it answers a main, starts a build of that main without selecting or showing the terminal; the latex store watches it, so an open LaTeX view's row says it is building and redraws when it ends. With `never`, nothing runs. The key is read from the config the page already holds, so a change applies to the next save. The key lives under a `latex:` map in `config/behavior.yml` and has its entry in `config/catalogs/options.yml` (`control: choice`, the two values, default `on_save`), its description saying what each value does and that any other value counts as `on_save`.
8. **The outline** (`latex.ts`, `latex-utensils`). `GET /api/latex?root=&path=&outline=<main>` answers the main's sections in order, `{ level, title, file, line }`, `level` 0 to 6 for `\part`, `\chapter`, `\section`, `\subsection`, `\subsubsection`, `\paragraph`, `\subparagraph` (starred forms included), the title as written, the file relative to the root, the line 1-based; parsed with `latex-utensils`' `latexParser.parse`, following `\input`, `\include`, `\subfile` and `\import` with a path relative to the main's folder (`.tex` added when the name has none), a file read once (a cycle stops), a file outside the root or missing skipped. A file the parser refuses yields no sections, and the answer carries `skipped: [<file>]`. The LaTeX view draws the outline under each main, a disclosure that is closed until pressed, each section indented by its level and a press opening its file at its line.
9. **Word count** (`latex.ts`). `GET ...&count=<main>` runs `texcount -inc -total -sum -brief -utf8 <main>` in the folder with no shell, a 20 s timeout, and answers `{ words }` (the first integer of its output) or a 502 with the process's error line. The view's Count Words shows the number in the row until the main is built again.
10. **Lint** (`latex.ts`). `GET ...&lint=<main>` runs `chktex -q -v0 -f '%f:%l:%c:%n:%m\n' <main>` the same way and answers `{ issues: [{ file, line, column, code, message }] }`, files relative to the root (chktex follows `\input` by itself); exit status 2 (warnings found) is a success. The view's Lint adds the issues to the main's problem list.
11. **The hover preview** (`ui/controls/editor/kit/`, the shared editor). In a source tab whose language is `latex`, the pointer resting 300 ms over math (`$...$`, `$$...$$`, `\(...\)`, `\[...\]`, and the `equation`, `align`, `gather`, `multline` environments, starred or not) shows a Monaco content widget holding KaTeX's rendering (`throwOnError: false`, display mode for every form but `$...$` and `\(...\)`); over `\includegraphics[...]{<path>}` it shows the picture, the path resolved from the main's folder (from `rootOf`) or the file's own, with the extensions `.pdf`, `.png`, `.jpg`, `.jpeg` tried in that order when none is given, a PDF shown as its name only. The widget goes when the pointer leaves the range or the editor. The span finder is a pure function of the text and an offset.
12. **Docs.** `DESIGN.md`'s LaTeX passage and `HELP.md`'s say a LaTeX view opens on any folder from the Files menu, what each control does, build on save and its key, and that magic comments name the root and the program. The catalog words go in the catalog file the panel's words are in, beside them.
13. **Dependency.** `latex-utensils` 7.0.0 is added to `package.json` and the lockfile.

## Cases

Unit cases (server cases with a scratch folder under the test's temp directory, as `tests/server/content/` does):

1. `mainsIn` over a folder with `main.tex`, `b.tex` and `a.tex` (each declaring a class) and `chapter.tex` (none): `['main.tex', 'a.tex', 'b.tex']`; a folder with none: `[]`; a missing folder: `[]`.
2. `program` from `% !TEX program = xelatex`, `%!TeX program=LuaLaTeX`, `% !TEX program = context` and none: `xelatex`, `lualatex`, `pdflatex`, `pdflatex`; a magic comment after the first code line is not read.
3. `GET ?root=&path=` for a folder with two mains: both, `pdfPath` relative to the root; a path outside the root: 404; a file: 404; both `id` and `root`: 400.
4. `rootOf`: a main answers itself; `chapters/c6/c6.tex` with `% !TEX root = ../../thesis.tex ` (trailing space) answers `thesis.tex` in the folder two up; a root comment naming a missing file or one outside the root falls through to the folder rule; a folder with one main answers it; with two mains, none.
5. `latexCommand('build', 'm.tex', 'xelatex')`: `latexmk -pdfxe -interaction=nonstopmode -file-line-error m.tex`; `lualatex`: `-pdflua`; `pdflatex`: `-pdf`; clean: `latexmk -c m.tex`.
6. The `latex` action with `root` and `path`: a main of the folder starts a terminal in that folder; a main not in it, a path outside the root and a missing target are refused with 400.
7. The outline of a main with `\section{A}`, `\input{sec/b}` (holding `\subsection*{B}`) and an `\input` of itself: A at level 2 in the main, B at level 3 in `sec/b.tex` with its line, no second pass over the main; a missing input is skipped.
8. Word count over a stub `texcount` on PATH printing `123`: `{ words: 123 }`; a process that fails: 502 with its line.
9. Lint over a stub `chktex` printing two `f:l:c:n:m` lines and exiting 2: two issues; the real `chktex` over a file with `a ... b` (code 11) when it is on PATH, skipped otherwise with the skip printed.
10. The math span finder: an offset inside `$x^2$`, inside `\[ a \]`, inside an `align*` environment, on an escaped `\$`, and outside any: the span and its display mode, or none.
11. The row menu: a `.tex` file offers "Open LaTeX"; a folder whose held listing holds a `.tex` file offers it; a folder with none and a `.md` file do not.
12. The store: `state({ root, path })` asks `/api/latex?root=&path=` once; `watch` on a folder target marks it on each `sessions` push until the terminal leaves.
13. Build on save: a saved `.tex` file whose `rootOf` answers a main with `on_save` starts one build, not shown; with `never`, none; a `.md` file, none.

Look items on landing (TEST, the orchestrator): the Files menu on `funding/2026-nwo-enw-xs/proposal-ls` and on a `.tex` file; the LaTeX view with two mains (build one, watch the row and the PDF), the problem list opening a line, the outline, Count Words, Lint; a save of a `.tex` file building it; the math and picture hovers; the project panel unchanged in what it shows.

Implied inputs, each with its result:

14. A main whose name holds a space or a quote: the command quotes it (`shellWord`) and the build runs.
15. A folder that is the root itself (`path` empty): its mains are read; the tab is named after the root.
16. A build started on save while one of the same main runs: a second terminal starts, as a second press does today (stated).
17. A `% !TEX root` cycle (a names b, b names a, neither a main): none.
18. A LaTeX view whose folder is removed: the state answers 404 and the view says the folder cannot be read, with Retry.
19. The outline of a main of 2,000 sections: answered whole (stated; no cap).

The builder's first task, before any change, is the first run of every unit case above on the unchanged tree, as tests, with each case's result noted (cases needing `mainsIn`, `rootOf`, `program`, the new query forms, the view or the finder fail on the unchanged tree; say which). When the first run finds a case the brief's own rules get wrong, the builder stops there, before changing any code, and hands back the first run and that case, with the rule and the result it gives.

1. Z192 (1) (the orchestrator, automode): a view `latex` named "LaTeX", opened by "Open LaTeX" on a `.tex` file or a folder holding one in the Files row menu, instance state `{ root, path }`, as LaTeX Workshop is reached from a `.tex` file.

6. Count Words and Lint run on a press, as LaTeX Workshop's commands do (its ChkTeX linting is off by default).
7. The hover is a content widget filled by the page, so KaTeX's markup and stylesheet are used whole, with no markdown sanitizer between.
