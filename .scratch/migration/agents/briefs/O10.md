## What to build

Under `tools/oculus/src/lib/data/` (the wire model grows where a field the board needs has no home; `DESIGN.md` says the snapshot is the typed model and this is where the model gains what a view reads):

- `model.ts`, `Project` gains: `pin?: boolean`, `compute?: string` (`hpc`, `local`), `codeAvailability?: { status?: string; date?: string; url?: string; doi?: string; repo?: string }`, `reproduced?: { date?: string; note?: string }`, `collaborators: string[]`, `venue?: string` (the free-text venue prose, kept for the manifests that have no `venue_id`), `docs: { name: string; present: boolean }[]` (the six fixed documents of O3's `projectDocs`, presence only). `normalise.ts` fills each from the manifest key of the same meaning and `buildPortfolio` runs `projectDocs` per manifest folder (O3's function, 91 folders, cheap). `validate.ts` gains the `collaborators` check the cockpit made: each id names a key of the `collaborations` collection, a dangling one a finding. The integrity test must still report zero findings on the real hub; if it does not, the finding is reported verbatim and never repaired.

Under `tools/oculus/src/lib/state/`:

- `board.ts` (no runes, pure, tested): the board's logic over the snapshot. `BoardPreset` maps a view id to its tiers and columns: `projects` is tiers `ideas`, `active`, `manuscripts` with the `cols_project` columns; `archive` is tier `archive` with `cols_archive`; `coauthor` is tier `coauthor` with `cols_archive`. `boardItems(snapshot, preset)`: the projects of those tiers joined with their venue (`venues[venueId]`), their domain theme (`themes[domain]` from the vocab: label and tone), their program titles and funding, sorted pinned first, then by `type_order` of the vocab, then by title. `bucketOf(item, rollup)`: the first `tab_rollup` bucket of the preset's tier whose keys match the item's type or one of its chips (`category` facet). `facets(items)`: the counts per value for category, year (newest first, `no_year` for the undated), domain, program, funding (with `no_funding` for projects naming none), dataset, status (chips), compute, reproduced, code status; a facet with fewer than two values is not offered. `applyFilters(items, filters, search)`: every selected value of a facet is OR within the facet and AND across facets; the search is a case-insensitive substring over title, short, eli5, latest, next, outcome, results, ideas, funding, program, datasets and collaborators. `firstSentence(text, limit)` for the `next` line on a card. Every function is pure and deterministic.
- `selectors.svelte.ts`: the reactive face of `board.ts` over `entities`: `board(preset)` returns `$derived` items, and nothing else computes a join in a component. It imports `entities.svelte.ts`, `tones.ts` and `data/model` only.
- The instance state of a board (through `instanceState` / `setInstanceState` of O8, so two boards keep separate state): `{ mode: 'cards' | 'list'; search: string; filters: Record<string, string[]>; expanded: string[]; labels: 'short' | 'full' }`, with a `parseBoardState(unknown)` that returns a valid state from anything.

Under `tools/oculus/src/lib/views/`:

- `Projects.svelte`, registered three times in `src/routes/views.ts` as `projects`, `archive` and `coauthor` (labels from the `tabs:` map of `config/layout.yml` through new `text.views` keys; glyphs `focus`, `archived` and `author`, all three in `glyphs.yml`). The component reads its preset from `instance.view`. It renders a `Pane` whose toolbar holds the `Search`, the cards/list `Segment` (`board.view_cards`, `board.view_list`), the short/full label `Segment`, and a facet `Menu` per offered facet showing each value with its count and a mark on the selected ones (`board.filter_by`); the body is the cards or the list.
- A card (a `Card` with the primitives, nothing else): the type as a filled `Chip` in `typeTone(type)`, the domain label as a chip in the theme's tone, the deadline badge (a chip: the date when submitted, `cards.overdue` in red when past, the days in amber within 14 days, the date otherwise), the pin mark when pinned; the title (`short` in short mode when the manifest has one, else `title`; the full title as the tooltip); the folder; a meta row: the focus lane as a chip, one chip per status chip with its `chipGlyph` and `chipLabel` as the tooltip, the code badge (`cards.code_deposited`, `code_anon`, `code_pending` by `codeAvailability.status`), the reproduced badge, the compute badge (`cards.hpc_label`, `cards.local_label`), the venue (name, quartile, `JIF <jif>`, `free`, joined by ` | `, from the joined venue), the authors (the list joined, else `lead`); a tag row of funding, program titles, datasets and collaborators as outline chips; the `eli5` block (`cards.eli5`); the first sentence of `next`. Expanded (a click on the card head toggles and the instance state remembers): `statusLine`, then the labelled fields `cards.latest`, `cards.results` (a list), `cards.outcome`, `cards.next`, `cards.ideas` (a list), `cards.reproduced` (date and note), and the six documents as chips (present ones in green, absent ones muted). No markdown rendering in this package: fields are shown as text; the report says so.
- The list mode is a `Table` with the preset's columns: for `projects` title, authors, venue short name, the status chip glyphs, the focus lane, the first sentence of `next`; for the other two title, authors, venue, domain label, program titles joined by ` | `, funding joined by ` | `. Sortable by title, authors and venue.
- An empty result shows `Empty` with `board.empty`.

Under `tools/oculus/tests/`:

- `state/board.test.ts`: on a hand-built snapshot: the tier split per preset, the sort (pinned, then type order, then title), the joins (venue, theme label and tone, program titles), every facet with its counts and the two `no_*` values, a facet with one value not offered, filters OR within and AND across, the search over each listed field, `firstSentence`, `parseBoardState` on garbage.
- `views/projects.test.ts`: `render` from `svelte/server` of `Projects.svelte` with the catalog, glyphs and vocab installed and a synthetic snapshot in `entities`: one card per project of the preset, the type chip, the venue string, the folder, the expanded fields present for an expanded instance state, the list mode rendering a table with the preset's columns.
- `data/normalise.test.ts`, extended for the new `Project` fields; `data/validate.test.ts` for the `collaborators` check; `tests/integrity.test.ts` unchanged and green.
