# Brief: O8, the workbench

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "Layer 3, view" (primitives, shell, views, boundaries), "Layout as data", "Client state", "Theming", and the decisions on layout and on order. O7 gave the tree, its operations, its persistence, the sash and the split view. This package puts the workbench around them: the activity rail, the tabs on a pane, the panel that docks right, bottom or hidden, the view registry, theme switching, and two real views so there is something to open. It is the first package meant to be looked at, and the orchestrator opens it in Chrome after landing.

## What to build

Under `tools/oculus/src/lib/state/`:

- `layout.svelte.ts`, extended: the persisted unit becomes the workbench, `Workbench = { main: Layout; panel: Layout; dock: 'right' | 'bottom' | 'hidden'; panelSize: number }`, where `main` and `panel` are two trees of the O7 type and `panelSize` is the panel's fraction (default 0.3, clamped to `[0.1, 0.6]`). The envelope in `localStorage` becomes `{ version: 2, workbench }`; `parseLayout` returns null for anything else, so a version 1 value falls back to the default. The store gains `dock(where)`, `resizePanel(fraction)`, and `openView(view: ViewId, where: 'main' | 'panel')`: if an instance of that view exists in the target tree it is activated, otherwise a new instance (`id` from `crypto.randomUUID()`, `state: {}`) is opened in the target tree's active pane (the pane of the most recently activated instance, else the first pane). Every O7 operation takes the tree it applies to through a `target` argument, or is wrapped so the store knows which tree changed. `defaultWorkbench()`: `main` one pane with an instance of `status`, `panel` one pane with an instance of `findings`, `dock: 'right'`.
- `ui.svelte.ts`: `theme` (a name from `text.js.theme.order`, default `light`), `crt: boolean`, and `instanceState(id)` / `setInstanceState(id, state)` for a view's own state keyed by instance id, all persisted under `oculus.ui.v1` through the same `Pick<Storage, 'getItem' | 'setItem'>` pattern as the layout store; `loadUi(storage)`; a stored theme that is not in the order falls back to `light`.
- `text.ts`, extended: `setGlyphs(map)` and `glyph(name)` beside the catalog, fed from the `glyphs:` map of `config/glyphs.yml`: at first load as page data (`+page.server.ts` ships `glyphs` next to `text`), afterwards from the `config` channel (`state/socket.svelte.ts` installs both). A missing glyph name throws like a missing text key.

Under `tools/oculus/src/lib/views/`:

- `registry.ts`: `registerView({ id, label, glyph, component })` where `label` and `glyph` are catalog keys, `viewFor(id)` (the registration or undefined), `views()` (every registration in registration order). The registry is the vocabulary of `ViewId`; nothing else imports a view by name.
- `Status.svelte` (`id: 'status'`): the O6 status block as a view: socket status, snapshot version, the seven counts. `Findings.svelte` (`id: 'findings'`): the snapshot's findings and the config findings, one row each (file, key, message), and a line saying none when there are none. Both read `state/entities.svelte.ts` and `state/socket.svelte.ts` and compose primitives; neither knows where it is mounted. `views/index.ts` registers both, and `+page.svelte` imports `views/index.ts` once so the registrations run before the workbench renders.

Under `tools/oculus/src/lib/ui/`:

- `Tabs.svelte`: a tab strip. Props: `tabs: { id, label, glyph? }[]`, `active`, `onselect(id)`, `onclose(id)`. Each tab is a button with `role="tab"`, `aria-selected`, the label, and a close control labelled through `t('ui.close_tab')`. Tokens only.
- `Glyph.svelte`: renders `glyph(name)` from `state/text` in a `<span aria-hidden="true">`; the one place a glyph character reaches the DOM.
- `Menu.svelte`: a button that opens a list of choices below it (`role="menu"`, `role="menuitem"`, Escape and click-outside close it, arrow keys move). Props: `label`, `items: { id, label, active? }[]`, `onpick(id)`. Used by the theme picker and the dock control.
- `theme.ts` (not a component): `applyTheme(document, classes: string, crt: boolean, tokensCss: string, themesCss: string)`: sets `document.body.className` to the class string plus `crt` when on, resolves the theme with `parseBlocks` and `resolveTheme` from `themes/parse.ts`, derives with `deriveTokens`, and writes every derived token with `document.documentElement.style.setProperty`. The two sheets reach it as text through Vite's `?raw` import (`import tokensCss from '$lib/themes/tokens.css?raw'`), so the derivation runs on the same bytes the page styles with. `ui/` may import `themes/**` and `state/text`; this file imports `themes/` only.

Under `tools/oculus/src/lib/shell/`:

- `Workbench.svelte`: the page. A row: `ActivityRail` at the left; then the main `SplitView`; then, when `dock` is not `hidden`, a `Sash` and the panel `SplitView`, side by side for `right` and stacked for `bottom` (the outer container is a row or a column accordingly and the sash follows). It renders every pane through `PaneView`. An `$effect` applies the theme whenever `ui.theme` or `ui.crt` changes. Height is the viewport; nothing scrolls but the pane bodies.
- `PaneView.svelte`: one pane node: `Tabs` over its instances (label and glyph from the registry; an instance whose view is not registered shows `t('ui.unknown_view', view)` as its label and an empty body) and the active instance's component mounted below with `instance` as its prop. Close removes the instance through the store.
- `ActivityRail.svelte`: a vertical strip. One button per registration, glyph and a title from its label, grouped under the `nav_groups`-shaped list in the merged config when a group names the view and after the groups otherwise (`nav_groups.collections` and `nav_groups.more` of `config/layout.yml` name cockpit tab keys; O8 reads them and matches by id, so today `status` and `findings` are ungrouped and the groups are empty; the shape is used, the entries are the cockpit's). Click opens or activates the view in `main`; shift-click in `panel`. At the bottom: the theme `Menu` (items from `text.js.theme.order` with `label_<name>`), a CRT toggle (`crt_on`), and the dock `Menu` with `ui.dock_right`, `ui.dock_bottom`, `ui.dock_hidden`.

Under `tools/oculus/src/routes/`:

- `+page.svelte` renders `Workbench` and nothing else; on mount it loads the two stores, connects the socket to `portfolio` and `config`, and registers the views. `+page.server.ts` ships `glyphs` with `text`; `+page.ts` installs both.
- `config/text.yml` gains under `text:`: `ui: { close_tab, unknown_view, dock_right, dock_bottom, dock_hidden, theme, crt, panel }` and `views: { status, findings, status_glyph, findings_glyph }` where the two glyph keys name entries of `glyphs.yml` (`now` and `warn` exist; pick from what is there and say which). Every string a component shows goes through `t()`; `keys.test.ts` enforces it.

Under `tools/oculus/tests/`:

- `state/layout.test.ts`, extended: the workbench envelope round trip, version 1 rejected, `dock`, `resizePanel` clamping, `openView` activating an existing instance rather than opening a second, and opening into the active pane.
- `state/ui.test.ts`: persistence of theme, crt and instance state through a fake storage; an unknown stored theme falling back to `light`.
- `views/registry.test.ts`: register, look up, order, and a second registration of the same id replacing the first.
- `ui/theme.test.ts`: `applyTheme` against a minimal fake document (an object with `body.className` and `documentElement.style.setProperty` recorded), over the real sheets read from disk: `mocha` sets `rice mocha`, sets `--ink-txt` and `--on-c-teal` among others, and `crt` adds the class.
- `shell/workbench.test.ts`: `render` from `svelte/server` of `Workbench` with a workbench of two panes and the panel docked right, two registered test views: the HTML holds one rail button per view, one tab strip per pane, the sashes, and the active views' markup; docked `hidden` renders no panel.

## Facts checked on the tree, 2026-09-10

- `text.js.theme.order` names fifteen themes with `class_<name>` and `label_<name>` for each; the labels carry a glyph character in the string, which is allowed because the string comes from the catalog. `crt` is a body class in `themes.css`.
- `config/glyphs.yml` is `{ glyphs: { name: char }, ascii: { char: stand-in } }`; the ASCII stand-ins and a toggle for them are not this package's (O9, with the primitives that render chips).
- `config/layout.yml` `nav_groups` is `{ collections: [{ label, keys }], more: [{ label, keys }] }` with cockpit tab keys; `nav.primary` and `nav.more` are the cockpit's top bar and are not read.
- `tests/boundaries.test.ts` allows `shell/` to import `views/registry` and nothing else under `views/`; `views/index.ts` importing the two view components is inside `views/`, and `+page.svelte` (outside `src/lib`) importing `views/index` is outside the table's reach. `ui/` may import `themes/**` and `state/text`.
- O7 split the layout module: `state/layout.ts` is the pure half (types, operations, `checkLayout`, `parseLayout`) and `state/layout.svelte.ts` is the store, because the boundary table matches `state/layout` exactly and a runes module is imported as `state/layout.svelte`. This package makes one change to `tests/boundaries.test.ts`, and only this one: `matches()` treats an exact pattern as also matching the `.svelte` module of the same name (`state/layout` allows `state/layout.svelte`, `state/ui` allows `state/ui.svelte`), with a row in the test's synthetic-violation case showing `shell/X.ts` importing `state/entities.svelte` is still refused. The table's rows are not edited. `ui.svelte.ts` follows the same split if it has a pure half worth testing without runes; otherwise it is one file.
- `.prettierignore`'s comment says the six config copies are kept byte for byte; `text.yml` has gained oculus's own groups since O1 and this package adds more. Reword that comment to say the five other files are byte for byte and `text.yml` is the cockpit's file plus oculus's own groups, kept in the cockpit's two-space style.
- `svelte/server` `render` works under Vitest's node environment (O7's `splitview.test.ts` relies on it).

## Conventions

Four-space indentation (`npm run format`); every file under 1000 lines; ASCII in every authored file (a glyph character reaches a component only through `glyph()` or a catalog string); no new dependency; `tests/boundaries.test.ts` and `tests/keys.test.ts` must pass; no literal user-facing string or colour in a component.
