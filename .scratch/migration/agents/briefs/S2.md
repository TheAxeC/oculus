## What to build

VS Code's Agents window, row by row from P1's inventory (`agents/reviews/vscode-parity.md` 109-131, and Axel's screenshot described below), on oculus's structure. Axel's word for the goal: the sessions view is "just ugly overall and not very clean or easy to follow". The screenshot shows three columns: on the left a Sessions header with New (and its shortcut), a filter and a search button, the sessions list, and at the foot a Customizations section (Overview, Plugins, MCP Servers 1, Skills 26, Instructions, Agents, Hooks 1, Tools 15, each with its count); in the middle an empty session with the composer: a workspace picker and an agent picker above a prompt box ("Pitch your idea"), a `+` to attach, the mode (Agent), the model (Auto) and the effort (Balance) inside the box's foot, and below it the permissions (Interactive, Manual permissions), New Worktree and the branch; on the right tabs Changes and Files, Files a tree of the workspace. Each item below is an acceptance item.

1. **The composer.** A new session is started from a composer, drawn when a Terminal tab has no session and at the top of the Sessions page for New: the workspace picker (the hub, every workspace, every configured root), the agent picker (Claude, Codex, Shell), the account picker (the `accounts:` rows of the chosen agent's tool, shown when there is more than one), the model, effort and permission mode pickers, and the prompt box, multi-line, Enter to start and Shift+Enter for a new line. Starting runs the agent in tmux as today with the chosen flags, the account's environment variable (`CLAUDE_CONFIG_DIR` or `CODEX_HOME`, set with tmux's `-e`), and the prompt as its first message. The prompt is passed as one argument vector element, never through a shell: a test starts a session whose prompt is `$(touch <tmp>/x); echo "q' ; rm -rf ~"` and asserts the file does not exist and the prompt arrives byte for byte. Shell takes no model, effort, mode or prompt; its pickers are hidden, its prompt box reads as the first command to run, sent as keys. The last choice of each picker is kept per tab in instance state and seeds the next composer of that tab.
2. **The choices catalog (Axel's ruling of 2026-09-25).** A new catalog `config/catalogs/agents.yml`, one entry per agent (`claude`, `codex`) listing its models, its efforts and its permission modes; each value has the words the picker shows and the flag or `-c` pair it passes, and each list a `default:`. It is seeded from fact 8: Claude models `opus`, `sonnet`, `haiku`, `fable` and a "CLI default" that passes no flag; efforts low to max; the six permission modes, `manual` the default; Codex models from `~/.codex/models_cache.json` when it lists them (read it, never write it) else `gpt-5.6-sol` and a CLI default, the reasoning efforts, the sandbox modes with `workspace-write` default and the approval policies. A parser in `data/` validates it (unknown key, missing default, a default not in its list, a flag outside the CLI's flag set: each a finding naming the line), a test holds the seed, and every value reaches the argv only from this file.
3. **Attach.** The `+` opens the file browser's picker over the chosen workspace; a chosen file is inserted in the prompt as an `@<path relative to the workspace>` mention, which both CLIs read; an image chosen for Codex is also passed as `-i <path>` at start. Dropping a file from the page's Files view into the prompt box does the same.
4. **Steer and stop a running turn.** Under a running session's terminal, the same prompt box sends a message into the session (typed through `send-keys -l`, then Enter), so a session can be steered without focusing the grid; a Stop button interrupts the current turn by sending Escape (both CLIs interrupt on Escape), distinct from ending the session. Both work for sessions running in an oculus terminal; for any other session the box is drawn disabled with a sentence saying the session runs in a terminal of its own.
5. **The sessions list.** A header with New (opening the composer; a shortcut through the workbench's key module, the chord reported), a filter menu (by state: needs input, working, idle, ended, archived; by agent) and a search box over title, prompts, workspace and branch, both kept in instance state. Rows grouped by workspace as today, drawn as VS Code draws them: one line of title with the state at the left (needs input first and marked), a second line with the agent, the model, the relative time, and the counts: files changed (from `record.files`) and prompts. Per row, the menu carries Pin (to the top of its group), Rename (inline), Archive (today's dismiss, renamed and shown under the Archived filter), Fork (`claude --resume <id> --fork-session`, `codex fork <id>`, started in a new terminal) and Export (the transcript as Markdown, handed to the browser as a download), beside the existing open pinned, transcript and resume. Delete is not offered: the agents' stores are read only here, and the report says so in one line.
6. **Customizations.** A Customizations section at the foot of the list, for the chosen workspace and account: Instructions (the `CLAUDE.md` or `AGENTS.md` files that apply: the account's, the workspace's and each parent's up to the root, `CLAUDE.local.md`), Skills (`<account>/skills/*/SKILL.md` and `<workspace>/.claude/skills/*/SKILL.md`; for Codex its own skills folder), Agents (`<account>/agents/*.md`, `<workspace>/.claude/agents/*.md`), Hooks (the hook entries in the account's `settings.json` and the workspace's `.claude/settings.json` and `settings.local.json`), MCP Servers (the workspace's `.mcp.json`, the `mcpServers` of the account's settings and of its `.claude.json` for that project; Codex's `mcp_servers` in `config.toml`), Plugins (the account's installed plugins file when present), each with its count. Pressing a row lists its items, and an item opens its file in a source tab. Everything is read only, from a server reader in `server/sessions/` reached through the request's locals, a missing file counting nothing and a malformed one a finding. Tools: counted when a file names the tools (an MCP server's tool list is known only once the server runs); where none does, the row shows no count and the report says which files were looked in.
7. **Changes and Files beside the session.** The Sessions page arrangement in `config/layout.yml` becomes the screenshot's three columns: the list with Customizations on the left; the session in the middle (the terminal, or the composer when none, with Transcript, Timeline, Session detail and Agents as tabs beside it); Changes and Files as tabs on the right. The Files tab follows the selected session's workspace: the Files view gains an instance mode that roots it at the pane's session's workspace (as Changes follows the selection or its pinned session), a change in `src/lib/views/sources/files/` and `state/sources/fs*` kept to that mode.
8. **Q35's session items.** Every session view picks a session through one control and says plainly when none is picked; Timeline grouped by turn with the turn's time; Agents with true durations (from start to end stamps, running ones ticking) and sizes (tokens and characters). The Changes panel's column items of Q35 stay with Q35, since X3b holds that folder.
9. **The look.** The list, composer and customizations drawn at VS Code's measures and tokens (list rows 22 px, the composer box with an 8 px radius and its controls inside its foot, section headers as the side bar's), under every theme; a browser spec measures the row height and the composer's layout.
