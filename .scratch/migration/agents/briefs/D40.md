Nothing about wording is judged: every mark is a character or a line break the file holds.

5. The paragraphs. Markdown only: a code comment is wrapped by design and is held to 100 columns by G23. One row per paragraph broken across lines, `severity: 'warning'`, code `wrapped-paragraph`, over the range from the paragraph's first character to its last, the message naming the number of lines. Its join holds one edit per soft break: the break's range runs from after the last non-space character of the line (spaces and tabs only, so a `<U+00A0>` at the end stays its own mark) through the line ending (`\n` or `\r\n`) and the next line's indentation, its block-quote markers (`>` and the spaces after each) and its list-continuation indentation, and the edit replaces it with one space. The join is a `kind: 'fix'` only when the joined text lexes to the same blocks as the text before (the same block types, the same list items, the same nesting); otherwise it is a suggestion, as for `> - a\nb\n> - c`, where the join would merge two lists. A hard break (two or more trailing spaces, a trailing backslash, a trailing `<br>`) is no soft break and is left. A line that starts with `$$` and the line after a line that ends with `$$` keep their breaks (case 10). A paragraph whose soft breaks are all kept answers no row. A line the derived position puts at a text that does not hold the token's first line is a reader defect: the paragraph gets no row, the run counts it, and the run over the tree in case 41 must count 0.
