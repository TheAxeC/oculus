## What to build

## Decisions taken in this brief (each reversible, none silent)

1. A top-level keyed family that is not a key/value family takes the form of oculus's own value of it (its entry's `default`), not a table of forms kept beside the in-place shapes. Oculus's files are read by the same readers as a hub's and a workspace's, so the form oculus writes is the form each reader takes; it holds for all 44 top-level keyed families, among them (`<scratch>/o136/enum.mts`, `def.mts`, `hub.mts`, `ws.mts`): `stages` (in-place map, default a map), `categories` (in-place rows, default a list), `focus_lanes` (in-place whole list, default a list), `sign_in` (in-place rows, default a list), `boards` (no in-place shape, the workspace layer a map, default a map), `collections` (read as a list by `collectionFiles`, default a list), `counts` (read as a map by `countsFindings`, default a map) and `audit.required_sections` (read as rows by `setting.ts`, default a list). A table would be a second copy of what `VOCAB_SHAPES`, `ROW_SHAPES`, `familyKind` and the readers already say.
2. A key/value family is a map wherever it stands, its default unread: `text` and `leads_fit` have none, and every reader of a key/value family takes a map.
3. `withShapes` in `engine.ts` is left as it is: it gives the in-place keys their null and `removed` rows and agrees with the new forms, so removing it is a different change.
4. The test compares line numbers, not messages, as the describe 'the schema of a multi' does, since `check.ts` words a union by one sentence.
