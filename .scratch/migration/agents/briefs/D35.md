## Decisions taken in this brief (each reversible, none silent)

1. The reload is the one watch on `local.yml` that exists (`watch/local.ts`), extended from the account keys to every key: one place reads the file, one place hands each key to what is built from it.
2. A watcher whose start options hold a changed key is closed and built again: the watchers take plain options at construction, and building again uses the code that builds them at start, with no setter per option.
3. A changed port moves the HTTP server of the same context, so the hub, the terminals and the token stay; the page follows through the `host` field the portfolio payload already carries, so no new channel or message shape is added.
4. The per-request readers of `local.yml` stay as main has them, since they already follow an edit.
5. The log lines follow the existing `the machine's own configuration is not read again:` and `config:` prefixes.
