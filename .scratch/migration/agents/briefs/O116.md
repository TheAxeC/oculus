## What is on the tree (read on main at 4e4e1cc23)

- `handleTranscript` in `src/lib/server/sessions/transcript-routes.ts:72` calls `readTurns(source.path, source.tool, from)` at line 100, then keeps the last `FIRST_READ_TURNS` (200, line 27) when `from` is 0. So a first read parses the whole file (`grep -n 'readTurns' src/lib/server/sessions/transcript-routes.ts`).
- `readTurns` (`src/lib/server/sessions/stores/turns.ts:161`) and `foldFrom` (`src/lib/server/sessions/stores/transcripts.ts:97`) are synchronous (`openSync`, `readSync`) and run on the server's one thread, so every other request waits. `sample` on a running server showed its main thread in JSON parsing while it read a 111 MB and a 4.4 GB session. A whole read of the 4.4 GB file costs about 10 s on the thread at load 4.5, and more on a loaded machine that is swapping.
- `foldLine` skips a line that does not parse (`transcripts.ts`, "a blank or broken line is skipped"), so a read that starts inside a line loses only that line; 494674 cuts of real and nested lines gave no parseable suffix. `foldFrom` returns the bytes consumed, so `answer.offset` is the end of the last whole line, which is not the file's size while the last line is being written.
- The client asks with no held offset on a first read and from `offset` afterwards (`src/lib/state/sessions/transcript.svelte.ts:168-175`). Selecting a session with no terminal opens its Transcript (O114), so a press in the list fires a first read.
- The real tail measured on the 111 MB session: the last 8 MiB hold 1923 lines, about 184 of them user or assistant records, longest line 164539 bytes; the last 32 MiB hold 5353 lines, about 579 such records, longest line 1119979 bytes (a read of the file by the session writing this brief).

## What to build

1. **Reads on the server yield.** A folding loop in `stores/transcripts.ts` reads a file in pieces and yields to the event loop between pieces (a macrotask, such as `setImmediate`), sharing its line and piece logic with `foldFrom` rather than copying it. An async form of `readTurns` runs on it. Every read `handleTranscript` makes, first read, read from an offset and export, goes through it, so no read of a transcript holds the thread for more than one piece. `handleTranscript` becomes async, the route module passes its answer through, and the sync `foldFrom` stays for the scan. `readTurns` in its sync form goes when nothing but tests use it.
2. **A bounded first read.** A read with `from` 0 and no `format=markdown` starts `FIRST_READ_BYTES` before the file's end, a constant local to the module of 32 MiB, whose comment says how it differs from `MAX_FIRST_READ_BYTES`, or at 0 for a smaller file. When that read gives no turn and the file holds more before it, the distance doubles until a turn is found or the start reaches 0, so a tail of one giant line never answers "This session has no turns yet." The answer comes from one pass only, capped at `FIRST_READ_TURNS` as today. Its `offset` is the value the read returns, the end of the last whole line, so a line still being written reaches the next read whole. A read with `from` above 0 starts where it asks. The comment on `FIRST_READ_TURNS` is rewritten to say this.
3. **A read that starts inside a line.** The first, partial line of such a read is dropped and never drawn.
4. **Results of earlier calls.** A tool result in the tail whose call lies before the start changes nothing and does not throw. A tool call in the tail whose result comes later is patched as today.
5. **The export.** The Markdown export still holds every turn of the file, in the same bytes as today, read through the yielding loop. A client that goes away stops the read where the stream allows it; the report says what happens in flight, after the client leaves, and on two presses, which share no state.
6. The comments of `state/sessions/transcript.svelte.ts` at lines 165, 198 and 271 say what a first read now is. No code of that file changes. `docs/HELP.md` is corrected only if a line there becomes false.

## Cases

- First read of a file above 32 MiB that holds a marked turn before its last 32 MiB and fewer than 200 turns in them: the answer holds the tail's turns in order and not the marked turn, with `offset` the file's size. Test.
- A next read from that `offset` after an append: only the appended turn. Test.
- A file whose last line has no line feed: `offset` is the end of the line before it, and after the line is finished the next read gives that turn whole. Test.
- A file under 32 MiB: the same answer as the unchanged tree, turn for turn. Test.
- A file whose last 32 MiB hold no turn, with one turn 40 MiB from the end and a marked turn further back than the doubled start: the answer holds the first and not the marked one. Test.
- A first read whose start falls inside a line: that line's turn is absent, the lines after it are present, no throw. Test.
- A subagent's transcript over 32 MiB with a marked head turn: the marked turn is absent. Test.
- A Codex rollout over 32 MiB with a marked head turn: the marked turn is absent. Test.
- An empty file and a missing file: the answer of the unchanged tree. Test.
- A result in the tail with no call, and a call in the tail whose result comes in the next read: no throw, and the second call's result patched. Run.
- A file that grows during a read: the answer ends at the last line feed before the read's size, and the next read neither loses nor repeats a line. Run.
- The export of a file of several pieces: bytes equal to the export on the unchanged tree. Test, a preserved behaviour.
- Any read of a file of several pieces, the export and a read from an offset each: macrotasks counted during the read, the body read to its end, are at least the pieces less one. Test.

## Decisions taken in this brief (each reversible, none silent)

1. 32 MiB: on the 111 MB session it holds about 579 user and assistant records, more than the 200 turns a first read keeps, and parses in well under a second on an unloaded machine.
2. A first read of a session whose last 32 MiB hold fewer than 200 turns shows fewer turns; it does not read further back. The older turns stay out of the view, as turns past 200 do today.
3. No worker thread: the bound and the yield end the wait with no new moving part.
4. A session whose tail holds fewer than 200 turns shows fewer with no sign of older ones; the two real tails hold 724 and 626.
