## What to build

Under `tools/oculus/src/lib/server/`:

- `git.ts`: `statusFor(roots: string[], timeout = 5000): Record<string, GitState>`, the cockpit's `sessions_git.py` rule for rule. Exactly four commands, and no others, ever: `git -C <root> rev-parse --abbrev-ref HEAD`; `git -C <root> rev-list --left-right --count @{upstream}...HEAD`; `git -C <root> status --porcelain=v1 -z --untracked-files=normal`; `git -C <root> diff --numstat -z`. One call site (`run(root, args, timeout)`) using `execFileSync` or `spawnSync` with list arguments, never a shell, a five-second timeout, and every failure collapsed into the empty shape with a short `error`. `GitState` is `{ branch, ahead, behind, detached, staged, unstaged, untracked, error }`, an entry `{ path, status, added, deleted }`: `--abbrev-ref` says `HEAD` when detached; `--left-right --count` prints behind then ahead and a branch with no upstream leaves both at zero; porcelain `-z` rows are NUL-separated and never quoted, a rename or copy (`R`, `C`) carries its old path as one extra field which is skipped; a row whose index letter is `?` (or worktree letter) is untracked; an index letter that is not blank, `?` or `!` is staged (with no line counts, since the numstat is the worktree's); a worktree letter that is not blank is unstaged with the numstat's counts; a binary file's `-` becomes null; each list is capped at 200 entries. A root that is not a directory, not a repository, or where git fails or times out, comes back as the empty shape with `error` set, so a caller renders every workspace without a special case; a timeout of zero falls back to the default. Reading a repository leaves it exactly as it was.
- `watch/sessions.ts`: `watchSessions(hub: Hub, options)`: publishes the `sessions` channel, payload `{ records: SessionRecord[]; workspaces: Workspace[] }` from O12's `sessions()`. `fs.watch` with `recursive: true` on `~/.claude/projects` (transcripts append, so a change is a `.jsonl` write), on `~/.claude/sessions` (a registry file appears, changes status, or vanishes), and on `~/.codex/sessions` (O12's second store: a rollout appends under `YYYY/MM/DD/`, and a new day makes a new folder, which the recursive watch on the store's root sees), debounced 500 ms into one rescan; a rescan on start; and, since a process can die without its registry file changing, and a Codex rollout's liveness is a running process plus a fresh file (O12's `codexLive`), a liveness re-check every 15 s that republishes only when the set of live ids or a status changed. The byte-offset cache makes a rescan cost the appended bytes; the report quotes the measured rescan time on the real store after warm-up. `options` carries the paths (`store`, `registry`, `cache`, `overrides`, `roots`) with O12's defaults, the project folders from the portfolio (the watcher takes a `projectFolders()` function so it follows the portfolio's latest snapshot without importing the portfolio watcher), and `windowDays` and `maxSessions` (2 and 40, the cockpit's).
- `watch/git.ts`: `watchGit(hub: Hub, options)`: publishes the `git` channel, payload `{ [root]: GitState }` for the workspaces the latest `sessions` payload names (the watcher subscribes to the hub's `sessions` channel through a sink of its own, so the two watchers meet only on the socket). Per workspace, `fs.watch` on `<root>/.git` (non-recursive: `index`, `HEAD`, refs) and recursive on the worktree, filtered to drop anything under `.git/objects`, `node_modules`, `.svelte-kit`, `build`, `__pycache__`; re-read no more often than every two seconds per root (a trailing-edge throttle), and only the root that changed. A root that stops being named is unwatched. The design's "no more often than every two seconds" is this throttle.
- `src/server.ts` and `vite.config.ts` start both watchers beside the portfolio watcher and close them with it.
- `src/lib/data/model.ts` gains `GitState`, `GitEntry`, `SessionsPayload`, `GitPayload`.
- `src/lib/state/entities.svelte.ts` gains `sessions()` and `git()` accessors; `+page.svelte` subscribes to `sessions` and `git` beside `portfolio` and `config`; the `status` view gains two lines: the count of sessions and how many are live, and the count of workspaces with git state, so the channels are visible before O14 draws them.

Under `tools/oculus/tests/`:

- `server/git.test.ts`: the cockpit's 19 cases on repositories created in a temporary directory with the real `git` (init, commit, stage, change, delete, rename, a path with a space, a binary file, one file staged and changed at once, ahead of an upstream made by cloning the temp repo, a plain directory, a missing path, rubbish input, the empty shape, a zero timeout), each list capped, and the two gates: the module's source names no writing subcommand (a scan of `git.ts` for `commit`, `push`, `add`, `checkout`, `reset`, `stash`, `merge`, `rebase`, `rm`, `mv`, `restore`, `switch`, `tag`, `branch -`, `apply`, `am`, `cherry-pick`, `revert`, `clean`, `gc`, `prune` as the first argument after `-C <root>`), and the one call site runs only the four commands (a spy on the run function recording every argument list over the whole suite, asserted at the end); reading a repository leaves `git status` identical before and after.
- `server/watch/sessions.test.ts` and `git.test.ts`: on synthetic stores in temporary directories with a recording sink: the first publish on start; a transcript append publishing within 2 s with the new record; a registry file appearing making the record live (with the liveness probe stubbed as O12's tests stub it); a git worktree edit publishing that root's state within 3 s and not another root's; a root no longer named is dropped from the payload. Every watcher closed at the end of every test.
- `tests/data/real-hub.probe.ts` prints the git state of the hub's own root (branch, ahead, behind, the three counts) read-only.
