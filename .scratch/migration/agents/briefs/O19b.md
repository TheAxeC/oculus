# Brief: O19b, the transcript view

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md` lines 150 to 156 ("Sessions" under Layer 2: the transcript store, what a record folds) and line 160 ("PTY": a session started elsewhere is observed, transcript only). Asked for by Axel on 2026-09-11: "How do I see an actual session (like the chat of the session)?" Nothing in oculus shows the conversation. O12 folds a transcript into counts, a timeline, the agents and the touched files; the turn text itself never reaches the page. This package adds the one thing missing: the turns of a session, read from its transcript on demand, drawn as a chat in a view of the sessions group, following the file while the session is live.

## What to build

Under `tools/oculus/src/lib/server/sessions/`:

- `turns.ts`: `readTurns(path, tool, from)` returns `{ turns: Turn[], offset: number }`, reading the file from byte `from` with `foldFrom` of `transcripts.ts` (lines 82 to 127; it hands each JSON record to a callback and returns the new offset), so the page can ask for the tail after the first read. `Turn` is a model type in `data/model.ts` beside `SessionEvent`: `{ at: string | null; role: 'user' | 'assistant' | 'tool'; text: string; html: string; tool: { name: string; summary: string; ok: boolean | null } | null }`. A Claude record (`fold.ts` lines 40 to 130 show the shape: `type` user or assistant, `message.content` a string or a list of blocks of `type` `text`, `thinking`, `tool_use`, `tool_result`) becomes: one `user` turn per record whose `origin.kind` is `human` with the text; one `assistant` turn per assistant record holding the concatenated `text` blocks (a `thinking` block is dropped); one `tool` turn per `tool_use` block with `name` and a one-line `summary` (the `file_path`, `command`, `pattern` or `description` field of the input, whichever the input carries first, cut at 120 characters), and its `ok` filled from the matching `tool_result` (`is_error`) when that arrives, matched by `tool_use_id`. A user record that carries only `tool_result` blocks yields no turn of its own. A Codex rollout (`codex.ts` lines 77 to 130 and 185 to 240: `item_completed` items of `type` `UserMessage`, `AgentMessage`, `CommandExecution`, `FileChange`, and the rest) becomes `user` and `assistant` turns from the first two and `tool` turns from the others, named by their type. `html` is `marked.parse` of the assistant's text, the way `server/docs.ts` line 40 renders a README (`marked` is already a dependency; the text is the user's own agent's output on the user's own machine, the same trust `Project.svelte` line 14 states for a README), and the empty string on every other role. The text of a turn is capped at 20000 characters, and `Turn` carries `cut: boolean`, true when the cap applied; the view says so through `t('sessions.turn_cut')`, since the server sends data and no words.
- `server/transcript-routes.ts` and `routes/api/transcript/+server.ts`: `GET /api/transcript?id=<session id>&from=<offset>` answers `{ turns, offset }`. The path and the tool come from the record in the last published `sessions` payload through `bridgedRecord(id)` of `server/sessions/hooks.ts` lines 122 to 130, so only a session the payload holds can be read and no path travels from the page; an id the payload does not hold answers 404 with `{ error }`; a `from` that is not a whole number answers 400. Same-origin like every endpoint (`sameOrigin` of `server/auth.ts` line 37); no token, since this reads. `handleTranscript(request, options)` takes an options bag with `recordFor` defaulted to `bridgedRecord`, the pattern of `handleTerminal`'s `TerminalOptions` (`server/pty/routes.ts` lines 40 to 50), so the route test stubs it.

Under `tools/oculus/src/lib/state/`:

- `transcript.svelte.ts`: `turnsFor(id)` returns the held `{ turns, offset, pending, error }` for a session and schedules the first fetch on a microtask the way `state/docs.svelte.ts` lines 54 to 100 do for a document; `follow(id, lastActivity)` is called by the view from an effect and fetches the tail (`from=offset`) when the record's `lastActivity` has changed since the last fetch, appending the turns and patching a `tool` turn's `ok` when a later result names it. Nothing polls: the `sessions` payload changes when the transcript does (O13's watcher), and that change is what triggers the tail read. What is held stays held for the page's life; a session's turns are a few hundred kilobytes at most, and `forget(id)` exists for a test to reset the module.

Under `tools/oculus/src/lib/views/sessions/`:

- `Transcript.svelte`, registered as `transcript` (`routes/views.ts`, beside `timeline` at lines 126 to 132; label `sessions.view_transcript`, glyph `sessions.transcript_glyph`, a glyph name `glyphs.yml` holds), reading the selected session through `sessionFor(instance.id)` the way `Timeline.svelte` line 30 does. The chat: each turn a block with the role as a label, the time as `clock(at)` of `state/format.ts`, the user's text preformatted (`white-space: pre-wrap`), the assistant's `html` through `{@html}` in a `.doc` block styled as `Project.svelte`'s doc block is, a tool turn one line (name, summary, and a chip `ok` / `error` / pending). A `cut` turn ends with `sessions.turn_cut`. The view scrolls to the last turn when turns arrive unless the reader has scrolled up (the scroll position is more than 40 px above the bottom), and a control in the pane's toolbar jumps to the end. No session selected: `sessions.detail_empty`; a session with no turns yet: `sessions.turns_empty`; a fetch error: the error line.
- `SessionDetail.svelte` gets a control "Open the transcript" (`sessions.transcript_open`) beside the resume control (lines 258 to 275) that opens `transcript` in the main tree through `openView` (`state/layout.svelte.ts` line 283) if no transcript view is up, and focuses it when one is; `SessionList.svelte`'s row menu (`rowItems` at lines 178 to 188) offers the same.
- `config/layout.yml`: the `sessions` entry of `nav_groups` (line 21) gains `transcript` after `terminal`; the `sessions` arrangement (lines 36 to 52) puts `[transcript, timeline]` as the tabs of the main tree's lower pane where `timeline` stands alone now.

Under `tools/oculus/config/text.yml`, the `sessions` group (line 769; the catalog is two files and a group lives in one of them): `view_transcript`, `transcript_glyph`, `transcript_open`, `transcript_open_tip`, `turns_empty`, `turn_cut`, `turn_user`, `turn_assistant`, `turn_tool`, `turn_end` (the jump control), and the tool chip words. `text.yml` is at 850 lines and stays under 1000.

## Facts checked on the tree, 2026-09-11

- No view draws a transcript's turns; the record (`data/model.ts` lines 541 to 600) carries counts, `lastPrompt`, `timeline`, `agents`, `files`, and `path` (the absolute path of the transcript or rollout).
- `foldFrom(path, offset, apply)` reads from a byte offset and returns the new one; O12's cache uses it for the appended bytes.
- `marked` 18 is a dependency, used server-side in `server/docs.ts`; `Project.svelte` draws the answer with `{@html}`.
- A Claude prompt is a `user` record whose `origin.kind` is `human` (`fold.ts` line 82); a Codex prompt is an `item_completed` of type `UserMessage` (`codex.ts` line 187).
