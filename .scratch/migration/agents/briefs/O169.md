## What to build

1. Start Agent on a task that exists starts it: the server finds the collection by its bare key whether the reference names it with its hub (the card, `<hub>:tasks`) or bare (the focus ticker), in the primary hub and in another hub, and `sameTask` treats a card's and the ticker's reference to one task as the same task. "That task is no longer in the hub" stays the answer for a task that is truly gone.
2. A git fetch whose failure matches no row shows ssh's cause line beside git's last line: when the error stream holds a line from ssh (it begins `ssh: `), the failure's line is the last such line, given a full stop when it has none, followed by git's line, each cut as `shortReason` cuts, so the tip reads as two sentences. The join is made in `fetchFailureOf`; `gitsReason` and every other git failure line stay as they are. A failure with no ssh line keeps git's line alone. A failure a row matches keeps the row's line.
3. The Submit Job box draws its cluster pick as a pick: a select of the clusters, the picked one chosen, with Submit and Cancel as the box's buttons, in place of one button per cluster; `Confirm.svelte` gains an optional select drawn above its buttons, through `Select.svelte`, and the other boxes are unchanged. With no cluster picked the select shows no choice and Submit is off; with one cluster, it is chosen; a picked cluster whose plan is refused keeps today's refusal. The delete ask of an entry named by a setting names the setting by its label from the Settings view's words, never by key and field, so a cluster entry reads "Referred to by" the label of `slurm.resource`; the entry page's "Named by" tag draws the same label. Project referrers keep `projectLabel`. The sentence stays `entry_form.delete_used`.
4. The compile database rows read and write the repository by its absolute path: `cpp-form.ts` turns the root key the tab carries into the root's real folder (the expanded path, `~` resolved) before the call, so Add and Edit reach `cpp.yml` and no "repo must be an absolute path" is said for a served root. A root whose folder is missing (`real: ''`) sends nothing and says so with a catalogue line of its own in the `cpp_` group of `config/text/app.yml` ("The folder of {0} does not exist.", `{0}` the root's name).
5. A new terminal whose tmux call fails says why: `routes.ts:516` passes the action to `refusalFor`, and for an action that starts a terminal (start, task, compose, chat, command, latex, resume) a `TmuxFailed` answers the existing word `terminal-not-started` carrying tmux's first line as a name, drawn "The terminal did not start: {0}." from a new catalogue line beside `refused_terminal_not_started` (tmux's own full stop dropped before one is added, so the line never ends ".."). The throwers that pass no names keep "The terminal did not start.". A `TmuxSilence` gives the catalogue's words of `silenceWords`, never execFile's message, so no argument of the tmux call reaches the page. A terminal that was running and ended, a resize and a rename of an unlisted id keep "The terminal has ended.". The comments at `refusal.ts:1-2`, `routes.ts:139-141` and `tmux.ts:96-100` are made true: tmux's own sentence is quoted inside a catalogue line, as git's and ssh's already are (Decision 3).
6. Live HPC's host lines open with a capital and end with a full stop, each of `hpc.yml:49-55`: "The settings of this hub name no cluster (slurm.resource in .oculus/config.yml)." and its four siblings.
7. A cluster's failure is drawn once, in the error box: while the error box is drawn and the resolution failed, the grey line is not drawn; a resolution that succeeded keeps its grey line whatever the poll answers. "Login reason" keeps its text.
8. The Settings view offers the Repository scope while a workspace folder is a git repository: the client's `marksShape` reads `git`, so the mark the server sends reaches `reposOf`, and Repository is offered and lists those workspace folders. A repository nested inside a workspace folder, which the Repositories view lists, is no scope root.
