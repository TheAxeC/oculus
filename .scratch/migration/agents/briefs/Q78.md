## What to build

Each item is an acceptance item.

1. **The library.** Add `marked-gfm-heading-id` 4.1.4 to `package.json` dependencies with its lock entry, and nothing else new. `renderMarkdown` uses it on its own `Marked` instance, for both branches (with and without a folder), so every rendered document's headings carry ids unique within the document, and no other reader of `marked` (`src/lib/ui/html.ts`, `src/lib/server/sessions/stores/turns.ts`) changes.
2. **`[TOC]` becomes the list.** A paragraph whose whole text is `[TOC]` (surrounding whitespace allowed, case as written) is replaced by a nested list of links, one per heading of the document in order, each `<a href="#<id>">` with the heading's text, nested by heading level (a deeper heading is a sub-list of the heading above it; a jump of more than one level nests once). The list sits in a `<nav>` or a `<ul>` with a class the partial styles; if an element or attribute is needed that `ALLOWED_TAGS`/`ALLOWED_ATTR` lacks, add it to the profile with a reason and prove it in `sanitise.spec.ts`. A `[TOC]` inside a code block or a code span, or inside a longer paragraph, stays text. A document with no heading draws an empty result, never the literal `[TOC]`. Two `[TOC]` paragraphs both draw the list. The heading text in the list is escaped; inline markup in a heading (code, emphasis) is shown as its text.
3. **A press on a TOC link scrolls the view's own box.** A press on any link whose `href` starts with `#` inside a drawn document finds the element with that id inside the view's own box (the element carrying the view's `data-instance`), scrolls that box so the heading is at its top, and does nothing else: the page's address does not change, no other tab or view scrolls, the browser's default is prevented. A fragment naming no element in the box does nothing. This holds in the doc view, in the manual (a link in one run of prose reaching a heading in another run, since `Help.svelte` draws the manual as several partials), and in a project's documents.
4. **One draw point.** `Project.svelte` draws a project's document through the shared `Markdown.svelte` partial instead of its own `{@html}` copy and styles, so the list's style and the press behaviour live once. The partial takes whatever it needs from the project view through props; what the project view drew in its loading and failed states stays as it reads today (same words, same classes where a test or a spec reads them).
5. **The list's look.** The list reads as a table of contents in every theme: the partial's link colour, no bullets or the partial's own bullets, indentation per level, the fonts the document uses; colours as tokens only.
6. **Docs.** `HELP.md` says, where it describes documents, that a `[TOC]` line draws the document's contents and a press on an entry scrolls to it. `DESIGN.md` gets a line only if a sentence of it becomes false (grep it for `renderMarkdown`, `Markdown.svelte` and `Project.svelte`).
7. **Tests.** Server tests of `renderMarkdown` in a new `tests/server/content/markdown.test.ts` (or the file that fits): ids on headings, unique ids for two headings with the same text, the nested list for levels 1-2-3 and a jump from 1 to 3, `[TOC]` in a code block and in a longer paragraph left as text, no headings, two `[TOC]` paragraphs, escaping of a heading carrying `<` and `&`, and the list present with a folder base and without. A browser case (in the spec file that fits, or a new one under `tests/browser/workbench/`) that opens a hub document holding `[TOC]` in the served test hub, presses a deep entry, and asserts that the view's box scrolled so the heading sits at its top, that `page.url()` is unchanged, and that a second tab's scroll position is unchanged; one case pressing an entry in the manual whose target heading sits in a later run of prose; one in a project's document. Every new or changed case keeps a `// revert:` directive naming the revert that turns it red.

## Decisions taken in this brief (each reversible, none silent)

1. The list is built on the server inside `renderMarkdown`, from the heading list of the same parse, so the HTML the page receives is already complete and the 304 of `api/docs` keeps covering it.
2. Heading ids are unique within one document, as the library makes them. Two tabs showing the same document hold the same ids; the press looks the target up inside its own view's box, so each tab reaches its own heading.
3. Assistant turns in the sessions views are not documents and keep their current rendering.
