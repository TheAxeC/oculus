## What to build

1. **A key on every entry.** Every entry of `funding`, `events`, `education`, `applications`, `tasks`, `code` and `statements` carries a `key`, in the hub's files and in the demo hub's (`tools/oculus/demo/`), by the rule of decision 1:
   - an entry that has a key keeps it (`FAIR`, `ZonMw-AI-HCC`, `FWO-PhD`);
   - an entry whose `link` names a folder of the hub takes the folder's name, the link normalised first (a trailing `/` or a `./` dropped);
   - every other entry takes its title in lower case, accents dropped, every run of other characters one `-`, no `-` at either end; a title that gives an empty slug takes `entry-<n>`, `<n>` its place in the file from 1;
   - no two entries of one file share a key: in file order, the first keeps the key and each later one takes `-2`, `-3` (the hub's entries have no clash);
   - a key YAML would read as anything but text (a number, a boolean, a null) is written double-quoted.
   The key is written on the entry's first line, before `title`, in the file's own style (a flow map stays a flow map), and no other byte of the entry changes. The builder writes the keys by hand in the worktree's copy, as Axel's ruling (13) asks for a key on every collection entry (`agents/spec.md`, the hub text a ruling asks to have reworded); the report lists every key line added, file by file, and no other line of a hub data file changes beyond item 2's schema row and the head comment of item 8. `data`, `pillars`, `domains` and `joint-work` already key every entry; `venues` keep `id` as their key (decision 3).

2. **The key is the identity.** In each of those seven files (hub and demo) the `schema:` holds `{ field: key, type: text, required: true, help: "..." }` as its first row, so the key is the field a write, Edit in File, the in-place controls and the identity findings address an entry by, and Add builds a new entry with `key:` first: in the five files with no `key` row it is added; in the two `funding.yml` files the existing `key` row moves to the front and becomes required, its help kept. `funding`'s `idRequired` becomes true (`hub-names.ts:106`), so a funding entry with no key is the finding `entry_no_id`, as a keyless entry of `data.yml` is today; `checkFundingIdentity` (`funding_no_identity`), `checkFundingStatements`' `funding_no_key` and `checkEntryIdentity`'s keyless funding branch go, with their two catalog sentences (`findings.yml:200-201`), since `entry_no_id` and the schema's `required` finding now say it for every keyless funding entry. A manifest's `funding: [FAIR]` still names the same scheme. An undo of a write recorded before the step, whose record names the entry by its old title, refuses with the sentence an undo of a gone entry gives and writes nothing.

3. **Which entries have a page.** An entry has a page when its `link` names a folder of the hub: a hub path (`hubPathsOf`'s rule) whose parent folder's listing in the file store holds it as `kind: 'dir'` (a link to a folder inside the hub is one, as the store lists it). The listing is the store's own, held and marked again on a change, so a folder made or removed after the page loaded gives or takes the page without a reload. An entry whose link is a file (the Veni, ENW-XS and VIB.AI entries among them, whose files sit in folders of their own), an address, a path outside the hub, a folder that does not exist or a folder the default listing leaves out has no page.

4. **The page.** A view `entry` (`src/lib/views/boards/entry/Entry.svelte`), registered as opened for something (`group: ''`, `listed: false`), one instance per entry, its state `{ id: '<collection>:<key>', collection, key, label }` so the same entry opened again activates its tab (decision 4). It is drawn from the project and person pages:
   - the pane's title is the entry's title; the toolbar carries the collection file's control (`SourceButton`, as the Person page carries the people file's) and a control that opens the collection view revealed at the entry;
   - the entry's card, drawn open as the project page draws the project card: the same component the collection view draws, with every control it has there (status in place, pin, Edit in File, Show in Files, subtasks, Start Agent on a task), its long fields whole, and no grip;
   - Documents: the folder's Markdown files (`.md`, from the listing), one shown at a time through a `Segment` as on the project page, the chosen one remembered in the instance state and drawn by the shared Markdown partial through `docs.hubDocument(path)`; with none, a sentence says so;
   - Files: the folder's files, each opened in a source tab as the Person page opens a student's file, the block's heading carrying Show in Files rooted at the folder; an empty folder says so;
   - Sessions: the sessions working in the folder or below it, drawn as the project page draws them (the same rule `sessionsForProject` applies to a project's folder).
   Opened for a key the collection no longer holds (an entry removed or its key changed while the tab was saved), the page says the entry is not found; opened for an entry that holds no folder link any more, it draws the card and says the entry names no folder; opened with no state (a saved layout or an app's open with none), it says it was opened for no entry. The session rows are drawn by a shared `views/shared/sessions/SessionRow.svelte`, which the project page draws too in place of its local snippet; the folder's files by a shared `views/shared/links/FolderFiles.svelte`, which the person page draws too in place of its local markup; neither page's look changes.

5. **Opening the page.** On the collection view, the title of a card whose entry has a page is a button that opens the page (`Card`'s `ontitle`), as a project card's title opens the project page; a card whose entry has no page keeps a title that is not a button.

6. **Show in Files of a folder.** On the card (collection view and page alike), the Show in Files control of a hub path that is a folder (by item 3's listing) opens a Files tab rooted at that folder, `showFolderInFiles(path)`, as the project card's does; a path that is a file keeps today's `showInFiles(path)`, which selects it in the Files tab.

7. **The card is shared.** `EntryCard.svelte`, `entry-actions.ts`, `Grip.svelte` and `task-card.ts` move to `src/lib/views/shared/forms/entry/` (decision 5), since the page and the collection view both draw the card with its Start Agent on a task and a view never imports another's files; their head comments and every import follow, and the entries of `tests/checks/tree/allow-styling.ts` and `allow-duplication.txt` that name them change their path and the line numbers their reasons quote, so each reason stays true, nothing added or widened.

8. **The text.** The words of the page in a new `config/text/views/boards/entry.yml` (the view's label and glyph, the block headings, the empty and not-found sentences, the tooltips), every key read. `docs/views.md`: the collection sections say a card whose link is a folder opens its page from its title and that Show in Files of a folder opens a rooted Files tab (`:95-118`, `:249-253`), and "Views opened for something" (`:257`) counts eight views and describes `entry`. `HELP.md:156` gives the true count. `docs/window.md:41` adds an entry to the list. `docs/DATA-MAP.md:156-177` gives `key` as the identity and the "Named by" of the seven files and the true place of `identityField`, `:193-194` say funding writes and is checked by `key`, and `:284` and `:352` say every funding entry carries a key. `docs/files-and-search.md:39` says a collection card's Show in Files of a folder opens a rooted Files tab and of a file selects it. The comments of `docs.svelte.ts:193` and `server/content/docs.ts:451-456` name the entry page among the callers. Each comment named under "What is on the tree" that says how a funding entry is identified (`validate.ts`, `normalise.ts:514`, `collections.ts:133`, `hub-names.ts:93-96`) and each collection file's head comment is made true, the funding file's saying a new entry needs a `key`.

9. **Sizes.** A source file at or under 880 lines, a component at or under 520; `state/boards/collection.ts` (730) takes the folder test in a function of its own; no folder passes 10 items (`views/boards` 9, `views/shared/forms` 10, `config/text/views/boards` 9).
