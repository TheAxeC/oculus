# Brief: O3, data sources part two, collections, documents and config

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "Layer 1, data" and "Boundaries", and the O2 sources (`src/lib/data/sources/manifests.ts`, `registries.ts`, `model.ts`) whose conventions this package continues: synchronous reads, every failure a `Finding`, provenance on every record, no throw.

## What to build

Under `tools/oculus/src/lib/data/sources/`:

- `collections.ts`: `readCollections(hub: string, files: CollectionFile[]): { collections: Record<string, RawCollection>; findings: Finding[] }`. A `CollectionFile` is `{ key: string; file: string }`, the shape of the entries under `collections:` in `tools/cockpit/data/config/layout.yml` (eight of them today: statements, funding, events, education, applications, collaborations, tasks, code). A `RawCollection` is `{ key, file, meta, entries: RawEntry[] }` where `meta` holds every top-level key except `entries` untouched (`title`, `intro`, `schema` are the ones seen) and a `RawEntry` is the YAML map untouched plus `source: { file, index }`. An entry's identity is its `key` when it has one, else its `title`; the source records both as read and derives nothing. A missing or unparseable file, or one whose `entries` is not a list, is a finding and an empty collection. The same file may be named by a registry and a collection (`funding/funding.yml` is): this source reads what it is asked to and does not know about registries.
- `docs.ts`: two functions, both on demand, never called by the portfolio build. `readDoc(path: string): { text: string; frontmatter: Record<string, unknown> | null } | Finding` reads one Markdown file and splits a leading `---` YAML block when present (none of the project READMEs sampled has one; the split still has to work). `projectDocs(folder: string): DocPresence[]` reports which of a fixed list of document names exist under a project folder, by existence only, no read: `README.md`, `PRESENT.md`, `RESULTS.md`, `code/README.md`, `manuscript/main.pdf`, `manuscript/main.tex`. Nothing under `attic/` is looked at. Hub-level documents (`HPC-UTwente-howto.md`, `RESEARCH-APPROACH.md`, `AGENT-APPROACH.md`) go through `readDoc` like any other.
- `config.ts`, extended: `loadConfig(engine: string): { config: Record<string, unknown>; findings: Finding[] }` merges every `config/*.yml` in name order into one map, each file contributing its top-level keys; two files defining the same top-level key is a finding naming both files, and the later one wins. `loadLocal` and `loadTextCatalog` stay as they are. The merged map is what O4's validate and O5's catalog consume; today `config/` holds only `text.yml`, so the function is tested on fixtures and its real-hub run merges one file.
- `model.ts`, extended with `RawCollection`, `RawEntry`, `DocPresence`, and the `Collection` and `Entry` typed entities O4 fills.

Under `tools/oculus/tests/data/`:

- `collections.test.ts`: fixtures in a temporary directory: a collection keyed by `title`, one keyed by `key`, one missing, one whose `entries` is a map instead of a list, one entry that is not a map. Asserts entries, `meta`, `source.index`, the findings.
- `docs.test.ts`: a Markdown file with frontmatter, one without, one missing; a project folder with some of the six documents present and a decoy under `attic/`.
- `config.test.ts`, extended: two fixture files with a shared top-level key produce one finding and the later file's value.
- `real-hub.probe.ts`, extended: also prints the entry count of each of the eight collections and, for the 91 manifests, how many have each of the six documents. The probe stays read-only and stays out of `npm test`.
