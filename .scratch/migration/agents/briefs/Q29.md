## The six fixes, each with its acceptance

1. **Delete over a dirty tab asks first.** A tab whose view holds unsaved text (a source tab whose draft has `text !== saved`) is closed, by Delete and by the close control alike, only after a confirmation drawn as the pane-close confirmation is: the words `ui.tab_close_dirty` ("Close this tab and lose its unsaved changes?" or the tree's wording), the shared `ui.confirm_ok` and `ui.confirm_cancel`. A clean tab closes at once as today. Whether a tab is dirty is one rule the shell asks the layout or the source store for by instance id, not a scan of the DOM. Cases in the Tabs or PaneView test: a dirty tab's Delete draws the confirmation and closes only on the yes; a clean tab's Delete closes at once; the close control follows the same rule. The Q27 decision line and HELP.md's Delete row say it.
2. **`editor.paint_limit_kb`.** `config/behavior.yml` gains `editor: { paint_limit_kb: 64 }` with a comment; a reader beside `changesKeep` throws when the key is missing or not a positive number; the source editor reads the cap from the merged config (`configMap()`) instead of the constant, `PAINT_LIMIT` removed or reduced to the fallback the reader documents. Cases: the reader's throws; the editor painting plain above the configured cap and coloured below it; HELP.md's `behavior.yml` row and the source-tab sentence name the key.
3. **`tasks.skip_permissions`.** The key moves from `chat:` to a `tasks:` block of `behavior.yml` (`tasks: { skip_permissions: false }`, the comment moved with it); the reader becomes `taskSkipPermissions` in a module named for it (`data/tasks.ts`, listed in the boundary table's state row with its reason, `data/chat.ts` keeping `chatModel` alone) and every reader, comment, test, HELP.md sentence, DESIGN.md decision line and the browser spec's write of the served copy follow. Nothing else about the tasks changes. A `chat.skip_permissions` still present in a config is ignored and reported: a finding on the config channel if the tree has a place for configuration findings, else a thrown sentence at start naming the new key.
