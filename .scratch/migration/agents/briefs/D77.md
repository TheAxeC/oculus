1. **The Transcript view keeps its turns while its session's record changes (open item 103).**
   - The cause and the fix are the diagnosis's (`agents/reviews/D77-diagnosis.md`), written into Step 0 of D77 in `plan.md`. The effect `$effect(() => showing(record?.id ?? ''))` at `src/lib/views/sessions/transcript/Transcript.svelte:80` depends on the session record object, which the sessions channel hands anew with every message (`src/lib/state/client/entities.svelte.ts:28,41`). So at every write of any session the effect re-runs, its teardown (the release `showing` returns, `src/lib/state/sessions/transcript.svelte.ts:199-208`) drops the count to zero and `forget`s the turns, the view draws "This session has no turns yet." and the whole transcript is read again from offset 0.
   - The fix: the hold effect reads a derived of the session's id (`const sessionId = $derived(record?.id ?? '')` beside `record`, `$effect(() => showing(sessionId))`), with the comment above the effect saying why.
   - The same view draws "This session has no turns yet." while a session's first read is pending (`Transcript.svelte:166-167` reads `turns.length === 0` and never `held.pending`), a flash each time a session is opened. While the read is pending the column keeps its place and draws no sentence; the sentence is drawn only for a session whose read landed with no turns.
   - When done, a Transcript tab whose session gets a new record (a turn appended, its activity time moved, its title changed) keeps the turns it holds, asks the server only from the offset it last read, and its column neither empties nor jumps; a change to another session, or the tab's close, still releases the held turns.
   - The diagnosis's red command (the twelve-case harness `tests/diag/flicker.client.test.ts` with `tests/diag/TranscriptInGroup.svelte`, quoted whole in the record's "Red command" section) is built in a scratch copy under `$TMPDIR`, run there on the unchanged tree and on the changed tree, and never added to the worktree, since no guarded entry covers a view (`agents/guarded.md`, its head) and the rules file keeps no other test.
