## What to build

When the step is done: a source tab learns of every change of its file on disk within a second; a tab with no unsaved text takes the new text with its caret and scroll kept; a tab with unsaved text keeps it, says the file changed, and its Save is refused by the server with Compare, Overwrite and Revert; `editor.autosave` saves after a delay or on a focus change, `off` by default; two keys per language trim trailing whitespace and end the file with one newline, off by default; and the server refuses to replace a file that is not UTF-8 throughout, keeping a BOM the file starts with.

### 1. A file changed on disk under an open tab (part 1)

1.1 The draft knows what it read. `SourceDraft` gains `base: string` (the hex SHA-256 of the bytes the tab last read or wrote, the empty string for an untitled text or a tab at HEAD or in the index) and `disk: 'same' | 'changed' | 'gone'` (what the tab knows of its file), both in `draftShape` with `catch` defaults (`''`, `'same'`). `loadSource` reads the bytes with `readCappedBytes(response, TEXT_LIMIT)` (`fs-transport.ts:313`), computes `base` with `crypto.subtle.digest('SHA-256', bytes)` (the page is served from localhost, a secure context) over exactly those bytes, and decodes them as today. A truncated read keeps the base of its bytes and still saves nothing.

1.2 The server says when an open file changes (Choice C1, written for its recommendation (a)). A channel per open file, `source:<root>/<path>`, its payload `{ hash: string | null }`: the hex SHA-256 of the file's bytes, or null when nothing readable is there (deleted, a folder, unreadable).
- A new server module `src/lib/server/files/fs/open-files.ts` (Layer 2 server; `server/files/` holds 10 items, `fs/` holds 7) registers with the hub at start a listener for the channel family: the first subscriber of a `source:` channel resolves its root key and path with `resolveRootPath` over `browserRoots` (the source route's roots); a name that does not resolve inside a root is never polled and never published. A resolved file is polled with `pollFile` (`POLL`, the server's clock); on each move it reads the file, hashes it with `node:crypto` and publishes the hash; the first publish is at the first tick. A tick that finds `hub.hasSubscriber(channel)` false closes that poll (every page holding it has closed its socket). It is started and closed beside the other watchers in `src/lib/server/root/context.ts` (the `make.watchGit` call at :355 and `close()` at :471-480, main), and DESIGN.md's channel list (`DESIGN.md:114`) gains `source:<root>/<path>` beside `pty:<id>`.
- The source store subscribes a tab's channel through the socket store's `subscribe` once its draft has loaded, listens with `listen`, and drops the listener and the name with `unsubscribe` when no open tab holds that file. Several tabs over one file share one channel.
- On a message for a file: a tab whose `base` equals the hash is `disk: 'same'` and nothing else moves; a null hash makes every tab over it `disk: 'gone'` with its text kept; another hash reads a tab with no unsaved text again (its text, `saved` and `base` from the new read, `disk: 'same'`) and makes a tab with unsaved text `disk: 'changed'` with its text kept. The read again keeps an edit typed while it was out, as `reloadSource` does now (main :355-369).
- `reloadClean` in `explorer/ops.svelte.ts` keeps reading clean tabs at once after a Replace; the channel's message that follows finds the same hash and moves nothing.

1.3 The save carries the base and the server compares it.
- `SourceBody` gains `base?: string` (64 hex characters; any other value is a 400 with `root, path and content are required` widened to name `base`) and `create?: boolean`.
- `handleSource` reads the file's bytes once (`readFileSync`) with the `stat` taken before the read. With a `base` that differs from the bytes' SHA-256, or a `base` and no file, it answers 409 `{ ok: false, error: 'changed', refused: [{ field: 'base', reason: 'changed' }] }` and writes nothing. The history copy is made from the bytes read (`keepCopy` takes the bytes, or a new `keepBytes` beside it in `fs/history.ts`), so the copy is the text the compare saw. Right before the write it stats the file again and refuses `changed` when inode, size, mtime or ctime moved since the first stat. The `ok` answer carries `hash`, the SHA-256 of the bytes written.
- A body without `base` writes as today (Overwrite, the Timeline's Restore). A body with `create: true` and no file writes a new file when its folder exists inside the root (`resolveRootPath` of the parent is a directory), refuses `outside` as today for a path out of the root, and answers 404 `the file is not there` when the folder is gone; `create` over an existing file is the ordinary save with its base rule.
- The tab's `saveSourceDraft` sends `base: draft.base` (or `create: true` and no base for a `disk: 'gone'` tab after Overwrite), sets `base` to the answer's `hash` and `disk` to `'same'` on `ok`, and on `changed` sets `disk: 'changed'` (or `'gone'` when the next channel message says so) and the message below.

1.4 What the tab draws (`SourceNote.svelte`, X3f's `save/`, or a new `save/DiskNote.svelte` beside it; the strip through the registry below).
- A tab with unsaved text and `disk: 'changed'`: the line under the editor `source.disk_changed`.
- A save refused `changed`: the line `source.save_conflict` with the file's name (VS Code's 16205), and three `ToolButton`s: Compare (`source.compare`), Overwrite (`source.overwrite`), Revert (`source.revert`).
  - Overwrite saves the tab's text with no base (with `create: true` for a gone file).
  - Revert reads the file again and takes its text, dropping the tab's edits (VS Code's 16348); for a gone file it takes `saved`, the text the tab last read, and keeps `disk: 'gone'`.
  - Compare opens a diff pane beside the tab: the file on disk on the left, the tab's text on the right, read-only, titled `source.conflict_title` (`'{0} (in file) <-> {0} (unsaved) - Resolve save conflict'`). `DiffSubject` (`state/sources/repositories/repositories.ts:133-156`, main) gains `unsaved?: string`, the source tab's instance id, held in its shape and its key (`compare@...` beside `save@...`, :167-169); `diff-read.ts` (`views/sources/repositories/diff/`) answers such a subject with one `DiffSides` whose `original` is the file's text read through `api/file` and whose `modified` is `sourceDraft(id).text`, built on the page, since the Monaco diff editor computes the hunks (`server/files/fs/ops.ts:794-803` builds the same shape for the Replace Preview). A pane whose tab is gone says `source.conflict_gone`.
- A tab with `disk: 'gone'`: its label on the strip is drawn struck through with the title word `ui.tab_deleted` ("Deleted", VS Code's 23871): `ui.svelte.ts` gains `registerDeleted` beside `registerUnsaved` (:335, main), `context.ts` registers the source store's `sourceGone`, `PaneView.svelte` passes `deleted` beside `dirty` (X3f :212), and `TabFace.svelte` draws it. ### 2. `editor.autosave` and its delay (part 2)

2.1 The keys, in `config/behavior.yml`'s `editor:` block after `sticky_scroll` and in `config/catalogs/options.yml` after `editor.sticky_scroll`, with `heading: editor`, `section: Source editor` (Choice C3 names the delay key):
- `editor.autosave`: `control: choice`, `values: ['off', after_delay, on_focus_change]`, `default: 'off'`, its description VS Code's three sentences (16454, 16453, 16455) with `on_focus_change` saying it also saves when the page loses focus.
- `editor.autosave_delay_ms`: `control: number`, `min: 0`, `whole: true`, `default: 1000`, described as 16406 says.
- `readEditorOptions` reads both through `settingReader` (`text`, `number`), and `EditorOptions` gains `autosave` and `autosaveDelay`. The comment above the block (`behavior.yml:114-116`) names them with VS Code's `files.autoSave` and `files.autoSaveDelay`.

2.2 The behaviour, in a new client store `state/sessions/source/autosave.svelte.ts` (see 6.1 for the folder), made in `context.ts` beside `createSource` with the store, `editorOptions` and a clock the store is handed (a `setTimeout` and `clearTimeout` pair, the page's globals in `context.ts`):
- A tab is saved automatically only while it holds unsaved text, its draft is loaded and whole, it is writable, it names a file on disk (not untitled, not at HEAD or in the index) and its `disk` is `'same'`. A tab whose save was refused `changed` is not saved automatically again until the reader saves, overwrites or reverts.
- `after_delay`: each edit restarts the tab's timer of `autosave_delay_ms`; at its end the tab is saved as an automatic save.
- `on_focus_change`: the tab is saved when its editor loses focus (Monaco's `onDidBlurEditorWidget`, handed up from `ui/controls/editor/Editor.svelte` and `views/sources/source/Editor.svelte` as `onblur`), which covers focus moving to another tab, pane, view, a frame or the tree; and every such tab is saved when the page loses focus (`window` `blur`, and `visibilitychange` to hidden).
- A change of the key into `after_delay` or `on_focus_change` saves every such tab at once.
- Closing a tab with unsaved text under `on_focus_change`, or under `after_delay` with a delay of 1000 ms or less, saves it and closes it without the question; a save that is refused keeps the tab open and asks as today (`close-question.svelte.ts`, X3f).
- An automatic save runs the same `saveSourceDraft` path as Cmd+S, base included, so it never writes over a change on disk.

### 3. Trim trailing whitespace and the final newline, per language (part 3)

3.1 The keys (Choice C2 names them; written for its recommendation): global `editor.trim_trailing_whitespace` (`control: toggle`, `default: false`) and `editor.final_newline` (`control: toggle`, `default: false`), and the same two fields in the `editor.languages` entry's `fields` (`control: toggle`), described with VS Code's 16501 and, for `final_newline`, 16474 and 16500 together ("Ends the file with one line ending when saving it: a last line with text gets one, and the empty lines after the last line with text are taken off."). `LanguageRecord` gains `trimTrailingWhitespace?` and `finalNewline?`, `readRecord` gains their two `case`s, `EditorOptions` the two globals, and `EditorResolved` the two values taken through `layered` (the root's `.oculus/settings.yml` record, `editor.languages`, the global key), so a repository's file overrides them as it does the indentation.

3.2 The rule, a pure module `src/lib/data/helpers/files/save-text.ts` (Layer 1 data; `data/helpers/files/` holds 5): `saveText(text, rules, keep)` answers the text to write, in VS Code's order and by its rules, over the text's own line endings (`\r\n` or `\n`, `lineEnding` in `state/workbench/navigation/editor-text.ts`):
- trim: on each line, the spaces and tabs at its end go; the line ending stays; on an automatic save a line in `keep` keeps the whitespace before its caret column.
- final newline, insert: when the last line holds a character other than a space or a tab, one line ending in the text's own form is appended.
- final newline, trim: every line after the last line that holds any character is taken off, so the text ends with one line ending; on an automatic save a line in `keep` stays.
- An empty text stays empty; a text of only line endings becomes empty.

3.3 Where it runs. `saveSourceDraft` takes the tab's rules from the store (the tab's language, `draft.language` or `languageOf(path, languages())`, the root's records through S5's `repoSettings` selector and `editorOptions`, resolved by `resolveEditor`), writes `saveText`'s answer into the draft's `text` before it sends it, and sends that text. Cmd+S, the palette's Save, Open Editors' Save, an untitled text's first Save and an automatic save all run it; the Timeline's Restore writes the copy as it is. `keep` is the caret line the tab reports to the editor status store, on an automatic save only.

3.4 The editor takes a changed text with its smallest edits. The effect at X3f `Editor.svelte:322-343` (the comment "A text the parent hands in that the model does not hold already") replaces only the lines that differ: the common leading and trailing lines are left, and when the lines between have the same count each changed line is one edit, else the span is one edit, in one `pushEditOperations` (one undo). A pure helper `src/lib/data/helpers/files/text-edits.ts` computes the edits from the two texts; the effect applies them. A trim, a final newline and a clean tab's read again then leave the caret and the scroll where they were, and one Cmd+Z puts the trimmed text back. The comment is rewritten for the new rule.

### 4. The whole file is tested as UTF-8 before a save (part 4)

- `text-kind.ts` gains `isTextFile(bytes)`: no NUL byte and a fatal UTF-8 decode of every byte, `isTextBytes` kept for the head sniff of the file browser. The head comment (:1-13) says which caller uses which.
- `handleSource` runs `isTextFile` over the bytes it read for the compare, and refuses `binary` when they fail; `isBinaryFile` goes (its only callers are `handleSource`, `grep -rn isBinaryFile src tests`). `source.binary` is reworded to say the file is not UTF-8 text throughout.
- A file that starts with the UTF-8 byte order mark keeps it: the server writes U+FEFF (the bytes EF BB BF) before the content when the bytes it read start with EF BB BF and the content does not start with U+FEFF. A new file (`create`) gets no BOM.

## Cases

Each case is the input, then the expected result. "Clean" is a tab with no unsaved text, "dirty" one with some.

Part 1, a change on disk:
1. Clean tab over `a.md`; another program appends a line: within one second the tab shows the new line, the caret line and the scroll unchanged, no unsaved mark, `base` the new hash.
2. Dirty tab over `a.md`; another program rewrites it: the tab keeps the typed text and its unsaved mark, and draws `source.disk_changed`.
3. Case 2, then Cmd+S: the server answers 409 `changed`, nothing is written (`shasum` of the file unchanged), and the tab draws `source.save_conflict` with Compare, Overwrite and Revert.
4. Case 3, Compare: a diff pane opens beside the tab, the file on disk on the left and the typed text on the right, titled `a.md (in file) <-> a.md (unsaved) - Resolve save conflict`.
5. Case 3, Overwrite: the file holds the typed text, the unsaved mark goes, the line goes, a copy of the other program's text is in the local history.
6. Case 3, Revert: the tab holds the file's text, the unsaved mark goes, the line goes.
7. Cmd+S on a dirty tab whose file nobody else wrote: saved, as today; the answer's hash becomes `base`; the channel's next message moves nothing.
8. Two tabs over one file in two panes, one dirty: an outside write reads the clean one again and marks the dirty one changed; one `source:` channel is subscribed for both.
9. A save racing an outside write: the outside write lands between the server's read and its rename (a test hook between the two, or a second stat that differs): refused `changed`, the outside text left on disk.
10. A dirty tab whose file is deleted on disk: the text stays, the strip draws the label struck through titled `Deleted`, the line says `source.disk_gone`; Cmd+S writes the file again with the typed text.
11. A clean tab whose file is deleted: the same mark and line; Save writes it again; no question on close (it holds no unsaved text).
12. A deleted file whose folder is deleted too: Save answers the 404 sentence `the file is not there` and the tab keeps its text.
13. A file replaced by a link to another file inside the root, with different text: the hash differs; a clean tab takes the target's text, a dirty one is marked changed; Overwrite writes the target and the link stays a link (`readlink`).
14. A file replaced by a link pointing out of every root: the channel's poll stays as it was resolved; Save answers 403 `the path is outside the named root` and writes nothing.
15. A `source:` channel naming `hub/../../etc/passwd`, a root key nothing names, or an empty path: never polled, never published.
16. Every page holding a `source:` channel closes: the next tick closes that poll.
17. Timeline Restore over a file open in a dirty tab: the copy is written (no base), and the tab is marked changed.

Part 2, autosave:
18. `editor.autosave: off`: typing and waiting 5 s writes nothing.
19. `after_delay`, delay 1000: typing, then 1 s with no key: saved once; typing every 500 ms for 3 s: saved once, 1 s after the last key.
20. `after_delay`, delay 0: each edit saves; the history keeps at most its 50 copies as today.
21. `on_focus_change`: typing, then a press in the Files tree: saved; typing, then a press into a Document tab's frame (an iframe): saved; typing, then Cmd+Tab to another app: saved.
22. `on_focus_change`: closing a dirty tab saves it and closes it with no question; under `off` the question is asked as today.
23. Autosave on a dirty tab marked changed: nothing is written; the line says so; Cmd+S gives the conflict.
24. Autosave on a read-only, truncated, untitled, HEAD or index tab: nothing is written.
25. The key changed from `off` to `after_delay` in the Settings view with two dirty tabs: both saved.
26. `editor.autosave: sometimes`, `editor.autosave_delay_ms: -5` and `1.5` in a synthetic `behavior.yml`: the default (`off`, 1000) and one finding naming the key each (G13).

Part 3, trim and final newline:
27. `trim_trailing_whitespace` on: `"a  \nb\t\n"` saves as `"a\nb\n"`; a CRLF file `"a  \r\nb \r\n"` saves as `"a\r\nb\r\n"`, every `\r` kept.
28. `final_newline` on: `"abc"` saves as `"abc\n"`; CRLF `"abc"` with CRLF elsewhere in the text gets `\r\n`; `"abc\n\n\n"` saves as `"abc\n"`; `""` stays `""`; `"\n\n"` becomes `""`; `"abc\n  "` stays `"abc\n  "` (VS Code's rule, the last line holds only whitespace).
29. Both off (the default): every byte the reader typed is written.
30. A language override: `editor.languages: { markdown: { trim_trailing_whitespace: false } }` with the global key on: a `.md` file keeps its two-space line breaks and a `.py` file is trimmed; a repository's `.oculus/settings.yml` `languages: { python: { final_newline: false } }` with the global on: that repository's `.py` files get none.
31. An automatic save with the caret at the end of `"x   "`: the whitespace of the caret's line stays; a Cmd+S trims it.
