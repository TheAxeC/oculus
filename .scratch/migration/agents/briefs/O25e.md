## Decisions taken in this brief (each reversible, none silent)

1. **The linkedin feed is a folder scan.** `server/feeds.ts` gains `linkedin`: the folder's `.md` files read with a small front-matter parser (`key: value` lines between the `---` fences; a value wrapped in one pair of double quotes loses them, as the folder's titles are), each as `{ file, title, date, category, body, idea }`; `GET /api/feeds?kind=linkedin` answers `{ ok, missing? , entries, cadenceDays }`.
2. **Two writes.** `kind: 'linkedin-idea'` `{ title, category }` writes `xx-<slug>.md` (a slug of lower-case letters, digits and hyphens; a numbered suffix when the name is taken) with the front matter `layout: post`, `title`, `category`, `publish: True`, `date: <today>` and an empty body, refused without a title; `kind: 'linkedin-post'` `{ file }` renames `xx-<slug>.md` to `<NN>-<slug>.md` with `NN` one past the highest number in the folder, and every other file of the same basename with it, refused for a name that is not an `xx-` idea file or that is not there. Both write only inside the configured folder (the path checked with the same inside-root rule `server/writes/entries.ts` uses). `state/writes.svelte.ts` gains `addLinkedinIdea` and `markPosted`.
3. **The pure parts.** `state/linkedin.ts`: `daysSince(posts, today)`, `cadence(days, target)`, `pickIdea(ideas, today)`, `snippet(body)`, `splitPosts(entries)`, `linkedinSearch`.
