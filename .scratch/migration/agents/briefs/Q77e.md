## What to build

1. **One parse per file per reader.** A new module `bin/diagrams/parsed.mjs` exports `parseReader(cache = new Map())`, which returns `{ imports(path, text), code(path, text) }`: `imports` gives what `importsOf(path, text)` gives and `code` what `codeOf(path, text)` gives, each computed once per path and kept in `cache` under the path with the text it was computed from, and computed again only when the text given differs from the text kept. It opens with a Layer 4 head comment in the tree's form saying what it is and why (every diagram reads the same parse of a file, and a caller that generates twice over trees that differ in a few files hands the same cache to both, so only the changed files are parsed again).
2. **Every reader in the generator goes through it.** `runtimeImports`, `layersDot`, `layerDot`, `channelsDot`, `writesDot` and `writesDrawn` take the reader as a new last optional parameter, defaulting to `parseReader()`, and call `read.imports` and `read.code` where they now call `importsOf` and `codeOf`; the write chain's own `importsOf` wrapper (`writes.mjs:72`) reads through it too. `generate(engine, cache = new Map())` makes one reader over `cache` and passes it to every diagram; `staleFiles(engine, drawn, cache)` passes `cache` to its `generate`. `main()` is unchanged in what it writes. Every drawing stays byte for byte what it is: `npm run diagrams` changes no file under `docs/diagrams/`.
3. **The tests share one cache.** `diagrams.test.ts` keeps one cache for the file: `engineDrawn()` generates the engine with it, and the changed-copy case passes it to `staleFiles(dir, undefined, cache)`, so that generation parses the two changed files and reads the rest from the cache. `readable.test.ts`'s `engineDrawn()` passes a cache of its own.
4. **Tests of the reader**, in a new `tests/checks/diagrams/parsed.test.ts`: the same path and text twice give the identical result object (`toBe`) for both `imports` and `code`; a changed text gives the new file's result; two readers over one cache share results; a reader with no cache argument keeps its own. Each case carries a revert directive in the tree's form, red under its revert.

## Decisions taken in this brief (each reversible, none silent)

1. The cache is keyed by the path and holds the text it was parsed from; a result is reused only when the text given is the same string. A comparison of the whole text is exact, where a hash is not, and costs less than one parse.
2. The cache lives in memory and is handed in by the caller. `npm run diagrams` runs in a fresh process and gets its speed from parsing each file once per run; no cache is written to disk, so there is no cache file to go stale when the parser changes.
