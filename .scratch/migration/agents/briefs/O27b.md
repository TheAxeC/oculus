# Brief: O27b, the file browser: bookmarks as a collection and transient notes

Read `../spec.md` first; it governs this package unchanged. O27a landed the file browser (`views/Files.svelte`, `views/File.svelte`, `server/fs.ts`, the workspaces); this package adds the two remaining bullets of the cockpit roadmap's item F (`ROADMAP.md` lines 86 and 87): bookmarks as a collection YAML editable in-page, and transient notes autosaved to a scratch folder. Today the rail's Docs section reads the two bookmarks of `config/layout.yml` lines 112 to 114 (label, root, path), which stay as the shipped defaults.

## The acceptance list, from the roadmap as read on 2026-09-11

1. Bookmarks: a reader's own list, each `{ label, root, path }`, drawn in the rail's Docs section after the configured ones and in the Files view's toolbar as a star on the open file (set, unset); "+ bookmark" and edit through the shared entry form over the schema of decision 1; a bookmark opens its file as the Docs entries do (`document` for HTML, `file` otherwise).
2. Notes: a "+ note" in the Files toolbar opening a `note` view (one instance per note; `listed: false`): a title line and a text area, saved to the scratch folder on every change after a short pause (autosave, with the saved time shown), listed in a Notes section of the Files view (title, modified, delete behind the confirm); a note is plain text and never leaves this machine.

## Decisions taken in this brief (each reversible, none silent)

1. **The bookmarks file is `~/.oculus/bookmarks.yml`**, a collection file in the hub's own shape (`title`, `schema` of `label` (text, required), `root` (select over the current roots' keys), `path` (text), `entries`), read and written through the collection machinery of `server/writes/entries.ts` with the collection key `bookmarks` resolved to that file rather than through `sources.yml` (a table in `server/fs.ts`: the key and its file), so `newEntry`, `writeEntry` and `deleteEntry` of `state/writes.svelte.ts` work on it unchanged; the identity is `label`. The rail's Docs section fetches the file's entries through `GET /api/fs?bookmarks=1` on mount and after a write; the shell reads the registry and its own fetch, never a view.
2. **The notes folder is `~/.oculus/notes/`**, one `<id>.md` per note with the title as the first line, the id a timestamp slug; `GET /api/fs?notes=1` lists them; `POST /api/fs` gains `{ action: 'note-save', id, title, body }` and `{ action: 'note-delete', id }`, both inside the folder by the inside-root rule; the autosave debounce is 800 ms in `config/behavior.yml` as `notes.autosave_ms`, a user-visible key named here.
3. **The pure parts.** `state/notes.ts`: `noteId(now)`, `titleOf(body)`, the debounce as a pure scheduler under test with a fake clock.
