## The write rule

A write changes the bytes of the field it writes and no others. The manifests are hand-written YAML with comments, alignment and a style per file, and a whole-file rewrite through a YAML serialiser reformats lines the user did not touch: measured on 2026-09-10 with the `yaml` package, `parseDocument(text).toString({ flowCollectionPadding: false, lineWidth: 0 })` gives back 65 of the 91 manifests byte for byte and changes 26, all cosmetically (a trailing space after `venue_id:`, comment alignment after `compute: hpc`, `{ do: ... }` padding, a list's indentation). So the file is never serialised whole. The edit is surgical: the `yaml` package's `parseDocument` gives every node its byte `range` in the source, the value's bytes of the one node are replaced, a missing key is inserted as one new line in its map, a cleared key's line is removed, and everything else is copied through. The result must parse, and parsed it must equal the old document with only that field changed.

## What to build

Under `tools/oculus/src/lib/server/`:

- `yaml-edit.ts`: `setFields(source: string, fields: Record<string, unknown>): { text: string; changed: string[] }`. A field name is a dotted path (`status.line`, `code_availability.url`); a value is a string, a number, a boolean, a list of strings, or null (clear). For an existing scalar, the value's byte range is replaced by the scalar rendered in the file's style: plain when YAML allows it, double-quoted otherwise, with the file's own quoting kept when the old value was quoted. For an existing list, a flow list stays flow (`[a, b]`, no padding, the style the manifests use for `funding`, `program`, `datasets`, `related`, chips) and a block list stays block (`results`, `ideas` are block lists on the tree); an empty list is `[]`. A missing top-level key is appended after the last top-level key as `key: value`; a missing nested key is appended inside its map at the map's indentation, and a missing map (`followup:` when neither key exists) is created with its first key. Null removes the key's line or lines (a block list goes whole). A value equal to the current one is not a change and is not in `changed`. `id`, `tier` and `type` are never written (the cockpit's rule, and O2's reader derives two of them from the folder). Nothing is thrown for a bad path; it is reported in a `refused: { field, reason }[]` beside `changed`. The output is verified inside the function: it parses, and `parse(text)` deep-equals `parse(source)` with the changed fields applied; if it does not, the function returns the source unchanged with every field refused, so a bad edit never reaches disk.
- `auth.ts`: `sameOrigin(request: Request, host: string): boolean`: true when `Sec-Fetch-Site` is `same-origin` or `none`, or when `Origin` parses to a hostname of `127.0.0.1` or `localhost` (the socket's rule of O6, reused, not copied: O6's `allowedOrigin` moves here and `socket.ts` imports it). `mintToken()`: 32 random bytes as hex from `node:crypto`. The token is minted once per process at module load of `src/hooks.server.ts` (the Kit graph, which is where the page load and the write route both run; `src/server.ts` and the socket never need it), put on `event.locals.token`, and shipped to the page as page data by `+page.server.ts`. `app.d.ts` declares `locals.token`.
- `writes.ts`: `writeManifest(hub, config, id, fields)`: finds the manifest by id through `readManifests` (O2, 60 ms on the hub), refuses an unknown id, refuses a field the schema does not name (`fieldNames` of O4), coerces values by the field's `type` (below), calls `setFields`, writes the file with `writeFileSync` only when `changed` is not empty, and returns `{ changed, refused }`. It never writes outside the hub's scan directories (the path comes from the reader, never from the request).

Under `tools/oculus/src/routes/api/write/`:

- `+server.ts`: `POST` only. Refused with 403 and `{ error }` when `sameOrigin` fails or the `x-oculus-token` header is not the process token; 400 on a body that is not `{ kind: 'manifest', id: string, fields: object }`; 404 on an unknown id; 200 with `{ ok: true, changed, refused }` otherwise. `kind` is a discriminator so later packages add `collection` and `session` writes on the same route.

Under `tools/oculus/config/manifest-schema.yml`, the form becomes data, which `DESIGN.md` says it is ("the project.yml edit form"): every entry under `fields:` gains `type` and `section`, and where the widget offers choices `from` or `options`. The types are the cockpit's, as facts: `readonly` (id, tier), `select` (type from `type_order`, focus from `focus_lanes`, priority from `priority_levels`, venue_id from the venues registry, domain from the domains registry, code_availability.status from the literal options `none`, `review-anon`, `deposited`, compute from `hpc`, `local`), `text`, `tags` (free strings: authors, waiting-on), `chips` (choices with search: status.chips from `status_legend`, program from programs, funding from funding, collaborators from collaborations, related from projects, datasets from datasets), `textarea` (eli5, next, latest, followup.do, code_availability.description), `lines` (results, ideas: one item per line), `date` (deadline, followup.after, snooze, code_availability.date, reproduced.date), `checkbox` (pin). `section` is one of the seven names already under `sections:`. `from` names a registry (`venues`, `programs`, `funding`, `datasets`, `domains`), the `collaborations` collection, `projects`, or a vocab key (`type_order`, `status_legend`, `focus_lanes`, `priority_levels`); `options` is a literal list. The file keeps its comments and its two-space style; it is no longer byte-identical to the cockpit's, and the `.prettierignore` comment says so as it does for `text.yml`.

Under `tools/oculus/src/lib/state/`:

- `writes.svelte.ts`: `setToken(token)` (from page data), `writeManifest(id, fields)` doing the `fetch` POST with the header and returning the response, `pending()` and `lastError()` as `$state` for a view to show; on a 403 the page data is reloaded once (`invalidateAll`) for the token a restarted dev server re-minted, and the write retried once.
- `schema.ts`: `formFields(config)` reading `manifest_schema` into `{ field, label, help, type, section, from, options }[]` in file order, and `choicesFor(field, snapshot, config)` resolving `from` into `{ id, label }[]` from the snapshot's entities or the vocab.

Under `tools/oculus/src/lib/ui/`: `Field.svelte` (label, help, the control as a snippet), `TextInput.svelte`, `TextArea.svelte`, `Select.svelte`, `MultiSelect.svelte` (chosen items as removable chips, a search box filtering the choices, keyboard through the list), `Checkbox.svelte`, `DateInput.svelte`, all tokens only, all under the colour gate.

Under `tools/oculus/src/lib/views/`: `Editor.svelte`, registered as `editor` (label `views.editor`, glyph `edit`), whose instance state is `{ id }`; it renders a `Pane` with the project's title, the sections in order, each field with its widget bound to a local copy of the project's current values, a Save button posting only the changed fields, a Revert button, and a line for the result (`ok`, or the refusals). `openView` in `layout.svelte.ts` gains an optional `state` argument so a card can open the editor for its project; the project card of O10 gains the edit control (`cards.edit_manifest`) that does `openView('editor', 'panel', { id })`. Saving leaves the editor open; the snapshot push updates the card.

## Facts checked on the tree, 2026-09-10

- The `yaml` package (2.9) is already a dependency; `parseDocument` keeps comments and gives every node `range: [start, valueEnd, nodeEnd]` byte offsets into the source. The round-trip measurement above is the reason the edit is surgical.
- `manifest-schema.yml` holds 45 fields with `label` and `help` and no `type`; the types and sections listed above are `schema.py`'s, one per field, and the options sources are its `type_opts` (`type_order`), `chip_opts` (`status_legend`), `focus_opts` (`focus_lanes`), `prio_opts` (`priority_levels`), and the five registries plus collaborations and projects.
- `focus_lanes` and `priority_levels` are keys of `config/vocab.yml` (lines 160 and 180).
- On the tree (counted over the 91 manifests): `results` is a block list in 37 and flow in 1; `ideas` block in 47, flow in 3; `funding` flow in 22, block in 3; `program` flow in 90, block in 1; `related` flow in 46, block in 1; `status.chips` flow in 90, block in 1; `datasets` flow in 25 and `collaborators` flow in 36, never block. So the rule "a list keeps the style it has" is what the edit follows, and the style for a list that is being added is flow for the relation fields and block for `results` and `ideas`. `followup` is a flow map on 2 manifests and a bare scalar on 1 (the cockpit's dual shape; setting `followup.do` on the scalar form replaces the scalar by the map). `venue_id: ` with a trailing space and nothing after it (five manifests) is a null the edit must treat as absent.
- Kit's server graph (`hooks.server.ts`, the routes) and `src/server.ts` are separate module graphs in the built server, so a module-level value in one is not seen by the other; the token therefore lives in the Kit graph only, which is where both its producer and its consumer run.
- The watcher of O6 republishes `portfolio` about 200 ms after a write; the editor does not update the snapshot itself.
