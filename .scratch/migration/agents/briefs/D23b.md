## What to build

Eight parts, under Z682.

1. **One entry per server** (Z686 (5)). A server is declared by one entry of `servers.ts` (its spawn, its adapter) and one entry of a shared module under `src/lib/data/` (in a subfolder with room: `helpers` 9, `prose` 4, `shapes` 1 or `snapshot` 8, named in the report) holding what the page needs before any message: its languages, its labels' text keys, its semantic tokens, its format-on-type, its own commands such as Organize Imports and its choice kinds (the interpreter, the compile database, the Svelte config approval); both are keyed by the server's id, and nothing else names a server or its language: every place listed under "What is on the tree" reads the entries instead of a `python`/`clangd` branch, the `approve` message and `ChoicesBody` included. `servers.ts:6`'s sentence is rewritten to name the two places, and `hosts.ts:10`'s head comment follows. The labels' key prefix joins `COMPUTED_PREFIXES` in `tests/checks/source/keys.test.ts`, and the report names that change. Existing behaviour of pyright and clangd is unchanged.
2. **The TypeScript and Svelte servers.** `typescript-language-server` 6.0.1, `svelte-language-server` 0.18.4 and `typescript-svelte-plugin` 0.3.52 as dependencies pinned exactly, and `typescript` moved from the devDependencies to the dependencies pinned exactly at 6.0.3. The TypeScript server serves `javascript` and `typescript` and runs on oculus's own TypeScript (`tsserver.path` set to oculus's `node_modules/typescript/lib/tsserver.js`), never a repository's, with `typescript-svelte-plugin` given as a global plugin from oculus's own `node_modules` so a rename in a `.ts` file reaches the `.svelte` files that use the symbol (Z686 (8)), with automatic type acquisition off (`disableAutomaticTypingAcquisition`) and tsserver's log off, so no `npm` runs and nothing is written into a repository (Z686 (7)). The Svelte server serves `svelte` (Z686 (1)): for every repository it starts with `isTrusted: false`, loading no repository config or package, and the status bar's server item says it runs in reduced mode with the approval offered; the approval is the processes approval of the text of the repository's `svelte.config.*` and `vite.config.*` files, asked in a Confirm as pyright's interpreter is (`ChoiceRows.svelte:60-79`), kept in the approvals store keyed by that text as `DESIGN.md:165` keys an approval, so a changed file asks again; once approved the server is restarted trusted; an approval revoked restarts it untrusted. A repository with no `svelte` package gets the server's own Svelte 4 diagnostics, which the status bar's tooltip says. Each server serves every feature it offers that oculus's client draws (completion with its trigger characters, signature help, code actions, Organize Imports, formatting, semantic tokens, inlay hints, folding, rename, the hierarchies), as Z72 (4) (b1) gave pyright and clangd (Z686 (9)). Both are launched as pyright is (`options.node` with the package's entry and `--stdio`); a server ended ends its children (tsserver) with it. G36's rule (one server per page and root) holds for both. `README.md:15` names `typescript`'s and the three packages' licences.
3. **The cross-file write.** A new operation `lsp-edit` of `POST /api/ops`, run behind `opsWrites` as `replace` is: its body names each file by root and path with its text edits and the text it expects the file to hold (a hash of it); it keeps a history copy of each file, applies the edits from the end, writes each file atomically, rereads each written file and refuses when the result is not what was asked (as `replace.ts` rechecks), and makes one `files` record for the whole edit, undone from History as one step, with the History label "Edited by a language server in {0} files" and its singular "Edited by a language server in 1 file" (Z686 (10)); its history copies have the kind `lsp-edit` beside `save`, `replace` and `delete`, which the Timeline and History name (Z686 (6)), and an undone `lsp-edit` makes its open tabs read again as a replace does (`undo.ts:93`). Positions are UTF-16 code units per line over the file's own line ends; a file's line ending and BOM are kept, and the hash is taken over the bytes the write compares. It refuses whole, writing nothing, when a file's text is not the text expected (G8), a file lies outside the served roots (G2), the path is `local.yml` (G3), a path lies under a `node_modules` folder or a folder whose name starts with a dot (refused as a library file is), one file is named twice, or two of a file's ranges overlap. There is no limit on the number of files; the History row lists them.
4. **The page side of an edit.** `workspace/applyEdit`, a code action's edit and a rename's answer all go through one function. A file open in any tab of the page, whatever language channel it is registered on (a header open as `c` named by a `cpp` server, a `.js` tab named by the TypeScript server, a `.ts` tab named by the Svelte server, a tab no server serves), is edited in that tab, unsaved, one undo stop, every model of that document showing it; every other file goes to `lsp-edit` in one request. `lsp-edit` is posted first, and the tab edits are applied only after it succeeds, so a refusal leaves nothing applied. The whole edit is refused, nothing applied, with a sentence naming the file, when any file it names is open in a tab of another page, is a library file (`oculus-lib:`), lies outside the served roots or under a `node_modules` or dot folder, when it holds a create, rename or delete of a file, when a versioned entry's version is not the tab model's, or when the asking document is no longer registered on the page (its tab closed before the answer). Peek models of a written file are refreshed. A code action whose edit names other files is offered (no longer dropped or stripped). The client declares `workspace.applyEdit` and `workspace.workspaceEdit` with `documentChanges` true and `failureHandling: 'transactional'`, and the answer to `workspace/applyEdit` says whether it was applied. `source.yml:51`'s sentence is rewritten for what remains refused.
5. **The `documentChanges` defect.** In `uris.ts`'s `toPage`, a `documentChanges` entry whose address does not map drops the whole edit, as a `changes` key does today; the relay's `applyEdit` routing reads `documentChanges` as well as `changes`.
6. **Rename.** Each server that offers rename declares it; F2 and the editor menu's Rename Symbol rename through `textDocument/prepareRename` and `textDocument/rename`, applied by part 4.
7. **Workspace symbols.** The palette's `#` prefix and Cmd+T (in the desktop app; in a browser the palette with `#` typed) list the symbols of `workspace/symbol` from the server of the active source tab's language and root, each with its kind, its container and its file; a press opens the file at the symbol with its name selected, as a References press does. The page names the language and root in the request, and the relay routes `workspace/symbol` to that server. The rows are drawn beside `ChoiceRows.svelte` in `shell/keys` (full at 10, so in a subfolder that takes moved items), and the mode's words join `app.palette`.
8. **Call and type hierarchy.** Show Call Hierarchy and Show Type Hierarchy in the editor's menu, Shift+Alt+H for the call hierarchy as VS Code's, open the References view in new kinds beside references and implementations: incoming and outgoing calls, supertypes and subtypes, each node expandable one level at a time, a press opening the location as a References press does. The relay routes the follow-up requests by `params.item.uri`. A server that offers neither leaves the menu items disabled.

Every string is in the text catalog (`config/text/views/sources/source.yml`, `search.yml`'s `references:` group, `app.yml`'s `palette:` group, `history.yml` or `statusbar.yml` as fits). `DESIGN.md:23`, `:165`, `:512`, `:571` and `:572`, `docs/files-and-search.md:69-71`, `docs/window.md:7` (Cmd+T) and `:74` (the `#` prefix), `HELP.md` and `docs/views.md`'s References section are made true for the new servers and features.

The file constraints: Svelte components at most 520 lines, other source files at most 880, comment lines at most 100 columns, no folder over 10 items; `relay.ts` and `context.ts` do not grow past 880, so code moves out of them into new modules where the work needs room.

## Cases

1. A Python file in the scratch hub defines `total` and another file imports and calls it; only the first is open. F2 on `total`, new name `grand_total`: both files hold `grand_total`; the open tab is unsaved with the change; the other file is written on disk; History shows one record "Edited by a language server in 1 file", and its undo restores the file and the tab that shows it reads it again.
2. Case 1 with the second file open in a tab of another page: the rename is refused whole with the sentence naming the file; no file changes.
3. Case 1 with the second file's text on disk not the text the page sent the hash of (staged by a test of `lsp-edit`, since the gap between the answer and the POST is too short to stage in a browser): the write is refused whole; nothing written. Case 8's test row covers it, and the report says so.
4. A rename whose edit would touch a library file: a scratch-hub Python file that subclasses a standard-library class and overrides one of its methods, renamed on the override (pyright includes the base method's file in the answer if it renames at all), or a `workspace/applyEdit` naming an `oculus-lib:` address fed through the relay's test: refused whole, the sentence names the file; nothing written. The report says which of the two reached the refusal, and quotes the server's answer when pyright refuses the rename itself.
5. A code action whose edit names another file (pyright's or clangd's quick fix that adds an import elsewhere, or a TypeScript "move to a new file" refused as a create): offered; applied as part 4 says, or refused with the sentence for a create.
6. `workspace/applyEdit` with `documentChanges` holding one entry whose address does not map: `toPage` returns null, the whole edit is dropped, the answer is `applied: false`. A test (G2's lsp row in `uris.test.ts`); the relay's answer and the page's nothing-written are checked by reading.
7. `lsp-edit` with a path outside the roots (a G2 row), with `local.yml` (a G3 row), and with a path under a dot folder or `node_modules` (a G2 row): refused before any read; nothing written. Tests, as rows of G2 and G3 (Z686 (3)).
8. `lsp-edit` with two files, the second's expected text wrong: nothing written to either. A test, a row of G8 (Z686 (3)).
9. `lsp-edit` undone from History: both files hold their texts before. A test, a row of G9 (Z686 (3)), beside its replace rows in `tests/routes/replace/replace-undo.test.ts`.
10. A TypeScript file in the scratch hub: hover, completion, go to definition, diagnostics, rename and Organize Imports from the TypeScript server; the server process runs oculus's TypeScript (its `tsserver` path quoted from the process list, `ps -o args`); no `typingsInstaller` process and no `npm` process starts, and no `.log` folder appears in the scratch hub (`ps` and `find` quoted).

A `.svelte` file in a scratch repository with a `svelte.config.js` whose import writes a marker file, and no `svelte` package: before any approval the Svelte server runs untrusted, the status bar says reduced mode and offers the approval, hover and diagnostics work, and no marker exists; approved, the server restarts trusted and the marker exists; the config file changed, the approval is asked again; revoked, the server restarts untrusted.
12. The spawned commands of every server for one page and root: one each, the TypeScript and Svelte servers included (G36's rows widened, and G7's row at `servers.test.ts:49` updated to the new list).
13a. A repository's `svelte.config.js` that would write a marker file if imported: with no approval, the Svelte server's start leaves no marker. A test, G55's row (Z686 (2)), run on the unchanged tree first.
13b. A rename of an exported function in a `.ts` file of the scratch hub that a `.svelte` file imports: the `.svelte` file's use is renamed too (through `typescript-svelte-plugin`).
13c. A `cpp` tab whose server's rename names a header open in a tab as `c`: the header's tab is edited, unsaved, and nothing is written to disk for it.
14. Cmd+T or `#` in the palette with a Python tab active, and again with a C++ tab and a TypeScript tab active: the workspace's symbols listed; a press opens the file with the name selected.
15. Show Call Hierarchy on a Python function called from two places: the References view lists incoming calls; expanding a caller lists its callers; a press opens the location.
16. Show Type Hierarchy on a C++ class with a base: supertypes and subtypes listed (clangd); with a Python tab the item is disabled (pyright offers none).
17. pyright's and clangd's behaviour before the step (hover, F12, references, Organize Imports, the interpreter choice, the compile database choice, semantic tokens for C and C++): unchanged, each run once. Under Z687, Organize Imports is the exception: unreachable before (Monaco's client sends no `context.only`), it works for every server that offers it, the report giving the before and after.

Inputs the step implies, each with its expected result, checked by reading the code unless a case above runs it:

- The same file named twice in one edit (a `changes` key and a `documentChanges` entry, or two entries): refused whole.
- A file open in two tabs of one page: both tabs show the edit, and neither saves over the other.
- Overlapping ranges in one file: refused whole.
- A CRLF file, a file with a BOM, non-ASCII text: positions taken in UTF-16 code units over the file's own line ends; line ending and BOM kept.
- An answer arriving after the asking tab closed: dropped, nothing applied or written.
- An approval revoked while the trusted Svelte server runs: restarted untrusted at once.
- A killed `typescript-language-server`: no tsserver child left running (`ps` quoted after case 12's run).

The builder's first task, before any change, is the first run of every case above on the unchanged tree, with each case's result noted.

- A case of a code step becomes a test of the step only when the rules file's test rule calls for one: cases 6, 7, 8, 9, 12 and 13a, each as rows of the guarded entry it names. A case kept as a test is run on the unchanged tree first. No prototype script stands in for such a test.
- Every other case is checked by a run the report quotes, in the standalone Electron script against the scratch server on port 8797, and no test is kept for it.

When the first run finds a case the brief's own rules get wrong, the builder stops there, before changing any code, and hands back the first run and that case, with the rule and the result it gives. The orchestrator rules on the case and resumes the builder with the ruling, and the final report carries it.
