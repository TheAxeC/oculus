## What to build

1. **One view.** Remove the view `transcript`: its file, registration, palette row, `SESSION_VIEWS` entry and every mention listed above. Its turn list and styles move, unchanged in look, to a body component under `src/lib/views/sessions/terminal/` that `Terminal.svelte` draws. `config/text/views/sessions/transcript.yml` stays as the strings of that body, with its head comment and `transcript_open_tip` true for the merged view, and `turn_bar` goes with its only reader. `layout.yml`'s Sessions page: the split of Terminal and Transcript becomes the one Terminal pane.

2. **Tab state.** `terminal-tabs.ts` gains, read by `readTab` and kept by every function that rewrites a tab: `showing: 'live' | 'transcript'` (default `live`), `locked: boolean` (default false) and `transcript: { session: string; agent: string } | null` (default null), the session a tab with no terminal reads. A state without the keys reads as the defaults; that is a default of the shape, not a reading of an older form. `readTab`'s branches for `{ session, label }` and `{ shown, beside, share }`, with their shape keys and comments, go.

3. **Detection, on the server.** A new pure function over the terminals, the process table and each session's active pane pid names the agent in a pane: walking the process tree down from the pane's pid, breadth first, the first entry whose command line runs an agent, in a new `src/lib/server/machine/processes/agents.ts`. A command line runs an agent when the file name of its first word is `claude` or `codex`, or its first word's file name is `node` or `bun` and its second word's is one of them. `man claude` runs none. tmux's `pane_current_command` is not used for this.
   - `Terminal` gains `agent: { tool: 'claude' | 'codex'; pid: number } | null`.
   - `kind` of a terminal whose id says `shell` is the agent's tool while one runs in it and `shell` otherwise. A terminal whose id says `claude`, `codex` or `app` keeps it. `kindOf`'s comparison of the pane's command goes.
   - Each pane, in any window, of a tmux session without the oculus name (no `oculus-` prefix, or under the prefix with an id oculus did not mint) that runs an agent is listed as a terminal with the new field `byHand: { session: string; cols: number; rows: number }` (the tmux session id and the pane's size), the id `h<server pid>p<pane number>-<tool>`, where `<pane number>` is the digits of `#{pane_id}` and the server pid is `#{pid}`, so a saved id never names a pane of a later tmux server. Every tmux command for such an id targets `%<pane number>`. `TERMINAL_ID` accepts both shapes. A session or pane that runs no agent is listed as it is today: not at all without the prefix, `foreign` with it. `USAGE_PREFIX` sessions stay out. A tmux session named so that its id has the by-hand shape is `foreign`: by-hand ids come from the pane list alone.
   - The `pty:` channel of a by-hand id attaches a control client to its tmux session, sends no size to tmux, and forwards the `%output` of that pane alone; the capture is of that pane. Agents in two panes of one session share nothing.
   - A new `isOwnTerminal` says an id is oculus-minted. Stop, restart, rename, restyle, clear, resize and every other action that writes to the tmux session refuse a by-hand id with `not-ours`, `taskTerminal` in `runs/commands/run.ts` among them; steer, interrupt and the `pty:` channel accept it. `foreign`, `parsePanes` and `startTerminal`'s id check read `isOwnTerminal`. No path ends, renames, resizes or marks a session oculus did not start. The grid of a by-hand terminal is drawn at the pane's `cols` and `rows` from the list and sends no resize. Closing a tab owning a by-hand terminal leaves the tmux session running and says nothing; the menus leave out Kill, Rename, Change Icon, Change Color and Clear for it.
   - The table is read through `readTable` by a timer of its own each `POLL_MS` while any page is subscribed to anything (`socket.ts:220` hands `Terminals.subscribed` every subscription), one child at a time. A list refresh uses the last answer and runs no `ps`; a tick whose answer changes an agent starts one refresh; a failed read keeps the last answer. The first publish waits for the first read to settle. So `claude` typed in a shell shows within one tick.
   - A steer on a terminal whose agent is detected (its id says `shell`, or by-hand) first asks tmux for the pane's `#{pane_current_command}`; when that is the login shell's name, as `busyTerminals` compares it, the steer is refused with a new refusal naming that no agent is running, and nothing is typed. So a quit or suspended agent never runs the box's text in the shell.

4. **Session and terminal.** `sessionTerminal` also matches `record.pid === terminal.agent.pid`, and a live Codex record with `pid: null` to the terminal running `codex` in the record's folder, when exactly one such record and one such terminal stand there and that terminal's `resumes` names no other session. A new inverse function gives the session of a terminal by the same rules, and `terminalChoices` (`folds.ts`) uses it in place of its own pid rule. `SteerBox` gains a `locked` prop, passed down from the tab, which applies to every grid of the tab; `foreign` still refuses, `byHand` does not.

5. **The switch.** On the tab's bar, a Live / Transcript switch built from an existing control, drawn while the shown terminal has a session or the tab reads a session. Transcript draws the body of item 1 for that session in place of the row of grids, Live draws the grids. `showing: 'transcript'` with no session to read (the agent quit, or another row was pressed) draws the grids. `Live` is disabled while the session has no terminal; once it has one (resumed elsewhere) Live is enabled and pressing it is `showTerminal`. The End tool of the old view stays while Transcript shows. A plain shell with no session draws no switch and no box. An agent terminal before its first session record has no switch and keeps its box.

6. **The box.** In Live the box stands where it stands today, in each grid (`TerminalGrid.svelte:486`), and its condition `kind !== 'shell'` now covers a shell running an agent. In Transcript the body draws one `SteerBox` for the session's terminal, or null for none. With a subagent's transcript there is no box, as today.

7. **The lock.** A Lock tool in the header, drawn while a terminal with a session shows, toggles `locked`. Locked, `SteerBox` is read-only with its controls disabled and a line of its own, not `composer.elsewhere`, and the grid takes no typing or paste (`disableStdin`, and the drop path at `TerminalGrid.svelte:262`). A session with no terminal has no lock and is read-only: a running one says `composer.elsewhere`, an ended one says a new line of its own, since `composer.elsewhere` is false for it.

8. **Opening a session.** One function in `state/sessions/` opens a session, used by every caller of item 1's list:
   - A session with a terminal: `showTerminal`, then `showing` per the caller (`transcript` from the Open-the-transcript commands, the tab's own from a press in the list).
   - A session with none: a Terminal tab with `transcript` set and `showing: 'transcript'`, activated when one with the same session and agent is open. A press in the list with no folder reuses the page's tab that reads a session with `agent` empty, retargeted, so presses do not pile up tabs; with a folder it opens one per session as `pick` does today.
   - A subagent (`AgentRows`): a tab with `transcript.agent` set, label as today.
   - `pageTarget` leaves out a tab with `transcript` set, so a start from elsewhere does not land on it; New in that tab's own header clears `transcript` and sets `live`.
   - `SessionPicker` is not drawn in the Terminal view. The press in the list always opens the session, since no tab follows the selection any more.

9. **Follow state.** G86's behaviour holds for the merged view: the turns are fetched and followed only while Transcript is drawn. `transcript-tab.svelte.ts` and its test name the merged view; G86's wording in `guarded.md` is the orchestrator's at landing.

10. **Ended terminals.** `closeEnded` takes a function giving a terminal's session. A tab left with no terminal whose `showing` was `transcript` and whose shown terminal had a session stays, reading that session; one on Live closes as today.

11. **Placement.** The folders and files at their limits stay within them. `pty/` gains a folder `pty/panes/` with `capture.ts` moved in and the by-hand code, and `channel.ts` and `sessions.ts` add no net lines. `state/sessions/terminal/` gains a folder `session/` with one existing file moved in, holding item 8's function and the link rules. `views/sessions/terminal/` gains a folder `transcript/` for the body, with one existing item moved into `bar/` or `list/`, and `Terminal.svelte` stays under 520 lines, the switch and lock in a new `bar/` component. `terminals.svelte.ts` and `context.ts` add no net lines past their limit.

12. **Words.** New strings live in `config/text/views/sessions/`. `docs/HELP.md`: the `transcript` row goes, line 342 says where an agent's transcript opens, the Terminal row and the Sessions text say what the switch, the lock and detection do. `docs/palette.md` and the diagrams are regenerated.

## Decisions taken in this brief (each reversible, none silent)

- Detection reads the process table, since tmux reports `2.1.316` for Claude Code. Comparing that word with a version pattern was the lazy option.
- A by-hand terminal is one pane that runs an agent, listed only while it does, and oculus writes to it only the keys of the box and the grid. Its size stays the user's.
- If the first table read after a server start fails, a tab holding a by-hand terminal closes; the tmux session is untouched.
- A review comment sent from a diff to a locked session still goes: the lock binds the tab's box and grids, the step's line names the box, and that send is its own press in another view.
- A tab on Transcript stays when its last terminal ends, so the reader is not thrown out of what they read.
- The lock also stops the grid's typing, since the reader asked for a terminal that can be read-only; the step's line names the box.
- Split of a shell running an agent starts that agent, since `kind` follows what runs.
- Grids are unmounted while Transcript shows and return through the path a rail switch uses.
- A Codex session links by folder when exactly one codex terminal stands there, since Codex names no pid.
