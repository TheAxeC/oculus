# Brief: O14c, local documents as tabs

Read `../spec.md` first; it governs this package unchanged. `DESIGN.md` sections that bind this package: "Auth" ("nothing outside a root is ever served"), "Layer 3, view", "Configuration", and the 2026-09-10 decision "a local HTML file under a configured root opens as a tab". Read those sections only.

## What to build

- `config/sources.yml` gains `roots:`, a list of `{ key, dir }` with absolute directories the server may serve files from; today `{ key: cathedra, dir: /Users/axelfaes/workspace/cathedra }` and `{ key: game-engine, dir: /Users/axelfaes/workspace/game-engine }` (the two Axel named; a `dir` that does not exist is a config finding, reported, and its root serves nothing). `config/layout.yml` gains `bookmarks:`, a list of `{ label, root, path }`; today `{ label: "cathedra manual", root: cathedra, path: docs/user/manual.html }` and `{ label: "game-engine manual", root: game-engine, path: docs/user/manual.html }`. Both are checked by the exact-key-set test of `tests/config.test.ts`, which gains the two keys.
- `src/lib/server/files.ts` and `src/routes/api/file/[root]/[...path]/+server.ts`: `GET /api/file/<root>/<path>` streams the file at `resolve(dir, path)` when, and only when, the resolved path is inside the root's resolved `dir` (`resolve` and a prefix check with the separator, O10d's `inside` pattern in `src/lib/server/wallpaper.ts` lines 60 to 66), with a `Content-Type` from the extension (html, css, js, png, jpg, jpeg, gif, svg, webp, woff, woff2, json, txt, md, pdf; anything else `application/octet-stream`), `Cache-Control: private, max-age=60`, 404 for a missing file or a directory, 403 for a request that fails O11's `sameOrigin` (`src/lib/server/auth.ts` lines 36 to 52). Symlinks are resolved with `realpath` before the check, so a link out of the root serves nothing. A relative link inside a served HTML file (`css/manual.css`, `../img/x.png`) resolves to the same route because the browser resolves it against the document's own URL, which is under `/api/file/<root>/`.
- `src/lib/views/Document.svelte` (`document`, registered in `src/routes/views.ts`; instance state `{ root, path, label }`): a `Pane` titled with the label holding one `<iframe src="/api/file/<root>/<path>" sandbox="allow-same-origin allow-scripts">` filling the body; a control in the pane's toolbar to open the same URL in a new browser tab (`document.open_outside`). Nothing of the page's state is exposed to the frame beyond what same-origin gives it; the report says what `allow-same-origin` grants and why the manuals need it (their own scripts and relative assets).
- The rail: `ActivityRail.svelte` draws a "Docs" section (`ui.docs`) with one button per bookmark from the merged config's `bookmarks` (passed from the page like `nav_groups` is, `src/routes/+page.svelte`), glyph `document` (an existing glyph name; the report says which), a click doing `openView('document', 'main', { root, path, label })`, a second click activating the existing instance (O14b's state match).
- `config/text.yml`: `views.document`, `views.document_glyph`, `document.open_outside`, `ui.docs`.
