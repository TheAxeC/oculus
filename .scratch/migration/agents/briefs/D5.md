## Shape for Axel (booked in the state file's open items when this brief was written; the package is built on the recommended reading)

How a manifest names its main files. Recommended: it does not; a main file is every `.tex` directly under the project's `manuscript/` whose text carries `\documentclass` outside a comment, `main.tex` first and the rest by name, which finds every one of the hub's 21 today with no manifest edit. The alternative is a `manuscript: { mains: [...] }` key on `project.yml`, which every manuscript would have to gain.

## The acceptance list

1. **The roots and the log.** `src/lib/server/latex.ts` (layer 2, pure over a folder): `mains(folder)` as the shape above; `parseLog(text)` reading a `latexmk -file-line-error` log into `{ errors: [{ file, line, message }], warnings: [{ file, line | null, message }] }` (`^(.+?):(\d+): (.*)$` rows; `! ` rows with the `l.<n>` line that follows; `LaTeX Warning:` and `Package <x> Warning:` rows, with `on input line <n>` where given; each message one line, the file relative to `manuscript/`); `buildState(folder, main)` answering `{ main, pdf: <mtime or null>, log: <mtime or null>, errors, warnings }` from `<main>.log` and `<main>.pdf`. `GET /api/latex?id=<project id>` (same-origin only, the id checked against the snapshot, `src/routes/api/latex/+server.ts` two lines over `server/latex.ts`) answers `{ mains: [buildState...] }`.
2. **The two terminals.** `POST /api/terminal` action `latex` `{ id, main, step: 'build' | 'clean', cols, rows }`: the project from the snapshot, the main checked against `mains(folder)` (a name outside it refused before anything runs), a `shell` terminal in the project's `manuscript/` folder named `latex <step> <id>/<main>` running `latexmk -pdf -interaction=nonstopmode -file-line-error <main>` for build and `latexmk -c <main>` for clean, both through `shellWord`; the page's `terminals.latex(id, main, step)`.
3. **The panel.** `views/project/Latex.svelte`, drawn in the project tab under the card when `mains` is not empty (asked from `/api/latex` on open and again when a build terminal of this project leaves the terminals list): one row per main with its name, the PDF's time or "no PDF yet", the build and clean controls (the terminal pane opened when it is not, as `SessionList.svelte` 129 does), the count of errors and warnings of the last log, and the errors under a disclosure as `file:line message` rows; a control opening the PDF as a file tab (`openView('file', { root: 'hub', path, label })` the way the file browser does). A project without a `manuscript/` folder draws no panel.
4. **The PDF refreshed.** The file view's address carries a version: `fileBytesUrl(root, path)` gains `?v=<n>` from a per-file counter in the fs store (`fs.fileVersion(root, path)`, `fs.bump(root, path)`), so a bumped file is fetched again; the panel bumps `manuscript/<main>.pdf` when a build terminal ends and the PDF's mtime moved. An open PDF tab draws the new build without a reload; a case in `tests/views/file.test.ts` asserts the address changes with the version.
5. **Words and docs**: `config/text/views/project.yml` (or a `latex.yml` if the panel's words are many); `HELP.md`'s `project` sentence (line 99) names the panel; DESIGN.md's decision line.
6. **Tests**: `tests/server/latex.test.ts` (`mains` over a `mkdtemp` folder with a commented `\documentclass`, a real one and a non-root file; `parseLog` over fixtures of the three row kinds and a clean log; `buildState` with and without a PDF); `tests/routes/latex.test.ts` (the id checked, the origin); `tests/routes/terminal.test.ts` (the build and clean commands and cwd, a main outside the roots refused, an unknown id refused); `tests/views/project.test.ts` (the panel drawn with two rows and the error count, absent without mains); `tests/state` for the version counter; and a browser case: the demo hub gains `projects/active/<one project>/manuscript/main.tex` (a five-line article), the case opens that project's tab, sees the row, presses build, waits for the terminal to leave the list and the row to show a PDF time, opens the PDF tab; when `latexmk` is not on PATH the case prints that it could not run the build and asserts the row and the refusal of an unknown main only, saying so in the run's output.

## Decisions taken in this brief (each reversible, none silent)

1. The build is `latexmk -pdf -interaction=nonstopmode -file-line-error`, since every manuscript here is built by latexmk and the file-line form is what the parser reads; no engine choice is exposed.
2. The end of a build is read off the terminals list rather than a new channel, since the list already says which sessions are running.
3. The PDF is drawn again through a version on its address rather than a new route.
