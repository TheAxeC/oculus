# Brief: O14b, a project as its own tab, and tooltips

Read `../spec.md` first; it governs this package unchanged. `DESIGN.md` sections that bind this package: "Layer 3, view" (lines under that heading: primitives, shell, views, the boundaries table), "The wire model" under "Decisions taken" ("documents on demand"), and the 2026-09-10 decision "a project opens as its own tab". Read those sections only.

## What to build

- `src/routes/api/docs/+server.ts` and `src/lib/server/docs.ts`: `GET /api/docs?project=<id>&name=<README.md|PRESENT.md|RESULTS.md|code/README.md>`: the file read with O3's `readDoc` (`src/lib/data/sources/docs.ts` lines 67 to 99 for the frontmatter split; `PROJECT_DOCS` is the fixed name list), rendered to HTML with `marked` (the one dependency this package adds, no transitive dependencies; `npm install marked`, version reported), and answered as `{ html, frontmatter }` with `Cache-Control: no-store`; the path is `join(hub, project.folder, name)` from the reader's own record, never from the request, and a name outside `PROJECT_DOCS` or an id the reader does not know is 404; same-origin check with O11's `sameOrigin` (`src/lib/server/auth.ts` lines 36 to 52). The hub's markdown is the owner's own files, so the HTML is not sanitised; the report says so.
- `src/lib/state/docs.svelte.ts`: `document(id, name)` fetching once per pair and holding `{ html, frontmatter }` or the error as `$state`, with `invalidate(id)` called when the `portfolio` payload's version changes so an edited README re-fetches when the tab is next shown.
- `src/lib/views/Project.svelte` (`project`, registered in `src/routes/views.ts`; instance state `{ id }`): a `Pane` titled with the project's title; the card of the board expanded as the top block. The boundary table forbids a view importing another view, `ui/` is domain-blind and `state/` holds no markup, so the card's snippets (`tags`, `field`, `listField`, `more`, `cardFor`, `src/lib/views/Projects.svelte` lines 196 to 320) are duplicated in `Project.svelte`; the report states the two line ranges, and widening the table is the orchestrator's decision, not this package's; below the card, a `Segment` over the documents present (`project.docs` from O10, names in `PROJECT_DOCS` order) rendering the chosen one's HTML through `{@html}` inside a `.doc` block whose styles use the tokens (headings, code, tables, links in `--accent-txt`), with `Empty` when none is present; below that, the project's sessions (`sessionsForProject(folder)` from O14's `src/lib/state/selectors.svelte.ts`) as the rows the session list draws, each selecting on click; and the edit control opening the editor in the panel as the card does.
- The title of a card in `Projects.svelte` (line 272 onward, the `cardFor` snippet's heading) becomes a button that `openView('project', 'main', { id })` (`src/lib/state/layout.svelte.ts` line 212); a second click on the same project activates the existing instance rather than opening another (`openView` does that today when the view id matches; here two projects are two instances of one view id, so `openView` gains a match on `state.id` when a state is given).
- `src/lib/ui/Tooltip.svelte`: a wrapper that shows its `text` after 150 ms of hover or on focus, positioned below or beside its child, `role="tooltip"` linked by `aria-describedby`, tokens only, dismissed on pointer leave, blur or Escape. Applied to the rail's view buttons and its three toggles and two menus (`src/lib/shell/ActivityRail.svelte`), the tab strip's tabs and close controls (`src/lib/ui/Tabs.svelte`), and `ToolButton`; the browser `title` attributes those carry are removed where the tooltip replaces them.
- `config/text.yml`: `views.project`, `views.project_glyph` (an existing glyph name), `project.documents`, `project.sessions`, `project.no_documents`, `project.no_sessions`.
