## What to build

1. **The types and the reader** (new `state/sources/explorer/pdf-place.ts`). The unions `ScrollName`, `SpreadName` and `SidePanelKind` move here, and `viewer.svelte.ts`, `side-panel.ts` and `Controls.svelte` import them from here, since state may not import views. `PdfPlace` is `{ page, left, top, scaleValue, scroll, spread, sidebar }`. `readPdfPlace(value: unknown): PdfPlace | null` checks with zod: `page` a positive integer, `left` and `top` finite numbers, `scaleValue` one of `auto`, `page-width`, `page-fit`, `page-actual` or a string of a positive finite number (anything else becomes `auto`), `scroll`, `spread` and `sidebar` from their unions (an unknown value becomes the default); a value that is not an object, or holds NaN, reads as null. `readPdfPlaces(value: unknown)` reads the per-file list: a value that is not an array is the empty list; each entry is `{ root, path, place }` with non-empty strings and a place `readPdfPlace` accepts, a bad entry dropped; one entry per root and path, the first kept; at most 50. `withPdfPlace(list, root, path, place)` returns the list with that entry first and no other entry of that root and path, cut to 50.
2. **The place reported by the viewer** (`viewer.svelte.ts`). A new optional hook in `ViewerHooks`, `placed?: (place: PdfPlace) => void`, called when the reader's place changes: on `pagechanging`, on `scalechanging`, when the scroll mode, the spread mode or the side panel changes, and at the end of a scroll. Calls are throttled to at most one per 500 ms, the last place always reported. Nothing is reported until the place a load restores has been applied (after `#scrollTo(keep)` in `#initialised`), so the `scalechanging` and `scrollmodechanged` that PDF.js fires inside `#initialised` at page 1 report nothing; nothing is reported while `status` is not `ready` or while the box has no size (a hidden tab, a frame with `display: none`). A report still pending is sent at once when the box is hidden, when the viewer is disposed and on the window's `pagehide`, so the place shown when a tab moves to a new window or the page closes is the place written.
3. **A saved place handed to the viewer** (`viewer.svelte.ts`). `open(url, key, saved?: PdfPlace | null)`: while a document is held and the key is unchanged, the in-memory place wins as now (a rebuilt PDF); otherwise, when `saved` is given, `#restore` takes it and `#initialised()` applies its zoom, its scroll and spread modes, its side panel and its place. So a reload during a build (the first load missing or invalid, `#doc` null) and a Clean followed by a build open at the saved place, never at page 1. A page beyond the document's page count opens the last page; a forward search pending (`#reveal`) wins over the saved place. The head comment `:9-12` says what `open` now does.
4. **The place kept while the box is hidden** (`viewer.svelte.ts`, Z700 (5)). The look above found the scroll offset lost when the pane is maximised and restored, because the box is hidden and shown again. The viewer takes its place when the box loses its size and scrolls back to it when the box has a size again, so Maximise pane, Restore panes, a page switched and a tab shown again leave the page and the offset as they were.
5. **The two records** (`File.svelte`). For a PDF:
   - per tab: the tab's ui record (`setInstanceState(instance.id, { ...held, pdf: place })`), so the place survives a reload, Open in New Window, Copy into New Window, Return to Page and Restore panes, is dropped with the tab as every ui record is, and is cleared when a preview tab is pointed at another file (`opening.ts:168`, `:254`), so it never needs to name its file;
   - per file: one ui record whose id is `pdf-place` (a fixed id that is no tab's id), the list of item 1, written with `withPdfPlace` over the list the store holds at the moment of the write, so a page never drops the entries another page wrote before its `storage` event arrived;
   - on open, the place is the tab's `pdf` record, else the per-file entry for the tab's `root` and `path`, else none (the PDF opens at the top as now);
   - writes go through the ui store's own save, which every page follows; one report of the viewer is one write of each record.
6. **The documents.** `docs/views.md:259` (the PDF paragraph) gains that a PDF opens where it was last read, per tab and, for a newly opened tab, per file for the last 50 files, and that Maximise and Restore keep the place; `docs/views.md:239` is left as it is unless its clause becomes false. `DESIGN.md:533` gains the same fact with where it lives (`viewer.svelte.ts`'s `placed` hook, the ui store's records, the reader in `pdf-place.ts`); `DESIGN.md:169` and `ui.svelte.ts:1-4` and `:105` say that the ui store also holds a record keyed by a fixed id that is no view instance's, `pdf-place`.

## Cases

1. A PDF scrolled to page 5, partway down the page, at 150 percent, with the thumbnails panel shown and wrapped scrolling, then the page reloaded: the tab opens at page 5, at the same offset, at 150 percent, with the thumbnails panel and wrapped scrolling.
2. The same PDF's tab closed, then the PDF opened again from Files: it opens at page 5 with the same zoom and modes (the per-file record).
3. Open in New Window on that PDF within 500 ms of scrolling to page 7: the window's viewer opens at page 7; Return to Page lands at page 7.
4. Copy into New Window: the copy opens at the original's place, and each then keeps its own.
5. Maximise pane, then Restore panes, on a PDF tab scrolled to page 4: the PDF stays at page 4 at the same offset (item 4); on a document tab, its frame is not loaded again.
6. A rebuilt PDF loads at the same page and zoom (D45's behaviour, kept).
7. A reload while a build has removed the PDF, then the build writing it: the PDF opens at the saved place, and page 1 is never written over it.
8. A saved page beyond the page count, after the PDF was rebuilt shorter: the last page opens, with no console error.
9. A saved zoom of `"banana"`, `"-2"` or `"NaN"`: `readPdfPlace` gives `auto`, and the PDF opens at `auto` with no PDF.js error.
10. A saved record that is a string, an array, `null`, or an object with `page: NaN`: `readPdfPlace` gives null, and the PDF opens at the top.
11. A preview tab of `a.pdf` read at page 4, then pointed at `b.pdf` from Files: `b.pdf` opens at its own last place or at the top, never at page 4 of the first file.
12. One PDF in two tabs on two pages of the rail, one at page 2 and one at page 9, then the browser page reloaded: each opens at its own page.
13. A PDF tab hidden behind another tab while the page reloads, then shown: it opens at its saved place; nothing is written while it is hidden.
14. A missing, invalid or unreadable PDF: nothing is written, and the place saved for that file stays.
15. A forward search (Show the PDF at the caret) that opens a PDF with a saved place: the search's place is shown.
16. Scrolling through a 100-page PDF for ten seconds: at most two reports a second, each one write of each record, counted by the orchestrator at landing.
17. An `oculus.ui.v1` from before this step, with no `pdf` key in any record and no `pdf-place` record: the PDF opens at page 1 and every other view's record reads as before.
18. A picture or a non-PDF file in a `file` tab: its ui record is unchanged.
19. A 51st PDF read: `withPdfPlace` keeps 50 entries, the oldest dropped.
20. A PDF of the same path in two roots (`hub` and a second root): each has its own per-file entry.
21. A main page and a float window each writing the per-file list after one build: both files' entries are kept.
22. `localStorage` full when the place is saved: the viewer keeps working and nothing is thrown.
23. A PDF renamed while its tab is open: the tab keeps its place.
24. A `pdf-place` value that is not an array, holds an entry with bad fields, holds one root and path twice, or holds 60 entries: `readPdfPlaces` drops the bad entries, keeps the first of each root and path, and keeps 50; no error.
25. A file read again: `withPdfPlace` moves its entry to the front and the list holds it once.

## Decisions taken in this brief (each reversible, none silent)

1. The per-file record is one ui record with the fixed id `pdf-place`; a tab id is a generated identifier and never equals it (`grep -n "newInstance" src/lib/state/workbench/layout/instance.ts`), so `clearInstanceState` of a tab never drops it.
2. Reports are throttled to one per 500 ms, the last place always reported, and a pending one is sent at once when the box is hidden, at `dispose` and at `pagehide`.
3. The types and the reader go into a new `state/sources/explorer/pdf-place.ts`, since state may not import views and `file-type.ts` is about what a file's name says.
4. `invert` is not kept, as LaTeX Workshop's viewer state does not keep it.
5. The tab's record names no file: a preview tab pointed elsewhere already has its record cleared, and a rename keeps the place.
6. Z700 (4): the equation card was looked at and nothing was found to fix, so `Equation.svelte` is not changed. Z700 (5): the PDF frame is kept under Maximise and Restore but its place was lost, and item 4 keeps it.
