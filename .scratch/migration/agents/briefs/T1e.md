## What to build

The sweep reads every file under `tools/oculus/tests/routes/`, `tests/data/`, `tests/checks/` and `tests/fixtures/`, slow-tagged files included, test by test, and applies the rules below.

1. **Delete** each test that breaks `agents/spec.md:57` or `:61`:
   - a test of behaviour whose failure costs nothing, the costs being the rule's list: lost or corrupted work, a write to the wrong file, a broken start or install, a wrong configuration or input accepted, or a view, key or command the user relies on that stops working;
   - a test of a constant, a label or catalog string, a type, a pass-through or re-export;
   - an assertion over one file's source text (`spec.md:61`), the wiring of `src/routes/+page.svelte` read as source in `routes/page.test.ts` among them;
   - a test that cannot fail on its own fixture, or that still passes with its behaviour taken out, judged by reading what the code does on that path;
   - a test whose outcome another case already gives through the same branch of the code (Z363): the case at the lowest level that reaches the branch stays (a data function's own test before a route test through it), and among cases at one level the one that reaches the most of the branch;
   - a route test of a behaviour a server or data test already holds, unless it is the one case of the wiring of that route (Z365);
   - a measurement that asserts nothing a user relies on (a test that prints a time and counts what it fed), `data/snapshot/build-timing.test.ts` among them.
   A kept test that carries one assertion of a kind this item deletes (over source text, a label, or markup the look covers) loses that assertion and keeps the rest; the report lists it.
2. **Fold** cases of one outcome that differ only in their input into rows of one table, one test per outcome. Each row has a short name as its first column, and the table's title prints that name, so the verbose output names every row in full.
3. **Tag** each test that cannot run well under a second as slow, by its cause and by its time (Decision 1), in the file, describe or test form: the whole file with `// @module-tag slow: <reason>` as the last line of the head comment when every test left in it is slow; otherwise `describe(name, { tags: ['slow'] }, fn)` or `{ tags: ['slow'] }` as a test's second argument, a numeric timeout moving into that object as `timeout`. A slow table takes its tag on its describe. A cause reached through imported code counts as the test's own. A hook counts with the tests it serves: a `beforeAll` or `beforeEach` with a cause, or whose body takes 100 ms or more, makes them slow, so a cold-start cost moves into the `beforeAll` of a slow describe, or the file takes the file tag. Item 3 does not apply to the tree checks of `tests/checks/` (item 5). A file already tagged whose tests are all quick after the sweep loses the tag.
4. **Keep** every other test. No assertion of a kept test is loosened, widened or rewritten except to fold it into a table under item 2. A kept test's title is corrected when it is false, and the word "audits" leaves the title of a kept test. A kept test's setup may lose what the test does not use. A wall-clock margin or a fixed sleep in a kept test breaks `spec.md:64`: the wait moves to a signal or a fake clock and the assertion holds on the answer, before item 3 judges the tag, so a test whose only cause was the sleep stays quick (`routes/git/untracked.test.ts:134`). An awaited `vi.waitFor` polls on a real 50 ms interval: where the code gives a signal the test awaits it; where none, it stays and the test is judged by time. A file the sweep changes that is left at 880 lines or more is split by concern (`spec.md:45`; `routes/edit/write.test.ts` 891 and `checks/diagrams/diagrams.test.ts` 882 today), within the folder limit. ## Decisions taken in this brief (each reversible, none silent)

1. **Slow, by cause and by time.** A test is slow when it starts a real process (git, a shell, a script of `utils/`), awaits a real timer of 1 ms or more, or opens a socket, in its body, in a hook it runs under, or at the load of its module; a zero-delay yield is no timer. Any other test is slow when the minimum of its times over the verbose runs of its own file, at least five and every one taken counted, is 100 ms or more; the report gives every time and the load average of each run. The minimum is used because load only ever adds time. A cause reached through imported code counts. The tree checks of `tests/checks/` are not tagged (item 5); their own unit cases over planted fixtures are swept and judged as tests.
2. **Shared helpers.** The helpers of `tests/fixtures/` and any helper here imported from another folder keep every export a file imports; only what nothing imports is removed.
3. **Per-test and describe tags.** The test and describe forms are used where a file mixes quick and slow tests, so its quick tests stay in their list; a head comment states the file's tagging rule once.
4. **Route tests.** A route test stays for the wiring of its route (the request it takes, the call it makes, the answer it shapes), one case per wire; an outcome the server or data function decides is held by that function's test.
5. **The page's source cases go.** `routes/page.test.ts`'s cases over the text of `+page.svelte` are deleted under `spec.md:61`; the page's wiring is a DOM behaviour seen at the look.
6. **The tree's checks stay, and `audits.test.ts` waits.** A check of the tree is part of the verify list, so this step sweeps its own fixture cases and never removes or loosens the check itself; a check found to guard no written rule is named for Axel, since removing it reverses the approval of the step that added it. `checks/tree/audits.test.ts` and `allow-audits.txt`, which require every non-rendering case under `tests/views/` to be titled as an audit, bear on T1d's sweep and wait for Axel's ruling on them, booked as an open item; T1d carries whatever he rules.
7. **`vi.waitFor`.** It polls on a real interval, so it gives way to the code's own signal where there is one, and where there is none it stays and its test is timed.
8. **The head-comment labels.** As item 7 names them, the spellings the tree uses most, with DESIGN.md's layers for routes and data.
