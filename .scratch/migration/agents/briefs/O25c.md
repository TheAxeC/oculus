## Decisions taken in this brief (each reversible, none silent)

1. **One new write.** `kind: 'lead-add'` `{ fields }` appends an entry to the leads file with `date` defaulting to today and `status` to `open` when absent, refused without a title, through `appendEntry` of `server/entry-edit.ts` with the fields in the schema's order; `state/writes.svelte.ts` gains `addLead(fields)`.
2. **The lead schema is the feed file's own.** `feeds/position-leads.yml` carries a `schema:` list of ten fields in the collection files' shape (title, inst, country, typ, focus text, fit textarea, status as a select over open, applied, declined, date as a date, deadline, url; checked 2026-09-12), which the cockpit ignored in favour of the eight fields `page.py` shipped. `server/feeds.ts` reads it through `collectionSchema` of `data/normalise.ts` (the parser the collection files use, line 396), `FeedData` in `data/model-collections.ts` gains `schema?: SchemaField[]`, `GET /api/feeds` carries it, and the shared form draws the file's fields in the file's order; nothing is added to `config/sources.yml`. The file's schema names no field required, so the `lead-add` write is what refuses a blank title (decision 1), and a blank `status` or `date` takes the write's defaults.
3. **The pure parts.** `state/leads.ts`: `isClosed(status)`, `deadlineOf(text)`, `isExpired(lead, today)`, `fitKey(fit)`, `fitTone`, `splitLeads(entries, today)` (live sorted, expired sorted), `leadsSearch`; a `LeadsState` from the instance state (search words, the two collapsibles).
