The builder's first run (a9657bc7866b03a87) found two premises of the brief false and the server count and the scratch port wrong. Each is ruled here; the brief stands everywhere else, and the final report carries this ruling.

1. Item 10, the spelling suggestions (Z555 (a), mechanism; Z562). Electron 44.5.1 emits no `context-menu` for a right-click whose DOM `contextmenu` event the page cancels (probe3: `/cancel` gave `[]`), and oculus's text menu cancels it. What Z555 (a) rules stays: no context-menu library, no native menu, oculus's own text menu shows the suggestions at its top in the app, each item the suggested word, nothing in Chrome. The facts come from the preload instead of the main:
   - The bridge gains `spelling(word)`, answering `{ misspelled: boolean, suggestions: string[] }` from `webFrame.isWordMisspelled` and `webFrame.getWordSuggestions` in the preload; the `spelling` message of the main and `replaceMisspelling` are dropped from the bridge, and the main does not listen to `context-menu`.
   - `TextBoxMenu.svelte`, on its right-click, finds the word around the pointer's position in its own box (the caret offset the right-click puts in the input or textarea, extended to the word's boundaries by one pure function in `text-menu.ts`), asks `spelling(word)` through the `ui/controls/text/spelling.ts` context, and draws the suggestions at the menu's top when `misspelled` is true. The menu's items are state, so an answer that arrives after the menu opened is drawn at its top.
   - A pick replaces that word's range in the box's value through the same path Paste uses (the box's `setRangeText` and its `input` event), so the field's binding, its undo and its draft follow as they do for Paste. The boundary function gets its own unit test rows in the test file of `text-menu.ts` if one exists, or a new `tests/ui/controls/text/text-menu.test.ts` (a parser with several outcomes: a word at the start, the end, between punctuation, an apostrophe inside, the pointer on a space).
   - The first lookup after a start can time out in macOS's spell server (probe3 `/plain`: `NSSpellServer findMisspelledWordInString timed out`). The preload calls `webFrame.isWordMisspelled('oculus')` once when it loads, so the spell server is warm before the first right-click. Case 23 is run on the first right-click after a fresh start and quoted; if that first right-click still shows no suggestion for a misspelt word, the report says so with the run.
