## What to build

1. **The server.** `handleOpen` accepts a body `{ path }` as now, or `{ root, path }` where `root` is the key of one of the roots it is given and `path` is relative to that root; a `root` that names no root answers 400 with a `refused` row on `root`. `allowed` returns the real path of an existing directory or regular file inside a root, still refusing a symlink that resolves outside every root. `openable` admits an absolute path that is a directory or a regular file now, or an `https` address; a path starting with `-`, a relative path and any other scheme stay refused. The 500 answer says `the path could not be opened: <reason>`. The route passes `browserRoots(locals.server)`, so every root the file browser shows is a root this endpoint accepts. The open-folder head comments of `open.ts` and the route say file or folder.
2. **The client.** `writes.openFile(root, path)` beside `openFolder`, posting `{ root, path }` to `/api/open` through the same `send`, typed in the `writes` interface (line 57).
3. **The file view.** `views/File.svelte`'s toolbar gains a control "Open in its program" for every file it holds, and the `other` block gains the same control beside Download, both calling `openFile(root, path)`; a refused or failed answer is said in the view the way the bookmark's failure is (`file.bookmark_failed`), with a new catalog line. The words go into `config/text/views/file.yml`.
4. **The cards.** A pure helper in `state/fs.ts`, `drawnInPage(name)`, true when the page draws the file by its name alone: `typeOfFile(name).kind` is `html`, `image` or `pdf`, or `languageOf(name)` is not `PLAIN`, or the extension is one of `.md`, `.txt`, `.csv`. In `CardDocs.svelte` a file row whose name is neither `READABLE` nor `drawnInPage` becomes a control that calls `openFile('hub', <folder>/<path>)`; a readable row keeps opening the document view and a drawn one keeps its link. In `EntryCard.svelte` a `link` value that is a hub-relative path (not an address `hrefOf` passes through, and not a local HTML document) and not `drawnInPage` becomes a control calling `openFile('hub', value)`; every other link stays a link. A failure is said through the card's existing message path (`onsaid` or the collection view's equivalent; name the one you use).
5. **Docs, written into the report and not into the files.** `HELP.md` and `DESIGN.md` are being changed by a step running beside this one, so you do not edit either file.
