## What is on the tree (read on main at 8fb9affd)

- `src/lib/state/layout.svelte.ts`: `closeInstance` (line 581 on) ends with `ui.clearInstanceState(id)` (line 588), and the instance removal at line 529 does the same; `closePane(path, page)` (line 592 on) removes the pane with `removePane` and clears nothing; `closePage(id)` (line 409 on) filters the page out, turns every leaf naming it into an empty pane through `clearPage`, and clears nothing.
- `src/lib/state/context.ts` lines 104 to 113 hand the layout a `clearInstanceState` that clears the instance's own record and its form drafts record (`formsKey(id)`); the source draft (`state/source.svelte.ts`) and the manifest edits (`state/manifest-draft.ts`) live in the instance's own record. So one call per closed instance forgets all three.
- A page's workbench can hold a `page` leaf that shows another page; that other page still exists after the outer page closes, and its instances are not the closed page's.
- The instance state lives in `localStorage['oculus.ui.v1']` through `state/ui.svelte.ts` (`clearInstanceState`, line 308).

## What to build

1. **`closePane`** calls the layout's `clearInstanceState` for every tab of the pane it removes.
2. **`closePage`** calls it for every instance of the closed page's own workbench tree (every pane's tabs, at any depth of splits), and for none of the instances of a page a `page` leaf shows. Closing the only page, which leaves a fresh default page, clears the closed page's instances too.
3. Any other layout operation that drops instances without going through `closeInstance` (read `removePane`, `clearPage`, the page and pane menus' close entries, `shell/closing.ts`) clears them the same way; name each one found, or say none is left.
