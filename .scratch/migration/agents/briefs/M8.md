## What to build

1. **The schema formats, one vocabulary.**
   - Every hub `schema:` block, `manifest-schema.yml`, `options.yml` and the new schemas use `from:` for a reference, `options:` for allowed values, `help:` for the help line and `when:` for a condition. `options_from`, `values_from`, `values`, `description`, `suggest_from` and `values_by` are renamed in the files and in every reader listed under "What is on the tree", the apps API's `optionsFrom` included (`model-collections.ts:37`, `fs.svelte.ts:209`, `collection.ts`, `docs/apps.md:247`), the migration template `migrate-joint-work.mjs:273` and `demo/network/joint-work.yml:11`.
   - `from:` takes a registry name (`venues`, `datasets`, `pillars`, `domains`, `funding`, `people`, `organisations`, `resources`), `projects`, or `vocab.<key>`; for `options.yml` the existing `SOURCES` names of `catalog/options.ts:76-95` stay valid. `from:` is one source, a list of sources offered together, or `{ field: <name>, sources: { <word>: <source> } }`, the source another field of the record picks (what `values_by` said). On a `select`, `choice` or `multi`, the value is held to the source; on a `text` field or control, `from:` names the source it is completed from and the value is not checked against it (what `suggest_from` said). A `from:` naming none of these, or a `when:` naming an undeclared field, is a finding on the schema's own file. `manifest-schema.yml`'s four bare vocab names (`:31`, `:36`, `:38`, `:39`) become `vocab.<key>`, and `state/forms/schema.ts:243` reads the prefix.
   - `when:` is a map of field to a value or a list of values, all of which must hold for the field to be allowed; `required: { when: ... }` makes a field required under a condition; `when: { path: <glob> }` is a tier or folder condition matched with `node:path`'s `matchesGlob`.
   - Two more words, each with its line in DATA-MAP's table of types: `type: records` with its own `fields:` is a list of records described once (career's sections; the word `options.yml` uses for a nested list of records); `open: true` on a field or a record form allows keys it does not declare (career's `hosts` score keys and `situation`). `metalist` keeps its meaning, and `raw` takes any value.
   - The help line is `help` in the code too: the `description` property of a catalog entry and of a Settings row is renamed through `rows.ts`, `search.ts`, `Control.svelte`, `Item.svelte` and `List.svelte` (rows only; a file's own description at `List.svelte:65-66` keeps its name). `findings.yml:113-114` are reworded for `options`, `from` and `help`, and the key `no_description` becomes `no_help`.
   - A help line on every field of every schema: the 87 hub fields that lack one get one, written as the field's meaning in one plain sentence, and the three false help lines (`venues.yml:27`, `data.yml:28`, `data.yml:32`) are corrected.
