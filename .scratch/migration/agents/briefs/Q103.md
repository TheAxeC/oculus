3. **The capacity section collapsible, held per pane.**
   - Add to `src/lib/state/system/hpc.ts` a type `HpcViewState = { capacity: boolean; sinfo: boolean }` and a pure function `parseHpcState(raw: unknown): HpcViewState` that reads `capacity` and `sinfo` from a map and falls back per key to the defaults `capacity: true`, `sinfo: false` for a missing, non-boolean or non-map value. Each other key of the held map is ignored by the parser.
   - Add to `hpc.ts` a pure function `toggledHpcState(held: HpcViewState, key: 'capacity' | 'sinfo', open: boolean): HpcViewState | null` that returns `null` when `held[key] === open` (a toggle event fired by the `open` attribute itself, which must write nothing) and otherwise `{ ...held, [key]: open }`.
   - `Capacity.svelte` draws nothing when `meters` is empty, as it draws an empty grid today. Otherwise it wraps the meters grid and the sinfo `<details>` in an outer `<details>` whose summary reads the partition count (`meters.length`): `hpc.capacity_title_one` for one partition and `hpc.capacity_title` with the count otherwise, as `Calendar.svelte`'s `dayCount` picks `calendar.days_one` or `calendar.days_n`. The outer `<details>` is open when `capacity` is true; the inner sinfo `<details>` is open when `sinfo` is true.
   - `Capacity.svelte` takes two new props, `held: HpcViewState` and `onheld: (next: HpcViewState) => void`. Each `<details>` has an `ontoggle` handler that calls `toggledHpcState(held, key, event.currentTarget.open)` and calls `onheld` with the result when it is not `null`. The `toggle` event does not bubble and Svelte 5.57 attaches it to each element directly, so the inner fold's event never reaches the outer handler.
   - `Hpc.svelte` reads `ui: { instanceState, setInstanceState }` from `useState()`, derives `held` as `parseHpcState(instanceState(instance.id))`, and passes `onheld` that calls `setInstanceState(instance.id, next)`, the parsed state as the tree's other views write theirs (`Inbox.svelte:94`, `Leads.svelte:106`).

## Decisions taken in this brief (each reversible, none silent)

1. The collapsible control is a `<details>` with a `<summary>`. This is an exception to the rules file's rule that every control a reader presses is a `ui/` primitive: no fold primitive exists under `ui/`, the tree already has eight raw `<details>`, and this view already uses one for its sinfo table (`Capacity.svelte:39`) and its recent jobs (`Recent.svelte:84`), so the view keeps one way of folding a part. `ui/tree/TreeSection.svelte` is a heading row of an explorer tree and must be drawn inside a `TreeView` with `li` rows, which the meters grid is not.
2. The capacity section is open by default and the sinfo table closed by default, which is what a new pane shows today.
3. The held keys are `capacity` and `sinfo`, in the pane's instance state; they are not a config key or a wire shape, and they go when the tab closes (`clearInstanceState`).
4. The words: the outer summary `Cluster capacity ({0} partitions)` (`(1 partition)` for one), the inner `sinfo table ({0} rows)` (`(1 row)` for one). Reversible catalog text.
5. The fetching line uses `ui/frame/Empty.svelte`; the unreachable line stays a `.said` paragraph in `--fs-md` and the muted colour, since rows stay under it and it is not a line saying nothing is here. The hint takes `--fs-sm`, the head's meta size.
6. With no sinfo rows the capacity fold is not drawn, as an empty meters grid draws nothing today.
7. The held state is written as the parsed `HpcViewState`, as the tree's other views write theirs; no other key is kept there.
8. The Quota meters under the capacity stay outside the collapsible section: the step line names the capacity, and the disk quota is a separate part.
