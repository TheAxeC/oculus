## What to build

1. **The session on the diff.** `DiffSubject` gains `session?: string`, the id of the session record the diff was opened for; `heldDiffShape` reads it (`z.string().catch('')`, empty for none, a non-string as empty); `diffState` appends `:${session}` to the id only when it is non-empty, so the diff opened from the Changes view is its own tab beside the same file's diff opened from the Repositories view. `openChange(root, group, path, session?)` passes it into the diff subject (the merge editor and the file open as before), and `Changes.svelte` passes the shown record's id. `followedDiffTab` (`explorer/follow.ts`) carries `session` with the other fields, so a session's diff tab followed to a renamed file keeps it.
2. **The prompt and the send, as functions.** A new module `state/sources/repositories/review-comment.ts` exports:
   - `commentPrompt(comment: { path: string; line: number; side: 'modified' | 'original'; staged: boolean; text: string }): string`: `<path>:<line>: <text>` for a line of the modified side, `<path>:<line> (staged): <text>` for the modified side of a staged diff, `<path>:<line> (before the change): <text>` for a line of the original side, whose path is the file's old path when it was renamed. The text is trimmed at both ends and kept whole inside. A path whose first character is `!`, `#`, `@` or `/` is written `./<path>`, since an agent's prompt box reads those as a command, a memory, a mention or a slash command.
   - `commentRefusal(prompt: string): 'empty' | 'control' | 'long' | null`: `empty` for a blank comment, `control` for a character the steer refuses (`\u0000-\u0008`, `\u000b-\u001f`, `\u007f`), `long` past `STEER_MAX`; the same rule on both paths, so the clipboard never gets what the terminal would refuse.
   - `sendComment(prompt, deps: { terminal: () => { id: string } | null; steer: (id: string, text: string) => Promise<TerminalAnswer>; copy: ((text: string) => Promise<void>) | null }): Promise<{ kind: 'sent' } | { kind: 'copied' } | { kind: 'failed'; error: string } | { kind: 'refused' }>`: the steer when the terminal is there (`failed` with the answer's error, or `''` when it has none), else the copy (`refused` when `copy` is null or rejects). The components call these and hold no logic of their own, so cases 3 to 8 and 18 to 24 are tests of this module.
3. **The editor's comment affordance.** `DiffEditor.svelte` gains the props `oncomment?: (side: 'modified' | 'original', line: number) => void` and `commentLabel?: string`. With `oncomment` set, the editor turns on the glyph margin of each side it offers (both in the side-by-side layout; the modified side only in the inline one, where removed lines are Monaco's own zones), and a pointer over a line of such a side shows a `+` in that line's glyph margin, a decoration kept on the hovered line only and cleared when the pointer leaves; a press on it calls `oncomment(side, line)`. Monaco's own `+` and `-` signs stay where they are, in the lines-decorations lane. The hover decoration and the reading of a mouse target into `{ side, line }` are pure functions added to `ui/controls/editor/gutter.ts`, tested over a fake editor as `gutter.test.ts` tests the breakpoints. The action Add Comment on Line, labelled `commentLabel`, is registered on each offered side and listed through `onactions`; it calls `oncomment` for the caret's line of the side holding the focus, the modified side when neither does. `onactions` is called again whenever `oncomment` comes or goes, so the palette lists the action only while it works; without `oncomment` nothing of this is drawn, registered or listed. `lineBars()` is mounted on the original editor too; `EditorBar` gains `side?: 'modified' | 'original'` (the modified side when absent) and `order?: number` (0 when absent), and a comment bar is placed with order 1, below a hunk bar after the same line. The head comments of `DiffEditor.svelte` and `DiffSection.svelte` say bars sit after lines of either side.
4. **The comment box.** A new partial `views/sources/repositories/diff/CommentBox.svelte`, drawn as the bar with id `comment` after the commented line; `DiffSection.svelte`'s bar snippet draws the comment box for that id and a hunk bar for a numeric id. One box per file section: a second `+` moves it, keeping its text. The text lives in the section's state, so a move to the other side, Escape and a re-read of the diff keep it; it is dropped when the section goes. The box holds a head "Comment to <session title>" (the session's id when the title is empty), a `TextArea` focused when the box opens (through its element, as `Prompt.svelte:33` focuses its input), and Send and Cancel. Ctrl+Enter or Cmd+Enter sends, on every platform, as `CommitBox.svelte` takes it; Escape closes the box keeping the text, as VS Code keeps a draft, with `preventDefault` and `stopPropagation` so it does not restore a maximised pane. While a send is in flight Send does nothing; an answer that comes after the box was closed, moved or its section gone writes nothing. A re-read of the diff while the box is open leaves it after the same line number, which is the line the prompt names. Switching to the inline layout closes a box on the original side, keeping its text.
5. **Where it is offered.** `DiffSection.svelte` passes `oncomment` only when the pane's state names a session that `sessionById` holds and the pane is a file's own diff (`diffActs(held)`), so a commit, stash, worktree, compare or group diff never offers it. `Diff.svelte` passes the session id and the subject's `staged` to the section and adds at most four lines, keeping it within 540. A session the payload no longer holds hides the `+` and the action, and an open box closes.
6. **Sending.** On Send, the section calls `commentRefusal` (empty: nothing happens; control or long: the box stays and says why) and then `sendComment` with `terminalOfSession(record)`, `steerTerminal` and the clipboard (null when `navigator.clipboard` is absent). `sent`: the box closes, its text cleared, and a line "Sent to <title>." shows for five seconds (a code constant, since nothing configures how long a notice stays). `copied`: the box closes, its text cleared, and the line reads "<title> has no oculus terminal now. The comment is on the clipboard.", true both for a session that never ran in oculus and for one whose terminal ended. `failed`: the box stays with its text and shows the error, or "The terminal did not answer." when the error is empty. `refused`: the box stays and says the clipboard refused the copy. The prompt is typed and Enter pressed, as the Steer box does; a session waiting at a question takes it as its answer, as it would from the Steer box.
7. **The words and the docs.** `config/text/views/sessions/changes.yml`'s `sessions:` group gains: the action's label, the box's head, the text area's label, Send, Cancel, the sent line, the clipboard line, the no-answer line, the clipboard-refused line, the control-character line and the too-long line. `HELP.md:132`, the Changes row, says a Changes row opens its own diff tab for the session, and gains one sentence: a line of that diff takes a comment with the `+` in its gutter or Add Comment on Line, sent to the session as a prompt that names the file and the line, typed into its terminal when oculus runs it and copied to the clipboard otherwise. `HELP.md:87`'s row gains "send, in a diff's comment box". `DESIGN.md:399`'s "the sessions' Changes rows open the same pane" says they open the same pane as their own tab, which takes comments for the session. `tests/views/whole/type-scale.test.ts` lists `CommentBox.svelte` and any new font size.

## Decisions taken in this brief (each reversible, none silent)

1. **The prompt's shape.** `<path>:<line>: <text>`, and `<path>:<line> (before the change): <text>` on the original side, the `path:line` form a compiler and an agent both read as a place. On five real cases:

   - `src/lib/ui/controls/editor/DiffEditor.svelte`, original line 143, "why was the menu on?": `src/lib/ui/controls/editor/DiffEditor.svelte:143 (before the change): why was the menu on?`.
   - `registries/organisations.yml`, modified line 13, "  keep the comment  " (spaces around): `registries/organisations.yml:13: keep the comment`.

2. **One comment, one prompt.** Each Send types one prompt at once; comments are not gathered into a review sent together, which is what the ruling's "sent to that session as a prompt" describes.
3. **Both sides in the side-by-side layout.** A removed line is a line of the session's diff, so it takes a comment too; in the inline layout Monaco draws removed lines as zones, which take no gutter decoration, so only the modified side is offered there.
4. **A separate tab.** The diff opened for a session is its own tab, so the comment affordance belongs to the tab that was opened for that session.
5. **The words a reader sees.** The action is Add Comment on Line, after VS Code's Add Comment; the markers are "(before the change)" and "(staged)"; the sent notice stays five seconds; Ctrl+Enter or Cmd+Enter sends on every platform and Escape closes keeping the draft, as VS Code's comment widget and oculus's commit box take them.
6. **The `+` in the glyph margin.** Monaco's own diff signs hold the lines-decorations lane, so the comment mark takes the glyph margin, which the text editor already uses for its breakpoints.
7. **Refused before sending.** A comment the steer would refuse is refused on both paths, so the clipboard path never hands over a prompt the terminal path would not type.
8. **Not blocked by D17.** `queue.md:26`'s "once D17 has landed" is A3's (`plan.md:469`); A1's line names no step it waits on (`plan.md:465`), and A1 uses nothing D17 builds.
