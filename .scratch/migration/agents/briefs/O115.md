## What to build

1. **One document rule set.** An assistant turn draws through `views/shared/prose/Markdown.svelte`; the `.doc` copy in `TranscriptBody.svelte` goes. `state/system/docs.svelte.ts` gains and exports `docOfHtml(html)`, the `DocState` of an HTML text with no error and not loading, and `RenderedMarkdown.svelte:136`'s literal uses it. `docOf(turn)` in `turn-rows.ts` holds it in a `WeakMap` over the turn object, so a read that appends leaves every older answer's `DocState` the same object and an append redraws only what changed. The turn's HTML is sanitised once, by that component. Tables then have borders, padding and whole words; code blocks carry Copy; a table wider than the pane scrolls in its own box. Headings in an answer draw at `--fs-lg`, by a rule of the transcript over the Markdown it holds, so a `#` in an answer is not larger than the view's own title. `onlink` answers true for a relative link, so a press on one leaves the page where it is; an answer gets the prose menu on right-click as a document does (Copy over a selection that starts in that answer).

2. **Who said what.** Each kind of turn reads apart with no word needed:
   - A person's turn opens an exchange: a line (`--line`) above it, a larger gap before it than between other turns, a 3px left bar in `--accent`, its words in `--ink-txt` at `--fs-md`. Its head names it, its label in `--accent-txt`. The first turn of the list draws no line.
   - An answer draws its prose at full ink.
   - Tool rows are muted and at `--fs-sm` (item 3).
   - No surface is painted behind a turn while `body.wall` holds, as `Markdown.svelte:316` states; off a wallpaper a person's turn takes `--chip` as its background.
   - An answer draws its head (label and clock) unless the last head drawn in the list has the same stamp to the minute, compared on the stamp itself and not on the clock's words; a tool run between them does not count; a turn with no stamp always draws its head. A person's turn always draws its head.
   - A list with no person's turn, as a subagent's, or that opens inside a run, draws the same way.
   - The labels stay the catalog's words.

3. **A run of tool calls is one line.** Turns with `role === 'tool'` next to each other in the list form one run; `groupTurns(turns)` in the new file `transcript/turn-rows.ts`, pure, does it and gives each run the index of its first turn:
   - A run of two or more is, closed, one `RowButton` (which gains an `expanded` prop giving `aria-expanded`): the mark of the disclosure, the clock of its first call, and the run's words from one catalog line with placeholders, `{0} tools: {1}`, the names counted by whole name in first-seen order, a name's count drawn when above one, the separators catalog text, cut with an ellipsis at the row's edge: `17 tools: WebSearch 15, Write, Bash`.
   - Open, it lists each call as a row: clock, name, summary.
   - A run of one is that call's own row, with no press.
   - A call that came back draws no tag. `error` draws in `--c-red-txt`, `running` as the muted tag, and neither shrinks: a wrapper in the view is `flex: none`, so the summary alone is cut. A closed run says so when it holds either.
   - A run has three states, kept in this component keyed by the index of its first turn: not chosen, opened, closed. Not chosen draws open while it holds a failed call, whenever that result arrives, and closed otherwise. A press chooses and the choice holds, so a turn appended to the last run keeps it. The states clear when the session or the agent changes, since one component outlives its target.
   - The foot effect reads `turns` and not only its length, so a reader at the foot stays there when a result patches a turn and opens a run. A press moves nothing.
   - An empty summary draws the name alone with no title. An empty name draws `turn_tool`'s word.

4. **Every call says what it was about.** `summaryShape` reads, after its four fields and in this order: `query`, `url`, `skill`, `summary`, `reason`, `task_id`, `action`. The first with a text wins, as now. `displayName` in `turn-rows.ts` gives what a row draws: for `mcp__a__b`, `b`, the part after the last `__`; a name with no second `__`, or one ending in `__`, draws whole; the row's title holds the whole name. Codex: `codexSummary` also reads `query`, and `server` with `tool` joined by a dot; `item_completed` means the item ended, so `ok` is false for a failed `status` or a non-zero `exit_code` and true otherwise. The export (`transcript-routes.ts:155`) gains those summaries and keeps the full name.

5. **Readable.** Line height at least 1.5 in the transcript, prose and a person's words held to at most 80ch so a wide pane does not draw very long lines (a table may pass it). `.frame` padding rises so the words stand clear of the pane's edge and the scrollbar, as the pane's other bodies do. Clocks are `--fs-sm` in `--font-num`, muted. Tool rows use `--muted-txt`. The rice rule at the file's foot stays.

6. **The font buttons work here.** The turns draw at the grid's size from the same setting, so the buttons change them as they change a grid and the reset returns the default. An inner box inside the scroller `.chat` takes CSS `zoom` at `gridFontSize(terminalFont(), textScale())` over `--fs-md` in pixels; a function beside `gridFontSize` in `terminal-list.ts` gives that ratio, and one that cannot be computed gives 1. The scroller itself is not zoomed, so `atFoot` is unchanged.

7. **Words and docs.** `turn_ok` goes from `config/text/views/sessions/transcript.yml`, and so does any key the step leaves with no reader (`tests/checks/source/keys.test.ts`); new words live there. `docs/HELP.md` says how a run of calls reads and that the font buttons size the transcript. The head comments of each changed file say what the code does now, `TerminalFontTools.svelte`'s and `Markdown.svelte`'s callers among them, and `terminal.font_px`'s help in `config/options/appearance.yml` and its line in `config/defaults/appearance.yml` name the transcript. No file under `docs/diagrams/` is expected to change.

## Decisions taken in this brief (each reversible, none silent)

- Runs of tools start closed, since 112 of 200 turns are tool calls; a failed call opens its run, so a failure is never hidden behind a press. Showing every call was the lazy option.
- A call that came back draws no tag, since "ok" on nearly every row says nothing.
- A person's turn carries the accent bar and opens an exchange, since the question is what a reader looks for when scrolling.
- The turns draw at the terminal grid's size, since the two share the buttons on one bar.
- Answers gain the prose menu and lose the browser's own right-click, as every document does; a selection across turns copies with the keyboard.
- `turns.ts` is in `READER_FILES` (`cache.ts:33`), so the first scan after landing folds every session once; no output changes.
- No virtual list: the transcript's length is not what the reader reported; case 17 measures it.
