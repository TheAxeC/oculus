# Brief: D62, apps: the host, the bridge and app management

Size: a full step

Read `tools/oculus/.scratch/migration/agents/spec.md` first; its rules govern this step unchanged. It is also the one standards page the configuration lists. No ADR folder exists (`ls tools/oculus/docs/adr` answers no such file), so no ADR touches this step.

You work in the worktree `.agents/worktrees/D62` (from the repository root) and nowhere else; the base copy is `.agents/worktrees/D62-base/tools/oculus/`.

A design ruling decides what is built. It never exempts the code: every line is written to the standards pages, so that people can read, use and maintain it.

This step is the first of three (D62, D63, D64) that give an oculus app everything a VS Code extension can do. D63 adds contributions to the shell and D64 contributions to the tools; both ride the protocol this step builds and specify in DESIGN.md, and neither changes it (ruling 43). Every part below is built whole in this step: nothing of it is left for D63 or D64 except what those steps' own lines name.

## What to build

Every item holds for a machine app and a root app alike unless it says otherwise. Every refusal is one of the existing words of `docs/apps.md` "Refusal words" (`not_declared`, `closed`, `missing`, `too_large`, `not_json`, `rate`, `declined`, `refused:<reason>`, `failed:<status>`) or the one new word `host_down` (ruling 46 (5)).

1. **The manifest.** `appShape` gains five keys, each checked when the folder is read, each a finding keyed `apps[<id>]` that refuses the app when wrong, worded in `config/text/findings.yml` under `findings.apps`:
   - `host`: a relative path ending in `.js` or `.mjs` that names a recorded file of the app (the `entry` rules: the segment rule, then present among the recorded files).
   - `files`: a list, for a machine app only, of folders the app's page may read, each `<root key>` or `<root key>/<path>`. The root key is the longest key of the roots the Files view shows that the entry equals or that is followed by `/` in it; an entry naming no shown root is kept and answers `missing` at the read (root keys are per workspace). The path obeys the segment rule and names no folder of `closed_paths`; the root is never `engine`. A root app that lists `files` is refused, since it reads its own root and nothing else.
   - `secrets`: `true` (ruling 41). Any other value refuses the app.
   - `activation`: a list of activation events, each once: `onTab`, `onCommand:<id>`, `onLanguage:<id>`, `onView:<id>`, `workspaceContains:<glob>`, `onStartupFinished` (ruling 45). Absent means `[onTab]`. An event other than those, or an empty id or glob, refuses the app. `activation` without `host` refuses the app.
   - `depends`: a list of machine app names, each once, matching the name pattern, never the app's own name (ruling 45). A root app may list machine apps. A dependency that is absent, refused, disabled or unapproved does not refuse the folder; it leaves the depending app's host unable to start, which its tab and the Processes view say.
   - The editor's JSON Schema of `app.yml` follows from `appShape` as it does today. `AppRow` carries the new keys' values under the names `host`, `readFolders` (the manifest's `files`, since `AppRow.files` is the count of recorded files), `secrets`, `activation` and `depends`, and its comment says what each holds. An entry of `files` given twice is one finding; `hub` beside `hub/projects` keeps both, the wider one deciding. A `workspaceContains:` glob that holds a `..` segment or starts with `/` refuses the app. `onLanguage:<id>` takes the language ids the language servers use (VS Code's).

2. **The approval panel** (`src/lib/views/apps/frame/ApprovalPanel.svelte`) says, each in plain words from `apps.yml`: for an app with `host`, that it runs a program on this machine with the reader's rights, which can read and write the reader's files and reach any address, and the host file's path; the folders `files` names; "stores secrets" for an app with `secrets: true` (ruling 41, said whether or not it has `connects`); the apps `depends` names; and, for an app that reads files (a machine app with `files`, or any root app, which reads its own root) and has `connects`, that what it reads can be sent to those addresses (ruling 42 (2)). The panel keeps 520 lines at most.

3. **Keep approved for root apps** (ruling Apps as capable). `routes.ts` no longer refuses `keep` for a root app and `scan.ts` keeps a root app as it keeps a machine app; the panel offers the control to both. A kept app's host never runs files other than the approved hash (item 5).

4. **WebAssembly.** `appPolicy`'s `script-src` gains `'wasm-unsafe-eval'`, so an app's script compiles a `.wasm` file it fetched from its own address. No other source changes.

   **`open({ file })` as the Files view opens it** (ruling Apps as capable, part (4)). `openFile` in `src/lib/state/system/apps/apps.svelte.ts:324-326` opens `'source'` for every file today. It chooses the tab as the Files view does: the kind from `fileType` and the tab from `tabForKind`, with `holds` keeping an apps-folder file as source. `tabForKind` sits in `state/workbench`, above `state/system` in `tests/checks/imports/order.ts`, so the choice comes in through the frame view's mount options from `src/lib/views/apps/frame/`, which may import `$lib/state/workbench/layout`.

5. **The host** (rulings 42, 44, 45). An app whose manifest names `host` gets one host process while it is approved, enabled and unchanged:
   - **Start.** At the app's first activation event (item 6). The process is `process.execPath` with `ELECTRON_RUN_AS_NODE=1` added to oculus's own environment (ruling 44 (6)), started by an argument array and never a shell (G7), in the app's real folder as its working folder, running oculus's own runner script with the arguments the runner needs (the host file's absolute path, the absolute path of `vscode-jsonrpc`'s node entry in oculus's `node_modules`). The runner is a plain JavaScript file of the tree, `host-runner.mjs` in the apps folder's host subfolder, started from `ownFolder()` as `eslint-child.mjs` is (`eslint.ts:45`). The app's host file never needs a package of its own to talk to oculus. The runner ends when its standard input closes, so a server killed by SIGKILL, or a desktop utility process lost, leaves no host running.
   - **Only approved code runs.** The host starts only while the app's current hash is in the approvals file. A kept app whose files differ from the approved hash does not start its host, and a host running when its app's files change is stopped (item 5, Stop); the tab and the Processes view say the host waits for an approval of the changed files, with the Approve control. A `git pull` that changes a root app's files is such a change. The hash is taken again right before each spawn, and a host whose files no longer match it does not start. The Approve control on a tab or a Processes row opens the approval panel, which shows the hash; it never approves directly (G49). The host imports nothing outside its approved files (ruling 46 (4)): the runner installs a Node module hook (`module.register` of `node:module`, its `resolve` hook) before it imports the host file, and the hook refuses every `file:` URL whose real path is not one of the app's recorded files, with an error that names the refused file and the rule; `node:` built-ins pass; a host ships the packages it needs inside its own folder, where they are recorded, counted under `apps.max_files` and `apps.max_mb`, and approved. A dynamic `import()` and a `require` made through `createRequire` meet the same hook. A refused import ends the host as any error of `activate` does, with the line in its output.
   - **The runner** loads the host file with `import()` by its file URL, takes `process.stdout` for the connection and sends everything the host writes to its standard output (`console.log`, `process.stdout.write`) to its standard error, so the host's own output never breaks the messages. It calls the host file's exported `activate(oculus)` once with the connection object, and its `deactivate()`, when exported, before the stop. A host file that exports no `activate`, or whose `activate` throws, ends the host with that error in its output. A write to file descriptor 1 that bypasses the redirection breaks the message stream: the host is stopped and its output names the broken stream.
   - **The connection object** `oculus` has: `onRequest(handler)`, the handler called with `(method, params, tab)` for each `oculus.host.request` of a page, its return value (or the value its promise settles with) the answer and a throw the refusal `refused:<the error's message>`; `store` as VS Code's Memento, `get(key)`, `update(key, value)` (`undefined` deletes the key), `keys()`, and `onDidChange(handler)`, called with the changed keys when a frame or another writer changes the store; `secrets` with `get(key)`, `store(key, value)`, `delete(key)` (item 8); `sendToPage(method, params, tab)`, to that tab of the app, or to every open tab of it when `tab` is left out; `apps.get(name)` (item 11). Every method that waits answers a promise.
   - **The store from the host** is the app's one store file (`store.ts`): the map the frame's `getStore` and `setStore` read and write whole. `update` changes one key and keeps every other byte of the value it read; a value of the file that is not a map is replaced by a map holding the one key. Each `update` is a store write: under `apps.store_max_kb`, counted under `apps.writes_per_min` per host (ruling 46 (6)), recorded in the change log and undoable as a frame's `setStore` is (G9), announced to every tab's `onStore`. Store writes of one app are serialised through one queue per store file, the frame's `setStore` (`server/edit/writes/apps/store.ts`) and the host's `update` alike, so a host `update` and a frame `setStore` at the same moment both land, and no tab receives a store value older than one it has seen (G50).
   - **Stop.** When the app is disabled, revoked, changed, removed, its host's Stop is pressed, or the server closes: `deactivate()` is called with `apps.host_stop_seconds` (ruling 46 (11), default 5) to settle, then SIGTERM, then SIGKILL 2 seconds later. A Stop pressed in the Processes view asks first, naming the app (DESIGN.md's Processes rule). The server's close stops every host and leaves no process behind. A server context made again by a dev hot reload stops the old context's hosts first, so no host runs twice. Two activation events at once start one process; an activation during a stop starts one host after the old one has exited. A `host.request` or `apps.call` in flight when its host stops rejects `host_down` (ruling 46 (5)); one from a tab already closed never settles, as `never()` does in `methods.ts`.
   - **A host that ends on its own** is not restarted (ruling 44 (5)). Each open tab of the app shows a line saying the host ended, with its exit code or signal, and a Restart button; the Processes view shows the same row with Restart.
   - **Output.** The host's standard error (its own output, redirected as above) is kept as its last 1000 lines and at most `apps.host_output_kb` kilobytes (ruling 46 (11), default 256), per host, the server's memory bounded by them, and shown in the Processes view (item 10). Nothing of it reaches an app.

6. **Activation events** (ruling 45 (2)). The host starts at the first of its events and runs until item 5's Stop. `onTab`: a tab of the app is drawn. `onStartupFinished`: the server has read its apps after it started, or the app becomes approved and enabled. `workspaceContains:<glob>`: a file matching the glob (picomatch, the glob relative to a root) exists in a root the Files view shows, the app's own root for a root app, every shown root for a machine app; looked at when the roots or the app change, never by a walk past `apps.scan_entries` entries per root (ruling 46 (11), default 10000), never inside a dot folder or `node_modules`, and never outside the root. `onLanguage:<id>`: a source tab of a file of that language id (the language servers' ids) opens on a page. `onCommand:<id>` and `onView:<id>`: fired by the server's one activation call, which this step builds and D63 calls when its command runs or its view shows; until D63 lands no command or view of an app exists, so these two never fire, and the manifest accepts them.

7. **The protocol** (ruling 42 (1), ruling 43). Every message between oculus and a host is JSON-RPC 2.0 over the host's standard input and output, through `vscode-jsonrpc`'s `createMessageConnection` on both ends. The method names are internal; the table of every method, this step's and the ones D63 and D64 add, is written into DESIGN.md (item 13), so D63 and D64 add methods to it and change none. The structure, built in this step:
   - requests both ways, notifications both ways, cancellation by `$/cancelRequest` with a cancellation token handed to the handler, and progress by `$/progress` with a token;
   - from oculus to a host: `oculus/activate` (the activation event), `oculus/request` (a page's request with its tab), `oculus/storeChanged` (the changed keys), `oculus/apiCall` (item 11), `oculus/deactivate`;
   - from a host to oculus: `oculus/store/get`, `oculus/store/update`, `oculus/store/keys`, `oculus/secrets/get`, `oculus/secrets/store`, `oculus/secrets/delete`, `oculus/sendToPage`, `oculus/apps/get`, `oculus/apps/call`;
   - written into the DESIGN.md table for D63 and D64 and not built here, since nothing of this step calls them: `oculus/register` and `oculus/unregister` (a contribution by kind, id and options), `oculus/provide` (oculus asks a registered provider for its answer), `oculus/event` (oculus tells a host of an event it subscribed to), `oculus/ui` (quick pick, input box, message, progress), `oculus/stream/open`, `oculus/stream/data`, `oculus/stream/control` (a resize of a terminal's rows and columns, or an end signal) and `oculus/stream/close` (a byte or message stream with an id, for a language server, a debug adapter or a terminal a host runs), `oculus/changed` (a host tells oculus a registered contribution changed: a status item's text, a tree's rows, source control groups, file decorations; a second `register` of the same id is refused), `oculus/settings/get` (a host reads one of its declared settings; their changes come as `oculus/event`), `oculus/subscribe` and `oculus/unsubscribe` (a host asks for the events of one kind, which then come as `oculus/event`), and `oculus/commands/execute` (a host runs a command by id, oculus's own or an app's);
   - the page's side, written into the same DESIGN.md section as a second table for D63 and D64 and not built here: the frame methods `ui.quickPick`, `ui.inputBox`, `ui.message`, `ui.progress`, `register` and `unregister` of a contribution a frame drives, `document.read` and `document.save` for a custom editor's document, and the handler `onVisibility(visible)` of a view's frame.

8. **Secrets** (rulings 40, 41, 42 (7)). Through `@napi-rs/keyring` 2.1.0, pinned in `package.json`, one code path on every platform and in the browser mode. Service `oculus-app:<view id>`, account the key. A value is written with `setSecret` and read with `getSecret` as UTF-8 bytes, at most 2048 bytes; the key is 1 to 64 of `[A-Za-z0-9._-]`. On Linux the entry is made with `{ linux: { store: 'secret-service' } }`, so a machine without a Secret Service refuses with a line that says so, as does a machine with no store at all; `get` and `delete` refuse the same way as `store`. `get` of an absent key answers `undefined`; a key outside the pattern, the empty key included, rejects `refused:key`; a value over 2048 bytes rejects `too_large`. The secrets of an app are counted for Remove with `findCredentials(service)`, whose values are dropped at once and never logged. An app without `secrets: true` is refused `not_declared` by every secret method. The frame's `oculus.secrets.get(key)`, `store(key, value)`, `delete(key)` and the host's same three reach one server module; the frame's go through the page with the write token and the `x-oculus-app` header, as a write does, and only for the tab's own app. A store or a delete counts toward `apps.writes_per_min` and is not recorded in the change log; no value of a secret is logged, published, put in a channel or written to any file. The keyring module is passed in, so the tests hand in a store that keeps entries in memory.

9. **The frame's new methods**, built in `oculus.js`, `methods.ts` and the page, documented in `docs/apps.md`:
   - `oculus.fs.readFile({ root, path })` answers a `Uint8Array`, `oculus.fs.readDirectory({ root, path })` a list of `[name, type]`, `oculus.fs.stat({ root, path })` `{ type, ctime, mtime, size }`, `type` VS Code's `FileType` numbers (1 file, 2 folder, 64 added for a link). For a machine app the folder must lie in a `files` entry, else `not_declared`; for a root app it is its own root. Then the checks of `open({ file })` in their order (`open.ts` `checkOpen`: the segment rule, `closed_paths`, never `engine`, a shown root, the real path inside the root, outside oculus's own `config/`), `closed` or `missing` as there. The bytes go from the server to the frame over the app's own address (ruling 44 (4)): a route under `/apps/<name>/<key>/` (and `/apps/@<root>/<name>/<key>/`) on a dot-led first segment no app file can have, answered only under the app's current key while it is approved and enabled, answered as `application/octet-stream` with `X-Content-Type-Options: nosniff`, `Content-Disposition: attachment` and the app's sandbox policy, so an `.html` or `.svg` file of a root is never drawn as a document on oculus's origin (G5); the body is a stream of the file, read in chunks. The page never holds the bytes, and no size limit applies. A FIFO, socket or device file answers `closed` without being opened. A dot-led segment in the address before the root key is the empty 404; a dot-led segment in the path under the root is `closed`, as `open` answers it. `readDirectory` lists no dot-led name and no name `closed_paths` closes, and at most `apps.scan_entries` entries, a longer folder answering its first `apps.scan_entries` names in the order the disk gives them.
   - `oculus.commands.run(name)` runs the command of that name from the app's root's `.oculus/commands.yml` (the hub's for a machine app) through `runCommand` and its chain approval, in a terminal the reader sees; it resolves once the terminal is open, rejects `missing` for no such command and `declined` when the reader refuses the approval. A command saved through the form, which runs with no question (run.ts:125-126), is not reachable: only the root's `commands.yml` is named, as ruling 42 (4) runs a command through the command approval, and a saved name answers `missing`. It counts under `apps.opens_per_min` per frame (ruling 46 (6)). `runCommand` and the terminal's approval question live above `state/system` in the import order (`state/sessions/terminal/commands.svelte.ts`), so the page reaches them through a new `AppsDeps` member set where `createApps` is called, `src/lib/state/client/context.ts:646-657` (the file is 740 lines).
   - `oculus.secrets.get`, `store`, `delete` (item 8).
   - `oculus.host.request(method, params)` sends to the app's host with the tab's id and answers what the handler answers: `not_declared` for an app with no `host`, `host_down` when the host is not running and cannot start, `refused:<message>` for a handler that threw. A request of a host that is not running is an `onTab` activation, so the first request starts it.
   - `connect` takes a fourth handler, `onHost(method, params)`, called for each `sendToPage` to the tab.

## Decisions taken in this brief (each reversible, none silent)

1. The refusal words are the existing nine and `host_down` (ruling 46 (5)): `not_declared` for an undeclared host, fs folder or secret use, `host_down` for a host that is not running and cannot start, `refused:<message>` for a handler's throw.
2. `oculus.fs` follows VS Code's `workspace.fs` (ruling 46 (7)): `readFile` a `Uint8Array`, `readDirectory` `[name, type]` pairs, `stat` `{ type, ctime, mtime, size }`, `type` VS Code's `FileType` numbers.
3. The page receives a host's message through a fourth `connect` handler, `onHost`, beside `onChannel`, `onTheme` and `onStore`.
4. A `files` entry's root is the longest shown root key that prefixes it; an entry naming no shown root answers `missing` at the read, since root keys are per workspace.
5. The host runs only from an approved hash; keeping an app approved never runs changed host code.
6. `commands.run` counts toward `apps.opens_per_min` per frame and a host's store update toward `apps.writes_per_min` per host (ruling 46 (6)); a secret's store and delete count toward `apps.writes_per_min` (ruling 41); a host's `sendToPage` toward `apps.messages_per_min` (ruling 46 (6)); `readFile` counts toward none.
7. The host's output is kept as its last 1000 lines and at most `apps.host_output_kb` (ruling 46 (11)).
8. `workspaceContains` walks at most `apps.scan_entries` entries per root (ruling 46 (11)) and never into a dot folder or `node_modules`.
