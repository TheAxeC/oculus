# Brief: O12, the sessions server

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "Sessions" under Layer 2 (the facts that cost real time to establish and must not be rediscovered), "Boundaries", and the decision "the cockpit is frozen; B ports rather than being rebuilt". This package ports the cockpit's B1 (transcript folding and the live registry), B2 (grouping) and B5 (the dismissal override) into `src/lib/server/sessions/`, with their tests, as facts: the record shape, the fold rules, the liveness check, the scoring, and every test case the cockpit has, rewritten in TypeScript on synthetic fixtures. Nothing here is a channel or a view; O13 watches and pushes, O14 draws.

## What to build

Under `tools/oculus/src/lib/server/sessions/`:

- `transcripts.ts`: `readSession(path): SessionRecord` (a full fold, no cache), `scan(options): SessionRecord[]` (newest activity first; `options` is `{ store, window_days, max_sessions, cache_path, registry, overrides_path }` with the defaults below; never throws: an unreadable transcript is left out). The fold is the cockpit's, rule for rule: a transcript is JSON lines; a trailing line without a newline is a record still being written and waits; a malformed line is skipped; `ai-title` sets the title, `last-prompt` the last prompt, `system` with subtype `turn_duration` is a `turn` event; `user` and `assistant` records count as messages and carry `cwd`, `gitBranch`, `version`, `permissionMode`, `entrypoint`, the first and last timestamps; a `user` record whose `origin.kind` is `human` is a prompt (the first one is the fallback title, cut to 60 characters; the first 200 characters go on the timeline); a `tool_result` block closes a pending tool use and, for an `Agent` block, marks the agent `done` or `error` with the result's length; an `assistant` record carries `model`, `effort` and the usage: lifetime sums of input, output, cache read, cache creation and thinking tokens, and the context occupancy as that turn's `input + cache_creation + cache_read` (never the sums); the cache window's TTL (`1h` or `5m` from `cache_creation.ephemeral_*`), the last creation and read stamps, and a `bust` (a creation above 10000 tokens right after a read above 10000) counted and put on the timeline; a `tool_use` block counts its tool, an `Agent` block opens an agent (`description`, `subagent_type`, `model`, started, running), an edit tool (`Edit`, `Write`, `NotebookEdit`, `MultiEdit`) or `Read` with a `file_path` or `notebook_path` counts the file and puts an `edit` or `tool` event with the path on the timeline, any other tool an event with its name. Caps: 200 files (newest first), 100 agents (newest first in the record), 200 timeline events, applied when pruning and when finishing. The state from the transcript alone: `unknown` with nothing seen; `idle` when the file is older than 30 minutes; `working` when the last record was a user message, or an assistant message with a tool use still pending; else `idle`. The record shape is the cockpit's `_finish` output with camelCase keys (`lastPrompt`, `permissionMode`, `lastActivity`, `liveStatus`, `registryName`, `contextTokens`), declared as `SessionRecord` in `src/lib/data/model.ts` beside the other wire types (O13 puts it on the socket).
- The cache: `~/.oculus/transcript-cache.json` by default, one entry per transcript path holding `size`, `mtime`, `inode`, `offset` and the accumulator; an entry is reused when the inode matches and the file has not shrunk, and the fold resumes at `offset`; a shrunk or replaced file is read from zero; a corrupt cache is discarded; at most 200 entries, the newest kept; the cache version is 1 and any change to the accumulator's shape bumps it (the cockpit is at 4; oculus starts its own). A first read of a file above 256 MB is not folded and the record says `truncated: true`. The cache is written atomically (a temp file in the same directory, then rename).
- `registry.ts`: `liveSessions(registry): Map<string, LiveEntry>`: every `<pid>.json` (never the `.key` files beside them) with `sessionId` and an integer `pid`; the process must exist (`process.kill(pid, 0)`, with `EPERM` meaning alive) and its start time must agree with the registry's `procStart` within two seconds, reading `ps -o pid=,lstart= -p <pid> ...` once for every candidate (three-second timeout, list arguments only, never a shell); the registry writes the stamp in UTC and `ps` prints local time, so both readings are tried, and an unreadable or missing stamp accepts the pid check alone. The entry carries `status`, `name`, `kind`, `entrypoint`, `cwd`, `startedAt`. `mergeLive(record, entry, dismissed)`: without an entry the session has `ended` and is `hidden` when dismissed; with one it is `live`, `liveStatus` is the registry's, `busy` maps to `working` and `idle` to `idle`, an unknown status passes through, an empty one leaves the transcript's guess, and a live session is never hidden.
- `overrides.ts`: the per-session overrides file, `~/.oculus/sessions.json` by default, `{ sessions: { <id>: { hidden?: true, area?: string, title?: string } } }`: `hiddenIds(path)`, `setHidden(id, hidden, path)` (writes only that key, keeps every other key of the file and of the entry, removes an emptied entry, starts the file when absent, rejects an id that is not a non-empty string, atomic write), `overrides(path)` for the grouping. A corrupt file hides nothing and pins nothing.
- `group.ts`: `group(records, projectFolders, roots, attachedIds, overridesPath): Workspace[]`, the cockpit's B2 rule for rule: a workspace is the nearest ancestor of the record's `cwd` holding a `.git` entry (a directory or a worktree's file), else the first segment below the deepest configured root (`~/workspace`, `~/data`, `~` by default, longest root first), else the cwd itself; no cwd is the unknown workspace `(unknown)`. Areas are scored from the record's files (one point each, the deepest known project folder holding the path, else the file's directory clamped to two segments below the workspace, known project folders exempt from the clamp) and the cwd (two points); a file outside the workspace does not score; the primary area is the highest score, then the newest stamp, then the longest path; secondary areas are the others with at least two points, at most three, in rank order; a session with nothing to score lands in `(general)`. An `area` override repins the session (moving its workspace when the pinned area lies outside) and keeps the scored area secondary; a `title` override renames it; `attachedIds` set `kind: 'attached'`, everything else is `observed`. Workspaces, areas and sessions all sort newest activity first; the input records are not modified; junk input never throws (an unplaceable record is left out).
- `codex.ts`: the same record shape from Codex CLI rollouts, asked for by Axel on 2026-09-10. The store is `~/.codex/sessions/YYYY/MM/DD/rollout-<stamp>-<uuid>.jsonl` (22 files, 64 MB on this machine, walked recursively, newest mtime first, the same window and cap as the Claude store). A rollout is JSON lines of `{ timestamp, type, payload }`: `session_meta` (payload `id`, `cwd`, `originator`, `cli_version`, `model_provider`, `git.branch`, `forked_from_id`) opens the record (id, cwd, branch, version); `turn_context` carries `model`, `cwd` and the collaboration mode; `event_msg` with payload `type` `task_started` (its `model_context_window` is the window the meter measures against, 258400 on the samples), `task_complete` (`duration_ms`, a `turn` event), `turn_aborted`, `token_count` (`info.total_token_usage` with `input_tokens`, `cached_input_tokens`, `output_tokens`, `reasoning_output_tokens`, the lifetime sums, and `info.last_token_usage` the last turn: the context occupancy is the last turn's `input_tokens` plus `cached_input_tokens`), `item_completed` whose `item.type` is `UserMessage` (a prompt: `item.content`, the first one the fallback title), `AgentMessage`, `Reasoning`, `CommandExecution`, `FileChange` (the touched files: each `changes[].path` counts as an edit) or a tool item; `response_item` with `custom_tool_call` (`name`, `input`) and `function_call` (`name`, `arguments`) count tools by name, and `agent_message` (`author`, `recipient`, on the multi-agent runs) opens an agent entry keyed by author when the author is not the root; `compacted` records are skipped; `token_usage_record` is redundant with `token_count` and skipped. The `item.type` vocabulary on the 22 rollouts, counted 2026-09-10: `CommandExecution` 796, `Reasoning` 562, `AgentMessage` 204, `Extension` 157, `SubAgentActivity` 85, `UserMessage` 82, `FileChange` 31 (keys `type`, `id`, `changes`, `status`, `stdout`, `stderr`), `CollabAgentToolCall` 21, `ImageView` 13, `ContextCompaction` 6, `McpToolCall` 3; `token_count.info` holds `total_token_usage`, `last_token_usage` (keys `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, `reasoning_output_tokens`, `total_tokens`) and `model_context_window`. `SubAgentActivity` and `CollabAgentToolCall` are the agent entries; `CommandExecution`, `McpToolCall`, `Extension` and `ImageView` count as tools under their type name; `ContextCompaction` is a `bust`-like event, `compaction`, on the timeline. The report lists every `type` and `payload.type` seen with its count and what the fold does with it. The record's `tool` is `'codex'` (Claude records get `tool: 'claude'`; the field is added to `SessionRecord`), `slug` is the rollout's date folder, and the transcript-tail state is `working` after a `task_started` with no `task_complete` or `turn_aborted` after it, `idle` otherwise, `unknown` with nothing seen. Liveness: Codex keeps no pid registry, so a rollout is live when a `codex` process (the CLI binary, not the ChatGPT desktop app's `Codex (Renderer)` and `codex-code-mode-host` processes, which are excluded by name) is running and the rollout was written within the last two minutes; `liveStatus` is `busy` while working and `idle` otherwise. `scan` merges both stores into one list, and `readSession` dispatches on the path. The cache holds both kinds in one file, keyed by path.
- `index.ts` under `sessions/`: `sessions(options)` composing `scan` (both stores), `group` and the project folders from the portfolio (every project's absolute folder with its title) and returning `{ records, workspaces }`.
- `src/lib/data/model.ts` gains `SessionRecord`, `SessionFile`, `SessionAgent`, `SessionEvent`, `LiveEntry`, `Workspace`, `Area`, all JSON-safe. The defaults (`~/.claude/projects`, `~/.claude/sessions`, `~/.oculus/transcript-cache.json`, `~/.oculus/sessions.json`, the three roots) are resolved from `os.homedir()` at the call, never at import, and `local.yml` may override the two `~/.oculus` paths with `sessions_cache` and `sessions_overrides` (`loadLocal` gains the two optional keys).

Under `tools/oculus/tests/server/sessions/`:

- `transcripts.test.ts`: the cockpit's 29 cases, each on a synthetic transcript written into a temporary directory (a helper builds records the way the cockpit's test does): the minimal record, malformed lines skipped, the title falling back through three levels, token sums and busts, a bust on the timeline, agents running, done and error, every state case, an incremental scan matching a full read, a partial trailing line waiting, a shrunk file read from zero, a corrupt cache discarded, the window and session bounds, an oversized first read reported truncated, a missing store yielding nothing, context tokens being the last turn, a running registry entry making the session live, busy mapping to working and an unknown status passing through, an entry without a status leaving the guess, no entry meaning ended, a gone process not live, a reused pid rejected by the start time (with `ps` and `kill` stubbed through an injectable `probe` so the test never asks the real system), broken registry files and `.key` files skipped, a missing registry folder, a dismissed ended session hidden, a live session never hidden, `setHidden` writing one key and keeping the rest, starting a missing file, rejecting a non-string id, a corrupt overrides file hiding nothing.
- `group.test.ts`: the cockpit's 24 cases, on temporary directories with real `.git` entries where the case needs them.
- `codex.test.ts`: synthetic rollouts in a temporary directory, one record type per case: the meta opening the record, a prompt and the fallback title, a turn from `task_started` to `task_complete` and an aborted one, the token sums and the last turn's occupancy from `last_token_usage`, a `FileChange` counting its paths, a `CommandExecution` counting a tool, a `SubAgentActivity` opening an agent, a `ContextCompaction` on the timeline, the state cases, liveness with the process probe stubbed (a `codex` process present and the file fresh; present and stale; absent), and `scan` merging both stores newest first with `tool` set on every record.
- `tests/data/real-hub.probe.ts` gains a read-only section that runs `scan` over the real `~/.claude/projects` with a cache path inside the scratchpad (never `~/.oculus`, which does not exist yet and is not created by a probe) and prints the count of records, how many are live, and the time taken; the report quotes it.

## Facts checked on the tree, 2026-09-10

- The store on this machine: `~/.claude/projects` with 509 transcripts and 1.2 GB (counted 2026-09-10); a 48 MB transcript folds in 0.2 s under the cockpit. The registry `~/.claude/sessions/` holds 11 entries today, `<pid>.json` with `sessionId`, `pid`, `status`, `name`, `kind`, `entrypoint`, `cwd`, `startedAt`, `procStart` among other keys (`bridgeSessionId`, `messagingSocketPath`, `peerProtocol`, `statusUpdatedAt`, `version`, which the record does not carry), and a `<pid>.<hash>.key` file beside each.
- `isSidechain` is false on every record and carries nothing; subagents are `tool_use` blocks named `Agent`, paired to their `tool_result` by id.
- The cockpit's state folder `~/.cockpit/` holds only `transcript-cache.json` today; its overrides file `sessions.json` does not exist, so there are no dismissals to carry over. oculus reads `~/.oculus/sessions.json` and nothing in oculus reads `~/.cockpit`.
- `process.kill(pid, 0)` in Node throws `ESRCH` for a missing pid and `EPERM` for one owned by another user; the cockpit treats `PermissionError` as alive.

## Conventions
