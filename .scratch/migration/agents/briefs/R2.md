## What to build

1. **`engineDir` loadable without packages.** `engineDir` moves, unchanged in what it does, out of `src/lib/data/sources/config.ts` into a module of the data layer that imports only `node:` modules, in a folder under the ten-item limit (a new subfolder of `src/lib/data/` is allowed, named in the report); `config.ts` re-exports it, so no other importer changes. Its head comment and `config.ts`'s say where it lives.

2. **The check's module**, `src/lib/server/root/process/start/first-run.ts`, beside `args.ts` and `port.ts`, which move into `start/` with their importers and `DESIGN.md:509` changed to the new paths and nothing else changed in them. It imports only `node:` modules, `server/core/program.ts` and the module of item 1. It answers what the machine lacks as a list of lacks, each with what it is, what of oculus needs it and its fix, in two parts:
   - **Before any package is loaded** (`installLacks(checkout, nodeVersion)`): the Node version (a major below 24 is a lack, fix `nvm install 24`; a pre-release such as `25.0.0-nightly...` is read by its major), and the installed packages over the checkout the code runs from (no `node_modules/.package-lock.json` beside `package-lock.json`, or a non-optional entry of `package-lock.json`'s `packages` missing from it or at another `version`, is one lack naming the count of entries missing or differing; fix `npm ci` in the checkout's directory). Their sentences are literals in this module (Decisions 3).
   - **After the packages load** (`machineLacks(...)`, given the engine's local values, the platform and an environment): the hub folder (`hub` resolves to no directory, or to a file: a lack naming the resolved path and the `hub` key of `<engine>/config/local.yml`); and the programs `git`, `tmux`, `perl` and the `claude_bin` value, each looked up with `onPath` against the given environment, each a lack naming the program, what of oculus needs it and its fix. On macOS a `git` that resolves to `/usr/bin/git` while `xcode-select -p` exits non-zero is a lack whose fix is `xcode-select --install`. What needs each: git, Source Control and History; tmux, the terminals and sessions; perl, the Status view's line counts; the Claude CLI, chat terminals, worktree agents, the usage refresh, schedules and tasks, and commit messages (item 7). These sentences come from the catalog.
   - A lack is **required** (the Node version, the packages, the hub folder) or **optional** (the four programs). The module decides nothing about printing or dialogs; its callers do.
   - Run as a program (`node src/lib/server/root/process/start/first-run.ts`), it checks the checkout it lives in: it prints each required lack of the first part to standard error, prefixed `oculus: `, and exits 1 when there is one; otherwise it loads the config reader with `await import(...)`, prints each lack of the second part, and exits 1 when one of them is required, else 0. With nothing lacking it prints nothing.

3. **The built server**, `src/server.ts`: the command line is parsed first (with `engineDir` from item 1, loadable without packages); then the first part runs over `engineDir()`; a required lack prints its sentences prefixed `oculus: ` to standard error and ends the process with exit 1, with no port opened. Every module the file imports today that loads a package (`config.ts`, `context.ts`, `serve.ts`, `port.ts`, `words.ts`, `memories.ts`) is then loaded with `await import(...)`, before the body-size line and the handler; `parent.ts`, `mover.ts`, `shutdown.ts`, `build-folders.ts` and `args.ts` stay static. The second part runs before the handler is loaded: a required lack ends the start the same way; each optional lack is printed as one line and the start goes on. A default handler that does not exist (no `--handler`, `build/handler.js` missing) is said by a new catalog line that names `npm run build`, in place of Node's module error; a handler that exists and fails to load keeps `server.start.handler_failed`. The server the app forks runs the same checks; its lines go to the app's output.

4. **The npm scripts**: `package.json` gains `"predev"`, `"preapp"` and `"prepreview"`, each `node src/lib/server/root/process/start/first-run.ts`, so `npm run dev`, `npm run app` and `npm run preview` run the check first and do not start Vite or Electron after a required lack.

5. **The app**, `src/desktop/main.ts` and `src/desktop/app.ts`: `main.ts` loads nothing that imports a package before the first part runs. It imports `electron` (present whenever Electron runs it) and the module of item 2, runs the packages half of the first part over the checkout (the Node version is not checked in the app, since the app's Node is Electron's own and `nvm install 24` does not change it), shows a required lack in one dialog with a Quit button, its sentence and the button's label literals (Decisions 3), and exits 1; otherwise it loads `config.ts` and `app.ts` with `await import(...)` and starts the app as today. In `app.ts`, after the environment the server will get is known (the login shell's for a packaged app, else the app's own), the second part runs with that environment: a required lack (the hub folder) is shown in a dialog with Quit before the server starts; the optional lacks, when there are any, are shown together in one sheet on the first window with Continue and Quit after the server starts. When the login shell was slow (`env_slow`) and there are optional lacks, one sheet says both, so the reader sees one sheet. With nothing lacking, no dialog.

6. **Install time**: `package.json` gains `"engines": { "node": ">=24", "npm": ">=11" }`, the same object is written into `package-lock.json`'s root entry `packages[""]` (by hand, nothing installed), and `tools/oculus/.npmrc` holds `engine-strict=true`, so `npm ci` under an older Node refuses with npm's own `EBADENGINE` line naming the range before anything installs (Decisions 4). This is where a Node too old to run a `.ts` file at all (below 22.18 or 23.6) is told what to install.

7. **Commit messages run `claude_bin`**: `server/git/git-message.ts` runs the program `claude_bin` names, passed in by its caller from the local values as the other callers of the Claude CLI do, in place of the literal `claude`, so one key names the Claude CLI everywhere and the check of item 2 covers commit messages. The test of the commit-message route, if it names the program, is updated as a row of its existing table.

8. **Text and pages**: the new catalog keys under `server.start` in `config/text/server.yml` and under `desktop.dialog` in `config/text/desktop.yml`, each read by a literal `t('...')` call (`tests/checks/source/keys.test.ts` fails on an orphan key). `README.md:5` says, in one or two sentences added to that paragraph, that each start checks the Node version, the installed packages, the hub folder and the four programs first and names what is missing with its fix, a missing program being named while oculus starts anyway, and that `npm ci` refuses a Node below 24. `DESIGN.md`'s "Decisions taken" (`:451`) gains one bullet stating the required and optional lacks and the installed-packages rule. Grep `DESIGN.md`, `HELP.md`, `README.md`, `docs/` and the head comments of the files the step changes for every sentence the change makes false (the `claude_bin` and `README.md:13` description of what uses the Claude CLI among them) and make it true; a sentence in `docs/window.md` goes to the report's "Doc text", since other steps write that page.

## Decisions taken in this brief (each reversible, none silent)

1. Required lacks refuse the start; optional lacks are named and the start goes on (open item 32 (a)).
2. "Installed" means: `node_modules/.package-lock.json` exists, and every entry of `package-lock.json`'s `packages` other than the root (`""`) and those marked `optional: true` is in it at the same `version`. Another package manager (pnpm, yarn, bun) writes no hidden lockfile and so reads as not installed, with the fix `npm ci`, which is the install `README.md:5` names.
3. The sentences said before the packages load (the Node version and the packages, in the server, the program and the app's dialog with its Quit label) are literals in `first-run.ts` and `main.ts`, as `args.ts`'s refusals are, since no catalog can be read without the `yaml` package; every other sentence is a catalog key.
4. `engines` with `engine-strict=true` in `tools/oculus/.npmrc`: `npm ci` under a Node below 24 refuses before it installs, which reaches a Node too old to run a `.ts` file, where no check of oculus can run.
5. The app shows the optional lacks once per start, while any is missing, as one sheet with Continue and Quit (merged with `env_slow` when both apply), and keeps no record of having shown them.
6. The program fixes on macOS name `xcode-select --install` for git and the Homebrew command for tmux (`brew install tmux`); perl ships with macOS and its fix names the Command Line Tools as well; the Claude CLI's fix names Anthropic's install page and the `claude_bin` key. Other platforms are O33's (Linux), and their fixes name the program to install.
7. The new module and the two start-time modules it sits with go into `src/lib/server/root/process/start/`, since `process/` reaches ten items when D50 lands; moving a file changes no line of it except a relative import path.
8. Commit messages run `claude_bin` (item 7): one key for the Claude CLI.
