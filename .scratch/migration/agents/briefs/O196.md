## What to build

1. A Save that lands ends what it saved.
   - After a Save's answer lands, every family row whose change the Save sent holds no change and no draft, in the scope and file the Save wrote. This holds whatever order the view's pushes come in. A push of the old value after the drop does not hold the draft again, and a push of the saved value ends the draft. The rows are matched as the writer keys them (`heldKey`, with the slot), so a Save of hub `lab` ends lab's draft and leaves the primary's draft of the same key.
   - The scope bar then reads 'No unsaved change', the tab is not marked unsaved, Save is off, and the editor draws neither 'Changed and not saved yet' nor 'The file changed since this edit was started'. No reload is needed.
   - This holds for:
     - an edited field (scout's `stale_days` 7 to 8);
     - a cleared field (`stale_days`, and `last_run` set to Not set);
     - an added or removed entry, and the emptied family of the existing rows;
     - each file of a Save All;
     - the workspace file saved through the name question (`resume`).
   - Kept as it is, each a case:
     - A row edited again while its Save is out keeps the newer change and its draft after the answer, through both pushes.
     - An edit made after a landed Save but before the push of the saved value is held as a change, and the push keeps it.
     - A refused Save keeps its changes, its drafts and its sentence; a later Save that lands ends them.
     - A draft the tab kept over a reload, with no Save in between, holds its change again at a push unless the file moved under it (the row 'holds a kept draft again at a push, unless the file moved from the value it was started over').
     - A push that brings a third value while a change is held keeps the change (the row 'keeps the change held when a push brings another value').
     - A Discard after a landed Save, before the push, leaves no change and no draft, and a later push of the old value holds nothing.
     - A writer closed while the Save is out moves nothing when the answer lands.
   - Where: the writer (`writer.ts`) learns which rows a landed Save wrote, from the scopes (`saveFile` in `scopes.svelte.ts`), through a dependency of `ScopesDeps` that `Settings.svelte` wires to the writer, since both are created there. A refused Save reports nothing. A change typed while the Save was out is not reported.
   - The layer rules hold: `writer.ts` and `scopes/` stay free of view imports.
   - Comments made true: `writer.ts:8-10`, `scopes.svelte.ts:6-8` and `Settings.svelte:230-231` say what holds after the change. The head comment of `editor-saved.test.ts:4-6` names what its rows now cover.

   - It does not depend on a suggesting box's list, so a loading list does not hide it.
   - An empty box is never refused by its form: the new function returns null for `''` itself.
   - The foot list of the editor keeps its line ('Entry 1, task: ...'), as it does for a number. Nothing is staged, as today. Enter and blur are not held: the draft that does not read back already holds nothing.
   - Only a card's field changes. `Cards.svelte` asks `FieldControl` for the form refusal through a prop of its own. `Control.svelte`, `AppControl.svelte`, `Item.svelte` and every other caller pass nothing and draw as today.
   - The words are drawn by `FieldControl` beside the box, and the box is marked through the `invalid` prop `TextInput` and `SuggestInput` already take. Neither input component changes, so `NumberInput`'s `refused` keeps its one meaning.
   - Where: a function of `fields.ts` beside `numberRefusal` that gives the form's refusal of a box's text or null, the prop and its drawing in `FieldControl.svelte`, and its pass in `Cards.svelte`. `FieldControl.svelte:18-19` says what the box now draws.
