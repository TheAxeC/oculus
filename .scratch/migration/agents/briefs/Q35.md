## What to build

1. **Changes' paths cut at their end.** `elide` is removed, with its tests in `format.test.ts`, `PATH_MAX` and the catalog key `sessions.ch_elide`. Its three callers draw the whole path in one line, cut at its end by `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`, the whole path in the `title` as today (`Repo.svelte`'s `.path` gains the three rules).
2. **Aligned columns in Changes.** `ChangesTouched.svelte`'s list is a grid whose columns are the mark, the path (`minmax(0, 1fr)`), the verb (`max-content`) and the count (`max-content`, right-aligned, `--font-num`); each row takes the list's columns through `grid-template-columns: subgrid`, so a verb and a count start at one x in every row. The same for `ChangeGroups.svelte`'s rows when they draw a count.
3. **Customizations open where the file is.** The listing gives each item's `path` as the file's real path (`realpathSync`, the path as found when that fails), its `name` unchanged; so a row whose real file a served root holds opens a source tab on it, and a row whose real file no root holds opens the Customization viewer, which accepts it since the listing gave it. `Customizations.svelte` is unchanged.
4. **Audit as a list.** Each finding is one `<li>` in a `<ul>` per section, carrying `data-card={finding.signature}` so the shell's arrow keys still step through the findings, drawn as the Findings view's rows are: the tree-row height, growing by whole lines when the words wrap. A row holds, in order: the scope in the row's main words (`--fs-md`, a `span`; the `h4` the card gave is not kept, the section's `h3` heads the list), the message through `CodeText` (muted ink), `where` in the mono face at `--fs-sm` (muted), and the mute or un-mute `ToolButton` (compact) at the row's end, shown under the pointer, with the focus inside the row, or always where nothing hovers, and kept in the tab order and the layout while clear. A row under the pointer takes `--chip`, as a tree row does; Audit has no selection. The Pane asks `tinted`. The section heads, counts, order, muted section, search, failure line and the note with Open Findings stay. `Card` is no longer imported. The head comment and the comments that speak of cards are made true. The terminal-theme rule at the end of the style keeps its meaning.
5. **Present filling its pane** (Z189, amended by Z193). The deck box fills the pane body (`height: 100%`, `overflow: hidden`). The slide is drawn in a frame of 1280 by 720 px (the design size) scaled uniformly to the box: an outer box of `1280 * s` by `720 * s` px centred in the deck box, an inner 1280 by 720 box with `transform: scale(s); transform-origin: 0 0`, `s = fit(width, height)` from the deck box's `bind:clientWidth` and `bind:clientHeight`. `fit(w, h)` is `min(w / 1280, h / 720)`, and 0 for a non-positive or non-finite size; while `s` is 0 (a hidden tab, the first paint) the frame is `visibility: hidden`, so no unscaled slide flashes. The frame draws its own surface: `background: var(--card)` and, over a wallpaper, the translucent mix every card surface takes (`Panel.svelte:147-150`), so the slide's words never sit on the picture.
6. **The slide laid out for its frame** (Z193). Inside the frame the slide parts use a slide type scale set on the frame in px at the design size: `--slide-fs-title` 56, `--slide-fs-h` 36, `--slide-fs-sub` 28, `--slide-fs-body` 24, `--slide-fs-small` 18, multiplied by `--text-scale`, in place of the UI's `--fs-*` tokens; the frame has 64 px padding; Title and Closing are centred both ways; a part's reading width is at most 1040 px (the frame less its padding) and centred, in place of the `ch` caps. A slide taller than the frame scrolls inside it (the inner box is `overflow-y: auto` and carries `data-scroll`), and `jump.ts` divides the distance it scrolls by the scale of the box it scrolls (`getBoundingClientRect().height / offsetHeight`, 1 when either is 0), so a `#` link lands on its heading in a scaled frame. The Overview grid, the empty state and the Panel are not scaled and keep the UI tokens.
7. **Tests.** `audit.test.ts`: the cards' describe becomes the rows' (one `li[data-card=<signature>]` per finding, the scope, the message as code with no backtick, the place, the mute control on an open row and the un-mute on a parked one, no `article.card`); its source-text case is removed and `allow-audits.txt:11` with it. `present.test.ts` (views): the deck draws the slide inside the frame with the design size, and the empty state and the grid outside it. `tests/state/life/present.test.ts`: `fit`. `format.test.ts`: the `elide` cases removed. `type-scale.test.ts`: the Audit row and the slide parts' rows as the change leaves them. The Changes and Customizations cases below.
8. **Docs.** `DESIGN.md:367` and `HELP.md:120`: the slide is a 16:9 frame scaled to its pane. `DESIGN.md:378` if it speaks of the Audit's cards. `HELP.md`'s Changes passage if it speaks of a cut path.
