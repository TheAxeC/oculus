## What to build

This brief is written for the recommendation of each choice listed under "Decisions for Axel" at its end; where Axel rules another option, the orchestrator rewrites the item before dispatch.

### 1. The app and its server

`npm run app` (the script runs `vite build`, then `electron .`) starts the app from the checkout; `package.json` gains `"main": "src/desktop/main.ts"`. The main process is TypeScript under `src/desktop/`, run unbuilt by Electron's Node as the probe ran it. It accepts `--engine <dir>` with `parseEngineArgs`'s rules and hands it to the server, and refuses any other argument with `parseEngineArgs`'s sentence in a dialog (Chromium's own switches excepted, which Electron consumes).

The server runs in a utility process (`utilityProcess.fork` of `src/server.ts`, `stdio: 'pipe'`, `serviceName` the app's name), never in the main process, so a long config read never stops the window's menus or its move. The main hands it the environment of item 1.1 and `--engine`. Its output is printed on the app's own output with a prefix naming the server.

`src/server.ts` reports to its parent when it has one (`process.parentPort`, read once in the entry and passed down; nothing else reads it): `{ kind: 'listening', port }` on every `listening` event of the http server (the first listen and every port move), and `{ kind: 'failed', reason, port }` when the first listen fails. The first listen gets an `error` listener in every run: `EADDRINUSE` prints `oculus: port <n> is in use` on stderr and exits 1, under the app and under `node src/server.ts` alike, in place of the stack it throws now. The message shapes live in one module under `src/lib/server/root/process/` that both ends import.

The main waits for `listening`, then opens the window on `http://127.0.0.1:<port>/`. It keeps the port the server last reported, so a port move (D35) is followed by the window, whose page goes to the new address itself (`socket.svelte.ts:254-277`), and the navigation guard of item 5 admits the new origin.

`build/handler.js` missing: a dialog says the server is not built and names `npm run build`, and the app quits. A server process that exits while the app runs (a crash, a kill) shows a dialog with its exit code and its last stderr line, offering Restart (the process forked again, the windows left open; their pages reconnect as on any restart) and Quit.

Quit (Cmd+Q, the menu, the Dock) stops the server process (`kill()`, which is SIGTERM, so `onShutdown` closes the socket, the context and the tmux control clients) and waits for its `exit`, at most 5 s, then the app exits. tmux sessions are left running, as a page that detaches leaves them (G28); the next start's Terminal tabs attach to them again.

1.1. The environment. Started from the Dock (`app.isPackaged`), the main resolves the login shell's environment with `shell-env` before forking the server and merges it over the inherited one, so PATH, LANG and the rest are the login shell's; a 10 s limit, after which, or on any failure, the server starts with the inherited environment and a dialog says once that programs on the login PATH (tmux, git, claude) may not be found. Started from a terminal (`npm run app`, unpackaged), the inherited environment is used as it is. DESIGN.md:393 ("The server reads no environment variable of its own") stays true: the server reads none of its own; the app hands it the shell's.

### 2. One instance

`app.requestSingleInstanceLock()`: a second start prints `oculus is already running; its window is brought to the front` on its output, quits with status 0 and starts no server; the first takes `second-instance` and shows its main window, opening one when none is open. The second start's arguments are not taken.

### 3. The windows' lifetimes

The main window is a `BrowserWindow` on the server's page. Closing the last main window leaves the app and the server running, as a macOS app does; a Dock click (`activate`) or File > New Window opens the main window again, with its popped-out windows (item 8). A window whose page crashes (`render-process-gone`) is reloaded, the reason printed on the app's output.

Every window: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `nodeIntegrationInSubFrames: false`, `webSecurity: true`, the preload of item 12, `spellcheck: true`. The page's `Content-Security-Policy` and `sameOrigin` are unchanged: Chromium sends `Sec-Fetch-Site` and `Origin` as Chrome does, so the guard admits the window's requests with no change to `hooks.server.ts`.

Permissions: `setPermissionRequestHandler` and `setPermissionCheckHandler` grant `clipboard-read`, `clipboard-sanitized-write` and `fullscreen` to the server's origin and deny every permission to every other origin and every other permission.

### 4. Window state

The main window's bounds, maximised and full screen state, and zoom factor are written to `~/.oculus/window.json` when the window moves, resizes, changes state or closes (debounced 500 ms, through a temporary file and a rename), and read before the window is made. A file that is missing or does not read opens the window at 1280 by 800 centred on the primary display; a saved place on no attached display opens on the primary display, its size kept and clamped to the display's work area. The popped-out windows keep their places in the arrangement (item 8), not in this file.

### 5. Links and navigation

One pure function decides where an address goes: the server's own page (same origin, path `/`) opens in an app window, a main window when it carries no `float` query and the popped-out window of item 8 when it does; any other `http:`, `https:` or `mailto:` address, same origin included (a file's own address from File.svelte:183 and Document.svelte:113), opens in the default browser through `shell.openExternal`; any other scheme is refused and printed. It is applied by `setWindowOpenHandler` (every `window.open` and `target="_blank"`) and by `will-navigate` and `will-frame-navigate` (a top-level navigation to another origin is stopped and handed to the same decision; a subframe keeps navigating as the page's own policy allows). The page's code is unchanged for links: Open Worktree in New Window opens a second main window, an Inbox thread opens in the browser.

A download (`will-download`) keeps Electron's Save dialog.

### 8. A floating pane in a window of its own (Z3)

A popped-out window is a page of its own: the server's page loaded with `?float=<id>`, with its own client, socket and stores, drawing the float with that id and nothing else (no rail, no status bar), filling the window. Both pages hold the whole arrangement and follow each other's writes through the `storage` event they already follow (`takeSaved`), so a move made in one window shows in the other. The main window's FloatLayer leaves out every float placed in a window. Every library draws in its own document, so nothing of Monaco, xterm, bits-ui or interactjs is made window-aware.

The arrangement: `FloatPlace` gains `{ kind: 'window'; x; y; w; h }`, the window's content bounds in screen points (`model.ts:111-113`, `saved.ts:125-138`, `placeFits`, which holds a window place to finite numbers with `w` and `h` at least 200). The envelope's version stays 6: a page of this code reads its own writes, and a window place met by a page with no bridge (Chrome) is read as the default free place (`floats.ts:65`) with its tabs kept, and written back only when that page changes the float.

What opens one (the words in item 13): a float's strip menu and pane menu, Move into New Window (the float placed in a window at its place on screen, 600 by 400 when it was docked); a pane's strip menu and pane menu, Move into New Window (`floatPane`, then the same); a tab's right-click menu, Move into New Window (`floatTab`, then the same) and Copy into New Window (a new instance of the same view with a copy of the tab's state, in a new float placed in a window; not offered on a Terminal tab, since a terminal belongs to one tab, HELP.md:136); a tab dragged and released outside every oculus window, a new window at the release point (VS Code's `workbench.editor.dragToOpenWindow`); a tab dragged from one oculus window and released over another, the tab moved into the pane under the pointer there (the source page hands the release to the main process, which finds the window holding the point, the one focused last when several do, and hands the point to that page, which runs its own drop hit test and performs the move). None of these is offered in a page with no bridge.

What the popped-out window's menus offer: its strip and pane menus hold Restore into Main Window (the float free in the main window, at the default place), Return to Page (`returnFloat`), Dock Left, Dock Right and Dock Bottom (docked in the main window), Lock Group and Unlock Group, Switch to Main Window, and no split, fold, maximise or Float; its tab menu holds Move into New Window and Copy into New Window.

How a window follows its float: the main process keeps one window per float id; a page that finds a float placed in a window and no window open for it asks the main to open one, and the main opens none twice. The main tells the page of a popped-out window its new bounds after `moved` and `resized` (debounced 500 ms), and that page writes the place. A popped-out page whose float no longer exists (returned, closed elsewhere) asks the main to close its window.

What closing does: closing a popped-out window by its close button or Cmd+Shift+W puts its tabs back in the main window as a free float at the default place, terminals running and unsaved text kept, with no question; closing the last main window closes its popped-out windows and keeps their places, so they open again with the next main window; Quit keeps them likewise, and the next start opens them where they were.

Move Terminal into New Window is a Terminal tab moved by Move into New Window: the terminal detaches from the page it leaves and attaches in the new window's page, and keeps running (G28's "ends no terminal when it moves").

## Decisions taken in this brief (each reversible, none silent)

1. The main process, the preload and the find bar's page live in `src/desktop/`, a seventh item of `src`; the packaging script is `src/desktop/package.ts`, since `utils/` holds ten items. The folder is a process host like `src/server.ts`, outside the three layers' `src/lib`, and imports from `src/lib/data` and `src/lib/server/root/process` only.
2. The server runs in a utility process and never in the main process, so the window's menus and moves never wait on work the server does on its own event loop.
3. The messages between the server process and the main are `{ kind: 'listening', port }`, `{ kind: 'failed', reason, port }`, `{ kind: 'pick-folders', id }` and `{ kind: 'picked', id, paths } | { kind: 'picked', id, cancelled: true } | { kind: 'picked', id, failed: true }`, declared once in `src/lib/server/root/process/`.
4. The popped-out window's address is the page's with `?float=<id>`; its place is in screen points in the arrangement; the envelope stays at version 6 (item 8).
5. The bridge's name on `window` is `oculusDesktop`, read once in `+page.svelte`.
6. `npm run app` builds before it starts, so the app from the checkout always serves the checkout's code; the packaged app serves what `build/` holds, which the README says.

## Decisions for Axel (the brief is written for each recommendation; reversible until the builder starts)

Each is a user-visible shape nothing in the plan names. The lazy option is named in each.

- D1, the packager: (a) `@electron/packager`; (b) `electron-builder`; (c) `@electron-forge/cli`; (d) none, `npm run app` only. Recommended (a): the Electron project's own tool, which makes and signs the `.app` and nothing more. Lazy: (d), which leaves no Dock icon of its own and the name "Electron" in the menu bar.
- D2, the login shell's environment for a Dock start: (a) `shell-env`, the whole environment; (b) `fix-path`, PATH alone; (c) by hand; (d) none. Recommended (a): PATH, LANG and the rest of the shell's environment reach tmux and the agents. Lazy: (d), under which a Dock start finds no tmux.
- D3, the text field's right-click menu: (a) `electron-context-menu`; (b) by hand from the `context-menu` event; (c) none. Recommended (a): less code, every label from the catalog. Lazy: (c), under which a plain field has no Paste on the right-click.
- D4, where the main window's place is kept: (a) `~/.oculus/window.json`, by hand; (b) `electron-window-state` in Electron's own folder; (c) not kept. Recommended (a): machine-local state lives under `~/.oculus` (DESIGN.md), and the library is unmaintained since 2018. Lazy: (c).
- D5, the app's name, id and icon: (a) `oculus`, `local.research.oculus`, an icon drawn for oculus that also replaces the Svelte-logo favicon; (b) the same with `io.github.theaxec.oculus`; (c) Electron's own icon. Recommended (a): `local.` says a machine-local app, which oculus is (DESIGN.md non-goals). Lazy: (c).
- D6, where the app goes: (a) `npm run app` from the checkout and `npm run app:package` writing `~/Applications/oculus.app`, which runs the checkout's code; (b) the package written under `tools/oculus/build/app/`, copied by hand; (c) `npm run app` alone. Recommended (a). Lazy: (c).
- D7, how a pane moves into a window: (a) each window a page of its own, the arrangement shared through `localStorage` as two browser tabs share it now; (b) one page drawing into several windows, VS Code's way, every library made to draw into another document; (c) no popped-out window. Recommended (a): every library draws in its own document unchanged and the sharing is the tree's own; its cost is a second client and socket per window, and DESIGN.md:305 and :322, written for (b), are rewritten. Lazy: (c). (b) costs more and rests on six libraries working in a second document, none of which was probed.
- D8, closing a popped-out window: (a) its tabs return to the main window as a float, nothing asked; (b) its tabs close, asking as Close pane asks. Recommended (a): nothing is lost. Lazy: (b).
- D9, closing the last main window: (a) the app and the server keep running, a Dock click reopens; (b) the app quits. Recommended (a): the hooks and notifications keep working. Lazy: (b).
- D10, a port in use at start: (a) a dialog, offering a window onto an oculus that answers there; (b) a dialog and quit; (c) a free port taken. Recommended (a). Lazy: (b). (c) changes the page's origin each start and so loses the arrangement.
- D11, the keys: (a) Cmd+W, Ctrl+Tab and Ctrl+Shift+Tab, Cmd+N given to the page, and the menu's Cmd+Shift+N, Cmd+Shift+W, Cmd+,, Cmd+R, zoom, full screen and developer tools; (b) the menu's roles alone. Recommended (a): VS Code's keys for the commands oculus has. Lazy: (b).

- D14, the menu: (a) the menus of item 6; (b) Electron's default menu. Recommended (a): the default's Cmd+W closes the window and its words are not the catalog's. Lazy: (b).
