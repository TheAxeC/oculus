## What to build

1. **The head's Refresh now.** It carries the `refresh` glyph and turns from the press until the press's request has answered, as `ConnectorHead.svelte:86` does. `Head.svelte` gets whether the cluster's refresh is running from `Cluster.svelte` as a prop.
2. **The error box's refresh.** The same glyph, turning over the same span, from the same state, so pressing either control turns the one on screen, and a press in the head whose poll then fails leaves the error box's control turning until the request answers.
3. **The log box's tail.** The same glyph, turning while the log is being read (`status === 'loading'`), from the press until `jobLog` answers. `showLog` sets the status to `'error'` when `jobLog` rejects (`try`/`catch`), so a failed read never leaves the glyph turning and the box says the read failed in its existing words. An answer of a `showLog` that a later `showLog` superseded (another job's log opened, or the box closed, before it answered) is dropped, never written over the later log's status and output (a request counter, or the job id checked against `logId`). A tail press while that log loads starts no second request. A load in flight keeps turning until its answer when `live` turns false meanwhile, though the control is then disabled.
4. **The state of a refresh.** The HPC store (`src/lib/state/system/machine/hpc/hpc.svelte.ts`) holds which clusters' refreshes run, a pressed count per resource from each press until that press's own answer, as `usage-refresh.svelte.ts` holds it per account: `refresh(resource)` posts the command, and `refreshing(resource)` says whether one runs. The count is lowered in a `finally`, so a request that rejects never leaves the glyph turning. `Cluster.svelte` reads `refreshing(data.resource)` and calls `refresh(data.resource)`. A press while that resource's refresh runs starts no second request and the control keeps its look, no `waiting`, as the precedent's. One cluster's press never turns another's control. A view opened again while a press waits turns until the answer.
5. **The words.** The head comments of the three components and of the store say what turns and for how long, with no history.
6. **The help page.** `docs/HELP.md:363`, the Live HPC bullet, gets one sentence: Refresh now, in the head and in the error box, and the log's tail turn their glyph from the press until that request answers. `docs/HELP.md:359` is left as it is unless it then reads as if only the Inbox and the Calendar turn, in which case Live HPC is named beside them.

3. The words of the controls stay as they are ("Refresh now", "tail"); only the glyph is added.
4. Under reduced motion the glyph does not turn, and the turning glyph is hidden from a screen reader (`Glyph.svelte`), as for the precedent; the step keeps that, and the look is taken in the default theme with motion allowed.
5. A second press while a refresh runs makes no request and leaves the control's look unchanged (no `waiting`), as `ConnectorHead.svelte:86`.
