## What to build

1. **`src/lib/state/boards/structure/forces.ts`**, new, the Map's force simulation on `d3-force`, pure of the DOM:
   - `FORCES`, the one parameter set: `charge: -120`, `chargeMax: 300`, `gap: 4`, `collideStrength: 1`, `collideIterations: 2`, `center: 0.02`, `dragHeat: 0.3`. The velocity and alpha decay stay at d3's defaults. `createForces` takes an optional parameter set, `FORCES` by default, so a test can switch one force off.
   - `createForces(nodes, edges, bounds = DEFAULT_BOUNDS, params = FORCES)` answers a stopped simulation (`.stop()` at once) over copies of the nodes, with: `forceLink` over copies of the edges (`{ ...edge }`; `forceLink` rewrites a link's `source` and `target` to node objects, so the Map's own edges are never handed to it) whose two ends are both in `nodes` (`forceLink` throws on a missing id), `.id((node) => node.id)`, each link's `distance` its length as the given nodes stand, which is neato's placement, and d3's default strength; `forceManyBody().strength(params.charge).distanceMax(params.chargeMax)`; `forceCollide((node) => node.radius + params.gap / 2).strength(params.collideStrength).iterations(params.collideIterations)`, so two circles rest `gap` apart; `forceX(width / 2)` and `forceY(height / 2)` at `params.center`. A parameter at 0 leaves that force out. d3's own deterministic random source is kept.
   - `clampToBox(simulation, bounds)` puts every node back inside the box less its pad and zeroes the speed that points out of it. It runs after every tick, since a d3 force runs before the move and cannot bound where the move lands.
   - `advance(simulation, ticks, bounds)` runs `simulation.tick()` then `clampToBox` that many times.
   - `settleForces(simulation, bounds)` advances until `alpha() < alphaMin()` (300 ticks from alpha 1 with d3's defaults) and answers the nodes as copies. The simulation is left settled and cold, and is the one the view goes on with.
   - `press(simulation, id)` fixes the node at where it is (`fx`, `fy`); it neither ticks nor restarts, and does nothing for an id not in the simulation.
   - `dragTo(simulation, id, point)` moves the fixed node to `point` and sets `alphaTarget(params.dragHeat)`; nothing for an unknown id.
   - `release(simulation, id)` sets `alphaTarget(0)` and frees the node (`fx = fy = null`), so the simulation cools to rest and the released node takes part again, as before Q86; nothing for an unknown id beyond `alphaTarget(0)`.
   - Head comment: what it does and why, no history.

## Decisions taken in this brief (each reversible, none silent)

1. The values of `FORCES`. d3's charge falls off as 1/d where the pre-Q86 one fell off as 1/d^2, so the old numbers do not carry over; these are the starting values. The builder may change a value only to meet a case, and reports each change with the case, the value before and after, and the measurement.
2. Each link rests at the length neato gave it, and the view goes on with the one settled simulation, so the first drag does not jolt the picture (the brief check measured up to 19.6 units of jolt with a second simulation built from the settled nodes).
3. A released node joins the simulation again (d3's standard drag, and the Map before Q86), so it may drift after the drop while the others cool. A press while the last drag still cools lets the others go on cooling; the pressed node stays put.
4. d3's own random source is kept; it is deterministic per simulation.
5. The settle runs synchronously when the node set or seed changes. The brief check measured 450 ms for 400 nodes in node; the builder measures the dense graph and the real portfolio's size and reports both.
