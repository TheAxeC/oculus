# Brief: P4, collections parity

Read `../spec.md` first; it governs this package unchanged. Then `../../parity.md`, its "Collections" section. O14d landed one generic read-only view over a collection file's own schema; the cockpit's collection tabs (Funding, Talks and Events, Education and Service, Applications, Collaborations, Tasks and Service, Statements, Code) carry an intro, an add control, and per entry an edit form, a pin, a subtasks block, status buttons, a drag grip, cross-links to the projects naming the entry, folder and posting links and a rendered note, and there is no Funding view in oculus at all. This package makes every collection view carry what its tab carries, on oculus's design: `state/collection.ts` for the pure parts, the primitives, P1's write path (`state/writes.svelte.ts`: `writeEntry`, `writeSubtask`, `addSubtask`, `newEntry`; read that file whole) plus the two writes this package adds.

## The acceptance list, from the cockpit tab as extracted on 2026-09-11

One collection tab (`render/collections.py` `collection_tab_html`, lines 21 to 118), top to bottom:

1. The intro: the file's `intro:` as rendered Markdown.
2. The controls: the search box "Search <title> ..." and "+ add" (a form over the file's schema, saving through `newEntry`; drawn only when the file has a schema).
3. The status facet bar: one toggle per distinct status with its count and colour, all on by default, a click hiding that status's cards; the Funding tab adds a "No funding" toggle for the synthetic card of projects with no scheme (item 9).
4. The cards, pinned first then in file order (`pin: true`), each: the drag grip (reordering the entries by drag, saved as the new order of identity values; `03-filters.js` lines 60 to 118), the pin mark, the title, the status chip in its palette colour, the date, the action row (the pin toggle writing `pin`, the edit control opening the form over the schema pre-filled with the entry, with a delete in it), then `sub`, the `meta` chips (`metalist`: label and value pairs), the `note` as rendered Markdown, the funding `statement` as a blockquote with its tooltip, the tags, the cross-links (item 5), the links (item 6), the subtasks block (item 7).
5. The cross-links (`collrel`): the projects naming this entry, grouped by type with counts ("5 active | 1 active | 4 manuscript"), each group's members opening their project tabs (`_xlink_groups`): for funding the projects whose manifest `funding:` names the scheme's key, for collaborations the projects whose `collaborators:` names the key, for every other collection the entry's own `related:` list of project ids.
6. The links: `link` (a hub-relative folder or file, opened through `/api/file/hub/<path>` as O14c's document tab for HTML and as a plain link otherwise) and `url` (an external posting, a new tab).
7. The subtasks block, as P3 item 8 draws it on a card, over the entry's `subtasks` through `writeSubtask` and `addSubtask`.
8. A collection without a schema (Code, Statements have one; check each file's `schema:`) keeps the status buttons (the lifecycle statuses of `status_palette` except the current one, writing `status`) instead of the form, as `_status_actions` draws them.
9. The Funding tab: the funding file as a collection view like the others (the statement blockquote is what the manuscripts paste), with the cross-links of item 5 from the manifests' `funding:` tags, and the synthetic "No funding" card listing the active and manuscript projects with no scheme.
10. The Code tab as the cockpit draws it: the repos file's entries, and the coverage groups over the projects' `code_availability` (deposited, review-anon, none) as three collapsible sections with counts, each project a link to its tab (`render/collections.py` and `page.py`, grep `tab-code` and `coverage`).
