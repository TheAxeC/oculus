# Brief: Q2, the browser test layer

Read `../spec.md` first; it governs this package unchanged, with one named exception under "Dependencies" below. Every view test in `tests/views/` renders a component to HTML on the server and reads the string; nothing in the suite opens a page, presses a control, or watches a write come back through the socket. Those are the interactions the orchestrator has hand-checked in Chrome at every landing since O10, and two of them (the drag of a Focus card onto a lane, the drag reorder of a collection) have never been checked at all, because Chrome automation does not drive HTML5 drag and drop. This package adds the layer that does: Playwright over the built server, serving a synthetic hub, with one spec per interaction of the acceptance list. `npm test` stays what it is, fast and browserless; the browser layer is its own script.

## Decisions taken in this brief (each reversible by the orchestrator, none silent)

1. **The harness is `@playwright/test`** (1.63.0 on npm on 2026-09-11), running the installed Google Chrome (152.0.7977.83 at `/Applications/Google Chrome.app`) through `channel: 'chrome'`, so nothing downloads a browser. Vitest's browser mode (`@vitest/browser` 4.1.11 for the pinned Vitest 4) tests a component in a browser in isolation; what these interactions need is the served application, its socket and its watcher, since a button on the page is proved by the file it changed and the DOM the watcher then pushed. Playwright over `node src/server.ts` is that.
2. **The demo hub.** `tools/oculus/demo/` is a synthetic hub copied from the cockpit's `tools/cockpit/dummy/`: its `projects/` (ten manifests across the five tiers), `registries/`, `funding/`, `network/`, `education/`, `applications/`, `tasks/`, `feeds/` and `CAREER.yml`, and none of `cockpit.html`, `_data/`, `_linkedin/`, `data/`, `talks/`, `AUDIT_AUTO.md`, `GUIDE.md`, `README.md` (about 130 KB). It is oculus's own file from then on: where oculus's reader reports a finding on it (a status outside the vocabulary, an id that does not resolve), the demo file is corrected, never the reader. `demo/README.md` (new, a paragraph) says what the folder is and that the browser tests copy it to a temporary directory per run and never write into it. R2 (release readiness) ships this folder as the demo a stranger sees, which is why it lives under `tools/oculus/` and not under `tests/`.
3. **`OCULUS_LOCAL`.** `loadLocal()` in `src/lib/data/sources/config.ts` (line 59) reads `<engine>/local.yml`; it gains one environment override: when `process.env.OCULUS_LOCAL` is set, that path is the local file read instead, absolute or relative to the engine, and a missing file at that path is an error rather than the defaults (a test that names a file that is not there should fail loudly). `hub:` in that file resolves relative to the file's own folder when relative. This is a user-visible shape (an environment variable) and is the one this brief adds; it also lets every later agent's server check run without writing `local.yml` into the worktree.
4. **Layout.** Specs live in `tests/browser/*.spec.ts` (Vitest's include is `tests/**/*.test.ts`, so they stay out of `npm test`); `playwright.config.ts` at the package root; `tests/browser/serve.ts` is the web server command; `tests/browser/hub.ts` is the fixture module the specs read the temporary hub's path from. The script is `"test:browser": "playwright test"`, run after `npm run build`; the config does not build.

## What to build

### A. The demo hub and its probe

`tools/oculus/demo/` as decision 2 says. `tests/data/demo-hub.test.ts`, modelled on `tests/integrity.test.ts` (read it whole), runs the reader over `demo/` and asserts zero findings and the counts the folder holds (ten projects, the registries, eight collections). This test is part of `npm test`.

### B. `OCULUS_LOCAL`

Decision 3, in `loadLocal()`, with `tests/config.test.ts` gaining three cases: the override is read instead of `<engine>/local.yml`; a relative `hub:` in it resolves against the file's folder; a missing file at the override path throws. `src/server.ts` and `vite.config.ts` need no change: both call `loadLocal(engine)`.

### C. The server command and the fixture

`tests/browser/serve.ts`: copies `demo/` to `mkdtempSync(join(tmpdir(), 'oculus-browser-'))` (asserting the resolved path is inside the temp dir before any write), writes `<temp>/local.yml` with `hub: <temp>/demo` and `port: 8792`, writes the temp path to `<repo>/tests/browser/.hub` (gitignored; add the line to `.gitignore`), and spawns `node src/server.ts` with `OCULUS_LOCAL=<temp>/local.yml`, forwarding its stdout and stderr and exiting with its code. `tests/browser/hub.ts` exports `hubDir()` (reads `.hub`) and `readHubFile(rel)` for the specs' file assertions. `playwright.config.ts`: `testDir: 'tests/browser'`, `webServer: { command: 'node tests/browser/serve.ts', url: 'http://127.0.0.1:8792/', reuseExistingServer: false, timeout: 60000 }`, one project `{ name: 'chrome', use: { channel: 'chrome', headless: true, baseURL: 'http://127.0.0.1:8792' } }`, `fullyParallel: false` and `workers: 1` (the specs write to one hub), `retries: 0`, `reporter: 'list'`. Every spec starts from a fresh page and its own project or entry of the demo, so the specs do not depend on order; a spec that writes puts the file back as it found it at the end, or asserts the exact bytes it left.

### D. The specs, the acceptance list

One file per row, each asserting on the DOM (Playwright's auto-waiting locators, by role and by the catalog's words read from `config/text-oculus.yml` and `config/text.yml` through `tests/text.test.ts`'s way of loading them) and, where a write happens, on the temporary hub's file through `readHubFile` after the DOM changed:

1. `boot.spec.ts`: the page loads, the Status view says the socket is connected and the snapshot holds ten projects.
2. `pages.spec.ts`: the page strip's menu adds a page, renames it, `Ctrl+2` switches to it, `Ctrl+1` back; closing a page opens the confirm dialog, cancel keeps the page, confirm removes it. The words are the strip's own catalog keys, `page_new`, `page_rename`, `page_close` and `page_from` at `config/text-oculus.yml` lines 64 to 71 (the group name is the line above them).
3. `focus-buttons.spec.ts`: on the Focus board, a deadline line's `1w` moves the line to the Snoozed group and the manifest gains `snooze:`; `un-snooze` puts it back and the manifest is byte-identical to before; the flame badge on a card cycles unset, low, medium, high, unset through the menu and the manifest's `priority:` follows; Quick add writes a follow-up to a project and the ticker shows it.
4. `focus-drag.spec.ts`: a card dragged from one lane onto another (`locator.dragTo`) lands there and the manifest's `focus:` is the new lane. If `dragTo` does not fire the HTML5 events the handlers listen to, drive the drag with `page.mouse` steps and say so in the report; if neither works, the spec is written to fail loudly, not skipped, and the report says the drag is unverified.
5. `board.spec.ts`: on the Projects board, expanding a card lists the file finder's rows; the pin control pins the card (manifest `pin: true`), the board moves it first, and unpin restores the bytes; the new-idea form scaffolds `projects/ideas/<id>/project.yml` and `README.md` in the temporary hub, and the card appears; a click on a card's title opens the project tab and its card carries the deposit control.
6. `collection.spec.ts`: on the Tasks tab, the add form creates an entry and the file gains its block; the edit form changes its status and the chip follows; a drag of one card onto another reorders the file (same fallback rule as row 4); `+ subtask` adds a line and `done` ticks it; delete behind the confirm removes the block, cancel leaves it.
7. `funding.spec.ts`: the Funding view shows the "No funding" card and a scheme's cross-links, and a cross-link opens the project's tab.

The specs read every word they look for from the catalog files, never a literal English string; a control is located by its accessible name (`getByRole('button', { name })`), which is the `aria-label` a compact `ToolButton` carries or its visible label.

### E. Scripts, lint, ignore

`package.json`: `"test:browser": "playwright test"`. `eslint.config.js`: `playwright.config.ts` and `tests/browser/**/*.ts` are linted (the `tests/**/*.ts` glob already covers the specs; add the config file to the `files` list or explain why it stays out). `.gitignore`: `tests/browser/.hub`, `test-results/`, `playwright-report/`.

## Conventions
