## What to build

1. **The object.** `src/lib/state/context.ts`: `type ClientState` holding one instance of every store the inventory lists except the catalogs, and `createClientState(): ClientState` building them. Each store module exports a factory (`createFiles(): FilesStore`, `createDocs()`, `createDeposit()`, `createTranscripts()`, `createSource()`, `createSocket()`, `createEntities()`, `createLayout()`, `createUi()`, `createUsageRefresh()`, `createRegistry()`, and for the singletons `createClock()`, `createDrag()`, `createSelection()`, `createGeneration()`, `createGlyphMode()`, `createWrites()`) whose returned object carries the module's public functions as methods over the instance's own collections; the module-level collections go. A store that reads another (the layout store reading the ui store, the selectors reading the entities store) takes it as a factory argument, so the wiring is in `createClientState` and nowhere else.
2. **The root and the reach.** `+page.svelte` creates the object once in its script body and provides it with Svelte's `setContext` under one key; `src/lib/state/use.ts` exports `useState(): ClientState` (a `getContext` under that key) and every view, shell component and route reaches the stores through it: `const { files } = useState()` at the top of the script, the call sites unchanged (`files.list(id)` or the destructured method, whichever keeps a call site to one line). The selectors module (`selectors.svelte.ts`) becomes methods of the entities store or a factory over it; `state/text.ts`, `tones.ts` and `appearance.ts` stay module-level catalogs, loaded once, exempt by name in the boundaries rule with the reason (immutable after load, read by `t()` from every layer including `ui/`).
3. **The audit.** `tests/boundaries.test.ts`: the client exemption narrows to the three catalog modules; every other module-level `Map`, `Set`, `{}`, `[]`, `$state` or `let` under `src/lib/state/`, `src/lib/views/registry.ts`, `src/lib/shell/` and `src/lib/ui/` is a violation, the server clause's own regex applied to the client. The rule fails on the tree as it is and passes on the package.
4. **The tests.** Every state test builds its own instance (`createClientState()` or the one factory it needs) in `beforeEach`, and the hand resets go; a view test renders with the object provided (`render(View, { context: new Map([[KEY, state]]) })`). The test count stays the same plus the context module's own cases (the object holds one of each store; two objects share nothing).

## Decisions taken in this brief (each reversible, none silent)

1. Provision is Svelte context under one key, not a prop threaded through the tree.
2. The catalogs stay module-level and are named in the boundaries rule with their reason.
3. Each store's public shape is its methods on the instance; no store exposes its collections.
