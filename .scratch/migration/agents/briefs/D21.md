# Brief: D21, files open as an editor opens them

Read `../spec.md` first, its section "The principles every package is judged on" and its amendment of 2026-09-16 (the port rule) above all. The plan's D21 line (Axel, 2026-09-16 00:35): every text file from the file browser opens in the source tab; the file view is kept for what an editor cannot show; `editable_extensions` and `viewable_extensions` are removed and text is told from content; read-only comes from the file mode alone; a single click opens a replaceable preview tab that a double click or a keystroke pins. DESIGN.md's decision line of 2026-09-16 states the same; DESIGN.md's non-goal is "Not an IDE", so nothing here needs a language server.

## How it lives in oculus (the three layers, the data live)

1. **Text is told from content, not from a list.** Data and state: `typeOfFile` keeps deciding `html`, `image` and `pdf` by name, since those are formats the browser draws, and keeps the language by name for colouring; every other file is `text` when its bytes say so and `other` when they do not. The rule, pure in `state/fs.ts`: the first 8 KB hold no NUL byte and decode as UTF-8 without a replacement character. It runs in the browser over the bytes `readCapped` already fetched, so no server change classifies a file. Server: the source route stops reading any extension list; a save is refused with `binary` when the body it would overwrite fails the same rule on disk (the rule lives in `data/text-kind.ts`, importable by both layers as `data/guards` is).
2. **Read-only comes from the file mode.** Server: `GET /api/source?root=<key>&path=<path>` (`server/source.ts`, the same resolver and origin check as the save) answers `{ readonly: boolean }` from `accessSync(W_OK)` on the resolved file. State: the source store reads it when a tab opens and holds it with the draft. View: a read-only file draws a lock in the source tab's bar with `source.readonly` ("This file is read-only on this machine; the editor shows it and saves nothing.") and the editor refuses keystrokes; Save is not drawn. A save that the server still refuses (the mode changed underneath) answers `readonly` and the tab shows the same sentence.
3. **The file browser opens the source tab for text.** View: the Files view's `onopen` opens `source` for a `text` kind and `file` for `html`, `image`, `pdf` and `other`, through the existing `sourceTabState(root, path)`. The file view's toolbar control of D6 goes (`File.svelte`, `file.edit` and its tooltip, the file-view describe); the file view no longer draws text at all: a text path handed to it (an old saved layout) opens the source tab instead, one line in `File.svelte`'s mount. The code window (`file/Code.svelte`) and its languages stay as the source tab's read-only rendering of a file the mode locks.
4. **The preview tab.** State: an `Instance` gains an optional `preview: true`. `openView` takes an option `{ preview: true }`: when the target pane holds a preview instance, that instance is retargeted to the new view and state (the tab is replaced in place, its position kept); otherwise a new instance is opened with the flag. `pinInstance(id)` clears the flag (the existing pin means "kept" already; a preview tab is the opposite end of that scale, and one flag on the instance holds both). The flag is cleared by: a double click on the tab or on the tree row, a keystroke in a source tab's editor, a drag of the tab, or the pane's split. Nothing else reads the flag. `LAYOUT_VERSION` is unchanged since the field is optional; `checkLayout` accepts it. View: the tab strip draws a preview tab's label in italics (a class, no new colour) and its tooltip `ui.preview_tab` ("Preview: the next single click replaces this tab; double click to keep it."). The tree: a single click opens with `preview: true`, a double click opens pinned; the `ToolButton` gains `ondblclick`, passed through like `onclick`.
5. **The lists go.** `editable_extensions` and `viewable_extensions` leave `config/sources.yml` (with their comment), `tests/config-folder.test.ts` (the pinned lists and the keys table), `data/sources/config.ts` if it names them, `state/source.svelte.ts` (`sourceAccess`, `configured`), `server/source.ts` (`extensionList`, `editableExtensions`, the `editable` parameter of `handleSource` and its tests), HELP.md line 118 and the file-view sentence at line 102, and `config/text/views/file.yml`'s `edit` words. `demo/`'s config copy, if it carries the keys, follows.

## Acceptance list

1. `typeOfFile` decides `html`, `image`, `pdf` by name and everything else by the bytes through `data/text-kind.ts`; cases: a `.py`, a `.npz` under a `.txt` name (binary, `other`), a UTF-8 file with accented letters (text), a file with a NUL at byte 100 (binary), an empty file (text).
2. A click on a text file in the Files tree opens a source tab; on an image, a PDF or a binary the file view; a browser spec proves `.py` and `.md` open in the source tab from the tree and a save of the `.py` lands on disk.
3. No extension list anywhere: `grep -rn 'editable_extensions\|viewable_extensions' src tests config demo HELP.md` prints nothing; the config-folder test's key table has neither.
4. The source tab of a read-only file shows the lock and the sentence and refuses keystrokes; the route case sets a file to mode 0444 and asserts `{ readonly: true }`; a save to it answers `readonly` and writes nothing.
5. The source route refuses a save over a binary file with `binary`, and writes nothing.
6. The preview tab: unit cases on the layout store (a preview open replaces the pane's preview instance in place; a pinned open does not; each of the four pinning events clears the flag; an old layout without the field loads); a browser spec: single click opens an italic tab, a second single click on another file replaces it, a double click pins, the next single click opens beside it.
7. The file view draws no text file: a text path handed to it opens the source tab; the file-view cases follow; the code window's language cases move under the source tab.
8. HELP.md's view table and the file sentence, `config/sources.yml`'s comment, DESIGN.md's views list; the catalog words `source.readonly`, `ui.preview_tab`; no new dependency.
9. The checks of `spec.md`, the narrowed ASCII gate included; every file under 1000 lines (`layout.svelte.ts` is near the cap: put the preview rule in `state/layout/preview.ts`).

## Decisions taken in this brief (each reversible, none silent)

1. The text rule is NUL-free and valid UTF-8 over the first 8 KB, the same rule on both sides through `data/text-kind.ts`; a file over `TEXT_LIMIT` is still opened cut, as the file view cut it.
2. Read-only is asked from the source route rather than carried on the file route's headers, so `server/files.ts` is untouched (Q21 runs beside this package and edits a comment there).
3. The preview flag is one optional field on the instance; the tab strip shows it in italics; four events pin.
4. The file view keeps html, image, pdf and the download; the code window becomes the source tab's read-only rendering.
