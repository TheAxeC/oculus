## The acceptance list

1. **The argument.** `src/server.ts` reads `--engine <dir>` from `process.argv` (the one flag; `--engine=<dir>` too; a relative path resolves against the current directory; an unknown flag is an error naming it) and passes the directory to `createServerContext`; without the flag the engine is `engineDir()` as today. A directory without a `config/` folder is an error at start naming the path, printed and exit 1, since a server over nothing is not a server; `config/local.yml` absent means the defaults, as today.
2. **No environment variable is read.** `localFile` and `configDir` lose their overrides: `localFile(engine)` is `<configDir(engine)>/local.yml` with `base` the engine, `configDir(engine)` is `<engine>/config`, always; `grep -rn 'process.env' src tests bin vite.config.ts` prints only what is not oculus's (the adapter's body limit set by `src/server.ts`, `HOME` and `PATH` in the browser layer's spawn), and the report quotes that grep whole. `README.md` line 9 says the server takes `--engine <dir>` and reads no environment variable; `HELP.md`'s running paragraph names the flag; DESIGN.md's line 124 ("a command-line argument, then `local.yml`, then a default") already describes it and gains the flag's name.
3. **The engine threads down from the context.** Every reader that calls `engineDir()` by default takes the engine it is given instead: a route passes `locals.server.engine` (as `api/memories` does) into the server function it calls, the pty options carry it, `writes.ts` `target(server)` reads `server.engine`, `data/index.ts`, `wallpaper.ts` and `files.ts` take it as a parameter from their callers, `hooks.server.ts` and `+page.server.ts` read it off the context they hold. After the change `grep -rn 'engineDir()' src` prints `src/server.ts` (the default when no flag is given) and `vite.config.ts`'s two uses (the dev server has no flag and runs over the checkout) and nothing else; the report quotes that grep whole. A test that today points `OCULUS_LOCAL` or `OCULUS_CONFIG` at a fixture passes a fixture engine directory (`<temp>/config/` with the files it needs, `local.yml` among them) to the function under test instead; no test sets or deletes a variable in `process.env`.
4. **The browser suite.** `tests/browser/serve.ts` builds `<temp>/engine/config/` (the copy `copyConfig` makes, the run's `local.yml` inside it) and spawns `node src/server.ts --engine <temp>/engine`, the `env` carrying `HOME` and `PATH` only; `tests/browser/layer.ts` and `present.spec.ts` lose their mentions. 1. `--engine` is the one flag, since the plan line names it and everything else the server needs is in that directory; a `--port` flag is not added, since `config/local.yml` holds the port.
