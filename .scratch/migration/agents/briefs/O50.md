## Decisions taken in this brief (each reversible, none silent)

1. The option lives in `config/defaults/sources.yml` (what the portfolio reads, which names the people registry) under the Settings heading `sources`, section `People`, as a top-level key, so the workspace file writes `settings: { self: <key> }` (ruling 204 names the key; the file and section are where it is listed).
2. The picker and the key name a person of the primary hub only (a record without `root`), since the workspace file's `primary` is "the hub folder whose .oculus/config.yml, records and state are the workspace's own" (`workspace-file.ts:46-50`), and another hub's build does not read the workspace's settings (`index.ts:587-601`). The choice draws each person by name and writes the key.
3. The wire field `Person.self` stays and is set from the setting, so the Person page and the portfolio chat read the setting through it and the apps' view of `people` (`docs/apps.md:380`) keeps its shape.
4. An empty `self` gives no finding: one setting cannot name two people, and an unset value is shown as the empty item in Settings; only a key naming no person is a finding.
5. The button takes the tag's place on the page and its words (`person.self`); pressing the pressed button writes nothing, and clearing `self` is done in Settings.
