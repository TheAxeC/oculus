## What to build

1. **Pages can be reordered.** `shell/PageStrip.svelte` (186 lines) draws the page tabs; today a page is added, renamed, switched and closed (`state/layout.svelte.ts` lines 192 to 241) and never moved. A page tab is dragged to a new position in the strip with the pointer, the way a view tab is dragged between panes (`state/drag.svelte.ts`: `start`, `move`, `hover`, `THRESHOLD` at line 53; read how `shell/PaneView.svelte` starts a tab drag), with the drop position shown while dragging and the order saved with the layout (`serialiseLayout`, `parseLayout` in `state/layout.ts` carry the pages list in order already; `checkPages` unchanged). The keyboard path: with the strip focused, Ctrl+Shift+Left and Ctrl+Shift+Right move the current page one place (the tree's shortcuts live where `pageShortcut` is, `layout.svelte.ts` line 241). The pure part `movePage(pages, id, index)` in `state/layout.ts` and the store's `movePage(id, index)` in `layout.svelte.ts`. `tests/state/layout.test.ts` is at 949 lines and is not extended: the new tests go into `tests/state/pages.test.ts` (the pure move: to the front, to the end, past the end clamps, an unknown id is a no-op, the current page stays current) and `tests/shell/pagestrip.test.ts` (the tabs carry the drag handle and the order the store gives). The browser spec `tests/browser/pages.spec.ts` gains a drag of the second page before the first through Playwright's mouse, which the orchestrator runs.

2. **Cross-link groups fold.** `views/shared/CrossLinks.svelte` (42 lines) draws every member of every type group; a venue targeted by six manuscripts and twenty ideas is a long list with nothing hidden. Each group is drawn as one `ToolButton` reading "N type" (the count and the type, as now) that opens its members below it on click and closes them on the next; closed by default; the open state local to the component (a card is short-lived). `views/collection/EntryCard.svelte` lines 242 to 260 draw the same groups on its own over `crossLinks()`; it uses the shared partial instead, which gains a `groups` prop for a caller that already holds `CrossGroup[]` beside the `projects` prop (one of the two is given). Tests: `tests/views/venues.test.ts`, `tests/views/programs.test.ts`, `tests/views/domains.test.ts`, `tests/views/data.test.ts` and `tests/views/collection.test.ts` assert the group control with its count and no member drawn in the server render (closed), and a unit render of `CrossLinks.svelte` opened shows the members.

3. **The concentrated venue explains itself.** `views/venues/VenueCard.svelte` marks a card `concentrated` (two or more active or manuscript projects target the venue, `state/venues.ts` `venueUsers`) with a violet border and nothing else. The card's head gets a `Tooltip` on the mark reading `col.ven_conc_tip` ("Two or more active or manuscript projects target this venue; the venue policy is to spread them"), and a chip with `col.ven_conc` ("concentrated") in the violet tone beside the quartile chip; the Venues view's facet row gains a legend chip with the same word and tooltip. The two keys join the `col` group of `config/text.yml`, which is at 999 lines: first remove the `fetch` group (lines 296 to 323, the cockpit's neofetch panel of the Focus board's terminal themes; nothing in `src` reads a `fetch.` key, checked 2026-09-12 with `grep -rn 'fetch\.' src`, and no package plans it), then add the two keys; the file ends under 1000 lines. `tests/views/venues.test.ts` asserts the chip and the legend.

4. **The rail flyout opens beside the rail, not inside it.** `ui/Menu.svelte` `place()` (line 103) sets the list's left edge at the button's right edge plus `GAP`; the button sits inside the 52 px rail column, so the list overlaps the rail's right edge and reads as oddly aligned. The list's left edge is the rail's right edge plus `GAP`: the primitive takes the containing rail's rect (the nearest ancestor with `data-rail`, which `shell/ActivityRail.svelte` sets on its root; add the attribute if absent) and falls back to the button's when there is none; the top stays level with the button's top in the upper half and its bottom in the lower half, as now. `tests/ui/primitives.test.ts` (or the Menu test the tree has; find it) asserts the style with a stubbed rect pair.
