## What to build

Under `tools/oculus/src/lib/themes/themes.css`, two blocks of token overrides and nothing else, in the style of the fourteen there:

- `body.vscode-dark-modern`: `--bg: #181818` (the side bar, activity bar and status bar of Dark Modern), `--panel: #1f1f1f` (its editor), `--ink: #cccccc`, `--muted: #9d9d9d`, `--line: #2b2b2b`, `--chip: #262626`, `--accent: #0078d4`, `--shadow: none`, and the palette hues of `body.dark` for `--c-red-bg`, `--c-red-s`, `--c-amber-bg`, `--c-amber-s` (the tints that must darken with the ground); every other hue inherits `:root`.
- `body.vscode-light-modern`: `--bg: #f8f8f8`, `--panel: #ffffff`, `--ink: #3b3b3b`, `--muted: #616161`, `--line: #e5e5e5`, `--chip: #f3f3f3`, `--accent: #005fb8`, `--shadow` as `:root`.
- Both are added to `appearance.yml`'s `themes` list after `dark`, as `{ name: vscode-dark-modern, class: vscode-dark-modern, label: "vscode dark modern" }` and the light one likewise; neither carries `rice`. `tests/contrast.test.ts` then measures them with the rest and must stay at zero pairs below 4.5:1; a pair that fails is reported with its ratio, and the fix is to the value in the block (these two blocks are oculus's own, so adjusting a chrome value is allowed here, unlike the fourteen ported ones), with the change named in the report.

Wallpaper, from `appearance.yml` `wallpaper:` (the keys O10c moved from `behavior.yml`: `dir`, `file`, `pick`, `dim`, `blur`, `themes`, `panel_opacity`, `popover_opacity`, `panel_blur`; `max_width` and `quality` are the cockpit's build-time downscale and are dropped from the key set, the report says so):

- `src/routes/api/wallpaper/+server.ts`: `GET` serves the chosen image: the files of `dir` (hub-relative; default `tools/cockpit/assets/wallpaper`, which is where the images sit today; the folder moves to `tools/oculus/assets/wallpaper` at migration step 8 and the state file carries that), filtered to `.jpg`, `.jpeg`, `.png`, `.webp`, sorted by name; `file` picks the first whose name contains the value, else `pick: first` gives the first and `pick: random` one chosen per server process (not per request). The response carries the right `Content-Type`, `Cache-Control: private, max-age=3600`, and the file's bytes streamed, never read whole into a string. The resolved path must be inside the resolved `dir` (`resolve` and a prefix check with the separator) or the response is 404; a `dir` outside the hub is refused at start with a stderr line and the route answers 404. No image, no `dir`, or an unreadable file: 404. `sameOrigin` of O11 is not available yet (O11 is later); the route checks `Sec-Fetch-Site` and `Origin` with O6's `allowedOrigin` from `server/socket.ts`.
- `src/lib/state/ui.svelte.ts` gains `wallpaper: boolean` (default from `appearance.wallpaper` being present and `themes` matching the current theme) and `unicode: boolean` (default false), both persisted under `oculus.ui.v1` with the theme and crt.
- `src/lib/shell/Workbench.svelte`: when `wallpaper` is on and the theme qualifies (`themes: rice` means only themes whose class string holds `rice`; `all` means every theme), the body gets the class `wall` and a `div.wallpaper` is rendered as the first child of the workbench: `position: fixed; inset: 0; z-index: -1; background: url(/api/wallpaper) center / cover no-repeat; filter: brightness(<1 - dim>) blur(<blur>px)`, the two numbers set as custom properties from the config. Under `body.wall` the pane boxes (`PaneView`'s `.pane`) and the rail paint `color-mix(in srgb, var(--panel) <panel_opacity as a percentage>, transparent)` with `backdrop-filter: blur(<panel_blur>px)`, and `Menu`'s list paints the same with `popover_opacity` (default three quarters of the way from `panel_opacity` to 1, the cockpit's rule, ported as a fact). The percentages reach the CSS as custom properties `--wall-panel`, `--wall-popover`, `--wall-blur` set on `documentElement` by `applyTheme`'s neighbour `applyWallpaper(document, config, on)` in `ui/theme.ts`. `tests/ui/colours.test.ts`'s allowance is widened by exactly one form, `color-mix(in srgb, var(--panel) var(--wall-panel), transparent)` and the `--wall-popover` twin, for `background` only, and the test's own fixture shows a `color-mix` with any other token still refused.
- The rail's control column gains two compact toggles beside the CRT one, drawn from the catalog: `ui.wallpaper` (`aria-pressed`, hidden when no wallpaper is configured or the theme does not qualify) and `ui.unicode`.

The glyph mode:

- `src/lib/state/text.ts`: `setAscii(map)` installs `glyphs.yml`'s `ascii:` map (a character to its stand-in) beside the glyph map, fed like the glyphs (page data at first load, the `config` channel afterwards); `setGlyphMode(mode: 'unicode' | 'ascii')`; `glyph(name)` returns the stand-in when the mode is `ascii` and the map has one for the character; `asciiOf(char)` for a character that came from data (a `status_legend` icon through `Chip`'s `icon`). The mode is `ascii` when the theme's class string holds `rice` and `unicode` is false, else `unicode`; `Workbench`'s theme effect sets it. `Glyph.svelte` and `Chip.svelte` read through those two functions and nothing else changes: the swap is at render, not a walk over the DOM.

Under `tools/oculus/tests/`:

- `routes/wallpaper.test.ts`: the route handler with a temporary directory as `dir`: the first file by name, `file` matching a substring, a `.txt` ignored, a path traversal in `file` (`../`) refused, an empty directory 404, a foreign `Origin` 403, the `Content-Type` per extension.
- `state/ui.test.ts`, extended: `wallpaper` and `unicode` persisted and defaulted.
- `state/text.test.ts` or `tests/text.test.ts`, extended: `glyph` under both modes, `asciiOf` with and without a stand-in.
- `ui/theme.test.ts`, extended: `applyWallpaper` sets the three custom properties from a config and clears them when off.
- `tests/contrast.test.ts` unchanged and green with seventeen themes; `tests/ui/colours.test.ts` with the one widened allowance and its negative fixture.

## Facts checked on the tree, 2026-09-10

- VS Code Dark Modern (the default since 2023): editor `#1f1f1f`, side bar, activity bar, status bar and title bar `#181818`, foreground `#cccccc`, borders `#2b2b2b`, focus and accent `#0078d4`. Light Modern: editor `#ffffff`, side bar `#f8f8f8`, foreground `#3b3b3b`, borders `#e5e5e5`, accent `#005fb8`. The values above are these, mapped onto oculus's chrome tokens; they are from memory of the theme files and the contrast test is the check on them.
- The cockpit's wallpaper images are 12 files in `tools/cockpit/assets/wallpaper/` (44 MB with the `.cache` folder of downscaled copies the build made; jpg and webp; the route ignores dotfiles and dotfolders and reads the originals). The cockpit inlined a downscaled base64 copy into its page; oculus serves the file, so no downscale step exists and `max_width` and `quality` have no meaning.
- The cockpit's `wallpaper` config today: `file: "wallhaven-83"` (which matches no file in the folder, so the cockpit fell back to the first), `pick: first`, `dim: 0.72`, `blur: 0`, `themes: rice`, `panel_opacity: 0.76`, `popover_opacity: 0.97`, `panel_blur: 2`.
- The cockpit's ASCII mode walked every text node of the page and swapped characters by regex, keeping the original per node; oculus renders a glyph in one component (`Glyph`) and a legend icon in one prop (`Chip`'s `icon`), so the swap is a lookup at render time and the DOM walk is not ported.
- `applyTheme` in `ui/theme.ts` sets the derived tokens on `documentElement.style`; the wallpaper's three properties go the same way.
