## What to build

1. **The type audit, every view.** For every file under `src/lib/views/` (views and partials) and the shell and ui files a view's text passes through (`Card`, `Chip`, `Disclosure`, `Intro`, `Table`, `Pane`, `Toolbar`, `ToolButton`, `Empty`, `Tabs`, `Menu`), every `font-size` rule is set to the token the cockpit gives the equivalent element in its CSS (the file and line cited in the report's table), and where the cockpit has no equivalent, to the role rule of Q4b (prose `--fs-md`; sub lines, meta rows, table cells and chip words `--fs-sm`; badges, counters, timestamps and meta chips `--fs-xs`; nothing in a view below `--fs-xs`). Within one view, two elements of the same role never differ. The report carries the whole table: file, element, cockpit rule, before, after; and lists every element left without a cockpit equivalent. `tests/views/type-scale.test.ts` grows to assert, per view file, the token of each role it draws.
2. **An app-wide text size.** A `textScale: number | null` in the ui store's appearance (null the default 1; steps of 0.1 from 0.7 to 1.6), applied by the workbench as `--text-scale` on the body, every `--fs-*` token of `tokens.css` becoming `calc(<px> * var(--text-scale, 1))`; three controls at the rail's foot beside the theme menu, smaller, larger, reset (the glyphs of the terminal's controls; new keys `app.text_smaller`, `app.text_larger`, `app.text_reset` in `config/text-oculus.yml`'s `app` group), in the same 34 px box as the other foot controls (Q4a's rule). The terminal's own control stays and is unchanged. Tests: `tests/state/ui.test.ts` (saved, bounded, null default), `tests/shell/rail.test.ts` (the three controls), `tests/ui/colours.test.ts` or `contrast.test.ts` (the tokens still resolve).
3. **The terminal reflows after a size step.** After `grid.options.fontSize` changes, xterm re-measures its cell on its next render, so a fit and a pty resize in the same frame use the old cell; the fix waits for the grid's render (`grid.onRender` once, or a second animation frame) before `refit` and `resized`, and the same for the theme change. Verified with a long line typed before and after a step. A unit test of the ordering if the stub grid allows one (`tests/views/sessions.test.ts` holds the terminal's stubs); otherwise the report says it is checked in Chrome only.

## Decisions taken in this brief (each reversible, none silent)

1. The text scale multiplies the tokens rather than replacing them, so every theme keeps its own scale and the terminal themes' smaller values are untouched.
2. The three foot controls, not a menu: a menu hides the step behind a click; the theme menu stays a menu.
3. Three new keys in `text-oculus.yml`'s `app` group, named above.
