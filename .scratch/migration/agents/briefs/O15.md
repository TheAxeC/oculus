# Brief: O15, session writes and the cards

Read `../spec.md` first; it governs this package unchanged. Then `tools/oculus/DESIGN.md`, "Sessions" under Layer 2, "Auth", "Layer 3, view", and step 5 of the migration order ("dismissal and pinning through `api/write`"). O14 gave the six views and the dismiss control; this package completes the write side of sessions (pinning a session to an area, renaming it) and puts sessions on the project cards, so the portfolio and the sessions meet on one screen.

## What to build

Under `tools/oculus/src/lib/server/`:

- `writes.ts`, extended: `kind: 'session'` accepts `{ id, hidden?, area?, title? }`; `hidden` goes through O12's `setHidden`; `area` (an absolute directory or empty to unpin) and `title` (a string or empty to clear) go through a new `setOverride(id, fields, path)` in `server/sessions/overrides.ts` that writes only the named keys of the session's entry in `~/.oculus/sessions.json`, keeps every other key, removes an emptied entry, and rejects an `area` that is not an absolute path. Every refusal is a `refused` entry, never a throw; the route stays token-guarded and same-origin as O11 made it.

Under `tools/oculus/src/lib/views/sessions/`:

- `SessionDetail.svelte`, extended: under the key-value block, a "pin" row: a `Select` of the session's workspace's known areas (the project folders under that workspace, from the `workspaces` payload's areas with `known: true`) plus "(scored)" to unpin, and a `TextInput` for the title override with a clear control; both post through `state/writes.svelte.ts` and the row shows the outcome. A pinned session shows the pin mark the list already draws (`pinned` on the record).

Under `tools/oculus/src/lib/views/Projects.svelte` (the card):

- A sessions row on every card whose project has sessions: `sessionsForProject(folder)` from O14's selectors gives the records whose `cwd` or `area` lies in the project's absolute folder; the row shows a count chip (`sessions.card_n`, `card_one`) and a live chip (`sessions.card_live`) in the `working` tone when any is live, then one chip per session carrying its tool mark (`claude` or `codex`, as the list rows of O14 draw it), its state dot and its title; a click on one selects it (`select(id)` from `state/selection.svelte.ts`) and opens `session-detail` in the panel if no session view is open (`openView`). The board gains one more facet menu beside category, year, domain and the rest, "Sessions", whose values are `live` (a session running now), `recent` (a session in the two-day window, none live) and `none`, so the board can be narrowed to the projects being worked on; like every facet it is offered only when at least two of its values occur.

Under `tools/oculus/tests/`:

- `server/overrides.test.ts`: `setOverride` on a temporary file: area set, area cleared, title set, title cleared, both, an emptied entry removed, other entries untouched, a relative area refused, a corrupt file replaced by a fresh map holding only the new entry (the cockpit's rule for `setHidden`).
- `routes/write.test.ts`, extended: the three session fields through the route.
- `views/sessions.test.ts`, extended: the pin row rendered with the workspace's known areas; `views/projects.test.ts`, extended: the sessions row on a card with two sessions, one live; the sessions facet.

## Facts checked on the tree, 2026-09-10

- The cockpit's overrides file shape is `{ sessions: { <id>: { hidden?: true, area?: string, title?: string } } }` and its grouping already honours `area` and `title` (O12 ported both, with the 24 cases of `test_sessions_group.py`, five of which are about overrides).
- `text.js.sessions` holds `card_n: "{0} sessions"`, `card_one: "1 session"`, `card_live: "{0} live"`.
- A project's absolute folder is `join(hub, project.folder)`; O14's `sessionsForProject` is the join.
