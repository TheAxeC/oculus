## What to build

1. **One menu over the whole Transcript.** A right-click anywhere in the list of turns, on a person's turn, a tool row, a head or an answer, offers the prose menu: Copy while text is selected in the list, whichever row the selection started in, and Copy Image and Open Image over an image. With no selection and no image nothing opens, as elsewhere. The rows and their styles move out of `TranscriptBody.svelte` to a new `transcript/TurnList.svelte`, which brings the body under 520 lines; it holds the `.turns` box, `roleLabel`, the row markup and one `ContextMenu` around the `.turns` box, outside it, since `reader-place.ts` reads the box's children as one per row. The box stays reachable by the body (a bindable prop). `Markdown.svelte` gets a boolean prop `plain`, default false, that draws it without its own menu, so every other use stays as it is, and the Transcript passes it so that one right-click opens one menu. The read of the selection and the image is shared with `Markdown.svelte`, not copied: move `pointed`'s read to `prose-menu.ts`, taking the box the selection must start in as an argument. `proseAt` keeps its signature and `Document.svelte` does not change. An answer's code-block Copy control and its links keep working. The comments at `Markdown.svelte:30-32`, `TranscriptBody.svelte:33-35` and `prose-menu.ts:1-3` say what is now true. The right-click is heard inside the `.turns` box only: the `.older` line and the space under the last row open nothing.

2. **A pressed run stays as pressed when the body is drawn anew.** The choices no longer live and die with the body. `tabSession` (`tab-session.svelte.ts`), made once per tab in `Terminal.svelte`, owns the `SvelteMap` of choices and hands it to `TranscriptBody` as a prop. It is emptied when the tab's target becomes another session or agent, and kept while the target is null, so a tab that returns to the same target finds them. `TranscriptBody` no longer clears the choices; it still clears `docs`. `runKey` becomes the id of the run's first call; with an empty id, which every Codex call has, that call's stamp, name and summary. It holds no list index, so the key survives a new first read of a run wholly inside that read. `movedRun` keeps its job. The head comment of `turn-rows.ts` and the comments in `TranscriptBody.svelte` and `TurnRun.svelte` are rewritten to what is now true.

3. **The cycle.** `NestedCards.svelte` no longer imports `Cards.svelte` at run time. `Cards.svelte` passes itself as a prop: `import Self from './Cards.svelte'`, and `<NestedCards Cards={Self} ... />`. `NestedCards` takes the prop, typed `Cards: typeof CardsView` with `import type CardsView from './Cards.svelte'`, uses `CardsView` at `ComponentProps<typeof CardsView>`, and draws the prop where it drew `<Cards>`. The type must not be imported under the name `Cards`: `svelte-check` refuses that as a type referring to itself. What Settings draws does not change. `tests/checks/imports/cycles.test.ts` passes with no edit to it or to `graph.ts`.

4. **Help.** `docs/HELP.md` gains one sentence after line 457 saying that a right-click on selected text in Transcript offers Copy. Regenerate `docs/diagrams` when `npm run diagrams` changes them.

## Cases

- Text selected in a person's turn, right-click on it: the menu offers Copy, and Copy puts that text on the clipboard.
- Text selected on a call's row of an open run, right-click on it: the same.
- Selection from a person's turn into the answer below it, right-click on the answer: one menu, Copy, with the whole selection.
- Text selected in an answer: one menu, not two.
- No selection, right-click on a blank part of a person's turn: nothing opens and no browser menu. On a word, macOS Chromium may select it first, and the menu then offers Copy as an answer does.
- A right-click with a selection on the `.older` line or under the last row: nothing opens.
- The selection changes, or turns arrive, under an open menu: Copy gives the text read at the right-click.
- The menu key on a focused control in the list, a run's press or a code block's Copy: Copy with a selection, nothing without.
- A right-click on an image in an answer: Copy Image, as before.
- A right-click in the Doc view's Markdown: its menu as before.
- Press a run open, press Live, press Transcript: the run is open, in the view the body drew anew, after its new first read.
- A session's terminal ends with the Transcript showing and a run pressed: the run stays as pressed.
- A run cut by a new first read: reads as never pressed until older turns grow it, then finds its press again.
- A tab moved to another pane, a page switch, a reload: reads as never pressed.
- The agent's transcript tab: the menu and presses work; moving to another agent empties the choices.
- Press a run, then the tab reads another session and comes back: the run reads as never pressed.
- Press a run closed that holds a failed call, Live, Transcript: closed.
- Two tabs on one session: a press in one does not change the other.
- A run grown at its head by a read of older turns keeps its press (`movedRun`).
- Two Codex runs, empty ids: keys differ by stamp, name or summary, read at `file:line`.

- Settings, a list inside a card inside a card: `svelte-check` passes with the prop's type, and nested cards draw (the look at landing).

## Decisions taken in this brief (each reversible, none silent)

1. The menu is one menu over the list, not a menu added to each person's turn and tool row, since a selection crosses rows and nested menus would open twice. Its items are the prose menu's, with no new word.
2. The choices are held by the tab, not in the transcripts store: the store drops a transcript when its last viewer stops, which is what happens here. They last while the tab's `Terminal.svelte` stays mounted; a move to another pane, a page switch or a reload reads as never pressed.
3. The reader's scroll place across a redraw of the body is not held; the step line names the pressed run. The reader lands at the foot, as on any first draw.
4. A self-import in `Cards.svelte` passed as a prop rather than a merge of the two components, since `NestedCards` has its own markup and style.
