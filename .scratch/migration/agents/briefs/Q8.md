## How each item lives in oculus (the three layers, the data live)

Every item reads the portfolio snapshot the watcher publishes on the `portfolio` channel (`server/watch/portfolio.ts` watches the scan tiers recursively at line 104 and every collection file), so nothing here fetches; a write goes through `POST /api/write` and comes back through the watcher.

1. **Folders without a manifest (ghosts).** Data layer: `data/sources/manifests.ts` skips a folder with no `project.yml` (`hasManifest` at line 38, used by the tier walk); it gains a ghost record instead, `{ id: <folder name>, title: <name without its prefix>, tier, type: <the scan rule's type>, ghost: true }` with every other field empty, the way the cockpit's `discover.py` `load_project` does at lines 78 to 92 (`_ghost: True`; a manifest that fails to parse is not a ghost, it is a finding, as today). The model (`data/model-entities.ts` `Project`) gains `ghost: boolean`. State: a ghost is counted by the boards' totals and splits as the cockpit counts it (a `type` from the rule). View: the card draws the cockpit's badge (`cards.no_manifest` with the `warn` glyph, tooltip `cards.ghost_badge_tip`, `render/cards.py` line 54) and offers no manifest edit, no pin, no chat (`helpers.py` lines 81 to 90 skip them for a ghost); the message `cards.ghostmsg` is the card's body. The watcher already republishes when a folder appears.
2. **The status line: waiting on, under review at, blocked.** State: `state/board.ts` or `state/focus.ts` gains `waitingLine(project, venues, collaborators)` with the cockpit's precedence (`helpers.py` `_waiting_on`, lines 102 to 117): the manifest's `waiting-on` list (the model's `waitingOn`, each id resolved to the collaborator's name from the snapshot's collaborations registry, else the id as written) as `helpers.waiting_on`; else the `submitted` chip as `helpers.under_review_at` with the venue's short name (`venue_id` through the venues registry) or `helpers.under_review_unset`; else the `blocked` chip as `helpers.blocked_external`; else nothing. View: `views/shared/ProjectCard.svelte` draws it as the cockpit's `.statusline` (05-lists.css line 30, `--fs-sm`) under the chips, with the kind (`people`, `review`, `blocked`) as a class.
3. **Copy context, open folder.** Copy context: a pure `contextText(project, snapshot)` in state (the cockpit's client builds it in `05-leads.js` or `08-entryform.js`, grep `ctxcopy` under `tools/cockpit/assets/js/cockpit/`; the same fields: title, id, type, status chips, venue, deadline, eli5, results, next, latest, the folder) copied to the clipboard by a `ToolButton` on the card (`helpers.copy_context`, `copy_context_tip`), with a transient "copied" state on the button. Open folder: the cockpit's `file://` link (`helpers.py` line 91) cannot work from a served page; oculus adds a server action `POST /api/open` `{ path }` opening the folder on the machine oculus runs on (`open` on macOS, the folder checked to be under the hub or a configured root, 403 otherwise, the token required as every write), and the card's `helpers.folder` button calls it. This action is a user-visible shape and is named here.
4. **The human-only and public marks on document links.** The model's `DocFlag` (`model-entities.ts` line 179) says which documents a project has; the cockpit marks a link `human` (README, the private prep) or `public` (PRESENT.md, `code/README.md`) from the doc's own rule (`helpers.py` lines 56 to 62 read `ln["human"]` and `ln["public"]`, set where `_links` is built: grep `"human"` in `tools/cockpit/src/cockpit/`). Data: `data/sources/docs.ts` sets `human` and `public` on each `DocFlag` by the same rule; view: the card's document links carry the class and the tooltip (`helpers.doc_human_tip`, `doc_public_tip`).
5. **The cross-link groups, the cockpit's way.** `views/shared/CrossLinks.svelte` groups by project type today; the cockpit groups into three: work (active projects, `helpers.xlink_active`, the `active` glyph, a warn mark when any is blocked), published (`helpers.xlink_published`, the `published` glyph), ideas (`helpers.xlink_idea` for one, `xlink_ideas` for more, the `idea` glyph), `helpers.py` lines 395 to 403 (`_xlink_groups`). State: `state/collection.ts` `groupProjects` returns those three groups by the cockpit's rule (read `_xlink_groups` for which types and chips fall where); the disclosure chips of Q4b keep their look; the five view tests that assert the groups follow.
6. **The Focus board's three collection lanes.** The cockpit draws, under the cards group (`render/focus.py` lines 340 to 362): a Funding lane with the entries stacked by stage (`FUND_STAGES` in `focus.py`: the stages, their colours and the statuses in each; read it), a Job applications lane (the `applications` collection's `active` entries), a Teaching and supervision lane (the `education` collection's `ongoing` entries), each entry drawn as a small card (`cards_for`) with its glyph (`coin`, `scout`, `teaching`), the lane's name and sub line from `focus.funding_lane`, `funding_sub`, `jobs_lane`, `jobs_sub`, `teaching_lane`, `teaching_sub`, the lane's colour as its tone bar. State: `state/focus.ts` gains `collectionLanes(snapshot, config)` (pure); view: `views/focus/Lanes.svelte` draws them after the project lanes, an entry opening its collection view with the reveal state of O25f. The stage colours and the statuses per stage are config: they go into `config/behavior.yml` as `funding_stages` (a list of `{ label, color, statuses }`, named here) if `FUND_STAGES` is a literal in the cockpit; if the cockpit reads them from its config, the same key.
7. **The "manifests behind their docs" line.** The cockpit's Command center lists, under Needs attention, the active and manuscript projects whose manifest is older than a document in the folder by at least `stale_lag_days` (`command_center.py` lines 425 to 436: `N manifests behind their docs - refresh`, the four most behind named as goto links, `cc.more` for the rest). oculus's snapshot already carries the lag per project (`data/sources/docs.ts` line 104, the card's stale badge reads it); state: the ticker's attention group (`state/focus.ts` `ticker`) gains the line; view: `views/focus/CommandCenter.svelte` draws it with the names as project openers.
8. **The "not on the board" hint.** Under the ideas backlog the cockpit writes `focus.hint_count` (the number of active or manuscript projects with no `focus:`) as a goto link to the first of them, followed by `focus.hint_tail` (`focus.py` lines 263 to 265). `state/focus.ts` `unplaced` exists (line 347); view: `views/focus/Lanes.svelte` draws the hint after the backlog.
9. **Chat about a project.** Not here: Q11.

## Decisions taken in this brief (each reversible, none silent)

1. `POST /api/open` (item 3) and `funding_stages` in `config/behavior.yml` (item 6, if the cockpit holds them as a literal) are the two user-visible shapes; both are named above.
2. A ghost project's `id` is its folder name; it opens no project tab (there is no manifest to show), the card's title opens the folder's README when one exists, as a document tab.
3. The cross-link regrouping (item 5) replaces the by-type grouping; the type is still shown as each member's chip.
