# Brief: Q23, the lead dismiss as a feed status

Read `../spec.md` first, its section "The principles every package is judged on" and its amendment of 2026-09-16 (the port rule) above all. The plan's Q23 line (Axel, 2026-09-16 00:35): a dismissed lead is a `dismissed` value of the feed's own `status` select, written through the existing `feed-field` write, recorded in the change log with its undo, the show-dismissed toggle reading it; `leadsDismissed` leaves the ui store. ## How it lives in oculus (the three layers, the data live)

1. **The vocabulary.** `feeds/position-leads.yml`'s `status` select gains `dismissed` as a fourth option and the header comment says the dismiss control sets it; the file is the hub's and is edited for that one line (the orchestrator's own commit carries the feed file; you edit it in the worktree like any other file of the package). The cockpit's `data/cockpit.yml` and skill know nothing of the value and need nothing: `status` is free text to them.
2. **The write.** The card's dismiss control writes `status: dismissed` through `writeFeedField('leads', title, 'status', 'dismissed')`, and the reopen control writes `open` back; both are one `feed-field` write each, so the change log records them and History offers the undo with no new kind. No new endpoint, no new body.
3. **The state.** `visibleLeads(entries, showDismissed)` reads `entry.status === 'dismissed'` instead of a list; `leadsDismissed` and `setLeadDismissed` leave `state/ui.svelte.ts` and its stored record (the ui store's version bumps so an old record's field is dropped on load, the way `loadUi` already discards another version). `isClosed` counts `dismissed` as closed. `splitLeads` unchanged.
4. **The view.** `Leads.svelte` derives the dismissed count from the entries; the toggle stays in the instance state as today; `LeadCard.svelte`'s `dismissed` prop reads the status; the control's words stay (`actions.decline_tip` and `actions.reopen` were Q9's nearest keys: give the two controls their own keys `leads.dismiss` and `leads.dismiss_tip`, `leads.reopen` and `leads.reopen_tip`, since a Decline action sits beside them and the two must not share a word). The status tag on a dismissed card reads `dismissed` in the grey tone like the other closed statuses.
5. **The lists that count leads.** Every reader that counts open leads (the rail badge through `nav_live`, the Focus board's lane, the ticker) treats `dismissed` as it treats `declined`: find them with `grep -rn "declined" src/lib/state src/lib/views` and add the word beside it where a status list is a literal, or through one `CLOSED` constant in `state/leads.ts` read by all of them.

## Decisions taken in this brief (each reversible, none silent)

1. The value is `dismissed`, beside `declined`: declined is an application you made and withdrew or lost; dismissed is a lead you never pursued.
2. No `dismissed_on` date: the change log holds when it happened.
3. The toggle stays per pane (instance state), since which pane shows the dismissed ones is a reader's choice, not a fact about the leads.
