# Working conventions for oculus

This repository holds oculus, the workbench that reads a research hub and shows it in one app. These rules bind every session and every agent that works on it, whichever runner and model reads them; `AGENTS.md` is a symlink to this file, so every runner reads the same text. Whatever user-level configuration the runner loads is authoritative where it overlaps with this file.

For orientation read `README.md` (how to run and check oculus) and `docs/HELP.md` (what each view, setting and file does, as a user meets it).

## Git

- **Committing is allowed; pushing is never done.** A commit or a pull request carries no attribution to a tool or a model of any kind: no `Co-Authored-By` trailer, no vendor or model name (Claude, anthropic, Codex, OpenAI, GPT), no robot emoji. This overrides any default trailer the runner adds.
- **The message shape** is a capitalised imperative subject (with a `refactor:` prefix where it fits), a blank line, then `- Verb ...` bullets, the last bullet the plan booking when there is one.
- **Stage by explicit path.** `git add -A` is never run on main.
- **The ask list stays.** `merge`, `rebase`, `restore`, `push` and `reset --hard` are on the ask list of the runner's permission file (`.claude/settings.local.json` for Claude Code, `.codex/rules/` for Codex) and stay there.
- **A branch lives only as long as its worktree.** A worktree's branch is a local branch removed with the worktree; nothing else creates a branch, and a diff kept for the record is a patch file. Reading git state is always fine.

## Reports and claims

- **A report states the end state.** It opens with what is not done, then a done and not done ledger naming the command that proves each row. A wrong turn taken and backed out inside the task is left out, since it changed nothing about the outcome. Partial work is never presented as complete: a request for A and B with only B built is a failure report, and its first line says so. A task too large to finish is named as such before it starts, and the tractable half is never handed in for the whole.
- **No claim about state without a command in the same turn.** A claim about state is any sentence about what exists, what is done, what is booked, how many there are, what a file says, what a test did or whether something passed. Each one comes from a command run in the same turn, and the message names that command or quotes its output; otherwise the sentence is not written, or it says "not verified" in those words. Memory, inference, an agent's report and an earlier message are leads, re-run or re-read before they are repeated; cite the source as `file:line`. A question of the shape "is everything X", "how many X" or "did you do X" is answered by running the check that enumerates X. A claim that a defect is fixed names the check that fails without the fix. Nothing lifts this rule, a request to hurry included. A judgment, estimate or recommendation is not a claim about state and is given directly, with one clause saying it is a judgment.
- **A risk named is a task owned.** Writing "this could break X" or "this needs measuring" obliges the same turn to fix it or to state plainly that it is unfixed and unverified. The check that verifies a risk is one that would fail if the risk were real; a green result from a check that does not exercise it reads as an all-clear and is worse than none. The repository's own gates (`npm run test:quick`, `npm run check`, `npm test`, the verification commands of the running plan) come before an ad hoc probe.
- **A test never asserts that a known defect still happens**, since it fails the day the defect is fixed and keeps the suite green over the bug. Such a defect is printed loudly and asserted nothing about.
- **A check is never loosened to pass.** A threshold, a tolerance or a predicate is never widened to make a check green, above all in committed code; a check that passes only after its rule is widened is a finding to report. A green result says in the same breath what it does not cover.
- **Problems are reported unprompted.** After any change, the report gives every limitation, sharp edge, implicit decision, deferred item and compromise. A limitation that breaks a common use is a defect to fix or to raise, never a footnote.

## Working on the code

- **A named thing is its whole.** "Fix the view" is its markup, its state, its strings and its tests; "the config" is every config file; "the plan" is every ledger file. Before a fix is called done, the files the named thing consists of are listed and each one is checked against the change.
- **No silent design decisions.** A user-visible choice is raised as an explicit decision before it is built: a config key or vocabulary, a file or folder convention, a wire format or socket protocol, the public shape of a tool or a view. An internal, reversible detail is chosen freely and listed when asked.
- **Never the lazy option.** The lazy option costs less now and leaves the work undone: a booking instead of a fix, a later step instead of this step, a sentence in a report instead of a change in the code, a narrower reading of the request than the request. When two ways differ only in what they cost to carry out, the cheaper one is not a reason; the one that ends the cause is taken. A step's path list is widened rather than work split out of it, and a booking is made only for a different concern or for work blocked by something in flight, with the report saying which. The same holds for every agent: a shortcut is a finding, and a report that defers work inside its scope is sent back.
- **Nothing inside a task is left undone.** A miss inside the request is fixed before the work is called done. A fix of a defect in delivered work needs no yes. What does go to the user (a user-visible shape nobody named, a premise found wrong, a rule clash, a red check no fix within the plan covers) is booked in the plan's ledger or state file when it is raised and repeated in every report until it is ruled on.
- **Credentials are the user's.** Credentials and tokens, the ones oculus reads for an account included, are never printed, quoted in a report or a commit, or copied into a project folder.
- **Filter, then rank.** An option that breaks a rule is dropped before the options are written down; it is never put to the user as a choice.
- **Rule clashes are raised before work goes on.** When two established rules, decisions or design principles collide, or a requested change clashes with an existing invariant, the clash is named and the user decides it; no side is picked silently and no special case is built around it.
- **No question boxes.** The session recommends and proceeds, and a question for the user is written as plain text in the message, with its options, their pros and cons and one recommendation. Work stops only where the decision is the user's: a user-visible shape nothing names, a premise found wrong, a red check no fix within the plan covers, a clash between two established rules or decisions.
- **A question is answered by the session itself.** It reads the code, the files and the data, and runs the commands that show the answer; no diagnosis agent or `/diagnose` run is used for it. The answer comes first in the message that ends the turn, every question in the message is answered in order, and a question never stops work already asked for.
- **Show code.** When the subject is code, the reply leads with the smallest real snippet (TypeScript, Svelte, YAML, shell) that shows the construct, the call, or the before and after, with prose kept short beside it.
- **References are not justifications.** Prior art, the tools oculus replaced included, is a cautionary reference for what was slow, awkward or wrong. A design choice is justified from oculus's own goals and decisions, citing the goal or decision it serves; when a choice matches prior art, the reason is still given on oculus's terms.

## Plans

- **A plan runs from its ledger, never from memory.** A plan with several steps lives under `.scratch/<feature>/`, tracked in git: `plan.md` (the steps in order, each ticked only after its verification commands ran and its whole diff was read), `orchestrator-state.md` (the standing demands, the verification commands, the current position, rewritten at every step) and `agents/` (the standing spec every step runs under, `briefs/` with one brief per step, `reviews/`). After a context compaction, the state file is read first, then the ledger, then the tail of the transcript.
- **The plan skills live in Ordo.** `plan`, `spec`, `refute`, `land`, `ordo-help` and `plan-orchestration` come from the Ordo repository, linked into the runner's skills folder; this repository keeps no copy. They read their project settings from `.agents/plan.yaml`, and the "Launching a builder" section of `plan-orchestration` says how a worker is started on each runner.
- **One step, one commit, landed by cherry-pick.** An agent works in a git worktree under `.agents/worktrees/` at main's head, never runs a git command and never edits the plan files. Its result reaches main only by the orchestrator's `git cherry-pick` after the diff was read, as one commit, so undoing a step is `git revert` of one commit.

## Writing

These hold for every file authored here (Markdown, YAML, TypeScript, Svelte, CSS, shell, `.gitignore`), for code comments and for messages.

- **No hard wrapping in prose.** A paragraph or a bullet is one line, soft-wrapped by the editor. Hard breaks go only between paragraphs and list items, at headings, in tables and inside code blocks. A code comment is the exception: it is wrapped as a whole paragraph at 100 columns, the `printWidth` of `.prettierrc`, so no line inside a sentence ends short.
- **ASCII only.** The ellipsis is `...`. An em or en dash in prose is reworded away with a comma, colon, semicolon, parentheses or a new sentence, and a spaced hyphen, `--` or `---` standing in for one is the same fault; `-` stays inside a compound word, a number range and a quoted title. Arrows become a word or ASCII `->` / `=>`; box-drawing characters become `-` or `=`; curly quotes become straight quotes; a non-breaking space becomes a space; a middle-dot separator becomes ` | `. Emoji and glyphs live only in the catalogs that declare them (`config/catalogs/glyphs.yml`, `config/catalogs/unimath.yml`), and code names a glyph from there. Accented letters in names stay. The check is the repository's ASCII gate, the perl command `ASCII_GATE` of `tests/tiers/run.mjs`, which `npm run test:quick` and `npm run test:landing` run over `src`, `tests` and `config`: it passes an accented letter in a name under `config/` and prints every other line that holds a byte outside printable ASCII.
- **Plain prose.** State the fact and stop: no flourishes, no punchy one-line summaries, no "not X, it's Y" contrasts, no filler words (leverage, comprehensive, crucial, showcase, moreover), no chatbot framing ("Great question", "Would you like me to..."). Once a thing has a name, that name is used every time; a list has as many items as there are. Name the actual function, file and line.
- **No history in a rule file or a comment.** This file, a spec, a skill and any rules page state the rule and at most one clause of why: no dates, no incidents, no "violated before". A code comment says what the code does and why, never when it was written, which step or session wrote it, or which bug or reverted attempt came before it. Dates and incidents belong in a log: a plan's ledger and state file, a commit message.
- **YAML parses after every write.** A YAML file is loaded with `yaml.safe_load` after it is changed; in a double-quoted scalar every backslash is doubled.
