# oculus

The private dashboard over the research portfolio. `DESIGN.md` is what it is measured against; this file is how to run it.

Install once, with Node 24.15 or later on the 24 line (or Node 26 or later) and npm 11 (`nvm install 24` gives both): `npm ci` from the committed lockfile, or `npm install` to regenerate it. The Status view's line counts also need Perl on the PATH to run cloc; macOS and most Linux systems carry it. `npm ci` refuses a Node outside `^24.15.0 || >=26.0.0` (Node 24.15 or later on the 24 line, or Node 26 or later, which every installed package accepts) before it installs anything. Each start (`npm run dev`, `npm run preview`, `npm run app`, `node src/server.ts` and `oculus.app`) first checks the Node version (the app runs on Electron's own Node and leaves it out), that the installed packages are the ones `package-lock.json` lists, the programs `git`, `tmux`, `perl` and the Claude CLI, and says what is missing with its fix; a Node outside that range and packages that do not match the lockfile end the start, and a missing program is named while oculus starts anyway (`npm run app` runs the Node and package part before Electron starts, and the app checks the programs over its own engine). A start with no open workspace, or with a workspace that lists no hub, is no lack: the views are empty and the Files view says to add a folder.

Develop with `npm run dev`, which hot-reloads and serves on 127.0.0.1 at the port the primary hub's `.oculus/local.yml` names (8790 by default), the same address as the built server, so the Claude Code hooks that post to it reach whichever is running; the two cannot run at once. In development a component's stylesheet is always served compiled, whichever the page asks for first. For the built server, run the build listed below, then `node src/server.ts`, or `npm run preview` to serve the build. The server runs on this machine only, bound to the loopback address. Port 8787 belongs to the cockpit and is never used.

The native app: `npm run app` starts oculus in its own window (Electron, with the server as a utility process; the first run fetches Electron's binary). It takes the single-instance lock, builds the checkout's server into `build-app/` and `.svelte-kit-app/` so it always serves the checkout's code, starts the server on the port the open workspace's primary hub names in its `.oculus/local.yml` (8790 without one) and opens the window, and it takes the same `--engine <dir>`. `--remote-debugging-port=<n>` is Chromium's own switch and the only way the app opens a debugging port. A port that another program holds is named in a dialog, and a port that an oculus holds is offered as a window onto that server. `npm run app:package` writes `oculus.app` (bundle id `local.research.oculus`, ad hoc signed) to `~/Applications`, or to the folder `--out <dir>` names; the bundle imports the checkout's `src/desktop/main.ts`, so it runs the checkout's code and is made again only when Electron's version changes, and it runs no build and reads `build-app/`, so it needs one `npm run app` from the checkout first. The window state is kept in `~/.oculus/window.json`, and the page's storage under `~/Library/Application Support/oculus`. The [manual](HELP.md#the-window) describes what the app adds to the page.

The built server takes three arguments. `--engine <dir>` (`--engine=<dir>` too) names the directory that holds the `config/` folder it reads and writes and the `HELP.md` the Help view draws; a relative path is resolved against the directory the command was typed in. Without it the engine is `tools/oculus` itself, which is what a plain `node src/server.ts` over the checkout means. `--default-port <n>` (`--default-port=<n>` too) is a whole port number from 1 to 65535: the port the server takes while the primary hub's `.oculus/local.yml` names none, which the app passes so that the port it expects is the port the server takes. `--handler <file>` (`--handler=<file>` too) names the built handler the server loads, resolved against the directory the command was typed in like `--engine`; the app passes `build-app/handler.js`, and without it the server loads `build/handler.js`, the build of `npm run build`. A directory holding no `config/` and a `--handler` that names no file are refused at start, and any other argument is refused naming it. The development server runs over the checkout and takes no argument. The app hands the server the environment of the login shell when the app is started from the Dock, and the inherited environment when it is started from a terminal or when the shell does not answer within 10 seconds, which a dialog says once. The app looks the programs up in the environment it hands the server and names the ones it does not find in the same sheet on the first window, with Continue and Quit.

Which folders oculus serves is the open workspace, a file `.oculus/workspaces/<name>.yml` of a hub that lists `folders` (each `{ name, path }`) and an optional `primary`; the open workspace and the recent list are kept in `~/.oculus/workspace.json`, which only oculus writes. A start with no state opens an unsaved workspace with no folders. A listed folder that holds `.oculus/config/` is a hub. Machine-local values live in each hub's `.oculus/local.yml`, gitignored and optional, read again whenever it changes and never merged with the rest of the hub's configuration: the rows of `accounts`, `calendars` and `mail` are joined over every hub of the workspace, and every other key is one value per oculus read from the primary hub's file alone. `port` is an integer, defaulting to 8790; `claude_bin` names the Claude CLI that the chat terminals, the worktree agents, the usage refresh, the update tasks, the prompts of schedules and the suggested commit messages run, defaulting to `claude` on PATH. The server reads no environment variable of its own except the operating system's `SHELL`, the command a plain terminal starts (`/bin/zsh` when the environment names none): a run that must not touch the checkout's configuration is started over a copy with `--engine`.

## Running it and checking it

The checks run from `tools/oculus`:

- `npm test` runs the unit suite over the data layer, the server, the stores, the shell and the views, leaving out the tree checks and the tests tagged slow; a file named `*.client.test.ts` runs in Svelte's client runtime with no DOM, which is where an effect's teardown runs, and every other file runs against Svelte's server build.
- `npm run test:checks` runs every tree check under `tests/checks`, the ones tagged slow included (comment width, file size, duplication, import order and the rest) with no time limit.
- `npm run test:slow` runs the tests tagged slow outside `tests/checks` (`// @module-tag slow` in a test file's head comment tags the file, `{ tags: ['slow'] }` a test or a describe), which start a process, wait on a real timer, open a socket or take 100 ms or more in a run of their own.
- `npm run check` runs the TypeScript and Svelte check over every file (svelte-check).
- `npm run build` builds the server.
- `npm run lint` and `npm run format:check` hold the source to its conventions: Prettier with four-space indentation, which `npm run format` applies.
- `npm run diagrams` redraws the diagrams of `docs/diagrams/` from the source, and the tree check `tests/checks/diagrams/diagrams.test.ts`, one of those `npm run test:checks` runs, fails while a committed diagram differs from what the source gives now.

## Two Claude accounts

Claude Code keeps its login, settings and session history in one folder, `~/.claude` by default; the environment variable `CLAUDE_CONFIG_DIR` points it at another folder, and the login stored for that folder is its own Keychain entry. Axel's second account (the university address, Max 5x) lives in `~/.claude-work`, whose `CLAUDE.md`, `rules`, `settings.json` and `projects` are symlinks to `~/.claude`'s, so both accounts share the rules, the settings, the transcripts and the memory, and only the login and the app state differ.

The Status view prints the Claude Code hooks block that posts to oculus, which goes in `~/.claude/settings.json`, the settings file both accounts read through that symlink, so a session started in any folder tells oculus when it wants you. A block in the hub's own `.claude/settings.local.json` is not needed once it is there.

Start Claude Code on the second account from the hub root:

```sh
cd ~/workspace/research-hub
CLAUDE_CONFIG_DIR=~/.claude-work claude
```

Resume a session there, whichever account it started on, since the transcripts are shared:

```sh
CLAUDE_CONFIG_DIR=~/.claude-work claude --resume <session-id>
```

`~/.zshrc` on Axel's machine defines `claude-work` as a shortcut for `CLAUDE_CONFIG_DIR=~/.claude-work claude`, with arguments passed through, so `claude-work` and `claude-work --resume <session-id>` do the same as the two commands above. A terminal without the variable runs on the first account. Never resume one session in two terminals at once: both write the same transcript. To branch instead, add `--fork-session`. Codex has the same in `CODEX_HOME`. The Usage view reads both folders through the `accounts:` list in `local.yml`.
