# Views guide

One section per view of the Views catalogue, with what it shows and how its controls behave, then the views opened for something rather than listed. The Files, Repositories, Terminal and Sessions views have their own guides, which their sections here point to.

## Focus

What wants attention now: deadlines, overdue items, follow-ups, the week's ticker, the lanes and the career strategy. A project of any tier, coauthor, archive and software included, sits on the lane its `focus:` names, and only a project of the ideas, active or manuscripts tiers can be dropped on the Ideas lane. A project of another tier on a lane has the flames and the Move to menu of every card, which write its manifest as they do any card's, and the ideas backlog and the unplaced hint stay over the three live tiers. Each card shows its first two statuses as a glyph and a word in the status's colour, and each lane's header is a strip of the lane's colour: Run green, Push blue, Revise amber, Review slate, Blocked red, Backburner grey, Scope dark cyan, De-risk honey and Build teal, the Ideas lane mauve, and the columns Funding gold, Jobs dark grey and Teaching teal, whose values are the `focus_lanes` and `focus_lane_tones` of `config/catalogs/vocab.yml`. A lane header is painted at full opacity, and a muted cluster fades a lane's sub-line and its cards and never its header. A ticker line's buttons appear under the pointer or the keyboard; on a device with a finger and a pointer, the first tap draws the buttons at the row's end and cuts the name where they begin, the next tap presses what it lands on, and a tap away closes them. A ticker line with no hidden button opens what it names on the first tap. A line that is a task, which is an entry of the Tasks collection or a subtask of a project, a funding scheme or an entry, has an `agent` button, which opens the composer in the task's folder with the task as the prompt; a snoozed line, a follow-up, a lead, a venue, a project's own deadline and any line of a side project have none. A subtask's, a follow-up's and a task's done is always shown. The Awaiting a response strip counts the people and venues of every live project and of every project of another tier on a lane, and the people a side project waits on while its status is live. A side project is live while its status row in `side_project_status` does not carry `live: false`, which only `parked` does. A live side project's `deadline`, due follow-ups and open subtasks are lines of the ticker like a project's: its deadline is in a group headed side projects between tasks and conference calls, an overdue one is in Overdue, its undated follow-ups and open subtasks are under side projects in the Tasks band, and a press on a line opens the project's `project.yml` in a source tab. A parked side project draws nothing and counts in nothing. While every cluster is open and every Funding, Jobs and Teaching column is drawn, each header has a colour that differs under every theme from the header drawn next to it, the one stacked above or below it, and the full-width Ideas lane; collapsing a cluster or emptying a column can bring two headers of the same or a near colour together.

## Projects

The projects board, as cards or as a list, searchable, with the pin, the stale badge and the card's own controls. An opened card draws the project's fields under their labels, Status, Latest, Results, Outcome, Next, Follow-up, Ideas / avenues and Reproduced, with backticked words drawn as code; Follow-up is one line per note, and a note whose `after` date lies in the future says `not until` that date. Under Files it draws the project's folder as the Files view's tree: the folder is the head of the tree and is open the first time the card is drawn, there is no workspace header and no `..` row, and a press, a key, a menu, a drag and a drop act as they do in the Files view, a file opening the way that view opens it. Each card of a tab keeps its own open folders and selection. The box above the tree filters: with text in it the tree gives way to the project's files of the extensions `file_index.ext` in `behavior.yml` names that match the text, where a Markdown file, a script or a LaTeX source opens as a document tab, a file whose extension `open.program_ext` maps to an application (a `.docx`, an `.xlsx`, a `.pptx`) opens in that application on this machine, and any other file is a link the browser opens or saves. A project folder that lies inside no folder of the workspace is said to be outside it, with Add Folder to Workspace. The folder control shows the project folder in Finder, and Show in Files selects it in the Files tab of the page, opening one there when the page has none. Each card's controls appear under the pointer or the keyboard and stay on one line, the ones that do not fit behind More at the controls' own size, and in a pane narrower than the card they stay inside what the pane shows; one Filter control in the bar holds every facet under its heading, ticks the values in force and counts them on its button, and its compute facet offers the resources present by name; a card draws one tag per resource, the cluster's with the HPC glyph; a long ELI5 is cut to four lines with Show more, which the tab remembers; a card with no subtasks offers adding the first among its controls and draws no subtasks block until it has one. The cards of a grid are stretched to one height along each row and stay in the file's order.

## Personal

One card per side project: a folder of `side-projects/` holding a `project.yml`, and a repository that is a Files root and holds `.oculus/project.yml`. A side project is on no lane and in no audit; the Focus ticker and the waiting tally read it while its status is live. A repository is read once it is a Files root, added with **Add Folder to Workspace...** in the Files view or under `roots:` in `sources.yml`. The status is one of `running`, `building`, `idea` and `parked`. A card shows the title, which opens the manifest, the status in its colour, where the project lives, the explanation cut to four lines with Show more, what the project last did (`latest`), what comes next, what it waits on, its collaborators and related projects, and its links, which are links only when they name a web page. A pinned card has the pin and the accent ring and is drawn first within its status; a priority is drawn as flames. The collaborators are the project card's person links, and each related project is a tag that opens its project tab. The bar searches title, explanation and next, and one toggle per status hides or shows its cards; a status the manifest names that the list does not is drawn as unknown and sorted last. Show in Files selects the project's folder. The tab's badge is the number of cards.

## Files

The Files view is the file browser over the hub, the engine config folder and the configured roots, with Open Editors, Outline, Timeline, Bookmarks and Notes under its tree, which follows the disk and whose roots, bookmarks, notes and sections reorder by drag and by Alt+Up and Alt+Down; its tree, menus, file operations and local history are in the [Files and search guide](files-and-search.md#the-files-view).

## Repositories

The Repositories view is VS Code's Source Control over every repository oculus knows, with the commit box, the changes, the graph, stashes, tags, branches and worktrees, over the repositories below a root as well as the roots down to `repository_scan_depth` levels; a changed file's name is a press that opens it, with Open File beside it, and the rows are selected by press, Cmd+press, Shift+press and Cmd+A and opened beside the pane with Cmd+Enter; the whole view is in the [Source Control guide](source-control.md#the-repositories-view).

## Search

A pattern across the files of one served root or of all of them, the hits grouped by file, each match one row opening its file in a source tab at that line, and, with the replace row shown, a replace over those matches as the editor's Search view replaces.

## References

The locations a language server found for Find All References (Shift+Alt+F12; in a YAML file of the hub, on a value that names an entry of another file, the files and lines that name it) or, where the server offers it, Find All Implementations in a source tab, or the call or type hierarchy of the symbol at the caret (Show Call Hierarchy, Shift+Alt+H, and Show Type Hierarchy in the editor menu), under a count, one row per file and one per location with the match marked. A press opens the location at its line with the match selected, which for a hub key in a YAML file is the whole key; a location in a library file opens the read-only library tab, which says after a reload that the library file is no longer open. A hierarchy is a tree: the first level is the incoming calls or the supertypes (or the outgoing calls or the subtypes, which the arrow button in the pane's title swaps to), and each node opens one level of its own when its arrow is pressed. F4 and Shift+F4 step through the latest result. The pane's actions refresh, clear, clear the history of the last ten searches and collapse all.

## Refactor Preview

The edit a language server answered, shown before anything is written, as the editor's Refactor Preview draws it. It opens when a rename of a hub key is made in a YAML file (Enter in the rename box) or any rename is accepted with Cmd+Enter, and when a move or rename in the Files view leaves links in Markdown files pointing at the old place (the Markdown server's edit, shown before anything is written), and it is not in the Views catalogue, so it has no chord; opened bare it says "Invoke a code action, like rename, to see a preview of its changes here." The title is "Renaming 'old' to 'new'" for a rename, "Update links in Markdown files" for the links of a move and "Refactoring" otherwise. Under it is one row for each file the edit changes, with its name, its folder and the number of its edits, and one row under it for each edit, with its line, the text the edit takes out struck through and the text that replaces it. Every file and every edit has a check, all checked at first; a file's check sets all of its edits, and a file with none checked is not written. A press on a file or on an edit opens the file as it is beside the file with the checked edits, at the edit's line. Apply makes the checked edits and closes the preview; Discard closes it and changes nothing, and neither a file nor a tab is changed while the preview is open. An Apply that is refused, because a tab was typed into after the preview opened or the server refused a file, says why under the header and leaves the preview for another try. A second refactoring asked for while a preview is open is held behind the question "Another refactoring is being previewed." with Continue, which drops the first preview and shows the second, and Cancel. A reload drops the preview.

## TeX view

The view `latex` is LaTeX Workshop's side bar, listed in the Explorer page's group (Cmd+Alt+X shows it beside the Files tab of the page, or opens it where a view opens when the page has no Files tab; the status bar's LaTeX item and the palette do the same). It follows the root of the active LaTeX source tab, or of the PDF of a build, and lists the roots it has seen so another can be picked. Three sections. Commands is a tree: Build LaTeX project with Clean, Kill and one node per recipe; View LaTeX PDF with Open in New Tab, Open in New Window, Open in Browser, Open in Program and Refresh Viewers; Logs with the compiler log (the build terminal) and the build log (`<main>.log` as a source tab); Navigate, Select and Edit with Show the PDF at the caret, the environment commands and Insert Root Comment; Miscellaneous with the citation browser, Count Words, Reveal Output Folder and texdoc; BibTeX with Align, Sort, Align and Sort and checkcites. Structure lists the parts to subsubsections of the root and its `\label`s and floats with their numbers and captions once the root is built, a press opening the file at the line, the section of the caret marked, and says when the parser refused a file and the list is from its sectioning commands alone. Math Symbols lists LaTeX Workshop's symbol groups each drawn with KaTeX, and a press inserts the command at the caret of the LaTeX tab.

A saved `latex` tab that names a folder and no main file opens on the first main file of that folder.

Math Preview (Cmd+Alt+M, or Open the math preview in a LaTeX tab's palette actions) is a view of its own, opened beside the LaTeX tab, that renders the math at the caret with KaTeX and follows the caret, with the document's `\newcommand`s as macros. It is opened for something and is not listed in the catalogue.

## Problems

The view `problems` is VS Code's Problems panel, listed in the Explorer page's group after the TeX view (Cmd+Shift+M shows it and hides it again when it is the view on screen, Ctrl+Shift+M off macOS; the status bar's problems item does the same). It lists the errors, warnings and infos the language servers found in the files they hold (library files included), the errors a project command printed, the errors and warnings of the LaTeX builds and the findings of the linters ([Linters](files-and-search.md#linters)), one row per problem under its file, a file row showing its folder and its count. The files are ordered by their worst severity and then their path, and a file's rows by severity and then position; each row shows the severity icon, the message, the source and code in grey and `[Ln 4, Col 12]`. The toolbar has Collapse All and View as Table or View as Tree. Under it the filter box takes comma-separated terms: a word matches the message, source, code and path fuzzily, a term with `*`, `?`, `[` or `{` is a glob over the path (`**/*.py`), and a term starting with `!` excludes. The chip beside it limits the list to one root, and the toggles Show Errors, Show Warnings, Show Infos and Show Active File Only narrow it further; the list says so when the filters hide everything, and says when there are no problems. A single press on a row shows its place in a preview tab without taking the focus; Enter, a second press or a double press keeps the tab and moves the caret to the range. The view is per page: each page, and each pop-out window, lists its own page's problems, and a page's view starts with the filter empty, Show Errors, Show Warnings and Show Infos on, Show Active File Only off, every root, and the tree. Hiding the view with the key or the status item keeps its filter, toggles, root scope and View as Table for that page, and showing it again gives them back; closing the tab by its own close button forgets them. A linter's row shows its rule as a link to the rule's documentation page where the linter has one; the writing rules' rows (source `writing`, a warning each) have none. A row's menu has Copy, Copy Message and, for a linter's row with a documentation page, Show Documentation. Taking a root out of the workspace (or switching to a workspace without it) removes the rows of that root's files from the list: the language servers' rows, the rows of a command run in a repository inside it, the LaTeX rows and the linters' rows. F8 and Shift+F8 go to the next and previous problem across files whatever the view filters, and the tab strip, Open Editors and the Files tree mark a file with its error or warning count, a folder with a dot, in the error or warning colour.

## Debug

The view `debug` is the debugger of rite, listed in the Explorer page's group after the TeX view. At the top the configuration picker lists the configurations of `.oculus/launch.yml` of the repository of the source tab on screen (a repository with none runs the open `.rite` file as Debug the open file), Start runs the chosen one and stays drawn while a session runs, answering then that a session is running, Add Configuration opens the file at its first entry and makes it with one configuration when it is absent, and Open launch.yml opens it at the chosen entry. The findings of the file are listed under them, one row per fault with its field. A line says what the session is doing: Starting, Running, Paused on breakpoint, Paused after a step or Ended with the reason. Four sections follow, each collapsible and kept with the tab. Variables lists the scopes of the selected frame, Locals then Module, each as `name = value`, flat as the adapter answers them, with no type. Watch lists the expressions you keep, each with its value at the last stop or the adapter's error, and not available while the program runs; a row edits on a press and has a remove, and the head adds one and removes all. Call Stack lists the frames of the paused program with their `file:line`, the selected one marked, and a press selects the frame and opens its file at its line. Breakpoints lists every line breakpoint by file and line with an enable box and a remove, then the function breakpoints; a breakpoint the adapter does not hold yet is drawn as a warning with the adapter's message as its tooltip, and a press opens the file at the line. The head adds a function breakpoint, enables all, disables all and removes all. The stepping controls are the floating toolbar, which is drawn over the top of the workbench while a session runs. The whole behaviour is in the [Debugging guide](debugging.md).

## Debug Console

The view `debug-console` shows the console of the session: what the program wrote, what the adapter said, each expression you evaluated and its result. It is drawn in the terminal's font, wrapped, with `stderr` and errors in the error tone, and a run of identical lines of one kind is one line with its count. It opens when a session starts and stays open when it ends. The input under the lines evaluates in the selected frame while the program is paused and is read-only otherwise; Enter sends the text, the earlier inputs that start with the typed text are listed under the box, Tab or a press takes one into it, and Up and Down step through what was sent.

## Present

A deck, one slide at a time as a 16:9 frame scaled to its pane, with an overview grid. A deck is a folder holding a `present.yml` and Markdown slide files, a file holding several slides split by a line of `---`. The deck menu in the toolbar opens the portfolio deck (`portfolio_deck:` in `sources.yml`), the deck of any project that has a `present/` folder, a deck the pane has shown, and a deck opened from the Files view with Open Presentation on a `present.yml` or on a folder that holds one. A deck has one tab on a page: Open Presentation, a project's Present button and the deck menu bring forward the tab that already shows the deck they ask for. A tab of a deck folder shows the folder's path above the slides and has the file items of a tab menu (Copy Path, Reveal and the rest). A figure or image the deck's folder lacks, or that lies outside the root, is drawn as a gap naming it, and the deck carries a finding for it.

The Present control in the toolbar and `F` put the slide on the whole monitor, in a browser tab and in the desktop app, with no rail, tabs or toolbar, and Esc leaves; there the arrows, Space (Shift+Space goes back) and a click move through the slides, and the pointer hides after 2 s at rest. The other single keys of oculus wait until you leave, and a shortcut that moves the keyboard to another pane ends the full screen. Full screen also ends when the tab is hidden or the deck holds no slides.

The Presenter control in the toolbar, and `P` while the deck has the focus, start the presenter screen. The pane then shows the current slide large, the next slide smaller beside it (or "End of the deck." after the last), the current slide's `notes:` as plain text under it with its line breaks kept (scrolling when long, or "No notes for this slide." when there are none), the counter, the time of day as `HH:MM` and a timer from `0:00:00` with Pause, Resume and Reset. The slide alone opens in a second window for the audience, at `/present/show`, with no toolbar, counter or key hint and a Full Screen control (and `F`) that hides in full screen and after 2 s at rest. In the desktop app that window is an app window of its own, on another display in full screen when there is one and beside the main window when there is not. The two windows keep one slide: the arrows, Space (Shift+Space goes back), PageUp, PageDown, Home and End move both whichever has the focus, and so do Previous and Next, a click on the audience's slide and a click on the presenter's current slide; a click on the next slide's preview or on the notes does nothing. O and the Overview control open the grid over the presenter screen, and a slide picked there moves both windows. Both windows draw the deck as saved, never a source tab's unsaved text, and redraw when it is saved; a current slide removed by a save falls back to slide 1, and a deck left with no slides ends the presentation. Presenting belongs to the pane and goes on over a tab switch, a page switch and a pane added. The End control, Esc (after the grid and, in full screen, after leaving it), closing the audience window, switching the deck in the toolbar and closing the pane's tab end it, and the audience window closes with it. Reloading the audience window does not end the presentation: the presenter screen waits 3 s for the window to come back and then draws the slide again, and a window that is closed and stays closed ends the presentation after those 3 s. Presenter pressed again brings the audience window forward (in the desktop app it also loads the window's page again when that page says the presentation ended), and Presenter in a second pane over the same deck takes the audience window over from the first pane, which shows the slide again. When the presenter screen's page is reloaded or lost, the audience window says "The presenter screen has ended." and offers Close, or "Close this tab to leave." when its tab was not opened by oculus.

The Slides button in the toolbar opens the catalog of the deck's groups beside it, for the deck that pane shows. The Order list at the top holds the entries of the deck's `order:` (a slide file, the slides of a group, a summary, a grid), and you drag each to another place or step it with its up and down controls. Each group lists its members in the order of its `slides:` list with a tick, a position and the controls that move it, the decks its `find:` (folders, tiers and status chips) found as candidates, the names `slides:` holds that match no deck as missing, and the decks two discovering groups both find as conflicts. A member is dragged within its group or onto another group; a deck dropped on a group whose `find:` does not find it is refused with a sentence that says so. Save writes the `slides:` list of every group that changed and the `order:` list into its `present.yml` in one write and keeps every other line of the file. An entry of `order:` moves with its own lines and comments. When the file changed on disk meanwhile the save is refused whole, with a sentence that says so, and the catalog shows what the file holds now. History lists each changed list as its own record and undoes it while the file still holds it. A project that has a deck gains a control on its card, Open Presentation, which opens its deck.

A right-click on the slide, or on its tile in the overview, offers Edit Slide, New Slide, Duplicate Slide and Delete Slide, and the command palette lists the same four for the slide on screen. Edit Slide opens the slide's file in a source tab beside the pane at the slide's first line; for a summary or a grid it opens the deck's `present.yml` at that entry. New Slide writes a file `slide-<n>.md` holding a text slide headed New slide, and adds it to `order:` after the slide on screen. Duplicate Slide copies the slide, as a file `<name>-copy.md` after the slide's file or, in a file of several slides, as a slide right after it. Delete Slide asks first. A file that holds only that slide goes to the Trash together with its entries in `order:`, and a slide in a file of several slides is cut out of the file. A summary or a grid leaves `order:` and keeps its group. A slide of a member deck belongs to that deck, so it offers Edit Slide and New Slide, and no Duplicate or Delete. History undoes each of these; undoing a New Slide moves the new file to the Trash. A source tab over a file of the deck's folder that holds no unsaved text reads the file again once an act has written it. An image dropped on a slide of the deck's own files is copied into the deck's folder, under a free name, and linked at the end of the slide's text. A file that is no PNG, JPEG, GIF, WebP or SVG image, more than one file and a file over 32 MB are refused in the status line at the end of the toolbar, which also says what each act came to.

While a source tab of the same page holds text of a slide's file that is not saved, the slide is drawn from that text within a quarter of a second of the last keystroke. Revert in the source tab draws the file's text again. Only the files the deck reads are drawn from drafts.

Export to PDF in the toolbar, and in the palette, writes the deck as `<name>.pdf` in the deck's folder (`<name>` is the folder's name, the project's name for a project's `present/` folder), one slide to a page of 1280 by 720 px with selectable text. A slide taller than its page is scaled down to fit it. A file of that name is replaced only after the question the Files view asks. In the desktop app the page is printed by a hidden window and saved through the Files view's upload, so History lists the file and undoes it. The export gives up after 60 seconds and says so. In a browser tab the control opens the deck's print page in a new tab, which opens the browser's print dialog when the slides are loaded, and the PDF is saved from there. A PDF over 32 MB is refused, naming the limit. No other format is exported.

## Lit Watch

The literature radar the scout writes, the toolbar closing with the control that opens that feed file. A long author and venue line is cut with an ellipsis, the whole line in its tooltip, and the cards narrow with the pane.

## Literature search

One query asked of OpenAlex, Semantic Scholar, Crossref, PubMed, Europe PMC and arXiv, and of Web of Science and Scopus when `local.yml` holds their keys. A toggle per source, each with the state of its answer beside it (the number of hits, rate limited with the wait the source named, no answer within `literature.timeout_s`, key refused with the status, failed, skipped when the source cannot hold a filter), and a toggle that cannot be pressed names its `local.yml` key in its tooltip. The hits are merged into papers when they share a DOI, a PubMed id or an arXiv id, and a preprint and its published version are one paper when some source names both. Filters: year range, document type, open access only, venue, author and minimum citations; each is also applied to the merged list, so a source that ignored a filter shows nothing outside it. Sort by relevance, date or citations changes the order and asks nothing; `More` asks the next page of every source that has one. A card shows the authors, the venue, year, type and citations (each source's count in the tooltip), one tag per source, the abstract under a disclosure, Open PDF when a source names an open one, Copy BibTeX (from doi.org, Semantic Scholar or the arXiv DOI, else formatted by citation-js; it writes no file) and Add to Lit Watch, which asks for a bucket, a project, the relevance and a note, appends the entry to the radar file and reads `In Lit Watch` afterwards. A search sends the query and its filters to the sources that are on and to nothing else. Google Scholar is a link that opens the same query on its site, since it has no API and its terms forbid scraping.

## Position Leads

The position leads the scout writes, the toolbar closing with the control that opens that feed file. A lead not yet applied to carries `applied`, which opens the Applications file beside the leads with a new entry filled from the lead in the tab's unsaved text and the caret in it, and then sets the lead's status to `applied`; an entry the file cannot take (the file does not parse, or the tab's text differs from the disk's) is answered with a sentence, the file opens at the line it names, and the lead stays as it was. Add on the bar opens the leads file with a new lead dated today in its unsaved text. While a source tab holds unsaved text of the leads file, the lead cards' `applied`, `decline`, reopen and delete are disabled. An open lead carries `decline`, which sets its status to `declined`, so it leaves the counts and History can undo it. The bar's toggle declined (n) shows the declined leads, counting the older `dismissed` ones with them, and its tooltip reads Show declined (n) or Hide declined (n); each closed card's reopen control puts it back on the radar.

## Inbox

The reader's own mailboxes read live: one row per configured mail account with its Connect control and a row menu whose Remove asks first, Add account in the head and on the empty page, and the plate in four sections by what each thread wants, each one column of cards. ## LinkedIn

The posts pipeline: what is posted and what is still an idea. It is drawn from a folder of one file per post rather than from one file, so the way into the text is each card's own control. The folder is `linkedin_dir` in the hub's `.oculus/config/sources.yml`; a hub that sets none sees a line saying the hub names no LinkedIn folder.

## Session

One session in a tab of its own, in three sections: Details, Changes and Agents. One picker in the bar picks the session all three show, and the toolbar opens the session's Transcript and its Timeline. Each head names its section, and the heads of Changes and Agents count the files the session touched and the agents it dispatched. Each section starts open, opens and closes on a press on its head, and a closed section draws nothing and asks for nothing until it is opened. The heads are dragged among each other and moved with Alt+Up and Alt+Down, as the sections under the Files tree are; the tab keeps which sections are closed and their order, through a reload, a switch of tab and a pick of another session.

Details is what the session is doing, its model, its workspace and its controls.

Changes is the git state of the workspace a session works in (a file is shown as its name followed by its folder, dimmed and cut at its end when the pane is narrow, with the whole path as the tooltip, and the verb and the count of the files the session touched at the right edge of its row): its branch, the same commit box as the Repositories view, and its changes with Stage All, Unstage All and Discard All on the group heads (its commit box says Sync Changes or Publish Branch where there is nothing to commit, which is how the section pushes) and each row opening its own diff tab for the session, a conflicted path the merge editor; in that tab a `+` beside a line (or Add Comment on Line in the line's menu) opens a comment box after it, and Send hands the comment to the session as a prompt naming the file and line, typed into its terminal when oculus runs it and copied to the clipboard otherwise, with a line saying which; a repository with no commit yet included; or one line saying the session names no workspace folder, that the workspace folder is not there, that the folder is not a git repository, that git could not read the repository and why, or that git has not read the workspace yet.

Agents are the agents a session has running under it: the subagents its transcript names. A subagent started in the background reads running until the session's notice that it stopped: done when it completed, stopped when it was killed, error otherwise; without a notice, until its own transcript has been still for 30 minutes. A subagent resumed after its notice reads running again once it writes its transcript, and its next notice ends it again.

## Live HPC

The cluster queue: what is running, what is pending and the quota; it is where a job queued by Submit Job shows. The cluster is `slurm.resource` in the hub's `.oculus/config/behavior.yml`; a hub that sets none sees a line saying the hub's settings name no cluster, and nothing is polled.

One poll runs `squeue`, `sacct` and `sinfo` over ssh every `slurm.poll_min` minutes, with the disk quota on its own slower cadence. While the cluster is not answering the next attempt comes after two minutes instead of the full period, and an answer restores the regular cadence. The head marks its "as of" time stale when the answer on screen is older than the period plus two minutes. A failed poll keeps the last good queue, recent and partition rows under the state word with the time the cluster was last reached, and their controls are shown unpressable until it answers again. When `slurm.prewarm` is on, the log paths of the finished jobs are resolved in the background after each good poll, one at a time, so the first press on a log is as fast as the second and no press waits on the prewarm's walk. The host it connects to is the machine's `hpc_host` of `local.yml` when that names one, else the `host` of the cluster entry of `registries/resources.yml` that `slurm.resource` of `behavior.yml` names; when the entry is missing, is not a cluster, has no host, or has a host that is not a plain ssh alias, no ssh runs, the state is `unreachable`, and the view shows the sentence for why in place of the ssh error.

Live HPC's cancel runs `scancel <id>`. Submit Job copies a project's code to the cluster and queues a job from it, in two steps. The plan, which the confirmation shows, names the code folder, the cluster folder (`paths.cluster` of the manifest, else `~/projects/<id>`), the files git keeps minus `__pycache__`, `.npy`, `results/` and `logs/`, the rsync arguments, the one remote command `cd <folder> && sbatch --parsable <script>`, and whether the script or a file it sources names `/local/$SLURM_JOB_ID`. The run computes the plan again at the press and refuses with `changed` unless it equals the confirmed plan, then runs `rsync` and the ssh command, with a refusal word for each step that fails: `copy-failed` carries one line of rsync's stderr, the first line that begins `ssh:` when there is one, else the last, and `submit-failed` carries sbatch's. The copy never uses `--delete`, passes no `--mkpath` and runs no remote `mkdir`, so a cluster folder that rsync cannot create ends in `copy-failed` with the line rsync wrote. One run per `<host>:<folder>` goes at a time.

## LaTeX builds

A LaTeX file builds through a root, which is found by four rules in order: the `% !TEX root = <path>` comment among the comment lines at the head of the file (followed through the files it names, so a chapter that names a part that names the thesis builds the thesis; a comment naming a file outside the served root, a missing file or a file that is not a source file is passed over, and a cycle with no main answers none); the file itself when it declares a document class; the main file of the file's folder, or of the nearest folder above it up to the served root, whose includes (`\input`, `\include`, `\subfile`, `\import`, the bibliographies it names and the files its last build recorded in `<main>.fls`) reach the file; and the only main file of the file's folder. A `.bib`, `.sty` or `.cls` file takes the last two rules. The status bar's LaTeX item and the TeX view name the root found. A `% !TEX program = xelatex` or `lualatex` comment picks the recipe of that engine and a `% !LW recipe = <name>` comment picks a recipe by name; a name no recipe has is refused.

A build is a recipe of `latex.recipes` and `latex.tools` in `config/behavior.yml`, with LaTeX Workshop's placeholders (`%DOC%`, `%DOC_EXT%`, `%DOCFILE%`, `%DOCFILE_EXT%`, `%DIR%`, `%OUTDIR%`, `%AUXDIR%`); `latex.recipe_default` says whether a build with no choice takes the first recipe or the last one used, and `latex.out_dir` and `latex.aux_dir` name the folders it writes to, refused when they leave the served root. It runs as a task terminal in the root's folder, so the output stays readable with its exit status after it ends, and a main file has one terminal for Build, one for Clean and one for checkcites. A program the recipe needs that is not found is named, with where it comes from, before any terminal starts. A build or clean that runs latexmk reads the latexmkrc files latexmk would read, which are code: the `.latexmkrc` and `latexmkrc` files of the main's folder and each folder above it up to the served root, the XDG file (`$XDG_CONFIG_HOME/latexmk/latexmkrc`, else `~/.config/latexmk/latexmkrc`) and `~/.latexmkrc`. A recipe tool whose program is none of TeX's own (`Rscript`, `julia`, `pweave`, `quarto`, `R CMD Sweave`) runs the document's code. Neither runs until you approve it on this machine: a press on Build or Clean lists the files and the tools in one question and starts nothing, Approve writes both approvals and runs the step once, and a changed file or tool asks again. Rerun and Restart on the Build or Clean terminal ask again when a file or a tool changed since it was approved, and start nothing until you approve; they are refused when the file is no longer a main file, and on a terminal that does not record its main file, which Build or Clean then runs again. A build the reader did not press (`latex.auto_build`, `latex.auto_clean`) waits for the approval too, with the status bar's LaTeX item in the warning tone; a press on it opens the list of the main file that has waited longest. Cancel on the list of a step you pressed ends its wait, and the wait of a step the reader did not press stays. When `latex.clean_and_retry` finds the clean unapproved, the failed build ends as failed and the clean waits; Approve runs the clean and then the build once more. A file latexmk would read that cannot be read refuses the step with its path. Build, Build with Recipe, Kill Build, Clean, View PDF, Show the PDF at the caret, Save without Building, Insert Root Comment, Count Words, the compiler log and the build log are in the breadcrumb bar of a LaTeX source tab (Build, View PDF and Build Log), in the TeX view and in the palette, with Cmd+Alt+B, C, V and J (Ctrl+Alt off macOS); the same Build, Clean and View PDF keys work in the PDF tab of a build. Build shows the spinner while it runs and offers Kill Build, a Clean while a build runs is refused, and a build after a stopped or failed one passes latexmk's `-g` so it runs. `latex.clean_and_retry` cleans and builds once more when a build fails, and `latex.auto_clean` cleans after a build as it is set to (`never`, `on_failed`, `on_succeeded` or `on_built`).

`latex.auto_build` says when a build starts without a press: `on_file_change` (the default) builds the root once when a file of its includes changes on disk, the writes of one `latex.auto_build_interval_ms` counting as one; `on_save` builds on a save in oculus; `never` builds only on a press. A save or a change during a build is built once more after the running one, however many came, and the status bar item stays on the spinner until the last ends. Save All in Open Editors and a Timeline restore save the same way. Save without Building writes the file and starts no build. A failed build posts a notice, once until a build of the root succeeds, with the actions Open Compiler Log and Show Problems; the errors and warnings of the last build (bad boxes as warnings) are listed in the Problems view, and the count in the TeX view and the project panel opens that view limited to the root; they are drawn as markers in the editor of an open source tab. `latex.texcount_autorun` counts the words after a save.

The PDF opens as a `file` tab drawn by PDF.js, with zoom, fit width and page, find, an outline, thumbnails, page entry, scroll and spread modes, inverted colours and a back control for the place an internal link left. The viewer is kept apart from the pane layout, so a pane added, a page switched away and back, and Maximise pane followed by Restore panes leave its page, offset, zoom and scroll as they were. A PDF opens where it was last read: a tab keeps its own place across a reload, a window and Return to Page, and a tab opened for a file starts at the file's last place, kept for the last 50 files. The place is the page, the offset in it, the zoom, the scroll and spread modes and the side panel; inverted colours are not kept. A rebuilt PDF is loaded in place at the same page, offset and zoom, a failed build leaves the old document shown, and after a Clean the viewer says the PDF is not built yet until the next build. A PDF opens in four ways, from the viewer's menu, the file tab's menu and the Files row menu: Open in New Tab, Open in New Window (a window of the app, or in a browser a browser tab at `/?float=<id>` that draws the PDF alone), Open in Browser (the browser's own viewer) and Open in Program (Preview, by `open.program_ext`). Show the PDF at the caret scrolls the PDF to the page of the line and draws a rectangle that fades; a root with no `.synctex.gz` says so and offers the build that writes it. A click on a PDF page with Cmd or Ctrl held (or a double click when `latex.reverse_synctex` is `double_click`) opens the source line, in the pane that holds a tab of that file, else beside the viewer; from a viewer in a window of its own it opens in the main page that opened the window, which is brought to the front, and in no other page of oculus. A click on a place with no record does nothing, and a record naming a file outside the served root is refused.

In the editor of a LaTeX tab, resting the pointer on math or on an `\includegraphics` path shows the typeset formula or the picture, on a `\ref`-like command shows the label's number and the block it sits in with a link that shows its place in the PDF, and on a `\usepackage` name shows a link to the package's documentation. `\` and the name of an environment inserts the environment with its closing line, and a `_{` or `^{` offers the sub- and superscripts the text already uses; `@` suggestions are LaTeX Workshop's table. The editing commands are: jump to the matching environment or bracket, select the current environment, its content or its name, a cursor at each end of its name, toggle display math between `\[...\]` and an equation environment, close the open environment, wrap the selection in an environment, surround it with a command, promote and demote the sections in the selection (Cmd+Alt+[ and ]), select the current section, and a smart selection by LaTeX structure. Enter in an `itemize`, `enumerate` or `description` starts a new `\item `, Alt+Enter a plain line, and the Cmd+L and Ctrl+Shift+M chords of the keys table wrap the selection in a text or a math command. Each is one undoable edit. In a LaTeX tab, `\` offers the Unicode math symbols of `config/catalogs/unimath.yml` with their glyph while `latex.unimath_symbols` is true, and a `.png`, `.jpg` or `.jpeg` file suggested inside `\includegraphics` shows the picture beside the list while `latex.includegraphics_preview` is true (the default is true). A LaTeX or BibTeX tab that texlab serves (docs/files-and-search.md, Language servers) also gets texlab's hover beside those: on a `\ref` the text of the label, and on a `\usepackage` name the description of the package. texlab adds completion of `\cite` keys, `\ref` labels and package names, Go to Definition and Find All References for labels and citations, Rename Symbol across the files of the document, and the document symbols the Outline lists. A `.bib` tab has Align, Sort and Align and Sort, which reformat the text as one undoable edit and save nothing, and Citation Browser lists the entries of the root's bibliographies and inserts `\cite{key}`. texdoc asks for a package name (offering the ones the root loads) and opens its documentation on this machine. Count Words runs `texcount`, and checkcites runs `checkcites` on the root's `.aux`. A file over `editor.paint_limit_kb` keeps the breadcrumb bar, the keys, the build, the PDF and SyncTeX, which follow the file's name, and loses hover, completion and the editing commands, which need the painted language; a LaTeX file a language server serves keeps both. Format Document (Shift+Alt+F) formats the file with the program `latex.formatter` names, as LaTeX Workshop's formatting setting offers them: `none` (the default, which formats nothing and says so), `latexindent` (it comes with TeX Live and MacTeX), `tex-fmt` (`brew install tex-fmt`) or `badness`; each program is found on PATH unless `latex.latexindent_path`, `latex.tex_fmt_path` or `latex.badness_path` names where it is. A program that is not found is named with where to set its path, and the formatted text is an unsaved edit that undo takes back.

The project tab's LaTeX panel, over the project's `manuscript/` folder, draws each main file's name (opening the source tab), its build state, Build, Clean, View PDF and Count Words through the same store as the TeX view, and a link to the TeX view.
