# Files and search guide

The Files view, how a file opens and is edited, and the Search view. The Repositories view is in the [Source Control guide](source-control.md).

## The Files view

The file browser over the hub, the engine config folder and the configured roots, read like an editor's explorer.

## The tree and its header

The tree starts with a header row for the workspace in force, its name or `Configured roots` for the default workspace, drawn as an editor's pane header with four actions under the pointer, New File..., New Folder..., Refresh Explorer and Collapse Folders in Explorer, which act on the selected row's folder or on the first root, and a menu (`...`) with Add Folder to Workspace..., Switch Workspace..., Save Workspace As..., Open Folder... and the checked items Show Hidden Files, Show Ignored Files and File Nesting. Each of the three checked items is off until turned on and kept per tab: Show Hidden Files lists dotfiles and the `node_modules`, `__pycache__` and `.git` folders, Show Ignored Files lists what git ignores in a repository, and File Nesting draws a file under the file that owns it by the patterns of `catalogs/file-nesting.yml`, with the owner marked by a twistie. Switch Workspace..., Save Workspace As... and Open Folder... open the palette with `:workspace`, `:workspace-save` and `:folder` typed; a pick of `:workspace` switches in place, `:workspace-save <name>` saves the folders in force under the name and says why when the name is empty or taken, and `:folder` opens the system's folder panel. Under the header every root is a top-level folder row, and a folder holding only one folder is drawn with it as one row (`a / b / c`) whose parts are each a target of a press, a menu and a drop. Folders come first, then files, each in natural, case-insensitive order; a row's label is the name of the file or folder, never its path; a file has its own icon, the colour of its name and its status letter at the row's right are what git says of it (a folder takes the strongest colour below it), and a name the filter matched fuzzily has its matched letters marked. The view's toolbar holds the follow toggle and the lock that fixes the pane to one session, and its bar the filter box over the folders already read, with a Fuzzy Match toggle: off, a name matches when it holds the typed text; on, when it holds the letters in order.

A match is drawn open under its folders, those folders held open only while the text is there, so clearing the text restores the tree as it was; a project card's tree has a finder box above it that does the same over the folders already read, and the project's file listing is asked for only while that box holds text.

## Open Editors and Outline

The Open Editors section sits above it, and under it the Outline, Timeline, Bookmarks and Notes sections, with AST and Memory Usage sections between Outline and Timeline. Those two appear for a C or C++ file clangd serves once Show AST or Show memory usage has been run from the tab. Open Editors and Timeline are closed at first. Open Editors lists the tabs of the page that show a file, grouped by pane (a Group line appears with two panes or more), with the dot of a tab holding unsaved text and a close control under the pointer; a press shows the tab, a row dragged onto another row moves its tab to that row's place in the pane, Save All saves the source tabs that are unsaved and Close All closes every listed tab, asking first which tabs lose unsaved text. Outline follows the file tab the reader looked at last on the page, so pressing the Files tab does not empty it: it lists the headings of a Markdown source tab and the sectioning commands of a LaTeX source tab, nested by level, and a press moves the editor to the line; it lists the headings of a Doc tab or a Markdown preview tab, and a press scrolls that tab to the heading. For a source tab over a Python, C or C++ file a language server serves it lists that file's symbols as a tree, each with the icon of its kind and coloured as an error or a warning when one lies in its range, a press moves the editor to the symbol and selects its name, and the list says it is loading until the server has answered. A source tab in another language says it has no symbols yet, and a picture, a PDF, an HTML document or a page with no file tab says the active editor cannot provide outline information.

## Timeline

Timeline lists the history of one file, newest first: File Saved, File Replaced and File Deleted for the copies the history folder holds, and the commits that touched the file (followed across renames). A commit row shows its subject with its author beside it and how long ago at its right; its tooltip names the author with the email, the date and time, the subject and the short hash, and says when the author date differs from the commit date. The file is the pinned one, else the one selected in the tree, else the file of the file tab the page showed last, so a press in the Files pane, or a Files tab shown for the first time after a reload, keeps the file the editor showed. The commits are read fifty at a time, in git's order from HEAD, so a commit that reached the file through a merge is listed once and in place; a Load more row after the last one reads the next fifty when pressed, when Enter is pressed on it or when it scrolls into view, and says Reading... while it is read. The head carries Pin the Current Timeline (Unpin the Current Timeline once pinned), which holds the Timeline on the file it shows, Refresh, which reads both lists again from the first page, and a `...` menu with the checked items Git History and Local History, which show or hide the commits and the copies; the pin and both choices are kept per tab. A list whose read failed says so in one row and leaves the other drawn. Open Timeline in a file row's menu and in a file tab's menu opens this view on the page with the file selected and the Timeline section open on it; it releases a pin and pins nothing. A press opens the diff of that copy or commit, and Restore, on a copy's right-click, writes the copy back through the source save, which first copies the text it replaces.

## Bookmarks and Notes

The Notes and Bookmarks heads draw their add control at all times. A section whose read failed says why in one row in place of its list, with a control beside it that reads it again; the line goes as soon as a read lands, and the bookmarks and the notes are read again whenever the view is opened. The bookmarks file is watched, so a bookmark added or taken away outside oculus reaches an open page without a write from it. A scratch note's file is made by the first keystroke typed into it, and the delete control in the Notes list is the one thing that takes a note away. A star on a folder row bookmarks the folder as one on a file does; a folder bookmark opened from the Bookmarks section or the rail's Bookmarks menu (which draws it with a folder icon) shows the folder open and selected in the page's Files tab, and a bookmark whose path is gone is drawn dimmed and struck through.

A star bookmarks a file under its name, or under its path below the root when the name is already a bookmark's label.

## Keys and selection in the tree

The tree is one Tab stop: the arrow keys move the selection, Right and Left open and close a folder, and Tab from a row reaches its controls. A press selects a row, Cmd (Ctrl off macOS) toggles it in the selection, Shift selects the range from the row last pressed, Cmd+A selects every row, and Shift with an arrow extends the selection; a menu or a key acts on every selected row when the row is one of them. On a focused row Enter and F2 rename it, Cmd+Down opens a file as the pane's preview tab and opens or closes a folder, Cmd+Backspace deletes, Cmd+C, Cmd+X and Cmd+V copy, cut and paste, Escape cancels a cut, Option+Cmd+C copies the path, Option+Shift+Cmd+C the relative path, Space opens a file kept in the background (while a type-ahead is pending it extends the type-ahead instead), and Cmd+Z and Shift+Cmd+Z undo and redo a file operation. Enter on a root, on the workspace header or with two rows selected does nothing; Enter on a row of Open Editors, Outline, Timeline, Bookmarks or Notes opens it. The row menu shows each item's key at its right.

## Workspaces, roots and Add Folder to Workspace

Add Folder to Workspace opens the system's folder panel (`POST /api/folders/pick`, which lists and serves nothing) and adds every folder it returns that is not a root already, each skipped one named in a line. In the default workspace the added folders are written to the `roots:` list of `sources.yml` and Remove Folder from Workspace removes the entry; the hub and the engine's `config/` folder have no Remove, and in a saved workspace a configured root offers none either.

## Show in Files

Show in Files of a folder (a project card, a person's supervision folder) opens a Files tab rooted at that folder, with no workspace header and a `..` row above the folder that moves the top up one folder while it is below the root serving it; Open Folder... does the same for the folder chosen when a root holds it, and otherwise says the folder is outside every root and offers Add Folder to Workspace. A project card draws this tree rooted at the project's folder (see the Projects view). Show in Files of a file opens this view on the page, restoring the panes when a maximised pane hides it and using the Files tab a maximised pane holds. It is offered on a project card and the project tab, on a collection card whose `link`, `url` or `folder` is a path of the hub, on a venue card whose `link` is one, and on a person's supervision folder when it is one. The view opens the folders above that path, selects the path, scrolls it into view and clears the filter. A path is read by its segments, so `a/../b` is `b`, and a value that climbs above the hub gets no control. A path that is not there selects the nearest folder on its way, and a line under the header says so. The line also names a folder on the way that cannot be read, a root the workspace lacks, and roots the file browser could not read at all; in that last case the ask is answered at once and not later, and the line goes once the roots read.

## The right-click menus

A right-click on a file offers Open to the Side, Open in New Tab and Open in New Window on a PDF (the PDF in oculus's own viewer, in a tab or in a window of its own), Open in Browser on a picture, a PDF, a download or an HTML document (the browser's own viewer), Open in Program (for a file whose extension `open.program_ext` maps to an application, which opens in that application on this machine; a PDF opens in Preview as shipped), Reveal in Finder, Open in Integrated Terminal (a shell in its folder), on a `present.yml` Open Presentation, Select for Compare and, once one is selected, Compare with Selected (a diff of the two files, the selected one on the left), Open Timeline, Cut, Copy, Download..., Copy Path, Copy Relative Path, on a Markdown file New Presentation from Outline (a folder `<name>-slides` beside the file, with a slide for each level-1 heading and the file left as it was) and Open Preview (the rendered file alone in a tab labelled Preview and its name, and above the text the line the source tab shows when the file is longer than the read window and only its first part is drawn), and Rename... and Delete; on a folder New File..., New Folder..., Reveal in Finder, Open in Integrated Terminal, Open Presentation when it holds a `present.yml`, New Presentation... when it holds none (a name box in the tree asks for the title, and the folder gets a `present.yml` and a closing slide), Find in Folder... (Search over that folder, a hidden or ignored one included), Cut, Copy, Paste (greyed until something is cut or copied), Upload..., the two copies, Rename... and Delete; on a root those of a folder except Cut, Copy, Rename... and Delete, with Add Folder to Workspace... and, on a root you added, Remove Folder from Workspace.

## Creating, renaming, deleting, moving and pasting

New File..., New Folder... and Rename... draw a name box in the tree: Enter or leaving the box accepts a valid name, Escape cancels, and an empty or unchanged name cancels; a name with several segments makes the folders between. Delete asks first, naming the rows when several are selected, and moves them to the macOS Trash, where they can be restored from, and offers to delete for good only when the Trash fails, a second question that is always asked. The first question names a folder that is not a link with "and its contents" ("Are you sure you want to delete 'src' and its contents?"), since deleting it takes everything inside; a link to a folder is named alone, since deleting a link removes the link only. The first question carries a Do not ask me again box; ticked, it writes `files: { confirm_delete: false }` to `behavior.yml`, after which a delete to the Trash goes without a question. A drag of rows onto a folder or a root moves them after asking, whichever root holds the folder (the source is moved and not sent to the Trash), and with Option held copies them; files dragged in from the system upload into the folder, and a folder dragged in from outside is refused with a line. A Cut item is drawn faded until it is pasted or another Cut or Copy replaces it. Pasting a Copy onto a name that is taken takes the next free name (`report copy.md`, then `report copy 2.md`) and asks nothing; pasting a Cut onto a taken name asks before it replaces the item, which goes to the Trash. A rename or a move restates the open tabs over the file and the bookmarks on it.

## Undo and the local history

Every create, rename, move, copy, paste, upload, trash and delete that changed something is a record of the History view, with its operation, its paths and an Undo control, and Cmd+Z in the Files view takes the newest one back while Shift+Cmd+Z takes that undo back. An undo of a delete asks first ("Would you like to undo 'Delete'?") and writes back each file whose content was kept, a folder coming back empty; the content of a file up to 5 MB is kept in the history folder before a delete, and the newest 50 such copies over all files are kept, so a larger file, the files inside a deleted folder and the files of a delete older than the newest 50 are not brought back; an undo whose copy is gone says so and changes nothing. An undo of a create, copy, paste or upload moves what it made to the Trash while each file is as the operation left it, an undo of a rename or a move moves it back while the old name is free, and an undo the check refuses says why in the view. The history folder is the `history` key of `local.yml`, `~/.oculus/history` by default: one folder per file, named by the first 16 hex digits of the SHA-256 of its real path, holding `entries.json` and one copy per save. A save through the source tab copies the file as it was first, at most 50 copies per file and none of a file over 256 KB; a copy that fails is said and the save goes on. `GET /api/history?root=<key>&path=<rel>` lists the copies of a file and `&id=<id>` answers one copy's text, and `GET /api/git?log=<repository>&path=<rel>` lists the commits that touched a file, fifty to a page, with `&before=<hash>` asking for the page after that commit. Nothing is written outside the served roots, and the machine's `config/local.yml` is never changed from here.

## The Files tab of the Sessions page

The Files tab of the Sessions page follows a session: its tree is rooted at that session's workspace folder. It follows the session the pane is locked to, else the selected one. The follow toggle in its toolbar turns following off and back on.

## Opening a file

Every text file of the file browser opens in `source`. What counts as text is the file's own first bytes: no extension list decides it, so a script nobody gave an extension opens for editing and an archive somebody called a `.txt` is a download. Whether it can be saved is the file's mode on this machine: a file this machine locks opens in the editor under a line saying why, takes no keystroke and still has the language features that change no text. A file too long to have been read whole, and a version of a file at HEAD or in the index, are drawn as a read-only window under a line saying why.

A single click in the tree opens a preview tab, drawn in italics: the next single click in that pane is pointed at the file it names instead of opening a second tab, so a walk through a folder leaves one tab and not twenty. Clicking the same file a second time keeps its tab; so do a double click on the tab itself, typing into it, dragging it and splitting the pane around it. A double click on the row keeps it where the tree stays on screen beside the file, in a split pane; in one pane the first click has already put the file where the tree was, so the second press lands on the tab, in its editor or its frame, and keeps the tab the first click opened; a file still being read when the second press goes down keeps its tab from the row. The second press is taken for 500 ms after the first click, selects no word in the editor, and leaves the keyboard in the kept tab: in its editor, its frame, or the picture, download, document or preview it shows. A file the server says is gone opens in the source tab, which says it cannot be opened and offers Read again.

## The source tab's editor options

The source tab's editor takes its options from `behavior.yml`: `editor.tab_size` and `editor.insert_spaces` for a file with no indented line, `editor.word_wrap` (`off`, `on`, `wordWrapColumn` or `bounded`), `editor.minimap`, `editor.render_whitespace` and `editor.sticky_scroll`, each a control in the Settings view's Editor group. `editor.languages` holds a record per language name with `tab_size`, `insert_spaces`, `word_wrap`, `rulers` (the columns that draw a vertical line) and `format_on_save`. `format_on_save` formats the document through the language server before each save where the server formats, and a language whose server does not format, Python among them, saves as typed. A repository's `.oculus/settings.yml` can hold a `languages:` map of the same records, which overrides `editor.languages` for the files served from that root; its `editor:` key is not read, and an entry that cannot be read is skipped and listed under the Languages row. A value is taken in this order. Indentation: the choice made on the status bar for the tab, then the file's own when it indents with spaces or tabs, then the root's record, then `editor.languages`, then `editor.tab_size` and `editor.insert_spaces`; a file that indents with tabs keeps its tabs and takes its width from the same order. Word wrap: the tab's Alt+Z, then the root's record, then `editor.languages`, then `editor.word_wrap`. Alt+Z (View: Toggle Word Wrap, listed among the editor's palette actions) turns the wrap off when it is on, returns it to the configured value when it is off and the configured value wraps, and sets it on when both are off; the tab keeps the result across a reload. Rulers: the root's record, then `editor.languages`, then none. The minimap, whitespace and sticky scroll are the global keys alone, and the diff editor takes the configured word wrap, rulers, whitespace and sticky scroll of the file's language with no minimap. Sticky scroll pins the headings of a Markdown or LaTeX file, the blocks TypeScript, JavaScript, JSON, CSS, SCSS, Less and HTML give, and the symbols the language server answers for a Python, C or C++ file it serves. It pins the braces of Java, Dart, R and Rite, and of C and C++ while no language server serves the file. Every other editor setting stays at Monaco's default, except that a file a language server serves draws semantic colours, and a C or C++ file clangd serves formats its line after Enter.

The diff editor falls back to the inline layout when its pane is under 900 px wide, and the sides of its comments follow the layout drawn.

## Language servers

A Python, C, C++, TypeScript, JavaScript or Svelte file in a source tab is served by a language server oculus starts in the background for the file's root, pyright for Python, clangd for C and C++, the TypeScript server (`typescript-language-server`) for TypeScript and JavaScript and the Svelte server (`svelte-language-server`) for Svelte, and ends 60 seconds after the last tab of that root and language closes. It gives hover, Go to Definition, Declaration, Type Definition and Implementation, peek, and Find All References (Shift+Alt+F12), which is listed in the References view with Find All Implementations where the server offers it, which pyright does not. It also gives highlights of the symbol under the caret, completion, signature help, diagnostics as markers, and document symbols for sticky scroll, the path over the tab and the Outline. Go to Definition into another file opens it with the name selected. A definition in a file outside every folder oculus serves, such as Python's standard library or a C++ system header, opens in a read-only tab named for the file, with hover and Go to Definition answered inside it by the server that named it, and Peek shows its text. oculus opens only a file a server named in an answer to a request you made, and never one under a folder whose name starts with a dot (the library folders of the interpreter pyright runs with are the exception), under a folder of the `closed_paths` setting, or in oculus's own configuration, `~/.oculus` or the hub's `secrets` folder. A library tab lives as long as the page's connection to the server: after a reload or a reconnect it says the library file is no longer open, and Go to Definition opens it again. Format Document and Format Selection come from clangd, the TypeScript server and the Svelte server. Each server gives the features it offers that the editor draws, so Organize Imports (Shift+Alt+O) is there for pyright, the TypeScript server and the Svelte server; clangd offers none. The TypeScript server's Organize Imports sorts and combines the imports, and Source Action in the editor menu lists its Remove Unused Imports beside it. Rename Symbol (F2 or the editor menu) renames through the server, and Show Call Hierarchy and Show Type Hierarchy in the editor menu (Shift+Alt+H for the call hierarchy) list incoming and outgoing calls, supertypes and subtypes in the References view, each node opening one level at a time; an item the server does not offer is left out of the menu and the palette and its key does nothing (pyright offers no type hierarchy). Workspace symbols are listed by Cmd+T in the app, or by typing `#` in the palette, from the server of the active source tab's language and root, each with its kind, container and file, and a press opens the file with the name selected. An edit a server asks for, by a rename, a quick fix or a code action, may change other files. A file open in a tab of this page is changed in that tab, unsaved, as one undo step; every other file is written to disk at once, with a copy kept in the local history, and History shows one record, Edited by a language server in N files, whose undo takes every written file back. A tab of a file the server holds is edited only when its text is the text the server holds, which includes a tab of the same server's other language (a `.c` file for clangd's C++ rename), so a second tab of the file with other text refuses the edit; a tab of a file the server holds no text of (a tab not shown since a reload) is edited only when its text is the file on disk. The whole edit is refused with a notice naming the file, and nothing is changed, when a file it names is open in a tab of another page (whether or not a tab of this page holds it too), is named twice, is a library file, lies outside the folders oculus serves or under a `node_modules` or dot folder, is `local.yml`, has changed on disk since the edit was asked for, is open in a tab whose text was typed into before the files were written, or when the edit creates, renames or deletes a file. Text typed into a tab after the other files were written is kept, and the notice names that tab, says every tab was left as it is and says how many files were written. The TypeScript server runs oculus's own TypeScript, never the repository's, and fetches no typings, so a repository with no `@types` package shows the missing types as diagnostics. The Svelte server starts in reduced mode for every repository: it runs none of the repository's `svelte.config.*` or `vite.config.*` files and uses its own Svelte, Prettier and preprocessors, which the status bar says. The `:svelte-config` list shows the files and approves their present text on this machine; a changed file asks again, and taking the approval back starts the server in reduced mode again. A rename in a `.ts` file reaches the `.svelte` files that use the symbol only after that approval is made, since the TypeScript server loads the Svelte plugin only for an approved configuration. A repository with no `svelte` package gets the server's own Svelte 4. For C and C++, clangd also gives folding, selection ranges, inlay hints, links on `#include`, dimmed inactive regions, Switch Between Source/Header (Alt+O), Show AST and Show memory usage, and its semantic colours. Each action is in the palette under the language's name, such as Python: Select Interpreter or clangd: Restart language server. Show Language Server Output opens the server's own log as a tab. pyright runs with the interpreter the status bar shows. That is the repository's `.venv` or `venv`, else the `python3` on oculus's PATH, else a path typed into the `:interpreter` list. A repository's own interpreter runs only after you approve it in that list, and the approval is kept for that path and repository on this machine. clangd runs with the compile database the status bar names. That is a `compile_commands.json` at the root or in a `build/*/` folder, or a configuration of the repository's `.oculus/cpp.yml`, chosen in the `:compile-database` list. oculus links the chosen database into its own `lsp` folder, so clangd's index is never written into a repository. `.oculus/cpp.yml` holds a `configurations:` list, each entry with a `name` and optionally `compile_commands` and `fallback_flags`. `compile_commands` is a folder of the repository that holds a `compile_commands.json`. `fallback_flags` are the flags for a file the database does not list, and a relative path of an include flag is read from the repository's root. A value that does not read is listed at the head of the compile database list, its entry is skipped, and the compile database item on the status bar is amber while there is one. The servers read the repository's own `.clangd`, `.clang-tidy`, `pyrightconfig.json` and `pyproject.toml`; oculus sets nothing else. A server that cannot start, not found or exited, says so on the status bar, and Restart Language Server starts it again. When the root stops being served, its server ends and the status bar says the root is not served; a tab still open under it is served again, without closing it, when the root is served again. A changed `lsp` key ends every server, and one with a tab open starts again at once under the new folder.

## Searching the files

The Search view runs one pattern over the files of one root or of every root, and the roots are the file browser's own: the hub, the engine's config folder, the roots `sources.yml` names, and whatever the workspace in force added. Nothing outside those is reachable, and the query never leaves the machine: the search is a local process reading local files, with no index and no service of any kind.

ripgrep does the reading, the copy that comes with oculus rather than one the account happens to have installed. What a repository ignores is skipped as ripgrep skips it, and `node_modules`, `.git`, `.svelte-kit` and `.svelte-kit-app` are skipped in every root whether or not a `.gitignore` says so. A hidden file and a hidden directory are skipped the same way, so a `.env`, a `.gitignore` and everything under a `.hidden/` folder are never opened. A folder chosen with Find in Folder... in the Files view is the exception: it is searched even when it is hidden or ignored itself, as ripgrep searches a path it is given, while the files and folders inside it follow the rule above, so a hidden file in it and an entry an ignore file names are still skipped, and the Search view says "In <root>/<folder>" above the box with a control that clears the scope. A file over two megabytes is not opened.

## The pattern

Three toggles decide what the pattern means: `word` matches whole words only, `case` matches the pattern's own upper and lower case, and `regex` reads the pattern as a regular expression rather than as text to find. Turning one over while results are shown, or while a search is running, runs the search again under the new toggles, so the preview and Replace use the toggles on screen. Finding every reference to a name is `word` over the root that holds the code, which finds a name in every file of the root. In a Python, C or C++ file, Find All References (Shift+Alt+F12) asks the language server, which finds the uses of that symbol and no other word of the same spelling. `case` is the only control over case: there is no smart case (an editor's `search.smartCase`, which matches case only when the pattern holds a capital), so a pattern is matched without regard to case until `case` is on. The files and the hits come in the order ripgrep answers them, which is not sorted, and the view lists them as they came.

## Running a search and reading the results

Typing runs nothing. Enter in the box and the Search control are the two ways a run starts, and `/` puts the cursor back in the box from anywhere in the results. A result heading opens its file at its first hit and a result row opens it at its own line, both in the source tab. The answer stops at the configured number of hits (`search.max_hits` in `behavior.yml`) and says so when it did; the reading stops there too, so a one-letter pattern over a large root costs what the cap needs and not what the root holds. Each root's search is given `search.timeout_s` seconds, and a root that fails or runs out of time is named under the count rather than passed over in silence. What a tab last found is kept with the tab, so a saved page draws its results again without running the search a second time. A hit is one match, so a line holding two matches is two rows, each with its own Replace and Dismiss.

The cursor lands on the hit's line once the file has loaded, and a line past the end of the file lands on its last line.

## Replace

Replace works as the editor's Search view does. The chevron at the start of the query row shows or hides the replace row: the replace box, the `AB` toggle (Preserve Case) and Replace All. Whether the row is shown, the replace text and Preserve Case are kept with the tab, and so are the last twenty texts each box ran, which Up and Down in the box walk, newest first. Enter in the replace box runs the search as Enter in the query box does, and Cmd+Alt+Enter in either box is Replace All. Cmd+Shift+F opens the Search view with the cursor in its query box and Cmd+Shift+H opens it with the replace row shown and the cursor in the replace box. While the row is shown each hit row draws the matched text struck through and the text that would replace it, which follows the replace text and Preserve Case as they are typed without a new run, and the count line says how many hits would be replaced in how many files. A hit offers Replace and a file heading Replace All in that file, under the pointer and on the focused row; Cmd+Shift+1 runs the one the focused row offers. Every hit and every file offers Dismiss, with Delete (Cmd+Backspace on macOS) on the focused row, which takes it out of the results without writing, and Replace All then leaves it out. After a Replace or a Dismiss the focus moves to the next row. After a Replace the hits left in a written file are read from the file as it is now, so each keeps the line and place the file has for the next Replace; a hit you dismissed stays out while its line is as it was, and comes back when the replace changed its line; a file whose hits could not be read keeps its row with "Search again to see this file's hits." A root that ran out of time or could not be searched is named on a line of its own under the count ("claude ran out of time.", "No answer from claude: ripgrep could not search it."), and the count says "cut at 500" only when the number of hits was reached. Replace All asks first, "Replace 12 occurrences across 3 files with 'bar'?", and when the search stopped at the configured number of hits it says that only the hits listed are replaced. One replace runs at a time. What a Replace All over the whole answer came to ("Replaced 12 occurrences across 3 files with 'bar'.") takes the place of the count line until the results next change (a Replace, a Dismiss, a new run or an edit of the query); a Replace of a hit or of a file leaves the count line, and a replace that fails says why. Pressing a hit while the replace row is shown opens its Replace Preview, a diff pane with the file as it is on the left and the file with this tab's replacements on the right, one pane per file, opened beside the Search view (in the pane of the other opened tabs, or in a new pane to the right of the Search view's, which the next previews land in) and never over it; a dismissed hit stays unreplaced in it, and after a Replace the next hit opens in the same preview.

## The replace text

The replace text is read as the editor reads it. In regular-expression mode `$0` is always the whole match and `$1` to `$99` are always the groups of the pattern, and `\n` is a newline, `\t` a tab and `\\` a backslash. `$<name>` (a named group), `$&` (the whole match) and `$$` (a dollar sign) take effect only when the replace text also holds a numbered reference, as in VS Code: `[$<name>]$1` writes the named group and the first group, and `$<name>` alone is written as typed. A group number the pattern lacks is written as typed. `\u`, `\U`, `\l` and `\L` placed directly before a group reference upper-case or lower-case the first character or the whole of that group's text. Without `regex` the replace text is written exactly as typed. Preserve Case gives the replacement the capitals of the match it replaces. In a file with Windows line ends a newline the replace text writes is written as `\r\n`. A file that a source tab holds with unsaved text is left out of a replace and named in the line that says what was done, since the search reads the disk and not the tab; a clean source tab on a replaced file reads the file again. The server decides what is written: it runs the search again over each file, refuses a file in which a named match is no longer where the search found it (`changed`), a file its mode locks (`denied`), a file that is not text (`binary`), a file over the save limit, `config/local.yml` and a file or a replace text holding one of the four private-use characters U+E000 to U+E003 that the search uses to read its groups (`marker`). A replace stops at the first refused file, names it and the files before it that were written (their hits are read again as well), and keeps a copy of every file it writes. The whole replace is one record of the History view, "Replaced in 3 files", with an Undo that writes each file back from its copy while every file still holds what the replace left, and, after that undo, a redo; the Timeline of the Files view lists those copies as File Replaced.
