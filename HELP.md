# Oculus

Oculus is the private working surface for the research hub: one page in a browser tab on this machine, or in the app's own window, reading the hub's YAML and Markdown from disk and showing it as boards, lists and documents. It writes only where a control says it writes: back into the same files and, from the Files view's right-click menu, files and folders under the roots the view serves. The Help page holds this manual, the [Apps guide](docs/apps.md) and the Memories wall, the hub's documents open from the Help group of the Views catalogue, and `README.md` says how to run and check oculus.

## The window

- Oculus runs in a browser tab or in its own app (Electron, run from the checkout or packaged as `oculus.app`, as `README.md` says).
- The app starts the server itself and ends it when it quits, leaving the tmux sessions running; started again it opens its windows where they were, and a second start brings the running app forward. When the server ends on its own, a dialog quotes why and offers Restart: the open windows keep their pages, unsaved text and running terminals, reconnect by themselves, and a window on another port than the new server's goes to the new one with its arrangement, settings and unsaved text.
- The app adds windows that remember where they were, a floating pane that becomes a window of its own, a native folder sheet for Add Folder to Workspace, a find bar, spelling suggestions in a text box's menu, a dark window frame and the keys marked "in the app" in [The keys](#the-keys).
- The app prints the Present view's PDF export through a hidden window and opens the audience window of the presenter screen (the slide alone, in full screen on another display when there is one and beside the window when there is not); Close Window with it focused closes it and ends the presentation. A page in the app with no stored theme starts on vscode dark modern, a link to another site opens in the default browser, and the windows of the app share one arrangement as browser tabs do.

### The rail

- The rail draws one button per entry of the `rail:` list of `config/layout.yml`, each `{label, glyph, page}` where `page` names an arrangement under `arrangements:`. A browser with no saved layout starts on the first and draws no page until the configuration has named it.
- A button shows its page: made from its arrangement the first time and shown as it was left after that. Its badge counts the first view of the page that counts anything, in the order of the page's tabs (the arrangement's views before the page is first made).
- Drag a button to move it; right-click it (or press Shift+F10) to hide it, reset its page to its arrangement or open the rail list in Settings. Hiding and moving rewrite `rail:`, and History undoes either; hiding the page on screen leaves it on screen. Reset asks first, then about each tab of the page holding unsaved text as closing it would (a no to any leaves the page as it was), and rebuilds the page from its arrangement, closing every tab it held.
- Every listed view sits on exactly one rail page, except Live HPC and Usage, which sit in a float on every page. The Views catalogue on the System page lists each page's views and the hub's documents under the page's name (the Help page's under Help, reached by `h`), and `nav_groups` and `docs` decide the groups, their order and their letters.
- A click on a Views catalogue entry opens the view on the page you were on before the System page (on the catalogue's own page when you moved the catalogue onto a page of yours), in the pane whose tab was activated last, and activates a view already open there; a unique view, and a hub document that a page or float already shows, goes to the page or float that holds it by a click or a shift-click, and a shift-click on any other view opens it in a new pane to the right that the next shift-click joins as a tab. An entry's right-click menu (or Shift+F10) offers Open on this page and Open beside on this page, a drag onto a pane of that page opens it there, and the catalogue's own pane is never covered.
- The Help page's tabs are the `help` arrangement of `config/layout.yml`: this manual, the Apps guide and the Memories wall, with the hub's documents added after the manual, in the order of the hub's `docs:` list, each entry whose `group` is `help` (on this hub Research approach, Agent approach, HPC how-to and Data map). Any page whose key a `docs:` entry names as its `group` gets that entry as a document tab in the same way, after its first tab. A saved page is given each document it lacks when it is restored, once, a tab the reader closed stays closed, a document added to the list later is added once, and Reset makes the page with every document. The Apps guide is a document of oculus's own folder, so it opens on any hub whatever that hub's `docs:` list holds, and the manual's links to it and its link back to the manual open the other document.
- An entry of the hub's `docs:` list (Research approach, Agent approach, HPC how-to and Data map) opens by its `h` chord or its row in the Views catalogue in the page you are on, and when a page or float already shows it (on this hub the Help page shows all four) the chord and the row show that tab there and put its page on screen; Open on this page and Open beside on this page in the row's right-click menu open a copy on the page you are on; a document tab saved at a path the list no longer holds follows the entry carrying its label, or closes into the tab already showing that entry, and a tab that matches no entry names the path it asked for.
- A document tab of the hub whose path lies inside oculus's own folder, saved in a layout or opened by a `docs:` entry, becomes the oculus document at that place and closes into the tab already showing it, so a guide is one tab. A document tab of oculus's own folder acts as the file it is at the folder's place in the hub: its breadcrumb, its icon, its right-click menu (Copy Path, Reveal, Show in Files, Open Timeline, bookmark and Open in Program), its row in Open Editors and the Timeline all name that file; when the folder lies outside the hub the tab names no file. The tab is named by its label, or by the last name of its path when it has none.
- Bookmarks at the foot of the rail is the star menu of `bookmarks.yml` in the hub's `.oculus` folder, which the Files view adds to and takes from, each bookmark opened as a tab of its own.

### Pages and the pane tree

- A page is a whole working surface with its own tree of splits and panes, each pane a strip of tabs, and the layout is saved as it changes. The browser tabs of one server and the windows of the app share the arrangement and each tab's state (a Terminal tab's composer and a view's forms and filters included), while each keeps its own page on screen and its own appearance; two that change the same thing at once end with the last change.
- The Pages view lists every page with show, rename and close (close asks first when the page holds more than one tab); a page of a rail button also offers Reset to its arrangement. Dragging a page's row onto a pane's edge shows that page there.
- Settings holds Reset all pages, which asks first, then about each tab holding unsaved text (a no to any ends the reset with nothing changed), rebuilds every page of a rail button from its arrangement, removes the pages of buttons the rail no longer has, puts the floats of `config/layout.yml` back and leaves the pages you made and every workbench as they are; a unique view held by a float of yours or by a rail page being rebuilt is closed with it and opens anew without its state.
- Eleven views are held once, each by one page or float at a time: Settings, Focus, Usage, Live HPC, Audit, Findings, History, Processes, Pages, Workbenches and Status. Opening one goes to the page or float that holds it, looking first in the pages drawn on the page on screen, then in the floats, then in the other pages in the order the Pages view lists them; Files, Search, Terminal and the session views may be open on several pages.
- A page made from its arrangement by the first press of its rail button or by Reset takes the unique views the arrangement names from the page or float that holds them, with their state; New page leaves a unique view out when a page or float holds it, Copy into New Window is not offered on one, and a layout saved with two copies of one keeps both until you close one.
- Split a pane by dragging a tab onto its edge or from the pane menu; fold and maximise are controls of the pane, and a folded child is saved folded. Every drag has a menu equivalent the keyboard reaches: the pane menu splits, floats, closes and maximises a pane and moves a tab to another page, and Shift+F10 opens the menu of the focused control.
- A leaf of a page's tree can be another page (Show a page here... in the pane menu), drawn where it sits with a header naming it: it is the same page itself, so a tab opened in it is open wherever that page shows, and a page never contains itself and is drawn at most once on a screen. A drop on a pane of a page shown inside another page lands in that page.
- Float in the pane menu or the strip's right-click menu floats a pane, and a tab dragged with Alt (Option on a Mac) held floats at the pointer. A floating pane stays on screen when the rail switches pages and while a pane is maximised, holds one pane of tabs (no split, fold or maximise) and is placed by fractions of the window, so it scales with it and may lie over the rail and the status bar; drag the empty part of its strip to move it and its edges or corners to resize it.
- A float let go within 24 pixels of the left, right or bottom edge docks there as a strip whose handle sets its size, and docking a second float on that edge joins its tabs to the first. Return to Page in a float's menu puts its tabs into the page on screen as a new pane split off the right of the largest pane, and a float disappears when its last tab goes.
- A view opened for something (a project, a person, an entry, a document, a file, a diff) never covers the tool views of its page. It lands in a workbench's documents pane, else in the pane that received the last such tab on this page, else in the pane you are in when that pane already holds such tabs, else in an empty documents or terminals pane, else in a pane holding such tabs and nothing else, else in a new pane split off to the right of the pane you are in, which the next one joins.
- A tab of that document already open anywhere on the page is activated where it is, a maximised pane of tools is restored first, and the rule moves no tool view. A tool view that asks for a tab (the Search view's Replace Preview) is never landed in: when no other pane takes the tab, a new pane is split off to its right.
- A pane the page's arrangement defines stays, empty, when its last tab closes (an empty pane says what appears in it), and so does the first pane of a page made by New page or of the Page 1 that closing the last page or Reset all pages leaves; a pane split off while the page is used closes with its last tab. Lock Group in a pane's right-click menu makes it take no tab opened from elsewhere (a tab can still be dragged onto it) and keeps it when its last tab closes; a page keeps at least one pane, and Close pane removes any pane.
- A new tab opens right after the active tab, after the pinned tabs when the active one is pinned, and closing the shown tab shows the one shown before it; both are VS Code's defaults and have no setting. Pin in a tab's right-click menu, Pin Editor in the palette (Cmd-K Shift+Enter) or a drag into the pinned tabs moves a tab to the start of its strip, where a press on the pin unpins; a pinned tab keeps its pin when its pane floats, moves to another page or splits, stays open through Close Others, Close to the Right, Close Saved and Close All, and Delete on it closes nothing.
- `show_tabs` (`multiple`, `single` or `none`), `editor_actions` (`strip` or `hidden`) and `wrap_tabs` of `appearance.yml` set the tab strip; they are also in Settings and in the strip's right-click menu. With `wrap_tabs: true` a `multiple` strip wraps the tabs it cannot fit onto more rows, and the key is ignored under `single` and `none`.
- New Text File, in the right-click menu of a strip's empty part or of an empty pane, opens an untitled text in that pane; its first Save asks for a folder among the served folders and for a name, which may hold folders that are made, and a name that leaves the folder is refused.
- A right-click elsewhere shows no menu, and the browser's own menu stays inside a text box, the code editor and the terminal. In the app a misspelt word adds spelling suggestions at the top of a text box's menu.
- A tab showing a file draws the file's path as a breadcrumb: a press on the root or a folder shows the Files view at that folder, a press on the file shows it there, and in a source tab whose file has symbols the path goes on with the symbols that hold the caret, each moving the caret when pressed.
- A tab holding text no save has taken shows a dot in the close control's place (a screen reader hears ", unsaved" after its name) and is closed only after a confirmation, whether the close came from Delete or from the tab's own control. That text is a source tab's unsaved edit (an entry that Add put in the tab included) or a field of the manifest editor not yet saved, which is there again after a tab switch and a reload; closing a pane or a page asks about each such tab, and a page shown inside the closed page keeps what its tabs hold.
- While a tab holds unsaved text of a file, the controls that write it in the collection, registry, Position Leads and Focus views are disabled, and a write from any view or from an app over that file is refused before it is sent, so the tab's text is never written over.
- In a source tab's editor, where Tab indents, an Escape that closes nothing of the editor's lets the next Tab move the focus on. The rail is one stop and each tab strip is one stop with its pane menu the stop after it; the arrow keys move inside a strip, which stops on the tab they left. Ctrl and a digit still shows its rail page while a field, the palette, the update tray or a confirmation holds the keyboard.

### Workbenches

- A workbench is a page that belongs to one folder of a served root. Its left pane holds Files rooted at the folder, Search, Repositories (the repositories inside the folder and the one that holds it), the TeX view, Problems and the sessions list (the sessions working in the folder or filed into it by their area, and the terminals started in it), each limited to it, and its right pane is the documents pane; the arrangement is the top-level `workbench:` key of `config/layout.yml`, which no rail button names.
- Open Workbench on a project card, a collection card whose link names a folder, an entry page, a side project card or the folder block of a person or entry page, or Open in New Files in the Files view's menu of a folder or a root, opens one; the venue card's Show in Files and a worktree's opening do not. A workbench for a project, an entry or a side project is named by its title and opens that item first (the project view, which a side project has too, or the entry page); one for a folder alone is named by the folder's last name or the root's key, with an empty documents pane. The Files and LaTeX tabs of a workbench are named Files and LaTeX.
- A folder that already has a workbench shows that page, compared by root key and path, so one folder reached through two roots has two workbenches. A limited tab says `In <root>/<path>` and has a control that widens that tab alone to the whole root; for a workbench of a root itself the sessions list alone draws the line, and a Search, Problems or TeX view tab limited to a root the workspace does not serve says so (the Search tab sends no search).
- The documents pane is the empty pane of `workbench:`, so a view opened from the workbench lands in it first, also after a reload; a session picked in the sessions list opens its Transcript and Timeline there, and New shows the composer in a Terminal tab there, with the workbench's folder as its working folder. The Workbenches button at the foot of the rail lists the open ones by their words with the one on screen marked, a press shows one, closing one there asks first about unsaved text and running terminals, and Manage Workbenches under the list shows the Workbenches view. The Pages view lists a workbench with Reset layout beside Rename and Close.
- The Workbenches view, the last view of the System group in the Views catalogue (so it has no chord of its own and every chord of that group stays), lists two sections. Open has one row per open workbench in page order with its folder (`root/path`, or the root's key for a root's top) and the branch of the repository holding that folder; the workbench on screen is the bold row, a press shows a workbench, and a row's controls reset its layout or close it, each asking as above. Closed has one row per kept layout, the one closed last first; a press or Reopen opens the workbench from its kept layout, with fresh tab ids when another page or float holds one of the kept ones, and Forget asks first and then drops the kept layout, so the next workbench of that folder is made fresh. A kept layout of a root the current workspace does not serve is dimmed with a warning mark at the row's end whose tooltip says so, and can be forgotten but not reopened; while the workspaces are still being read none is dimmed. New workbench, the icon in the view's header, lists the roots of the Files view, each opening the workbench of that root's top, and Open Folder..., which shows the folder panel: a folder inside a served root opens its workbench at that root and path, one outside every root is added to the workspace as Add Folder to Workspace adds it and its workbench opens at the new root's top, and a cancelled panel does nothing. The view opens like any unique view; when no page or float holds it and the page on screen is a workbench, it opens on the System page of the rail, else on the first page that is no workbench, else on a new page, never inside a workbench.
- Closing a workbench keeps its layout by folder in the browser's saved layout (its tabs and the state each view holds, except a source tab's text and the terminals of a Terminal tab), twenty at most: closing a 21st drops the one closed longest ago. Reset layout asks first, makes the workbench again from `workbench:` with the folder given to each tab and drops the kept layout, and Reset all pages leaves workbenches and kept layouts as they are.
- A unique view opened while a workbench holds it goes to that workbench. A workbench made from `workbench:` or again by Reset layout takes the unique views the arrangement names from the page that holds them, and one restored from a kept layout leaves out each unique view another page or float holds.

### The palette

- Cmd+K opens the palette (Cmd-K and Ctrl-K work inside a source tab's editor too): with nothing typed it lists the views, and a typed word matches fuzzily, its letters in order (`rpls` finds RAW-PLS), across views, projects, collection entries and feed entries, each result naming its kind. The opened result's tab takes the keyboard.
- While a source tab is on screen the palette also lists the editor's own Cmd-K commands as Editor (Add Line Comment, Fold All, Pin Editor among them), and while a Present tab is on screen Edit Slide, New Slide, Duplicate Slide, Delete Slide and Export to PDF. A colon starts a command: `:` and a number go to that line of the source tab, `:language` lists Auto Detect, Configure File Association (written into `languages:` of `sources.yml`, undoable in History), the language's settings and the languages, and `:interpreter` and `:compile-database` choose what pyright and clangd run with.
- Cmd+P lists files by name across the served roots, matching the name first and the whole path after, at most 200 rows with the file's icon and its folder; with nothing typed the rows are the file tabs open on the page. Enter or a press opens the file in the view the Files view would choose, in the pane the palette was opened over, as a kept tab, and Cmd+P closes the palette when it is open in this mode.
- The names are read once each time the file mode opens: hidden files and folders are listed, `.gitignore` is honoured, `node_modules`, `.git`, `.svelte-kit` and `.svelte-kit-app` are skipped, the machine's private folders are left out (a served root that is a private folder or lies inside one lists no name at all), no size limit applies and links are not followed. Each root's listing gets `search.timeout_s` seconds, and a root that fails or runs out of time gives the names read so far. A file under two roots is listed once, under the root whose folder is deepest; the list stops at `search.max_names` names (100000 by default) and says so, and a colon typed first leaves the file mode for the command mode and a hash for the symbols.
- A `#` (Cmd+T in the app) searches the workspace's symbols through the language server of the source tab on screen, each result with its kind, container and file. F1 is taken from the source and diff editors, so Monaco's own palette does not open there, and Cmd+Shift+P or F1 pressed with the palette open in another mode switches it to the command mode.

### The update tray and schedules

- Update at the foot of the rail opens the tray of schedules (the entries of `schedules.yml` in the hub's `.oculus` folder) and update tasks (Lit Watch, Scout, LinkedIn and Inbox). A task runs the `/research-cockpit` skill as an ordinary Claude session in a terminal, where you answer its permission prompts, and Chat starts a portfolio-wide Claude session.
- A schedule runs an update task, a saved command or a prompt on a cron pattern in the machine's local time. The schedule dialog shows the next three runs before it saves, and opens filled in from Schedule... on a task or in the right-click menu of a saved command.
- `schedules.yml` may be edited by hand: the dialog, Pause and Resume change only the keys they change and keep every other key, its order and every comment. An entry is `- name: Weekly radar` with `runs: { task: litwatch }`, `when: "0 7 * * 1"` and the optional `paused: true` and `unattended: true`; an entry without `when` runs only from Run now.
- `runs:` takes `{ task: litwatch }`, `{ command: sync, folder: ~/workspace/research-hub }` for a saved command, or `{ prompt: "Summarise what is blocked", folder: hub }` for the first message of a Claude session started in the hub folder or in a root the file browser serves. A row lists its latest five runs, a run whose terminal is still listed opens it, and Pause and Resume, Run now and Delete act on the entry.
- A run missed while oculus was stopped starts once when it starts again; a run whose due time came while oculus was stopping shows `failed` with the sentence that the server stopped before it started. A due time that arrives while the earlier run is working starts nothing and is listed as skipped, and one that arrives while the earlier terminal is idle or ended closes that terminal and starts a new run.
- Run unattended starts the run with `--dangerously-skip-permissions`, so an agent edits files and runs commands with nobody asked; it applies to an update task or a prompt, a saved command always runs with it off (so a command entry whose `unattended` value oculus does not read is saved with it off), and a chain holding a command from a file or a found command is refused until it is approved from the command bar.
- A schedules file or run record that does not read stops every schedule, is said in the tray and is never written over. The run record is `schedule.json` under `~/.oculus`, and the keys `tasks.skip_permissions` and `chat.skip_permissions` are not read: a file that carries one gets a finding that names Run unattended. A save, Delete, Pause or Resume the tray cannot make is refused with its sentence and writes nothing, and an entry that shares a block with another through a YAML alias is changed by hand.

### The status bar and notifications

- The branch and sync items follow one repository, named by the repository item at the left of the bar: the repository holding the active tab's file (a Files or LaTeX tab counts by the folder it shows), else the one holding the folder of the workbench on screen, else the one last chosen in the repository item's list, else the hub's. A file or a workbench folder in no repository decides, and the repository, branch and sync items are then not drawn. A press on the repository item lists the repositories of the Files view (each repository at or below a served root that git reads without an error, a session's workspace outside the served roots not among them) with the followed one marked, and a pick becomes the one last chosen, kept in this browser tab's saved settings; when a file or a workbench decides, the list says the pick is drawn once neither does. A chosen repository the git channel does not report yet (after a reload) is kept and the hub is followed until it does; one no longer under a served root is dropped. The repository item hides like the others.
- On the status bar, switching the branch and syncing the followed repository ask first: sync pushes a branch that is only ahead, otherwise pulls then pushes, and with no upstream offers Publish Branch. A press on the problems item shows or hides the Problems view and keeps its filter for the page, the debug item (once a session has run since the server started) lists the configurations, and a right-click on the bar hides or shows any item.
- For a source tab, a press on the blame item opens the caret line's commit in the Repositories graph, the line and column open the palette on `:`, the indentation, the encoding and the line ending each convert the text, and the language server's item lists Restart Language Server and Show Language Server Output.
- The LaTeX item shows while the active tab is a LaTeX source or a build's PDF, or while a build runs, and a press shows the TeX view. It is in the warning tone while a build or clean waits for the approval of a latexmkrc file or a weave tool (a press opens the list to approve, of the main file that has waited longest).
- The bell counts unread notifications and opens the notification centre (Clear, Clear All and Do Not Disturb, which stays on after a reload); a toast shows for eight seconds. Notifications come from a refused rail change, a session waiting on a permission prompt or for input, an update task that ran, a Live HPC job that ended, and a write that was refused or got no answer.

## The keys

The key sheet opens with `?` and closes with `?` or Escape; its letters before a digit are the `direct_chord` of `config/layout.yml` and the `chord` of each group in `nav_groups`. A group's documents follow its views, and a chord reaches the first nine entries of a group. Every view sits in a group with a letter of its own, so the direct chord reaches nothing and the table has no row for it; a group that names no `chord` gives it entries again.

- TeX view: it follows the root of the active LaTeX source tab or build PDF; Structure adds the `\label`s and floats once the root is built and says when the parser refused a file, and a press on a Math Symbol inserts the command at the caret. A saved `latex` tab that names a folder and no main file opens on the first main file of that folder; Math Preview (Cmd+Alt+M) renders the math at the caret with KaTeX, follows the caret and takes the document's `\newcommand`s as macros.
- References: Find All References, Find All Implementations and the call or type hierarchy list their locations, and a press opens the location with the match selected; a location in a library file opens the read-only library tab, which says after a reload that the file is no longer open. A hierarchy's first level is the incoming calls or the supertypes (the title's arrow swaps to outgoing calls or subtypes) and each node opens one level.

### LaTeX builds

- A LaTeX file builds through a root, found by four rules in order: the `% !TEX root = <path>` comment among the first lines (followed through the files it names; a comment naming a file outside the served root or a non-source file is passed over), the file itself when it declares a document class, the main file of its folder or of the nearest folder above it in the served root whose includes (`\input`, `\include`, `\subfile`, `\import`, its bibliographies and `<main>.fls`) reach the file, and the only main file of the file's folder. A `.bib`, `.sty` or `.cls` file takes the last two rules.
- `% !TEX program = xelatex` or `lualatex` picks that engine's recipe, and `% !LW recipe = <name>` picks a recipe by name; a name no recipe has is refused. A build is a recipe of `latex.recipes` and `latex.tools` in `config/behavior.yml` with LaTeX Workshop's placeholders (`%DOC%`, `%DOC_EXT%`, `%DOCFILE%`, `%DOCFILE_EXT%`, `%DIR%`, `%OUTDIR%`, `%AUXDIR%`); `latex.recipe_default` says whether a build with no choice takes the first recipe or the last one used, and `latex.out_dir` and `latex.aux_dir` name the folders it writes to, refused when they leave the served root.
- A build runs as a task terminal in the root's folder, and a program the recipe needs that is not found is named before any terminal starts. A build or clean that runs latexmk reads the latexmkrc files latexmk would read (the main file's folder and each folder above it up to the served root, `~/.config/latexmk/latexmkrc` or `$XDG_CONFIG_HOME/latexmk/latexmkrc`, and `~/.latexmkrc`), and a recipe tool that runs the document's code (`Rscript`, `julia`, `pweave`, `quarto`, `R CMD Sweave`) counts the same way; a latexmkrc file that cannot be read refuses the step with its path.
- Neither runs until you approve it on this machine: a press on Build or Clean lists the files and tools in one question and starts nothing, Approve writes both approvals and runs the step once, and a changed file or tool asks again; Rerun and Restart on the terminal ask again and are refused when the file is no longer a main file. An automatic build or clean waits for the approval too, and when `latex.clean_and_retry` finds the clean unapproved the failed build ends as failed and Approve runs the clean and then the build once more.
- `latex.auto_build` is `on_file_change` (the default; builds once when a file of the includes changes on disk, the writes within `latex.auto_build_interval_ms` counting as one), `on_save` or `never`. `latex.auto_clean` is `never`, `on_failed`, `on_succeeded` or `on_built`, `latex.clean_and_retry` cleans and builds once more after a failed build, and `latex.texcount_autorun` set to `on_save` counts the words after a save. A save or change during a build is built once more after the running one, a Clean during a build is refused, and Save without Building starts no build.
- A failed build posts a notice, once until a build of the root succeeds, with Open Compiler Log and Show Problems; its errors and warnings (bad boxes as warnings) are listed in the Problems view and drawn as markers in an open source tab, and the count in the TeX view and the project panel opens that view limited to the root. A build after a stopped or failed one passes latexmk's `-g` so it runs.
- The PDF opens in oculus's own viewer as a `file` tab, and the first build of a root opened from a source tab shows it beside the tab. Its place (page, offset, zoom, modes, side panel; not inverted colours) is kept per tab across a reload and per file for the last 50 files, a rebuilt PDF loads in place and a failed build leaves the old document shown.
- SyncTeX runs through the `synctex` program (`latex.synctex_path` names it when it is not on PATH). Show the PDF at the caret scrolls to the page of the line and draws a rectangle that fades, and a root with no `.synctex.gz` says so and offers the build that writes it; a click on a PDF page with Cmd or Ctrl held opens the source line in the pane that holds a tab of that file, else beside the viewer (from a viewer in a window of its own, in the main page that opened it), does nothing on a place with no record, and refuses a record naming a file outside the served root.
- In a LaTeX tab, resting the pointer on math or an `\includegraphics` path shows the formula or the picture, on a `\ref`-like command the label's number and the block it sits in with a link to its place in the PDF, and on a `\usepackage` name a link to the package's documentation. `\` and an environment's name inserts the environment with its closing line, `_{` or `^{` offers the sub- and superscripts the text already uses, and `@` suggestions are LaTeX Workshop's table.
- The editing commands (jump to the matching environment or bracket, select an environment, its content or its name, toggle display math between `\[...\]` and an equation environment, close the open environment, wrap the selection in an environment, surround it with a command, promote and demote sections, select the section, smart selection) are each one undoable edit. `latex.unimath_symbols` (off by default) and `latex.includegraphics_preview` (on by default) switch the Unicode math symbol and picture completions.
- A LaTeX or BibTeX tab that texlab serves also gets hover on a `\ref` (the label's text) and a `\usepackage` name, completion of `\cite` keys, `\ref` labels and package names, Go to Definition, Find All References, Rename Symbol and the Outline. A `.bib` tab has Align, Sort and Align and Sort, each an unsaved edit, and Citation Browser lists the entries of the root's bibliographies and inserts `\cite{key}`; texdoc asks for a package name (offering the root's packages) and opens its documentation on this machine, Count Words runs `texcount`, and checkcites runs on the root's `.aux`.
- A file over `editor.paint_limit_kb` keeps the breadcrumb bar, the keys, the build, the PDF and SyncTeX and loses hover, completion and the editing commands, unless a language server serves it. Format Document in a LaTeX tab uses the program `latex.formatter` names (`none`, the default, which formats nothing and says so, `latexindent`, `tex-fmt` or `badness`), found on PATH unless `latex.latexindent_path`, `latex.tex_fmt_path` or `latex.badness_path` names where it is; a program not found is named with where to set its path, and the formatted text is an unsaved edit that undo takes back.

## Files and the editor

- The Files view follows the disk: a file or folder made, renamed or deleted under a root by anything else appears or goes within a couple of seconds. Show Hidden Files (dotfiles and the `node_modules`, `__pycache__` and `.git` folders), Show Ignored Files and File Nesting (the patterns of `catalogs/file-nesting.yml`) are off until turned on and kept per tab.
- `:workspace`, `:workspace-save <name>` (which says why when the name is empty or taken) and `:folder` in the palette switch the workspace, save it under a name and open a folder, as the view's `...` menu does. In the default workspace an added folder is written to the `roots:` list of the hub's layer `.oculus/config/sources.yml`, and Remove Folder from Workspace removes the entry; the hub and the engine's `config/` folder have no Remove, and in a saved workspace a configured root offers none either.
- Add Folder to Workspace opens the system's folder panel and adds every folder it returns that is not a root already, naming each skipped one; it is disabled while the panel is open, and a cancelled panel adds nothing. A root other than the hub and `config/` is moved by drag or by key, and the order is written to `roots:` as an undoable write; bookmarks, notes and the sections under the tree reorder the same way.
- The bar's filter box matches over the folders already read: with Fuzzy Match off a name matches when it holds the typed text, on when it holds the letters in order; a match is drawn open under its folders, which stay open only while the text is there.
- The tree is one Tab stop, and Tab from a row reaches its controls. On a focused row Enter and F2 rename, Cmd+Down opens a file as the pane's preview tab and opens or closes a folder, Cmd+Enter opens a file beside the pane, Cmd+Backspace deletes, Cmd+C, Cmd+X and Cmd+V copy, cut and paste, Escape cancels a cut, Space opens a file kept in the background (it extends a pending type-ahead instead), Option+Cmd+C copies the path, Option+Shift+Cmd+C the relative path. A name with several segments makes the folders between.
- A press selects a row, Cmd or Ctrl toggles it, Shift selects the range, and a menu or key acts on every selected row when the row is one of them. Enter on a root, on the workspace header or with two rows selected does nothing.
- Show in Files of a folder (a project card, a person's supervision folder, a collection card whose `link` names a folder, the folder block of an entry page) opens a Files tab rooted at that folder with no workspace header and a `..` row that moves the top up one folder; Open Folder... does the same when a root holds the folder, else says the folder is outside every root and offers Add Folder to Workspace.
- Show in Files of a file (on a project card, a collection card whose `link`, `url` or `folder` is a path of the hub, a venue card and a person's supervision folder) opens the folders above that path, selects it and clears the filter, restoring the panes when a maximised pane hides the view. A path is read by its segments, a path that climbs above the hub gets no control, and a path that is not there selects the nearest folder on its way and says so.
- A star on a file or folder row adds a bookmark to `bookmarks.yml` in the hub's `.oculus` folder under the file's name (its path below the root when the name is already a label); the Bookmarks head has no add control, each bookmark row has Rename Bookmark... and Remove Bookmark, History undoes them, and the file is watched, so a bookmark added outside oculus reaches an open page. A folder bookmark opens the folder selected in the page's Files tab, and notes reorder in `order.json` of the notes folder, which refuses the move when it does not read.
- A scratch note is a file in the `notes` folder, made by the first keystroke typed into it, and the delete control in the Notes list is the only way to remove a note. Close All in Open Editors asks first, and Outline follows the file tab last looked at and lists the headings of a Markdown or LaTeX tab or the symbols a language server gives, and AST and Memory Usage sections appear for a C or C++ file after Show AST or Show memory usage.
- The Timeline section lists the saved copies of one file and the commits that touched it (fifty at a time, followed across renames; Load more reads the next fifty on a press, on Enter or when it scrolls into view). The file is the pinned one, else the selected one, else the file tab shown last; Open Timeline in a file row's menu or a tab's menu shows it on that file and releases a pin, and a press opens the diff of the copy or commit. Restore on a copy writes it back through the source save, which first copies the text it replaces.
- The Files tab of the Sessions page follows a session: its tree is rooted at that session's workspace folder, the session the pane is locked to else the selected one, and the follow toggle in its toolbar turns following off and back on.
- Delete asks first, names the rows when several are selected and moves them to the macOS Trash; a folder that is not a link is named "and its contents" and a link to a folder is named alone, since deleting a link removes the link only. It deletes for good only when the Trash fails, after a second question, and the first question carries a Do not ask me again box, which writes `files: { confirm_delete: false }` to `behavior.yml`.
- A drag onto a folder moves after asking, and with Option held copies; files dragged in from the system upload, and a folder dragged in from outside is refused. Pasting a Copy onto a taken name takes the next free name and asks nothing, pasting a Cut onto a taken name asks before the replaced item goes to the Trash, and a rename or a move restates the open tabs over the file and the bookmarks on it.
- Every create, rename, move, copy, paste, upload, trash and delete is a record of History with an Undo (Cmd+Z in the Files view takes the newest back, Shift+Cmd+Z redoes it). An undo of a delete asks first and writes back each file whose content was kept: a file up to 5 MB, and the newest 50 such copies over all files, so a larger file, the files inside a deleted folder and an older delete stay gone; an undo of a create, copy, paste or upload moves what it made to the Trash while each file is as it was left, and an undo of a rename or a move moves it back while the old name is free.
- The local history is the `history` key of `local.yml`, `~/.oculus/history` by default: one folder per file, named by the first 16 hex digits of the SHA-256 of its real path, holding `entries.json` and one copy per save. A save keeps at most 50 copies per file and none of a file over 256 KB, and nothing is written outside the served roots or to `config/local.yml` from the Files view.
- Every text file opens in a source tab, and a file counts as text by its own first bytes, whatever its extension. A file this machine locks, a file too long to have been read whole, a version at HEAD or in the index and a file that is not UTF-8 text throughout open read-only under a line saying why, and a file the server says is gone opens a tab that says so with Read again.
- A single click opens a preview tab in italics, and the next single click in that pane points it at the file it names; a second click on the same file, a double click on the tab, typing, dragging or splitting keeps it, and a second press within 500 ms of the first click keeps the tab the first click opened. A press on a Problems row opens its file the same way, a press on a row whose tab already shows it after the caret moved selects the range again.
- A save copies the text it replaces into the local history and replaces the file through a temporary neighbour and an atomic rename; it refuses a file that holds a NUL byte or is not UTF-8 text, a file that starts with the UTF-8 byte order mark keeps it, and a file replaced by a folder is refused with a sentence.
- A source tab keeps the SHA-256 of the bytes it last read or wrote, and the server polls every open file twice a second. A tab with no unsaved text reads a changed file again and keeps its caret and scroll; a tab with unsaved text keeps its text and says the file changed on disk, and its save is then refused with "Failed to save", Compare (the disk's file on the left, the tab's text on the right), Overwrite (saves without the hash) and Revert (reads the file again), and Revert File in the bar does the same without a refusal first.
- A file deleted on disk keeps its tab and text, struck through, and its next Save writes it again when its folder is there. A tab whose root is no longer served keeps its text, offers no Save (Cmd+S and the palette's Save say so, and an automatic save writes nothing) and keeps the mark across a reload; when the root is served again a tab with no unsaved text shows the disk's text and one with unsaved text keeps it. A draft kept across a reload whose file changed meanwhile keeps its edits and is marked changed as a tab is.
- `editor.autosave` is `off`, `after_delay` or `on_focus_change` (which saves a tab when its editor loses focus and every such tab when the page does), with `editor.autosave_delay_ms` as the wait, restarted at each edit. Only a tab that holds unsaved text, was read whole, may be written and has heard of no change of its file is saved this way; a refused automatic save is not tried again until the next edit, `after_delay` formats nothing, and changing the key from `off` saves every tab holding unsaved text at once.
- Closing a tab with unsaved text under `on_focus_change`, or under `after_delay` with a delay of 1000 ms or less, saves it first and asks only when the save is refused. A save trims trailing whitespace when `editor.trim_trailing_whitespace` is on, then formats when the language's `format_on_save` is on (through the language server; Python saves as typed), then ends the text with one line ending and no empty lines after the last text when `editor.final_newline` is on; each is the smallest edit, so the caret and scroll stay and one Cmd+Z puts the text back.
- A line ending that is there is never changed, a text with CRLF is ended with CRLF, and an automatic save leaves the whitespace before the caret. `editor.languages` holds a record per language (its keys are in Settings). Indentation is taken from the tab's own choice on the status bar, then the file's own indentation (a file indented with tabs keeps them), then the root's record, then `editor.languages`, then the global keys; word wrap from the tab's Alt+Z, then the root's record, then `editor.languages`, then the global key; rulers from the root's record, then `editor.languages`, then none.
- Alt+Z turns the wrap off when it is on, returns it to the configured value when it is off and the configured value wraps, and sets it on when both are off, and the tab keeps the result across a reload; the minimap, whitespace and sticky scroll are the global keys alone, and the diff editor takes the language's wrap, rulers, whitespace and sticky scroll with no minimap and falls back to the inline layout under 900 px of pane width; every other editor setting is Monaco's default.
- A repository's `.oculus/settings.yml` may hold a `languages:` map of the same records, which overrides `editor.languages` for the files served from that root; any other top-level key is not read, is marked in the editor and is listed as skipped under the Languages row of Settings.
- A Python, C, C++, TypeScript, JavaScript, Svelte, YAML, Markdown, LaTeX or BibTeX file is served by a language server oculus starts in the background for the file's root (pyright, clangd, `typescript-language-server`, `svelte-language-server`, `yaml-language-server`, `vscode-markdown-languageserver` and `texlab`) and ends 60 seconds after the last tab of that root and language closes; a changed `lsp` key ends every server. A server that cannot start says so on the status bar, Restart Language Server starts it again, and a root that stops being served ends its server until it is served again.
- A server gives hover, Go to Definition, Declaration, Type Definition and Implementation, peek, Find All References (listed in the References view; pyright offers no Find All Implementations), highlights, completion, signature help, diagnostics (listed in the Problems view) and the document symbols of the Outline. An item the server does not offer is left out of the menu and the palette.
- Format Document comes from clangd, the TypeScript server and the Svelte server, Organize Imports from pyright, the TypeScript server (with Remove Unused Imports in Source Action) and the Svelte server, and Show Call Hierarchy and Show Type Hierarchy list in the References view. For C and C++ clangd also gives folding, inlay hints, links on `#include`, dimmed inactive regions, Switch Between Source/Header, its semantic colours and a line formatted after Enter.
- A definition outside every served folder opens in a read-only library tab named for the file, with hover and Go to Definition answered inside it, that lasts until the page reloads or reconnects. oculus opens only a file a server named in an answer to a request you made, never one under a dot folder (the interpreter's library folders excepted), under a folder of the `closed_paths` setting, or in oculus's own configuration, `~/.oculus` or the hub's `secrets` folder.
- An edit a server asks for may change other files: a file open in a tab of this page is changed in that tab, unsaved, as one undo step, and every other file is written at once with a copy in the local history (up to 5 MB), as one History record "Edited by a language server in N files" whose undo takes every written file back. A tab of a file the server holds is edited only when its text is the text the server holds, so a second tab with other text refuses the edit.
- The whole edit is refused with a notice naming the file when a file it names is open in a tab of another page, is named twice, is a library file, lies outside the served folders or in `node_modules`, a dot folder, `secrets` or `~/.oculus`, is `local.yml`, is over 5 MB or changed on disk, or when the edit creates, renames or deletes a file; text typed into a tab after the other files were written is kept, and the notice names that tab and says how many files were written.
- pyright runs with the repository's `.venv` or `venv`, else the `python3` on PATH, else a path typed into `:interpreter`, and a repository's own interpreter runs only after you approve it there, the approval kept for that path and repository on this machine. clangd runs with the compile database the status bar names (a `compile_commands.json` at the root or in a `build/*/` folder, or a configuration of the repository's `.oculus/cpp.yml`, chosen in `:compile-database`), which oculus links into its own `lsp` folder so clangd's index is never written into a repository.
- `.oculus/cpp.yml` holds a `configurations:` list, each entry with a `name` and optionally `compile_commands` (a folder of the repository that holds a `compile_commands.json`) and `fallback_flags` (the flags for a file the database does not list, with relative include paths read from the repository's root); a value that does not read is listed at the head of the compile database list, its entry is skipped and the status bar item is amber. The servers read the repository's own `.clangd`, `.clang-tidy`, `pyrightconfig.json` and `pyproject.toml`.
- texlab is a separate program: the `texlab` on PATH (`brew install texlab`) or the file `latex.texlab_path` names, and a path that cannot be used is reported and not replaced by the PATH; it builds nothing, runs no ChkTeX, formats nothing and reads no latexmkrc, and a `.rnw`, `.jnw` or `.pnw` file is not served by it.
- The TypeScript server runs oculus's own TypeScript and fetches no typings, so missing `@types` show as diagnostics; the Svelte server starts in reduced mode and runs none of the repository's `svelte.config.*` or `vite.config.*` until `:svelte-config` approves their present text (a changed file asks again, and a rename in a `.ts` file reaches `.svelte` files only after that approval). In a repository with no `svelte` package the Svelte server uses its own Svelte 4.
- The YAML server checks a file against the schema oculus generated for it (the Data map lists which files have one), completes the keys and values a schema declares (the keys of the file a reference field points at included), gives the field's help line on hover, marks an undeclared key, a value outside the allowed ones, a reference that names no key and a missing required field, and offers no formatting. `$schema:` and modelines are not loaded, a file with no schema gets syntax marks only, and `config/local.yml` and the files under `secrets` and `~/.oculus` are never sent to a server.
- The Markdown server marks a link to a file that is not there (not one to a heading, a reference definition, a code span or a fenced block), completes paths after `](` and renames a heading and its links. A path in single backticks that holds a `/`, no space and no `://` and starts with an entry at the top of the folder reads as a link that Cmd+click opens at the line after the colon (or the `#L` fragment); a Markdown file created or moved meanwhile is in its answers once the disk reports it. A file under `secrets` or `~/.oculus` is never marked, completed or opened.
- After a move or rename in the Files view the Markdown servers of the folders that hold both places are asked which links and backticked paths now lead nowhere, and the answer is a Refactor Preview titled "Update links in Markdown files" that writes nothing until Apply; a move of something no Markdown file names, a copy, a refused move and an undo from History show nothing. When two served folders rewrite the same text differently the file is left out and a notice names it, and a notice says so for a folder whose server cannot be asked.
- In a YAML file of the hub, and in the files of oculus's own configuration that name a hub key (`behavior.yml`, `layout.yml`, `sources.yml`, the config `present.yml` and `catalogs/vocab.yml`), a value that names an entry of another file is a link wherever its field's `from:` in the schema says it takes keys from a registry, the projects or a vocabulary list, also in a tab's unsaved text. Going to its definition selects the whole key, in both files when a key stands in two.
- A rename of a hub key is shown as a Refactor Preview first; Apply writes the checked edits only, History undoes the whole rename, and the new key is written the way the old one was (quotes and comment stay, and a key that would read as a number, `null` or text with a colon is double-quoted). It is refused with a reason when the key is a project's folder name, a word of `catalogs/vocab.yml`, stands twice in a source, is a key of more than one source, is already a key or is empty, or when a file is over 5 MB, not UTF-8 text, open in another window or open with unsaved text that is not YAML.
- ChkTeX runs on `.tex` and `.latex` files, Ruff on `.py` and `.pyi`, ESLint on TypeScript, JavaScript and Svelte files, and ShellCheck on `.sh`, `.bash` and `.slurm` (not `.zsh`, `.bib`, `.sty` or `.cls`), on the file on disk after a save and when a tab with no unsaved text opens, never while typing; a tab with unsaved text keeps its last findings until it is saved, and a library tab, a version at a commit, an untitled tab and a tab of a folder that is not served are not linted. `lint.chktex`, `lint.ruff`, `lint.eslint`, `lint.shellcheck` and `lint.writing` switch them on or off.
- ChkTeX, Ruff and ShellCheck are separate programs: the one on PATH or the file `lint.chktex_path`, `lint.ruff_path` or `lint.shellcheck_path` names, and a path that cannot be used is reported as not found. `lint.chktex_args` holds ChkTeX's arguments (`-wall -n22 -n30 -e16 -q` by default; it reads the `.chktexrc` beside the file or in the root and does not follow `\input`), Ruff runs without its cache and never from the repository, and a run past 30 seconds is stopped.
- ESLint is the repository's own: a file under an `eslint.config.*` of a folder with the `eslint` package is linted by it only after you approve that configuration in the `:eslint-config` list, each configuration folder on its own, a changed file asks again, and the same list takes the approval back, which ends that folder's ESLint at once. The first lint after an approval takes as long as the repository's ESLint takes to start, oculus keeps that ESLint running for the folder and ends it after 15 minutes without a lint, and a file ESLint ignores shows no findings.
- The writing rules run on Markdown and YAML files and on the comments of code files (and a Python file's docstrings), give warnings with the source `writing` and the codes `em-dash`, `en-dash`, `curly-quote`, `ellipsis`, `arrow`, `nbsp` and `wrapped-paragraph`; a finding falls only in text outside front matter, code, code spans and addresses, and a fix in a YAML file is offered only when the file parses to the same value after it. `lint.writing_skip` lists the globs they leave alone (`glyphs.yml` is always skipped) and `lint.writing_glyphs` the files that draw arrows as icons.
- Fix All Writing Problems in Folder (the Files view's menu on a folder) lists the files with an automatic fix, ticked by default, and writes the ticked ones all together or none, each after a copy is kept in History ("Fixed by the writing rules in N files"). It is disabled while `lint.writing` is `false`, lists a file whose tab holds unsaved text, or one over 256 KB that holds a marked character, unticked and disabled, leaves out a file over 2 MB, does not enter `node_modules`, a dot folder, `secrets` or `~/.oculus`, and refuses a folder with more than 2000 such files.
- A finding with a fix offers it in the lightbulb and Quick Fix (Cmd+.), and Fix All Auto-fixable Problems for a linter applies the fixes that do not overlap as one undo step; a fix is offered only while the tab has no unsaved text. Every finding of ChkTeX, Ruff, ESLint and ShellCheck offers Show documentation where the linter has a page and a comment that silences it (`# noqa: CODE`, `// eslint-disable-next-line RULE`, `# shellcheck disable=SCnnnn`, `% chktex N`). A linter with no findings shows `not found`, `failed`, `timed out` or `not approved` on the status bar, the reason in its tooltip.

## Searching the files

- In the Search view a pattern runs on Enter or the Search control; typing runs nothing. The `word`, `case` and `regex` toggles decide what the pattern means, turning one over while results are shown runs the search again, and `case` is the only control over case, so a pattern matches without regard to case until it is on.
- The roots are the file browser's own, the search is a local ripgrep process (the copy that comes with oculus) with no index and no service, and the query never leaves the machine. Files a repository ignores, hidden files and folders (a `.env`, a `.gitignore`), `node_modules`, `.git`, `.svelte-kit` and `.svelte-kit-app` are skipped, and a file over two megabytes is not opened; a folder chosen with Find in Folder is searched even when it is hidden or ignored itself, with its contents following the same rule, and the view says `In <root>/<folder>` with a control that clears the scope.
- The answer stops at `search.max_hits` hits and says so, each root gets `search.timeout_s` seconds, and a root that fails or runs out of time is named under the count. Hits come in the order ripgrep answers, which is not sorted, a hit is one match (a line holding two matches is two rows, each with its own Replace and Dismiss), a heading opens its file at its first hit and a row at its own line, and a tab keeps what it last found. For every use of a name in a Python, C or C++ file use Find All References; `word` over the root finds the name in every file.
- Whether the replace row is shown, the replace text, Preserve Case and the last twenty texts each box ran are kept with the tab, and Dismiss takes a hit or file out of the results without writing.
- The replace text is read as the editor reads it. In regex mode `$0` to `$99` are the groups, `\n`, `\t` and `\\` are escapes, and `\u`, `\U`, `\l` and `\L` before a group change its case; `$<name>`, `$&` and `$$` take effect only when the replace text also holds a numbered reference, a group number the pattern lacks is written as typed, and without `regex` the text is written exactly as typed. Preserve Case gives the replacement the capitals of the match, and in a file with Windows line ends a newline is written as `\r\n`.
- Replace All asks first (and says when the search stopped at the hit cap that only the hits listed are replaced); one replace runs at a time. The server runs the search again over each file and refuses a file in which a named match moved (`changed`), a file its mode locks (`denied`), a file that is not text (`binary`), a file over the save limit, `config/local.yml` and a replace text holding U+E000 to U+E003 (`marker`); a file a source tab holds with unsaved text is left out and named.
- A replace stops at the first refused file, names it and the files written before it, and keeps a copy of every file it writes; the whole replace is one History record, "Replaced in 3 files", whose Undo writes each file back while every file still holds what the replace left. After a Replace the hits left in a written file are read from the file as it is now, the focus moves to the next row, a hit you dismissed stays out while its line is as it was, and a file whose hits could not be read keeps its row with "Search again to see this file's hits."
- Pressing a hit while the replace row is shown opens its Replace Preview, a diff pane with the file as it is on the left and the file with this tab's replacements on the right, beside the Search view and never over it; a dismissed hit stays unreplaced in it, and after a Replace the next hit opens in the same preview. What a Replace All came to takes the place of the count line until the results next change.

## Terminals

- Each Terminal tab owns terminals running Claude, Codex or a shell inside tmux, which keeps them running when the server ends, and shows only those. A new tab shows the composer, where you pick the workspace, agent, account and options and write the first prompt; a start that is refused is said on the bar and changes nothing.
- A start whose options make the agent ask less (Claude's Accept edits, Auto and Bypass permissions, Codex's Full access and a Never approval) asks first, at every start, what the option changes, and the server refuses such a start that did not come from that question. A value of `config/catalogs/agents.yml` with `confirm: true` asks before every start that resolves to it, and a `confirm` that is neither true nor false is reported and reads as true.
- A start from a hub task (a task's `agent` button, Start Agent, a worktree control) opens the composer in the page's Terminal tab, or a new one, with that agent and every option at its default (Permissions reads Manual permissions), in the task's folder: the project's, the funding scheme's `link:` folder, the one project an entry relates to, else the hub. The composer shows the task's text read-only, offers only Claude and Codex, and Remove the task makes the start an ordinary one.
- The task's text runs only after you approve it for that agent and that real folder (Approve and Start), kept in `~/.oculus/approvals.json`; a changed text asks again, and a task changed since it was shown replaces the shown text and starts nothing. It is refused when the agent is a shell, the task is gone from the hub, or the text is longer than a prompt may be, and an approvals file that cannot be written is said and starts nothing.
- Every terminal runs Claude's classic renderer (`CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`), and a Claude already running keeps its renderer until it is started again. Once Claude or Codex runs, the steer box sends more text and Stop interrupts; a shell is typed into at the grid, and a terminal's line height, letter spacing, weight and ligatures are fixed.
- A list on the right names each terminal of a tab from two on (by the title you gave it, else after what runs in it). Split starts a new terminal of its kind in its folder, Kill needs two presses, and a double click renames; a row of terminals holds any number side by side, at least 80 px each, a handle between two resizes them and a double click on it evens them, and pressing a terminal outside the row shows it alone.
- Drag a row to reorder it or to move it to another Terminal tab; a tab left with no terminal closes unless it shows the composer. Join Terminals in a row's menu moves a terminal another tab owns into this one, Attach to Session lists the terminals no Terminal tab owns (a tmux session started by hand is not one) and moves the one you pick in, and a terminal started elsewhere (an update task, a resume or fork, a dataset recovery, a project chat, a LaTeX build, a Repositories shell) shows in the tab that owns it, else in the page's Terminal tab, else a new one.
- In the grid a web address opens in a new browser tab on Cmd+click, and Shift+F10 opens its menu at the cursor. A paste that holds a line break, a single trailing one included, asks before it is sent, and a file dropped from Files types its quoted path. A terminal opened again, or shown again after the server restarted, shows its screen with the cursor where the program left it and keeps the modes the program set, so a paste into a waiting shell still reaches it as a paste and an editor gets the arrow keys and the mouse as it asked.
- When a terminal ends, its row leaves its tab, except a task terminal, which stays until closed, and a tab whose last terminal ended closes unless it shows the composer. Closing a tab, pane or page, or resetting a page, ends the terminals it owns after asking when one runs a program other than its shell (a task terminal whose line ended is not asked about), and closing a task terminal ends its session; moving, splitting and reloading end none.
- The sessions list groups sessions by workspace, ordered pinned first, then those that need input, then newest first. Archived sessions are hidden until the filter asks for them and Archive is offered on ended sessions only; every terminal oculus runs is listed below the sessions, those no Terminal tab owns included, and pressing one shows it in the Terminal tab that owns it or takes it into the page's.

## Project commands

- A repository's project commands are named lines that run in its folder, from three places in this order: `.oculus/commands.yml` of the repository, the commands saved through the form (`~/.oculus/commands.json`, under the repository's absolute path), and what oculus finds (CMake presets named `cmake: <preset>`, `cmake build: <preset>` and `ctest: <preset>`, the scripts of `package.json` as `npm: <script>`, run with `pnpm` or `yarn` when their lock file is there, and the targets of the top `Makefile` as `make: <target>`, without pattern rules).
- `.oculus/commands.yml` is a list `commands:` of entries with `name`, `run`, an optional `cwd` (a folder inside the repository), an optional `depends_on` (command names that run first) and an optional `default` (`build` or `test`). A name held by the file and the saved commands is listed with its source (`build (file)`, `build (saved)`) and a press runs that source's command; the form refuses to save a name the file or a found command holds, and a wrong field, a repeated name, a folder outside the repository or a second `default` of one kind is a finding that leaves the entry out.
- The Repositories view draws a repository's commands above its commit box, a project card draws them below its chips when its folder is a repository, and the Files view's right-click menu on a root or folder that is a repository has a Run Command submenu. Add Command... saves one for that repository, and a command from a file or a found one is edited in its file.
- A press starts one terminal; with `depends_on` it runs each command of the chain once, in order, and stops at the first that fails (a cycle, a self-dependency and an unknown name are refused with the names).
- The placeholders `${file}`, `${fileDirname}`, `${fileBasename}`, `${fileBasenameNoExtension}`, `${lineNumber}`, `${selectedText}` (all from the source tab on screen, or the one whose editor had the focus last when a button in another view started the command) and `${workspaceFolder}` reach the command as environment variables and are never read as shell text, so inside single quotes they print as written, and a line that evaluates text itself (`eval`, `sh -c`, and `$((...))` arithmetic in bash) runs the value as code. A placeholder with no value refuses the run, and any other `${...}` is left as written.
- A command from a file or a found command runs only after you approved its exact text on this machine, listed in run order with Approve and Run: the chain with the repository's real path is approved as one text, kept in the file the `approvals` key of `local.yml` names (`~/.oculus/approvals.json`, its folder made private to you), and a changed line, folder or dependency, a gained dependency and the same text in another repository ask again. A command saved through the form runs without the question.
- A command's terminal stays after the line ends with a green check for exit code 0 and a red cross otherwise (the server looks at a running command's terminal every five seconds); Rerun runs the same line again and is refused while it runs, Restart stops a running line after a confirmation and runs it again. A `file:line:column: error: message` or `file:line: warning: message` line in the output opens that file at that line when it exists under the repository, and the errors are kept as the command's diagnostics until it runs again.
- With no default build or test, the build or test key says on the status bar which is missing.

## Debugging

- The Debug view runs a `.rite` program under cathedra's `rite_dap` adapter: set a breakpoint with F9 or a left press in the editor's margin, press F5 (or Start, or a configuration in the list of the status bar's debug item), and the program runs until it stops on one, where Variables, Watch, Call Stack and the Debug Console show its state. The keys are the F5, Shift+F5, Cmd+Shift+F5, F9 and F10 / F11 / Shift+F11 rows of [The keys](#the-keys), and they answer while the editor or a field has the keyboard and no dialog is open.
- The repository is the deepest git repository holding the file of the source tab on screen (or the one focused last), else the served root holding it, and a file under no served root is refused with a notice naming it. A repository's configurations live in `.oculus/launch.yml`, a map whose `configurations:` is a list; with none, F5 runs the `.rite` file on screen as Debug the open file, a `launch.yml` listing no configuration that reads launches nothing and says so, and the first configuration is the default until you pick another.
```yaml
configurations:
    - name: Debug the open file
      program: ${file}
    - name: Benchmark
      program: utils/benchmark/fib.rite
      cwd: utils
      before: build
```

- `name` follows the rule of a project command's name, and a repeated name keeps the first entry. `program` is required: a path relative to the repository that exists and ends `.rite`, or a text holding `${file}`, `${fileDirname}`, `${fileBasename}`, `${fileBasenameNoExtension}` or `${workspaceFolder}`, filled with the file on screen at the launch, which must then name an existing `.rite` file under a served root. `cwd` is a folder of the repository (the repository when absent) and takes no placeholder.
- `before` names a project command, found as a `depends_on` name is; the launch goes on when it ends with exit code 0, asks Debug Anyway, Show Errors or Abort otherwise, and posts a notice after ten seconds of waiting, where Debug Anyway launches now and leaves the command running and Abort asks to stop its terminal. A name that is no command refuses the launch, a launch that waits drops when the command is refused, not approved or its terminal is closed, another start while it waits is refused, and Stop drops it and leaves the terminal.
- An entry with a fault is left out and each fault is a finding in the Debug view; a key other than these four is one, and so are the keys of VS Code's `launch.json`. Add Configuration opens the file at its first entry and makes it with one configuration when it is absent.
- Every launch asks before it runs, listing `rite_dap <program>` and the folder, and a yes is kept in the file the `approvals` key of `local.yml` names, together with the project commands'; the text is the repository, the configuration's `cwd` and its `program`, so a changed `program` or `cwd` asks again and a renamed entry does not, and the default configuration's text equals a configured `program: ${file}` in `cwd: .`, so one yes covers both. The adapter is `rite_dap_bin` of `local.yml` (an absolute path, a path under `~/` or a name on PATH, `rite_dap` when absent), read at each launch.
- One session runs at a time, and a start while one is starting, running or paused is refused from every surface. The unsaved `.rite` tabs are saved first, and a tab that cannot be saved stops the launch; the Debug Console opens when a session starts and stays open when it ends, the Debug view opens when the program pauses, and Start stays drawn while a session runs.
- Only a `.rite` file on disk takes breakpoints (a version, diff or library tab takes none), a breakpoint moves with its line, and a middle or right press in the margin does nothing. When the program pauses, the file of its top frame opens at the line (a frame in a file under no served root is listed and not opened, with a notice), the editor takes the focus and the page asks the browser to focus its window; a hover over a word in a `.rite` tab shows its value in the selected frame while paused.
- The adapter cannot be stopped by the protocol: Stop sends SIGTERM to the process oculus started and SIGKILL two seconds later, after a confirmation naming the process. Restart is Stop followed by the same configuration again, its `before` command included; Finish Frame runs to the end of the frame and has no key.
- Breakpoints, function breakpoints, watch expressions, the chosen configuration of each repository and the floating toolbar's place are kept in the browser under `oculus.debug.v1`, two tabs follow each other, and a change made during a session is sent at once. The Debug Console keeps the last 10,000 lines, is emptied at each new session, evaluates its input in the selected frame while the program is paused and is read-only otherwise.
- While a session runs, the debug keys except Cmd+Shift+F5 go to the debugger also when a Terminal tab has the keyboard, which then gets none of them, and F5 never reloads the page while a session or a `.rite` tab holds the keys. The adapter offers no Pause, no conditional, hit-count, log, data, inline or exception breakpoints, no setting of a variable, no Restart Frame, no loaded scripts, no expanding variable and no second session, and none of VS Code's `debug.*` settings is a key of oculus.

## Apps

- An app is a folder of web files that oculus finds while it runs and draws in a tab; it needs no build and no restart. A machine app lives in `.oculus/apps/<name>/` of the hub (or in the folder `apps_dir` of `local.yml` names), and a root app in `.oculus/apps/<name>/` of any other root shown in the Files view. Each folder holds an `app.yml` that names it and lists what it asks for.
- An app runs only after you approve it, and the approval holds only for the files you read: a changed file shows the approval panel again, and a root app changed by a `git pull` asks again too. Keep approved while I edit lets an app stay approved while you work on it, a machine app or a root app, until oculus closes. An app that names a host also runs a program on this machine with your rights, and its approval panel says so and names the file; the program runs only while the app's files are the ones you approved.
- An app runs in a sandboxed frame with no access to your files, cookies or the write token. It reads the channels its manifest lists, asks oculus to write the kinds its manifest lists, and every write is recorded in the change log with the app's id; a write that deletes an entry or a feed, or creates an idea or a LinkedIn post, asks you to confirm first.
- Approve a host: open the app's tab, read what the panel says it runs, which folders it reads, whether it stores secrets and which apps it needs, and press Approve. The program starts when the app asks for it, usually when a tab of the app is drawn, and stops when you disable, revoke or remove the app or change its files.
- Disable and Enable are on an app's right-click menu in the Views catalogue, on its approval panel and on its tab. Disable (Workspace) and Enable (Workspace) change the state for the current workspace only. A disabled app keeps its place in the catalogue with a mark, shows a line with an Enable button in its tabs, and reads, writes and runs nothing. When enabled apps need the app, oculus names them and asks before it disables them too.
- Remove is on a machine app's right-click menu and approval panel. The question says how many secrets the app holds; Remove moves the app's folder and its data file to the Trash, deletes its secrets and takes its approval back. A root app has no Remove: delete its folder in its repository.
- Add app from folder is in the Apps group of the Views catalogue; where the folder panel is not available, use Add as App on a folder of the Files view that holds an `app.yml`. The folder is copied into the machine's apps folder and asks for your approval like any app.
- Restart: when an app's program ended by itself, its tab and its row in the Processes view show the exit code or the signal and a Restart button.
- The limits are the `apps:` block of `config/behavior.yml`, and `closed_paths` lists the folders no app can open a file from, `secrets` as shipped. [`docs/apps.md`](docs/apps.md) is the guide to building an app: the manifest, the bridge methods, the channels, the writes, the refusal words and a worked example, and it opens in oculus as Apps guide on the Help page and from the manual's links to it, on any hub; it is not a row of the Views catalogue.

## Source Control and worktrees

- The Repositories view lists every root the git channel carries, the repositories below the file browser's roots down to `repository_scan_depth` levels (1 by default, 0 for the roots alone, at most 3 in `sources.yml`; a repository cloned while oculus runs is found) and every session's workspace, leaving out a workspace that is gone or is no repository. The rail badge counts the changes over every repository, closed ones included, and no write is offered while one is running.
- What a repository row shows is pushed by the server: a commit made in a terminal moves it within two seconds. A diff, the graph, a commit's files, the blame and the gutter marks are read when a pane or section asks, a repository git could not read stays in the list with git's reason in place of the sections, and a read in which git ran out of time is made again two seconds later, and again until one finishes.
- Stage, Unstage and Discard act on every selected row (a press, Cmd+press, Shift+press, Shift with an arrow and Cmd+A select), and the list and the sections are one Tab stop each, moved along with the arrow keys. Every write runs from a press, and every one that throws work away or reaches a remote asks first, except Fetch; every commit asks first too. Nothing forces a push except a deposit's snapshot push, which replaces the remote's `main` and the history that was there.
- Pull is a plain `git pull`, so the repository's own `pull.rebase` decides between merging and rebasing; Sync pulls and then pushes; Fetch prunes; Publish Branch offers each remote of a branch with no upstream and makes it the upstream; signing is left to git's `commit.gpgsign`; a commit never takes an identity git guessed from the machine (`user.useConfigOnly`: a repository with no name or email refuses with git's message); untracked files are a group of their own, so Stage All Changes never stages a new file. The status bar's sync item does the same for the repository of the tab on screen.
- `git.autofetch_minutes` in `behavior.yml` fetches every repository with a remote at that period, as Fetch does and without asking for a password or a passphrase, and moves each branch's behind count; when only the older `GIT_SSH` variable names the ssh program, autofetch adds nothing for ssh, which may then still ask. 0, the default, fetches only when Fetch is pressed; nothing else reaches a remote unasked, and nothing pushes after a commit except Commit and Push or Commit and Sync.
- The commit box holds one message per repository, shared by the Repositories view and a session's Changes panel. With nothing to commit the button is Sync Changes or Publish Branch (both ask first), an amend needs nothing staged and keeps the last message when the field is empty, and the button inside the field writes a message from the staged diff.
- A commit, merge, cherry-pick, rebase continue, push, pull, switch and worktree creation run the repository's own hooks and have no time limit, and Sync has none; while a write runs the repository says Working with a Cancel button, which stops the hooks and other processes that command started and lets git end on its own ("Git was stopped by Cancel"), as does the deposit's panel. Every other command is limited to 10 seconds (60 for Fetch), and a command that fails without a message of git's own says why: its limit, more than 8 MB of output, a signal, or its exit status.
- A changed row opens its diff in a pane of its own, side by side or inline (the pane remembers which), with the words that changed marked, an unchanged run hidden with three lines kept beside each change (Collapse Unchanged Regions turns that off) and what was shown kept across a re-read and a reopen. A diff of several files gives each a header with a fold chevron and Open File, and a commit's diff opens one file per pane; a file whose line endings alone changed says so above it and shows all its lines.
- A diff's blocks have Stage Block, Revert Block (asks first) and Unstage Block, and selecting lines on either side narrows them to those lines; a new or deleted file is staged or reverted whole from its bar. A file has no block or line actions, and its bar says to use Changes, when it holds a carriage return, is not UTF-8, or git converts it (a `filter`, `working-tree-encoding` or `ident` attribute, `eol=crlf`, or `core.autocrlf` set to `true` or `input`), and a path in conflict has them in the merge editor only.
- A comment on a line of a session's own diff tab (the + in the glyph margin, or Add Comment on Line) is sent to the session as the prompt `<path>:<line>: <text>` through its oculus terminal, or copied to the clipboard with a line saying so.
- A merge, pull, stash apply or pop that stops on conflicts is left in progress and listed under Merge Changes with a count. In the merge editor Ignore on a conflict keeps what the two sides had in common; the Result can be typed into, a choice is one edit that Undo takes back, and the commit box starts with git's merge message.
- Complete Merge writes the Result over the file and stages it (asking first while a conflict is open); where one side deleted the file, or both did, Accept Deletion (and Complete Merge with an empty Result) takes the file out of the index and the folder after a confirm, and Mark Resolved stages a file resolved some other way. Abort asks after a confirmation; a rebase stopped on conflicts offers Continue, and a cherry-pick offers Abort only, since committing finishes it.
- Stash, Stash (Include Untracked) and Stash Staged ask for an optional message (Stash Staged needs git 2.35 or later); stashes are listed newest first with Apply, Pop and Drop (Drop asks first). Create Tag asks for a name git accepts and an optional message, which makes it an annotated tag, at the checked-out commit; Delete Tag asks first, and Push Tags pushes every tag after a confirmation.
- Checkout (Detached) runs `git switch --detach` and a branch switch the same rule: both are refused when a tracked file has a change, an untracked file does not stop them, and a switch that would overwrite one is refused with git's message. Create Branch... and Create Tag... start at the commit; Delete Branch runs `git branch -d` and asks again before `git branch -D` when git keeps the branch as not fully merged, and any other refusal is git's reason with the branch kept.
- The Graph section draws the checked-out branch's history fifty commits at a time (Load More reads the next fifty), with Incoming and Outgoing first while the branch has an upstream; the checked-out branch's pill has Checkout and Delete Branch unavailable with their reasons. Pressing a commit lists its changed files, each opening that commit's diff.
- Cherry Pick applies the commit to the checked-out branch after asking, and a pick that stops on conflicts is left in progress as a merge is; one that would change nothing is aborted and says so. Compare with Remote needs an upstream, Compare with Merge Base needs a base git names, and Compare with... asks for a branch, remote branch or tag; each opens a diff pane over the files that differ.
- Discard Changes on an untracked file or folder moves it to the Trash after asking (a path outside the repository, one the server keeps for itself and a tracked one are refused first), and Add to .gitignore appends the path to the repository's `.gitignore`, one line each, and opens it. When git lists more than 200 changes the view shows the first 200 of a group and says so, and the rail badge counts what git reported.
- Close Repository takes a repository out of that Repositories tab's list only (another tab, a session's Changes panel and the rail count still have it), and Reopen Closed Repositories brings closed ones back. Open Worktree adds the worktree's folder as a root of the workspace and shows it in Files, saying so when no root holds it; Open Worktree in New Window opens this page's address in a new window as well.
- A source tab over a file of a repository marks its changes against the index in the gutter; a press on a mark opens the diff at that change, and Go to Next Change, Go to Previous Change and Open Change in the palette move the caret from mark to mark.
- Blame (the Toggle Blame button or Git: Toggle Git Blame Editor Decoration) writes who last changed each run of lines beside the numbers, reads the file as it is saved, and shows Not Committed Yet for a line no commit holds; a tab over the file at HEAD or in the index blames that version, with no change marks, and a press on a blamed line's number opens its commit in the Graph.
- A worktree is a second checkout of the same repository on a branch of its own. The control at the bottom of a root's worktree list takes a name (Enter submits it), says the path before anything is made and, on confirm, makes `<root>/.agents/worktrees/<name>` on a new branch of that name from HEAD and opens a shell there (Create with Claude and Create with Codex open the composer instead; a worktree that cannot be made opens nothing); a repository whose `.gitignore` lacks `/.agents/worktrees/` is warned about and left as it is.
- The merge back is git's own `merge` onto the checked-out branch, a fast-forward where it can be one; it is refused when the repository has staged or changed paths of its own, no branch checked out, or when the name is not one of its branches or is the checked-out one (an untracked file does not refuse it), and a merge that stops on conflicts is left in progress with Abort one press away.
- Removing a worktree is a second control, never part of the merge, and refuses a worktree holding uncommitted changes or untracked files, since the removal takes the folder and everything in it. The branch goes with the worktree only when no work is left only there, and the answer says when the branch was kept.

## Configuration and the data

- Everything oculus shows is read from the research hub's files and written back to the files it came from. Every setting is a file of the engine's `config/` folder or this machine's `local.yml`; each is read on every load and merged into one map by its top-level keys (so a key can move between files), except `local.yml`, and an edit saved in a source tab reaches the page without a reload, a cadence, a window, a count or the usage tiers taking effect at once.
- In `config/`, `appearance.yml` holds the UI themes, the wallpaper, the Memories wall's folder, the CRT default, the code theme, the terminal's text size, cursor style and blinking, `mac_option_is_meta` and `copy_on_selection`, and `show_tabs`, `editor_actions` and `wrap_tabs`. `behavior.yml` holds the thresholds, horizons and cadences: read limits, `refresh_stale_days`, the Live HPC settings, the audit's lists, and the `editor`, `files`, `literature`, `apps`, `open`, `git`, `lint`, `latex`, `search`, `mail`, `calendar`, `changes`, `processes`, `usage_refresh_min` and chat keys.
- `layout.yml` holds the rail, the arrangements, `workbench:`, `nav_groups`, `docs:`, the board chrome, the tab rollups and the live badges; `sources.yml` holds what the portfolio reads (the scan paths, the registry, collection and feed files, `portfolio_deck:`, `roots:`, `repository_scan_depth` and the `languages:` map from file names and extensions to the language that colours the file and names it in the status bar, a file no entry matches opening as plain text); `present.yml` holds `defaults.tag_tones`, the hue each tag class of a project slide wears, for every deck.
- `catalogs/` holds `agents.yml` (the composer's models, efforts and permission modes, each with its words, flag and default), `file-nesting.yml` (the patterns of File Nesting), `glyphs.yml` (each glyph name with its one to three character ASCII stand-in), `icons.yml` (the line icon of each glyph name), `latex.yml` and `unimath.yml` (the LaTeX editing tables), `meta.yml` (the window's title), `options.yml` (the options catalog) and `vocab.yml` (words and their colours: the palette, statuses, Focus lanes, venue tiers, radar buckets, side-project statuses, domains and theme words).
- `schemas/` holds `manifest-schema.yml` (a `project.yml`), `side-project-schema.yml` (a side project's), `deck-schema.yml` (a deck's `present.yml`) and `cpp-schema.yml` (a repository's `.oculus/cpp.yml`), the forms the YAML editor checks them against; `text/` holds every user-facing word, one file per surface (`app.yml`, `desktop.yml`, `findings.yml`, `server.yml`, `statusbar.yml`, `ui.yml` and `views/`).
- Every option is described once in `catalogs/options.yml` and set in the Settings view. A sentence of `text/findings.yml` holds `{0}` and `{1}` for the values the finding names. A value the option's control, range or list refuses is a finding with the file and key, and that setting takes its default while every other setting is read as written; a key a catalog or text file does not take, a value of the wrong kind and a word outside the ones a key takes are findings that name the file and key, and a sentence the text file lacks is shown as its key followed by its values, as is every sentence while the `config/` folder is missing (`findings.config.directory_missing`).
- The hub's own settings are the hub's layer, `.oculus/config/`, read after the engine's with the same file names; no file is required. A value it sets replaces the engine's value of that key whole, and inside a map the rule is per dotted path (`slurm: { resource: x, days: 5 }` sets `slurm.resource` and is a finding for `slurm.days`); a change to the layer on disk is read at once, and every finding about a value the layer set names that file.
- The layer may set only these keys; a key outside the list, a file outside the list and a `local.yml` in the folder are each a finding that names the file and are not read, and a file that does not parse is a finding and the engine's values stand.
- `sources.yml` may set `scan`, `portfolio_deck`, `venues_file`, `datasets_file`, `pillars_file`, `domains_file`, `people_file`, `organisations_file`, `resources_file`, `collections` (an entry named as the id of a built-in view, `debug` or `files` for one, is not registered, so a collection never replaces a built-in view), `leads_file`, `radar_file`, `publications_file`, `linkedin_dir`, `career_file` and `roots`.
- The engine holds the folder layout every hub follows for `scan` to `career_file`, no `publications_file` and no `linkedin_dir` (so a hub that names none has no publications file to cross-check and no LinkedIn folder), and an empty `roots`.
- `layout.yml` may set `docs`, the hub documents of the view catalogue (empty in the engine): each entry is `{ label, path, group }` with `path` relative to the research hub and `group` a key of `nav_groups`. `behavior.yml` may set `slurm.resource` (empty in the engine, which means no cluster) and `data_domains` (empty, so the audit expects no dataset of any domain).
- `catalogs/vocab.yml` may set `domains`, `venue_themes` and `data_themes`, edited in the file; a theme word a registry uses that the list does not hold is a finding. The tiers, types, statuses, Focus lanes, lifecycle and manifest schema stay in the engine, one for every hub.
- A write of a key of the list goes to the layer file, and any other key to the engine's file. When the file or the key is not there the write adds it, making the file and its folders, and the undo takes the added key out again and removes what the write made; the Settings view names the layer file as the file of each such option and says when it is not there.
- The hub's `.oculus/` folder also holds `bookmarks.yml`, `notes/`, `schedules.yml`, `workspaces.json`, `apps/`, `memories/` (the photo wall's pictures) and `wallpaper/` (the backdrop's pictures), each at that place unless the key of `local.yml` that names it (`bookmarks`, `notes`, `schedules`, `workspaces`, `apps_dir`) or, for the last two, the key `memories.dir` or `wallpaper.dir` of `appearance.yml` says otherwise, and a root's `.oculus/project.yml` for a side project. The folder is tracked by git unless the hub ignores it, and a saved workspace rebuilds the portfolio while a bookmark, note or schedule does not.
- `local.yml` is this machine's own, untracked and never merged, and is read again whenever it changes: `hub` (the absolute path of the research hub), `port` (8790 by default; a changed port moves the server and the open page follows with its tabs, layout and settings, a port in use or reserved keeps the server where it is, and a `port` that is not a whole number takes the default), `hpc_host` (the ssh alias Live HPC uses, ahead of the cluster entry's host).
- Also in `local.yml`: `claude_bin` (the Claude command every chat, worktree agent, usage refresh, update task, schedule prompt and commit-message suggestion runs), `open_bin` (the program an address, a consent page or an event's link is opened with, macOS `open` when absent) and `rite_dap_bin` (the rite debug adapter, read at each launch: an absolute path, a path under `~/` or a name on PATH, `rite_dap` when absent).
- `accounts` of `local.yml` (the agent account folders the Usage view and the sessions read: `<dir>/projects` for Claude transcripts, `<dir>/sessions` for which Claude session is alive and for Codex rollouts, and two accounts that are one real folder through a symlink are read once). `calendars` and `mail` of `local.yml` list the accounts, one `provider` of `google` or `microsoft` and one `label` each, written by the views' Add account and Remove with the file's comments kept.
- `literature` of `local.yml` is a map of `wos_key`, `scopus_key`, `scopus_insttoken`, `openalex_key`, `semantic_scholar_key`, `ncbi_key` and `mailto`, each an optional non-empty text (another key under it is warned of and ignored).
- The places `local.yml` sets, each defaulting under `~/.oculus` or the hub's `.oculus`: `apps_dir`, `calendar_dir`, `mail_dir`, `sessions_cache`, `sessions_overrides`, `workspaces`, `bookmarks`, `notes`, `changes`, `history`, `approvals`, `lsp`, `schedules` and `schedule_record`. A value that is `~` or starts with `~/` is under the home folder, and any other relative value is resolved against the engine folder.
- A `local.yml` key with a wrong value is a finding that names the key and leaves out the value, and takes its default (a wrong row of `accounts`, `calendars` or `mail` is left out with its finding); a body with a key the server would read as its default is refused on save, and a file that does not read keeps the values in force. Every key has a default, so a machine that sets only `hub` works, and the Settings view lists `local.yml` as a group tagged as this machine's own, with its description and never its values.
- Outside the hub, under `~/.oculus` unless `local.yml` says otherwise: the session cache and overrides, the change log `changes.jsonl`, the local history, the approved texts in `approvals.json`, the language servers' folder, the schedules' run record, the app stores in `app-data/`, the providers' client halves in `connect/`, and the calendar and mail credential files and triage notes. The engine's `config/` folder is written when a file of it is saved from a source tab.
- The change log records every write through the write endpoint that changed something (manifest fields, collection entries, subtasks, feeds, the slides list of each deck group and the order of a deck, the files an act on a deck's slides made or changed, one record for each, the rail list, settings, per-session overrides, a scaffolded idea and the two LinkedIn writes, which cannot be taken back); a text file saved from a source tab, a scratch note and the muting of an audit finding are not recorded.
- `changes.keep` in `behavior.yml` is how many changes the file holds, and History's control puts the earlier value back through the writer the change came from, refusing when the file changed since.
- An undo of a write that removed a field puts the removed text back where it stood, before the text that followed it; when the following text is gone, whole lines go back at the nearest line start giving the right values, else the value comes back as a new line. Text removed from inside a line (a flow map's key) goes back only at the place of its following text, else through the value write; an undo of a write that rewrote a bare follow-up note or a one-note list as a map puts the replaced text back over the lines the write left while the file still holds them, so the note keeps its shape.
- The Literature search sends keys of `local.yml` in a header or parameter of the request and never in an answer, a message or a log line. A mail account is its own consent with the mail scopes alone, so a calendar account of the same mailbox never gains the right to send; its refresh token is one file per account under `mail_dir` (`~/.oculus/mail`), mode 0600, which the consent brings back, and the poller publishes only the provider's one-line snippet with its HTML entities decoded.
- `mail:` in `behavior.yml` sets `poll_min` (10) and `per_signal` (25), and `calendar:` sets `poll_min` (15), `days_back` (31) and `days_ahead` (62); both are read every 2 minutes while a provider refuses. The first account of a provider opens the Account setup view (it never draws a saved id or secret), whose Save writes the provider's client half to `~/.oculus/connect/google.json` or `microsoft.json`, mode 0600, and every later account of it, calendar or mail, needs no setup; Add account in the Inbox and the Calendar writes the row of `local.yml` and opens the consent.
- A calendar published as a link is added with Published link as the provider and its address, which starts `https://` or `webcal://`; its row in `local.yml` is `- { provider: ics, label: <label> }` and the link is kept in `<calendar_dir>/ics-<label>.json`, mode 0600, read at every poll and never logged or sent back to the page. A calendar or mail account is removed by its row's Remove, which asks first, takes the row out of `local.yml` and deletes the account's own file; the provider's client half in `connect/` stays for the other accounts.
- In the Inbox a thread is on the plate when it is in the inbox and unread, carries the `todo` label, or is unlabeled and a single message whose subject is not an answer or a forward; a thread whose newest message is the reader's own, or is in the trash, is off it.
- The triage notes (what each thread wants, the line about it and the drafted answer) are one JSON object per thread id in `<mail_dir>/triage.json`, written by the card and by `/research-cockpit inbox` (which reads the mailbox through the runner's Gmail connector), polled every half second and dropped thirty days after the thread leaves the plate; a reply goes to the `Reply-To` of the thread's newest message where it has one, else to its sender.
- The hub's own files (the registries, collections and feeds, and the fields and links of each) are described in the Data map on the Help page, `docs/DATA-MAP.md` of the hub.
- A `roots:` entry of `.oculus/config/sources.yml` marked `hub: true` is built as a hub of its own and merged into the one portfolio, so its projects, entries, venues, people and feeds appear on every view beside the first hub's; a `hub:` that is not true or false, a key `side`, `root`, `hub` or `engine` or one with a colon, a directory that is, lies inside or holds the first hub or an earlier hub root, is a finding on that entry and the root is read as a plain root.
- A `roots:` entry with `tier: projects`, `coauthor` or `archive` reads the repository's `.oculus/project.yml` as a project of the first hub on the Projects, Coauthor or Archive board, with the entry's key for its id; with `tier: personal`, or no `tier`, the repository is a side project of the Personal board. Under `tier: projects` the manifest's `type` line (`idea`, `active` or `manuscript`) picks the column. A project moves between boards by a change of the entry's `tier` or of the manifest's `type` line. It has LaTeX and no Deposit, its manifest is written at `<root>/.oculus/project.yml`, and a write from an app's frame to it answers not found. An entry that cannot be read as a research project (a `tier` of another word, a key with a colon, a slash or a space, a directory that is, lies inside or holds the first hub, a key that is also a project folder of the hub, a manifest with no usable `type` under `tier: projects`) is a finding and the repository is read as a side project; a research `tier` on a repository with no `.oculus/project.yml` is a finding and gives no project.
- A second hub's own `.oculus/config/` layer sets what reads its files (the scan tiers, the registry, collection and feed files, the vocabulary); the career file, the website keys, the portfolio deck, the served roots and everything the Settings view edits are the first hub's, and a second hub's `roots:` is not read.
- A change to a record goes to the file of the hub the record is of; a new project, entry, lead, Lit Watch entry or idea goes to the first hub.
- A record of a second hub has the id `<root key>:<id>` and a chip with the root key on its card, row or page, and the people, venues, projects and other records its entries name are that hub's own; a first-hub record has no chip, and a portfolio with one hub shows none.
- The `secrets` folder of every hub is private, in any letter case the file system folds: it is withheld from the language servers, the writing rules' folder Fix All and fixes, search and the library rules, as the first hub's is.
